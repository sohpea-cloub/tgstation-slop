# #72900: Disposable sentry turrets can be deployed on top of each other

| | |
|---|---|
| Issues | [#72900](https://github.com/tgstation/tgstation/issues/72900) fixed (reproduced, fix verified in game) |
| Status | Fixed, one commit, verified on the test server |
| Fix branch | [fix/72900](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/72900) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The Disposable Sentry Gun (an emergency toolbox that turns into a turret when hit with a combat wrench in combat mode) never checked whether its tile already held a turret, so any number of turrets could be built on one tile. The fix refuses to deploy when a `/obj/machinery/porta_turret` is already on the tile, both when the wrench is first used and again after the 2 second construction delay.

## The bug

A player with several sentry toolboxes can put them all on one tile and hit each with a combat wrench in combat mode. Each one becomes a turret, and the turrets stack on the same tile. The issue calls this "almost infinite stacking of sentries in a given tile". A comment from June 2023 confirms it still worked then.

## Reproduction

1. On the test server, start the round and open the Lua editor.
2. With Lua, spawn a human and give them a combat wrench (`/obj/item/wrench/combat`) and turn combat mode on (`set_combat_mode(true)`).
3. Spawn two or three `/obj/item/storage/toolbox/emergency/turret` toolboxes on one tile near the human (the test used a tile 2 tiles away), and take control of the human.
4. Click the first toolbox with the combat wrench and wait for the 2 second delay. Chat shows "constructing..." and then "You bash the emergency toolbox with the combat wrench!", and a "turret" object appears on the tile.
5. Click a second toolbox on the same tile in the same way.
6. Result on master: a second "turret" object appeared on the same tile, so two turrets were stacked.

## Cause

`/obj/item/storage/toolbox/emergency/turret/item_interaction` (`code/game/objects/items/storage/toolboxes/weapons.dm:324-348`) checks that the tool is a combat wrench, that the user is in combat mode and that the tool has a nonzero `toolspeed`. Then it runs a 2 second `use_tool` and creates the turret with `new(get_turf(loc))` (line 344), without looking at what is on the tile. The turret type is `/obj/machinery/porta_turret/syndicate/toolbox`, which is dense (`density = TRUE`, `code/game/machinery/porta_turret/portable_turret.dm:33`), but nothing in this path checks for dense objects or other turrets.

The toolbox is sold as "Disposable Sentry Gun" to station engineers (`code/modules/uplink/uplink_items/job.dm:151`) and to nuclear operatives (`code/modules/uplink/uplink_items/nukeops.dm:664`), both with this item interaction.

## Fix

One commit, "Fix issue 72900: disposable sentry turrets can't be deployed on a tile that already has a turret". In `item_interaction`, after the `toolspeed` check, it returns `ITEM_INTERACT_BLOCKING` with a "no room!" balloon alert if `locate(/obj/machinery/porta_turret) in get_turf(src)`. The same check runs again after the 2 second `use_tool`, so two toolboxes started at the same time on the same tile cannot both finish. The check looks for any `/obj/machinery/porta_turret`, so it also blocks building next to a map turret on the same tile.

## Verification

On the test server with the fixed build, with the same setup (human with combat wrench, combat mode on, two toolboxes on one tile):

- The first toolbox was deployed normally and became a turret.
- Clicking the second toolbox on the same tile produced the floating text "no room!" and no second turret. The toolbox stayed where it was.

Not checked:

- Deploying a turret on a different tile after a blocked attempt (it uses the same path as the first deployment).
- Two toolboxes started at the same moment by two people, to exercise the check after the delay.
- The nuclear operative variant (`/obj/item/storage/toolbox/emergency/turret/nukie`) specifically. It differs only in how it sets the turret's faction.

## Notes

- The check only looks for turrets. A turret can still be deployed on a tile that has other dense objects, as before. A broader test such as `is_blocked_turf` would change that behavior and was not tried.
- During the post-fix test the first turret shot at a nearby security bot (Beepsky) and destroyed it. This is the normal hostile behavior of the turret and not related to the fix.
