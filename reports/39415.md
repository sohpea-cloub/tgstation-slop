# #39415: Spirits summoned by a manifest rune are listed as cultists in the round-end report

| | |
|---|---|
| Issues | [#39415](https://github.com/tgstation/tgstation/issues/39415): fixed |
| Status | Fixed on the branch below; verified in game before the final rebuild (see Verification) |
| Fix branch | [fix/39415](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/39415) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A ghost summoned with the "Summon a Cult Ghost" option of the manifest rune becomes a `cult_ghost` human and receives the cult antagonist datum, which makes it a member of the cult team. The team's round-end report prints every member, so manifested ghosts appear under "The cultists were:". The datum was also only removed when the rune ended if the body still existed; a gibbed or deleted body left the spirit on the team for the rest of the round. The fix flags manifested spirits and leaves them out of the cultist list, always removes the datum when the rune ends, and fixes a runtime that stopped the datum's removal for a body that was already gone.

## The bug

At round end, a player who only joined the round as a manifested ghost is listed among the cultists, for example "Factoryman942 was Tasmin Elliot the Unassigned and had their body destroyed" in the original report. These players never joined the cult. They were summoned for a short time and are dusted when the rune stops. (The issue text shows only a list of players, not the heading above it; the issue's title and the triage notes say it was the cultist list.)

## Reproduction

A full run that ends the round and reads the real round-end report was not done. Instead the team's `roundend_report()` was called directly from the Lua editor, which is the part of the report that lists the cultists.

Before the fix (the manifest rune itself was not used in this run):

1. On a test round, observing as a ghost, opened the Lua editor.
2. Spawned a `/mob/living/carbon/human/cult_ghost` named "Manifested Ghost", possessed it with the admin's ckey, and gave its mind the `/datum/antagonist/cult` datum (the same thing the rune does).
3. Called `roundend_report()` on the datum's `cult_team`.
4. Result: the returned text listed the spirit under "The cultists were:" ("... was Manifested Ghost and survived"). An attempt to read the report through `SSticker:antag_report()` from Lua did not work, because `CHECK_TICK` sleeps inside it.

A second observation was made on the fixed build, using the real rune:

5. The manifest rune asks for a choice through `tgui_alert`, which an admin test mob without a client cannot answer. A temporary test-only line was added to force the "Summon a Cult Ghost" choice when the invoker has no client. (It was removed before the commit.)
6. Created a human, invoked a `/obj/effect/rune/manifest` with that human as the invoker from Lua, and took control of the spawned `cult_ghost` as the observing admin.
7. On the fixed build, with the spirit alive, its cult datum had `manifested_spirit` = 1, the team had 1 member, and the report did not contain the spirit's name or the "The cultists were:" heading.
8. Gibbed the spirit's body. On the first fixed build (before the third change below) the cult datum stayed on the mind and the team still had 1 member, and the runtime log showed `Cannot execute null.clear mood event()` from `clear_antag_moodies` (`code/modules/antagonists/_common/antag_datum.dm:387`). This is the second defect described under Cause. The line is unchanged in master, so master has the same problem for any removal on a mind with no body; this was not run on an unmodified build.

## Cause

1. In the manifest rune's `invoke` (`code/modules/antagonists/cult/runes.dm`, the "Summon a Cult Ghost" branch around lines 975-1039) the spirit's mind gets `/datum/antagonist/cult` (line 1021). Adding the datum adds the mind to the cult team's `members`.
2. `/datum/team/cult/roundend_report()` (`code/modules/antagonists/cult/datums/cult_team.dm:109`) prints `true_cultists` if there are any, otherwise all `members` (lines 127-132). A manifested spirit is a member, so it is printed.
3. The only place the datum is removed is inside `if(new_human)` after the rune's loop (`runes.dm:1033-1038`, `new_human.mind?.remove_antag_datum(/datum/antagonist/cult)`). If the body was gibbed or deleted, or the round ends while the spirit is alive, the datum stays and the spirit stays on the team.
4. Even where the removal was reached for a body that is gone, `clear_antag_moodies` (`antag_datum.dm:383-387`) did `target.clear_mood_event(...)` with `target = mob_override || owner.current`, which is null after a gib. The runtime aborted `on_removal` (`antag_datum.dm:321`) before it reached `team.remove_member` (line 341).

The code comment above the spirit creation (`runes.dm:1001-1002`) already notes that `cult_ghost` should be a simple mob or species rather than a human.

## Fix

One commit, "Fix issue 39415: manifested spirits are no longer listed as cultists at roundend", changing four files:

- `code/modules/antagonists/cult/datums/cultist.dm`: new `manifested_spirit` boolean on the cult antagonist datum.
- `code/modules/antagonists/cult/runes.dm`: the rune sets `manifested_spirit` on the datum it creates and keeps the spirit's mind in a variable. After the loop, it removes the cult datum from that mind whether or not the body still exists, instead of only inside `if(new_human)`.
- `code/modules/antagonists/cult/datums/cult_team.dm`: `roundend_report()` builds a copy of `true_cultists` (or `members`), removes the minds whose cult datum has `manifested_spirit`, and prints the "The cultists were:" heading and list only if something remains.
- `code/modules/antagonists/_common/antag_datum.dm`: `clear_antag_moodies` now uses `target?.clear_mood_event(...)`, so removing an antagonist datum from a mind with no current body no longer runtimes.

Approach: the spirit keeps its cult datum (and so its cult powers) while it is alive; only the report is changed, plus the cleanup. The alternative suggested in the issue's comments, making the spirit a separate simple mob or species and excluding it by type, is a larger change and was not attempted.

## Verification

In game, with the manifest rune invoked through the Lua editor (with the temporary test line described above):

- Alive spirit: `manifested_spirit` = 1, 1 team member, and the report contained neither the spirit nor the heading.
- After gibbing the spirit's body, on the build with the `target?.` change: the spirit's mind had no cult datum, the team had 0 members, the rune's `ghosts` count was 0, and the runtime log had no `clear_antag_moodies` runtime.
- Before the fix, the report-level check above listed the spirit as a cultist.

Not checked:
- The temporary test line was removed and the tree rebuilt (0 errors) before the commit, and that final build was not run in game. The in-game results above are from the builds with the test line.
- A real round end through `SSticker`, or an actual cult round with real cultists. The report was read by calling the team's `roundend_report()` directly.
- A real player answering the rune's alert, and a real player ghost being picked for the spirit; the test spirit was the admin's own observer.
- A real round end while a spirit is still alive (the alive-spirit check above covers the same report path).
- A rune that ends because its invoker moves away or is incapacitated, rather than the spirit being gibbed.

## Notes

- `antag_datum.dm` is shared by every antagonist, so the `target?.` change affects them all. It only turns a runtime into a no-op when the owner has no current mob, which seems safe, but a reviewer should look at it.
- A commenter in 2018 suggested the issue may be a duplicate; no duplicate was identified here.
- The comment at `runes.dm:1001-1002` (from August 2022) asks for `cult_ghost` to become a simple mob or species. Doing that would make the filter unnecessary.
