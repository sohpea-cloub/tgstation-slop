# #96951: Gizmo light stays on after being switched off until the gizmo moves

| | |

| Status | Fixed (one commit) |
| Fix branch | [fix/96951](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/96951) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The gizmo `lights_off` pulse switched the light off with `set_light_on(FALSE)`, which only sets the `light_on` variable. For atoms using `COMPLEX_LIGHT`, such as gizmos, the light source is only destroyed by `update_light()`, which did not run until the gizmo next moved. The fix calls `set_light(l_on = FALSE)`, which does call `update_light()`, matching what `lights_on` already does.

## The bug

A player with a gizmo set up as a light turned it off and the light kept shining until the gizmo was moved by a tile.

## Reproduction

The pulses were called directly from the Lua editor. The bug was not reproduced through the gizmo's wire or interface path.

1. Observe on the test server and open the Lua editor.
2. Spawn an `/obj/item/gizmo`.
3. Create a `/datum/gizpulse/lights_on` and call `activate()` on the gizmo, then do the same with `/datum/gizpulse/lights_off`.
4. Read `light_on` and the `light` source datum on the gizmo.

Observed on master after the off pulse: `light_on` was 0, but `light` was still non-nil. The gizmo's `light_system` was `COMPLEX_LIGHT`.

## Cause

At master, `/datum/gizpulse/lights_off/activate()` (`code/modules/research/gizmo/gizmodes/gizmisc.dm:33`) ends with:

```dm
holder.set_light_on(FALSE)
```

`set_light_on()` (`code/modules/lighting/lighting_atom.dm:143`) only sets `light_on` and sends `COMSIG_ATOM_UPDATE_LIGHT_ON`. On a `COMPLEX_LIGHT` atom the light source is only rebuilt or removed by `update_light()`, which in this case ran only the next time the gizmo moved. `lights_on` (`gizmisc.dm:21-28`) uses `set_light(...)`, which calls `update_light()`, so turning the light on took effect at once and turning it off did not.

## Fix

One commit, "Fix issue 96951: gizmo lights-off pulse now updates the light source": `holder.set_light_on(FALSE)` became `holder.set_light(l_on = FALSE)` in `gizmisc.dm`. This is the same call family `lights_on` uses, so no other code needed to change.

## Verification

After rebuilding, the same steps gave `light_on` of 0 and `light` of nil after the off pulse.

Not checked: toggling the light through the gizmo's wire or interface path, and looking at the screen to see the light disappear. The check was on the light source datum only.

## Notes

- The other gizmo code that turns a light off was not searched, so other callers of `set_light_on()` on `COMPLEX_LIGHT` atoms were not reviewed.
