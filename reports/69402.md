# #69402: Removing a jumpsuit drops belt, ID and pocket items even with slots from other sources

| | |
|---|---|
| Issues | [#69402](https://github.com/tgstation/tgstation/issues/69402): not reproduced (already fixed on master) |
| Status | No change needed |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The 2022 report says that taking off a jumpsuit dropped everything in the belt, ID and pocket slots, even when the character still had those slots through a robotic torso augment. On master `87b93338` this does not happen: the drop is conditional on whether the slot can still be used without the jumpsuit, and robotic chest and legs (and `TRAIT_NO_JUMPSUIT`) keep the items in place. No fix was needed.

## The bug

As reported: with a robotic torso, items in the ID and belt slots, then equipping and removing a jumpsuit, all of the items fell to the floor. The reporter was unsure whether this was intended, but noted it makes no sense mechanically to lose a slot item while still having the slot.

## Reproduction

Using the Lua editor on the test server, after the round had started:

1. Spawned a human, replaced the chest with `/obj/item/bodypart/chest/robot` (`replace_limb`), put a PDA in the ID slot and a toolbelt in the belt slot, equipped a grey jumpsuit, then called `dropItemToGround` on the jumpsuit. Result: the PDA stayed in `wear_id`, the toolbelt stayed in `belt`, and `w_uniform` was empty.
2. Spawned a human with robotic left and right legs, a pen in the left pocket and a lighter in the right pocket, equipped the jumpsuit and removed it. Result: both pocket items stayed in place.
3. Control: an organic human with a belt item and a pocket pen, jumpsuit removed. The belt item and the pen both fell to the floor, so the test does detect the drop.

The jumpsuit was removed by a proc call, not through the player's unequip action.

## Cause

There is no defect. The relevant code is `code/modules/mob/living/carbon/human/inventory.dm:197-204`. When the uniform is removed, each slot item is dropped only if the slot would no longer accept it:

```dm
if(belt && !can_equip(belt, ITEM_SLOT_BELT, TRUE, ignore_equipped = TRUE))
	dropItemToGround(belt)
```

The slot checks in `code/modules/mob/living/carbon/human/_species.dm` (around lines 583-640) for belt, ID and both pockets require a jumpsuit unless the character has `TRAIT_NO_JUMPSUIT` or the relevant bodypart (chest, or the legs for pockets) is robotic (`!O || IS_ORGANIC_LIMB(O)` is the condition that demands a jumpsuit). So with the robotic parts, `can_equip` still succeeds and nothing is dropped. The unconditional drop described in the report was changed upstream before this master.

## Fix

None.

## Verification

The cases in Reproduction were checked on master. Not checked: items with `TRAIT_NODROP` in a pocket (`can_equip` refuses those in pockets, so they would still drop, which is arguably intended); items with an equip delay (only the collar bomb in the neck slot has one, which is not one of these slots); a robotic torso with a PDA and belt through the player's own unequip action; other sources of the slots (for example other species traits) beyond the ones named above.

## Notes

The issue can be closed as already fixed. If maintainers want a regression test, the three cases above (robotic chest, robotic legs, organic control) are small to write.
