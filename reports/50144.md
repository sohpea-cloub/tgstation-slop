## Summary

The issue (2020) reported that blob zombies have no languages and that their speech showed up to bystanders as "The blob zombie makes a strange sound." On current master the zombie does have an empty language holder, but that is deliberate: every blob minion is mute and can only talk through blob telepathy. The "makes a strange sound" message cannot be produced by a blob zombie any more, so the report is outdated and no fix was written.

## The bug

As reported, in March 2020 (testmerge of PR #49756) a blob zombie "spoke" and nearby players saw only "The blob zombie makes a strange sound." The reporter treated the missing languages as the bug. The only follow-up comment, from 2022, points at the relevant code in `code/game/say.dm`.

## Reproduction

Result: the reported behavior was not reproduced.

1. On the test server, started the round and joined as an observer with admin rights.
2. In the Lua editor, spawned a human, killed it (`death()`), spawned a `/mob/living/basic/blob_minion/spore` next to it and called the spore's `zombify()` proc on the corpse. This produced a blob zombie holding the corpse ("The corpse of ... suddenly rises!"). The Lua call itself reported an error about a destructed callback or userdata, because `zombify()` deletes the spore that Lua was holding; the zombie was created regardless.
3. Used the admin "Assume Direct Control" verb on the blob zombie.
4. Said "hello there" as the zombie.

Evidence: the only chat line produced was `[Blob Telepathy] blob zombie gurgles, "hello there"` (a radio-type message). No ordinary spoken message was sent, so bystanders got no "makes a strange sound" line.

This was reproduced by creating the zombie through `zombify()` directly, not by the spore actually attacking a corpse, and not by a real blob victory. Victory was not run on the test server; the statement below that victory zombies behave the same is from reading the code.

## Cause

There is no defect, only behavior that replaced the old one:

- `code/modules/mob/living/basic/blob_minions/blob_mob.dm:21` sets `initial_language_holder = /datum/language_holder/empty` on the abstract blob minion type, and `:36` gives every minion `TRAIT_MUTE`. A zombie therefore has no languages on purpose.
- `code/datums/components/blob_minion.dm:84` registers `on_try_speech` on `COMSIG_MOB_TRY_SPEECH`. The handler (`:173-176`) starts `send_blob_telepathy()` and returns `COMPONENT_CANNOT_SPEAK`. `try_speak()` in `code/modules/mob/mob_say.dm:84-88` checks that signal before any message is sent or a language is looked up, so normal speech never starts. `send_blob_telepathy()` (`:178-185`) relays the text to `GLOB.blob_telepathy_mobs` as `[Blob Telepathy] <name> ...`.
- "makes a strange sound." is returned only by `translate_language()` (`code/game/say.dm:312-314`) when a spoken message has a null language. Blob minions no longer reach that point.
- Zombies created by a blob win go through the same path. `victory_sequence()` (`code/modules/antagonists/blob/overmind.dm:236`) kills living people on blob-allowed station areas and calls `create_spore(..., spore_type = /mob/living/basic/blob_minion/spore)` on each (`:256`). Those spores zombify corpses through `zombify()` (`code/modules/mob/living/basic/blob_minions/blob_spore.dm:52`), which uses `change_mob_type()` and the blob zombie type, which inherits the minion's mute, empty-language setup.

## Fix

None. No commit was made.

## Verification

Not applicable, since nothing was changed. What was checked is limited to the reproduction above: one zombie made through `zombify()` and controlled by an admin, saying one phrase. Not checked: a zombie made by a spore attack on a corpse, a zombie from an actual blob victory, a zombie made by a factory spore (`zombie/controlled`), or a gold-core spore zombie. The code paths for these were read and appear to share the same minion setup.

## Notes

- The issue can probably be closed as outdated or by design. The mute-and-telepathy behavior for blob minions replaced whatever state the 2020 testmerge was in. Which change introduced this behavior was not traced.
- If a maintainer would rather give blob minions a real language so they could speak aloud, that would be a design change, not a fix for this report.
