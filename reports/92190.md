# #92190: Open pizza box with sliced pizza cannot be picked up

| | |
|---|---|
| Issues | [#92190](https://github.com/tgstation/tgstation/issues/92190): verified, fixed |
| Status | Reproduced and fixed; right-click pickup checked on the test server |
| Fix branch | [fix/92190](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/92190) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An open pizza box holding a sliced pizza, lying on the floor, gives a slice to anyone who clicks it with an empty hand, so the box itself can never be picked up. The cause is a branch in `/obj/item/pizzabox/attack_hand()` that always takes a slice in that state. The fix keeps left click as "take slice" and makes right click skip that branch, so right click picks the box up. It also adds a screentip that shows both actions.

## The bug

A player puts a pizza in a box, slices it, and drops the box. Because the box is open with a sliced pizza, every empty-hand click takes a slice instead of picking the box up. The box stays on the floor.

## Reproduction

1. Start a round on master and observe.
2. Using the Lua editor, spawn a human and possess it, and spawn an `/obj/item/pizzabox/margherita` on the adjacent floor tile. The box was set open, with its pizza sliced at init.
3. With an empty hand, left-click the box.

Observed: the human received a margherita slice in the left hand, and the box stayed on the floor. The test set the box up directly instead of slicing a pizza by hand, but the resulting state (open, sliced pizza, on the floor) is the one from the report.

## Cause

`/obj/item/pizzabox/attack_hand()` in `code/modules/food_and_drinks/pizzabox.dm:158` begins with:

```
if(user.get_inactive_held_item() != src)
	if(open && pizza?.sliced && !isobj(loc))
		pizza.produce_slice(user)
		...
		return
```

The condition (line 160) is true for any open, sliced box that is not inside another object, and it returns before the normal item pickup. A box on the floor therefore always produces a slice.

## Fix

One commit, "Fix issue 92190: right-click picks up a pizza box with sliced pizza", in `pizzabox.dm`:

- `attack_hand()` adds `&& !LAZYACCESS(modifiers, RIGHT_CLICK)` to the slice condition. Left click is unchanged. Right click falls through to ordinary pickup.
- `add_context()` shows `LMB: Take slice` and `RMB: Pick up` when the box is open, sliced, not inside an object, and the user is not holding it in their inactive hand.

Right click was chosen as a minimal interaction change. An upstream PR for this issue (#92954, closed without merging) proposed drag-click instead. That approach was not used.

## Verification

After rebuilding and restarting the test server, with the same setup, right-clicking the box on the floor put the pizza box in the player's left hand.

Not checked: that left click still takes a slice after the change (that branch only gained the extra condition), the new screentip text, slicing a pizza by hand rather than spawning it sliced, and boxes in a stack.

## Notes

- Which click picks up versus slices is a design choice. Alternatives are drag-click (as #92954 proposed), or letting the box be picked up once it holds no slices.
- Players who do not know about right click still cannot pick the box up by left click. The screentip is the only discoverability aid.
