The two issues are unrelated (both involve xenomorph visuals). They were worked in one unit. Only #39997 needed a code change.

## Summary

**#36017.** The issue asked for the queen's "small sprite" toggle to use the resting and crit sprites. That alternate sprite no longer exists. The queen's toggle is now the generic `seethrough_mob` component, which makes the player's own view of the mob semi-transparent by copying the mob's live render, so whatever icon state the mob is in (resting, unconscious, dead) is what the transparent copy shows. This was concluded from the code only: the see-through image is client-side and could not be inspected on the test server. No code was changed.

**#39997.** Dirt decals are drawn above alien weeds because they inherit the cleanable decal layer (18) while weeds sit at layer 15 on the same plane. The fix gives dirt a layer just below the weeds, so weeds cover dirt, and blood and other cleanables still draw on top of weeds.

## The bug

### #36017

In 2018 the alien queen had a button that swapped her large sprite for a smaller one, so she would not hit herself while moving. The report says the small sprite overrode the resting and crit sprites, so the queen stayed in the small standing sprite when she was lying down or in crit. The issue thread has no fix; the commenters discuss registering for rest and crit changes.

### #39997

A dirt decal on the same tile as alien weeds is drawn on top of the weeds, so the resin looks dirty and half hidden. Both screenshots in the issue (2018 and a 2023 confirmation) show this.

## Reproduction

### #36017

Not reproduced. This was a code investigation only. On master:

- `code/modules/mob/living/carbon/alien/adult/queen.dm:25`, in `/mob/living/carbon/alien/adult/royal/Initialize()` (so it applies to the royal subtypes, including the queen), adds `/datum/component/seethrough_mob`. `/datum/component/seethrough_mob/Initialize()` (`code/datums/components/seethrough_mob.dm:20`) grants a `toggle_seethrough` action.
- When toggled on, the component sets the mob's `render_target` to `*transparent_bigmob<uid>` (line 68), adds a render-source atom to the mob's `vis_contents`, and shows the owning client an `image` of that render source at a lower alpha (`target_alpha` defaults to 100). The image copies the mob's current appearance. It does not set any alternate icon or `icon_state`.
- The queen's icon state still comes from `/mob/living/carbon/alien/adult/update_icons()` (`code/modules/mob/living/carbon/alien/adult/adult_update_icons.dm`), which picks `alien<caste>_dead` or `_husked`, `_unconscious` (crit or paralyzed), `_sleep` (lying down) and so on. The see-through copy follows whatever that sets.
- A search of the alien code for "small", "smol" and "tiny" sprites found nothing for the queen.

So the 2018 "small sprite" no longer exists, and its replacement shows the live sprite. What was not checked: the transparent image itself. It exists only on the owning client, so it could not be viewed through the test server's tools, and the queen was not put into crit or lying down with the toggle active. A queen was spawned (icon state `alienq`) but nothing further was done with it.

### #39997

1. Using the Lua editor on the test server, spawn an `/obj/effect/decal/cleanable/dirt` and an `/obj/structure/alien/weeds` on the same turf. (A `/obj/effect/decal/cleanable/blood` was spawned there too in the check after the fix.)
2. Read the layers. On master the weeds had layer 10015 and plane -6 (`FLOOR_PLANE`). Dirt does not set its own layer, so it inherits the cleanable layer 10018 on the same plane. The dirt therefore draws over the weeds.

Only the layer values were recorded before the fix. A screenshot of the tile was taken before the fix too, but what it showed was not noted, so the "dirt covers weeds" result rests on the layer values and the issue's screenshots.

## Cause

### #36017

No defect. The behaviour in the issue belongs to a feature that was replaced (see Reproduction).

### #39997

`/obj/structure/alien/weeds` sets `layer = ABOVE_OPEN_TURF_LAYER` and `plane = FLOOR_PLANE` (`code/game/objects/structures/aliens.dm:138-139`). `ABOVE_OPEN_TURF_LAYER` is `15 + TOPDOWN_LAYER` (`code/__DEFINES/layers.dm:192`). `/obj/effect/decal/cleanable` sets `layer = CLEANABLE_FLOOR_OBJECT_LAYER` (`code/game/objects/effects/decals/cleanable.dm:3`), which is `18 + TOPDOWN_LAYER` (`layers.dm:195`). `/obj/effect/decal/cleanable/dirt` (`code/game/objects/effects/decals/cleanable/mess.dm:66`) did not override the layer, so on the shared floor plane it is drawn 3 layers above the weeds.

## Fix

**Fix issue 39997: alien weeds are no longer covered by dirt.** `/obj/effect/decal/cleanable/dirt` in `mess.dm` now sets:

```dm
/// Below ABOVE_OPEN_TURF_LAYER so things lying on the floor, like alien weeds, cover the dirt instead of being covered by it
layer = ABOVE_OPEN_TURF_LAYER - 0.1
```

`/obj/effect/decal/cleanable/dirt/dust` is a subtype and inherits it. I changed only the dirt type, rather than changing the cleanable layer or the weeds' layer, because that is the narrowest change that fixes the report and does not move blood, runes or other floor objects relative to the weeds.

No change was made for #36017.

## Verification

After rebuilding and starting the test server, the same three objects (dirt, blood and weeds) were spawned on one turf using the Lua editor:

- Layers read back: dirt 10014.9, weeds 10015, blood 10018, with all three on plane -6.
- A close-up render of the tile showed the weeds with the blood on top and the dirt hidden under the weeds.
- The build finished with no errors. The runtime log was not examined beyond that.

Not checked:
- Dirt on a floor with a smoothed (tiled) dirt icon versus the flat icon was not compared.
- Weed nodes and other weed subtypes were not tried; only `/obj/structure/alien/weeds` was.
- No before and after render was compared side by side, and no comparison was made of how the dirt looks at its edges where it overlaps neighbouring tiles.

## Notes

- **Side effect on layer order.** Dirt now draws below everything on the floor plane that sits above layer 10014.9, not only weeds. The report notes that this includes runes (`LOWER_RUNE_LAYER` is 16 and `RUNE_LAYER` is 17, `layers.dm:193-194`) and other cleanables at layer 18. Before, dirt shared layer 18 with the other cleanables and drew above the runes. The dirt would now be hidden under a rune drawn on the same tile. This was judged minor and was not examined further; a maintainer may prefer a smaller change.
- **#36017 can probably be closed.** The 2018 small sprite was replaced by the generic see-through component. A client-side check of how that component looks for a queen in crit or lying down would settle it fully.
