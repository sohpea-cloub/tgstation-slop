## Summary

Three language-related issues were worked together. #62176: the HUD "language menu" button used the clicker's language holder instead of the holder of the mob whose HUD it is, so an observer clicking an observed mob's button got their own menu; it now opens the HUD owner's menu. #62523: the Compli-o-Nator (sechailer mask) printed its phrases as plain text to everyone in earshot, so drones and others who do not understand Common could read them; the phrase is now translated per listener. #76316 (species languages stored on the body rather than the brain) could not be reproduced as described on current master, where languages live on one holder per atom by design, and was not changed.

## The bug

### #62176

An observer (ghost) orbiting or observing another mob sees that mob's HUD. Clicking the HUD's language menu button showed the observer's own menu (with the Grant/Remove controls and omnitongue an admin ghost has), not the observed mob's. The reporter noted that non-admins could not change anything in it, but that it should not open the observer's menu at all.

### #62523

Phrases from the Compli-o-Nator are spoken in Common, but they were delivered with `audible_message()`, which sends the same raw text to every hearer. A drone (whose language holder blocks understanding Common) therefore read "HALT! HALT! HALT!" as if it understood it. The issue says it also applies to other things beyond the Compli-o-Nator; only the hailer was examined.

### #76316

Reported: a non-human's brain moved into an MMI speaks only Galactic Common; put back into its body it speaks its species language again; a human brain put into a lizard body can speak Draconic. Commenters added that a forced race swap loses languages learned from books. A maintainer's comment says species languages are atom languages by design and that a 1-holder-per-mob cleanup (and removing the mind holder) is wanted.

## Reproduction

All steps used the Lua editor to set up state on the test server; the language-menu click and the hailer output were observed in game.

### #62176

1. Spawn a pAI (`/mob/living/silicon/pai`) and possess it from the Lua editor with `pai:PossessByPlayer(ckey)`, so that it has a HUD. (A pAI that never had a client has no `hud_used`.)
2. Aghost, then from the Lua editor make the ghost observe the pAI with `ghost:do_observe(pai)`.
3. Click the "language menu" button on the pAI's HUD (bottom right area).
4. Read the opened LanguageMenu's data.

Observed on master: `is_living` = 0 and `omnitongue` = 1, which is the ghost's own menu. Expected: the pAI's.

### #62523

1. Spawn a human with a `/obj/item/clothing/mask/gas/sechailer` and a drone (`/mob/living/basic/drone`) nearby, and possess the drone.
2. Make the human play a hailer phrase (the Lua editor was used to trigger it with a timer, which fired late, so the messages appeared in the next call's output).
3. Read the drone's chat.

Observed on master: the drone saw "HALT! HALT! HALT!" in plain text.

### #76316

Not reproduced as a bug. Using the Lua editor on a lizard-species human and a plain human: moving the human's brain into the lizard body left the body with Draconic (from the body), and a language granted to the human's mind (Codespeak) was no longer present afterwards. A species change (human to lizard) kept the mind-granted Codespeak and added Draconic. Moving a brain into an MMI: the brain mob copied no languages; no language-copying code was found in the brain or MMI code.

## Cause

### #62176

`code/_onclick/hud/screen_objects/screen_objects.dm:175-176`:

```
/atom/movable/screen/language_menu/Click()
	usr.get_language_holder().open_language_menu(usr)
```

`usr` is whoever clicked, which for an observed HUD is the observer, not the mob the HUD belongs to (`get_mob()` returns `hud?.mymob`, line 97).

### #62523

`code/modules/clothing/masks/hailer.dm:185`: `play_phrase` called `user.audible_message("[user]'s Compli-o-Nator: ...[initial(phrase.phrase_text)]...")`. `audible_message()` does no per-hearer translation, so the text reaches everybody regardless of what they understand.

### #76316

Current master has no separate mind language holder in use: there is one holder per atom, and species languages are applied to the body with source `LANGUAGE_SPECIES`. Languages therefore follow the body for species, while languages granted to the mind (`LANGUAGE_MIND`, for example by ghost roles) stay with the mob across species changes. This matches the maintainer's comment rather than being a defect in a code path.

## Fix

- **"Fix issue 62176: language menu button opens the menu of the mob whose HUD it is"**: `Click()` now uses `var/mob/menu_owner = get_mob() || usr` and calls `menu_owner.get_language_holder().open_language_menu(usr)`: the holder comes from the HUD's mob, the menu is still opened for the clicker, and `usr` is the fallback when the button has no HUD mob.
- **"Fix issue 62523: Compli-o-Nator phrases are gibberish to listeners who don't understand common"**: instead of `audible_message()`, `play_phrase` loops over `mob_only_listeners(get_hearers_in_view(DEFAULT_MESSAGE_RANGE, user))`, skips mobs without a client, runs the phrase through `hearing_mob.translate_language(user, /datum/language/common, phrase_text)` and sends it with `show_message(..., MSG_AUDIBLE)`. This keeps the existing message format and uses the same translation routine as normal speech.

No change for #76316.

## Verification

- **#62176** (fixed build, same steps): `is_living` = 1, `omnitongue` = 0, speak list Galactic Common / Galactic Uncommon / Encoded Audio Language, which is the pAI's. After the ghost stopped observing (`reset_perspective`), its own button gave `is_living` = 0, `omnitongue` = 1 as before. No language-related runtimes in `runtime.log`.
- **#62523** (fixed build): the drone saw "AREDUI! AREDUI! AREDUI!" (gibberish); a human nearby still saw "HALT! HALT! HALT!".
- Not checked: the opposite menu for non-admin observers in game (see Notes); hailer output for other hearer types (deaf, no client, silicons other than drones); other `audible_message` callers that may have the same problem; the `/halt` verb at `hailer.dm:208`, which still uses `audible_message` with a fixed "HALT!" (not changed).

## Notes

- Non-admin observers: the menu's UI state (`code/modules/tgui/states/language_menu.dm`) closes the UI for anyone who is neither an admin nor the holder's owner. After the fix a non-admin observer clicking the observed mob's button opens nothing; before, they saw their own menu. This was reasoned from the code, not tested as a non-admin.
- #62176's last line (the same happens on people, not only pAIs) is covered by the same code path.
- #62523: the issue says "includes but is not limited to" the Compli-o-Nator; other sources of plain-text speech were not searched for.
- #76316: making languages follow the brain/mind would be a refactor (one holder per mob updated by species changes, and the mind holder removed), not a small fix. The part about a forced race swap losing book-learned languages did not occur in the test. If maintainers still want the refactor, the issue should stay open as a design item.
