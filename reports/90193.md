# #90193: Mirror reflections aren't disguised if you hold a plant

| | |
|---|---|
| Issues | [#90193](https://github.com/tgstation/tgstation/issues/90193): verified, fixed |
| Status | Fixed (one commit), checked in game on a test server with a spawned human and a directional mirror |
| Fix branch | [fix/90193](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/90193) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A mob holding a potted plant is shown to other players as the plant, but a mirror still reflects the real mob. The disguise is an alternate-appearance image, which is not part of the mob's own `appearance`, and the reflection component copies only `appearance`. The fix makes the tactical component rewrite the reflection with the item's appearance while the disguise is active, and refreshes the user's appearance when the disguise ends so the reflection reverts.

## The bug

Items with the tactical component (the potted plant, for example) disguise the holder: other players see the item instead of the mob, and the examine text changes. A mirror in front of the holder still shows the holder's normal body, so the disguise is visibly broken.

## Reproduction

On master, with admin tools:

1. Using the Lua editor, spawn a `/obj/structure/mirror/directional/north`, a `/mob/living/carbon/human` and an `/obj/item/kirbyplants` on one turf.
2. Call `put_in_hands` on the human with the plant.
3. Read the reflection through the mirror's `vis_contents` (nested one level: `mirror.vis_contents[1].vis_contents[1]`) and render the tile.

Observed before the fix: the reflection showed the human's body, not the plant.

This was reproduced with a Lua-spawned human and a mirror that was not mounted on a wall, not with a player picking up a plant at a real station mirror.

## Cause

`code/datums/components/tactical.dm:60-71` (`on_icon_update`) builds the disguise as an `image` of the held item with `override = TRUE` and attaches it to the user with `add_alt_appearance`. That image is only shown to clients; it does not change the mob's `appearance`.

`code/datums/components/reflection.dm:169-171` (`copy_appearance_to_reflection`) builds each reflection with `reflection.appearance = copy_appearance_filter_overlays(target.appearance)`, so mirrors always show the real mob. After updating a reflection, the component sends `COMSIG_REFLECTION_UPDATED` (`reflection.dm:206`), which the tactical component did not use.

## Fix

One commit, "Fix issue 90193: Mirror reflections are disguised by tactical items (potted plants)", changes `code/datums/components/tactical.dm`:

- `modify` registers `COMSIG_REFLECTION_UPDATED` on the user, and `unmodify` unregisters it.
- The new `on_reflection_updated` handler sets `reflection.appearance = copy_appearance_filter_overlays(master.appearance)` from the held item, then restores the reflection's `vis_flags`, `transform`, `dir`, `pixel_x`, `pixel_y` and `name`, so only the visuals change and the reflection keeps its placement and its "<mob>'s reflection" name.
- `unmodify` now calls `user.update_appearance(UPDATE_ICON)` (when the user is not deleted and is a mob). Without this, the reflection stayed on the plant after the item was dropped until something else, such as a direction change, refreshed it. This part was added after the first test run showed that stale reflection.

## Verification

In game on the test server, reading the reflection after each step:

- Plant held: the reflection used `plants.dmi` state `plant-01`, named "potted plant's reflection", with no overlays.
- Plant dropped with `dropItemToGround`: the reflection reverted to `human.dmi`, named after the human, with 16 overlays (the real mob).
- Plant picked up again: the reflection showed `plant-01` again.
- The server log showed no runtimes other than those from Lua proc calls.

Not checked: a real station mirror on a wall, a player picking up or dropping the plant normally, and any other tactical item. Other disguise paths, such as photos, were not tested.

## Notes

- The reflection copy is made once per reflection update, so a held item whose appearance changes later is only picked up on the next reflection update.
- The handler uses the item's whole appearance, as the alt-appearance image does, rather than trying to merge it with the mob's.
- Posters in the thread consider the bug funny; the issue is labelled Oversight and is not marked as intended behaviour.
