## Summary

The issue reported that using a design disk on an autolathe ended with an "interrupted!" alert and no design was imported. That came from an inverted `do_after` check in the autolathe's disk-loading code. It was fixed upstream by PR #90170 ("fix inverted autolathe check", merged 2025-03-23), and the fix is in master `87b93338`. Uploading a design disk was tested on master and worked, so no change was made.

## The bug

As reported (client 515.1647, round 250390): using any design disk on any autolathe, the reporter's example being the illegal 3D printer design disk, showed "interrupted!" at the end of the upload. A commenter on 2025-03-29 said they still saw it.

## Reproduction

On master `87b93338`, using the Lua editor on the test server:

1. As a player mob, spawn an autolathe (`/obj/machinery/autolathe`) and an illegal 3D printer design disk (`/obj/item/disk/design_disk/liberator`) next to yourself.
2. Hold the disk and click the autolathe.
3. Observed: the chat showed "begins to load the illegal 3D printer design disk in the autolathe...", the progress bar ran and the balloon said "uploading design...". After 1.5 seconds there was no "interrupted!" alert.
4. Querying the autolathe with SDQL2: `imported_designs` contained `/datum/design/liberator_gun` and `busy` was 0.

So the upload completed and the design was imported. The bug does not occur on master.

## Cause

This is the cause of the old bug, taken from the history of the disk-loading code in `code/game/machinery/autolathe.dm`: the check after the progress bar was inverted, `if(do_after(...))`, so a successful upload took the "interrupted!" branch and only an actual interruption imported the designs. The current code at `code/game/machinery/autolathe.dm:494-498` reads:

```
if(!do_after(user, 1.5 SECONDS, target = src))
	busy = FALSE
	update_static_data_for_all_viewers()
	balloon_alert(user, "interrupted!")
	return ITEM_INTERACT_BLOCKING
```

which is correct: "interrupted!" only appears when `do_after` fails. The old inverted form was identified from the upstream fix; it was not re-created on this build.

## Fix

None. Upstream PR #90170 already contains it.

## Verification

The upload was run once on master with the illegal 3D printer design disk, with the result above. Not checked: other design disks, disks with designs the autolathe cannot build, or actually interrupting the upload by moving away.

## Notes

The commenter who reported the issue still occurring on 2025-03-29 was after the merge date of the fix (2025-03-23). That could be a server that had not yet updated; this was not investigated.
