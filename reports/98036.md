# #98036: powercrepes are always made as iron-glass powercrepes

| | |
|---|---|
| Issues | [#98036](https://github.com/tgstation/tgstation/issues/98036): verified, fixed |
| Status | Fixed; verified by spawning, not by a real craft |
| Fix branch | [fix/98036](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/98036) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

`/obj/item/food/Initialize()` is meant to mark the item's largest custom material as "intrinsic" to the food, so that material does not rename or recolor it. Its loop never updates the running maximum, so it picks the last listed material instead of the largest. For the powercrepe that is glass rather than iron, so iron is treated as a foreign material and the food becomes translucent and is named "iron-glass powercrepe". The fix updates the maximum inside the loop.

## The bug

Per the issue, a crafted powercrepe is translucent and named "iron-glass powercrepe". The issue guessed this came from the super power cell ingredient being made of iron and glass. The cause is how the food picks its intrinsic material, not the cell itself.

## Reproduction

1. On master, using the Lua editor on the test server, spawn `/obj/item/food/powercrepe` with `SS13.new`.
2. Read its `name` and `alpha`.

Observed: name "iron-glass powercrepe", alpha 249, on a plain spawn (crafting is not needed to trigger it).

An actual recipe craft was not performed: calling `construct_item` from Lua returned nil for the cooking recipe even with the ingredients and a milk/cherry jelly beaker present (probably because of the recipe's timed action or requirement checks; not investigated further). The reproduction is therefore a spawn, not the player action.

## Cause

`/obj/item/food/Initialize()` in `code/modules/food_and_drinks/food/_food.dm:72-79`:

```dm
var/main_mat_type = null
var/mat_amount = 0
for(var/mat_type in custom_materials)
	if(custom_materials[mat_type] > mat_amount)
		main_mat_type = mat_type
LAZYADD(intrinsic_food_materials, main_mat_type)
```

`mat_amount` stays 0, so every material with a positive amount passes the comparison and `main_mat_type` ends as the last one in the list. The powercrepe's materials are iron 2400 and glass 70 (the observed values after combining the ingredients, see Verification), so glass was chosen although iron is far larger. Iron is then not in `intrinsic_food_materials`, and `apply_material_effects` (the same file, around line 118, `is_type_in_typecache(main_material, intrinsic_food_materials)`) applies the material prefix and color, which gives the new name and the reduced alpha.

## Fix

One commit, "Fix issue 98036: powercrepes are always made as iron-glass powercrepes", adds one line inside the loop in `code/modules/food_and_drinks/food/_food.dm`:

```dm
main_mat_type = mat_type
mat_amount = custom_materials[mat_type]
```

This makes the code do what its structure already implied (pick the largest). No alternative was weighed.

## Verification

After rebuilding:

- A spawned powercrepe had name "powercrepe" and alpha 255.
- Calling `set_custom_materials` on one with the crafted material sum (iron 2400, glass 70) also left it named "powercrepe" with alpha 255.

Not checked: a true craft of the recipe (see Reproduction). The agents reasoned that the crafted sum matches the typedef (super cell iron 1400 plus the captain's sabre iron 1000, and glass 70), so the same code path applies; that was not tested by crafting. Other multi-material food types were not individually tested.

## Notes

- The change affects every food type with several custom materials: only the largest material is now intrinsic, whereas before it was the last one listed. Foods whose materials were relying on the old behavior should be checked by a maintainer.
- A comment on the issue suggests the real fix would be giving the captain's sabre an iron-gold material. That is a separate content change and is not part of this fix.
