## Summary

The abductor console's "Set Experiment Release Point" action accepted any open turf, because `SetDroppoint()` only checked the turf type. The other camera-console actions (teleporting the agent in or sending the agent to a place) refuse teleport-shielded areas and turfs not covered by cameras, but the release point did not. The fix adds the same area and camera checks to `SetDroppoint()`, so a release point on CentCom, in space or off camera is refused.

## The bug

As an abductor, a player can use the camera eye to select any turf as the experiment release point, including anywhere on the CentCom level, on or off camera, and open space. When an experimented-on subject is sent back, they are moved there with no further checks. The reporter describes using this to strand people on CentCom or in space. A commenter asks whether this reopens #25600, where abductors could tour CentCom with the emergency teleport.

## Reproduction

Reproduced on master with admin tools. The player action was not performed through the camera eye UI, which needs a full abductor team. Instead the proc the action calls was invoked directly.

1. Start a round, observe, and open the Lua editor.
2. Spawn an `/obj/machinery/abductor/console` and an `/obj/machinery/abductor/pad`, and set the console's `pad` to the spawned pad.
3. Call `console:SetDroppoint(turf, user)` on a chosen turf. This is the whole body of the "Set Experiment Release Point" action (`code/modules/antagonists/abductor/machinery/camera.dm:158`: `console.SetDroppoint(remote_eye.loc,owner)`).

Observed on master:
- Two open space turfs on the CentCom z-level, (107,100,1) and (100,90,1), where `SScameras.is_visible_by_cameras` returned 0: both answered "Location marked as test subject release point." and `pad.teleport_target` was set.
- A camera-covered hallway on the station was also accepted (expected).

## Cause

`code/modules/antagonists/abductor/machinery/console.dm:200`:

```dm
/obj/machinery/abductor/console/proc/SetDroppoint(turf/open/location,user)
	if(!istype(location))
		to_chat(user, span_warning("That place is not safe for the specimen."))
		return

	if(pad)
		pad.teleport_target = location
```

The only validation is that the location is an open turf. The sibling actions in `code/modules/antagonists/abductor/machinery/camera.dm` do more: they refuse areas with `NOTELEPORT` (except the abductor ship, lines 65 and 109) and turfs that `SScameras.is_visible_by_cameras()` does not cover (lines 75 and 119). The camera eye can move anywhere, including CentCom. When the experiment ends, `send_back()` does `H.forceMove(console.pad.teleport_target)` without any check (`code/modules/antagonists/abductor/machinery/experiment.dm:189`).

## Fix

One commit on `fix/84633`: **Fix issue 84633: Abductor release point obeys the teleport and camera restrictions**.

After the open-turf check, `SetDroppoint()` now:
- refuses a location whose area has `NOTELEPORT` (unless it is `/area/centcom/abductor_ship`) or is `motion_monitored`, with "This area is too heavily shielded to safely release the specimen there.";
- refuses a location not visible to cameras, with "That place is not covered by cameras, so the specimen cannot be safely released there."

These are the same conditions as the "Send To" action. The check was put in `SetDroppoint()` rather than in the action so every caller gets it, and so `send_back()` only ever receives a validated target.

## Verification

On the test server after rebuilding, calling `SetDroppoint()` the same way:

- CentCom open space: refused.
- Thunderdome arena open floor (not visible to cameras): refused.
- Off-camera maintenance plating in several areas (Aft Port, Central, Lesser Aft, Central Science, Lesser Starboard, Aft Starboard, Xenobiology): refused with the "not covered by cameras" message.
- Camera-covered station tiles (a hallway, Lesser Fore maintenance plating, Engineering maintenance, solars): still accepted.
- The "too heavily shielded" message was seen once (for the `NOTELEPORT`/motion-monitored check).

Not checked: the real camera eye UI and the full abductor flow (baton, organ, analysis machine, send-back), and whether the abductor ship area itself is still accepted as a release point.

## Notes

- Release points are now limited to camera-visible, non-shielded open turfs. A maintainer may want to confirm that is the desired rule, or whether the abductors' own ship should stay allowed.
- The commenter's question about #25600 was not tested; the fix closes the release-point route only.
- Side finding, not fixed: `Send()` in `code/modules/antagonists/abductor/machinery/pad.dm` (around line 21) with no target assigns an entry of `GLOB.teleportlocs`, which is an area, to a turf variable. This was spotted while reading and is a separate, pre-existing oddity.
