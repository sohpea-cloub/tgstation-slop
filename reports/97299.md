# #97299: Simple bots resist out of closed crates

| | |
|---|---|
| Issues | [#97299](https://github.com/tgstation/tgstation/issues/97299) verified, fixed; [#98118](https://github.com/tgstation/tgstation/issues/98118) duplicate of #97299, fixed by the same commit |
| Status | Reproduced on master and fixed on the branch below; fix checked in game with spawned crates and the supply pack's `generate()` |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97299 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Most simple bots (medibot, repairbot, cleanbot, firebot, honkbot, hygienebot, vibebot, and any bot on the base bot tree) use the `escape_captivity/pacifist` behavior subtree. Its "contained in an object" branch makes the bot resist, and resisting inside an unlocked, unwelded crate just opens it. A bot closed into a crate, including the ones in the Emergency Bot/Internals Crate, therefore climbs out about a second later. The fix adds a `dopey` variant of the subtree that only resists grabs and restraints, and switches those bots to it. Security bots and ED-209s keep the old behavior.

## The bug

Closing a medibot or repairbot in a crate does not hold it. Both issues describe the same thing from different angles: #97299 notes that this makes ordering the bot/internals crate pointless and gets in the way of carrying bots around in a crate, and #98118 reports that the bots in the Emergency Bot/Internals Crate break out immediately on the supply shuttle. A comment on #97299 suggests that regular bots should be dopey and easy to contain, while security bots should keep resisting.

## Reproduction

Done with the Lua editor as an admin on the test server (the round had been started and the admin was observing).

1. Spawn a `/obj/structure/closet/crate`, a `/mob/living/basic/bot/medbot` and a `/mob/living/basic/bot/repairbot` on adjacent turfs.
2. `forceMove` both bots into the crate and call `close()` on the crate.
3. Wait one second (`SS13.wait(10)` in Lua) and read the crate's `opened` var and the bots' `loc`.

Observed on master: the crate was open (`opened` = 1) and both bots were on the floor, within about a second of closing it.

The Emergency Bot/Internals Crate (#98118) was not spawned before the fix, so its exact "before" state was not observed; it is the same two bot types in a crate, and the cause below applies to it directly.

This was done by moving the bots in with `forceMove` and calling `close()`, not by a player stuffing a bot into a crate or by ordering through the cargo console.

## Cause

Every bot behavior tree starts with the escape subtree, for example `code/modules/mob/living/basic/bots/bot.bt.json:7`:

```json
"subtype": "/datum/bt_node/subtree/escape_captivity/pacifist"
```

The per-bot trees (`medbot.bt.json`, `repairbot.bt.json`, `cleanbot.bt.json`, `firebot.bt.json`, `honkbot.bt.json`, `hygienebot.bt.json`, `vibebot.bt.json`, each in its bot's directory under `code/modules/mob/living/basic/bots/`) do the same.

`code/datums/ai/basic_mobs/basic_subtrees/escape_captivity_pacifist.bt.json` is a selector with four branches, each calling the `resist` behavior, gated on: the pawn being buckled to an object, the pawn being contained in an object (`pawn_contained_in_obj`), the pawn being grabbed by an enemy, and the pawn being restrained. The `resist` behavior (`code/datums/ai/generic_behaviors/resist.dm`) calls `execute_resist()` on the bot. For a bot inside a closet or crate that ends up in `/obj/structure/closet/container_resist_act()` (`code/game/objects/structures/crates_lockers/closets.dm:1085`), which for a closet that is neither welded nor locked simply calls `open(user)`. So the contained-in-object branch is enough to open any ordinary crate as soon as the bot is closed in.

## Fix

One commit on `fix/97299`: **"Fix issue 97299: regular bots no longer resist out of crates"**.

- Adds `/datum/bt_node/subtree/escape_captivity/pacifist/dopey` (`code/datums/ai/basic_mobs/basic_subtrees/escape_captivity.dm`) with a new tree, `escape_captivity_dopey.bt.json`. It has only the two branches for being grabbed by an enemy and being restrained; the buckled and contained-in-object branches are left out.
- Switches `bot.bt.json`, `cleanbot.bt.json`, `firebot.bt.json`, `honkbot.bt.json`, `hygienebot.bt.json`, `medbot.bt.json`, `repairbot.bt.json` and `vibebot.bt.json` to the dopey subtree.
- Leaves secbot, ED-209 (and the Syndicate ED-209) and dedbot as they were. The secbot case follows the suggestion in the #97299 thread that security bots should keep resisting.
- The commit also contains the compiled behavior-tree JSON under `build/behavior_trees/`, because those compiled files are tracked in the repository: one new file for the dopey tree and the changed compiled files of the eight edited trees.

The alternative of keeping the pacifist subtree and adding a variable or a blackboard flag to skip the container branch was not tried; a separate subtree follows how the existing `pacifist` variant is already done and needs no changes to the decorators.

## Verification

After rebuilding and restarting the test server with the fix, using the same kind of Lua setup as above and waiting 1.5 seconds:

- A crate with a medibot and a repairbot stayed closed, with both still inside.
- A second crate with a security bot opened and ended up empty, so secbots still escape, as intended.
- A crate made by calling `generate()` on `/datum/supply_pack/emergency/equipment` (the Emergency Bot/Internals Crate) stayed closed, with 2 medibots, 2 repairbots, 5 emergency oxygen tanks and 5 breath masks inside. The medibot kept talking from inside.

No new runtimes were seen from the change; the only runtimes in the log came from the checking script itself (Lua reading `opened` on objects that are not crates).

Not checked:

- Buying the pack through a cargo console and sending it on the shuttle.
- That a dopey bot still resists a grab or handcuffs (the two kept branches). They are copies of the old branches, but they were not exercised.
- Bots buckled to chairs, which the new subtree no longer resists (see Notes).
- Welded or locked crates (the bot is not expected to open those; `container_resist_act()` has its own path for them).
- The remaining bots that use the `pacifist` subtree through other trees, and other `pacifist` users outside the bots directory (animals such as spiderlings, seedlings, gutlunchers), which are unchanged.

## Notes

- The dopey subtree also drops the "buckled to an object" branch. A bot buckled to a chair will no longer free itself. This matches the "boxed or sat in a chair" remark in the #97299 thread, but it goes beyond the crate bug in the issue titles and was not tested.
- Mulebots have no escape subtree in their tree and were not touched.
- The pack description in `code/modules/cargo/packs/emergency.dm` says "two floorbots", but the pack contains two repairbots. This is unrelated and was left alone.
