# #80733: Frogs become solid mobs upon revival

| | |
|---|---|
| Issues | [#80733](https://github.com/tgstation/tgstation/issues/80733): fixed |
| Status | Fixed and verified in game |
| Fix branch | [fix/80733](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/80733) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A frog is a non-dense mob that players can walk over. After it died and was revived it became dense and blocked movement. `update_density()` in `living.dm` set density to TRUE whenever `TRAIT_UNDENSE` was absent. Dying and reviving adds and then removes that trait on basic mobs, so any mob whose own density is FALSE ended up solid. The fix restores the type's initial density instead of forcing TRUE.

## The bug

As reported, a live frog can be stepped on (with its squish sound). After it is killed and revived (the reporter used the revival surgery), it can no longer be walked over, like a standing human, unless the walker is resting.

## Reproduction

On master `87b93338`, with the Lua editor on the test server:

1. Spawned a frog with `SS13.new('/mob/living/basic/frog')`.
2. Read its `density`, called `death()`, read it again, called `revive(1)`, and read it a third time.
3. Result before the fix: density `0` (alive), `0` (dead), `1` (revived), so the revived frog is solid.

Controls with a human, via SDQL: density 1 while standing, 0 while resting, 1 again after standing up. This calls `death()` and `revive()` directly rather than performing the revival surgery, but the density change comes from the same code path.

## Cause

`code/modules/mob/living/living.dm:758`:

```dm
/mob/living/proc/update_density()
	if(HAS_TRAIT(src, TRAIT_UNDENSE))
		set_density(FALSE)
	else
		set_density(TRUE)
```

Basic mobs add `TRAIT_UNDENSE` in `look_dead()` and remove it in `look_alive()` (`code/modules/mob/living/basic/basic.dm:205` and `:220`). When the trait goes away on revival, `update_density()` sets density to TRUE regardless of what the mob's density was to begin with. Frogs (`code/modules/mob/living/basic/vermin/frog.dm`) and other vermin start with `density = FALSE`, so they turn solid. The same happens whenever any source of `TRAIT_UNDENSE` is removed from such a mob, not just on revival.

## Fix

One commit, "Fix issue 80733: mobs that start non-dense (frogs) become dense after losing TRAIT_UNDENSE", changes the fallback in `update_density()` from `set_density(TRUE)` to `set_density(initial(density))`. A mob that starts dense still becomes dense again, and a mob that starts non-dense stays non-dense.

## Verification

With the fix built on the test server, the same frog sequence gave density `0`, `0`, `0` (alive, dead, revived). Before the fix it was `0`, `0`, `1`.

Not checked: the actual revival surgery, walking a character over a revived frog, other non-dense mobs (the other vermin), and mobs that have `TRAIT_UNDENSE` applied from other sources.

## Notes

- `initial(density)` ignores any density change made at runtime by other code for a mob type. None was found, but a later change that sets a mob's density permanently at runtime would be overwritten by `update_density()`.
- The trigger is general: any `/mob/living` with `density = FALSE` that gains and then loses `TRAIT_UNDENSE` is affected, not just frogs.
