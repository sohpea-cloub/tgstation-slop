# #73778: Several Voice of God input windows can be opened at once, so the spell's cooldown is bypassed

| | |
|---|---|
| Issues | [#73778](https://github.com/tgstation/tgstation/issues/73778): fixed (the fix was checked in game; the unfixed bypass was inferred from the code, see Reproduction) |
| Status | Fixed on the branch, one commit |
| Fix branch | [fix/73778](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/73778) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The Voice of God spell (and its Voice of Clown subtype) opens a text prompt when it is cast, and the cooldown only starts after the prompt is answered. Clicking the action again while the first prompt is still open opens a second prompt, and every open prompt can be submitted. After the prompt, `before_cast()` re-validated the caster with `can_cast_spell()`, which does not look at the cooldown. The fix uses `IsAvailable()` there, which checks the cooldown as well, so a second prompt answered after the first cast is cancelled.

## The bug

The report was made with the admin-granted "Voice of Clown" spell on a mob during an event. Clicking the spell repeatedly opens several "Speak with the Voice of God" windows. Each one can be submitted and recites its phrase and applies its effect, even though the spell goes on cooldown after the first one. The reporter ended up with a chain of "drop" commands. A commenter noted that the Colossus's vocal cords do not have this problem because they store the time the cooldown ends and check it on every invocation, while the spell variant did not.

## Reproduction

All steps used the Lua editor, a test round, and a normal player-style click on the action button.

1. Join the round as a crew member, open the Lua editor and grant the spell to yourself: `SS13.new('/datum/action/cooldown/spell/voice_of_god/clown'):Grant(me)`. The "Voice of Clown" button appeared.
2. Click the button twice before answering. Two "Command" prompts opened (the second was not refused).
3. Submit "first" in the first prompt and "second" in the second prompt.

Result on unmodified master: the character said "FIRST" and then "SECOND", with the spell's horn sound on each. The spell was cast through both windows.

Limits of this reproduction:

- In that run no listeners were in range and no command word matched. In that case `voice_of_god()` returns null and `cast()` sets `cooldown_time` to 0 (see Notes), so the spell had no cooldown at all and nothing was actually bypassed. The run shows that two prompts can be open and both can be cast, but it does not show the cooldown being skipped.
- The unfixed code was not rebuilt and rerun with a listener nearby. That the bypass is real follows from the code (see Cause) and from the fixed build refusing the second cast in exactly this setup.

## Cause

Casting a spell goes through `Activate()` in `code/modules/spells/spell.dm:261-290`:

```dm
var/precast_result = before_cast(cast_on)
if(precast_result & SPELL_CANCEL_CAST)
	return FALSE
...
cast(cast_on)
if(!(precast_result & SPELL_NO_IMMEDIATE_COOLDOWN))
	StartCooldown()
```

The cooldown is only checked at click time, by `IsAvailable()` (`code/datums/actions/cooldown_action.dm:133-134` and its callers, `code/modules/spells/spell.dm:130-131`), and it is only started after `cast()` returns. Voice of God's `before_cast()` blocks on a text prompt in between:

```dm
command = tgui_input_text(cast_on, "Speak with the Voice of God", "Command", max_length = MAX_MESSAGE_LEN)
if(QDELETED(src) || QDELETED(cast_on) || !can_cast_spell())
	return . | SPELL_CANCEL_CAST
```
(`code/modules/spells/spell_types/self/voice_of_god.dm:23-33`, the check is on line 29)

While the first prompt is open, the cooldown has not started, so a second click passes the click-time check and opens another prompt. When the prompts are answered, each one is re-validated with `can_cast_spell()`, which checks the caster's state (mute, mind, station-level requirements and so on) but not `next_use_time`. So the first answer casts and starts the cooldown, and every later answer still passes the post-prompt check and casts too. Each cast then runs `cast()`, which re-assigns `cooldown_time` and starts a fresh cooldown on top.

## Fix

One commit: "Fix issue 73778: Voice of God spell re-checks cooldown after the input prompt". In `code/modules/spells/spell_types/self/voice_of_god.dm`, the post-prompt check in `before_cast()` now reads `!IsAvailable()` instead of `!can_cast_spell()`. `IsAvailable()` on a spell is the cooldown check plus `can_cast_spell()` (`spell.dm:130-131`), so the existing state check is kept and the cooldown is added. A comment on the line explains why.

This was chosen over storing a separate "cooldown ends" timestamp on the spell (the way the vocal cords do), because the action already has `next_use_time` and `IsAvailable()` is the standard way to ask whether it can be used. The change is local to this one spell; the spell framework was not touched.

## Verification

On a rebuilt test server:

1. Granted "Voice of Clown" to a player and spawned a second human next to them (so there was a listener).
2. Clicked the button twice and got two prompts.
3. Submitted "drop" in the first prompt: the character said "DROP", the target fell over, and the button showed a cooldown of 59.4 seconds.
4. Submitted "drop again" in the second prompt: nothing was said, the window closed, no second cast happened, and the cooldown display just kept counting down (58.6 seconds a moment later).

Not checked:

- The unfixed code with a real cooldown, as noted above. Without a listener, the second prompt still casts after the fix too, for the reason given in Notes (the cooldown was 0), so that case is unchanged.
- The base Voice of God spell and other subtypes; only the Clown variant was cast. They share the same `before_cast()`.
- Cancelling or emptying the second prompt.
- The Colossus vocal-cords version, which was not changed and was not tested.

## Notes

- Side finding, not fixed: `cast()` sets `cooldown_time = (command_cooldown * cooldown_mod)` from the return value of `voice_of_god()` (`voice_of_god.dm:36-38`). That proc returns null when there are no listeners or no command matched (`code/datums/voice_of_god_command.dm`), so such a cast gets `cooldown_time` 0 and therefore effectively no cooldown. It means a player can spam the spell with phrases that match no command, for example with nobody around. That is probably a separate issue and not part of this report.
- Code reading, not tested: in the same `before_cast()`, an empty answer calls `reset_spell_cooldown()` (`voice_of_god.dm:31-33`), which does `next_use_time -= cooldown_time` (`spell.dm:450-453`). On unmodified master, an empty or cancelled second prompt answered after the first cast would have run that and could cut the running cooldown short. With the fix the `IsAvailable()` check comes first, so this path is skipped for a second prompt while the spell is on cooldown.
- The commenter on the issue suggested the problem is limited to the spell form given by admins. The spell is the only version that has the prompt between click and cooldown, so that matches the cause above.
