## Summary

The displacement masks used for mob height (Settler, Spacer, dwarf) are 32x32, and BYOND centres a filter's icon on the appearance it filters and displaces nothing outside it. For 64x64 and larger icons only the central 32x32 was cut or lengthened, which tears the sprite. The fix builds larger masks for large icons by repeating the edge pixels of the original mask. On current master shoes are no longer height filtered, so rollerskates alone no longer show the bug, but other large icons still did.

## The bug

Issue #90615 reports that with a height filter, one shoe of the rollerskates was cut off. SmArtKar's comment in the thread gave the cause: the mask is 32x32 and the shoes are 64x64, so the mask affects only part of the sprite. The same applies to any large icon that goes through the height filter, such as large moth wings.

## Reproduction

I could not confirm the visual symptom in game, because the test client cannot render BYOND filters, so there was no before/after screenshot. What was established:

1. Give a human a non-default height (the tester used `base_mob_height` 18), which is what the Spacer and Settler quirks and dwarfism do.
2. Put a 64x64 overlay that is filtered with `ENTIRE_BODY` on them, such as large moth wings or a large worn icon.
3. The cause then follows from the code and the mask size: `apply_height_filter` hands the 32x32 `cut.dmi` masks to a 64x64 appearance.

Rollerskates by themselves no longer reproduce on this master: the line that height-filters shoes is commented out (`code/modules/mob/living/carbon/human/human_update_icons.dm:296`, `// apply_height(shoes_overlay, NO_MODIFY) // Shoes are rooted`).

## Cause

`apply_height_filter` (`human_update_icons.dm:806`) used five static masks loaded straight from `icons/effects/cut.dmi` (`Cut1` to `Cut5`, line 809 onward), all 32x32 (`displacement_map_filter` masks). A filter icon is centred on the filtered appearance and does not displace anything beyond its own bounds, so for a 64x64 or larger icon the outer part was left unchanged and the central tile was displaced. It is called from the main overlay path (line 796) and for `KEEP_TOGETHER` child overlays (line 938).

## Fix

One commit, "Fix issue 90615: height filter masks only covered 32x32 of large icons", in `human_update_icons.dm`:

- A new global cache, `GLOB.height_filter_masks`, and a proc `get_height_filter_mask(state, width, height)`. For icons larger than one tile it returns a mask of `(1 + 2n) x (1 + 2n)` tiles (n = extra tiles per side, per axis), with the original mask in the centre and the outer tiles filled by stretching the original's edge row or column. The displacement therefore continues unchanged outside the original tile (clamp-to-edge). Icons of 32x32 or less still get the original mask, cached.
- `apply_height_filter` reads the appearance's size with `get_icon_dimensions(appearance.icon)` (defaulting to 32x32 when it has no icon) and asks for the five masks through the new proc instead of the static icons.

Edge replication was chosen over tiling the original mask because the masks encode a vertical displacement gradient, so a repeated pattern would break the continuity.

## Verification

In game via the Lua editor, on a human with `base_mob_height` 18:

- `get_height_filter_mask("Cut1"` to `"Cut5", 32, 32)` returned a 32x32 mask, and with `64, 64` a 96x96 mask whose centre tile equals the original and whose edge pixels are replicated (for `Cut2`, the pixels above, below, left and right of the centre were `#8000ff`, equal to the original's edge, and transparent pixels stayed transparent).
- `apply_height` with `ENTIRE_BODY` ("full body") on a 64x64 rollerskates image (`feet.dmi`) and on a 32x32 armor image added three filters each, with no runtimes (`runtime.log` empty of new entries).

Not checked: any rendered before/after of the sprite, large moth wings or other actual worn large icons on a living player, and the original reported rollerskates case (not reproducible on this master, as above).

## Notes

- Known limitation: `KEEP_TOGETHER` parents are sized by their main icon only, and the masks assume the icon is centred on the mob. That holds for large worn icons because of the worn-offset code.
- #97603 (bodypart textures not applying to large icons) is a different mechanism (`layering_filter`, not the height `displacement_map_filter`) and was not touched. It appears to be fixed upstream already: #98119, "Centers bodypart texture filters", is on this master, and `code/datums/bodypart_overlays/texture_bodypart_overlay.dm:17-24` tiles the texture filter 3x3 for `LIMB_OVERLAY_WIDE_ICON` and `LIMB_OVERLAY_TALL_ICON` overlays, which `code/modules/surgery/organs/external/wings/wings.dm:282` sets for large wings. This was a code check only; it was not re-rendered.
- The large moth wings case that was used to reason about #90615 is `offset_location = ENTIRE_BODY` at `wings.dm:281`.
