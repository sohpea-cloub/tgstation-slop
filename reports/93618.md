## Summary
In `assess_perp()` the `SHOOT_ALL` access check came before the "spare heads of staff" check, so the "Non-Security and Non-Command" setting shot command staff and "Ignore Command" had no effect with it. The fix moves the head exemption ahead of `SHOOT_ALL`, keeping angry (attacked) turrets shooting everyone without security access. #92117 (borgs stunned by a baton or flash still being shot) could not be reproduced.

## The bug
#93618 lists three complaints: "Non-Security and Non-Command" shoots command staff; "Non-Mindshielded" does not shoot non-mindshielded people; "Ignore Command" does nothing. Only the first is a real defect (and explains the third in that mode).

## Reproduction
Using the Lua editor on the test server, a `porta_turret` and three humans were created: one with a Chief Engineer ID, one with no ID, one with an Assistant ID. `turret:assess_perp(human)` was called under several flag sets (SHOOT_ALL=8, UNSHIELDED=32, HEADS=128, ALL_REACT=1, none). This tests the targeting function directly, not live shooting.

Before the fix, threat levels (CE / no ID / Assistant):
- SHOOT_ALL: 10 / 10 / 10 (CE shot although heads should be spared)
- SHOOT_ALL + HEADS: CE 10
- UNSHIELDED: 0 / 4 / 4
- UNSHIELDED + HEADS: CE 4

For #92117, a turret was set on, anchored, with SHOOT_BORGS and mode 1, and `process()` was called with a cyborg in view when it was normal, `Paralyze(200)`d and `Stun(200)`d. `last_fired` (reset each time) was set in all three cases, so a disabled cyborg was still targeted.

## Cause
`assess_perp()` in `code/game/machinery/porta_turret/portable_turret.dm` (about line 587) began with `(SHOOT_ALL | SHOOT_ALL_REACT) && !allowed(perp)` and returned 10 immediately. The "Ignore Command" check (`!SHOOT_HEADS` and head of staff returns 0) came afterwards, so a head without security access was always shot in that mode.

Other items, by code reading and the matrix above:
- The "Ignore Command" checkbox in `PortableTurret.jsx` is `checked={!neutralize_heads}`. The default flags lack `SHOOT_HEADS`, so it is correctly checked by default; a comment on the issue worried it was not.
- "Non-Mindshielded" does target non-heads (threat 4). The reporter tested dressed as a head, who are exempt via Ignore Command (the flag comment says "and who arent heads"). Not changed.

## Fix
One commit, "Fix issue 93618: turret "Non-Security and Non-Command" no longer shoots command staff". The order in `assess_perp()` is now: emagged returns 10; `SHOOT_ALL_REACT` and no access returns 10 (angry turrets still shoot all non-security, command included); head exemption returns 0 when `SHOOT_HEADS` is unset; then `SHOOT_ALL` and no access returns 10. The redundant nested `allowed()` check was removed.

## Verification
After the fix, same Lua matrix (CE / no ID / Assistant): SHOOT_ALL: 0 / 10 / 10; SHOOT_ALL + HEADS: CE 10; ALL_REACT: CE 10; UNSHIELDED: CE 0, others 4; UNSHIELDED + HEADS: CE 4; no flags: all 0. Not checked: a turret firing at a player in game, or a rebuilt-UI click-through.

## Notes
- #92117: not reproduced. Batons (`baton.dm:248`) and flashes (`assembly/flash.dm:189`) both use `Paralyze` on cyborgs, which does not add `TRAIT_KNOCKEDOUT`, so `IS_UNCONSCIOUS_OR_CRIT` in `process()` (around line 490) is false and the turret keeps targeting. That matches what was observed, but only `Paralyze`/`Stun` were called directly; real batons and flashes were not used. The report is from July 2025 with test merges, so lethal turrets, faction, or an emagged cyborg vs a syndicate turret may explain it.
- Mindshield handling was not changed.
