# #66663: Observing while the round is starting leaves your empty body on station

| | |
|---|---|
| Issues | [#66663](https://github.com/tgstation/tgstation/issues/66663): verified (reproduced with a temporarily widened timing window) and fixed |
| Status | verified, fix committed |
| Fix branch | [fix/66663](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/66663) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A player who is readied up and confirms the "Observe" prompt after round setup has already created their character becomes a ghost, while their newly created body stays on station with their name and mind but no one controlling it. The cause is that `make_me_an_observer()` shows a sleeping `alert()` and does not re-check the round state when the player answers. The fix refuses to observe in that situation and lets setup transfer the player into their body as usual.

## The bug

The report: press Ready, wait for the round to roll roles, press Observe before the game actually gives you control, and you end up as a ghost while an empty body of your character spawns on station. A commenter restated it as clicking observe after "Starting game" but before control is handed over.

Pressing Observe opens a confirmation prompt that waits for the answer. If the round begins setting up while that prompt is open, and the player then answers Yes, the player is moved to an observer even though setup has already made their character.

## Reproduction

The real window is very short: round setup (`create_characters()` and `equip_characters()`) only yields at `CHECK_TICK`, so on an idle test server the prompt cannot realistically be answered inside it. To make it reliable, a temporary `sleep(300)` was added right after the `create_characters()` call in `setup()` (`code/controllers/subsystem/ticker.dm:252`). That edit was reverted and is not part of the fix. All other steps used the normal lobby actions. Because of the artificial delay, the report's timing is reproduced, not its natural frequency; on a laggy live server a window of this kind is plausible but was not observed.

1. Build with the temporary sleep, start the test server and join the lobby.
2. Press Ready, then press Observe. The "Observe: Are you sure you wish to observe?" prompt stays open.
3. Use the admin "Start Now" verb to begin the round. Round setup runs and pauses at the added sleep, after the character has been created.
4. Answer "Yes" to the still-open prompt during the sleep.

Observed on master: chat showed "Now teleporting." and "<name> has observed." and the player became an observer. An SDQL2 query (`SELECT /mob/living/carbon/human MAP [name, ckey, key, mind, loc]`) listed a human with the player's name, `ckey` NULL, `key` NULL, a `/datum/mind`, standing on the floor of the Morgue. That is the empty body with the player's name and mind but no soul.

## Cause

`make_me_an_observer()` (`code/modules/mob/dead/new_player/new_player.dm:72`, called from the lobby's "observe" action in `code/modules/lobby_menu/lobby_menu.dm`) sleeps on `alert()` (line 81), and the comment on the proc already says so. After the answer it only checks that the mob and client still exist and that the answer was "Yes" (line 82), then creates the observer. It does not look at the ticker state or at `new_character`.

Meanwhile `setup()` has run `create_characters()` (`ticker.dm:458`), which for every ready player with a mind calls `player.create_character(destination)`, creating `new_character` and moving the mind into it. Because the player turned into a ghost and the lobby mob was deleted, `transfer_characters()` (`ticker.dm:547`) no longer gets to transfer the key to the body. The body is left on station, mindful but unplayed.

## Fix

One commit, "Fix issue 66663: refuse observing once round setup has already spawned your character". After the prompt returns "Yes", `make_me_an_observer()` now returns early with a message ("The round is starting and you are about to be spawned. You can no longer observe.") when:

```dm
if(new_character || (SSticker.current_state == GAME_STATE_SETTING_UP && is_ready_to_play()))
```

`new_character` covers the case where setup has already created the body; the second condition covers a ready player while the ticker is in the setting-up state but before their body exists. In both cases setup continues as normal and the player is transferred into their character. Observing while not ready, or before setup starts, is unchanged.

An alternative would be to also clean up the orphaned body when observing, or to give the new character back to the player; refusing is simpler, and the player explicitly readied up.

## Verification

With the temporary sleep still in place, the fix was built, the same steps were repeated (Ready, Observe, Start Now, answer Yes during the sleep). The player received the "The round is starting and you are about to be spawned. You can no longer observe." message, stayed in the lobby mob, and once setup finished was transferred into their character in the Recreation Area. No orphaned body was observed. The temporary sleep was then reverted.

Not checked: the pre-`create_characters()` part of the condition (the setting-up state with no body yet) was not exercised separately; the fix was tested only with the artificial delay; a real-timing reproduction was not attempted; observing from the lobby when not ready was not re-tested.

## Notes

- Because the window is only open when setup is slow or the prompt is answered at an unlucky moment, the bug may be rare in practice; the fix is cheap and side-effect free for the common path.
- The refusal message appears after the player has already confirmed a prompt, so the player is not told why until the answer. A re-check before showing the prompt would not help, since the prompt itself is what stays open across the state change.
