# #82623: Signaler-triggered chem grenade logs the builder, not the person who sent the signal

| | |
|---|---|
| Issues | [#82623](https://github.com/tgstation/tgstation/issues/82623): verified, fixed |
| Status | Fixed on a branch, verified in game for chem grenades |
| Fix branch | [fix/82623](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/82623) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a chem grenade with a signaler attached is set off by a remote signal, the game and attack logs blame whoever last touched the signaler when it was attached (the builder), and the signal itself is not logged. This is because the grenade logs `get_mob_by_ckey(fingerprint)`, and because signalers discard the signal's log text unless they sit in a transfer valve bomb. The fix records the sender on the signal, keeps the last received signal (and its sender) on signalers wired into a chem grenade, and has the grenade append the signal log and blame the sender, falling back to the builder.

## The bug

Build a chem grenade with a signaler, give the matching remote signaler to someone else, and have them send the signal. The "primed a chemical grenade" log line names the builder, and the pulse message says only that "a remote signaling device" pulsed the grenade "which was installed by" the builder. The person who actually triggered it is never named. The issue's comments add that the signal log is thrown away for anything except transfer valve bombs.

## Reproduction

On master, using the Lua editor and the test server:

1. As an observer, spawn two humans (builder and sender). Give the builder a fake ckey so the logs show who is blamed.
2. Create a chem grenade at stage 3 and attach a signaler (code 7) to it with `grenade.wires:attach_assembly`, with the signaler's `fingerprintslast` set to the builder's ckey (the value the grenade stores as `fingerprint` at attach time).
3. Give the sender a second signaler on code 7, possess the sender, click the signaler in hand and press "Send signal" in the signaler's tgui window.
4. Read `game.log` and `attack.log`.

Observed: the lines named the builder as primer ("`buildermob[DC]/(Builder Bob) primed a chemical grenade casing ...`") and read "`A remote signaling device has pulsed the chemical grenade casing ..., which was installed by buildermob`". The sender was not mentioned.

## Cause

`/datum/wires/explosive/chem_grenade/explode()` (`code/datums/wires/explosive.dm:71`) logs the grenade with `grenade.log_grenade(get_mob_by_ckey(fingerprint))` (`explosive.dm:81`). `fingerprint` is set in the wire datum when the assembly is attached, from `assembly.fingerprintslast` (`explosive.dm:46`), so it identifies the builder, not whoever pulsed the grenade.

The signal text, which does name the sender, is discarded by `/obj/item/assembly/signaler/receive_signal()` (`code/modules/assembly/signaler.dm:175`):

```dm
last_receive_signal_log = istype(holder, /obj/item/transfer_valve) ? signal.logging_data : null
```

It keeps `signal.logging_data` only when the holder is a transfer valve. For a signaler in a chem grenade, `holder` is null (the signaler is only `connected` to the grenade's wires), so the log is wiped. The `/datum/signal` also had no field for the mob that caused it (`code/game/communications.dm:229-236`).

## Fix

One commit, "Fix issue 82623: chem grenade signaler logs blame the signal sender":

- `code/game/communications.dm`: `/datum/signal` gets a `sender` weakref, the mob that caused the signal if known.
- `code/modules/assembly/signaler.dm`: `signal()` sets `signal.sender` from `usr` when it is a mob. `receive_signal()` now stores `last_receive_signal_log` and a new `last_receive_signal_sender` when the holder is a transfer valve or when the signaler is connected to a chem grenade (`connected?.holder`); in other cases both are cleared, as before.
- `code/datums/wires/explosive.dm`: `chem_grenade/explode()` appends ". Last signal received: <log>" to the admin/game message when the pulser is a signaler with a stored log, and calls `log_grenade` with the signal's sender, falling back to `get_mob_by_ckey(fingerprint)` if there is none. The builder still appears in the "installed by" text.

The sender is taken from the signal itself rather than from the signaler's fingerprints so that it is whoever pressed the button, and the stored values are kept only when attached to a bomb, to limit what is retained.

## Verification

After rebuilding, the same test was repeated. `attack.log`/`game.log` then read "`testplayer/(Sender Sue) primed a chemical grenade casing ...`" (the guest name here is the test client's own account used to possess the sender) and "`... installed by buildermob. Last signal received: ... testplayer/(Sender Sue) used the remote signaling device @ location (107,144,2) : 145.7/7`". No new runtimes appeared.

Not checked: syndicate bombs and other signaler-triggered devices; transfer valve logging after the change (the existing TTV path was left as it was); voice or proximity pulsers; non-mob signal sources; the signal log when the grenade is triggered by something other than a signaler.

## Notes

- Only signals sent from a signaler carry a sender. Signals from other sources (for example the signal commander or wiremod components) still give the text log, but `sender` is empty, so the builder is blamed for those.
- The third comment on the issue suggests keeping the signal log for other bombs (syndicate bombs and similar). That was not done; only chem grenades and the existing transfer valve case keep it.
- The sender is a weakref and may no longer resolve if they were deleted; the code then falls back to the builder.
