# #81566: Throwing plays the blind "attack" visual effect at the clicked tile, not where the item landed

| | |
|---|---|
| Issues | [#81566](https://github.com/tgstation/tgstation/issues/81566): verified, fixed |
| Status | Fixed and verified in game |
| Fix branch | [fix/81566](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/81566) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a blind player (or one whose view is limited by FOV) throws an item, the "attack" cue that stands in for sight is drawn on the tile they clicked. If the throw is stopped early, for example by a window, the cue still appears at the clicked tile, not where the item came to rest. `throw_item()` called `do_attack_animation()`, which always plays the effect at its target. The fix suppresses the effect there and plays it from the throw's completion callback at the item's final turf.

## The bug

A blind mob gets small visual cues for sounds and actions near it. Throwing produces an "attack" cue. The cue was placed at the turf the thrower targeted. An item stopped by a transparent obstacle, such as a window, lands somewhere else, so the cue marked a place where nothing happened.

## Reproduction

On master, using admin tools (the Lua editor was used):

1. Spawn a human and make it blind.
2. Build a reinforced full-tile window 3 tiles east of it.
3. Take control of the human and give it a crowbar.
4. Make it throw the crowbar at a turf 4 tiles east, beyond the window. The test called `throw_item()` directly with that turf, not a client click. The crowbar stopped at the tile before the window, 2 tiles east of the human's tile at x=109 per the test coordinates, while the target was at x=111.
5. Inspect the images shown to the thrower's client.

Observed: an `attack` image appeared at x=111 (the clicked turf), while the crowbar dropped at x=109.

The effect only reaches the thrower when the turf is within 5 tiles, the range given to `play_fov_effect`. A first test with a 6-tile throw showed no image at all.

## Cause

`throw_item()` in `code/modules/mob/living/living_item_handling.dm:98` calls `do_attack_animation(target, no_effect = 1)`. In `code/game/atoms_movable.dm:1554` that proc has a `fov_effect = TRUE` parameter, and at `code/game/atoms_movable.dm:1579` it runs:

```dm
if(fov_effect)
	play_fov_effect(attacked_atom, 5, "attack")
```

`attacked_atom` is the clicked target, which is known before the item moves. The throw ends elsewhere when something blocks it.

A related defect was found on the way. `/mob/living/do_attack_animation` (`code/modules/mob/living/living_defense.dm:759`) declared only four parameters and called `..()` without arguments. It therefore never passed `fov_effect` or `item_animation_override` on, so a living thrower could not turn the effect off by argument.

## Fix

One commit, "Fix issue 81566: throwing plays the blind fov effect where the item landed":

- `throw_item()` now passes `fov_effect = FALSE` to `do_attack_animation()`.
- It passes a `CALLBACK` to `safe_throw_at()` (the existing callback parameter, `code/game/atoms_movable.dm:1382`). The throw datum calls it when the throw finishes.
- The callback is a new proc, `/mob/proc/throw_landed_fov_effect(atom/movable/thrown_thing)`. It returns if the thrown thing was deleted. Otherwise it calls `play_fov_effect(get_turf(thrown_thing), 5, "attack")`.
- `/mob/living/do_attack_animation` now declares `fov_effect = TRUE` and `item_animation_override = null` and forwards all arguments to the parent proc, returning its result.

The effect stays tied to the throw and the thrower. It moves from the start of the throw to its end.

## Verification

Checked on the test server after the fix, with the same blind human, window and crowbar:

- Throw blocked by the window: the `attack` image appeared at x=109, where the crowbar landed.
- 3-tile throw west over open floor: the image appeared at x=104, where the crowbar fell.
- Throwing a drinking glass that shatters on landing produced no runtime.

Not checked: throws by a player's real click rather than a direct call, mobs that are sighted but have a limited FOV, thrown mobs, throws that hit a mob, and other users of the thrown-item callback.

## Notes

- The callback fires when the throw finalizes. If the thrown thing is deleted first (for example a glass that shatters), no effect is played. The effect is skipped silently in that case, which was not compared with the old behaviour.
- The 5-tile range is unchanged, so a landing more than 5 tiles from the thrower still shows nothing to them.
- The `do_attack_animation` override change is general: other living callers that pass `fov_effect` or `item_animation_override` now have those honoured instead of dropped.
