# #40040: Quirks are lost when a mind moves into a new body

| | |
|---|---|
| Issues | [#40040](https://github.com/tgstation/tgstation/issues/40040): verified, fixed |
| Status | Fix committed (changes the core mind-transfer proc; design review recommended) |
| Fix branch | [fix/40040](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/40040) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Quirks are datums held by the body (`mob/living.quirks`), and the only code that moves them to another body is the jellyperson spare-body path. `/datum/mind/proc/transfer_to` never carried them, so any transformation that moves the mind into a newly created mob (the Xenobio changeling headslug and the monkey that hatches from its egg, for example) left the quirks behind. The fix makes `transfer_to` call a new `carry_quirks()` proc: transferable quirks leave the old body and go to the new body if it is a human with no quirks, or wait on the mind while it is in a mob that cannot hold quirks (headslug, cyborg, animal).

## The bug

The report describes a Xenobio changeling: the player's mind is moved with a Consciousness Transference Potion into a changeling headslug, the headslug implants an egg into the player's old body, a monkey hatches, and the player then uses Human Form and Transform. Afterwards, quirks such as Light Step or Heavy Sleeper are gone although the mind and memories are intact. The reporter noted that in-place conversions (jellyperson from slime toxin, lizard or skeleton from dragon's blood) keep quirks, so the loss is inconsistent. The thread also lists other cases where a mind moves to a new body, such as a monkeyed character changed back by genetics and a replica pod.

What actually happens is that nothing in the game ties quirks to the mind: they live on the mob. Conversions that change the species of the same mob keep them, and conversions that put the mind into a different mob lose them.

## Reproduction

Done with the Lua editor on the test server, with the transfers made by calling `mind:transfer_to` and the egg's `pop()` directly rather than through the potion, the Transform ability or any player action.

1. Spawn a human, give it a mind (`mind_initialize()`) and four quirks: Light Step, Nyctophobia, Prosthetic Limb and Bald (`add_quirk`).
2. Move the mind with `transfer_to` into a mob that is not a human (a mouse in the pre-fix run), create a new human and call `monkeyize(true)` on it, then `transfer_to` that monkey from the mouse.
3. Check `has_quirk` on the new monkey and on the original human. On master the monkey had none of the four quirks (0 for each) and the original human still had all four (1 for each).

The check for the real hatch path (a mind transferred to a `/mob/living/basic/headslug`, then a changeling egg in a dead host human, then `egg:pop()`) was only run on the fixed build; no pre-fix run of the headslug and egg sequence was done. The pre-fix result therefore comes from the mouse and monkey sequence above.

## Cause

Quirks are held in `mob/living.quirks` (`code/modules/mob/living/living_defines.dm:102`). The only code that moves quirk datums between mobs is `/mob/living/proc/transfer_quirk_datums` (`code/modules/mob/living/status_procs.dm:529`), which is used only by the jellyperson spare-body and body-duplicate code (`code/modules/mob/living/carbon/human/species_types/jellypeople.dm:366` and `:511`). `/datum/mind/proc/transfer_to` (`code/datums/mind/_mind.dm:173`) moves languages, antagonist datums, the HUD and the client, but not quirks. So any transformation that ends in `transfer_to` into a different mob loses them: the changeling egg (`pop()` in `code/modules/antagonists/changeling/headslug_eggs.dm:27` calls `origin.transfer_to(spawned_monkey)`), and the other mind-moving cases in the thread. In-place changes (`monkeyize`, `humanize`, `set_species`, the Human Form and Transform abilities) act on the same mob and already keep quirks.

## Fix

The commit "Fix issue 40040: quirks follow the mind between bodies" changes `code/datums/mind/_mind.dm`:

- Adds `var/list/datum/quirk/stashed_quirks` to the mind, cleaned up in `Destroy` with `QDEL_LIST`.
- Calls a new `/datum/mind/proc/carry_quirks(old_body, new_body, client_source)` at the end of `transfer_to`, just before the `COMSIG_MIND_TRANSFERRED` signals. The client used for quirk setup is the new body's client, or the old body's if the new one has none yet.
- `carry_quirks` does nothing if the new body is not living, or if it is the same mob. If the new body is a human that already has quirks it also returns, leaving the old body's quirks where they are. Otherwise the old body's quirks that do not have `QUIRK_NO_TRANSFER` are removed from it (`remove_from_current_holder(quirk_transfer = TRUE)`) and added to `stashed_quirks`. If the new body is not a human, or there is nothing stashed, it stops there and the quirks wait on the mind. If the new body is a human, every stashed quirk is applied with `add_to_holder(..., quirk_transfer = TRUE)` (so item-giving quirks do not respawn their items), except quirks that are not appropriate for the new body's species, which are deleted.

No alternative was tried. Putting the move in `transfer_to` itself, rather than in each transformation, means one change covers every path that moves the mind (changeling egg, replica pod and similar). Leaving bodies that already have quirks alone avoids piling quirks up when a mind swaps with a quirky body, and with cloners or jellyperson spare bodies.

## Verification

On the rebuilt test server (Lua editor), with the four-quirk human from the reproduction:

- After `transfer_to` a real headslug, the original human had none of the four quirks (0000) and the mind's `stashed_quirks` was set.
- After a changeling egg in a dead human host, `egg:pop()` produced a monkey (`/datum/species/monkey`) with all four quirks (1111), and the stash was empty afterwards.
- Calling `humanize` on that monkey (the in-place Human Form path) gave `/datum/species/human` still with all four (1111).
- Swapping minds between two humans, A with Light Step and B with Nyctophobia, left each body with its own quirk (A 1000, B 0100 both before and after), i.e. unchanged by the fix.
- The runtime log showed no runtimes. An earlier build of the fix did runtime on `null.Copy()` for a body with an empty quirk list; it was caught by the egg test and fixed with `?.Copy()` before the final commit.

Not checked: the real Consciousness Transference Potion and gold-slime headslug sequence and the Transform ability; a replica pod or cloner; cyborg or AI transfers; the `dm` unit tests (none were run); and behaviour with a connected player rather than a spawned test mob (quirk effects that depend on a client, such as visual preferences, were not examined).

## Notes

- This changes a core proc that every mind transfer goes through. Anything that moves a mind from a quirky living body into a living human with no quirks will now move the quirks as well, and the old body loses them. This includes cases the reporter did not mention (possibly including temporary possession or a transfer into a mob that is later abandoned; this was not tested). A maintainer should decide whether that is the right default or whether some callers need to opt out.
- Prosthetic Limb and Prosthetic Organ do not set `QUIRK_NO_TRANSFER`, so they now transfer too, but the new body has the quirk without the physical prosthetic (the item/limb setup is not run on transfer). The reporter said such quirks could reasonably be lost. Flagging them `QUIRK_NO_TRANSFER` would also change the existing jellyperson spare-body transfer, so it was not done.
- When two bodies that both have quirks swap minds, quirks stay with the bodies, as before.
- The reporter said that a monkeyed character changed back with genetics also lost quirks. That change should act on the same mob (the in-place `monkeyize`/`humanize` calls kept quirks in the test above), so it was not reproduced separately and may behave differently from what the 2018 report saw.
- A related upstream pull request about the shapeshift status effect (#69091) does not touch this behaviour. The reporter's thread also links #35539, #42308 and #59127, which were not looked at.
