## Summary

The issue reports three citation problems: paying with a holochip worth more than the fine eats the whole chip, citations cannot be cancelled, and citations cannot be edited. On master the first two no longer happen (fines are now paid only from the ID card's bank account, and invalidating a citation works). The third is still real: `edit_crime` in the security records console only searches the record's crimes, never its citations, so editing a citation's name or description silently does nothing. The fix adds a fallback lookup in `target.citations`, the same pattern `invalidate_crime` already uses.

## The bug

The issue was filed in 2020 and has three parts. A 2023 comment says the records refactor had fixed fine payment and that editing and invalidating citations was broken because the console only looked at crimes. A 2024 comment says citations still could not be invalidated or edited.

On master, in the Security Records interface, a citation (a crime entry with a fine) shows an Edit button and an Invalidate button. Invalidate works. Edit lets the user type a new name or description, but nothing changes afterwards, with no error message.

## Reproduction

Only the editing and invalidating parts reproduced. The payment part was checked by reading the code, not in game.

The security records console was spawned with its access requirement removed, and its interface was driven with the same actions the UI sends (`add_crime`, `edit_crime`, `invalidate_crime`) rather than by clicking buttons.

1. On the test server, start a round and join as Warden (so the user has armory access and is the author of any entries they add).
2. With the Lua editor, spawn a `/obj/machinery/computer/records/security` on your tile, set its `req_access` to nil and clear `obj_flags`, then call `ui_interact()` on it as yourself to open the Security Records interface.
3. Add a citation to a crew record: `add_crime` with name "Littering", details "Dropped a banana", fine 50. The citation appeared in the record's `citations` list (valid, unpaid, fine 50) and the crew member received the PDA message "You have been issued a 50cr citation for Littering."
4. Send `edit_crime` for that citation with name "Dumping trash".

Observed on master: the interface data was unchanged and the citation's name stayed "Littering".

5. Send `invalidate_crime` for the same citation.

Observed on master: `valid` went from 1 to 0 and `voider` was set to the user. Invalidation therefore already works for citations.

## Cause

`/obj/machinery/computer/records/security/proc/edit_crime` (`code/game/machinery/computer/records/security.dm:245`) looks up the target entry only in the crimes list:

```dm
var/datum/crime/editing_crime = locate(params["crime_ref"]) in target.crimes
if(!editing_crime?.valid)
	return FALSE
```

Citations are `/datum/crime/citation` objects stored in a separate `target.citations` list (`add_crime` appends them there, `security.dm:235-237`). A citation reference is never found in `target.crimes`, so `editing_crime` is null and the proc returns FALSE before changing anything. `invalidate_crime` (`security.dm:298-304`) avoids this by trying `target.crimes` first and then `target.citations`.

The other two complaints, on master:

- Payment: `/obj/machinery/computer/warrant/proc/pay_fine` (`code/game/machinery/computer/warrant.dm:81`) charges the paying user's ID bank account and rejects an amount greater than the fine (`warrant.dm:109`). Holochips are not involved, so they can no longer be consumed. This was not tested in game.
- Cancelling: `invalidate_crime` finds citations through the fallback described above, and worked in the test.

## Fix

One commit, "Fix issue 49045: security records console can edit citations". In `edit_crime`, if the reference is not found in `target.crimes`, it now looks in `target.citations`:

```dm
if(!editing_crime)
	editing_crime = locate(params["crime_ref"]) in target.citations
```

The existing `valid` and author/armory-access checks that follow apply to citations unchanged. This mirrors `invalidate_crime`, so the two procs now treat citations the same way. A combined lookup helper was not introduced, to keep the diff to two lines.

## Verification

After rebuilding and restarting the test server, with the same setup as the reproduction (Warden, console with no access requirement, citation of 50 credits named "Littering", details "Dropped a banana"):

- `edit_crime` with a new name: the citation's name changed from "Littering" to "Dumping trash".
- `edit_crime` with a new description: the details changed from "Dropped a banana" to "Dropped two bananas".

Not checked in game: fine payment (and over-payment) at the warrant console, editing a citation as a user who is neither the author nor has armory access, invalidating a citation after the fix, and editing crimes (non-citation entries) after the fix, which the new code does not touch because the first lookup succeeds for them. Editing was exercised by sending interface actions directly, not by typing into the Edit fields in the rendered UI.

## Notes

- Related quirks in `edit_crime` that were looked at but not changed. The interface's name field has `maxLength={25}` (`tgui/packages/tgui/interfaces/SecurityRecords/CrimeWatcher.tsx:180`), which is independent of `MAX_CRIME_NAME_LEN` used server-side. The proc handles one field per call (name first, then description), and that is how the UI sends them, so both work as the UI sends them. The 2023 comment that `params` did not pick up `name` was not seen in the test: name and description edits both applied.
- Editing a citation does not change its fine, and `edit_crime` reports the edit to the blackbox with `SSblackbox.ReportCitation`, as it does for crimes.
- The issue can be closed with the editing fix; the payment and cancelling reports are already resolved on master.
