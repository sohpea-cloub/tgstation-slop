## Summary

The issue reports that wearing the heretic's crimson necklace (the item is named "crimson medallion" in the code) stops stamina damage from wearing off. On master `87b93338` it does not: stamina damage on a wearer of the medallion went from 60 to 0 within about 15 seconds, the same as on an unequipped control. The most likely original cause, visible in the code, no longer applies on master, so no fix was written.

## The bug

As reported: while the medallion is worn, stamina loss never recovers (the reporter describes a "permanent stun" after being hit with batons and disablers). Taking the medallion off restores normal recovery. The reporter guessed that the medallion's healing effect was involved.

## Reproduction

Attempted on master with admin tools:

1. Started a round on the test server and used the Lua editor to spawn two humans, A and B, at the same spot.
2. Spawned `/obj/item/clothing/neck/heretic_focus/crimson_medallion` and equipped it on A's neck slot. B wore nothing (control). A was not a heretic.
3. Gave both humans 60 stamina damage with `adjust_stamina_loss(60)`. Immediately afterwards both read 60.
4. Read `staminaloss` again about 15 seconds later: A = 0, B = 0, health 100.
5. Repeated with A also taking brute damage first. The medallion's healing effect was visibly active on A (green "heal" effects appeared on A's tile, which shows the aura-healing component was running with the medallion's Mansus-touched trait in effect), and stamina still returned to 0.

No runtime errors came from game code during the test. The only errors in the log came from mistakes in the Lua snippets themselves.

Not tested: stamina damage from real batons or disablers (damage was applied by calling `adjust_stamina_loss` directly), a heretic wearer, and the medallion's "squeeze" action.

## Cause

The original cause could not be observed, since the bug does not occur. It can be inferred from the code. The medallion adds a `/datum/component/aura_healing` (`code/modules/antagonists/heretic/items/heretic_necks.dm:69`), limited to wearers with the Mansus-touched trait. On every tick that component calls, for each carbon in range (`code/datums/components/aura_healing.dm:138`):

```dm
candidate.adjust_stamina_loss(-stamina_heal * seconds_per_tick, updating_stamina = FALSE)
```

`stamina_heal` defaults to 0 (`aura_healing.dm:27`), so every tick is a stamina adjustment of zero. In an earlier version of `adjust_stamina_loss`, such a call probably restarted the stamina regeneration timer each tick, which would keep the timer from ever expiring. This is an inference from the code and from the pull request below; it was not reproduced on the older code.

On master this no longer happens:

- `adjust_stamina_loss` returns immediately when the amount is zero: `if(!amount || !can_adjust_stamina_loss(...)) return 0` (`code/modules/mob/living/damage_procs.dm:444`).
- The timer is only restarted in `on_damage_loss_changed()` when the damage type is stamina and the change is positive (`code/modules/mob/living/damage_procs.dm:483`), via `timed_stamina_reset()` (`:489`).

So a zero-amount heal neither changes stamina nor touches the timer.

## Fix

None. The behaviour on master is already correct.

## Verification

See Reproduction: with the medallion worn, stamina damage recovered fully in about 15 seconds, both with and without the healing aura actively working on injuries.

## Notes

- The reproduction used direct `adjust_stamina_loss` calls, so interactions specific to stun weapons (for example other effects applied by batons) were not exercised.
- A closed pull request, tgstation/tgstation#87810, changed the `adjust_stamina_loss` proc in a way aimed at this problem (an early return when the change is not above `DAMAGE_PRECISION`). It targeted an older version of the proc; the current master has since been reworked and carries the zero-amount early return shown above. Which master change actually removed the bug was not identified beyond that.
