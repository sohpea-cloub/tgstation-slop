# #95491: Disposal junctions placed with a diagonal RPD direction become broken pipes when welded

| | |

| Status | Fixed on the fix branch; verified on the test server by direct construction calls (no real RPD click or welder) |

| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The rapid pipe dispenser (RPD) offers the mirrored variants of disposal junctions, sorting junctions and mail junctions as diagonal directions. The construct kept that diagonal direction and the unflipped pipe type, and the finished pipe treats any diagonal direction as a bend, so it ended up with only one connection (its own diagonal direction). The fix converts such a construct, on creation, into the flipped pipe type with the cardinal direction it stands for.

## The bug

The reporter first described the junction's sprite flipping after being welded in place, then clarified in a comment that it is not only visual: the pipe's direction is actually wrong and the pipe no longer connects as previewed.

## Reproduction

Reproduced with admin tools (Lua editor) on a started round, replicating the two calls the real actions make, rather than by clicking with an RPD and welding:

1. As a ghost, create a disposal construct the way the RPD does (`code/game/objects/items/rcd/RPD.dm:431`): `new /obj/structure/disposalconstruct(turf, pipe_typepath, dir, 0)`, with the junction type and a diagonal dir of 5, 6, 9 or 10 (NE, SE, NW, SW). Pass real typepaths (not strings), otherwise `is_pipe()` is false.
2. Create the finished pipe from the construct the way the welder step does (`code/modules/recycling/disposal/construction.dm`): `new pipe_type(turf, construct)`.
3. Read the new pipe's `dir` and `dpdir` (connection mask).

Observed on master: junction (and sorting and mail junction) with dir 5, 6, 9 or 10 gave a pipe with `dir` equal to the diagonal and `dpdir` equal to the same diagonal only, i.e. no usable connections. Cardinal directions were fine (`dpdir` 7, 11, 14, 13).

## Cause

- `code/_globalvars/pipe_info.dm:36-54`: for disposals, the RPD menu lists the mirrored junction variants as diagonal directions ("North Flipped" etc.), and `flipped` is passed as FALSE (the `flipped` computation at about line 54 excludes disposal pipes).
- `code/modules/recycling/disposal/construction.dm:22`, `Initialize`: the non-`make_from` branch just sets `pipe_type` and `setDir(_dir)`, keeping the diagonal dir and the unflipped type.
- `code/modules/recycling/disposal/pipe.dm:41`: pipe `Initialize` does `if(ISDIAGONALDIR(dir)) initialize_dirs = NONE` ("Bent pipes already have all the dirs set"), so for a junction `dpdir` is just `dir`.

## Fix

One commit, "Fix issue 95491: disposal junctions built with a diagonal RPD dir lost their connections". In `disposalconstruct/Initialize`, in the non-`make_from` branch: if the construct was not created flipped, its dir is diagonal and `is_pipe()`, and the pipe type has a `flip_type`, then `pipe_type` becomes the `flip_type` and the dir becomes `turn(dir, -135)` (NE to S, SE to W, SW to N, NW to E). The conversion happens when the construct is created, so the preview, the placed construct and the welded pipe agree.

## Verification

After the fix, same calls: junction NE (5) gave the flipped junction with dir 2 and `dpdir` 7 (S, E, N); SE (6) gave dir 8, `dpdir` 14; NW (9) gave dir 4, `dpdir` 13; SW (10) gave dir 1, `dpdir` 11. These are the shapes named in the RPD preview (`pipe_info.dm:36-40`). Sorting and mail junctions behaved the same; segment bends, Y-junction diagonals and all cardinal directions were unchanged.

Not tested: a real RPD click followed by a welder; the tgui is unchanged.

## Notes

- The conversion lives in the construct, so any code that creates a construct with a diagonal dir for a flippable pipe type gets the flipped type with a cardinal dir.
- The fix was not tried from the RPD side, so whether that would be preferable is untested.
