## Summary

`/mob/living/silicon/robot/update_icons()` began with `cut_overlays()`, so any overlay it did not add itself (a planted C-4, stickers) disappeared whenever a cyborg's icon updated: when a hat is put on, a light is toggled, and so on. The fix moves the cyborg's eyes, open-cover and hat overlays into a managed `update_overlays()` and drops the `cut_overlays()`. A second, separate bug in the same batch (#93246) is that colorful reagent (colorful foam) paints a cyborg's module tools, because a cyborg "holds" them. The fix skips silicons in the clothing-colouring branch.

## The bug

### #84317

A cyborg with C-4 attached has the explosive's sprite vanish when someone throws a hat on it. As a commenter on the issue found, the charge is still attached and will still explode; only the overlay is gone. A later comment says stickers disappear in the same way when a cyborg does anything that changes its visual state, such as toggling its lamp.

### #93246

Spraying a cyborg with colorful foam (or the foam from scrubber overflow) colours the tools in its module. The reporter adds that non-janitor cyborgs cannot wash the colour off.

## Reproduction

### #84317 (reproduced on master)

The player action (throwing a hat) was not performed. The cause was reproduced by calling the same procs through the Lua editor on the test server:

1. Start a round and, with the Lua editor, spawn a `/mob/living/silicon/robot` and a `/obj/item/grenade/c4`.
2. Set the C-4's `target` to the cyborg and call `add_overlay(c4.plastic_overlay)` on the cyborg.
3. Inspect the cyborg's overlays: `robot_e`, `emissive blocker`, `plastic-explosive2`.
4. Call `place_on_head()` on the cyborg with a top hat.
5. Inspect the overlays again: only `emissive blocker` is left. The C-4 overlay is gone. The eyes are gone too, which is expected here because the spawned cyborg had no client (`is_empty_shell()`).

### #93246 (not reproduced before the fix)

The first in-game attempt used `INGEST` instead of `TOUCH` as the exposure method, and a later Lua call that indexed `atom_colours` as a list crashed the test server. No run on unfixed code was completed. The cause is evident from the code (see below); the run on the fixed code is under Verification.

## Cause

### #84317

`code/modules/mob/living/silicon/robot/robot.dm:310` (`update_icons()`) started with `cut_overlays()` (line 311) and then re-added its own overlays with `add_overlay()`: eye lights, the shield module's overlay, the open-cover overlays, and the hat. `cut_overlays()` removes every overlay on the mob, including ones added by other code. Other callers had the same pattern: `update_worn_icons()` (line 354) did `cut_overlay(hat_overlay)`, `on_changed_z_level()` (line 375) cut and re-added `eye_lights`.

### #93246

`colorful_reagent/expose_mob()` colours the target's equipment:

```dm
if (can_color_clothing && (methods & (TOUCH|VAPOR|INHALE)))
	var/include_flags = INCLUDE_HELD|INCLUDE_ACCESSORIES
```

(`code/modules/reagents/chemistry/reagents/other_reagents.dm:2414`; the inverse reagent has the same check at `code/modules/reagents/chemistry/reagents/impure_reagents/impure_medicine_reagents.dm:1242`.) `INCLUDE_HELD` takes the mob's `held_items`, and a cyborg's `held_items` are its active module tools, so they get painted.

## Fix

Two commits on `fix/84317`.

**Fix issue 84317: cyborg icon updates no longer remove C4 and other added overlays**
- `update_icons()` now only sets state (icon state, eye light colour and plane, the hat overlay) and calls `update_appearance(UPDATE_OVERLAYS)`.
- A new `update_overlays()` adds the eye lights, the open-cover overlay (`ov-opencover +w`, `+c` or `-c`) and the hat overlay, so they are managed overlays. A new helper `eye_lights_visible()` holds the old "not dead, not stunned, not an unpiloted shell" condition.
- `update_worn_icons()` only updates the hat offset and then calls `update_appearance(UPDATE_OVERLAYS)`. `on_changed_z_level()` calls `update_appearance` instead of cutting and re-adding the eye lights. `flash_headlamp` in `death.dm` loses its extra `add_overlay(eye_lights)`. The shield module's `cyborg_unequip` calls `update_appearance(UPDATE_OVERLAYS)` instead of `cut_overlay` (the shield overlay was already added through a signal, so it stays managed).
- `do_transform_animation` in `robot_model.dm` calls `cut_overlays()` directly, so it now also sets `managed_overlays = null` so the `update_icons()` after the transform re-adds the managed overlays.

Alternative: removing only `cut_overlays()` would have left the re-added overlays duplicating on each update. Making them managed is the pattern the shield module already used.

**Fix issue 93246: colorful reagent no longer paints cyborg module tools**
- Both `expose_mob()` checks gain `!issilicon(exposed_mob)`, with a comment. Cyborgs do not wear clothes, so the equipment-colouring branch is skipped for them. The cyborg's body is still coloured by the other code path.

## Verification

On the test server with the fixed build, via the Lua editor:

- #84317: same sequence as above (cyborg, C-4 overlay added, then `place_on_head()` with a top hat, `toggle_headlamp()`, `update_icons()`). The overlays were the hat (offset 0,-3), the emissive blocker, the headlamp light (`robot_l`) and `plastic-explosive2`. The C-4 overlay survived. Then `opened = TRUE` and `update_icons()` added `ov-opencover +c` while keeping the hat, light and C-4.
- #93246: a cyborg with a cyborg crowbar in its held items, and a human with a pocket crowbar in hand, were both exposed to `colorful_reagent` with `TOUCH`. The cyborg's crowbar was not painted (`atom_colours` nil); the human's crowbar was (`atom_colours` set). The cyborg's body colouring was seen set.
- The round's runtime log showed no cyborg or overlay runtimes; the only runtimes came from mistakes in the test scripts.

Not checked: a real model transform animation after the change, the hat offset after a direction change, z-level changes, the actual hat throw, real foam, and the shield module's overlay after unequip. #93246 was not run on unfixed code in game.

## Notes

- The #84317 change is a small refactor of how cyborg overlays are built, not a one-line patch, so a maintainer should weigh it against the unchecked cases above.
- Other code that calls `cut_overlays()` on a cyborg directly will still wipe added overlays (the transform animation does this on purpose).
- The two issues were not related except that both involve cyborgs and visual state.
- In Lua, matching mobs by name also hits a cyborg's MMI brain; searching `GLOB.silicon_mobs` avoids it.
