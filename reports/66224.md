# #66224: Machines cannot be wrenched down on icebox snow, ash or asteroid

| | |

| Status | Fixed |
| Fix branch | [fix/66224](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/66224) |

## Summary

Plumbing machines (and anything else that uses `can_be_unfasten_wrench`) could not be wrenched down on `/turf/open/misc` turfs such as icebox snow, lavaland ash and asteroid sand, because the `is_anchorable_floor` helper only accepted `/turf/open/floor` and indestructible floors. The fix adds `ismiscturf` to that helper.

## The bug

On icebox, a player builds a chemical plumbing machine with the plumbing constructor on snow. It is placed fine, but wrenching it gives "needs to be on the floor to be secured". The only workaround is to lay rods and a floor tile first. The comments say the same applies to the asteroid on TramStation, where the chemistry lab is dug out of the asteroid. Commenters thought it was intended (a side effect of PR #65504, which made snow, ash and asteroid `/turf/open/misc` instead of floors), but also noted that it used to be possible.

## Reproduction

Using the Lua editor on the test server:

1. As an admin, change your own turf to `/turf/open/misc/asteroid/snow/icemoon`.
2. Spawn a `/obj/machinery/plumbing/synthesizer` on it.
3. Call `can_be_unfasten_wrench(user, TRUE)` on the machine.

On master it returned 1 (`FAILED_UNFASTEN`, `code/__DEFINES/construction/actions.dm:5`) and the machine stayed unanchored. The check was called directly; the wrench interaction itself was only exercised after the fix.

## Cause

`obj/proc/can_be_unfasten_wrench` refuses when the location is not an anchorable floor (`code/game/objects/objs.dm:281`):

```
if(!is_anchorable_floor(loc) && !anchored)
```

and `is_anchorable_floor` is defined as `(isfloorturf(A) || isindestructiblefloor(A))` (`code/__DEFINES/is_helpers.dm:74`). Snow, ash and asteroid turfs are `/turf/open/misc`, which is neither (`ismiscturf` is defined at `is_helpers.dm:82`), so they are rejected. The same helper is used by the AI law rack (`code/game/machinery/ai_core/law.dm:135`).

## Fix

One commit, "Fix issue 66224: allow securing machines on misc turfs (snow, ash, asteroid)": `is_anchorable_floor` now also accepts `ismiscturf(A)`. This is the smallest change that restores the old behaviour; the alternative of special-casing plumbing machines was not tried.

## Verification

On the rebuilt test server, with the same turf and machine, plus a wrench: `default_unfasten_wrench` printed "You secure the chemical synthesizer." and the machine was anchored. The runtime log of the new round had no runtimes.

Not checked: Tramstation's asteroid or a lavaland ash map specifically (same turf class as the one tested), the AI law rack on misc turfs, and any other users of the helper.

## Notes

- The change is broad: every machine that goes through `can_be_unfasten_wrench` can now be anchored on any misc turf, and so can the AI law rack. A maintainer should decide whether that is wanted or whether the restriction should apply to specific machines. #65504 made misc turfs deliberately distinct from floors.
- The issue was triaged as possibly "working as intended"; the comments disagree about it, but the tram chemistry complaint suggests the restriction was a side effect.
