# #72905: Player ticket panel contains reply links that message yourself

| | |
|---|---|
| Issues | [#72905](https://github.com/tgstation/tgstation/issues/72905): verified, fixed |
| Status | Fixed; adminhelp half checked in game, adminpm half not |
| Fix branch | [fix/72905](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/72905) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The ticket log shown to the player ("View latest ticket") embedded reply links whose target is the player themself, so clicking their own name offered a prompt to private-message themself. The links came from text that was built once and used for both the admin view and the player view. The fix puts the plain name in the player-facing copy at three places and leaves the admin-facing log unchanged.

## The bug

The report: get a ticket, open the View latest ticket panel, reply, then click your own name in the reply; a prompt opens to respond to yourself.

## Reproduction

On master, via admin tools. The test account was the local server's guest, which is an admin, so this exercises the link target rather than a true non-admin session:

1. Send an adminhelp (the Adminhelp verb with a message such as "test ticket").
2. Open the View latest ticket verb. The panel listed the line as a link, "Test-Player/(Test-Player)" (the sender's own name), pointing at `byond://?_src_=holder;...;ahelp=<ref>;ahelp_action=reply`.
3. Follow the link. A prompt "Private message to Test-Player." opened, i.e. a reply to oneself.

Caveat: for a true non-admin, the `_src_=holder` link does nothing because there is no admin holder. The panel also carries `priv_msg` links to the viewer for non-admins (see Cause) but that variant was not exercised.

## Cause

Player-visible interaction lines are stored with a separate `player_message`, but several were built from the same string as the admin copy:

- `/datum/admin_help/New()` (`code/modules/admin/verbs/adminhelp.dm:240`): for a ticket opened by an admin PM, the player message is "`<admin> PM'd [LinkedReplyName()]`".
- `MessageNoRecipient()` (`adminhelp.dm:413`): the opening ahelp line uses `LinkedReplyName(ref_src)` in `player_message`.
- `LinkedReplyName()` (`adminhelp.dm:389-392`) returns an `ahelp_action=reply` link to the ticket's initiator, who is the player viewing their own panel.
- `adminpm.dm:482`: the player's own "Reply PM from" line uses `link_to_us`, which is `key_name(src, TRUE, FALSE)`, a `priv_msg` link to the sending player themself. For a non-admin, clicking it runs the PM command on their own ckey.

## Fix

One commit, "Fix issue 72905: no self-reply link in the player ticket panel":

- `adminhelp.dm`: both `player_message` strings now use the plain `initiator_key_name` instead of `LinkedReplyName()`. The admin copy keeps the link.
- `adminpm.dm`: `player_replymsg` uses `key_name(src, FALSE, FALSE)` (no link) instead of `link_to_us`.

Links to the admin in the player's view (for example `PM From [link_to_us]` at `adminpm.dm:404`) were left alone, since replying to an admin is legitimate.

## Verification

After a rebuild, repeating the reproduction steps: the panel showed the plain "05:15:07: Test-Player/(Test-Player): test ticket" with Refresh as the only link.

Not checked: the `adminpm.dm` change (it needs a second client, an admin replying to a non-admin player); the admin-PM-opened-ticket line ("PM'd ..."); the view as a real non-admin. The change compiled cleanly. The admin PM code deserves a review.

## Notes

- Admin-facing ticket logs are unchanged.
- The `adminpm.dm` edit is untested, so reviewers should look at that line particularly.
