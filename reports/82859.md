## Summary
Turning a bot's personality setting off only cleared a flag; the `ghost_direct_control` component stayed on the bot, so it stayed in `GLOB.joinable_mobs` and in the ghost spawners menu, where taking it just printed "personality download has been disabled". The fix deletes the component in `disable_possession()` (`enable_possession()` already adds it back). The related issue #66837 (the spawners menu ignores `policy.json`) is fixed in a second commit that appends the job's policy text to the menu's flavor text.

## The bug
### #82859
A bot, for example a roundstart Medibot, whose personality setting has been turned off still shows up in the spawners menu that ghosts open. Trying to take it only says that the personality download has been disabled.

### #66837
The spawners menu showed only the spawner's hard-coded `flavour_text`. Servers that set role text in `policy.json` (the issue's example is golems) saw that text in the spawn greeting but not in the menu.

## Reproduction
### #82859
1. Start a round and observe as an admin. Open the Lua editor.
2. In Lua, build a `/datum/spawners_menu` and call `ui_static_data()` on it (the data the tgui receives). List the names and `amount_left` of the `spawners` entries. The roundstart station Medibot was listed (`Medibot=1`; the other roundstart bots were listed too).
3. Call `disable_possession()` on that Medibot (the proc the personality toggle in the bot UI calls).
4. `can_be_possessed` was 0, but the menu data still contained `Medibot=1`.

This was reproduced by calling the proc and reading the menu's data from Lua, not by clicking the toggle and opening the menu in the tgui.

### #66837
Not reproduced in game before the fix. By code: `ui_static_data()` copied only `mob_spawner.flavour_text`, and `get_policy` is not used anywhere in `code/datums/spawners_menu.dm`.

## Cause
### #82859
`disable_possession()` (`code/modules/mob/living/basic/bots/_bots.dm:251`) sets `can_be_possessed = FALSE` (line 254) and does nothing else to the listing. `enable_possession()` (line 229) attaches `/datum/component/ghost_direct_control` (line 236). That component adds its parent to `GLOB.joinable_mobs` when it is created (`code/datums/components/ghost_direct_control.dm:43`) and removes it only when destroyed (line 63). The spawners menu builds its bot entries from `GLOB.joinable_mobs` (`code/datums/spawners_menu.dm:48-52`), so a bot with personality off stayed listed. The click-to-possess prompt also stayed available, and the only result of using it was the "disabled" message.

### #66837
`code/datums/spawners_menu.dm:39` sets `this["flavor_text"] = mob_spawner.flavour_text` and never consults `get_policy`. Jobs look up their policy text in `code/modules/jobs/job_types/_job.dm:311` with `get_policy(policy_override || title)` for the spawn greeting.

## Fix
- **"Fix issue 82859: bots with personality disabled no longer stay in the spawners menu"**: `disable_possession()` now does `qdel(GetComponent(/datum/component/ghost_direct_control))` right after `can_be_possessed = FALSE`. The component's Destroy removes the bot from `GLOB.joinable_mobs`. This also removes the bot's click-to-possess prompt, which would otherwise only report the disabled setting. Re-enabling needs no change: `enable_possession()` already creates the component.
- **"Fix issue 66837: spawners menu shows the policy.json text for the role's job"**: in `ui_static_data()`, after the code `flavour_text`, the job is looked up with `SSjob.get_job_type(mob_spawner.spawner_job_path)`. If `get_policy(job.policy_override || job.title)` returns text, it is appended to `flavor_text` (or used alone if the flavor text is empty). This is the same lookup the spawn greeting uses.

## Verification
After rebuilding, on a fresh round, using the Lua editor to read the menu data:
- #82859: with the Medibot enabled it was listed (`Medibot=1`). After `disable_possession()` it was gone from the menu data and `can_be_possessed` was 0. After `enable_possession()` it was listed again (`can_be_possessed` 1). Disabling again removed it again.
- #66837: a Hermit ghost role spawner was spawned. Its menu `flavor_text` was the code text. After setting `config.policy["Hermit"]` to a test string from Lua, the `flavor_text` ended with that string.
- No new runtimes were seen in the runtime log.

Not checked: clicking the personality toggle in the bot UI, or opening the spawners menu in the tgui, with the fix. The reported menu data is static data, so an already-open menu only updates when static data is next pushed. The #66837 behaviour was not seen before the fix, and a real `policy.json` file was not used (the config entry was set from Lua).

## Notes
- Policy text is appended to the "Directives" (flavor text) field, not shown separately.
- Only policy keyed by the job title (or `policy_override`) is covered. Other policy keys, such as mob typepaths used for joinable mobs, are not.
- Joinable mobs (bots and similar) have no spawner job, so they get no policy text in the menu.
