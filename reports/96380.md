# #96380: Nukie overwatch bodycams give AIs camera coverage

| | |
|---|---|
| Issues | [#96380](https://github.com/tgstation/tgstation/issues/96380): fixed |
| Status | Fixed and verified at the camera-visibility level |
| Fix branch | [fix/96380](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/96380) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The bodycams given to nuclear operatives by the Overwatch Intelligence Agent were counted as ordinary cameras by the AI camera chunk system. Wherever an operative stood, camera static was cleared for AIs, so an AI could interact with machines there, such as the nuclear bomb and the disk inside it. The fix adds an `ai_coverage` var to cameras. The two overwatch bodycam setups set it to `FALSE`, so those cameras stay viewable on the overwatch console but never clear AI static.

## The bug

As the issue describes, all cameras provide AI coverage, including the overwatch bodycams. An AI can therefore get vision, and with it the ability to act, near a nuclear operative, for example ejecting the disk from the bomb before the operatives can arm it.

## Reproduction

Reproduced at the visibility level, not with a full nuke round and a real AI:

1. On the test server, using the Lua editor, spawned a human on a space turf with no camera coverage (20,20 on z-level 2). `SScameras.is_visible_by_cameras(turf)` returned 0 for it.
2. Added a `/datum/component/simple_bodycam` to that human on network `operative` (the overwatch setup).
3. The same call now returned 1: the turf was visible to the camera system, which is what AI interaction depends on.

An AI actually using the nuke was not tried.

## Cause

Camera chunks decide coverage from every camera that passes `can_use()`, regardless of its network: `code/modules/mob/living/silicon/ai/freelook/chunk.dm:155`, `:188` and `:282`, and `code/controllers/subsystem/cameras.dm:130` and `:159`. The overwatch bodycams (`code/modules/antagonists/nukeop/datums/operative_support.dm:21` and `:45`, network `OPERATIVE_CAMERA_NET`) are normal `/obj/machinery/camera` objects made by `simple_bodycam`, so they were included.

## Fix

One commit, "Fix issue 96380: nukie overwatch bodycams no longer give AI camera coverage":

- `code/game/machinery/camera/camera.dm`: new var `ai_coverage` (default `TRUE`) and `can_provide_coverage()`, which returns `ai_coverage && can_use()`.
- `chunk.dm` and `cameras.dm`: the five coverage checks above call `can_provide_coverage()` instead of `can_use()`.
- `code/datums/components/simple_bodycam.dm`: the component takes an `ai_coverage` argument (default `TRUE`) and sets it on the camera; the dupe-check signature gains the argument.
- `operative_support.dm`: both overwatch bodycam sites pass `ai_coverage = FALSE`.

Cameras with the flag off remain usable on camera consoles; only AI vision and static are affected.

## Verification

On the test server after the fix, with the Lua editor:

- A human at (20,20) with a bodycam whose `ai_coverage` was `FALSE`: turf visibility 0.
- A human at (200,200) with a default bodycam: visibility 1, so ordinary bodycams still give coverage.

Not checked: a full nuke round with a real AI trying to eject the disk, and the overwatch console's view of the bodycams in game (the code path is unchanged).

## Notes

The check was done by calling the camera subsystem directly, not through an AI player. Other cameras that should not give AI vision can now use the same flag.
