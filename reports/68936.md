## Summary

When a brain that belongs to a player is put into a monkey (or humanized monkey) and the body is revived, the monkey's `ai_controller` is never removed. The AI only stays off while a client is attached to the body, so if the player is disconnected the body is run by the monkey AI. The fix deletes the body's `ai_controller` in `/obj/item/organ/brain/on_mob_insert()` right after the player's mind has been moved in. All three issues describe this same behaviour.

## The bug

#68936, #57466 and #80484 give nearly the same steps: take a monkey-human, cut out its brain, put in the brain of a player, revive it. The revived body walks around and attacks people using the monkey AI. A comment on #68936 notes that the brain's owner has to be disconnected for this to happen, and #57466 is titled around "the brain of a disconnected person". A comment on #57466 adds that the AI also remembers who damaged it, so a disconnected person can attack the surgeon.

What happens in code is that the mind is transferred into the monkey body, but the body is still a monkey with a monkey AI. While the player's client is connected, the AI is switched off, which hides the problem. When the player is disconnected (or leaves), the AI is on again and drives the body.

## Reproduction

The reproduction used a player-owned mind that has a key but no client, which is the disconnected-player case from the issues. It was done by calling the relevant procs from the Lua editor, not by performing the surgery by hand.

1. On the test server, as an admin, start a round and open the Lua editor.
2. Spawn a human (the donor) and give it a mind with a key but no client: create a `/datum/mind` with the key `fakeckey` and call `transfer_to()` on the donor.
3. Spawn a monkey (`/mob/living/carbon/human/species/monkey`).
4. Remove the monkey's brain and delete it.
5. Remove the donor's brain and `Insert()` it into the monkey.
6. Call `revive(1)` on the monkey.
7. Read back the monkey's `ai_controller`, `ai_status`, `stat`, `mind`, `mind.key` and `client`.

Observed on master:

- `ai_controller` was `/datum/ai_controller/monkey` and `ai_status` was `ai_on`.
- `stat` was 0 (the monkey was alive and conscious).
- `mind` was a `/datum/mind` with key `fakeckey`, and `client` was `nil`.

So the body belonged to a player but was running the monkey AI. The run did not show the monkey actually walking or attacking; the evidence is the controller being present and switched on, which is what moves a clientless body.

## Cause

`/obj/item/organ/brain/on_mob_insert()` in `code/modules/mob/living/brain/brain_item.dm:60` handles moving the brain's occupant into the new body. For a normal (non-changeling, non-decoy) brain with a brainmob, it transfers the mind (`brainmob.mind.transfer_to(brain_owner)`, line 85) or possesses the body by key, copies the suicide state (line 89) and deletes the brainmob (line 91). Nothing in this path touches `brain_owner.ai_controller`.

Monkeys are given `ai_controller = /datum/ai_controller/monkey` by type (`code/modules/mob/living/carbon/human/monkey.dm:4`), so the body keeps it after the mind arrives.

`get_expected_ai_status()` in `code/datums/ai/_ai_controller.dm:442` only turns the AI off for a mob that has a client:

```dm
var/mob/living/mob_pawn = pawn
if(!continue_processing_when_client && mob_pawn.client)
	return AI_STATUS_OFF
```
(line 460). A body that has a player's mind but no client therefore has its AI on. The controller also reacts to the player leaving: `on_sentience_lost()` (line 680) calls `reset_ai_status()` on logout, "resume AI control now that the client is gone". So a monkey with a connected player has its AI off, and the moment that player disconnects it comes back on.

Elsewhere the code already assumes a player-owned humanoid has no AI: `code/modules/mob/living/carbon/examine.dm:245` only prints the "totally catatonic" / "blank, absent-minded stare" text when `isnull(ai_controller)`.

## Fix

One commit, "Fix issue 68936: a player's brain put into an AI-driven monkey removes the monkey AI", changes `on_mob_insert()` in `code/modules/mob/living/brain/brain_item.dm`. Right after the suicide state is copied, inside the branch where the brain's occupant takes over the body, it adds:

```dm
// A player's mind now lives here, so don't let an NPC AI (monkeys) run the body whenever the player isn't connected.
if(brain_owner.mind?.key && brain_owner.ai_controller)
	QDEL_NULL(brain_owner.ai_controller)
```

Deleting the controller (rather than only setting it off) was chosen because the controller turns itself back on whenever the client logs out, so an "off" state would not stick. This is the same thing other code does when it makes a mob player-like (for example `QDEL_NULL(owner.ai_controller)` in `code/datums/brain_damage/special.dm:514` and `:526`, and `code/datums/elements/cursed.dm:22`).

The check on `mind?.key` limits this to bodies that now hold a real player's mind; it runs after the mind transfer, so it is the body's mind that is tested.

## Verification

After the fix, the same Lua steps were run again on a fresh round, with a second, untouched monkey spawned as a control:

- The transplanted monkey had `ai_controller` = `nil`, `stat` = 0, and `mind.key` = `fakeckey`.
- The control monkey still had `/datum/ai_controller/monkey`.
- The runtime log showed no runtimes.

Not checked:

- A player with a live client in the brain's owner. The AI is already off in that case before the fix (the client check at `_ai_controller.dm:460`), so nothing should change, but it was not tested. This is why #80484, which does not say whether the player was connected, was not separately tested.
- The surgical route (cutting the brain out and putting it in with surgery tools). The brain was moved with `Remove()` and `Insert()` calls.
- The behaviour of the body after the player later logs out or ghosts, beyond reasoning from the code.
- Other ways a mind reaches an AI-driven body.

## Notes

- After the fix the monkey has no AI for good. If the player later leaves, the body stays idle: with no controller and no key, `examine` shows the "totally catatonic" text. That matches how an ordinary human body with a gone player behaves, but it means the body does not return to being a wandering monkey.
- Bodies that become player-controlled without a brain transplant (for example a monkey given sentience with a potion) are not covered by this change. They still resume the monkey AI when the player logs out. That was not changed.
- The fix only runs when `brain_owner.mind?.key` is set after the transfer. A brain whose brainmob has a mind without a key would still leave the AI in place.
- Upstream: the inputs did not show any upstream PR that fixes this.
