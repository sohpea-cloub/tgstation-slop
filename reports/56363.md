# #56363: ID set back to "Unassigned" looks different from a blank ID

| | |
|---|---|
| Issues | [#56363](https://github.com/tgstation/tgstation/issues/56363): not reproduced (obsolete) |
| Status | not reproduced; the described UI no longer exists |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The 2021 issue said that giving a blank ID a job at the ID console and then pressing the dedicated "Unassigned" button left the card with the "unknown job" HUD icon instead of the blank card's icon. The ID console is now a modular computer program, and it has no "Unassigned" button. The nearest action, "Terminate Employment", removes the card's trim, and a card with its trim removed has the same trim, security HUD icon state and overlays as a blank one. There was nothing to fix.

## The bug

As reported: an ID in the console's slot starts out Unassigned with a grey blank icon. After a job was assigned and then the "Unassigned" button was clicked, the job read Unassigned again, but the icon was the unknown-job icon rather than the blank one.

## Reproduction

Not reproduced. The ID console UI was not clicked through; the procs it calls were run directly with the Lua editor.

1. Started a round on the test server and opened the Lua editor as an observer.
2. Spawned two `/obj/item/card/id/advanced` cards. One stayed blank. On the other, applied the botanist job trim with `SSid_access.apply_trim_to_card()`, then removed it with `SSid_access.remove_trim_from_card()`. That is what "Terminate Employment" does to the trim.
3. Compared the cards.

Observed (trim, security HUD icon state, assignment, overlay count, `trim_state_override`):

| Card | Trim | HUD state | Assignment | Overlays | Trim state override |
|---|---|---|---|---|---|
| blank | none | `hudunknown` | none | 1 | none |
| trim applied | `/datum/id_trim/job/botanist` | `hudbotanist` | Botanist | 4 | none |
| trim removed | none | `hudunknown` | Botanist | 1 | none |

In a first run, applying the job template through `add_trim_access_to_card()` (which the console's job template button calls) left every field identical to the blank card, confirming that it changes access only.

The card with the trim removed matches the blank card in everything that drives its look. Only the assignment string differs ("Botanist" here; the console sets "Demoted" or "Fired").

## Cause

There is no defect on master.

- `code/modules/modular_computers/file_system/programs/card.dm` has no "Unassigned" control. The string only appears in the display line `data["id_rank"] = card.assignment || "Unassigned"` (line 326), and the interface file `tgui/packages/tgui/interfaces/NtosCard.tsx` has no such button.
- "Apply template" (`PRG_template`, lines 240-260) calls `SSid_access.add_trim_access_to_card()` (`code/controllers/subsystem/networks/id_access.dm:500`), which only changes the card's access, not its trim or icon.
- "Terminate Employment" (`PRG_terminate`, lines 144-157) sets the assignment to "Demoted" or "Fired" and calls `remove_trim_from_card()` (`id_access.dm:432`). That sets `trim = null` and refreshes the icon.
- The HUD icon comes from `get_trim_sechud_icon_state()` (`code/game/objects/items/cards_ids.dm:886`), which returns `trim?.sechud_icon_state || SECHUD_UNKNOWN`. A trimless card therefore gets the same icon as a blank card.

## Fix

None.

## Verification

The comparison table above, produced on the test server, and the code reading. Not checked: clicking through the console UI in a round, and cards whose trim was changed by other means (for example forged cards or the trim "override" variables).

## Notes

- The issue is most likely obsolete. The 2021 ID console and its "Unassigned" button no longer exist.
- A small difference remains by design: after "Terminate Employment" the card's assignment text reads "Demoted" or "Fired", not blank or "Unassigned". That is the assignment string, not the icon, and the issue did not ask about it.
