# #84167: Non-harm stun baton hits no longer drain energy-shield charges

| | |
|---|---|
| Issues | [#84167](https://github.com/tgstation/tgstation/issues/84167): verified, fixed |
| Status | Verified on the test server; fixed on the fix branch |
| Fix branch | [fix/84167](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/84167) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A stun baton used with a normal (left-click) attack is deflected by a `shielded` component without costing it a charge, so the shield can never be broken that way. The non-harm baton attack sets its force to 0, and the shielded component treats any hit under 3 damage as free. The fix adds an attack modifier, `BLOCK_DAMAGE_OVERRIDE`, that carries the baton's real force to the blocking checks while the force actually dealt stays 0.

## The bug

Against a target protected by an energy shield (the report was about a nuclear operative), hitting with a stun baton without right-clicking made the shield deflect every hit. The shield lost no charges, so it never overloaded and the stun never landed. Only the harm-baton attack (right-click) wore the shield down. Before the change in #83361, the stun hit did break the shield.

## Reproduction

The test was done by calling the attack proc directly from the Lua editor, not by a player clicking.

1. In the Lua editor, spawn a human (target) and a second human (attacker) a few tiles away. Give the target `never_wounded`.
2. Spawn an armor vest, add `/datum/component/shielded` to it (default 3 charges) and equip it on the target.
3. Spawn a `/obj/item/melee/baton/security/loaded`, put it in the attacker's active hand and set `active = TRUE`.
4. Call `baton.melee_attack_chain(attacker, target)`, which is a non-harm left-click attack.

Observed on master: the chat showed "<target>'s shields deflect the stun baton in a shower of sparks!", the shield's `current_charges` stayed at 3 (3 before, 3 after), and the target was not stunned.

## Cause

`attacked_by` in `code/_onclick/item_attack.dm:351` passes `final_force` to `check_block`:

```dm
if(check_block(attacking_item, final_force, "\the [attacking_item]", MELEE_ATTACK, attacking_item.armour_penetration, attacking_item.damtype))
```

A non-harm baton attack sets its force to 0 (`SET_ATTACK_FORCE(attack_modifiers, 0)`, `code/game/objects/items/weaponry/melee/baton.dm:181`). The shielded component then sees a 0-damage hit. In `code/datums/components/shielded.dm:183` a hit under 3 damage sets `charge_loss = 0`, but the hit is still blocked (`. = COMPONENT_HIT_REACTION_BLOCK`, line 176). So a stun hit is blocked for free. As MrMelbert noted in the issue, this follows from #83361, which made 0-damage attacks not deduct charges.

## Fix

One commit, "Fix issue 84167: non-harm stun baton hits count as real hits against shields":

- `code/__DEFINES/combat.dm`: new attack modifier `BLOCK_DAMAGE_OVERRIDE` and a setter macro `SET_ATTACK_BLOCK_DAMAGE`, next to `SET_ATTACK_FORCE`.
- `code/_onclick/item_attack.dm`: `attacked_by` passes `attack_modifiers[BLOCK_DAMAGE_OVERRIDE]` to `check_block` when it is set, and `final_force` otherwise.
- `code/game/objects/items/weaponry/melee/baton.dm`: on a non-harm hit the baton sets `BLOCK_DAMAGE_OVERRIDE` to `CALCULATE_FORCE(src, attack_modifiers)` before zeroing the force. The force and damage actually dealt are unchanged.

This approach keeps the 0-damage rule in the shielded component (so projectiles and other harmless attacks keep their behaviour) and leaves the baton's damage at 0. Changing the shielded threshold was not tried, since necromanceranne pointed out in the issue that harmless 0-damage attacks do exist.

## Verification

On the test server with the fix, the same setup was run four times in a row, resetting the baton's cooldown between hits. The first 3 hits were deflected ("shields deflect the stun baton", charges going down), the 4th hit produced "shield overloads", and the next hit stunned the target ("stuns ... with the stun baton"). This matches the report's description of the original behaviour.

Not checked: a real player click (the attack was called as a proc), shield types other than a `shielded` component on a vest, MOD energy shield modules, other stun items (for example the cattleprod), and in-game balance.

## Notes

- `block_chance_modifier` (`damage / -3`) for held shields and armor now also sees the baton's force on a stun hit, the same as on a harm-baton hit. That is a behaviour change for those items against non-harm baton hits.
- The cooldown question raised in the issue (stun hits have a longer cooldown than harm hits) is a balance matter and was not looked at.
- The fix only changes the baton. Other attacks that set their force to 0 but should count as a hit would need to set `BLOCK_DAMAGE_OVERRIDE` themselves.
