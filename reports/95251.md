## Summary

#95251 describes a grave mechanic for the ghost species (a ghost killed while in passthrough mode returns as a gravestone that a shovel can dig up into a skeleton). That mechanic is not in the tested tree; the notes say it was removed upstream by a revert (PR #95779, 2026-04-15, "Reverts 'Merges ghosts into spirits & a rework'"), so the report is obsolete and nothing was changed. #95304 (felinid ears rendered too high on settler-height characters) was not reproduced in the one attempt made, and the investigation stopped there.

## The bug

### #95251

Per the report: a player with the ghost species and the changeling antagonist drops a grave with the ghost action button, then someone digs the grave up with a shovel. The resulting skeleton was still a traitor when the antagonist was a traitor, but was not a changeling when the antagonist was a changeling. The reporter guessed that the dig-up code moved the mind over with the brain and mishandled a changeling mind.

### #95304

Per the report: felinids with lynx ears (later narrowed in a comment to all ear types) show the ears too high on the head at settler height, in every view except the back. The ears render correctly while the face overlay is being changed (blushing, lipstick) and jump back up afterwards. The reporter said it appeared, went away, and came back; a maintainer reproduced it later on a test-merge build.

## Reproduction

### #95251

1. On the test server, made a mob with the ghost species and gave it the changeling antagonist datum. This worked without problems.
2. Clicked the ghost species' "Toggle passthrough" action button. No grave was dropped.
3. A code search of the tested tree found no grave or skeleton handling in `code/modules/mob/living/carbon/human/species_types/ghost.dm`. The other grave-related code is unrelated to ghosts: the gravedigger element (`code/datums/elements/gravedigger.dm`) and the elephant graveyard ruin's burial mounds.

The notes trace the described grave behaviour to PR #95169 ("Fix some quirks with ghosts"), which is not present in this tree, and say that the revert PR #95779 removed it upstream. That PR history was taken from the investigation notes; it was not re-checked here.

### #95304

1. Using the Lua editor, spawned a human, set its `ears` feature to "Lynx", made it a felinid, set its mob height to the settler height (`HUMAN_HEIGHT_SHORTEST`, value 8), and regenerated its icons.
2. Rendered the south-facing sprite before and after setting `lip_style` on the head and calling `update_body_parts()`.
3. The ears looked the same in both renders: not reproduced.

This used `set_mob_height` directly. It did not use the Settler quirk path, so a difference between the two paths remains possible.

## Cause

### #95251

No cause: the code path does not exist in the tested tree.

### #95304

No cause was found. Notes from reading the code, as leads only:

- Ears are a `/datum/bodypart_overlay/mutant/cat_ears` overlay on the head, with `offset_location = UPPER_BODY` (`code/modules/surgery/organs/internal/ears/_ears.dm`, around line 160). The height offset is applied in `code/modules/surgery/bodyparts/_bodyparts.dm` (around line 1446) via `owner.apply_height(actual_overlay, overlay.offset_location)`, which adds the offset to `pixel_z`. For settlers the `UPPER_BODY` offset is -2 (`code/__DEFINES/mobs.dm`, around line 782).
- Limb images are cached in a static `limb_icon_cache` keyed by `get_cache_key()` (`code/modules/mob/living/carbon/carbon_update_icons.dm`, around lines 391-399; the key is built around lines 437-460 and includes `mob_height`). The ear overlay's `get_image` builds a mutable appearance while temporarily changing `feature_key`.
- The report's hints (all ear types, fixed while the face changes, intermittent, back view fine) point at the cached limb image or the offset being applied inconsistently. Untried ideas: adding the Settler quirk to a mob that already has ears, checking whether `set_mob_height` refreshes the limb icons when the height changes after a cache key was stored, and checking whether a cached image shared between a medium-height and a short mob could accumulate `pixel_z` through repeated `apply_height` calls.
