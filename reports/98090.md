# #98090: Weakpoint cracks can be placed on open space and fall down a z level

| | |
|---|---|
| Issues | [#98090](https://github.com/tgstation/tgstation/issues/98090): verified, fixed. [#96116](https://github.com/tgstation/tgstation/issues/96116): duplicate (same cause, confirmed by reading the code; its own steps were not run) |
| Status | Fixed on the branch below, checked on the test server with multi-z forced on (see Verification for what was not checked) |
| Fix branch | [fix/98090](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/98090) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a weakpoint crack explodes it spawns new cracks on nearby turfs. The list of turfs it must avoid (`skip_turfs`) contained plain space, asteroid and snow, but not open space. A new crack placed on an open space turf is an object standing on open space, so it fell to the z level below, possibly ending up in space under the room (#98090, #96116). The fix adds open space to `skip_turfs`. It also repairs the handler that is meant to move a crack off a turf that changes into something unsuitable; that handler never ran because it was registered on the wrong object.

## The bug

Players saw a weakpoint crack appear on the level below the one where the explosion happened, in some cases over space (#96116 shows a crack in space; #98090 describes the new crack falling to the level below after the old one exploded). Cracks are meant to stay on the floor of the level where they were generated, where they can be found and welded.

What happened: the code that picks turfs for the new cracks did not exclude open space turfs. A crack spawned on one is treated like any object that enters open space and falls.

## Reproduction

Reproduced with admin tools on the test server. The test map has no multi-z linkage, so z level 2 was linked to z level 1 by setting `SSmapping.multiz_levels[2][2] = 1` from the Lua editor so that z2 falls to z1. The player-level scenario in the issues (a real multi-z station) was therefore not run; the cause was demonstrated by spawning cracks directly.

1. Open the Lua editor as an admin and enable the link between z2 and z1 as above.
2. Change the turf at (105,144,2) to `/turf/open/openspace` with `ChangeTurf`.
3. Create an `/obj/effect/weakpoint` at that turf.
4. Observed on master: the crack was returned at z=1. It fell immediately on creation, because open space makes a newly entered object fall.

This shows that anything which places a crack on open space loses it to the level below. The remaining question is whether the explosion's regeneration code can place a crack there. From the code it can: `create_new_cracks` only filters out turf types in `skip_turfs`, and open space is not among them (see Cause). A full explosion run on unfixed master (open space around the crack, then `ex_act(1)`) was not performed; only the direct spawn above was run before the fix.

## Cause

All references are to `code/game/objects/effects/decals/turfdecal/weakpoint.dm` at master.

1. `skip_turfs` (lines 31-35) is:

   ```dm
   var/static/list/skip_turfs = typecacheof(list(
   	/turf/open/space,
   	/turf/open/misc/asteroid,
   	/turf/open/misc/snow,
   ))
   ```

   `/turf/open/openspace` is not a subtype of any of these. It is used by `get_crack_chain` (line 128) and passed to `create_new_cracks` (line 68). `create_new_cracks` filters its candidate turfs with it (line 165) and checks again before spawning (lines 175-177). Open space turfs therefore pass both checks and can receive a new crack (line 178). An object that enters open space falls, via `/turf/open/openspace/Entered` and `initialize_occupant` (`code/game/turfs/open/openspace.dm:56-66`).

2. The safety net for turfs that change under an existing crack did not work. `Initialize` runs `RegisterSignal(src, COMSIG_TURF_CHANGE, PROC_REF(turf_changed))` (line 42), which listens on the crack, but `COMSIG_TURF_CHANGE` is sent by the turf that is being changed, so `turf_changed` was never called. Had it been called, its retry loop (lines 143-150) was also broken: it called `pick_n_take(get_adjacent_open_turfs(src))` on a fresh list each iteration instead of on `choices`, and it never assigned the result of the skip checks, so it would accept any picked turf. It also did not check whether the new turf type was actually one of the skipped types.

## Fix

One commit, "Fix issue 98090: weakpoint cracks no longer spawn on or fall through open space", changing only `weakpoint.dm`:

- `/turf/open/openspace` is added to `skip_turfs`, so neither the crack chain nor the child-crack placement will use open space turfs.
- The `turf_changed` signal is now attached with `AddElement(/datum/element/connect_loc, list(COMSIG_TURF_CHANGE = PROC_REF(turf_changed)))`, so the crack listens to the turf it is on (the same pattern other decals use).
- `turf_changed` now takes the signal's arguments. It returns at once unless the new turf type is in `skip_turfs`. Otherwise it picks from the adjacent open turfs taken from `choices`, skips turfs that already hold a crack or are in `skip_turfs`, and moves the crack there. If nothing is valid the crack is deleted. The move happens while the change is still pending (the signal is sent before the turf is replaced), so the crack leaves before the new turf, e.g. open space, would make it fall.

Adding open space to `skip_turfs` alone would stop new cracks being placed on open space, but not the case of a floor under an existing crack being replaced later, which is what the turf change handler is for; so the handler was repaired as well.

## Verification

Done on the test server, with the z2-to-z1 link forced on:

- Explosion with open space around: a 15x13 patch of iron floor around (105,144,2) was turned into open space, a crack was created in the middle and `ex_act(1)` was called on it. The new cracks appeared at (103,150,2) and (104,147,2), both on plating on z2. `GLOB.weakpoints_spawned` contained only cracks on z2 on floor turfs; none were on open space or on z1.
- Turf changing under a crack: a crack was created on a floor at (60,140,2), then the turf was changed to open space. The crack moved to (60,141,2), a floor tile, stayed on z2 and was not deleted.
- No new runtime errors appeared in the round's runtime log during these runs.

Not checked:

- The same explosion run on unfixed master (only the direct spawn onto open space was run before the fix).
- A real multi-z map (the test map has none; the link was forced), and #96116's own scenario of a room above space.
- Roundstart placement in `place_weakpoints` (`code/controllers/subsystem/minor_mapping.dm:108-120`, uses `find_satchel_suitable_turfs`), which does not use `skip_turfs` and was not examined for open space.
- The case where no valid adjacent turf exists and the crack is deleted.

## Notes

- #96116 shows a crack in space with only screenshots and the reproduction step "spawn a weakpoint in a room above the space". Commenters guessed it fell through a breach. That is consistent with this fix, but it was not confirmed against the original map or round.
- The fix also makes cracks leave a turf that becomes plain space; the handler reacts to any turf type in `skip_turfs`, including asteroid and snow.
- `ex_act` passes `skip_turfs` as a fourth argument to `get_crack_chain` (line 53), which only declares three parameters. The skip list used inside is the static one, so this has no effect here; it was left untouched.
- Turfs added to the explosion chain as neighbours (lines 54-58) are not filtered, but they only receive `ex_act`. New cracks are only placed through `create_new_cracks`, which does filter.
