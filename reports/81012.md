## Summary

When the RPG titles event re-themes an ID card, it changes the card sprite, name and assignment but leaves the job's normal trim icon and still draws the subdepartment bar, which is wider than the smaller RPG card. The fix makes the event set the trim icon that matches the RPG title (Chaplain becomes Paladin) and stops drawing the subdepartment bar on those cards.

## The bug

The issue has three complaints about the Chaplain's card while RPG titles is active: (1) it shows the Chaplain trim rather than the trim for the RPG title "Paladin"; (2) the coloured subdepartment bar at the bottom does not fit on the card; (3) the red "assigned name" stamp is partly covered by the trim. A comment from the reporter suggests changing the `trim_state` on the job trim singletons so ID changes by the Head of Personnel don't break the icons.

## Reproduction

Using the Lua editor on the test server (the event was not run through its normal trigger):

1. Start a round, spawn a human, and call `equipOutfit` for the Chaplain on it.
2. Create a `/datum/rpgtitle_controller` and call `on_crewmember_join(SSdcs, human, 'Chaplain')`.
3. Read the card's variables.

Observed on master: `icon_state` was `card_rpg` and `assignment` was `Paladin`, but the card's trim was still `/datum/id_trim/job/chaplain` with `trim_state` `trim_chaplain`. That confirms point 1.

Points 2 and 3 were worked out from the sprite geometry in `card.dmi`, not by seeing a rendered card (an ID in a worn slot isn't drawn on the mob without a real client). The `card_rpg` sprite spans x4..25, y8..21 of 32, while the subdepartment bar spans x6..27, so it overhangs by 2 pixels. `trim_chaplain` spans x7..13 and the `rpg_assigned` stamp x13..16, so they overlap; `trim_paladin` spans x5..11.

## Cause

`on_crewmember_join` in `code/modules/events/wizard/rpgtitles.dm` (around lines 100-112) sets the card's name, description, `icon_state`, `assignment` and `assigned_icon_state` and nothing about the trim. The card's `update_overlays` (`code/game/objects/items/cards_ids.dm`, around lines 1175-1200) takes the icon from `trim_state_override` or else the job trim's `trim_state`, and always draws a `subdepartment` overlay below it. With the job trim unchanged, the Chaplain icon is used, and the subdepartment overlay is sized for a full ID card.

## Fix

One commit, "Fix issue 81012: RPG titles IDs use the RPG trim icon and drop the oversized subdepartment bar":

- `/obj/item/card/id/advanced` gets a new `show_subdepartment_overlay` variable (default `TRUE`), and `update_overlays` only draws the subdepartment overlay when it is set.
- The RPG titles event sets it `FALSE` on advanced cards, and sets `trim_state_override` to `trim_<title in lowercase without spaces>` when that icon state exists in the card icon file. A new `GLOB.rpg_trim_state_exceptions` list maps "Tavern Chef" to `trim_tavernstationhand`, which doesn't follow the naming.
- RPG titles with no matching sprite (Peasant, Defeated Miniboss, Omnissiah, Beast of Burden) keep the job's normal trim.

The reporter's suggestion (editing the trim singletons) was not followed. The override is set on the individual card.

## Verification

After a rebuild and restart, the same Lua steps gave these card values: Chaplain `card_rpg` / Paladin / `trim_paladin` / `show_subdepartment_overlay` 0; Cook `trim_tavernstationhand`; Captain `trim_starduke`; Assistant `trim_lout`; Head of Security `trim_guardleader`. No runtimes appeared during the run.

Not checked: the rendered card sprite (so points 2 and 3 are confirmed only by geometry and by the variables), the event run through its normal trigger, and the titles without a trim sprite.

## Notes

- `trim_state_override` persists, so if a Head of Personnel later changes the card's trim, the RPG trim icon would remain, as the `card_rpg` `icon_state` already does.
- `update_label()` overwrites the "adventuring license" name. This is pre-existing and was not changed.
- Titles without a trim sprite (four listed above) still show the job trim, now without the subdepartment bar.
