## Summary

On master, the `face_decal` component (spray paint on a head, creampie) asks for overlay layers keyed `ADJ`/`FRONT`. The simple bodypart overlay appends that key to the icon state, giving `spray_human_ADJ`, which does not exist in the icon file, so face decals were not drawn on any carbon. This is what #83495 saw as the paint being hidden. Once the first commit makes the decals draw, they show a second bug, #97149: on dwarves the decal used the `UPPER_BODY` offset while a dwarf's head limb is displaced and squashed by the `ENTIRE_BODY` offset, so the paint appeared as a wide collar across the shoulders. The second commit uses `ENTIRE_BODY`.

## The bug

- #97149: a dwarf (by DNA or rat infusion) painted with a spray can shows a malformed sprite: a red shape wider than the head across the shoulders and chest instead of paint on the head.
- #83495: a human painted on the head, then given a bandana, balaclava or similar, appeared to lose the paint. The report took this to be beard-hiding items hiding the paint.
- What is actually going on: on master the decal is not drawn on carbons at all, for any species. With nothing drawn there is nothing to see on a dwarf either, so the dwarf problem only appears once the decals draw.

Note that #97149's screenshot shows a painted dwarf, so the decal was visible to that reporter. This write-up could not explain how, given the finding below that nothing drew on master in the tests (see Notes).

## Reproduction

On master with the Lua editor on the test server after the round started:

1. Spawn a human and add the component with a red colour, for example `AddComponent('/datum/component/face_decal', 'spray', {ADJ = 22.9}, '#ff0000')`, the same arguments the spray can passes (`crayons.dm:867`, `crayons.dm:925`).
2. Inspect the head's overlays (View Variables) and render the mob. The overlay list contained `spray_human_ADJ`, and the render reported that part named an icon state its icon lacks, so nothing was drawn.
3. Parsing the icon file `icons/mob/human/species/misc/bodypart_overlay_simple.dmi` showed only the states `creampie_human`, `creampie_lizard`, `creampie_monkey`, `spray_human`, `spray_lizard` and `spray_monkey`; there are no `_ADJ` or `_FRONT` variants.

The dwarf offset defect (#97149) could not be seen on unmodified master because of the first bug. It was seen after applying the first commit only: a painted dwarf drew the paint as a red collar wider than the head across the shoulders and chest, while a painted normal human showed the red face with a small collar at the neck. The player action of a real spray can was not used; the component was added directly from Lua with the same arguments.

## Cause

Two defects in `code/datums/components/face_decal.dm`, in `RegisterWithParent` (around lines 35-55):

1. `bodypart_overlay.set_layers(layers)` (line 43) passes the caller's layer list, whose keys are `EXTERNAL_ADJACENT` (`ADJ`) for the spray can in `crayons.dm:867` and `crayons.dm:925` and likewise in `syndie_spraycan.dm:146` and `splat.dm:19`. In `code/datums/bodypart_overlays/simple_bodypart_overlay.dm:12`, `get_image` builds the icon state as `icon_state + (layer_index ? "_[layer_index]" : "")`. The decal's icon state (for example `spray_human`) therefore became `spray_human_ADJ`, which the icon file does not have, and nothing was drawn. The other users of key suffixes on that overlay type (roach shell `_BEHIND`/`_FRONT`) have matching states; the decal states do not.
2. `bodypart_overlay.offset_location = UPPER_BODY` (line 44). The head limb of a dwarf is displaced and squashed by the `ENTIRE_BODY` filter (see the comment in `_bodyparts.dm` around line 1440), so an overlay using the upper-body offset is placed where the undisplaced head would be.

## Fix

Two commits.

1. **Fix issue 83495: face decals (spray paint, creampie) were never drawn on carbons.** The layers passed to the simple overlay are flattened to a single entry with an empty key, so the icon state stays `spray_human` and the decal draws on the layer the caller asked for. Adding `_ADJ`/`_FRONT` states to the icon was the other option; flattening needs no icon change.
2. **Fix issue 97149: face decals on dwarves were drawn at the undisplaced head position.** `offset_location` is `ENTIRE_BODY`, like the head limb itself.

## Verification

After both commits, in game, with the component added from Lua and the mob rendered at 8x scale:

- Normal human: red face with a small collar at the neck, as the sprite is drawn.
- Dwarf: the paint sat on the dwarf's lowered head, with no collar across the shoulders or chest. A clean dwarf for comparison had no red.
- A monkey with the dwarf trait, and a lizard: paint on the head.
- Bandana (red) on a painted human: the paint stayed visible around the mask. Balaclava: the face was covered by the mask and the paint showed only at the neck edge.
- No runtimes came from the decal code (the only runtimes were from mistakes in the test script itself).

Not checked: creampie (`splat.dm`) and the syndicate spray can, which share the component and layer keys but were not exercised; applying paint with a real spray can; the before-fix render of a dwarf with the old code on a build where decals draw (it was seen with the first commit only, as described above).

## Notes

- #83495: there is no clothing check in the decal code (`overlay_flags = NONE`) and no beard or hide-flag logic touches it, so the "things that hide beards hide the paint" mechanism does not exist as the title describes. The paint was always missing. If the reporter wanted paint visible over a balaclava, that would be a feature request, not what the code does or did.
- The first bug looks like a regression on master that made face paint and creampie invisible on all carbons. The inputs did not establish which change introduced it, and #97149's screenshot suggests decals did draw for that reporter, possibly on an earlier build or with a test merge. This is uncertain.
