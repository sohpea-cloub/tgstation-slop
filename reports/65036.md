## Summary

The 2022 report says the Opportunist midround antagonist runtimed when dynamic tried to execute it on a test server with a single client. On master the Opportunist (thief) antagonist and its dynamic ruleset no longer exist in the code, and dynamic's handling of a ruleset that cannot find enough candidates was rewritten so that it cancels cleanly instead of failing during execution. The game was not run for this issue, because nothing in the current code corresponds to the reported ruleset. The issue looks obsolete.

## The bug

The reporter ran a local test server with one client while testing unrelated code. About half a dozen times a runtime appeared when the Opportunist midround ruleset tried to run and failed. The runtime text was in a screenshot, which is not available. They suspected it only happens at very low population and might be related to #64371.

The ruleset author replied that "all rulesets are like this", a trade-off made when ruleset execution was changed in "Dynamic 2021", and that all rulesets should have weight 0 in `dynamic.json`. A second comment, on 2022-03-03, only contained an image and a joke that it was "not my fault".

## Reproduction

Not attempted in game. The intended check was to start a one-player server, let dynamic try midround rulesets, and look at the runtime log. That was not done: there is no Opportunist or thief ruleset on master to trigger.

What was checked instead, by reading and searching the source of master:

1. Searching `code/` for "opportunist" (case-insensitive) finds only two unrelated comments, in `code/modules/mob/living/basic/lavaland/legion/legion_monkey.dm` and `code/modules/mob/living/basic/space_fauna/spider/spiderlings/spiderling.dm`. The remaining hits are in the tgui Orion game and archived changelogs. The 2022-06 changelog has one line about fixing the "thieves/opportunists icon".
2. There is no thief antagonist directory under `code/modules/antagonists`, and nothing in `code/controllers/subsystem/dynamic/` refers to a thief or Opportunist ruleset.
3. The dynamic subsystem now lives in `code/controllers/subsystem/dynamic/` (`_dynamic_ruleset.dm`, `dynamic_ruleset_midround.dm`, and others).

## Cause

For the original runtime, none could be established. The screenshot with the runtime text is not available, so the exact error is unknown, and the code it came from no longer exists.

For the failure path in general, current master handles a ruleset that cannot be filled like this. `prepare_execution()` in `code/controllers/subsystem/dynamic/_dynamic_ruleset.dm` (line 217) picks candidates and, if there are fewer than the minimum, stores a reason and cancels:

```dm
var/list/selected_candidates = select_candidates(antag_candidates, max_candidates)
if(length(selected_candidates) < min_candidates)
	log_data = "Reason: Not enough eligible candidates. Have: [length(selected_candidates)], Need: [min_candidates]"
	return FALSE
```

(lines 231-234). It likewise returns FALSE with "Reason: Ruleset cannot be selected." if `can_be_selected()` fails (line 225). The caller therefore gets a normal "do not run" answer and no failure during execution. This matches the commenter's description of the old behaviour as a deliberate trade-off that has since been replaced, though the code was not compared against the 2022 version.

## Notes

- Suggested resolution: close as obsolete. The ruleset the issue names is gone from the codebase and dynamic's candidate-failure path no longer relies on execution failing.
- If this runtime is still seen on a current build, it will need new information: the runtime text and which ruleset produced it.
