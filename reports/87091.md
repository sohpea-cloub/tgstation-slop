# #87091: Service borgs cannot remove items from oven trays

| | |
|---|---|
| Issues | [#87091](https://github.com/tgstation/tgstation/issues/87091): verified, fixed |
| Status | Fixed; verified in game for the default "gather everything" mode |
| Fix branch | [fix/87091](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/87091) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A service borg's serving tray uses quick gather. In its default "gather everything" mode, `on_preattack()` in the storage code silently cancels the click on any item that is not directly on a turf, and food on an oven tray is inside the tray, not on the turf. The fix lets items whose location is a plate (which includes oven trays) go through the normal gather path. Items inside other containers, such as backpacks, are still refused.

## The bug

A service borg opens an oven, with food on the oven tray, and clicks the food with the serving tray selected. Nothing happens: no message, no pickup. The reporter can put food on the oven tray from the serving tray but cannot get it back off.

## Reproduction

1. On the test server, use the Lua editor to spawn a service cyborg and possess it.
2. Spawn an oven, open it, and put an oven tray holding three cookies in it.
3. Select the serving tray module and leave quick gather on its default mode, "gather everything".
4. Click a cookie on the oven tray.

Observed on master: nothing happens (no chat message, no pickup). With the tray switched to "pick up one at a time" (`COLLECT_ONE`), the same click works ("You put the cookie onto the serving tray"). One earlier attempt in the default mode also failed, but the cyborg had no module selected then, so that attempt does not count.

## Cause

`code/datums/storage/storage.dm:749` `/datum/storage/proc/on_preattack()` handles clicks made with a storage item. The serving tray (`/datum/storage/bag/tray`, `code/datums/storage/subtypes/bags.dm:111`) has `allow_quick_gather` on and the default `collection_mode = COLLECT_EVERYTHING`. For `COLLECT_ONE` the handler inserts the item directly. For the other modes:

```dm
if(!isturf(thing.loc))
	return COMPONENT_CANCEL_ATTACK_CHAIN
```

(`storage.dm:758-759`). Food on an oven tray has the `/obj/item/plate/oven_tray` as its `loc` (it is only displayed in the oven through `vis_contents`), so the click is swallowed without a message. `collect_on_turf()` itself works on the contents of any holder, so the guard is the only thing in the way.

## Fix

One commit, "Fix issue 87091: serving trays can gather food from oven trays". The guard becomes:

```dm
if(!isturf(thing.loc) && !istype(thing.loc, /obj/item/plate))
	return COMPONENT_CANCEL_ATTACK_CHAIN
```

with a comment saying that items on a plate are reachable and can be gathered like items on a turf. This is narrow on purpose: other non-turf locations (for example inside another storage item) are still cancelled.

## Verification

On the test server after a rebuild, with the same setup (service cyborg, open oven, oven tray with three cookies, serving tray selected, "gather everything"):
- Clicking a cookie on the oven tray showed the "picked up" floating text and the rustle sound, and the serving tray then held all three cookies.
- Calling `on_preattack` on a cookie inside a backpack lying on the floor still returned the cancel value, and the cookie stayed in the backpack.

Not checked:
- "Gather same type" mode (`COLLECT_SAME`); it goes through the same code path.
- Other plates (for example a regular plate with food) or other bags that use quick gather; the change applies to any plate, but only oven trays were tried.
- Retrieving items by a route other than the serving tray, such as the service apparatus module.

## Notes

- Whether the borg also needs the oven open: the click only reached the food with the oven open and the tray selected; a closed oven needs to be opened with no module selected (a selected tray would attack the oven instead).
- Cookies left on the tray when the oven closed burned to ashes during testing, which is unrelated to this bug.
