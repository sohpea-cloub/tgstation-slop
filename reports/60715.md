## Summary

The 2021 report lists three hard deletes seen on a local reference-tracking run: a `/obj/structure/closet/decay`, a `/mob/living/carbon/human` and repeating `/image` batches. None of the three could be reproduced on current master. The locker case was fixed upstream (the locker projectile now holds a weak reference). No cause was found for the other two because neither failed to garbage collect. No fix was written.

## The bug

The reporter ran a local round with the reference tracker and saw three kinds of hard-delete log lines a few minutes after round start:

1. A `/obj/structure/closet/decay` that could not be GC'd, found in the `locker_temp_instance` var of an `/obj/projectile/magic/locker`.
2. One `/mob/living/carbon/human` that could not be GC'd. The search found no reference.
3. Batches of `/image` (1 to 6 every few minutes) that could not be GC'd, found in `client.images`.

In the issue thread, the first case was said to be already fixed. The human case was called a mystery, and the image case was described as strange (nobody was sure images should be `qdel`'d at all). #11365 was linked as related, but it was said to be only related in that it also hard-deletes.

## Reproduction

All attempts were made on a test server built with reference tracking (`REFERENCE_TRACKING_STANDARD`) on master.

1. Started a round and joined as the AI. The AI eye's detector hud `qdel`s images (`code/modules/mob/living/silicon/ai/freelook/eye.dm:80`). Moved the eye to the map corner, so the visible-turf image list shrank (589 to 576 images) and the `qdel` path ran.
2. Spawned a full crew (43 humans) with the debug verb and let the round run about 13 minutes.
3. Using the Lua editor, created a locker bolt projectile and fired it at a monkey, then deleted the projectile and the decay closet with SDQL2.
4. Deleted all `/mob/living/carbon/human` with SDQL2.
5. Read the hard-delete log.

Observed:

- During about 13 minutes of idle round plus AI eye movement, the hard-delete log had no reference search at all: no `/image`, no human, no decay closet.
- The SDQL-deleted decay closet produced no GC failure.
- The only reference search for the locker case was for the locker projectile itself, which was still held by the Lua editor variable used for the test. This comes from the test method, not from the game.
- The 43 crew humans were garbage collected without a failure. The one human-type hard delete was a monkey that the Lua editor was still holding. The search found only the garbage queues.

## Cause

Not applicable, since the reported failures did not occur. For context:

- **Locker / decay closet.** The projectile now stores `var/datum/weakref/locker_ref` and sets `locker_ref = WEAKREF(locker_temp_instance)` (`code/modules/projectiles/projectile/magic.dm:213-218`). It resolves the weakref where it needs the closet (`magic.dm:223-243`). The strong `locker_temp_instance` var from the issue no longer exists.
- **Images.** `/image` is a datum, so `qdel` on one is an ordinary GC. The AI eye removes itself from the hud before its images are `qdel`'d (`eye.dm:80` and `Destroy()` at `eye.dm:20-27`). The bot hud images (`bot_hud.dm:108-112`) were read in the code as being animated away and dropped without a `qdel`. No image GC failure was seen.
- **Human.** Nothing was found. The original failure may have depended on a particular event (for example a client disconnect or the `/mob/new_player` case in #11365). A stock round on master did not show it.

## Fix

None.
