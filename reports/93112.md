## Summary

The newscaster's wanted-issue screen always rendered an `<Image>`, passing `src={null}` when the wanted issue had no photo, which the browser draws as a broken-image box. The fix renders the image only when the wanted issue has one. The with-photo path and the rendered UI itself were not checked in game, and the issue's screenshot was not available, so it is uncertain whether the reporter hit exactly this case.

## The bug

The issue has only a screenshot (not available to the investigation) and the steps "Open a newscaster with a wanted issue / Observe". A wanted issue created without a photo produced a broken image placeholder above the "Posted by" line on the wanted screen.

## Reproduction

Server-side half, checked on the test server:

1. Start a round and open the Lua editor.
2. Submit a wanted issue with no photo: `GLOB.news_network:submit_wanted('Bob', 'stole', 'Tester', nil, false, false)`.
3. Call `ui_data` on a newscaster (`GLOB.allCasters[1]:ui_data(user)`) and read `wanted[1].image`. It was `nil`, and `GLOB.news_network.wanted_issue.img` was `nil`.

The UI half follows from the code (below): with `image` null, the interface renders `<Image src={null}>`. That render was not observed, because the available tooling cannot run tgui JavaScript or display it. A second attempt to attach a photo (building an `/icon` from Lua) failed with a `bad proc` runtime, so the with-photo case was not exercised.

## Cause

`code/game/machinery/newscaster/newscaster_machine.dm:185-193` builds the wanted data:

```dm
var/has_wanted_issue = !isnull(GLOB.news_network.wanted_issue.img)
if(has_wanted_issue)
	user << browse_rsc(GLOB.news_network.wanted_issue.img, "wanted_photo.png")
...
"image" = (has_wanted_issue ? "wanted_photo.png" : null)
```

so `image` is null when there is no photo. The interface then does, at `tgui/packages/tgui/interfaces/Newscaster.jsx:285`:

```jsx
<Image src={activeWanted.image ? activeWanted.image : null} />
```

The ternary only maps a falsy value to `null`; the `<Image>` element is still rendered, producing an `<img>` with no `src`, shown as a broken image.

## Fix

One commit, "Fix issue 93112: Newscaster wanted issue without a photo shows a broken image", changes `Newscaster.jsx:285` to:

```jsx
{!!activeWanted.image && <Image src={activeWanted.image} />}
```

The element is omitted when there is no photo. The tgui bundle was rebuilt successfully after the change.

## Verification

- Checked: the server-side data (`image` is `nil` for a photo-less wanted issue); the tgui build compiles.
- Not checked: the rendered UI before or after the change; a wanted issue with a photo; the reporter's exact scenario.

## Notes

- If the reporter's wanted issue did have a photo, this fix does not address it. In that case a candidate to look at is the relative `src` value `"wanted_photo.png"` sent via `browse_rsc`, which was not investigated. The article-photo path (`Newscaster.jsx:638`) uses the same approach and looked fine on reading.
- Apart from the broken image box, no other symptom was identified.
