# #33653: Tactical turtleneck cannot be dyed with a crayon in the washing machine

| | |
|---|---|
| Issues | [#33653](https://github.com/tgstation/tgstation/issues/33653): verified, fixed on the branch below |
| Status | Reproduced and fixed; fix checked on the test server |
| Fix branch | [fix/33653](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/33653) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Washing a tactical turtleneck (`/obj/item/clothing/under/syndicate`) with a crayon in a washing machine did nothing, because the base syndicate jumpsuit type never set a `dying_key`, and `dye_item()` returns early for items without one. The fix adds `dying_key = DYE_REGISTRY_UNDER` to the base type. The turtleneck, and the syndicate-family jumpsuits that inherit from it, now take the crayon colour like ordinary jumpsuits.

## The bug

A player puts a tactical turtleneck and a crayon in a washing machine and runs it. The garment comes out unchanged, still a "tactical turtleneck", instead of a jumpsuit in the crayon's colour. The issue's comments disagree about whether this was intended (one says dyeing used to be a feature for nuclear operatives, another says it is intended and compares it to combat gloves). The code settles it as an omission rather than a deliberate exclusion: the washing machine's under-clothing dye registry has an entry for the syndicate colour (`DYE_SYNDICATE`, mapping to `/obj/item/clothing/under/syndicate`), the tacticool turtleneck has a dye override that expects a `dying_key`, and the matching skirt (`/obj/item/clothing/under/syndicate/skirt`) already had one. Nothing marks the turtleneck as `undyeable`.

## Reproduction

On master, using the Lua editor as an observer (no player needed in the machine):

1. Spawn a washing machine.
2. Spawn a tactical turtleneck (`/obj/item/clothing/under/syndicate`) and a red crayon (`/obj/item/toy/crayon/red`) inside it, and set the machine's `color_source` to the crayon. The same was done for a tacticool turtleneck (`/obj/item/clothing/under/syndicate/tacticool`) and for the tactical skirtleneck (`/obj/item/clothing/under/syndicate/skirt`) as a control.
3. Call `machine_wash(washer)` on each garment. This is the proc the machine calls for every item in a wash cycle (`code/game/machinery/washing_machine.dm:313`). A first attempt that ran the machine's full `wash_cycle()` with the items loaded was also made, but its output was not captured because of a script error, so the result below comes from `machine_wash` called directly.
4. Read each garment's name and icon state afterwards.

Observed on master:

- Tactical turtleneck: name "tactical turtleneck", icon state `syndicate`. Unchanged.
- Tacticool turtleneck: unchanged.
- Tactical skirtleneck (control): became a "red jumpskirt".

This was reproduced by calling `machine_wash` directly from Lua rather than by loading the machine through its interface and starting a cycle by hand.

## Cause

`dye_item()` begins with:

```dm
/obj/item/proc/dye_item(dye_color, dye_key_override)
	var/dye_key_selector = dye_key_override || dying_key
	if(undyeable || !dye_key_selector)
		return FALSE
```

(`code/game/machinery/washing_machine.dm:249-252`). `/obj/item/machine_wash()` calls it with only the crayon's colour (`code/game/machinery/washing_machine.dm:313-315`), so the item's own `dying_key` is the only thing that selects a dye registry.

The base type `/obj/item/clothing/under/syndicate` (`code/modules/clothing/under/syndicate.dm:1-11`) does not set `dying_key`. `/obj/item/clothing/under/color` and the `/obj/item/clothing/under/rank` types get theirs from `DYE_REGISTRY_UNDER` (`code/modules/clothing/under/color.dm:10`, `code/modules/clothing/under/_under.dm:584`), but the syndicate types do not inherit from either. Only the two skirts in the file set a key, both `DYE_REGISTRY_JUMPSKIRT` (`syndicate.dm:25` and `syndicate.dm:101`). So `dye_item()` hit `!dye_key_selector` and returned FALSE for every non-skirt syndicate jumpsuit.

`/obj/item/clothing/under/syndicate/tacticool/dye_item()` (`syndicate.dm:82-90`) already assumes a key may be present: it checks `dying_key == DYE_REGISTRY_JUMPSKIRT` to decide which plain syndicate garment a Grime Liberator dye should turn it into. That code only makes sense if these types are meant to be dyeable.

## Fix

One commit, "Fix issue 33653: tactical turtleneck can be dyed in the washing machine". It adds one line to the base type in `code/modules/clothing/under/syndicate.dm`:

```dm
	bodyshapes_with_variations = BODYSHAPE_CERULEAN
+	dying_key = DYE_REGISTRY_UNDER
```

Setting it on the base type, instead of on the tactical turtleneck only, matches how `color` and `rank` jumpsuits do it and gives every syndicate-family jumpsuit the same behaviour. Subtypes inherit the key. The two skirts (`syndicate/skirt` and `syndicate/tacticool/skirt`) set their own `DYE_REGISTRY_JUMPSKIRT` and keep it.

## Verification

After rebuilding, the same Lua test was repeated on the test server with a red crayon as the machine's colour source:

- Tactical turtleneck: became "red jumpsuit" (icon state `jumpsuit`).
- Tacticool turtleneck: became a red jumpsuit.
- Tactical skirtleneck (control): still became a "red jumpskirt".
- Tactical turtleneck suit (`/obj/item/clothing/under/syndicate/sniper`): became a red jumpsuit.

No new runtimes appeared in the round's runtime log.

Not checked:

- A real hand-loaded wash through the machine's interface; `machine_wash` was called directly.
- Washing a tacticool turtleneck with a syndicate-coloured dye (the Grime Liberator telelocational podcrystal path in `tacticool/dye_item()`). A script for it was written, but the run errored before reporting a result and it was not repeated. The override runs before the registry lookup, so it should not be affected, but this was not confirmed in game.
- Other syndicate subtypes (blood-red sneaksuit, camouflage fatigues, Cybersun businesswear, Soviet, combat and Russian army uniforms, syndicate scrubs and so on) were not washed individually.

## Notes

- Making the base type dyeable also affects every syndicate-family jumpsuit that does not set its own key (bloodred and its sleepytime variant, the sniper suit, camo, cybersun, floor tile camo, soviet, combat, rus_army, scrubs). Maintainers who want some of these to stay un-dyeable (for example to keep a nuclear operative or antagonist item distinctive) should set `undyeable = TRUE` on those subtypes, or move the key from the base type to the turtleneck alone. The issue only asks about the tactical turtleneck.
- Washing a syndicate jumpsuit with a syndicate dye looks up `DYE_SYNDICATE` in the registry, which maps back to `/obj/item/clothing/under/syndicate`, so such a wash turns the garment into a copy of the tactical turtleneck. The tacticool type handles this case itself.
- Earlier upstream attempts at this issue (PRs #63603 and #63722) were closed without merging, so no upstream fix existed at the tested commit.
