## Summary

The issue says fake zipties take the regular ziptie time to break out of. On current master they are removed in about one second by every route that was tested, which is what the code specifies (`breakouttime = 1 SECONDS`). The report was filed a day after a change that added a separate resist cooldown for fake restraints, so it may have been made on a build around that change, or may have mistaken the click cooldown for breakout time. The reporter's screenshot could not be viewed, so their exact setup is unknown.

## The bug

As reported: cuffed with fake zipties, a player has to resist for the same time as with real zipties, although the item's `breakouttime` looks correctly set. The reporter found it while testing something else locally and gave no steps beyond "fake zipties, break out".

## Reproduction

Not reproduced. Using the Lua editor and the test server on master:

1. As an observer, spawn humans and a `/obj/item/restraints/handcuffs/cable/zipties/fake`.
2. Cuff a human with the fake zipties by three routes: `equip_to_slot(ITEM_SLOT_HANDCUFFED)`; `set_handcuffed(new ziptie)`; and the real attack path (`zipties.attack(victim, user)`, which goes through `attempt_to_cuff` and `apply_cuffs`).
3. Possess the cuffed human and resist (key `B`).
4. Observe chat and timing.

Result: chat showed "You attempt to remove the fake zipties... (This will take around 1 second and you need to stand still.)", and "You successfully remove the fake zipties." followed within about a second (a progress bar read 30% on the first look). The attack-applied case also finished within the 3-second wait used. No runtime was logged.

The honkbot's cuffing component was also checked: its handcuff type is the same fake ziptie item (`code/modules/mob/living/basic/bots/honkbots/honkbot.dm:27`, `cuff_type = /obj/item/restraints/handcuffs/cable/zipties/fake`), so honkbot-applied cuffs would behave identically. A honkbot-applied cuffing was not run in game.

## Cause

Nothing found. The item (`code/game/objects/items/handcuffs.dm:379-383`):

```dm
/obj/item/restraints/handcuffs/cable/zipties/fake
	name = "fake zipties"
	...
	breakouttime = 1 SECONDS
	resist_cooldown = CLICK_CD_SLOW
```

`carbon/resist_restraints()` (`code/modules/mob/living/carbon/carbon.dm:181`) sets the next special move delay from `restraint.resist_cooldown` and calls `cuff_resist()`, which uses `cuffs.breakouttime` as the `do_after` duration (`carbon.dm:~205-215`). A search for other `breakouttime` overrides found none that apply to fake zipties.

## Fix

None.

## Verification

The one-second breakout was confirmed on all three cuffing routes above. Not checked: honkbot cuffing in game, a hulk or other modifiers that change cuff-break speed (hulk's `FAST_CUFFBREAK` is a faster, not slower, break), being buckled or restrained in other ways while resisting, and the build the reporter used.

## Notes

- `resist_cooldown = CLICK_CD_SLOW` (10 ticks, one second) on fake zipties means a player cannot start another resist for a second after one, which can look like "slow" breakout. The report may have meant this; it is not a breakout-time problem.
- The reporter's issue was filed on 2024-04-23. A PR adding the `resist_cooldown` variable for fake restraints, #82828, was merged 2024-04-22 (per the agents' notes; not re-checked against the tgstation history). It likely fixes whatever the reporter saw.
- Comments on the issue say fake zipties are used by honkbots. Source search finds the type only in `handcuffs.dm` and the honkbot; the arcade prize pool has fake handcuffs, not fake zipties (`arcade.dm:44` per the notes; one comment claims otherwise).
