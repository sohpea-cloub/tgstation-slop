## Summary

The issue says a deaf player who screams (for example from surgery pain) sees "You see how <own name> screams." On master a deaf player's own `*scream` already prints "<name> screams!", so that exact case was not reproduced. The same "You see how <own name> ..." text did appear for emotes flagged `EMOTE_RUNECHAT` (such as `cough`) when the emoting player has runechat turned off. The fix leaves out "You see how " when the viewer is the emoting mob.

## The bug

The reporter described a deaf character being operated on and seeing "You see how <YOUR NAME> screams." The phrase is meant for a deaf bystander who can see someone else make a noise. Shown to the emoter about themselves, it reads wrongly.

## Reproduction

1. Using the Lua editor, spawn a human, give it `TRAIT_DEAF` and a recognisable name ("Deafy"), and give control of it to an admin client.
2. Send `*scream` as that mob. Chat showed "Deafy screams!", which is correct and not the reported text.
3. Spawn a second human ("Other") and make it scream with `emote('scream')`. The deaf mob saw "You see how Other screams!", which is the intended message for a third party.
4. The scream from surgery pain goes through the same `mob.emote("scream")` call (`code/modules/surgery/operations/_operation.dm:1028`), so it takes the same path as step 2. Surgery itself was not performed.
5. To reach the remaining case, turn the enable-runechat preference off for the deaf mob's client (the Lua editor's `write_preference` on `/datum/preference/toggle/enable_runechat`), then make the deaf mob run `emote('cough')`. `cough` is `EMOTE_VISIBLE | EMOTE_AUDIBLE | EMOTE_RUNECHAT` (`code/modules/mob/living/emote.dm:399`).

Observed on master: chat showed "You see how Deafy coughs!" to the deaf mob itself. Steps 2 and 3 are done by calling emotes on the mobs, not by real surgery.

## Cause

Emotes with `EMOTE_RUNECHAT` take a separate branch in the emote code (`code/datums/emotes.dm:157`). For each viewer, if the viewer's runechat preferences do not allow a runechat bubble, it falls back to chat, and for an emote that is both audible and visible it calls `show_message` with a "deaf" alternative (`code/datums/emotes.dm:174-178`):

```dm
else if(is_audible && is_visual)
	viewer.show_message(
		span_emote("<b>[user]</b> [msg]"), MSG_AUDIBLE,
		span_emote("You see how <b>[user]</b> [msg]"), MSG_VISUAL,
	)
```

The loop covers every viewer, including the emoting mob (`viewers(user)` contains `user`), and the alternative text does not check whether `viewer == user`. A deaf emoter therefore gets "You see how <self> ...".

The non-runechat path does not have this problem: there `audible_message` is called with `self_message = msg` and `ALWAYS_SHOW_SELF_MESSAGE` (`code/datums/emotes.dm:201-207`), so the user gets the plain message. `scream` is not an `EMOTE_RUNECHAT` emote, which is why the scream in the report was already correct.

## Fix

One commit, "Fix issue 76895: deaf mobs no longer get "You see how" for their own runechat emotes". In the branch above, the deaf text becomes `[viewer == user ? "" : "You see how "]<b>[user]</b> [msg]`, so the emoter gets the plain "<name> <msg>" and other deaf viewers still get "You see how ...". A smaller change was chosen over restructuring the branch.

## Verification

After rebuilding, the deaf mob with runechat off ran `emote('cough')` and chat showed "Deafy coughs!".

Not checked after the fix: the scream case (already correct before the change), surgery pain in game, a deaf bystander seeing another mob's runechat emote (the change should leave it as "You see how ..."; this was only seen for `scream` before the fix), and the two other "You see how" strings in the emote code (`code/datums/emotes.dm:518` and `:527`, the AI-eye relay) which were not looked at beyond finding them.

## Notes

- The reporter suggested "You scream." as the ideal text. Neither the fix nor master does this: a deaf player's own emote is shown in third person ("Deafy screams!"), the same as for a hearing player. Changing that would be a wider message-style change for all emotes.
- The reported scream wording may have been correct on an older version or come from the runechat path (a different emote or preference setting); the issue does not say which, so this is a guess.
