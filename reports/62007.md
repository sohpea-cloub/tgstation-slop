## Summary

The 2021 report said that hitting someone with an active stun baton on harm intent printed only a "beats" message, so the attack could not be told apart from hitting with a switched-off baton, even though the stun sound played. On current master a harm hit with an active security baton prints both the ordinary attack line and a separate "stuns" line. The stun message now comes from `afterattack`, which always sends it when the hit was a stun. No code change was made.

## The bug

As reported (October 2021): with an active baton, a harm-intent hit still stunned (the stun sound could be heard) but the chat only showed the generic "beats" attack text. The reporter expected both "stuns" and "beats" to be listed, and suspected the message had been lost in PR #61418. A video was attached; it was not viewed.

## Reproduction

I tried to reproduce on master with admin tools. The bug did not occur.

1. Started the test server, started the round and used the Lua editor.
2. Spawned two humans. Gave the first a `/obj/item/melee/baton/security/loaded`, switched it on (`turn_on`), put it in the first human's active hand, and took control of that human. Moved the second human to a tile adjacent to the first.
3. Right-clicked the second human. On a security baton, right click is the harm attack, and it still stuns because `stun_on_harmbaton = TRUE`.
4. Chat showed both lines from that single click:
   - `You attack <victim> in the chest with the stun baton!`
   - `<attacker> stuns <victim> with the stun baton!`

   The hit sound and the baton's stun sound both played.

The attacker's own message uses the generic attack wording ("attack"), not "beat". The issue only requires that a stun line is shown, and it is.

I tested only the right-click harm hit with a loaded security baton on a human target. Left click in combat mode, other baton types (cattle prod, stunsword, boomerang) and cyborg targets were not run. For those I only read the code, which uses the same path.

## Cause

Not a current bug. The reasons the text is now present, at master `87b93338`, all in `code/game/objects/items/weaponry/melee/baton.dm`:

- `pre_attack` (line 141) decides whether a hit stuns. For a right click on a baton with `stun_on_harmbaton` it keeps the normal attack, so the generic attack message is still printed. It only hides the generic attack messages (`HIDE_ATTACK_MESSAGES`, line 183) when the hit is a non-harm stun. It then marks the attack with `STUN_ATTACK` for `afterattack`.
- `afterattack` (line 189) applies the stun and then prints the description returned by `get_stun_description` (line 201) for any attack marked `STUN_ATTACK`. This happens whether or not the normal attack message was shown.
- The security baton's override (lines 712-716) supplies `"[user] stuns [target] with [src]!"` for observers and `"[user] stuns you with [src]!"` for the target.
- `stun_on_harmbaton = TRUE` on `/obj/item/melee/baton/security` (line 482) is what makes the harm hit also stun.

So the generic attack line and the stun line are separate messages by design.

## Fix

None. No code was changed and nothing was committed.

## Verification

Only the check listed under Reproduction was done: one right-click harm hit on a human with an active, loaded security baton, with both messages seen. Not checked: left-click stuns, the other baton types, cyborgs, and a baton that is off or on cooldown.
