# #36751: Open RTGs don't irradiate their surroundings (or the mob buckled to them)

| | |
|---|---|
| Issues | [#36751](https://github.com/tgstation/tgstation/issues/36751): verified and fixed (first half); second half (buckled mobs) not reproducible on master |
| Status | Fixed on the fix branch; checked on the test server |
| Fix branch | [fix/36751](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/36751) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An RTG with its maintenance panel open emits no radiation at all on master. The open-panel radiation pulse was dropped in the radiation rework (#62265) and `process()` now only produces power. The fix restores a radiation pulse each process tick while the panel is open, and turns it off for the abductor void core, which inherits from the RTG. The issue's original complaint, that the buckled mob is exempt while everyone around is irradiated, does not apply to the current radiation system: it irradiates every movable on the pulse's turfs, buckled mobs included.

## The bug

The issue (opened 2018) says that if you buckle someone to an RTG and open its panel with a screwdriver, everything around it except the buckled person gets irradiated. A later edit adds that RTGs no longer irradiate their surroundings at all when open since #62265. Comments from 2022 confirm that opening an RTG "sends out nothing to anyone" and that the RTG pulse was removed accidentally in #62265. RTGs still exist in the code (and in the deep storage ruin), and the RTG source has a comment about buckling someone to an RTG and opening the panel, so the behaviour was intended.

## Reproduction

Reproduced on master `87b93338` using admin tools.

1. Started a round on the test server and observed.
2. In the Lua editor, spawned an `/obj/machinery/power/rtg` and anchored it. Spawned a human on the RTG's tile, handcuffed them and buckled them to the RTG (the RTG requires restraints to buckle). Spawned a second human one tile east.
3. Set `rtg.panel_open = true` and updated its appearance.
4. Waited roughly a minute (several polls over about 70 seconds) and checked `GetComponent(/datum/component/irradiated)` on both humans.

Result before the fix: neither human had the irradiated component.

An earlier version of the Lua script hit an error in the Lua editor and was rerun; the results above come from the successful run.

## Cause

`/obj/machinery/power/rtg/process()` (`code/modules/power/rtg.dm:32`) is just:

```dm
/obj/machinery/power/rtg/process()
	add_avail(power_to_energy(power_gen))
```

There is no radiation anywhere in `rtg.dm`. The pulse that used to be emitted while the panel was open (the pre-rework code reportedly called `radiation_pulse(src, 60)` under the old radiation system; this was not checked against the old source) was removed in #62265 and not re-added in the new system.

The "buckled mob is not irradiated" half does not reproduce on current master. `SSradiation.pulse` (`code/controllers/subsystem/radiation.dm:32`) iterates every `/atom/movable` on each turf in the pulse's range (line 38), and a buckled mob is on the RTG's turf, so it is a normal target.

## Fix

One commit, "Fix issue 36751: open RTGs irradiate their surroundings and buckled mobs again", changing `code/modules/power/rtg.dm`:

- New var `irradiate_when_open` (default TRUE) on `/obj/machinery/power/rtg`.
- `process()` now also calls `radiation_pulse(src, max_range = 3, threshold = RAD_LIGHT_INSULATION)` when `panel_open && irradiate_when_open`.
- `/obj/machinery/power/rtg/abductor` (the void core) sets `irradiate_when_open = FALSE`, so opening a void core's panel does not make it radioactive. The issue only discusses RTGs, and the void core, a different alien power source, shares the type only by inheritance.

The pulse strength is a judgement call, not taken from an earlier design: range 3, the light insulation threshold (0.8), and the default irradiation chance (10%). No higher or lower values were compared.

## Verification

After rebuilding and restarting, the same setup was recreated on the test server (RTG with panel open, a handcuffed human buckled to it, a second human one tile east). About 30 seconds later both humans had the irradiated component, and chat showed "chest bubbles unnaturally, then bursts into blisters" for both the buckled and the adjacent human.

Control: with the RTG's panel closed and a void core with its panel open, a third human standing on the void core's tile (8 tiles east of the RTG) had no irradiated component 40 seconds later.

Not checked:
- Other pulse ranges, chances or insulation values; the numbers were not tuned against anything.
- Walls or other insulation between the RTG and a victim.
- Advanced RTGs and RTGs built from the circuit board; they inherit the same `process()`.
- The void core control is a single negative sample on a 10%-per-pulse mechanic over 40 seconds, but the void core's pulse is switched off by an explicit var, so the result is expected rather than lucky.

## Notes

- Whether the pulse should be this strong is a design decision for maintainers; the constants live in one line in `process()`.
- `radiation_pulse` is called every process tick for any open RTG, which allocates a pulse datum each time. A cooldown, or the existing `radioactive_emitter` component, would be an alternative if that is a concern.
- The issue mentions possible relation to #36437; this was not looked into.
