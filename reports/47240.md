## Summary

All three issues are small bugs in the gun code. In #47240 a burst aborted with a dry-fire click when an earlier bullet destroyed the clicked object, because the remaining shots tried to aim at the target's (now null) turf. In #56903 `fire_gun` treated every adjacent non-mob click as a melee attack, so adjacent turfs could never be shot. In #93838 the suppressed Makarov subtype raised its own `w_class` during `Initialize`, which made any container it spawned in eject it. Each is fixed with a small change in its own commit. For #56903 only adjacent turfs (in combat mode) became shootable; adjacent objects are deliberately still bashed.

## The bug

### #47240

A gun on burst fire, clicked at an object, fired some bullets and then went *click* (dry fire) with ammunition still in the magazine, if one of the first bullets destroyed the object. The remaining shots of the burst were lost and the burst ended.

### #56903

With a gun in hand, clicking a turf next to the player (a wall or floor tile) made the character face it and nothing else happened, with or without combat mode. Clicking a turf further away fired normally, and adjacent mobs could be shot.

### #93838

`/obj/item/gun/ballistic/automatic/pistol/suppressed` creates its own suppressor in `Initialize`. If an instance is created inside a container (storage items, mystery boxes), the gun immediately falls out of the container. No such instance exists on the maps at present, but mystery boxes use the subtype.

## Reproduction

All steps were done on the test server using the Lua editor to call procs directly. For #47240 and #93838 the player action was therefore simulated, not performed by a player. For #56903 the behaviour was checked only after the fix (see Verification); the cause there was found by reading the code.

### #47240

1. Spawn a human and give them a C-20r (burst size 3). The default Syndicate firing pin refuses to fire for this mob, so a plain `/obj/item/firing_pin` was installed in the gun.
2. Spawn a paper five tiles east of the human.
3. In one Lua run, call `try_fire_gun(paper, human, '')` on the gun and then `qdel` the paper. The burst timers fire on later ticks, so the paper is already gone when the first burst step runs. This stands in for "a bullet destroyed the target mid-burst".
4. Result on master: the human's "*click*" floating text and dry-fire sound appeared, and the burst ended. (The bullet count was not read back in this run, so the number of bullets that left the gun before the click is unknown. The issue reporter describes two bullets and then a click.)

A control run with a real 50 integrity paper showed that a burst at an intact object works: all three bullets were fired, and the paper only died on the third.

### #93838

1. In the Lua editor, call `SS13.new('/obj/item/gun/ballistic/automatic/pistol/suppressed', box)` where `box` is a `/obj/item/storage/box`.
2. Result on master: chat showed "The Makarov pistol falls out of the box!".

### #56903

Not reproduced on master in game. Steps to follow: give a mob a pistol with a plain firing pin, stand next to a wall or floor tile, click that tile in combat mode and out of combat mode. Expected on master, going by the code and the issue: no shot in either mode.

## Cause

### #47240

`process_fire` schedules one `process_burst` timer per shot with the original `target` (`code/modules/projectiles/gun.dm:590-593`). Each step calls `fire_casing`, which starts with `var/targloc = get_turf(target)` (`code/modules/projectiles/ammunition/_firing.dm:3`). Once the target is qdeleted, `get_turf(target)` is null, and `throw_proj` returns null for a non-turf `targloc` (`_firing.dm:79-82`). `fire_casing` then returns FALSE (`_firing.dm:12-14`). In `process_burst` a failed shot leads to `shoot_with_empty_chamber` (the click) and `firing_burst = FALSE`, so the rest of the burst is abandoned.

### #56903

In `fire_gun` (`code/modules/projectiles/gun.dm:393`), the branch for `flag` (target adjacent, the user, or on the user) returns `NONE` for anything that is not a mob (`gun.dm:407`):

```
if(!ismob(target)) //melee attack
	return NONE
```

Returning `NONE` lets the click proceed to the normal melee interaction, so an adjacent turf is never a firing target. A commenter on the issue had already identified this area.

### #93838

`/obj/item/gun/ballistic/automatic/pistol/suppressed/Initialize` (`code/modules/projectiles/guns/ballistic/pistol.dm:50-53`) creates a suppressor and calls `install_suppressor`. That proc (`code/modules/projectiles/guns/ballistic.dm:649-656`) calls `update_weight_class(w_class + suppressor.w_class)`. `update_weight_class` sends `COMSIG_ATOM_CONTENTS_WEIGHT_CLASS_CHANGED` to the containing storage, which re-checks the item, finds it too large and ejects it. This is the same behaviour that is intended when a player attaches a suppressor to a gun that sits in a container; it is wrong only at spawn time.

## Fix

Three commits on the fix branch, one per issue.

**Fix issue 47240: burst fire keeps firing at where the target was when it is destroyed mid-burst.** Adds a `turf/burst_target_turf` var on `/obj/item/gun`. `process_fire` stores `get_turf(target)` in it when a burst starts. At the top of `process_burst`, if the target is `QDELETED`, `target` is replaced by that stored turf (and the burst ends cleanly if there is none). The remaining shots therefore go toward where the object was. Energy guns override `process_burst` but call the parent, so they get the fix too.

**Fix issue 56903: guns fire at adjacent turfs in combat mode.** The melee condition in `fire_gun` becomes `!ismob(target) && !(isturf(target) && user.combat_mode)`. In combat mode a click on an adjacent turf now fires the gun. Out of combat mode nothing changes. Adjacent objects are still melee targets. The first version of the commit made every adjacent non-mob shootable in combat mode, but that would have replaced the bashing of adjacent tables, machines and windows with gun fire, which is how players use a gun as a melee weapon. It was narrowed to turfs, which matches the issue title.

**Fix issue 93838: map-spawned silenced Makarov no longer falls out of its container.** `install_suppressor` gets a parameter `adjust_weight_class = TRUE`. The suppressed pistol's `Initialize` now adds `S.w_class` to its own `w_class` directly and calls `install_suppressor(S, adjust_weight_class = FALSE)`. The size is then correct before any container can react, and no weight-class signal is sent at spawn. Attaching a suppressor by hand still goes through `update_weight_class`, so it behaves as before. An alternative, as the issue author suggested, would be removing the subtype; this was not pursued because mystery boxes use it.

## Verification

All on the final build, in game.

- **#47240:** C-20r burst of 3 at a paper that was qdeleted right after the trigger: three "fires the C-20r SMG!" lines, three casings, three .45 bullets, no click. An assault laser rifle (burst of 2) with the same test fired twice ("fires the Type 5/A assault laser rifle!" x2), covering the energy-gun override.
- **#93838:** a suppressed pistol created in a box stayed in it: its location was the box, `w_class` 3, `suppressed` set.
- **#56903**, with a Makarov, starting at 12 rounds:
  - out of combat mode, adjacent turf: `try_fire_gun` returned 0, no shot;
  - combat mode, adjacent table: returned 0, no shot, and a real click gave "You bash the table with the Makarov pistol.";
  - combat mode, adjacent floor: returned 1 and ammo went 12 to 11; a real click on the adjacent floor gave "You fire the Makarov pistol point blank at the floor!" and a casing appeared;
  - combat mode, targeting oneself: still returned 0 (self-shooting still needs the mouth zone).
- The round's `runtime.log` showed no runtimes from these changes.

Not checked: the unfixed behaviour of #56903 in game; a real (non-simulated) burst in which a bullet destroys a real object on its own; other burst guns and other storage types for #93838; adjacent walls specifically for #56903 (the real click test used a floor tile); effects on turrets, cyborgs or mechs that use `fire_gun` or `process_burst`.

## Notes

- Shooting adjacent objects ("structures" in the #56903 body) is not enabled. Doing it would end gun-bashing of adjacent objects while the gun is loaded in combat mode; whether that is wanted is a design decision. Empty guns in combat mode already skip to the attack either way. Turfs have no melee use for a gun, so firing at them costs nothing.
- In #47240 the burst continues toward the destroyed object's turf, so remaining bullets travel on past it. If a different behaviour is preferred (stop quietly rather than click), the change is localized to the `QDELETED(target)` branch in `process_burst`.
- #93838: the issue author wondered whether to remove the subtype instead. The fix keeps it and only changes how the suppressor size is applied.
