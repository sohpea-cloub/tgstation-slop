# #98076: Changing species away from a fish species leaves the fish_flopping speed boost on permanently

## Summary

The fish organ set bonus gives a `/datum/movespeed_modifier/fish_flopping` speed boost to a wet, lying mob that has a fish tail. When the bonus is lost, `disable_bonus()` only removed that modifier if the owner was still wet and still had a fish tail in the tail slot. A species change takes the tail away before the bonus is disabled, so the check always failed and the modifier stayed. The fix removes the modifier unconditionally.

## The bug

A mob with the fish organ set (a cerulean, or a fish-infused human) who is changed to another species, for example by mutation toxin, View Variables, a teleporter that turns them into a fly person, or a hardcore random species change, keeps the fish_flopping speed boost for good. #98069 describes a cerulean who "becomes extremely quick, around almost twice the speed of a regular crew member" after getting legs this way. #98076 describes the same thing from a View Variables or mutation toxin species change.

## Reproduction

Reproduced on the test server with the Lua editor, by setting up the conditions in which the modifier is normally given, then changing the species. It was not tried with mutation toxin, View Variables or the teleporter themselves; these all go through the same species change code.

1. Start a round and open the Lua editor as an admin.
2. Spawn a human and call `set_species` with `/datum/species/human/cerulean`.
3. Add the `is_wet` trait to the mob (`TRAIT_IS_WET`), then call `set_body_position(1)` to make it lie down. The fish_flopping movespeed modifier was present.
4. Call `set_species` with the human species. The chat shows "The oversized fish tail detaches from ...'s human chest, spilling out liters of blood!".
5. Check `has_movespeed_modifier(/datum/movespeed_modifier/fish_flopping)`.

On master, after the species change the mob was a human, the modifier was still present, and calling `set_body_position(0)` (standing up) did not remove it either. Because the modifier stays after the mob gets up, the mob keeps the extra speed.

## Cause

The code is in `code/game/machinery/dna_infuser/organ_sets/fish_organs.dm`. `enable_bonus` adds the speed buff only when the owner is wet and has a fish tail (line 50):

```dm
if(HAS_TRAIT(owner, TRAIT_IS_WET) && istype(owner.get_organ_slot(ORGAN_SLOT_EXTERNAL_TAIL), /obj/item/organ/tail/fish))
	add_speed_buff()
```

`add_speed_buff` (line 174) registers `check_body_position` on `COMSIG_LIVING_SET_BODY_POSITION`, which adds or removes `/datum/movespeed_modifier/fish_flopping` as the mob lies down or stands up. `disable_bonus` (line 55) is the mirror image and has the same condition around `remove_speed_buff()` (lines 75-76):

```dm
if(HAS_TRAIT(owner, TRAIT_IS_WET) && istype(owner.get_organ_slot(ORGAN_SLOT_EXTERNAL_TAIL), /obj/item/organ/tail/fish))
	remove_speed_buff()
```

The bonus is lost because the fish organs left the mob, and on a species change the tail is replaced or removed first. By the time `disable_bonus` runs, the tail slot no longer holds a fish tail, so the condition is false and `remove_speed_buff()` (line 179), which removes the modifier, is never called. Nothing else removes the modifier afterwards. That is the check suspected in a comment on #98069.

## Fix

One commit, "Fix issue 98076: remove fish flopping speed when the fish organ set bonus is lost". In `disable_bonus`, the conditional around `remove_speed_buff()` is removed and the proc is called unconditionally, with a comment that the tail may already be gone by then. The commit message also says it fixes #98069.

`remove_speed_buff()` is safe to call when the buff was never added: it unregisters a signal that may not be registered and removes a modifier that may not be present. No new code path was needed.

## Verification

On the test server after the fix, with the same Lua steps (cerulean, wet, lying, then changed to human): the cerulean showed the fish_flopping modifier before the change. After the change the species was human, `has_movespeed_modifier(fish_flopping)` was `nil`, and the body was still lying down (the movespeed modifier list had 4 other entries). No runtimes were logged for the run.

Not checked:

- Mutation toxin, View Variables and teleporter species changes, #98069's hardcore random species change, and the chaplain android conversion that the reporter mentions. These were assumed to reach the same code.
- A fish-infused human (DNA infuser) rather than a cerulean.
- Removing the fish tail or other fish organs without a species change.
- The modifier being removed while standing after the fix. The check was done with the mob still lying down, which is the case that kept the boost on master.

## Notes

- #98069 is a duplicate of #98076. The cerulean in that report gets the boost for the same reason.
- The modifier's slowdown is `- (CRAWLING_ADD_SLOWDOWN * 0.65)` (`code/modules/movespeed/modifiers/status_effects.dm:74-76`). A comment on #98069 gives the value as -2.6.
- `enable_bonus` and `check_tail` use the same wet-plus-tail condition when adding the buff, which is correct. Only the removal side needed to be unconditional.
- It is not known whether other organ-set bonuses have the same mistake: only the fish set was examined.
