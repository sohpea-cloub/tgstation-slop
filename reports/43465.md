## Summary

#43465 describes a lit cigarette going out when a fire hallucination ends. That came from the old fire hallucination, which really set the mob on fire and then removed the fire stacks. The hallucination has since been rewritten (`code/modules/hallucination/on_fire.dm`): it no longer ignites the mob, and the cigarette stayed lit through a full hallucination on master, so the issue is not reproducible as written.

#96163 is a real bug in the rewritten hallucination. A second fire hallucination on the same mob replaced the "On Fire" alert of the first one, so stop, drop and roll only ended the newer hallucination and the older one kept going until the mob was stamina-crit. The fix makes `start()` refuse a new fire hallucination while another is active on the same mob.

## The bug

### #43465

The reporter says that every time they hallucinate being on fire while smoking, the cigarette goes out when the hallucination ends, and other players briefly see their character on fire at that moment. A 2023 comment explains the old mechanism: the hallucination set the mob on fire, and removing its fire stacks put out smokables.

### #96163

After hallucinating fire and doing a hallucinated stop, drop and roll, the fire does not go away and the mob still collapses from stamina damage. The report is thin, with only the three steps: hallucinate fire, stop drop roll, be stamcrit anyway.

## Reproduction

### #43465 (not reproduced)

1. Using the Lua editor on the test server, spawn a human, put a lit `/obj/item/cigarette` in its mask slot, and call `light()` on it.
2. Cause a fire hallucination on that human with `_cause_hallucination({/datum/hallucination/fire, "test"})` and wait for its whole life (about 30 seconds).
3. Observed: the cigarette's `lit` stayed 1 the whole time, `on_fire` stayed 0 and `fire_stacks` stayed 0. The hallucination ran through its stages and decayed without touching the cigarette.

One related behaviour was seen during the #96163 tests (see Notes): starting a hallucinated roll knocks a worn cigarette off. That is not what the issue describes.

### #96163 (verified)

1. Using the Lua editor, spawn a human, give it a client (possess it as an admin) and call `_cause_hallucination({/datum/hallucination/fire, "test"})` twice in a row on it. (In normal play this happens when the fake lava hazard is stepped on repeatedly, or when the random hallucination roll picks fire again.)
2. Master shows "You're set on fire!" twice and one "On Fire" alert.
3. Click the "On Fire" alert. The chat shows "You stop, drop, and roll!", and later "You extinguish yourself."
4. Observed on master: the global list of ongoing hallucinations (`GLOB.all_ongoing_hallucinations`) still held one fire hallucination with `active = 1` and `fake_firestacks` about 9.9. About 10 seconds later the mob got "You're too exhausted to keep going..." (stamina crit).
5. Control: with a single fire hallucination, the same roll worked. `active` went to 0, the fire images were cleared, and the hallucination decayed away.

## Cause

### #43465

At master, `/datum/hallucination/fire/start()` (`code/modules/hallucination/on_fire.dm:44-57`) only creates a client-side fire image, throws a fake "On Fire" alert, adds a mood event and later applies stamina damage in `process()`. It never touches `fire_stacks` or `on_fire` on the mob, so nothing can extinguish a held cigarette. The code linked in the 2023 comment is from before this rewrite.

### #96163

`/datum/hallucination/fire/start()` throws the alert with `override = TRUE` and stores a weakref to itself on it (`on_fire.dm:53-54`):

```dm
var/atom/movable/screen/alert/fire/fake/alert = hallucinator.throw_alert(ALERT_FIRE, /atom/movable/screen/alert/fire/fake, override = TRUE)
alert.hallucination_weakref = WEAKREF(src)
```

Clicking that alert runs `handle_stop_drop_roll()` (`on_fire.dm:148-149`), which applies `/datum/status_effect/stop_drop_roll/hallucinating` bound only to that weakref. When a second fire hallucination starts on the same mob, its alert replaces the first one's. The alert now points at the newest hallucination, so rolling reduces only the newest one's `fake_firestacks` (`code/datums/status_effects/buffs/stop_drop_roll.dm:115-125`). The older hallucination stays active, keeps its overlay, and keeps applying stamina damage in `process()` (`on_fire.dm:110-115`) until the mob is stamina-crit.

A second fire hallucination can start because nothing stops it. The fake lava hazard calls `cause_hallucination(/datum/hallucination/fire, ...)` every time the hallucinator steps on it (`code/modules/hallucination/hazard.dm:70`), and the random hallucination roll can pick fire again.

## Fix

One commit, for #96163: **"Fix issue 96163: only one fire hallucination at a time"**, in `code/modules/hallucination/on_fire.dm`.

- `start()` now loops over `GLOB.all_ongoing_hallucinations` and returns FALSE if another fire hallucination on the same hallucinator is still `active` and not deleted.
- A new `duplicate` variable is set on the refused hallucination. `Destroy()` returns early for it, so the refused hallucination does not clear the alerts and the mood event belonging to the one that is still running.

Refusing the second hallucination keeps the alert, the roll and the hallucination in a one-to-one relation with a small change. Other approaches (letting the new one replace the old one, or making the alert track every active hallucination) were not tried.

## Verification

On the test server with the fix built, using the Lua editor:

- A human with a client and a lit cigarette got two fire hallucinations in a row. Only one "You're set on fire!" appeared, and the global list held one fire hallucination.
- Clicking the alert and rolling ended it: "You extinguish yourself.", the hallucination went inactive (`active = 0`, `fake_firestacks` negative) and decayed, and the mob did not go stamina-crit.
- The runtime log of the new round had no runtime errors.

Not checked:

- A hallucination in its decay phase (inactive, up to about 9 seconds) is not counted as active, so a new one can start meanwhile, and the old one's `Destroy()` would then still clear the alert and temperature alert of the new one. This was found in the code and not tested.
- The reporter's test merges (an inventory UI refactor) might also play a part; this could not be told.
- The fake lava path and the random hallucination roll were not run; two direct calls stood in for them.
- Whether the pyrophobia terror handler (`code/datums/components/fearful/sources/_sources.dm:165-200`), which keeps a weakref to the latest fire hallucination it is told about, is affected by a refused hallucination was not examined.

## Notes

- **Cigarette knocked off by the roll (side finding, not a fix).** Starting a hallucinated stop, drop and roll printed "Your cigarette was knocked off!" for a mob wearing a lit cigarette. The status effect applies a `Knockdown` in `on_apply()` (`stop_drop_roll.dm:19`) and then calls `extinguish()` on every item on the mob's tile (`stop_drop_roll.dm:30-31`), which the report reads as snuffing the dropped cigarette on the floor. That second step was inferred from the code and not checked in game. This is intended for real fire, but the hallucinating subtype inherits it. It might be worth skipping for the fake case. It is not what #43465 describes, so it was left alone.
- **Overlay re-added after the stamina clear (not confirmed).** `process()` seems to re-create the fire overlay on every tick while `fake_firestacks > 0` even after the exhausted path has called `clear_fire()`, for up to about 9 seconds until `Destroy()`. Seeing it needs a real client, and it was not confirmed visually.
- #43465 could be closed as already fixed by the rewrite of the fire hallucination, unless the reporter still sees it on current master through the knock-off above.
