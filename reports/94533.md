## Summary

A bare `/obj/item/poster` has `poster_type = /obj/structure/sign/poster/random`. That structure never set `poster_item_name` or `poster_item_desc`, so it inherited the placeholder values from `/obj/structure/sign/poster`, and the item was named "hypothetical poster - random poster". The fix gives the random poster structure a real item name ("rolled poster") and description. The reporter's other observation, that the poster was pasted one tile north through a wall, is how poster placement works and was not treated as a bug.

## The bug

A player found an item called "Hypothetical Poster - Random Poster" in the upper cargo maintenance of Wawastation. When placed it turned into a poster (the report says a "lusty xenomorph" one). The item's name and description were the developer placeholders, "hypothetical poster" and "This hypothetical poster item should not exist, let's be honest here."

The report also says the poster was placed one tile north of where the player clicked, appearing on the other side of a wall.

## Reproduction

The Wawastation map is not in the tested tree, so the item in the report could not be found where it was seen. The placeholder name was reproduced by spawning the same item.

1. On the test server, join the round as a crew member.
2. With the Lua editor, create a bare poster item: `SS13.new('/obj/item/poster', loc)` and read its `name`.
3. Result on master: `"hypothetical poster - random poster"`.

For comparison, the two usual random poster items were named correctly: `random_contraband` gave "contraband poster - random contraband poster" and `random_official` gave "motivational poster - Random Official Poster (ROP)".

## Cause

In `code/game/objects/effects/posters/poster.dm`, the item's `Initialize` builds its name and description from the structure type it carries (line 45 onwards):

```dm
name = "[poster_type::poster_item_name] - [poster_type::name]"
desc = poster_type::poster_item_desc
```

The default `poster_type` of a bare `/obj/item/poster` is `/obj/structure/sign/poster/random` (line 21). The base `/obj/structure/sign/poster` defines the placeholders (lines 156 and 157):

```dm
var/poster_item_name = "hypothetical poster"
var/poster_item_desc = "This hypothetical poster item should not exist, let's be honest here."
```

and `/obj/structure/sign/poster/random` (around line 309) set only `name`, `icon_state`, `never_random` and `random_basetype`. Poster structures that are meant to be handed out as items define their own `poster_item_name`/`poster_item_desc`, or copy them from the poster they randomly choose (lines 206 and 207). A bare item never goes through that choice, so it shows the placeholder.

Only a bare `/obj/item/poster` hits this. The `random_contraband` and `random_official` item subtypes use their own structure types. The report says the poster was in a map, so the map presumably placed a bare `/obj/item/poster`. That could not be checked because the Wawastation map file is not in the tree.

## Fix

One commit, **Fix issue 94533: bare rolled posters are named 'hypothetical poster'**. It gives `/obj/structure/sign/poster/random` its own `poster_item_name = "rolled poster"` and a `poster_item_desc` ("A rolled up poster with an automatic adhesive mechanism, for easy pinning to any vertical surface. Who knows what is printed on it.").

This is the smallest change that fixes the name for any bare poster item, wherever it comes from. Changing the map is the other option and is complementary (see Notes).

## Verification

After rebuilding, `SS13.new('/obj/item/poster', loc).name` returned "rolled poster - random poster". The item was also placed on a wall by clicking it. Placement worked: "hanging poster..." and then a poster named "poster - Jovial" appeared on the wall.

Not checked: the item's description text in game, the Wawastation map itself, and any other code that reads `poster_item_name` from the random poster type.

## Notes

- **Placement offset.** In `/obj/item/poster/interact_with_atom` (around line 102 onwards), the placed poster is created on the user's turf and given `pixel_y = 32` (or another offset depending on the direction of the wall), so it is drawn on the wall tile. A poster that looks like it is one tile north "through a wall" may be this drawing offset, but the agent testing this did not reproduce the report's exact case, and this was not investigated further.
- **The map still has the bare item.** The fix changes only the name that players see. The reporter's map still places a bare `/obj/item/poster`, which spawns a random poster of any kind, including ones that normal maintenance loot excludes. Mapping `random_contraband` or `random_official` instead would be a better fix there. The map is not in the tested tree, so this was not changed.
- The issue's test merge list could not be resolved (the issue text shows API errors), so it is unknown whether the report is related to a test merge.
