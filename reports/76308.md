## Summary
A wielded high frequency blade (HFB) attacks from `pre_attack` and returns TRUE, which ends the item's attack chain before `COMSIG_ITEM_AFTERATTACK` is sent. Sanguine Strike listens for that signal, so its enchantment never ended and never drained or healed anyone. The fix sends the signal after a successful slash and also removes the lifesteal element correctly when the enchantment ends. Separately, killed wizard worm segments had no dead icon and were not deleted, so they turned invisible; they are now deleted on death. Splattercasting (#95367) behaves as its code comments describe.

## #76308: Sanguine Strike and the HFB

### The bug
Casting Sanguine Strike on a wielded HFB makes it glow red but the attack is just a normal hit. In the issue thread, a commenter noted "the enchant works, just doesn't go off".

### Reproduction
On master, using the Lua editor with a wizard-style wielded HFB (force 8) and two humans (the target created with the `never_wounded` option, because the first wound on a fresh human hit a `stack_trace` in `scars/_scars.dm:86` unrelated to this bug):
1. Cast Sanguine Strike (force went 8 → 16, red outline filter added).
2. Hit the target with the wielded blade.
3. Observed: force stayed 16, the outline filter stayed, and neither target nor attacker blood volume changed. The enchantment lasted until the item was dropped, and the spell's cooldown stayed stuck. The attacks were made via the attack procs rather than by clicking.

### Cause
`/obj/item/highfrequencyblade/pre_attack` (`code/game/objects/items/weaponry/melee/high_frequency_blade.dm:58-68`) ends with `return slash(target, user, modifiers)`. A TRUE result from `pre_attack` makes `melee_attack_chain` return early (`code/_onclick/item_attack.dm:54`), so `COMSIG_ITEM_AFTERATTACK` is never sent. Sanguine Strike's `on_enchanted_afterattack` (`code/modules/spells/spell_types/self/sanguine_strike.dm`) is registered on that signal, and is what ends the enchantment, starts the cooldown and moves 50 blood from the target to the caster.

A second defect in `end_enchantment` of the same file: it restored `enchanted.force = original_force` before calling `RemoveElement(/datum/element/lifesteal, enchanted.force)`. The element is bespoke per force value, so the removal used the wrong argument and left the element on the item.

### Fix
Commit "Fix issue 76308: high frequency blade slash now sends afterattack so Sanguine Strike works":
- `pre_attack` stores the slash result and, if it succeeded, sends `COMSIG_ITEM_AFTERATTACK` on the blade (target, user, modifiers, attack modifiers) before returning. This also lets other listeners for finished attacks react to HFB slashes.
- `end_enchantment` removes the lifesteal element first, then restores the original force.

### Verification
Same setup after the fix:
- After the cast, force 16. After one hit, force back to 8 and the filter removed.
- Target blood −50, attacker +50, attacker healed 13.5 by the lifesteal; a second hit healed 0 (the element was gone).

Not checked: a real click attack by a player, the dropped-item path, offhand enchanting, and other items that respond to `COMSIG_ITEM_AFTERATTACK` with the blade (now they fire on slashes).

### Notes
- Whether other `pre_attack` overrides that return TRUE should also send the signal was not surveyed.

## #93847: invisible dead wizard worm

### The bug
After a wizard worm (from the wormborn component) is damaged, a killed part turns invisible instead of disappearing.

### Reproduction
On master, using the Lua editor, create a worm of 6 segments and call `death()` on the third. The segments behind it die too (`mob_chain` kills those behind) and `look_dead` sets an empty `icon_state`. The commit message gives the cause; the invisible-corpse state was derived from the code, while the fixed result was confirmed in game (below).

### Cause
`/mob/living/basic/wizard_worm` (`code/datums/components/wormborn.dm:30-50`) defines no dead icon and does not set `DEL_ON_DEATH`, so a dead segment is left with an empty icon state.

### Fix
Commit "Fix issue 93847: wizard worm segments are deleted on death instead of turning invisible" sets `basic_mob_flags = DEL_ON_DEATH` on the worm type.

### Verification
After the fix, killing segment 3 of a 6-segment worm deleted segments 3 to 6. Segment 2 stayed alive (showing the end sprite) and the head stayed alive. Not tested: the death of the head of a worm spawned by a real wormborn wizard.

### Notes
- Whether deleting is the desired behaviour (compared with giving them a dead sprite) is a design choice; deleting needs no new art.

## #95367: splattercasting "bad math"

### The report
The reporter said splattercasting cut cooldowns to 0.5 seconds and drained about 100 blood per cast, instead of halving cooldowns.

### Findings (not a bug)
Using the Lua editor, a human with `/datum/component/splattercasting` was given the timestop spell (cooldown 500 deciseconds, requirements and invocation bypassed) and cast it. Result: the next use was available after 50 ds (5 seconds), and blood went 560 → 335, a cost of 225. That matches `on_after_spell_cast` in `code/datums/components/splattercasting.dm:68-85`:

```dm
var/new_cooldown = cooldown_remaining / 10
var/blood_cost = (cooldown_remaining - new_cooldown) * COOLDOWN_TO_BLOOD_RATIO  // 0.5
```

The comments in the file state this 1/10 cooldown and roughly 270 blood for a 60-second spell as intended. The 30-second spell the issue names (space-time distortion) would give 3 seconds and 135 blood by the same formula. So the cooldown is ten times shorter, not 0.5 s, and the price is as designed; any change is a balance decision. No code change was made.

### Notes
- Not examined: spells whose cooldown starts after the cast (`SPELL_NO_IMMEDIATE_COOLDOWN`) may get a blood cost of 0 under this formula.
