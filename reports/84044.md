## Summary

#84044 ("Changeling speak doesn't take into account that lizards lisp") could not be reproduced as a defect: on current master, hivemind speech from a lizard is lisped like normal speech. #89967 is real: the fake ID a changeling wears after transforming is not an ID card, so examining the wearer never offered the "take a closer look at the ID" link that shows name, age, job, blood type and so on. The fix makes the examine link and its handler work for the changeling's flesh ID and carries the job over from the absorbed person's ID.

## #84044: Changeling speak and the lizard lisp

### The bug

The issue has only a screenshot and no text. The report was filed with the title above; the screenshot is of a hivemind line from a changeling. The investigation could not see what the reporter expected beyond the title and the screenshot. The title reads as if the hivemind line was *not* lisped when it should be, but the screenshot's line reads as lisped ("Let'sss meet at lavaland?"), which is the opposite. This is uncertain; the issue may refer to older code.

### Reproduction

All steps used the Lua editor on the test server (the player action was a forced `say`, not typed in chat).

1. Spawn a human, set its species to lizard, give it the changeling hivemind trait, and make it say `:g sssss hiss` (forced).
2. Read the hivemind chat as a ghost.
3. Repeat with a real changeling: give a human the changeling antagonist datum, add a lizard profile, transform into it, and speak on the hivemind.

Observed on master: the hivemind line was "Scaly: Sss hisss" in step 1 and "Ms. Delta: Sss hisss" in step 3 (same name format as the issue screenshot's "Ms. Pi"). Normal speech from the same lizard was lisped too. So hivemind speech *is* lisped.

### Cause analysis

Speech goes through the tongue's speech modifier first and the say mode second. `COMSIG_MOB_SAY` is sent at `code/modules/mob/living/living_say.dm:195`, and the lizard tongue's speech modifier (`code/modules/surgery/organs/internal/tongue/_tongue.dm:221`) changes the message in response. The say mode (hivemind) handles the already-lisped message later (`living_say.dm:244`, `saymode->handle_message`). Two intended exceptions: speaking Draconic skips the tongue's modifications (`should_modify_speech`, `_tongue.dm:109-112`), and the "imaginary friend" hivemind members added later (`code/modules/antagonists/changeling/powers/absorb.dm:206`, `send_speech`) call the say mode directly with no tongue, so they never lisp. Those members were added after the issue was filed (2024).

### Notes

The agent treated this as already fixed or not reproducible. If the maintainers' intent is that the hivemind should *not* lisp, that is a design change, not a bug fix, and no change was made.

## #89967: Changeling fake ID cannot be examined for details

### The bug

When a changeling transforms with an empty ID slot, it gets a fake ID. Examining the changeling shows "wearing an ID card", but there is no closer-look link that shows the extended information (age, blood type and so on) that a real ID gives.

### Reproduction

1. Spawn a human in a grey jumpsuit with a Head of Personnel ID (age 27).
2. Make a changeling that absorbs this human as a profile and transforms into it.
3. Examine the changeling and compare with a real ID card on a normal human with a missing crew record.

Observed on master: a real ID shows the link (with "Age: 30, Gender: Unknown, Blood Type: ?" in the reproduction), while the changeling's flesh ID showed no link at all. This is the agent's verification run after the fix; the missing link before the fix is established from the code (below) and the reporter, not from a separate before-run. The exact scenario from the issue (own ID removed, redisguise as self) was not run; it differs only in that the flesh ID is created from the changeling's own profile.

### Cause

`/obj/item/changeling/id` (`code/modules/antagonists/changeling/powers/transform.dm:141`) is not an `/obj/item/card/id`. In `code/modules/mob/living/carbon/examine.dm:448`, `wear_id.GetID()` returns null for it, so the "see ID" link (`see_id`) is never produced. The handler in `code/modules/mob/living/carbon/human/human.dm:94-117` also assumes a real card (`id.registered_name`, `id.registered_age`, `id.assignment`).

### Fix

One commit, "Fix issue 89967: Changeling flesh IDs can be examined for their details":

- `examine.dm`: offer the link when the worn item is a changeling flesh ID, using the wearer's `real_name`.
- `human.dm`: the `see_id` handler recognises a flesh ID; it uses `real_name` and `age`, takes the job from a new `assignment` var on the flesh ID, and fills in gender, species and blood type the same way it already does for chameleon IDs, to keep the illusion of a real ID.
- `changeling.dm` / `transform.dm`: a new `assignment` on the flesh ID and `id_assignment` on the changeling profile. When a profile is created, the job is taken from the target's ID (the trim assignment override for advanced IDs, else the assignment); when transforming, it is copied onto the flesh ID.

### Verification

In game, a changeling absorbed a human wearing a Head of Personnel ID (age 27) and transformed. The flesh ID's link, previously absent, now appeared and showed "Name: Gordon Freeman, Job: Head of Personnel, Age: 27, Gender: female, Blood Type: O+, Species: Human". Not checked: the exact reporter scenario, a changeling disguising as someone with no ID, the "no longer wearing that ID card" path for flesh IDs, and examine from different distances.

### Notes

- The job on the flesh ID is only the absorbed person's ID job at absorb time; a profile made from someone without an ID has no job.
- The issue notes that agent IDs are "still affected by this bug" in some other way; that was not investigated.
