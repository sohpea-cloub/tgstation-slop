# #76385: Players inside containers (soul scythe spirits) cannot hear jukebox / dance machine music

| | |
|---|---|
| Issues | [#76385](https://github.com/tgstation/tgstation/issues/76385): verified, fixed |
| Status | Reproduced and fixed; the new-listener path of the fix was not exercised in game |
| Fix branch | [fix/76385](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/76385) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The spirit of a soul scythe is a mob that lives in the scythe's contents. The jukebox component only registers listeners found by `hearers()` and mobs that themselves enter its range, and neither finds a mob inside another movable. The spirit was therefore never registered as a listener and received no music. The fix also registers client mobs found through the recursive-contents lists, both when music starts and when something enters range.

## The bug

A dead player who accepts the offer to become the spirit of a soul scythe cannot hear the radiant dance machine (the disco ball in Uncle Pete's Rollerdome and Disco Inferno) or, by the same code, an ordinary jukebox. The same applies to any player-controlled mob that sits inside another movable rather than on a turf. Commenters on the issue pointed out that the mob is in an item's contents and so is not part of `range()`/`hearers()`.

## Reproduction

On master, using admin tools only:

1. As a ghost (observer), open the Lua editor and spawn a `/obj/machinery/jukebox` a few tiles away and a `/obj/item/soulscythe` on the floor.
2. Possess the scythe's `soul` mob with the observer's ckey (`soul:PossessByPlayer(ckey)`).
3. Start the music with the SDQL2 query `CALL activate_music() ON /obj/machinery/jukebox`, which is what the machine's play button runs. This was done by calling `activate_music()` directly, not by a player pressing the button.

Observed on the unfixed build:
- The possessed spirit's sound list showed only ambience, with no sound on the jukebox channel.
- `music_player.active_song_sound` stayed `null`, because no listener was registered. An SDQL2 query over `music_player.listeners` was also used to inspect the registered listeners.

## Cause

In `code/datums/components/jukebox.dm`:

- `start_music()` (`:204`) registers listeners with only:
  ```dm
  for(var/mob/nearby in hearers(sound_range, parent))
      register_listener(nearby)
  ```
  `hearers()` does not include mobs that are inside other movables' contents, so the scythe's spirit is skipped.
- `check_new_listener()` (`:376`), which handles things entering the jukebox's range after music has started, returns early with `if(!ismob(entered)) return` (`:381`) and registers only `entered` itself (`:385`). A scythe walking into range is not a mob, so the spirit inside it is never registered either.

## Fix

One commit, "Fix issue 76385: players inside containers (soulscythe spirits) now hear jukebox/dance machine music", in `code/datums/components/jukebox.dm`:

- `start_music()` also iterates `get_hearers_in_range(max(x_cutoff, z_cutoff), parent, RECURSIVE_CONTENTS_CLIENT_MOBS)` and registers any mob not already in `listeners`. This uses the recursive-contents lists that the hearing code already maintains, so it also covers MMIs, pAI cards and similar containers.
- `check_new_listener()` registers `entered` if it is a mob, as before, and additionally registers every client mob in `entered.important_recursive_contents[RECURSIVE_CONTENTS_CLIENT_MOBS]` that is not already a listener.

## Verification

After the fix, with the same setup (spirit possessed, jukebox three tiles east, `activate_music()` run through SDQL2), the spirit's sound list showed a sound on the jukebox channel (1021) played positionally from three tiles east at 50% volume. The runtime log had no runtimes.

Not checked:
- The `check_new_listener()` change (a scythe carried into range after the music started) was not exercised in game, because it needs a second client.
- The real dance machine in the Rollerdome / Disco Inferno was not used, only a spawned jukebox.
- The play button was not pressed by a player.

## Notes

- The spirit's sound position is not refreshed when only the scythe moves. `listener_moved` (`:259`) hooks the spirit's own movement signal, and the spirit does not move when its container does. Movement of the jukebox itself is refreshed. A maintainer may want to hook the container's movement, or re-register on container changes.
- The upstream PRs found for this issue (#91667 and #76582) did not fix it. The basic-mob refactor still keeps the soul in the scythe's contents.
- The dmfast patch of BYOND was ruled out as a cause.
