## Summary

#91061 (the file manager refusing names with digits or parentheses) no longer happens on this master: renaming uses `filter_filename_pda()`, not `reject_bad_name()`. #73462 is real: a modular computer built into a computer console sits inside the console's contents, so its own `visible_message()`/`audible_message()` calls have no viewers and print, error and notification messages from console programs were silent. The fix overrides both procs on the console's processor to relay the message through the console.

## #91061: NTos file manager cannot rename files

### The report

The report said the file manager's rename used `reject_bad_name()`, which blocks digits and symbols such as parentheses and requires a capitalised first letter. Renaming to "ntpay" or "picture (30504)" failed with an error sound, while "William" worked.

### Result: not reproduced

On master, both rename actions in `code/modules/modular_computers/file_system/programs/file_browser.dm` validate with `filter_filename_pda()` (`PRG_renamefile` at line 123 and `PRG_usbrenamefile` at line 135); `reject_bad_name` is no longer used there. `filter_filename_pda()` (`code/__HELPERS/text.dm:293`) rejects only names caught by the IC filters and names containing `\ / : * ? " < > |`.

In game, a file on a console's file manager was renamed to "picture (30504)" through the `PRG_renamefile` action called from the Lua editor, and the renamed file was found by `find_file_by_name`. "ntpay" was not tried separately; per the code, it would only be refused if the IC filters match it.

### Notes

The issue's other point, that every file button is labelled "Rename", is covered by [PR #91060](https://github.com/tgstation/tgstation/pull/91060) per the reporter and is a UI matter. It was not checked.

## #73462: Visible messages from a modular computer inside a console are invisible

### The bug

Printing the command manifest from an ID console produced a paper but no chat message such as "prints out a paper", while a PDA shows one.

### Reproduction

1. On the test server, with the Lua editor, spawn `/obj/machinery/modular_computer/preset/id` next to a player.
2. Give its processor paper: set `cpu.stored_paper = 10`.
3. Run the manifest print program's action: `cpu:find_file_by_name('plexagoncrew'):ui_act('PRG_print', {})`. This calls the program directly, not through the UI.

Observed on master: a "crew manifest" paper was printed, and no chat line appeared.

### Cause

A console's computer is an `/obj/item/modular_computer/processor` that lives inside the machine (`code/modules/modular_computers/computers/item/processor.dm`, with `machinery_computer` pointing at the console). Programs call `computer.visible_message(...)` on it, for example the crew manifest print (`code/modules/modular_computers/file_system/programs/crewmanifest.dm:30`); other programs (ID card, arcade, camera, revelation, NT chat) also message through the computer. `/atom/proc/visible_message()` (`code/modules/mob/mob.dm:280`) and `audible_message()` (`:358`) look for viewers or hearers around the source; for an object inside another object there are none, so nothing is shown.

### Fix

Commit "Fix issue 73462: messages from a console's processor are shown to nearby players" overrides `visible_message()` and `audible_message()` on `/obj/item/modular_computer/processor` in `processor.dm`. If `machinery_computer` is set, the call is forwarded to it with the same arguments and its return value; otherwise the normal behaviour runs. Overriding at the processor fixes every program at once. The alternative of changing each program's call site was not tried.

### Verification

After rebuilding and restarting, the same print action showed "The identification console prints out a paper." in chat.

Not checked: other programs that message through the computer (only the manifest print was run), audible messages, a real player pressing print in the UI, and any program that relies on its message going to a mob holding or standing near the processor.
