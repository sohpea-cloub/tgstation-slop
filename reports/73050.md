# #73050: Unattached transit tube pieces cannot be flipped by hand

| | |
|---|---|
| Issues | [#73050](https://github.com/tgstation/tgstation/issues/73050): verified, fixed |
| Status | Fixed; the new verb was checked in game, the bug itself was confirmed from the code only |
| Fix branch | [fix/73050](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/73050) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An unattached transit tube piece (for example the dispenser station) can be rotated in 90 degree steps, but nothing lets a player flip it into its mirrored variant. The code that does the flip, `post_rotation()`, is only called from the RPD. The fix adds a "Flip" right-click verb to `/obj/structure/c_transit_tube` that turns the piece 180 degrees and calls `post_rotation()`, which turns it back and toggles the flipped state.

## The bug

The reporter tried to rebuild the upper transit tube on Charlie Station with a tube dispenser, and could not mirror a deployed piece. They recalled that this used to be done with right-click and "Flip". On master a deployed (not yet wrenched) piece has no such option.

## Reproduction

The no-flip behaviour was established by reading the code. The pre-fix state was not run in game.

1. On the test server, spawn `/obj/structure/c_transit_tube/station/dispenser` next to a human.
2. Alt-click it to rotate it, or right-click it and look at its verbs. Only 90 degree rotation is offered, and no flip verb exists. Flipping works only through the RPD (`code/game/objects/items/rcd/RPD.dm:476`).

## Cause

`/obj/structure/c_transit_tube/Initialize` adds the rotation element with no callback (`code/game/objects/structures/transit_tubes/transit_tube_construction.dm:17`):

```dm
AddElement(/datum/element/simple_rotation)
```

`simple_rotation` rotates by 90 degrees on Alt-click (`code/datums/elements/rotation.dm:47-73`) and only runs a callback after rotating if `post_rotation_proccall` was given. None is given here, so `c_transit_tube/post_rotation()` (`transit_tube_construction.dm:30`), which swaps `flipped`, `build_type` and `icon_state` for pieces that have a `flipped_build_type`, is never reached by hand. The RPD calls it directly.

Disposal pipe constructs pass `post_rotation_proccall` and have a flip verb (`code/modules/recycling/disposal/construction.dm`), so this looks like a transit-tube-only gap.

## Fix

One commit, "Fix issue 73050: add a Flip verb to unattached transit tubes", adds this to `transit_tube_construction.dm`:

```dm
GAME_VERB_SRC(/obj/structure/c_transit_tube, verb_flip, view(1), "Flip", null)
```

The verb requires the user to be able to perform the action (`NEED_DEXTERITY`). If the piece has no `flipped_build_type` it shows the balloon alert "can't be flipped!". Otherwise it turns the piece 180 degrees and calls `post_rotation(usr, ROTATION_FLIP)`. `post_rotation()` expects the 180 degree turn to have already happened and turns it back, so the direction ends unchanged and only the flipped state changes.

A verb was chosen because the issue asked for right-click and flip, and it reuses the existing `post_rotation()` logic, which also covers curves, junctions and termini.

## Verification

On a rebuilt test server, with a possessed human and two pieces on its tile:

- Right-clicking the dispenser showed the verb `Flip {src in view(1)}`.
- Calling Flip on `/obj/structure/c_transit_tube/station/dispenser`: `icon_state` changed from `open_dispenser0` to `open_dispenser1`, and the direction stayed south.
- Calling Flip on a plain straight `/obj/structure/c_transit_tube`: the floating text "can't be flipped!" appeared and nothing changed.

Not checked:

- The pre-fix behaviour in game.
- Wrenching a flipped piece to confirm it builds the flipped tube. That is existing, unchanged logic.
- Curve, junction and terminus pieces, and the distance and dexterity limits.

## Notes

- Disposal constructs were not examined in game and not touched.
- The verb only appears on unattached pieces, as `c_transit_tube` is the construction object.
