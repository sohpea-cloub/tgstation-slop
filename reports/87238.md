# #87238: Slimeperson Split Body and luminescent extract buttons show stale availability

| | |
|---|---|
| Issues | [#87238](https://github.com/tgstation/tgstation/issues/87238) (fixed), [#49559](https://github.com/tgstation/tgstation/issues/49559) (duplicate, same cause, fixed by the same commit) |
| Status | Reproduced, fixed and checked in game |
| Fix branch | [fix/87238](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/87238) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The Split Body button of a slimeperson only changes between greyed-out and lit when something unrelated triggers a refresh (such as resting and standing up), so it stays greyed after blood volume reaches the split threshold and stays lit afterwards. The Extract Minor/Major buttons of luminescents have the same problem when used and when their cooldown ends. The action itself works correctly because the click is checked against the real availability; only the button's appearance is wrong. The fix makes the slime species refresh the Split Body button status on every life tick, makes luminescents refresh their extract buttons on every life tick, and also right after an extract is used.

## The bug

#87238: "slimepeople's split body and regenerate limb buttons dont update until you lay down". A comment on the issue confirms that clicking a greyed Split Body button still works once there is enough blood, so the grey colour is purely visual. #49559 (2020) is the same complaint for the slime powers in general: the buttons keep the state they had when last refreshed, and a later comment says they only update when a core is inserted or removed.

## Reproduction

On master `87b93338`, on a private test server, with admin tools:

1. Start a round and open the Lua editor. Spawn a human, make them a slimeperson with `set_species(SS13.type('/datum/species/jelly/slime'))` (a plain path string failed with a runtime in `set_species`), and take control of them.
2. Set their blood volume above the split threshold, `set_blood_volume(1300)`. The threshold is `BLOOD_VOLUME_SLIME_SPLIT`, 1120 according to the comment on its define (`code/__DEFINES/mobs.dm:19`).
3. Read the actions' availability from Lua: `Regenerate Limbs: 0`, `Split Body: 1`, `Swap Body: 1`. So the action itself reported available.
4. Inspect the Split Body button in the HUD. It was still greyed (colour `#800000`, alpha 128). It was unchanged 8 seconds later. Nothing refreshed it until the player rested and stood up (as reported in the issue).

The luminescent buttons were checked only in the fixed build (see Verification); their stale state on master was derived from the code, not observed.

## Cause

Action button appearance is only recalculated when `build_all_button_icons(UPDATE_BUTTON_STATUS)` is called on the action; `update_button_status` (`code/datums/actions/action.dm:340`) is where the red tint for `!IsAvailable()` is applied. Other triggers exist (an `update_status_on_signal` handler, for instance on resting and standing), which is why lying down appeared to fix it.

For slimepeople:

- `Split Body`'s `IsAvailable` (`code/modules/mob/living/carbon/human/species_types/jellypeople.dm:311-318`) depends on `get_blood_volume() >= BLOOD_VOLUME_SLIME_SPLIT`, but nothing ever refreshed the button when blood volume changed. The Regenerate Limbs button, in contrast, is refreshed every tick by `slime_blood` (`jellypeople.dm:91`, `regenerate_limbs?.build_all_button_icons(UPDATE_BUTTON_STATUS)`), so it did not have this problem in the same way. The species' `on_life` (`jellypeople.dm:292-301`) changes blood volume and prints the "You feel very bloated!" message, but did not touch the button.

For luminescents:

- `use_extract`'s `IsAvailable` (`jellypeople.dm:680-688`) depends on a held extract and on `extract_cooldown`. `Activate` (`jellypeople.dm:690-698`) starts the cooldown but never refreshed the buttons, and nothing refreshed them when the cooldown finished, so after use the buttons stayed lit and after the cooldown they stayed grey, as far as the code goes.

## Fix

One commit on `fix/87238`: "Fix issue 87238: slimeperson split body and extract buttons refresh availability", in `jellypeople.dm`:

- `/datum/species/jelly/slime/proc/on_life` now ends with `slime_split?.build_all_button_icons(UPDATE_BUTTON_STATUS)`, so the Split Body button follows blood volume every life tick, in the same way Regenerate Limbs already does.
- The luminescent species registers `COMSIG_LIVING_LIFE` on the new owner and a new `update_extract_buttons` handler refreshes the status of every `use_extract` action in `luminescent_actions` on each tick. The signal is unregistered in `on_species_loss`. This covers the cooldown expiring.
- `/datum/action/innate/use_extract/Activate` also refreshes the extract buttons right after starting the cooldown, so they grey out at once rather than up to a tick later.

Polling on the life tick was chosen over hooking the exact points where blood volume crosses the threshold, because blood volume can change from many places and the species already polls it each tick for the Regenerate Limbs button.

## Verification

On a rebuilt server in a new round:

- Slimeperson: setting blood volume from 560 to 1300 changed the Split Body button from greyed (`#800000`, alpha 128) to plain (alpha 255) within about a second. Setting it to 700 turned it grey again. Setting it back to 1300 and clicking the button with a real click started the split, which completed ("...you're besides yourself!"). The new body's Split Body button was greyed.
- Luminescent with a grey slime extract inserted: clicking Extract Minor Activation ("You spit out a monkey cube.") greyed both Extract Minor and Extract Major at the same time. After the cooldown (about 10 seconds) both returned to plain, within the 12-second wait.
- No new runtimes in the round's runtime log.

Not checked: the luminescent buttons and the post-split state of the original body's button were not observed on unmodified master (the first came from reading the code, the second was not compared). Swap Body was not touched because it is always available. The Integrate Extract button, stargazers and other jelly subspecies were not examined. Performance impact of refreshing the button each tick was not measured.

## Notes

- The refresh runs every life tick for every slimeperson and luminescent, and refreshing a button updates every viewer's copy. This is small, but a threshold-crossing hook would be cheaper if maintainers prefer one.
- The luminescent extract part goes slightly beyond the title of #87238 but is the same stale-button problem described in #49559.
