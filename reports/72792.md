# #72792: Mobs can move up through lattices but not down

| | |
|---|---|
| Issues | [#72792](https://github.com/tgstation/tgstation/issues/72792): verified, fixed |
| Status | Fixed on a branch; not merged |
| Fix branch | [fix/72792](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/72792) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A lattice carries `BLOCK_Z_OUT_DOWN` but not `BLOCK_Z_IN_UP`. A mob standing above a lattice cannot go down through it, but a mob below it can go up through it. The fix adds `BLOCK_Z_IN_UP` to the lattice, so it blocks both directions like its catwalk subtype already does.

## The bug

As the issue describes it: stand over a lattice and try to move down, and you get "Something's in the way". Go underneath the lattice, try to move up, and you pass through it.

## Reproduction

The test used Catwalk Station, a multi-z map, loaded as the next map. The real Up verb was not used, because it needs flight. Instead, `can_z_move` was called directly. That is the proc the verb uses (`code/modules/mob/mob_movement.dm:549`). A flags argument of 0 limits it to the obstacle checks.

1. Start the round, observe, and open the Lua editor with a new state.
2. Turn the turf at (127,124) on z3 into `/turf/open/openspace`, place an `/obj/structure/lattice` on it, and spawn a human on z2 below it. Z2 was the lowest level here, with z3 above it.
3. Call `human:can_z_move(UP, z2_turf, openspace_turf, 0)` for the move up. Call it with DOWN from a human on the openspace turf to the z2 turf for the move down.

Observed on master: `up=the open space down=0`. The upward move was allowed and the downward move was refused.

## Cause

`code/game/objects/structures/lattice.dm:13` reads:

```dm
obj_flags = CAN_BE_HIT | BLOCK_Z_OUT_DOWN
```

The openspace turf refuses upward entry only when the object on it has `BLOCK_Z_IN_UP` (`code/game/turfs/open/openspace.dm:90`). The lattice sets only the downward-exit flag, so the upward check passes. The catwalk subtype at `code/game/objects/structures/lattice.dm:126` already sets both flags.

## Fix

One commit: "Fix issue 72792: lattices block moving up through them like they block moving down".

It changes the lattice's flags to `CAN_BE_HIT | BLOCK_Z_OUT_DOWN | BLOCK_Z_IN_UP`, matching catwalks.

The issue's one comment suggests the opposite: allow moving both up and down through lattices, since they have gaps. The fix does not take that route. Allowing downward movement would stop lattices from holding anything up. Blocking both is consistent with catwalks.

## Verification

After rebuilding, a second check on the same map covered three tiles, each with openspace on z3 and a human below:

| Tile | Up | Down |
|---|---|---|
| lattice | 0 (blocked) | 0 (blocked) |
| catwalk | 0 (blocked) | 0 (blocked) |
| plain openspace | the open space (allowed) | the floor (allowed) |

Not checked: the actual Up verb or a flying mob, a jetpack, or any other real movement. Only `can_z_move` was called. Other `BLOCK_Z_IN_UP` users and interactions with spacemove backup were not examined.

## Notes

- Side effect: a flying mob or a jetpack user can no longer go up through a lattice-covered openspace tile. This was not tested with a real flyer, and a maintainer should decide whether it is acceptable.
- #68844 concerns `get_spacemove_backup`. It was not touched here, and the inputs do not say whether it is related.
