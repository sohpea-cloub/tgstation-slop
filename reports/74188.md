# #74188: Sheep are unable to be sacrificed

| | |
|---|---|
| Issues | [#74188](https://github.com/tgstation/tgstation/issues/74188): verified and fixed |
| Status | fixed |
| Fix branch | [fix/74188](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/74188) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When the cult has no live sacrifice target (none was found, or it was already sacrificed), the offer rune refuses a sheep and asks for three acolytes. The cause is that `is_sacrifice_target()` compares the sheep's mind, which is null, to each sacrifice objective's target, which is also null. The fix makes `is_sacrifice_target()` return FALSE for a null mind. The sheep easter egg then runs with one invoker.

## The bug

A cultist placing a sheep on an offer rune and invoking it gets "The sheep is too greatly linked to the world! You need three acolytes!", even with three cultists nearby, and the sheep is not sacrificed. The sheep's special handling (a hat overlay, a bleat and a joke message) never runs. The reporter guessed the sheep needed a player controlling it, or enough living cultists. Neither is the case.

## Reproduction

1. On the test server, using the Lua editor, spawn an offer rune (`/obj/effect/rune/convert`), a sheep with its AI off, and a human on the next tile. Possess the human and give it the cult antagonist datum (a client is required for `is_convertable_to_cult`).
2. Put the sheep on the rune. Cult objective #1 had no target ("Objective #1: Nothing").
3. With one invoker, click the rune.

Observed: "The sheep is too greatly linked to the world! You need three acolytes!" and the sheep was not sacrificed.

Because of the cleared target, this fails only when the objective has no live target. With a real target present the sheep is accepted. That second case was not tested; it is inferred from the code.

## Cause

`do_sacrifice()` (`code/modules/antagonists/cult/runes.dm:335`) demands three invokers if the victim is a living human or cyborg, or if it is a sacrifice target:

```
if((((ishuman(sacrificial) || iscyborg(sacrificial)) && sacrificial.stat != DEAD) || cult_team.is_sacrifice_target(sacrificial.mind)) && length(invokers) < 3)
```

A sheep is neither human nor cyborg, so only the second term applies. `is_sacrifice_target()` (`code/modules/antagonists/cult/datums/cult_team.dm:136`) returns TRUE when `mind == sac_objective.target`. A sheep has no mind (null). The sacrifice objective's target is null when no target was found or after `clear_sacrifice` has run (`cult_objectives.dm:14`). `null == null`, so the sheep counts as the sacrifice target, the rite is refused, and the sheep's `on_sacrificed()` (`code/modules/mob/living/basic/farm_animals/sheep.dm`) is never reached. The same applies to any mindless mob.

## Fix

One commit, "Fix issue 74188: mindless mobs matched a cleared cult sacrifice target". `is_sacrifice_target()` now starts with:

```
if(isnull(mind))
	return FALSE
```

The fix is in the helper, not in `do_sacrifice()`, so the other callers (`soulstone.dm:323`, `cult_other.dm:29`) also get a correct answer for a null mind. `soulstone.dm:323` already checks `victim.mind` before calling it.

## Verification

After the fix, the same setup was run by invoking the rune (`attack_hand`) with one invoker. The chat showed "This feels a bit too cliché, don't you think?", the sheep said "BAAAAAAAAH!", then "I accept this meager sacrifice." No refusal appeared.

Not checked: that the hat overlay is rendered (`cult_converted`, which drives it, is set in the same `on_sacrificed()` proc); invoking the rune with three cultists; a live sacrifice target present; sacrificing a sheep a second time; soulstone and `cult_other.dm` behaviour.

## Notes

- The after-fix invocation used `attack_hand` on the rune rather than a click, while the before-fix one used a real click.
- Any other mindless mob should have been affected the same way under these conditions; this was not tested.
