## Summary

The issue reports that a hypnotic flash bought through an implanted uplink while wearing nitrile gloves still carried the buyer's fingerprints when scanned. On master `87b93338` an item bought this way has no fingerprints at all, gloved or bare-handed, and nothing in the purchase path adds any. No change was made.

## The bug (as reported)

A CMO who became a sleeper agent chose an implanted uplink and bought a hypnotic flash while wearing the nitrile gloves from their locker. The gloves were never removed, but the detective found the CMO's prints on the flash. The reporter asked whether roundstart implants, purchased implants and other gloves behave the same. A commenter linked `uplink.dm` and `uplink_handler.dm` as the relevant code and labelled the issue a bug on the assumption it was true.

## Reproduction

On the test server (MetaStation) the round was started and the Lua editor, SDQL2 and the tgui were used:

1. With the Lua editor, spawn a human, give it a mind (`mind_initialize()`), equip nitrile gloves, implant an `/obj/item/implant/uplink` (`implant(h, h)`), give the uplink handler 20 telecrystals, unlock the uplink component, and take control of the human.
2. Press the implant's HUD "Activate" button, which opens the uplink interface, and buy the hypnotic flash (`/datum/uplink_item/device_tools/hypnotic_flash`). The game answered "The flash materializes into your hands!".
3. Inspect the flash's forensics: the Lua editor showed `forensics` as nil, so there were no fingerprints and no hidden prints. An SDQL2 query (`SELECT /obj/item/assembly/flash/hypnotic MAP [loc, forensics, forensics.fingerprints, forensics.hiddenprints]`) returned null for all three on every flash held by a mob (five), including the one bought by the gloved character.
4. Control: take the gloves off, drop everything, and buy another flash bare-handed. `forensics` was again nil.
5. Sanity check of the method: calling `add_fingerprint` on a flash by hand created a forensics datum with fingerprint lists, so the check can see prints when they exist.

The purchase was also made by calling `purchase_item` directly on a mindless human, with the same result (no forensics). That path runtimed in `implantuplink.dm` ("Cannot read null.assigned_role") only because the human had no mind; this is unrelated to the issue.

## Cause

None found on master: the purchase path never fingerprints the new item.

- tgui "buy" in the uplink component calls `/datum/uplink_handler/proc/purchase_item` (`code/modules/antagonists/traitor/uplink_handler.dm:92`).
- That calls the uplink item's `purchase` and `spawn_item` (`code/modules/uplink/uplink_items.dm:148` and `:162`), which hand the item to the buyer through `/mob/proc/put_in_hands` (`code/modules/mob/inventory.dm:293`).
- None of these call `add_fingerprint`. The nearest one is in `/obj/item/ui_act` (`code/game/objects/items.dm:484`), which fingerprints the item hosting the UI (the implant or PDA), not the purchased item.

The 2022 report may have come from an older version of the purchase code (the comment links point to older revisions of `uplink.dm` and `uplink_handler.dm`), or the detective's scan may have picked up prints added later. Neither was confirmed, as the history available for this test was shallow.

## Fix

None.
