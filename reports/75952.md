## Summary
The issue reports that on the PDA's Medical Records app, record notes show up as datum names run together without spaces, and that `<br>` is shown literally instead of as a line break. Reading master, neither happens: the program sends each note's `content` text, and the UI splits disabilities on `<br>`. The in-game check could not be done, so this verdict rests on code reading alone. One cosmetic leftover exists: several notes are joined with a single space on one line.

## The bug
From the issue text and screenshots: with one or more notes on a medical record, the PDA app showed the notes as `/datum/medical_note` names with no separator between notes, and showed `<br>` characters in the disabilities text.

## Reproduction
Not reproduced in game. The planned steps were: spawn a medical records console and a geneticist PDA (which has the Medical Records app preinstalled, `code/modules/modular_computers/computers/item/role_tablet_presets.dm:228`), add two notes to a crew record from the console, open the PDA app and read the notes in its UI data.

What was tried and failed:
- Creating `/datum/medical_note` objects from the Lua editor crashed the test server three times (in `lua_state.dm`'s `load_script`), as did calling the program's `GetRecordsReadable()` from Lua. This looks like a separate problem and was not investigated.
- SDQL2 `UPDATE ... SET medical_notes = list(new /datum/medical_note(...))` failed to parse ("Missing ) at end of expression").

The console/PDA run was not completed.

## Cause
Nothing matching the report was found at master:
- `code/modules/modular_computers/file_system/programs/records.dm:62-65` builds the notes string from each note's text:
  ```dm
  for(var/datum/medical_note/note as anything in person.medical_notes)
  	notes += note.content
  current_record["notes"] = notes.Join(" ")
  ```
  so it sends plain text, not datums.
- `tgui/packages/tgui/interfaces/NtosRecords.jsx:100-104` splits `mi_dis` and `ma_dis` on `<br>` and renders each entry separately. `get_quirk_string()` joins with `<br>` when `medical` is TRUE (`code/modules/mob/living/status_procs.dm`, around line 505).

Both therefore appear to have been fixed since the issue was filed. The repository checkout was shallow, so the commit that fixed them was not identified.

## Notes
- Leftover nit, not the reported bug: `NtosRecords.jsx:108` prints `Notes: {record.notes}` as one text node, so two notes appear on one line separated by a space ("First note Second note"). Sending the list and rendering one box per note, as is done for disabilities, would tidy it.
- The records list uses `key={record.id}`, but no `id` is sent, which is a harmless React warning.
