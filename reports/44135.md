## Summary

The 2019 report says the fugitives spawned by the event had no objectives. On current master a fugitive is given one objective, "Avoid capture from the fugitive hunters.", when it gains the antagonist datum, and it is announced in the greeting and shown in the antagonist info panel. The issue most likely describes an old build that was fixed later. The test ran the ruleset's own assignment call, not the whole midround event, so the full event path is not covered.

## The bug

Reported from a live round in 2019 on client 512.1467: "The antags spawned by the event literally had no objectives." Comments: one says they are not really antagonists, one confirms the bug, and a third asks whether it was fixed. The issue carries the Bug and Tested/Reproduced labels, but no more detail than that.

## Reproduction

Not reproduced. What was done, with the Lua editor on the test server after starting the round and observing:

1. Created a human and gave it a mind. Created a `/datum/team/fugitive` and a `/datum/antagonist/fugitive` with `backstory = "prisoner"`, and called `mind.add_antag_datum(antag, team)`. This is the same sequence as `equip_fugitive()` in the Fugitives midround ruleset (`code/controllers/subsystem/dynamic/dynamic_ruleset_midround.dm:949-955`).
2. Result: the antagonist datum held 1 objective, `mind.get_all_objectives()` returned 1 entry, the team was assigned correctly and the mind's assigned role became Fugitive.
3. Repeated on an admin-possessed human with a client. The chat showed "You are the Fugitive.", the backstory text, "Your current objectives:" and "Objective #1: Avoid capture from the fugitive hunters." The "Open Fugitive Information" button appeared and its panel data listed one objective (`name: "Objective"`, `explanation: "Avoid capture from the fugitive hunters."`, `complete: 0`).

A runtime appeared in the log from an earlier attempt to call `add_antag_datum` on a clientless mob through admin proc call ("WrapAdminProcCall with no ckey"). That came from how the call was made, not from the fugitive code.

## Cause

There is no defect to point at on master.

- `/datum/antagonist/fugitive/on_gain()` calls `forge_objectives()` before the parent `on_gain()` (`code/modules/antagonists/fugitive/fugitive.dm:39-42`).
- `forge_objectives()` (`fugitive.dm:48-52`) creates a plain `/datum/objective` owned by the mind with the text "Avoid capture from the fugitive hunters." and adds it to `objectives`.
- `greet()` ends with `owner.announce_objectives()` (`fugitive.dm:84`), which prints the objective list.
- The hunters get the same treatment: `forge_objectives()` in `code/modules/antagonists/fugitive/hunters/hunter.dm:19-23` adds "Capture the fugitives in the station and put them into the bluespace capture machine on your ship.", and `greet()` announces it (`hunter.dm:50`). This was read in the code only, not run.

Two things may explain how the original reporter saw "no objectives", both only conjecture:

- The objective is a bare `/datum/objective` with no completion check. The code comment says it "isn't the actual survive objective because it's about who in the team survives". The team's round-end report (`fugitive.dm:106-124`) only lists how many fugitives took refuge and who they were, with no objective or success line.
- The 2019 build predates the current objective code, which was added at some point after the report.
