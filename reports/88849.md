| Status | Fixed and checked on the test server |

## Summary

Washing machines are meant to gib animals that are put in them, but the gib code only exists for `/mob/living/basic/pet`. A sloth (Citrus) or a mothroach is a basic mob but not a pet, so when it was held and put in a machine it was only "washed", which does nothing to a mob, and it came out alive when the door was opened. The fix applies the gib behaviour to every `/mob/living/basic`. While verifying it, a second bug showed up: gibbing a mob that is inside a mob holder deleted the mob twice, which produced a runtime. That is fixed in the same commit.

## The bug

The issue reporter put Citrus the sloth into a washing machine and said it came out "crisp and pristine", looking like an item of clothing and not dead, and that throwing it down made it turn back into a creature. Commenters pointed out that the same happens with mothroaches, and one of them guessed that the mob holder (the item a held mob is wrapped in) had been put in the machine instead of the mob being released.

What is really happening: a held mob is an `/obj/item/mob_holder` with the mob in its contents. The washing machine washes the holder, and the holder forwards the wash to the mob. The mob's wash handler only gibs pets, so a non-pet mob inside the holder is left untouched. The holder is then a normal item in the machine, and the mob is still alive inside it.

On master the held sloth did not change its name or icon in the test, so the "clothing" look in the issue's screenshot was not reproduced. The issue lists test merge #88826 under test merge information, and the agents who investigated suspected that its sprite changes caused the look, but this was not checked. What was reproduced is the underlying defect: the animal is not gibbed.

## Reproduction

On master, using the Lua editor as an admin on a running round:

1. Spawn a washing machine, a human, a sloth and a mothroach on the same tile. Set the human's combat mode off.
2. Have the human pick up the sloth (`mob_pickup`), then call the washing machine's `item_interaction` with the human and the sloth's holder as the item. Repeat for the mothroach. This loads the machine by calling procs directly, not by a player clicking on it.
3. Set the machine's `state_open` to false, update its appearance, and call `attack_hand_secondary` with the human to start the cycle.
4. Wait about 20 seconds for the cycle to end, then open the machine.

Observed on master: the cycle ran, the holder was not destroyed, and opening the machine released the live sloth with its name and icon unchanged. Neither mob was gibbed. For comparison, pets (for example corgis) are gibbed by the same machine, since `/mob/living/basic/pet` has a `machine_wash` that gibs.

## Cause

`/atom/movable/proc/machine_wash` does nothing by default (`code/game/machinery/washing_machine.dm:291`). The wash cycle calls it on everything in the machine (`wash_cycle`, `code/game/machinery/washing_machine.dm:234-238`).

The only gibbing override is on pets:

```dm
/mob/living/basic/pet/machine_wash(obj/machinery/washing_machine/washer)
	washer.bloody_mess = TRUE
	investigate_log("has been gibbed by a washing machine.", INVESTIGATE_DEATHS)
	gib()
```
(`code/game/machinery/washing_machine.dm:302`)

A mob holder's wash is forwarded to the held mob (`/obj/item/mob_holder/machine_wash`, `code/game/machinery/washing_machine.dm:325`). Sloths and mothroaches are `/mob/living/basic` but not `/mob/living/basic/pet`, so they inherit the empty default and nothing happens to them.

A lizardqueenlexi comment on the issue named the same cause.

The second bug is in `/obj/item/mob_holder/proc/on_mob_deleted` (`code/modules/mob/living/inhand_holder.dm:49`). It is called from the `COMSIG_QDELETING` signal of the held mob. It cleared `held_mob` and then qdeleted the holder while the dying mob was still in the holder's contents. The holder's `Destroy()` (`inhand_holder.dm:31`) then deleted its contents, including the mob, which was already being deleted. This was not reachable before in this way, because held non-pet mobs were never gibbed by the washer.

## Fix

One commit, "Fix issue 88849: washing machines gib any held basic mob, not just pets", with two changes:

- `code/game/machinery/washing_machine.dm`: the override `/mob/living/basic/pet/machine_wash` became `/mob/living/basic/machine_wash`, so every basic mob that reaches `machine_wash` is gibbed. The simplest change that fixes the reported mobs. A narrower alternative would be to list sloths and mothroaches, or to release the mob from its holder before washing, but neither was tried.
- `code/modules/mob/living/inhand_holder.dm`: `on_mob_deleted` now takes the deleted mob out of the holder's contents (`moveToNullspace()` if its `loc` is still the holder) before qdeleting the holder, so the holder's `Destroy()` does not delete the mob a second time.

## Verification

After the fix, on a fresh round on the test server, the same Lua steps were run with a held sloth and a held mothroach. After the cycle both were gibbed: meat, hide and gibs were produced and the machine showed the bloody state (`wm_0_blood`). The round's runtime log had no new runtime.

Before the second change, with only the `machine_wash` change in place, the same test produced two runtimes in `runtime.log`: "/mob/living/basic/sloth destroy proc was called multiple times, likely due to a qdel loop in the Destroy logic" (`code/controllers/subsystem/garbage.dm:367`), and the same for the mothroach. The call stack showed `on_mob_deleted` qdeleting the holder from the mob's `COMSIG_QDELETING` signal and the holder's `Destroy()` qdeleting the mob.

Not checked: the washing machine loaded by a player clicking with a held mob (the machine was loaded through `item_interaction` calls); other held mob types such as drones, mice or chicks; the stated "crisp clothing" appearance, which did not appear on master; the sprite changes from test merge #88826.

## Notes

- Design choice for review: gibbing now applies to every held `/mob/living/basic`, which also includes held drones, mice, chicks and so on. A narrower rule is possible if only sloths and mothroaches, or only non-sentient animals, should be gibbed.
- Pulling a mob into an open washing machine is still limited to `/mob/living/basic/pet` (`code/game/machinery/washing_machine.dm:405`). Only the held-mob route changed.
- The second change in `on_mob_deleted` is general: any held mob that is deleted while in its holder would have hit the same double qdel, not only washer gibbing.
