# #97097: Butchering a corpse with an unwielded spear from two tiles away fails silently after the do-after

| | |
|---|---|
| Issues | [#97097](https://github.com/tgstation/tgstation/issues/97097): verified, fixed (design question open, see Notes) |
| Status | One fix commit on the branch |
| Fix branch | [fix/97097](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97097) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An unwielded spear has a reach of 2, so the click on a corpse two tiles away is accepted and the butchering do-after starts. When the do-after finishes, `start_butcher` additionally requires `target.Adjacent(source)`, which is never true at that distance, so the butchering is dropped with no message and no meat. The fix replaces the adjacency check with `target.IsReachableBy(user, source.reach)`, the same reach test the click code uses, so the butchering completes from two tiles. Whether spears should be able to butcher at all is a design question a maintainer raised on the issue; the fix does not address it.

## The bug

The reporter attacks a butcherable corpse from two tiles away with a spear that is not wielded in two hands (introduced by #93685, which lets unwielded spears hit from two tiles). The game prints "You begin to butcher ...", shows the progress bar, and when it finishes nothing happens: no meat, no failure message. The reporter confirmed it with a giant slayer spear and a regular spear.

## Reproduction

On master, using admin tools after the round had started:

1. From the Lua editor, spawn a human, give it a regular spear in hand (unwielded; `spear.reach` was 2), turn on its combat mode, and give control of it to the admin's client.
2. Spawn a cow two tiles east of the human and kill it (`death()`).
3. Click the cow.
4. Observed: "You begin to butcher the cow..." and the progress bar. After about 10 seconds nothing happened: no "You butcher the cow." message, no meat, no failure message.

This was done with the real click on the cow, not by calling procs directly.

## Cause

`code/datums/components/butchering.dm:327-331`:

```dm
/datum/component/butchering/proc/start_butcher(obj/item/source, mob/living/target, mob/living/user)
	to_chat(user, span_notice("You begin to butcher [target]..."))
	playsound(target.loc, butcher_sound, 50, TRUE, -1)
	if (do_after(user, speed, target) && target.Adjacent(source))
		on_butchering(user, target)
```

The click is allowed to reach the item because `code/_onclick/click.dm:171` tests `A.IsReachableBy(src, W?.reach)`, and the butchering component's attack handler does not check distance. Once the do-after completes, the `Adjacent(source)` condition is false for a target two tiles away, so `on_butchering` is skipped. There is no `else` branch, hence the silence.

## Fix

One commit, "Fix issue 97097: butchering with a reach weapon no longer fails silently after the do-after". It changes the post-do-after condition in `start_butcher` to `target.IsReachableBy(user, source.reach)`. This keeps the existing behaviour for normal items (reach 1 is the adjacent case) and makes it consistent with how the click was accepted in the first place. The alternative, refusing to start a non-adjacent butchering up front, was not implemented (see Notes).

## Verification

After rebuilding with the fix and repeating the same setup (unwielded spear, dead cow two tiles away, real click): after the do-after the game printed "You fail to harvest some of the eco meat from the cow." and "You butcher the cow.", and the cow was butchered. The "fail to harvest" line is the component's normal effectiveness roll, not the bug.

Not checked: wielded spears, other reach weapons, targets at distance 2 behind obstacles, butchering humans or the neck-slice path, and whether the do-after is interrupted if the target or user moves out of reach mid-way beyond what `IsReachableBy` already does.

## Notes

- A maintainer (Jacquerel) commented that spears should not be able to butcher at all. If that is the intended design, the fix is to remove butchering from spears (or refuse non-adjacent butchering before the do-after starts) instead of this change. The commit instead keeps butchering working at the weapon's reach.
- Side finding, not changed: the neck-slice path at `code/datums/components/butchering.dm:375` has `if (!do_after(user, ...) && victim.Adjacent(source))` followed by `return`. Because of operator precedence this returns only when the do-after fails *and* the victim is adjacent, which looks like it was meant to be "fail or not adjacent". It may deserve its own look.
