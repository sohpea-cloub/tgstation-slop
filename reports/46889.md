## Summary

Hidden (invisible, intangible) revenants could still do two physical things. They could start pulling a mob, because nothing on the pull path checked the revenant's state. They also made a closing door reopen, because `CheckForMobs()` reopens the door for any living mob on its tile. The fix cancels pull attempts while the revenant is not revealed and drops any existing pull when it hides, and makes `CheckForMobs()` ignore mobs with `incorporeal_move`. The projectile half of #50266 was already fixed on master.

## The bug

#46889: a hidden revenant can right-click a cuffed player and pull them. The pulled player cannot be dragged anywhere (the revenant detaches when it moves), but they are held in place. A later comment says that a hidden revenant "can only change their direction", while a revealed one can tug people around. Comments on the issue disagree on whether this should be a feature; the issue is labelled Bug and was handled as one.

#50266: a hidden revenant standing in an open airlock stops the airlock from closing, because the door reopens as soon as it closes. The report also said that a hidden revenant standing in a plasmaglass window hole is not hurt by emitter beams but the glass still breaks.

## Reproduction

All steps were done on the test server with the Lua editor and SDQL2. The pull was started by calling `start_pulling` on the revenant directly, not by right-clicking as a player; the door was closed by calling `close()` on it.

**#46889**

1. Started a round, then in the Lua editor spawned a `/mob/living/basic/revenant`, and a `/mob/living/carbon/human` handcuffed with `set_handcuffed`.
2. Called `rev:start_pulling(human)` on the revenant while it was hidden (invisibility 50, density 0).
3. Master result: the call succeeded and an SDQL2 query showed `rev.pulling` was the human.

**#50266, airlock**

1. Spawned an airlock and moved a hidden revenant onto its tile (`incorporeal_move` was 3, the jaunt value).
2. Called `close()` on the door.
3. Master result: the sound played `airlockclose.ogg` and then `airlock.ogg`, which shows the door reopened.

**#50266, projectiles**: not reproduced in game. Reading the code showed the projectile case is already handled (see Notes).

## Cause

**#46889.** `/mob/living/start_pulling` (`code/modules/mob/living/living.dm:391`) checks `can_be_pulled`, the mobility flags and then sends `COMSIG_LIVING_TRY_PULL` before pulling. The revenant (`code/modules/mob/living/basic/space_fauna/revenant/_revenant.dm`) registers no handler for that signal and has no other check. The `TRAIT_REVENANT_REVEALED` trait is what tells hidden from revealed revenants apart. Applying the revealed status effect (`code/modules/mob/living/basic/space_fauna/revenant/revenant_effects.dm:15-37`) sets that trait, makes the revenant visible and sets `incorporeal_move = FALSE`; when it ends the revenant goes back to `INCORPOREAL_MOVE_JAUNT` and is invisible.

**#50266.** `/obj/machinery/door/proc/CheckForMobs()` (`code/game/machinery/doors/door.dm:655-658`) was:

```dm
/obj/machinery/door/proc/CheckForMobs()
	if(locate(/mob/living) in get_turf(src))
		sleep(0.1 SECONDS)
		open()
```

It runs after a safe close (`door.dm:644-645`; `code/game/machinery/doors/airlock.dm:1467-1468` for airlocks). A revenant is a `/mob/living` with `density = FALSE`, so it is found and the door reopens.

## Fix

Two commits.

**"Fix issue 46889: hidden revenants can no longer pull"** (`_revenant.dm`):

- Registers `COMSIG_LIVING_TRY_PULL` to a new `on_try_pull()`. If the revenant has `TRAIT_REVENANT_REVEALED`, it returns `NONE` and the pull proceeds. Otherwise it sends "You are too intangible to grab [target]!" and returns `COMSIG_LIVING_CANCEL_PULL`.
- `update_revenant_appearance()` already runs when the revealed trait is added or removed. It now calls `stop_pulling()` when the revenant is not revealed, so a pull started while revealed ends when the revenant turns invisible again.

Using the existing pull signal keeps the check in the revenant file, as the revenant already uses signals for similar state. A revealed revenant still pulls normally.

**"Fix issue 50266: intangible mobs no longer hold doors open"** (`door.dm`): `CheckForMobs()` now loops over the living mobs on the tile and skips any with `incorporeal_move`. For the first mob that does not have it, it waits and reopens as before, then returns. The check is on `incorporeal_move`, not on the revenant type, so it applies to any living mob that is intangible.

## Verification

Checked in game on a build with the fix, with the Lua editor and SDQL2:

- #46889: with the hidden revenant, `start_pulling(human)` returned false and `pulling` was nil. After applying the revealed status effect, the revenant pulled the human (the chat said it "grabs ... passively"). After removing the effect, `pulling` was nil again.
- #50266 airlock: with a hidden revenant on the door's tile and `close()` called, only `airlockclose.ogg` played, the door stayed dense (`density` 1) with `operating` 0, and the revenant stayed on the tile. This was checked twice and was stable.

Not checked, or uncertain:

- Pulling by a player clicking, rather than calling `start_pulling`.
- The door check had some confusing intermediate readings during testing (density values read through Lua timers that did not match the expected state right after `open()`); the later, cleaner runs above agreed with each other, but the check was not done against a player-style close.
- The projectile case was not tested in game.
- Doors other than a plain airlock (windoors, shutters and similar) were not tested. They share `CheckForMobs()`, so they are expected to behave the same.

## Notes

- #50266's projectile report: `projectile_hit` for revenants (`_revenant.dm:345-347`) returns `BULLET_ACT_FORCE_PIERCE` for hidden revenants, from the earlier fix for #43804. A 2024 comment on the issue says ranged weapons no longer affect revenants. The emitter beams that break plasmaglass in the report hit the glass, not the revenant, so that part is not a revenant bug.
- Several commenters on #46889 suggested keeping the pull as a feature. The fix removes it for hidden revenants, and a revealed one can still pull. If the owners prefer to keep it, only the first commit needs to be dropped.
- A 2024 comment says hidden revenants can also grab objects but do not move them. The new handler runs for any `start_pulling` target, so objects are covered as well, but this was not tested.
- A related older issue was mentioned in a comment (#17409, "same cause"). It was not examined.
