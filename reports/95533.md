# #95533: Items with no suit storage sprite are drawn as a pink gun, a smoked cigarette or a missing texture

| | |
|---|---|
| Issues | [#95533](https://github.com/tgstation/tgstation/issues/95533) verified (cigarettes, folders, wallets); [#69938](https://github.com/tgstation/tgstation/issues/69938) verified (energy sword); [#93925](https://github.com/tgstation/tgstation/issues/93925) verified (fish); [#86617](https://github.com/tgstation/tgstation/issues/86617) verified and fixed (surgery tools); [#94767](https://github.com/tgstation/tgstation/issues/94767) verified and fixed with a stand-in sprite (Sky Bulge) |
| Status | Fixed on the branch below. Items that never had a suit storage sprite are now left undrawn rather than given art. |
| Fix branch | [fix/95533](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/95533) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When an item with no sprite for the suit storage slot is worn there, the game draws a placeholder instead: the pink "nameless" state of `belt_mirror.dmi`, or, for cigarettes, the item's mask sprite at the mouth's position. The fix adds a check in `update_suit_storage()` so that an item with no usable suit storage sprite gets no overlay at all. It also corrects the surgery tools, which set `worn_icon` where they meant `worn_icon_state`, and gives the Sky Bulge the glass spear's suit storage sprite as a stand-in. A large number of item types (roughly 800) still have no suit storage art; they are now invisible in that slot, not drawn wrongly.

## The bug

Suit storage accepts any item of tiny weight class, plus a list of explicitly allowed types (`GLOB.any_suit_storage`), whatever suit is worn. Most of those items were never given a sprite for the slot. Players see:

- cigarettes in suit storage drawn as lit/smoked cigarettes (#95533);
- folders and wallets drawn as a broken sprite (#95533);
- fish drawn as the missing-texture belt sprite (#93925);
- energy swords drawn as an "ugly pink patch" (#69938);
- surgery tools drawn as a missing texture (#86617);
- the Sky Bulge drawn with no sprite (#94767).

All of these have the same shape: the game asks for a sprite that does not exist and draws whatever the engine substitutes.

## Reproduction

All on master `87b93338`, with admin tools.

1. Spawn a human and dress them in a suit (a plain jacket was used for most items; a surgical apron for the surgery tools).
2. Put the item in the suit storage slot. This was done from the Lua editor with `equip_to_slot_if_possible(item, ITEM_SLOT_SUITSTORE)`, not by the player action of using the inventory UI.
3. Read the human's `overlays_standing` entry for the suit storage layer (`SUIT_STORE_LAYER`, index 11) with the Lua editor or View Variables.

Observed on unfixed code:

- Folder, wallet and goldfish: the overlay used `icons/mob/clothing/belt_mirror.dmi` with the state named after the item (`folder`, `wallet`, `goldfish`). None of those states exist in that file. (This was seen on a build whose first attempt at the fix had a bug and did nothing, so it behaved like master.)
- Static check of the dmi: `belt_mirror.dmi` has no state named `folder`, `wallet`, `fish`, `e_sword`, `scalpel`, `retractor`, `hemostat`, `cautery`, `cigoff` or `dragoonpole0`.
- Cropping the nameless (`""`) state out of the `belt_mirror.dmi` sheet showed a pink/magenta gun, matching the "pink patch" in #69938.
- Cigarette: not observed on unfixed code in game. From the code, `worn_icon` is the mask sprite file and `cigoff` exists there, so the sprite is found and drawn at the mouth's position, which matches the "smoked" look in the report.
- Nothing was looked at as pixels: the test client cannot show rendered images, so the overlay's icon file and state were read instead.

A scan with a throwaway proc (the same logic as the existing `suit_storage_icons` unit test, extended to every tiny item and `GLOB.any_suit_storage`) found roughly 800 item types without a sprite for the slot, including food, disks, instruments, energy swords, shield energy and staffs, as well as some with a `worn_icon` that is not a file.

## Cause

`update_suit_storage()` (`code/modules/mob/living/carbon/human/human_update_icons.dm:301`) builds the overlay with

```dm
worn_item.build_worn_icon(default_layer = SUIT_STORE_LAYER, default_icon_file = 'icons/mob/clothing/belt_mirror.dmi', ...)
```

(`:311`). `build_worn_icon()` takes the state from `worn_icon_state || icon_state` (`:577`) and the file from `worn_icon || default_icon_file` (`:579`), then draws `mutable_appearance(file2use, t_state, ...)` (`:604`). It never checks that the state exists. When the state is missing from a dmi, BYOND draws that dmi's nameless state; in `belt_mirror.dmi` that is the pink gun. That covers the folder, wallet, fish and energy swords.

Two other cases fall out of the same code:

- **Cigarettes.** `/obj/item/cigarette` sets `worn_icon = 'icons/mob/clothing/mask.dmi'` (`code/game/objects/items/cigarettes.dm:197`) and `icon_state = "cigoff"`. Both are valid, so in suit storage the cigarette draws its mask sprite, positioned for the mouth.
- **Surgery tools.** In `code/modules/surgery/surgery_tools.dm` the retractor (line 6), hemostat (37), cautery (70), scalpel (213) and surgical drapes (332) set `worn_icon = "retractor"` and so on. `worn_icon` is a file, and a bare string is not one, so the overlay is built from a nonexistent file and shows a missing texture. The intent was clearly `worn_icon_state`. The carp, ratvar and narsie plushes and the light tube and bulb carry the same kind of text-valued `worn_icon`.

The existing unit test `code/modules/unit_tests/suit_storage_icons.dm` already looks for these cases but only calls `log_test`, so it never fails.

## Fix

Three commits.

**"Fix issue 95533: don't draw a suit storage overlay when the item has no sprite for it".** Adds `/obj/item/proc/has_suit_storage_icon()` next to `update_suit_storage()` and makes `update_suit_storage()` return without building an overlay when it is false. The proc:

- returns TRUE for a generated `/icon` object (greyscale items are already built for their state; `isicon()` was tried first and is also TRUE for dmi file literals, so `istype(x, /icon)` is used);
- returns FALSE when `worn_icon` is text that is not an existing file;
- otherwise returns `icon_exists(worn_icon || belt_mirror.dmi, worn_icon_state || icon_state)`.

It also overrides the proc on `/obj/item/cigarette` (`cigarettes.dm`) to return FALSE, because the cigarette's `worn_icon` is the mask sprite and would otherwise be drawn. This commit covers #95533, #69938 and #93925. A cheaper alternative, adding art for every item, does not scale to roughly 800 types.

**"Fix issue 86617: surgery tools used worn_icon where worn_icon_state was meant".** Changes `worn_icon` to `worn_icon_state` for the retractor, hemostat, cautery, scalpel and surgical drapes. Only the scalpel has a matching state (`scalpel`) in `belt_mirror.dmi`, so it now draws its existing sprite; the others have none and are left undrawn by the first commit.

**"Fix issue 94767: give the Sky Bulge a suit storage sprite (the glass spear's, for now)".** Adds `worn_icon_state = "spearglass0"` to `/obj/item/spear/skybulge` (`code/game/objects/items/weaponry/melee/spear.dm`, defined at line 523), reusing the glass spear's sprite already in `belt_mirror.dmi`. No new art was made.

## Verification

On the fixed build, with a human in a suit and the item put in suit storage from the Lua editor, the suit storage overlay's icon state was:

- cigarette, folder, wallet, goldfish, retractor, pirate energy sword: no overlay (nil);
- scalpel: `scalpel` (its existing sprite);
- Sky Bulge: `spearglass0`;
- pen `pen`, flashlight `flashlight`, cigarette pack `cigpack`, energy gun `gun`: unchanged from before, so items with real sprites still draw;
- carp plushie (text-valued `worn_icon`): no overlay.

The runtime log showed no runtimes caused by the change. A runtime seen earlier (`Error while reading DMI metadata for path 'carp'`) came from the throwaway scan calling `icon_exists` on a text `worn_icon`; the `fexists` check in the fix avoids it.

Not checked:

- Nothing was viewed as rendered pixels; only the overlay state was read.
- The standard (non-pirate) energy sword, the fish other than the goldfish, drapes, hemostat, cautery, and heretic blades in void armour were not individually put in suit storage in the final run. They are covered by the same code path.
- No MODsuit was used (#69938 mentions a Syndicate MODsuit), and no non-default bodyshape or species (e.g. digitigrade).
- The unit tests and the full CI were not run.

## Notes

- Items are now invisible in suit storage when art is missing. That is a design choice: it hides the placeholder but does not give the item a sprite. Real art is still needed for the energy sword, fish, folders, wallets, retractor, hemostat, cautery, drapes and many others. A maintainer may prefer a generic fallback sprite for this slot instead.
- The Sky Bulge's glass spear sprite is a placeholder, so it will look like a glass spear. An earlier upstream commit, "Fixes Giantslayer Spear Having a broken suit slot sprite" (#97834), is similar in spirit.
- `suit_storage_icons` is still warn-only. It could be changed to fail now that missing sprites are handled, but with roughly 800 offenders it would need an allowlist first.
- Other items with a text-valued `worn_icon` (carp, ratvar and narsie plushes, light tubes and bulbs) still carry the bogus variable. It is harmless for suit storage now but could affect other slots; it was not changed.
- #69938 mentions heretic blades in void armour looking the same; `belt_mirror.dmi` has `eldritch_blade` states, so that case may already have a sprite. It was not tested.
