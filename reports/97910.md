# #97910: Goliaths no longer dig for worms (and lobstrosities no longer fish)

| | |
|---|---|
| Issues | [#97910](https://github.com/tgstation/tgstation/issues/97910): verified and fixed. [#97905](https://github.com/tgstation/tgstation/issues/97905): verified and fixed (same wake-up cause as #97910, plus a missing fishing branch) |
| Status | Fixed on the branch and checked in game |
| Fix branch | [fix/97910](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97910) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Two things stopped goliath idle digging, and a third stopped lobstrosity fishing. First, goliath and lobstrosity AI controllers do not run at all when no living player is near them, unless the controller has the `RUN_WHILE_UNWATCHED` trait, which these two did not. On lavaland that is nearly always the case. Second, even when awake, a goliath's dig did nothing, because the `shovel_hands` component dug by calling `attackby()`, which no longer performs item interactions. Third, the lobstrosity behavior tree had no fishing branch left at all. The fix gives both mobs `RUN_WHILE_UNWATCHED`, makes `shovel_hands` dig through `melee_attack_chain()`, and adds a fishing branch to the lobstrosity tree, modelled on the penguin's.

## The bug

Players watching lavaland goliaths (or the crashed pod site) never saw them dig for worms, and nobody found a lobstrosity fishing, even after an hour. In the discussion on #97910 a maintainer noted that mobs now skip their idle behavior when no player is within a screen's width, so the sleeping part may have been intentional. The investigation found that sleeping is only part of it: both the dig and the fishing were also broken independently, so enabling the idle AI alone would not have fixed them.

## Reproduction

All done with admin tools on a test server running master, on the default station map, which has lavaland on a mining z-level.

Cause 1, AI switched off:

1. Start a round and observe. Open the Lua editor.
2. Walk `GLOB.mob_living_list` and read `ai_status` and `ai_traits` for every goliath and lobstrosity.

Observed on master: all 85 goliath and lobstrosity mobs on the lavaland z-level had `ai_status` `ai_off` and `ai_traits` 20 (`DEFAULT_AI_FLAGS`, with no `RUN_WHILE_UNWATCHED`).

A ghost standing next to a goliath did not wake it, because the nearby-client check only counts client-controlled living mobs. Possessing a human next to the goliath woke it at once, and it attacked.

Cause 2, digging that does nothing:

3. With only the wake-up fix applied (see Fix), goliaths did pick dig targets: 11 goliaths reached their hole target (distance 0) and cleared it, but 0 turfs were dug.
4. Calling `melee_attack` on a goliath at its own turf also left the turf's `dug` at 0 after 10 seconds.

Cause 3, no fishing: a search of the code showed that `BB_FISHABLE_LIST` is set in `lobstrosity.dm:60` and `BB_ONLY_FISH_WHILE_HUNGRY` in `lobstrosity_ai.dm`, but nothing reads either key, and the subtrees in `lobstrosity.bt.json` are only escape-captivity, pet command, random speech, random walk and run-away. A lobstrosity could not have fished even when awake. This was established by reading the code, then confirmed by the "after" result below; the "before" state with the wake-up fix alone was not separately watched for lobstrosities.

## Cause

1. `/datum/ai_controller/proc/get_active_ai_status()` (`code/datums/ai/_ai_controller.dm:479-496`) returns `AI_STATUS_OFF` for a controller whose pawn is not in a station or shuttle area, has no nearby client, and lacks `RUN_WHILE_UNWATCHED`. The goliath controller (`goliath_ai.dm:4`) and lobstrosity controller (`lobstrosity_ai.dm:8`) use `DEFAULT_AI_FLAGS` only. The goldgrub (`goldgrub_ai.dm:2`) and mook (`mook_ai.dm:18`) controllers already set the trait.
2. `/datum/component/shovel_hands/proc/dig()` (`code/datums/components/shovel_hands.dm:34`) did `INVOKE_ASYNC(target, TYPE_PROC_REF(/atom, attackby), internal_shovel, mole)`. `/atom/proc/attackby()` (`code/_onclick/item_attack.dm`, near line 150) now only sends `COMSIG_ATOM_ATTACKBY`; item interactions such as digging moved to `base_item_interaction()`, which `melee_attack_chain()` runs. So the shovel never dug. The goliath's `goliath_dig` behavior reaches this through `melee_attack` and `COMSIG_HOSTILE_PRE_ATTACKINGTARGET`. The component is also used by mole-arm bodyparts; that path was not tested, but it calls the same function.
3. `lobstrosity.bt.json` lost its fishing subtree in the behavior-tree conversion.

## Fix

Two commits, one per issue.

"Fix issue 97910: goliaths idle-dig again":

- `goliath_ai.dm`: `ai_traits = parent_type::ai_traits | RUN_WHILE_UNWATCHED`, so the AI keeps planning at the low-priority tier when nobody is near.
- `shovel_hands.dm`: the dig now calls `melee_attack_chain(mole, target)` on the internal shovel instead of `attackby()` on the target.

"Fix issue 97905: lobstrosities fish again":

- `lobstrosity_ai.dm`: the same `RUN_WHILE_UNWATCHED` trait.
- `lobstrosity.bt.json`: a `move_to_and_hunt` subtree bound to `BB_FISHING_TARGET` and `BB_FISHING_TIMER` (45 seconds, combat mode off), placed before random walk, and a target-acquisition leaf (`update_interaction_target`) behind a `key_off_cooldown` on `BB_FISHING_TIMER`, using `/datum/targeting_strategy/fishing`. This follows `penguin.bt.json`.
- `range_turfs_typecache_visible.dm`: a new `/datum/target_source/range_turfs/typecache_visible/lava` target source for visible lava turfs.
- The compiled tree under `build/behavior_trees/...lobstrosity.bt.compiled.json` was regenerated.

The trait was preferred to a proximity-only change because it is how goldgrub and mook controllers already handle the same situation, and it keeps these mobs on the low-priority controller tier.

## Verification

On a fresh round with the fixed, rebuilt tree:

- Before: all lavaland goliaths and lobstrosities `ai_off`. After the trait: 41 goliaths `ai_on_low`, 18 lobstrosities `ai_on_low` (14 on lava in an earlier count). One goliath still reported off; why was not examined.
- With only the wake-up fix, goliaths set their hole target, arrived and cleared it, but nothing was dug (cause 2).
- With the `shovel_hands` change, a manual `melee_attack` on a goliath's own turf turned `dug` from 0 to 1 within 7 seconds. After about 3.5 minutes of round time there were 51 goliaths, 5 holding a hole target, and 7 with a dug asteroid turf next to them. One of those dug turfs was from the manual test; the rest are natural digging.
- Lobstrosities: of 18 awake, 6 had `BB_fishing_timer` set (a hunt had succeeded) and 1 had a fishing target (a lobstrosity at 171,137 with a lava target at 176,136). An SDQL query `SELECT /obj/effect/fishing_float` found 4 floats in the world; those are only created by `profound_fisher` fishing, so lobstrosities were casting.
- No new runtimes, apart from those from the Lua probes themselves.

Not checked:

- A player watching, rather than counts from Lua. No client was standing near the fishing or digging mobs for any length of time.
- A pet or befriended juvenile lobstrosity, and the exact reproduction in #97905 (reviving or befriending one next to lava).
- Mole-arm users and other `shovel_hands` users.
- That fishing yields anything or that the dug turfs produce worms visibly.
- The cost of running the AI of about 85 more mobs at low priority; it was not measured.
- The lobstrosity's ability to hit a target while fishing, interrupting the fishing timer, and the reaction of the hunting behavior to nearby players.

## Notes

- `BB_ONLY_FISH_WHILE_HUNGRY` is still not honoured: nothing reads it, and the penguin pattern only gates on a `BB_NEXT_FOOD_EAT` cooldown, which the lobstrosity does not use. Lobstrosities will therefore fish on a 45-second cycle whether hungry or not. A maintainer who wants the old "only when hungry" behavior needs to add a gate.
- Making unwatched lavaland mobs run again is a deliberate trade for performance, and the sleeping may have been intentional (see the issue comment about tracking a player on the z-level instead). If a different wake-up rule is adopted, the `shovel_hands` and lobstrosity-tree changes are still needed on their own.
- The fix for #97905 touches a behavior tree and its compiled JSON; the compiled file was regenerated by the build, not edited by hand.
- No upstream PR that already fixes these was found in the inputs.
