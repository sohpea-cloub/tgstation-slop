# #95165: Cyborgs (and other non-carbon mobs with a mind) get the Exercise buff from swimming

| | |
|---|---|
| Issues | [#95165](https://github.com/tgstation/tgstation/issues/95165): verified, fixed (the fix is a judgment call, see Notes) |
| Status | verified, fix committed |
| Fix branch | [fix/95165](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/95165) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The `exercised` status effect only checked that its owner had a mind, so a cyborg that entered deep water received the "Exercise" buff and its mood event. The effect only has a purpose for carbons (its payoff comes from sleeping, which only carbons do). The fix makes `on_apply()` refuse owners that are not carbons. A maintainer's comment on the issue ("I mean they did exercise") suggests the behaviour may be considered intended, so the change is for maintainers to accept or reject.

## The bug

Cyborgs, and according to the report mulebots and probably other nonhuman mobs, received the "Exercise" alert ("You feel well exercised! Sleeping will improve your fitness.") after swimming. The screenshot in the report shows a cyborg with the alert. A cyborg cannot sleep, so the buff and its mood event do nothing useful for it.

## Reproduction

Done on an unmodified build through the Lua editor, as an observer. Only a cyborg was tested; mulebots and animals with a mind were not tested separately.

1. Using the Lua editor, changed the turf under the observer to `/turf/open/water/deep_beach/lethal` (with `exhaust_swimmer_prob` 100).
2. Spawned a `/mob/living/silicon/robot` and gave control of it to the player (set its `ckey`).
3. Moved the cyborg out of the water and back in with `forceMove`.
4. After re-entering, a new "Exercise" alert appeared on the cyborg's screen, and the `swimming` status effect was present as well.

## Cause

`code/datums/elements/swimming_tile.dm:100` applies the effect to any `/mob/living` that enters the tile:

```dm
floater.apply_status_effect(/datum/status_effect/exercised, 15 SECONDS)
```

`/datum/status_effect/exercised/on_apply()` (`code/datums/status_effects/buffs.dm:252-256`) only checked for a mind:

```dm
/datum/status_effect/exercised/on_apply()
	if(!owner.mind)
		return FALSE
	owner.add_mood_event("exercise", ...)
	return TRUE
```

Everything that consumes the effect is carbon-only: the sleeping code that turns it into athletics experience is in `code/datums/status_effects/debuffs/debuffs.dm:312`, under a `carbon_owner` variable. A cyborg (or a mob with a mind) therefore got the effect, the alert and the mood event, with no use for them. Other sources apply the same effect (the weight machine, punching bag, boxing, gulag vent, the immovable rod event, some gloves), so they would have the same result for non-carbons.

## Fix

One commit, **Fix issue 95165: only carbon mobs can get the exercised status effect**. In `code/datums/status_effects/buffs.dm`, `on_apply()` now returns `FALSE` unless `iscarbon(owner)` and the owner has a mind. Returning `FALSE` from `on_apply()` stops the status effect from being applied, so all sources are covered by one check rather than patching `swimming_tile.dm`.

## Verification

After a rebuild and restart, with the same steps:

- The cyborg had no `exercised` status effect (`has_status_effect` returned null), still had `swimming`, and got no "Exercise" alert.
- A human taken over by a player entering the same water got the "Exercise" alert and the mood change, so carbons are unaffected.

Not checked: mulebots and animals with a mind; the other sources of the effect (weight machine, punching bag, boxing and so on) with a non-carbon owner; anything that depends on `exercised` for non-carbons, for example the Spacer quirk check at `code/datums/quirks/positive_quirks/spacer.dm:150`, which only reads the effect.

## Notes

- **This may be intended.** Jacquerel commented on the issue "I mean they did exercise", and another comment joked about a live pufferfish getting it. If maintainers want any mob that swims to count as exercising, the fix should not be taken. The reproduction and cause stand either way.
- The effect still requires a mind, so mindless mobs never got it.
- The issue's label is Oversight and it was reported on 2026-02-14.
