# #80770: Blind people can read written text

| | |

## Summary

Blind mobs could open and read the newspaper and the wizard spellbook, because neither item's tgui checks blindness or literacy. Books and the DNA infuser manual already refuse blind readers through the `book_state` tgui state. The fix gives the newspaper and the spellbook that same state and makes `ui_interact` refuse with a message when the user is blind or cannot read.

## The bug

The issue says a few objects, such as certain books and newspapers, can be read while blind, even though the code for books and paper already checks. On master a blind character who used a newspaper in hand got the full Newspaper window with no message. The wizard spellbook behaved the same way.

## Reproduction

1. Start a round on the test server and, using the Lua editor, spawn a human, a newspaper and a spellbook.
2. Blind the human with the Lua editor by applying the `grouped/blindness` status effect (source "test").
3. Give the human control by setting its ckey to the admin's.
4. Pick up the newspaper and click it in hand.

Observed on unfixed master: a tgui window titled "newspaper (Wielded)" opened (interface `Newspaper`) with no blind message. The spellbook's `ui_interact` opened its window for the blind human too. The report describes the spellbook case as the same defect but does not say whether it was triggered by the player action or by calling `ui_interact` directly.

## Cause

`/obj/item/newspaper/ui_interact` (`code/game/machinery/newscaster/newspaper.dm:198`) only checks `ON_FIRE` before opening the UI and has no `ui_state` override, so it uses the default state. `/obj/item/spellbook/ui_interact` (`code/modules/antagonists/wizard/equipment/wizard_spellbook.dm:123`) has no check at all, and the spellbook's `attack_self` (line 61) only checks ownership. By contrast, `/obj/item/tgui_book/manual` uses `GLOB.book_state` (`code/modules/library/book.dm:295`), whose `can_use_topic` (`code/modules/tgui/states/book_state.dm:9`) closes the UI for readers who cannot read or are blind.

## Fix

One commit, "Fix issue 80770: blind mobs can no longer read newspapers and spellbooks":

- Both items get `ui_state()` returning `GLOB.book_state`, so an already open window closes if the user becomes blind, illiterate, or stands in the dark, and (for items) closes when the item is on fire.
- Both `ui_interact` procs now return early with "You are blind and can't read anything!" if `user.is_blind()`, and return if `!user.can_read(src)` (which prints its own message).

This reuses the existing book mechanism rather than adding a new check. A closed upstream PR (#80764) attempted a similar fix.

## Verification

On the rebuilt test server:

- A blind human clicking the newspaper in hand got "You are blind and can't read anything!" and no window.
- With the human blind, calling `ui_interact` on both the spellbook and the newspaper from the Lua editor printed the message twice and opened no windows.
- After removing the blindness status effect, both items opened their windows (Spellbook and Newspaper).
- No runtimes were seen.

Not checked: other tgui readables beyond books, the newspaper, the spellbook and the infuser book; illiterate or dark-room cases for the two items.

## Notes

- The spellbook change is a design call: blind wizards can no longer use the spellbook to buy spells. Maintainers should decide whether that is wanted.
- `book_state`'s "can't read" message may repeat on each UI update in darkness. The report says this already happens for manual books.
- The newspaper's old `attack_self` check no longer exists on master, which is how the gap appeared.
