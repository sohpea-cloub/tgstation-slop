## Summary

Four reports, three defects, all in the shapechange status effect (`/datum/status_effect/shapechange_mob`) and how other systems react to it. Moving the caster's mind into the shape was treated as a real change of body, so a heretic's Living Heart knowledge deleted the heart component and never restored it (#81625, #80525). Reverting a spell shapechange called `fully_heal(HEAL_DAMAGE)` on the caster, which also removed every source of husking, including a ghoul's (#86278). The action movement code moved the caster's body-bound actions to the shape before the mind transferred, which left a mind-bound martial art unable to remove the caster's button, so another button was created on each shift (#98061). Three small commits fix these separately.

## The bug

- **#81625**: a heretic who becomes a spider with a polymorph belt and then reverts no longer has a Living Heart (the "Living Heartbeat" action and the tracking component are gone), although the heart organ itself is still there.
- **#80525**: the same for the ascended lock heretic's greater shapeshift. The report also says all heretic buttons disappeared on reverting; that part did not happen on this build (see Reproduction).
- **#86278**: a ghoul (voiceless dead) who shapeshifts and reverts looks like a normal human again, while remaining bound to the master, mute and "dead" on examine.
- **#98061**: a mind-bound martial art (sleeping carp from a scroll) gets an extra "Recall Teachings" button on each shapechange; the reporter had 11.

## Reproduction

All steps used the Lua editor and the game's own action buttons on a test server, with the tester observing and then taking over a spawned human. Detail that matters: the shapechange has to be triggered by clicking the action button (e.g. "Invert Polymorphic Field") in the client, not by calling the action's proc from Lua. Called from Lua, the client stayed on the human and the shape's AI bit the human out of the body, which is an artifact of the test and not a game bug.

Setup common to all: using the Lua editor, spawn a human, give it a mind with the tester's key (needed or the client does not follow the mind), put a jumpsuit on it, give it a `/obj/item/polymorph_belt/functioning` configured with a stored mob type (giant spider or fox), `channel_time` 0 and a short cooldown, and possess the human.

1. **#81625**: make the human a heretic (add the heretic antagonist, give the Living Heart). Click the belt action to shift, then click it again to revert. Observed on master after the revert: the Living Heart count was 0 (`has_living_heart` = 0), the heart organ still existed but `TRAIT_LIVING_HEART` was gone, and the "Living Heartbeat" action was missing from the action list (Mansus Grasp, Open Heretic Information and Invert Polymorphic Field were still present).
2. **#80525**: grant the heretic `/datum/action/cooldown/spell/shapeshift/eldritch/ascension` (the ascended lock shapechange), choose the rust walker form, click to shift and then to revert. This was run only on the fixed build (see Verification). The "all buttons gone" symptom did not occur there either: the buttons were present on the base build, consistent with it having been fixed upstream by PR #81434 (not independently checked). The living heart part was not run on master for the lock spell; it goes through the same code path as #81625.
3. **#86278**: only the cause was shown on master. Using the Lua editor, `fully_heal(HEAL_DAMAGE)` was called on a ghoul and its husk flag went from 1 to 0, which is what the revert code does. An end-to-end belt shift and revert of a ghoul on master was not done.
4. **#98061**: give the human a sleeping carp style bound to the mind (the `mindbound_martial_arts` component, as the scroll granter does), then shift once with the belt. Observed on master: after one shift there were two "Recall Teachings" (`swap_arts`) actions on the fox, one targeting the human and one targeting the fox. A style bound to the body (`teach()` called directly) never duplicated: one button every time.

## Cause

- **#81625 / #80525.** When the shapechange effect applies (`code/modules/spells/spell_types/shapeshift/_shape_status.dm:37-38`), it calls `caster_mob.mind?.transfer_to(owner)`. That triggers the heretic antagonist's `on_body_transfer()` (`code/modules/antagonists/heretic/heretic_antag.dm:473`), which treats it as a real body change: it calls `on_lose(old_body)` and `on_gain(new_body)` on every researched knowledge. For the Living Heart, `on_lose()` (`code/modules/antagonists/heretic/knowledge/starting_lore.dm:141`) deletes the `living_heart` component from the old body's heart, and the knowledge has no `on_gain()` to put it back. The caster's real body (and its heart) is only stored inside the shape, so the component is lost and not recreated when the mind returns, as pointed out in a comment on #81625.
- **#86278.** On revert with damage conversion, `from_spell/after_unchange()` (`_shape_status.dm:213`, the call is at line 219) used `caster_mob.fully_heal(HEAL_DAMAGE)` to zero damage before applying a share of the shape's damage. `fully_heal()` always calls `cure_husk()` with no source (`code/modules/mob/living/living.dm:999`), which removes all husk sources, including the ghoul status effect's. This matches the explanation in the comment on #86278.
- **#98061.** `from_spell/on_apply()` (`_shape_status.dm:171`) moved the caster's body-bound actions to the shape (lines 186-189) and only then called `return ..()` (line 191), where the mind transfer happens. The mind-bound martial art is moved by the mind transfer and, in `unlearn()` (`code/datums/martial/_martial.dm:386`), looks for the caster's `swap_arts` button to delete. That button was already gone from the caster, so it was not deleted; `teach()` (`_martial.dm:342`) then created a new one for the shape. On revert the left-over button went back to the caster and `teach()` added another one, hence one more button per cycle.

## Fix

Three commits.

- **"Fix issue 81625: shapechanging no longer strips a heretic's Living Heart"** adds `TRAIT_SHAPESHIFT_CASTER` (`code/__DEFINES/traits/declarations.dm` and `code/_globalvars/traits/_traits.dm`). `on_apply()` adds it to the caster before the mind moves, and `restore_caster()` removes it. `living_heart/on_lose()` returns early when the user has the trait. The heart is left alone while the caster is stored in a shape, so nothing needs restoring on revert. This also covers #80525's heart.
- **"Fix issue 86278: reverting a spell shapechange no longer cures the caster's husking"** replaces the `fully_heal(HEAL_DAMAGE)` call with explicitly setting toxin, oxygen, brute, burn and stamina damage to 0 and calling `updatehealth()`, so only damage is cleared. The issue comment suggested instead separating husk healing from damage healing in the heal flags; that was not implemented, and changing the zeroing in this one place avoids touching the shared heal flags.
- **"Fix issue 98061: shapeshifting no longer duplicates the martial arts button"** calls `. = ..()` first in `from_spell/on_apply()`, so the mind transfer (and the martial art's unlearn/teach) happens first, and the body-bound action loop runs afterwards. A different ordering, moving `transfer_to()` after `forceMove()` inside `on_apply()`, was tried and rejected: it stops the client from following the mind (the client stayed on the caster).

## Verification

After the fix, on the test server, using real button clicks:

- #81625: after shift and revert, `has_living_heart` was 1 and the actions were Living Heartbeat, Invert Polymorphic Field, Open Heretic Information and Mansus Grasp.
- #80525: after the ascended lock shapechange (rust walker) and the revert, the living heart was present and the actions included Living Heartbeat, Invert Polymorphic Field, Open Heretic Information, Mansus Grasp and Ascended Shapechange.
- #86278: a ghoul with the polymorph belt, after shift and revert: husk 1, fakedeath 1, ghoul status effect present.
- #98061: a mind-bound sleeping carp: one "Recall Teachings" button as the fox and one as the human, after two full shift and revert cycles. A body-bound style stayed at one button.
- No new runtimes in the runtime log. The build compiled with no errors or warnings.

Not checked:

- The DM unit tests, including the shapeshift unit test (`code/modules/unit_tests/spell_shapeshift.dm`), were not run.
- #86278 end to end on master (the symptom itself), and #80525 on master for the lock spell.
- Other knowledge or antagonist effects that react to a mind transfer into a shape; only the Living Heart was changed.
- Mansus Grasp: a pre-existing "action_status_update overridden" warning (`signals.dm:43`) appears on every shift because the knowledge's `on_gain` re-grants the grasp while the old action still has its signals. This is unrelated to the fix and was left alone.

## Notes

- The `TRAIT_SHAPESHIFT_CASTER` approach assumes every other knowledge that implements `on_lose()` does not care about the same false "body change". Only the Living Heart was checked. A maintainer may prefer handling this in `on_body_transfer()` itself, skipping knowledge callbacks when the new body is a shape of the old one.
- The issue comment on #81625 suggested adding an `on_gain()` to the knowledge. The fix goes the other way, not removing the component in the first place, because the heart never leaves the caster's body.
- The fix for #86278 zeroes five damage types explicitly; any damage type added to `fully_heal(HEAL_DAMAGE)` later would need to be added in this place too.
- #80525 mentions that buttons are gone after reverting; upstream PR #81434 appears to have fixed this already (the buttons were present on this build).
