The three issues are unrelated and were worked in one unit. Each fix has its own commit.

## Summary

**#94537.** `init_slime_auto_activate_reaction_list()` is meant to limit self-sustaining slime extracts to reactions that need only a short list of common reagents. Its loop read `required_reagents` from a reaction *typepath*, which gave no reagent list, so the filter never skipped anything. A self-sustaining gold extract therefore offered the spider broodmother reaction, which needs the uplink-only spider extract reagent. The fix creates an instance of each reaction and checks that.

**#92748.** Using a regenerative crossbreed extract was not logged with who used it on whom. The fix writes a game log line for the user and a personal log line for the target.

**#46464.** A recurring rainbow extract being used up by plasma could not be reproduced on master.

## The bug

### #94537

A self-sustaining slime extract, used in hand, offers the player a menu of reactions it can run on its own. The reporter found that the self-sustaining gold extract offered the spider broodmother reaction. That reaction is normally reachable only with a reagent sold through the uplink, so it bypassed the telecrystal cost and the antagonist requirement.

### #92748

A bluespace regenerative core used on another mob can teleport them somewhere dangerous. The only log line was the teleport itself ("has teleported from ... to ..."), which did not say who caused it. The reporter suspected other slime core uses were also unlogged.

### #46464

The 2019 report says a recurring rainbow extract is used up when it reacts with plasma, regardless of how many uses it had left.

## Reproduction

### #94537

1. On the test server, with the Lua editor, spawn a gold slime extract and read `GLOB.slime_extract_auto_activate_reactions` for the gold extract type.
2. The list had four recipes. One of them was `/datum/chemical_reaction/slime/slimemobspawn/spider`, whose `required_reagents` is `/datum/reagent/spider_extract`.
3. For comparison, the green extract had six entries, including ones that need milk, cellulose and liquid electricity, none of which is on the whitelist.

This reads the generated list, which is what the in-hand menu is built from. The menu itself was not opened as a player.

### #92748

Done by calling `interact_with_atom` on a bluespace regenerative extract from the Lua editor, with one human as user and another as target, rather than by a player clicking. Before the fix, the game log had only the unattributed teleport line.

### #46464

Not reproduced. With the Lua editor, on master:

1. A recurring rainbow extract with 3 uses had 1 unit of plasma added. Its uses went to 2, then the extract's regeneration process raised them to 3 and then 4. The extract was not deleted.
2. A recurring rainbow extract with 10 uses had 5 units of plasma added (the path that spawns the clusterbuster). It survived at 10 uses.

## Cause

### #94537

In `code/modules/research/xenobiology/xenobiology.dm`, `init_slime_auto_activate_reaction_list()` (starting at line 118) loops over `subtypesof(/datum/chemical_reaction/slime)`. The loop variable is a typepath, but it is typed and used as an instance:

```dm
for(var/datum/chemical_reaction/slime/slime_reaction as anything in subtypesof(/datum/chemical_reaction/slime))
	var/recipe_extract_type = slime_reaction.required_container
	...
	for(var/datum/reagent/chem as anything in slime_reaction.required_reagents)
		if(!(chem in auto_activate_reagent_whistlist))
			skip = TRUE
```

Reading `required_container` off the path works, but reading the `required_reagents` list off a path does not give the list. The inner loop therefore never ran, `skip` stayed `FALSE`, and every slime reaction was added to the extract's list (as `new slime_reaction()`). The whitelist of plasma, water, blood, holy water, uranium, radium and slime jelly was never applied.

It was not tested whether stock BYOND behaves the same way as the patched BYOND used on the test server. Reading list variables off a typepath is unreliable in either case.

### #92748

`/obj/item/slimecross/regenerative/interact_with_atom` (`code/modules/research/xenobiology/crossbreeding/regenerative.dm`, around line 17) shows messages, runs the core effect and revives the target, but writes no log line of its own. Only effects such as `do_teleport` log, without a user.

### #46464

Not applicable, since the bug is not present. The reaction handler decrements the extract's uses before `on_reaction` runs (`code/modules/reagents/chemistry/holder/reactions.dm:253`), and `delete_extract` in `code/modules/reagents/chemistry/recipes/slime_extracts.dm:30` only deletes the extract when its uses are 0 or less. Both match the observed behavior.

## Fix

The branch has two commits.

- **Fix issue 94537: self-sustaining extracts no longer offer non-whitelisted reactions.** The loop now iterates `slime_reaction_type`, creates `new slime_reaction_type()` for each, and checks the instance's `required_container` and `required_reagents`. Instances that are skipped are deleted with `qdel`; kept ones are added to the list directly instead of creating a second instance. Creating instances is needed because `required_reagents` is a list that only exists on an instance. This runs once when the global list is built.
- **Fix issue 92748: log regenerative extract use with user and target.** In `interact_with_atom`, before `core_effect_before`, the user gets a `LOG_GAME` line "used <extract> (<type>) on <target>". The target gets a `LOG_VICTIM` line, "had <extract> (<type>) used on them by <user>", in their personal log only. Using it on yourself logs "used ... on themselves". This applies to every regenerative colour, not only bluespace.

## Verification

### #94537

After the fix, the lists contained only whitelisted reagents: gold had `slimemobspawn`, `lesser` and `friendly`; green had `slimemutate`, `slimehuman` and `slimelizard`; rainbow had `slime_rng`, `slimebomb`, `slime_transfer` and `flight_potion`. The spider broodmother reaction was no longer in the gold list. The runtime log showed no new runtimes (only the known empty-line Lua runtimes).

Not checked: the in-hand menu as a player sees it, and that each remaining reaction still works when chosen.

### #92748

After the fix, the game log contained a line of the form "<user> used the regenerative bluespace extract (/obj/item/slimecross/regenerative/bluespace) on <target> (Central Primary Hallway)" directly before the existing teleport line. The target-side personal log line and the self-use line were not read back in game.

Not checked: other regenerative colours, and the other slime extract uses that the issue suggests may be unlogged.

### #46464

Only the two cases above were run.

## Notes

- Fixing the whitelist removes more than the spider reaction: gold, green, rainbow and others now lose any reaction that needs a non-whitelisted reagent. That appears to be the original intent of the whitelist (the variable is spelled `auto_activate_reagent_whistlist` in the source), but a maintainer should confirm that the remaining lists are what they want, for example whether green's slimehuman and slimelizard are still wanted.
- #46464 is seven years old and the code around it has changed since; it may have been fixed by an earlier change. The issue could be closed as not reproducible, with the observed behavior above as support.
- For #92748 the issue also says other slime cores may deserve logging. Only regenerative extracts were addressed.
