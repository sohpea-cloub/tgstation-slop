## Summary

#77532 reported that a HONK mech's Oingo Boingo Punch-Face ignores its cooldown. On current master the cooldown works, so nothing was changed for it. Two other mech issues from the same area were fixed. #93304: the mecha log wrote a pilot's or attacker's visible name (which is "Unknown" or an ID-card name when the person is disguised) instead of their real identity, so the log now uses `key_name()`. #94260: the Ripley's goliath armor module only got its name from the first plate, so later plates never showed up in the mech UI; the name now carries the plate count. The missing goliath-plate sprite in the mech UI is not fixed, because it needs new art.

## The bug

### #77532 (not reproduced)

The reporter said that with a HONK mech and an Oingo Boingo Punch-Face, spamming the weapon on someone killed them almost instantly, even through a pirate spacesuit and a syndicate swat helmet. Commenters noted that the launcher has a cooldown in the code, that the flashbang launcher also seemed to have none, and that other weapons (an Ultra AC 2) did have normal delays. One commenter guessed that launchers might skip the cooldown check.

### #93304

The mecha log (`mecha.log`) named people by their visible name. In the reported round it said that "Nicholas Perry" moved in as pilot, drilled through walls and a head, but the person was actually someone else wearing Nicholas Perry's ID and a spacesuit. Anyone reading the log was pointed at the wrong person.

### #94260

On a Ripley, goliath plates showed no sprite in the mech UI's module list, and the reporter said it refused to show more than one plate (the issue has only a screenshot and "should be obvious", so the exact complaint is partly an interpretation: the investigation found that the module's entry never reflected how many plates were applied).

## Reproduction

### #77532

1. On the test server, using the Lua editor, spawned a HONK mech (`/obj/vehicle/sealed/mecha/honker`) with a punching glove launcher (`.../launcher/punching_glove`, the Oingo Boingo Punch-Face) attached, put a pilot in it, and a human target 4 tiles away.
2. Took control of the pilot and clicked on the target. The first click fired ("HONK", "... is hit by the punching glove!"). Two further clicks 1 to 2 seconds later did nothing.
3. In Lua, called the weapon's `action()` five times in the same tick against the target. Only one projectile was used (the glove's `projectiles` went from 8 to 7), and the calls after the first returned nil.
4. Checked the damage: one hit did 32.5 brute damage and threw the target 7 tiles. The weapon's `equip_cooldown` is 20 (2 seconds). With roughly 4 hits needed to kill an unarmored human, that is strong, but it is the intended 2-second cadence, not a bypass.

Armored targets (pirate suit and swat helmet) were not tested.

### #93304

1. Using the Lua editor, equipped a human with an ID card registered to another name and a gas mask, called `update_visible_name()`, and had them enter a HONK mech (`moved_inside`). The human's `name` was "Unknown".
2. Read the mecha log. Before the fix it said: `[H.O.N.K] () Unknown moved in as pilot.` The person's real name and ckey appear nowhere in the line.

The reporter's exact case (an ID name shown for a spacesuited wearer) was not reproduced as such; the test case showed "Unknown" because of the mask. Both come from the same cause (below).

### #94260

The bug itself was not observed before the fix; the cause was found by reading the code and the fix was checked afterwards. Pre-fix expectation from the code is described under Cause.

## Cause

### #77532

Not a bug on master. The launcher's `action()` (`code/modules/vehicles/mecha/equipment/weapons/weapons.dm:451-466`) starts with `if(!action_checks(target)) return`. `action_checks()` (`code/modules/vehicles/mecha/equipment/mecha_equipment.dm:104-123`) returns FALSE while `TIMER_COOLDOWN_RUNNING(chassis, COOLDOWN_MECHA_EQUIPMENT(type))`, and the launcher then calls `TIMER_COOLDOWN_START(chassis, COOLDOWN_MECHA_EQUIPMENT(type), get_equip_cooldown(target))`. The cooldown is on the mech, keyed by the weapon type. The report was from August 2023, and the issue's own comment links to the code of that time; it was probably fixed since, but the history was not checked.

### #93304

A human's `name` variable is set from `get_visible_name()` (`code/modules/mob/living/carbon/human/human_helpers.dm:40`), which gives "Unknown" for a hidden face or the ID card's name for a disguised one. Mecha code logged mobs with plain string interpolation (`"[newoccupant] moved in as pilot."`, `"[user] drilled through [src]"` and similar), which uses that visible name. The first lines affected are in `code/modules/vehicles/mecha/mecha_mob_interaction.dm` (e.g. `:54`, `:7`, `:165`), `mecha_defense.dm`, `combat/durand.dm`, `equipment/tools/mining_tools.dm:182` and `equipment/tools/medical_tools.dm`. The rest of the codebase uses `key_name()` for this, as the nearby brain/MMI entry does (`mecha_mob_interaction.dm:110`).

### #94260

`applyplate()` in `code/datums/components/armor_plate.dm:65-111` handles each plate. For a mech it creates an abstract armor module (`plate_component`) and copies the hide stack's name, description and icon state onto it, but only the first time:

```dm
if (plate_component)
	return
plate_component = new(mecha_for_upgrading)
plate_component.name = our_upgrade_item.name
```

Later plates hit the early return, so the module never changed after the first plate; the mech UI had no way to show how many plates there were. Separately, the module's `icon_state` is copied from the hide stack (`goliath_hide`, `goliath_hide_2`, `goliath_hide_3`), but the mech UI draws module icons from a spritesheet built from `icons/obj/devices/mecha_equipment.dmi` and `icons/obj/ore.dmi` (`code/modules/asset_cache/assets/mecha.dm`, used in `tgui/packages/tgui/interfaces/Mecha/ModulesPane.tsx:149`). Neither file has a `goliath_hide*` state (the art lives in `icons/obj/stack_objects.dmi`), so the icon is blank.

## Fix

Branch: [fix/77532](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/77532), two commits.

1. "Fix issue 93304: mecha logs name pilots/attackers with key_name, not the visible (disguise) name". Replaces plain mob interpolation with `key_name()` in the mecha log messages in `mecha_mob_interaction.dm` (try to enter, moved in as pilot, moved out), `mecha_defense.dm` (hand/paw, alien, simple animal, hulk, item attacks), `combat/durand.dm` (the two defense-field messages), `equipment/tools/mining_tools.dm` (drilled through) and `equipment/tools/medical_tools.dm` (syringe gun). The move-out line uses `ismob(mob_container) ? key_name(mob_container) : mob_container` because the container can be a brain item rather than a mob. `key_name()` was chosen over `real_name` so the log shows both the ckey and the real mob name, the usual format in admin logs.
2. "Fix issue 94260: each goliath plate on a mech updates the armor module's name with the count". In `applyplate()`, the module is still created once, but its name is now set on every plate to `"[our_upgrade_item.name] ([amount]/[maxamount])"` (for example "goliath hide plates (2/3)"). The description and icon are still copied only at creation.

## Verification

- #93304: after rebuilding, a disguised pilot (gas mask, so visible name "Unknown") entering the HONK mech produced `[H.O.N.K] () <ckey>/(<real name>) moved in as pilot.` instead of "Unknown". Only this line was checked in game; the other changed log lines (attacks, drill, syringe gun, defense field, move out) were not exercised, only compiled.
- #94260: on a Ripley, applied three goliath hide plates one at a time and read `get_module_ui_data()`. The `mecha_armor` entry read "goliath hide plates (1/3)", then "(2/3)", then "(3/3)", with `icon` still `goliath_hide_2` (the stack's icon state when the first plate was applied, as before the fix). The mech UI itself was not opened to look at the result.
- #77532: no fix, nothing to verify.

Not done for #94260: adding `goliath_hide`, `goliath_hide_2` and `goliath_hide_3` 32x32 states to `icons/obj/devices/mecha_equipment.dmi` (copying from `stack_objects.dmi` would work), or giving the module its own icon state. An attempt to build the DMI from Lua did not produce a usable file, and no art was changed. Until then the plate icon remains blank.

## Notes

- Maintainers may want to close #77532 as no longer reproducible. Each punch is 35 throwforce (32.5 brute observed) plus a throw of about 7 tiles, every 2 seconds, so the weapon is lethal in a handful of hits, which matches the report's description of "nearly instant" without any cooldown being skipped.
- Because the icon state is copied from the first plate applied, a Ripley that gets a single plate and then more will keep that first stack's icon state. This will matter once art exists; using one fixed icon for the module would be simpler.
- Other mecha log lines still format mobs with plain interpolation (for example in the equipment and `_mecha.dm` code paths not touched here); only the places found with a search for the affected phrases were converted.
