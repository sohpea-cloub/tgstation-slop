## Summary

#98106: atmospherics machines set no `interaction_flags_click`, so the generic ctrl-click and alt-click handlers let mobs without advanced tool use (a xenomorph larva was tested) toggle them and change their settings. The fix sets `NEED_DEXTERITY` on `/obj/machinery/atmospherics` and on the electrolyzer. #83595: the larva Hide action added and removed `TRAIT_IGNORE_ELEVATION` the wrong way round, so a hidden larva on a table stayed raised by the table's 12 px elevation and was visible. The fix swaps the two calls.

## #98106: hotkeys on atmospherics machinery

### The bug

A xenomorph larva can ctrl-click an atmospherics machine (tested with an outlet injector) to turn it on or off, and alt-click it to change its settings. Larvae and other xenomorphs are not supposed to operate complex machinery. A maintainer's comment on the issue traces it to PRs #83784 and #82656, which removed the `can_interact()` guards that kept non-dexterous mobs away from such machines.

### Reproduction

1. On the test server, using the Lua editor, spawn an outlet injector and a xenomorph larva, and give the larva a player's client (set its `ckey`).
2. As the larva, ctrl-click the injector. Floating text said it was "turned on".
3. As the larva, alt-click the injector. The volume output was set to 200 L/s.

So a larva changed the machine's state. This was done through real clicks by a player-controlled larva.

### Cause

`/obj/machinery/atmospherics` did not set `interaction_flags_click`, which defaults to `NONE` (`code/game/atom/_atom.dm:143`). The ctrl-click and alt-click handlers check `can_perform_action(target, target.interaction_flags_click | SILENT_ADJACENCY)` (`code/_onclick/click_ctrl.dm:24`, `code/_onclick/click_alt.dm:22`). With no `NEED_DEXTERITY` in the flags, the check passes for mobs lacking `TRAIT_ADVANCEDTOOLUSER`, such as xenomorphs. `/obj/machinery/atmospherics/portable_atmospherics` already had `interaction_flags_click = NEED_DEXTERITY` (`portable_atmospherics.dm:11`), and the vents, scrubbers and passive vents set `NEED_VENTCRAWL` instead, so the plain machines were the gap.

### Fix

Commit "Fix issue 98106: xenomorphs can no longer use ctrl/alt-click on atmospherics machinery" adds `interaction_flags_click = NEED_DEXTERITY` to `/obj/machinery/atmospherics` (`code/modules/atmospherics/machinery/atmosmachinery.dm`) and to the electrolyzer (`.../electrolyzer/electrolyzer.dm`), which sets its own interaction flags. Vents and scrubbers keep their `NEED_VENTCRAWL` override, so alt-click ventcrawling still works. The fix is on the base type rather than per machine, to cover every atmospherics machine.

### Verification

After the fix, on the test server, the larva's ctrl-click and alt-click on the injector both gave "You don't have the dexterity to do this!" and changed nothing. A player-controlled human ctrl-clicking the same injector still turned it on. No new runtimes appeared.

Not checked: whether a xenomorph can still open the machine's UI by a plain click (the question asked in the issue's comments); only the hotkeys were addressed. Other xenomorph castes, other atmospherics machines than the injector, and the electrolyzer in play were also not tested.

## #83595: Hide does not work under tables

### The bug

When a larva uses Hide on a table's tile, it is meant to be covered by the table. Instead its sprite is offset upward, as the issue guessed because of the table's climbable/elevation offset, so it remains visible above the table.

### Reproduction

1. On the test server, using the Lua editor, spawn a table and a larva on the same tile.
2. Run the Hide action's `Activate` on the larva and read its `layer` and `pixel_z`.

Before the fix: normal `layer` 4, `pixel_z` 12; hidden `layer` 2.08, `pixel_z` still 12. The larva stayed raised by the table's elevation. This was done by calling the action directly rather than through the ability button, and the rendered sprite was not looked at, only the values.

### Cause

In `/datum/action/cooldown/alien/hide/Activate` (`code/modules/mob/living/carbon/alien/larva/powers.dm:9-24`), `ADD_TRAIT(owner, TRAIT_IGNORE_ELEVATION, ACTION_TRAIT)` sat on the branch that stops hiding, and `REMOVE_TRAIT` on the branch that starts hiding. The elevation element skips mobs that have the trait (`code/datums/elements/elevation.dm:188` and `:227`), so the larva had the trait while visible and lacked it while hidden: the opposite of what is wanted.

### Fix

Commit "Fix issue 83595: xenomorph larva hide now ignores table elevation" swaps the two calls: hiding adds `TRAIT_IGNORE_ELEVATION`, unhiding removes it.

### Verification

After the fix: start `layer` 4, `pixel_z` 12; hidden `layer` 2.08, `pixel_z` 0; unhidden `layer` 4, `pixel_z` 12; hidden again `layer` 2.08, `pixel_z` 0.

Not checked: a visual render of the hidden larva under the table (values only), and moving onto or off a table while hidden.

## Notes

- The issue author's elevation guess in #83595 was right; the cause is the inverted trait, not the elevation system itself.
- #98106 touches only click hotkeys. If xenomorphs should also be unable to open these machines' UIs, that needs a separate check (not tested here).
