# #92181: Carbon `heal_overall_damage()` and `take_overall_damage()` ignore the stamina argument

| | |
|---|---|

| Status | Reproduced and fixed; fix checked on the test server |
| Fix branch | [fix/92181](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/92181) |

## Summary

`/mob/living/carbon/heal_overall_damage()` and `/mob/living/carbon/take_overall_damage()` accept a `stamina` argument but never use it, while the `/mob/living` versions do. A carbon asked to heal stamina through these procs therefore heals nothing. The fix adds an `adjust_stamina_loss()` call to both carbon procs after the bodypart loop, and removes the "stamina arg nonfunctional for carbon mobs" doc comments.

## The bug

Calling `heal_overall_damage(brute, burn, stamina)` on a carbon heals brute and burn, but its stamina loss stays the same. The same call on a non-carbon living mob (for example a corgi) heals stamina as expected. `take_overall_damage()` has the same defect: the stamina argument is dropped on carbons. The issue reporter noticed only the heal case.

In-game, the only caller found that passes a stamina value is the hunter boxing crit punch (`code/datums/martial/boxing.dm:496`). It calls `attacker.heal_overall_damage(healing_factor, healing_factor, healing_factor)`, so the boxer was meant to recover stamina but did not.

## Reproduction

The issue gives no steps ("you're gonna have to improvise a means of calling these"). This was reproduced by calling the procs directly, not through the boxing punch.

1. Start a round on master and observe.
2. Open the Lua editor. Spawn a human (`SS13.new('/mob/living/carbon/human', ...)`) and call `adjust_stamina_loss(40)` on it. A `never_wounded` trait was added so wounds would not interfere.
3. Call `heal_overall_damage(5, 0, 15)` on the human and read `staminaloss`.
4. For comparison, spawn a corgi (`/mob/living/basic/pet/dog/corgi`), call `adjust_stamina_loss(40)`, then `heal_overall_damage(0, 0, 15)`.

Observed on master:

- Human: `staminaloss` was 40 before and 40 after the heal. The call returned 5.
- A later `take_overall_damage(0, 0, 10)` on the same human also left `staminaloss` at 40.
- Corgi: `staminaloss` went from 20 to 5. The corgi's value before the call was 20, not the 40 that was applied, and the inputs do not explain why. The comparison still shows the living version healing stamina. I did not investigate the difference.

## Cause

Both carbon overrides in `code/modules/mob/living/carbon/damage_procs.dm` loop over damaged bodyparts for brute and burn only, and never read `stamina`:

- `/mob/living/carbon/heal_overall_damage()` (line 245)
- `/mob/living/carbon/take_overall_damage()` (line 278)

The `/mob/living` versions in `code/modules/mob/living/damage_procs.dm` (lines 513 and 523) include `adjust_stamina_loss(...)` in their return sum. Their doc comments said "note: stamina arg nonfunctional for carbon mobs", so the omission was known. The issue thread suggests it may have been intentional. However, the boxing caller above passes a stamina value expecting it to take effect, and both carbon procs keep `stamina` in their signature, so the evidence points to an oversight.

## Fix

One commit, "Fix issue 92181: carbon heal_overall_damage and take_overall_damage now apply the stamina argument":

- In the carbon `heal_overall_damage()`, after the bodypart loop and before the `if(!.)` early return, it adds `. += adjust_stamina_loss(-abs(stamina), updating_stamina = FALSE, forced = forced)`.
- In the carbon `take_overall_damage()`, it adds the same line with `abs(stamina)`.
- It drops the "stamina arg nonfunctional for carbon mobs" notes from the two `/mob/living` doc comments.

This mirrors what the `/mob/living` versions already do, so the two behave the same. The stamina delta is added to the return value, so a stamina-only call is no longer treated as "no change".

## Verification

After rebuilding, a fresh human on the test server was given 40 stamina loss and checked through the Lua editor:

- `heal_overall_damage(5, 0, 15)`: `staminaloss` went 40 to 25. The return value was 20.
- `take_overall_damage(0, 0, 10)`: `staminaloss` went 25 to 35. The return value was -10.
- `heal_overall_damage(0, 0, 100)`: `staminaloss` went 35 to 0, clamped at zero. The return value was 35.
- The runtime log for the round had no runtimes.

Not checked: the boxing crit punch itself, other callers of these procs, and non-human carbons (monkeys, aliens). Also, `bruteloss` read 0 before and after in this run, so the brute half of the 20 return value was not independently confirmed. The report attributes the 20 to 5 brute plus 15 stamina. I could not confirm that split from the readings.

## Notes

- `take_overall_damage()` now applies stamina on carbons too, which is a behavior change. No caller was found that passes stamina to it by name, so no change in practice is expected, but a maintainer may want to confirm.
- The `take_overall_damage()` return value is negative for stamina damage, because `adjust_stamina_loss()` returns the old value minus the new one. The `/mob/living` version has the same sign behavior.
- The issue thread notes the omission might be intentional. If so, the alternative is to keep carbons unchanged and fix the boxing caller. This fix assumes stamina should work for carbons.
