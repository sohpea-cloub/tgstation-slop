## Summary

The corpse spawner for dwarf legions adds the dwarfism mutation after the parent `special()` has already killed the corpse, and mutations refuse to be added to dead mobs, so the call silently does nothing and the corpse is full-sized. The fix adds the mutation first and then calls the parent. #83983 (lavaland mobs "have no attack cooldown" against mechs) was tested with a lobstrosity: it does attack with a cooldown, and the mech simply dies quickly.

## #78156: dwarf legion corpses lack dwarfism

### The bug

Corpses dropped by dwarf legions are meant to be dwarves, but they come out normal-sized.

### Reproduction

On master, using the Lua editor as an admin observer:

1. Create the corpse spawner's result directly: `SS13.new('/obj/effect/mob_spawn/corpse/human/legioninfested/dwarf', loc):create()`.
2. Inspect the returned human.

Observed: a dead human (stat 3) whose `dna.mutations` was empty (nil), with no Dwarfism.

This was reproduced by invoking the corpse spawner, not by killing a live dwarf legion on master.

### Cause

`/obj/effect/mob_spawn/corpse/human/legioninfested/dwarf/special()` (`code/modules/mob_spawn/corpses/mining_corpses.dm:96-98`) called the parent first and added the mutation afterwards:

```dm
. = ..()
spawned_human.dna.add_mutation(/datum/mutation/dwarfism, MUTATION_SOURCE_MUTATOR)
```

The parent path kills the spawned human (`death(TRUE)`, `code/modules/mob_spawn/mob_spawn.dm:354-358`). `/datum/mutation/on_acquiring` (`code/datums/mutations/_mutations.dm:122`) returns without effect when `acquirer.stat == DEAD`, so the mutation is never applied, with no error.

### Fix

One commit, "Fix issue 78156: dwarf legion corpses now get dwarfism", moves the `add_mutation` call before the parent and returns the parent's result (`return ..()`), with a comment saying why. This follows the first comment on the issue (the mutation has to be placed before the corpse becomes a corpse).

### Verification

On the test server with the fix:

- The corpse spawner's `create()` returned a dead human (stat 3) for which `dna.get_mutation(dwarfism)` returned "Dwarfism".
- A real `/mob/living/basic/mining/legion/dwarf` was killed; its `death()` dropped a corpse, and the chat showed "<name> suddenly shrinks!". The spawner test showed the same message for its own corpse.

Not checked: the corpse's rendered size in game was not looked at (only the mutation and the chat message), and the plasmaman corpse the dwarf legion can spawn was not tested. In code dwarfism has no species restriction, so it should apply there too.

### Notes

- Side effect: the mutation's `on_acquiring` text, "suddenly shrinks!", now appears as a visible message when the corpse spawns, since the mutation is applied while the mob is alive. It is harmless but visible to nearby players.
- Not addressed, from the issue comments: removing non-DNA-species corpses (a plasmaman) from dwarf legions, and a special dwarf drop.

## #83983: lavaland mobs attack mechs without a cooldown

### The report

Lavaland mobs that target a mech are said to attack until it is destroyed, with no cooldown. A comment from a maintainer who tested a lobstrosity locally said the cooldown is only 1 second and that the real problem is that it runs up and clobbers the mech instead of using its charge attack.

### Attempt to reproduce

On master, using the Lua editor: a Ripley MK-II with a human inside and a chasm lobstrosity 8 tiles away. The lobstrosity charged ("charges into ..."), then meleed the mech. The attack log showed hits about every 2 seconds (22:31:47.5, :49.6, :51.7, :53.7, :56.1, :58.2, :60.3, ...), compared with about 1 second against a human. 17 hits at 15 `obj_damage` each destroyed the mech (250 integrity) in about 31 seconds.

### Analysis

There is an attack cooldown: `atom/attack_generic` sets `CLICK_CD_MELEE` (`code/game/atom/atom_defense.dm:124`) and `melee_attack` sets `melee_attack_cooldown` when the attack succeeds (`code/modules/mob/living/basic/basic.dm:229-239`). The commenter's observation (melee rather than charging) is explained by the charge being on cooldown after the first rush: the charge ability is tried first in the lobstrosity's behaviour tree (`lobstrosity.bt.json`), and Lobster Rush's `hit_target` only grabs living targets (`code/modules/mob/living/basic/lavaland/lobstrosity/lobstrosity.dm:122`). Mechs have little HP against 15 `obj_damage` hits, which is a balance matter rather than a code defect.

### Verdict

Not reproduced; no change. Only the lobstrosity was tested. The legion (`obj_damage` 60, `legion.dm:18`) and vent drones, mentioned in a comment, were not.
