## Summary

The 2023 report says that a mob with the no-dismember trait still gets "limb removed" messages, blood spray and a scream from repeated sharp hits, although nothing is actually removed. On master the dismemberment code is gated by `can_dismember()`, which checks `TRAIT_NODISMEMBER`, before any of those messages or effects. In a test with 40 claymore hits on a protected target, none of the dismemberment text or effects appeared. The issue looks stale.

## The bug (as reported)

Give someone the no-dismember trait, aim at a limb with something sharp and keep attacking. According to the report, chat and logs say the limb has been removed, blood sprays and the victim screams, but the limb stays.

## Reproduction

Attempted, and not reproduced.

1. Using the Lua editor, spawn two humans and a claymore (edged, force 30).
2. Give one of them the trait. The trait's value is the string `"dismember_immunity"` (`TRAIT_NODISMEMBER`, `code/__DEFINES/traits/declarations.dm:211`); the name `"nodismember"` is not the trait and applies nothing. The other human is the control.
3. Control run (no trait): the attacker, in combat mode targeting the left arm, ran the melee attack 40 times on the control human. The arm came off. Chat showed "slicing through to the bone", "slices ... threatening to sever it entirely!" and "...'s left arm is slashed through the last flesh holding it together, severing it completely!". The chest was also "split open".
4. Trait run: the same 40 claymore hits on the arm and legs of the protected human produced only ordinary wound messages (cut open, torn open, "janks violently and becomes unseated", "sprays chips of bone and develops a nasty looking bruise"). There was no "threatening to sever it entirely", no "severing it completely", no dismemberment scream and no limb loss.

The only runtimes seen were "no valid description found for scar!" for mobs without a mind, which are unrelated.

Not tested: damage that is not a weapon hit (burns, explosions) and species that grant the trait. By reading the code they go through the same guards.

## Cause

Not applicable as a defect; this is where the checks are on master:

- `code/modules/surgery/bodyparts/dismemberment.dm:1-4`: `can_dismember()` returns `FALSE` for unremovable bodyparts and for an owner with `TRAIT_NODISMEMBER`.
- `dismemberment.dm:12`: `dismember()` itself returns early for `TRAIT_NODISMEMBER` (and godmode).
- `dismemberment.dm:149`: `try_dismember()` starts with `if (!can_dismember()) return`.
- `code/datums/wounds/loss.dm:29`: `apply_dismember()` frees the wound and returns when `!dismembered_part.can_dismember()`, before any message or blood spray.
- `code/modules/mob/living/carbon/carbon_defense.dm:108`: the "threatening to sever it entirely" text is under `hit_bodypart.can_dismember()`.
- `code/modules/surgery/bodyparts/wounds.dm:85`: the outright-dismember branch of `check_wounding` also requires `can_dismember()`.

So the messages, blood and scream that the report describes are not reachable for a protected mob.

None. No commit was made.

## Verification

The control and trait runs above are the verification: dismemberment text and limb loss for the unprotected target, only ordinary wound text for the protected one.
