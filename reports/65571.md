# #65571: CTF "ammo pickup" does not refill spare magazines

| | |
|---|---|
| Issues | [#65571](https://github.com/tgstation/tgstation/issues/65571): verified, fixed |
| Status | Fixed on the fix branch; not merged upstream |
| Fix branch | [fix/65571](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/65571) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Walking onto the ammo pickup in Capture the Flag prints "Ammunition reloaded!" but only refills the magazine currently loaded in the player's gun. The spare power packs in their pockets stay empty, although players used to receive refilled spares. The pickup only signalled guns and flamethrowers; the fix makes it also top off any magazine carried on the mob that is not loaded in a gun.

## The bug

A CTF player fires off their ammunition, steps on the ammo pickup, gets the "Ammunition reloaded!" message and a refilled loaded gun, but the spare power packs carried in the pockets are still empty. The reporter remembers the pickup once granting two spare power packs into the pockets; that no longer happens.

## Reproduction

The pickup was triggered by calling its `trigger()` proc directly; a player was not walked onto it. `trigger()` is the same path the pickup's entered handler takes.

1. Start a round on the test server (CTF is not needed as a game, only its outfit and pickup).
2. With the Lua editor, spawn a human and equip the `/datum/outfit/ctf/red` outfit: a rifle with a loaded magazine plus two spare power packs in the pockets.
3. With SDQL2, empty every CTF magazine: `CALL empty_magazine() ON /obj/item/ammo_box/magazine/recharge/ctf WHERE stored_ammo`.
4. With the Lua editor, spawn `/obj/effect/powerup/ammo/ctf` and call `trigger(human)`.
5. Read the ammo counts of the two pocket magazines and the gun's magazine.

Before the fix, the counts went from left pocket 0, right pocket 0, gun magazine 0 to left 0, right 0, gun 20. Only the loaded magazine was refilled. No runtimes.

## Cause

`/obj/effect/powerup/ammo/trigger` (`code/game/objects/effects/powerup.dm:94`) loops over `target.get_all_contents()` and sends `COMSIG_ITEM_RECHARGED` only to items that are guns or flamethrowers:

```
for(var/obj/item/gun in target.get_all_contents())
	if(!isgun(gun) && !istype(gun, /obj/item/flamethrower))
		continue
	SEND_SIGNAL(gun, COMSIG_ITEM_RECHARGED)
```

For a ballistic gun, the recharge handler only tops off the loaded magazine (`instant_reload` in `code/modules/projectiles/guns/ballistic.dm`). Magazines not inside a gun are never touched. CTF magazines are rechargeable power packs with no self-recharge, so they stay empty. The old behavior (the pickup handing out spare packs) was lost in refactors; the PR #56605 that was merged for this area did not restore it.

## Fix

One commit, "Fix issue 65571: ammo pickup also refills spare magazines", in `code/game/objects/effects/powerup.dm`. The loop now sends the recharge signal to guns and flamethrowers as before, and additionally, for each `/obj/item/ammo_box/magazine` in the mob's contents whose location is not a gun, calls `top_off()` followed by `update_appearance()`. Magazines without an `ammo_type` are skipped. The check on the location avoids doing the work twice for magazines already handled via the gun.

The change is in the shared `/obj/effect/powerup/ammo` trigger, so all its subtypes behave the same way, not just the CTF one. An alternative suggested in the issue comments (spawning new magazines into the pockets, choosing the type via `accepted_magazine_type`) was not implemented; refilling the magazines a player already carries needs no item creation or magazine-type selection.

## Verification

Same setup and calls as in the reproduction. After the fix the counts went from 0 / 0 / 0 to left pocket 20, right pocket 20, gun magazine 20. No runtimes.

Not checked: walking a player onto the pickup (only `trigger()` was called); magazines inside a bag or belt (the loop covers nested contents via `get_all_contents()`, but this was not tested); non-CTF magazines and other weapon types.

## Notes

- Because the change is in the base ammo powerup, any other placement of `/obj/effect/powerup/ammo` also now refills carried magazines. That is likely intended, but a maintainer may prefer to limit it to the CTF subtype.
- `top_off()` is applied to every carried `ammo_box/magazine` with an `ammo_type`, including non-CTF ones, which would also refill ordinary magazines a player carries into CTF.
- The issue also describes the pickup as having once given spare packs; this fix refills existing ones rather than granting new ones, so a player who has dropped or lost their spares gets nothing extra.
