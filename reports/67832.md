# #67832: Formaldehyde stops a nightmare's heart from reviving its owner

| | |
|---|---|
| Issues | [#67832](https://github.com/tgstation/tgstation/issues/67832) (verified, fixed) |
| Status | Fixed, one commit |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/67832 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a dead carbon has formaldehyde or cryostylane in its blood, `handle_organs()` returns before calling any organ's `on_death()`. That is meant to stop organ decay, but the nightmare heart runs its whole respawn countdown inside `on_death()`, so a single dose of formaldehyde (an epinephrine medipen contains 3 units) stops a nightmare from ever coming back. The fix removes that early return and moves the "preserved" check into the decay code of the base organ `on_death()`, so organs that do more than decay there still run. Body eggs keep their old behavior and still do not grow in preserved corpses.

## The bug

A nightmare whose heart has `respawn_progress` accumulating in darkness is supposed to get up again after death. If the body contains formaldehyde, the countdown never advances and the nightmare stays dead. The issue notes the nightmare also has to be in darkness for the countdown to run, so this only matters in the dark.

## Reproduction

Observer on the test server, using the Lua editor:

1. In a dark maintenance area, spawn two humans on tiles where `check_lumcount_below(0.2)` is 1. (Note that Lua treats 0 as true, so compare the result with `== 1`.)
2. Insert an `/obj/item/organ/heart/nightmare` into each and set `respawn_progress = 700`, 100 below the threshold of 800.
3. Give human A 5 units of formaldehyde, and none to human B.
4. Kill both with `death()`.
5. Wait about 60 seconds.

Result on master: B had revived (`stat` 0, `respawn_progress` 0). A was still dead (`stat` 3), `respawn_progress` was still 700, and the formaldehyde was still in its blood.

The kill was done by calling `death()` and the dose given directly, not with a medipen. The formaldehyde source is a medipen with epinephrine (`hypospray.dm:155`: 10 epinephrine, 3 formaldehyde, 2 coagulant).

## Cause

`/mob/living/carbon/proc/handle_organs` (`code/modules/mob/living/carbon/life.dm:503`) is:

```
if(stat == DEAD)
    if(reagents && (reagents.has_reagent(/datum/reagent/toxin/formaldehyde, 1) || reagents.has_reagent(/datum/reagent/cryostylane))) // No organ decay if the body contains formaldehyde.
        return
    for(var/obj/item/organ/organ in organs)
        // On-death is where organ decay is handled
        ...
            organ.on_death(seconds_per_tick)
```

The early return (`:505-506`) skips `on_death()` for every organ. The base `/obj/item/organ/proc/on_death` (`code/modules/surgery/organs/_organ.dm:160`) is where decay is applied, so the skip does what the comment says for ordinary organs. But `/obj/item/organ/heart/nightmare/on_death` (`code/modules/antagonists/nightmare/nightmare_organs.dm:138`) is where the nightmare heart adds to `respawn_progress` when the owner's turf is dark and revives the owner when the threshold is reached. It never runs for a body with formaldehyde or cryostylane.

## Fix

Commit "Fix issue 67832: nightmare hearts still revive their owner while preserved by formaldehyde":

- `handle_organs()` no longer returns early for preserved bodies. A comment says why: some organs do more than decay in `on_death`.
- A new `/mob/living/carbon/proc/organs_preserved()` (`life.dm`) holds the same formaldehyde (at least 1 unit) / cryostylane check as before.
- The base `/obj/item/organ/proc/on_death` returns before the decay calculation if `owner.organs_preserved()`, so decay is still skipped.
- `/obj/item/organ/body_egg/on_death` skips `egg_process` when the owner's organs are preserved, which keeps the old behavior for eggs (before the change they were also skipped).

The alternative was to special-case the nightmare heart in `handle_organs()`. Putting the check in the decay code was chosen so any organ with its own `on_death` work is not blocked by preservatives. This is the change in behavior to review: other organs overriding `on_death` now also run in preserved corpses.

## Verification

After rebuilding, the same setup (two humans, A with formaldehyde) was run again. Both revived (`stat` 0, `respawn_progress` 0). A's formaldehyde read 0 afterwards, which is consistent with the revive (`HEAL_ALL`) clearing reagents.

Not checked: body egg behavior (kept as before by construction, not tested), other organs that override `on_death`, cryostylane, and the unit tests (not run). The only runtime seen was from a bad `get_turf` call in the test script.

## Notes

- `handle_organs()` is part of the carbon life tick, so the change is worth a maintainer's review even though it is small.
- Other organs whose `on_death` does work other than decay now run while a body is preserved; none were looked at beyond the nightmare heart and body eggs.
- The nightmare still needs darkness for the countdown, as a commenter on the issue pointed out; the fix does not change that.
