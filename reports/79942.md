# #79942: Ctrl-clicking the floor no longer stops pulling

| | |
|---|---|

| Status | Verified on the test server; fix committed |

## Summary

Ctrl-clicking a non-movable atom (a floor tile, a wall) does nothing on master, so the click shortcut for letting go of a pulled object is gone. The issue describes this as a combat-mode problem. In testing it happened in both modes. `/mob/living/base_click_ctrl` returns early for any target that is not an `/atom/movable`. The fix makes it call `stop_pulling()` in that case when the mob is pulling something.

## The bug

The report says that ctrl-click starts a pull, and ctrl-clicking empty space while pulling stops it. In combat mode, the reporter says, the second part does not work, and the player has to leave combat mode or press the "stop pulling" HUD button.

On master 87b93338 the shortcut did not work outside combat mode either. Ctrl-clicking a floor tile left the pull in place. Ctrl-clicking the pulled object again did nothing either. That second behaviour is unchanged by the fix and was not part of the request.

## Reproduction

1. On the test server, join the round as an observer and open the Lua editor.
2. Spawn a human and possess it. Spawn a closet a few tiles away on the same row, in view.
3. Ctrl-click the closet. The pull starts and the HUD "stop pulling" icon changes from `pull0` to `pull`.
4. Ctrl-click an empty floor tile (not in combat mode). Nothing happens, and the pull stays on. The same check was not run in combat mode before the fix; the code path does not depend on the mode (see Cause).

## Cause

`code/_onclick/click_ctrl.dm:33-45`, `/mob/living/base_click_ctrl`:

```dm
. = ..()
if(. || !ismovable(target) || world.time < next_move || !can_perform_action(...))
	return
```

For a floor or wall, `!ismovable(target)` is true and the proc returns without doing anything. The only code reached from a ctrl-click is `grab(target)` and `pulled(target)`, and `pulled` only starts a pull. The `Pull` verb is defined in `code/modules/mob/living/living.dm` (`GAME_VERB_CONTEXT_RANGE(/mob/living, pulled, "Pull", ...)`, line 531). It appears that the old verb's stop-pulling branch for non-movable targets was lost when the verbs were refactored. This was inferred from the code; the history was not checked.

## Fix

One commit, "Fix issue 79942: ctrl-clicking the floor stops pulling again". It splits the early-return condition. If `base_click_ctrl` receives a target that is not movable and the mob is pulling something, it calls `stop_pulling()` and returns `TRUE`. If the mob is not pulling anything, it returns as before. The cooldown and `can_perform_action` checks apply only to movable targets, as before.

## Verification

On the test server after rebuilding:

- Not in combat mode: ctrl-click the closet (pull starts), ctrl-click the floor. The HUD icon went from `pull` to `pull0` and the pull stopped.
- Pull again, toggle combat mode on (HUD icon `combat_off` to `combat`), ctrl-click the floor. The icon went from `pull` to `pull0` and the pull stopped.
- The runtime log of the test rounds had no runtimes.

Not checked: ctrl-clicking a wall, and pulling a mob rather than a closet.

## Notes

- The floor click does not check range. This matches the old verb's behaviour.
- Ctrl-clicking the pulled object itself still does not toggle the pull off. This was not changed.
