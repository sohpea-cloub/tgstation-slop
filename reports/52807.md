# #52807: Point-blank kinetic accelerator hits on rock lose the mining skill reload bonus

| | |
|---|---|
| Issues | [#52807](https://github.com/tgstation/tgstation/issues/52807): verified, fixed |
| Status | Fixed (one commit), checked on the test server after the fix |
| Fix branch | [fix/52807](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/52807) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A proto-kinetic accelerator (PKA) that mines a mineral turf is supposed to reload faster the higher the shooter's mining skill. When the rock is adjacent to the shooter (a point-blank shot), the speed-up is silently lost and the gun reloads at its normal speed. The skill-adjusted reload is requested while the gun's cell is still full, which `attempt_reload()` ignores, and the gun's own default reload then starts afterwards. The fix defers the skill-adjusted reload by one timer tick when the cell is still full, so it runs after the firing has finished and replaces the default reload.

## The bug

With a high mining skill, a PKA fired at a rock reloads noticeably faster than the base time. Players who dual wield two PKAs see one gun ready long before the other, so the two stop firing together. The report describes this as the off-hand gun being "on a normal cooldown". A later comment on the issue added that the problem appears when the mined rock is adjacent to the player: hugging a wall and firing at adjacent rock loses the reduction on one or both guns, while shooting from at least one tile away applies it to both.

What actually happens is not specific to the off-hand gun. Any PKA shot that mines an adjacent rock turf loses the skill bonus. Carrying two PKAs doubles each gun's reload time (see Cause), so the lost bonus is more obvious when dual wielding.

## Reproduction

All steps used the Lua editor on the test server. The guns were fired by calling `process_fire` on each gun directly, not by clicking, so the player input path was not exercised.

1. Spawn a human with a mind and set its mining experience to 10,000,000. `get_skill_modifier(/datum/skill/mining, "speed")` then returned 0.5.
2. Give that human two proto-kinetic accelerators, one in each hand. Each has a base `recharge_time` of 16 deciseconds (1.6 s). With two of the same gun carried, the reload time is multiplied by 2, so the expected total is 32 ds without the bonus and 16 ds with it.
3. Replace the turfs directly north and directly east of the human with iron mineral turfs.
4. Call `process_fire` on one gun at the north rock and on the other at the east rock, and read the remaining time on each gun's `recharge_timerid` timer.

Evidence on master:

- Temporary debug logging inside the reload path showed that when the projectile hit the adjacent rock, the skill-adjusted reload (requested time 8 ds, i.e. 16 x 0.5 before the carried multiplier) was requested with the cell at 5000/5000 charge, which is full. `attempt_reload()` returns without doing anything in that case.
- A first attempt to read the timer on master gave 28.5 ds remaining 0.2 s after the shot, but that run had accidentally used a half-charged cell, so it is not a valid before measurement. No clean pre-fix timer reading was taken. The pre-fix behavior rests on the code path above and the debug log line, not on a timing comparison.

The same setup was not reproduced from the player's side (real clicks, real movement), and the diagonal and "two rocks in a line" cases from the issue comment were not tried individually.

## Cause

`/obj/projectile/kinetic/proc/strike_thing()` in `code/modules/projectiles/guns/energy/kinetic_accelerator.dm` handles the hit. If the target turf is a mineral turf (line 255) and the firer is a carbon, it computes `skill_modifier` from the firer's mining skill and calls:

```dm
kinetic_gun.attempt_reload(kinetic_gun.recharge_time * skill_modifier) //If you hit a mineral, you might get a quicker reload. epic gamer style.
```

(line 264). `attempt_reload()` in `code/modules/projectiles/guns/energy/recharge.dm:65` starts with:

```dm
if(cell.charge == cell.maxcharge)
	return
```

(lines 68-69), so it does nothing for a full cell. The order of events when a shot is fired in `process_fire()` (`code/modules/projectiles/gun.dm:605-612`) is:

1. `fire_casing()` creates and launches the projectile. The cell is not drained yet.
2. `shoot_live_shot()` runs.
3. `process_chamber()` calls `handle_chamber()`, and `/obj/item/gun/energy/handle_chamber()` (`code/modules/projectiles/guns/energy.dm:221-226`) drains the cell with `cell.use(shot.e_cost)`.
4. `/obj/item/gun/energy/recharge/handle_chamber()` (`recharge.dm:51-53`) then calls `attempt_reload()` with no argument, which starts the default reload timer.

For a point-blank shot at an adjacent rock, the projectile's hit (and so `strike_thing()`) happens during step 1, before the cell is drained. The skill-adjusted call is therefore a no-op, and the default reload from step 4 is the only one that runs. For a shot at a distant rock, the projectile hits later, after the cell has been drained, so the skill-adjusted call arms the timer and the bonus applies. This matches the observation in the issue comment that keeping a tile of distance makes the bonus work.

`attempt_reload()` also multiplies the time by the number of guns of the same type in the shooter's contents (`recharge.dm:72-80`). That is why two PKAs reload at twice the time of one and why the missing bonus is more visible when dual wielding.

## Fix

One commit, "Fix issue 52807: point blank KA mining hits ignore the mining skill reload bonus", in `code/modules/projectiles/guns/energy/kinetic_accelerator.dm`:

- A new proc, `/obj/item/gun/energy/recharge/kinetic_accelerator/proc/attempt_reload_after_hit(set_recharge_time)`. If the gun has no cell or the cell is not full, it calls `attempt_reload(set_recharge_time)` directly, as before. If the cell is full, it schedules the same call with `addtimer(..., 0)`, so it runs after the current firing sequence finishes, when the cell has been drained and the default reload has been started. The skill-adjusted reload then replaces the default one (`attempt_reload()` calls `deltimer` on the existing timer before arming a new one).
- `strike_thing()` calls the new proc instead of `attempt_reload()`.

The deferral is limited to the full-cell case so the existing timing for distant hits is unchanged. The investigation noted that the infernal/repeater modkit already drains the cell before the skill reload, so it is unaffected.

## Verification

On the test server, with the same two-gun, mining-skill-10,000,000 setup as above and the fix applied:

- Adjacent rocks (north and east): 13.5 ds remained on both guns' reload timers 0.2 s after firing, i.e. a 16 ds total reload. The unfixed default for two carried PKAs is 32 ds.
- Rock three tiles away: about 7 ds remained after 1.0 s on both guns, about 17 ds total. This matches the previous behavior, so distant shots are unchanged.
- No runtimes were reported. The temporary debug logging was removed before the commit.

Not checked: a clean before-the-fix timing measurement; shots made by real player clicks; mecha, cyborg and minebot kinetic accelerators; the specific diagonal and in-line cases from the issue comment (they go through the same code path, but were not run).

## Notes

- The issue title blames the off-hand gun, but the cause affects every adjacent-rock shot from any KA. The reported "one gun is ready, the other is not" symptom with both guns firing at adjacent rock was not explained separately: in the test both guns lost the bonus together. The off-hand asymmetry described in the report may come from firing order or from one shot being non-adjacent; this was not investigated.
- A zero-tick timer means the corrected reload is armed on the next timer processing after the shot, not in the same tick. Any other code that reads the reload timer in between would see the default value.
- An alternative would be to make `attempt_reload()` accept a full cell for this call, or to apply the skill modifier inside `handle_chamber()`'s default reload instead of in the projectile. Both would change the shared `recharge` base type used by other guns, so the change was kept local to the kinetic accelerator.
