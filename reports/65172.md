## Summary

The dejavu component (used by the rewind camera) teleports you back to where you were when it was applied. If that place was a Hilbert's Hotel room and the room has since been released, you land on an unused turf of the reserved z-level, which has no exit. The fix skips the teleport, with a message, when the starting turf is on a reserved z-level and no longer belongs to a reservation.

## The bug

A player uses a rewind camera inside a hotel room, checks out of the room, and later gets pulled back to "where they were". That spot is now just space on a reserved z-level (the issue shows odd lighting there). A commenter noted the same z-level is used for shuttle transit, so a similar spot could be reached next to a shuttle in transit.

## Reproduction

On master, with admin tools (the rewind camera was not used itself; its effect was applied through the Lua editor):

1. Spawn a human, possess it, and spawn a `/obj/item/hilbertshotel`.
2. Use the hotel (room 5) to enter a room on the reserved z-level (z12 on the test map).
3. Add the dejavu component to the mob with 2 rewinds and a 40 second duration (`_AddComponent` with arguments `{/datum/component/dejavu, 2, 400}`). The rewind camera's `on_flash` does `AddComponent(dejavu, 2)`, so this matches it.
4. Click the Hotel Door and choose Leave. The last mind leaving the room calls `storeRoom`, which releases the reservation.
5. Wait for the rewind.

Observed: the chat showed "You remember a time not so long ago...", and the mob ended up at 222,25,12, "on space in Space", with Low Pressure and Weightless alerts.

## Cause

`rewind()` in `code/datums/components/dejavu.dm:83-88` forces the parent to `starting_turf` after only calling `check_teleport_valid(parent, starting_turf)`. That check compares reservations only when an `original_destination` is passed (`code/datums/helper_datums/teleport.dm:263-265`), and dejavu passes none, so a turf in a released reservation passes. The hotel releases the reservation in `storeRoom` (`code/modules/mapfluff/ruins/spaceruin_code/hilbertshotel.dm:496`) when the room empties.

## Fix

One commit, "Fix issue 65172: dejavu no longer teleports you to a released reservation". In `rewind()`, before the existing `check_teleport_valid` branch:

```dm
if(is_reserved_level(starting_turf.z) && !SSmapping.get_reservation_from_turf(starting_turf))
	to_chat(parent, span_warning("You try to remember where you were, but the place no longer seems to exist..."))
else if(!check_teleport_valid(parent, starting_turf))
```

The fix is local to dejavu and also covers other temporary reservations such as shuttle transit, rather than changing `check_teleport_valid` for every caller.

## Verification

With the same steps on a rebuilt test server, the chat showed "You try to remember where you were, but the place no longer seems to exist..." and the mob stayed at 107,144,2 (Central Primary Hallway), where it had been after leaving the room.

Not tested: rewinding into a reservation that still exists (room still occupied, shuttle in transit). The condition is false there so behavior should be unchanged, but it was not exercised. The actual rewind camera item was not used; the component was added directly.

## Notes

- Heal-and-restore effects of the rewind still happen; only the teleport is skipped.
- The reported shuttle-transit variant was not reproduced.
