# #93302: Spilling ants (or uranium) on a clean floor creates a decal holding double the volume

| | |
|---|---|
| Issues | [#93302](https://github.com/tgstation/tgstation/issues/93302): verified (reproduced, fixed, verified in game) |
| Status | Fixed |
| Fix branch | [fix/93302](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/93302) |

## Summary

When ants are spilled on a turf with no existing ant decal, `/datum/reagent/ants/expose_turf` creates a decal holding twice the spilled volume: `lazy_init_reagents()` already fills the decal with the volume, and the code then adds the same volume again because the call returns a truthy value. Scooping the decal up therefore yields double the ants. A commenter on the issue pointed out that uranium's `expose_turf` is identical; it has the same bug, and the fix covers both.

## The bug

Scooping ants into a bluespace beaker, throwing the beaker to the floor and scooping up the resulting pile returned more ants than were put in. Some commenters took this as intended ("gotta spend ants to make ants"), but a reagent that doubles on spilling is a plain accounting error, and the same code path doubles uranium.

## Reproduction

On a round with admin tools:

1. Using the Lua editor, spawn a bluespace beaker containing 100u of ants and `throw_at` a clean floor tile so it breaks and spills (this triggers `expose_turf` on the turf).
2. Look at the "space ants" decal on the tile. Observed on master: it held 200u, and scooping it up gives 200u.

The player action (scooping and throwing by hand) was not performed; the throw and spill were done through Lua, which runs the same `expose_turf` path.

## Cause

`code/modules/reagents/chemistry/reagents/other_reagents.dm:3350` (`/datum/reagent/ants/expose_turf`), lines ~3361-3365:

```dm
pests.decal_reagent = type
var/rounded_volume = round(reac_volume, 1)
pests.reagent_amount = rounded_volume
if(pests.lazy_init_reagents()) // Decal already has reagents inited, add instead
	pests.reagents.maximum_volume = min(pests.reagents.maximum_volume + rounded_volume, 300)
	pests.reagents.add_reagent(type, rounded_volume)
```

The comment assumes `lazy_init_reagents()` returns truthy only if the decal already had reagents. It does not: `code/game/objects/effects/decals/cleanable.dm:81-85` returns `reagents` if it exists, otherwise calls `init_reagents(decal_reagent, reagent_amount)`, which creates the holder and adds `reagent_amount` of the reagent, then returns the holder. On a fresh decal the call therefore creates the reagents holding `rounded_volume` and returns them (truthy), and the `add_reagent` line adds the same amount again, giving 2x.

The uranium handler at line 1299 (`/datum/reagent/uranium/expose_turf`, check at line 1311) has the same structure and the same result for the "glowing goo" decal.

## Fix

One commit, "Fix issue 93302: ants and uranium spilled on a turf no longer double", rewrites the branch in both handlers to test for existing reagents directly:

```dm
if(pests.reagents) // already has reagents: add on top
	pests.reagents.maximum_volume = min(pests.reagents.maximum_volume + rounded_volume, 300)
	pests.reagents.add_reagent(type, rounded_volume)
else // lazy_init_reagents() creates them holding exactly this much
	pests.decal_reagent = type
	pests.reagent_amount = rounded_volume
	pests.lazy_init_reagents()
```

(the uranium version is the same with an early `return`). `decal_reagent` and `reagent_amount` are now only set when the decal has no reagents yet, so they are not overwritten on a decal that already holds some. The existing top-up behaviour (volume cap of 300) is unchanged. Changing `lazy_init_reagents()` itself was not chosen, since other callers (`cleanable.dm:76` and the scoop interaction) rely on it returning the holder.

## Verification

After rebuilding, on the test server:

- 100u of ants spilled on a clean tile produced a 100u decal.
- A second 50u of ants spilled on the same tile brought the decal to 150u.
- 50u of uranium produced a 50u glowing-goo decal (100u before the fix).

Not checked: scooping into a bluespace beaker by hand; spills where a decal existed but had no reagents initialised yet; other reagents that use `lazy_init_reagents()`.

## Notes

- A third user of the same pattern, `industrial_waste` in `code/modules/reagents/chemistry/reagents/toxin_reagents.dm` (~line 1707), calls `lazy_init_reagents()` but only raises the holder's `maximum_volume` afterwards, never adding the reagent again, so it does not double the volume; it was left untouched.
- The `HalfPunch` comment on the issue (ants and uranium handlers are identical) was correct; the bug is in both.
