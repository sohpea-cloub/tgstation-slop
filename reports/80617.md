# #80617: Reaction lookup UI reveals TaTP's randomized temperature

| | |
|---|---|
| Issues | [#80617](https://github.com/tgstation/tgstation/issues/80617): fixed |
| Status | Fixed on the branch; the server data was checked in game, the tgui change was only compiled and type-checked |
| Fix branch | [fix/80617](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/80617) |

## Summary

TaTP's reaction temperature is randomized every round (450 ± 49 K for TaTP, 550 ± 49 K for its explosion) so that players have to find it by experiment. The reagent reaction lookup UI sent the real value to the client and displayed it, along with a rate-profile graph built from it. The fix adds a `REACTION_HIDE_TEMPERATURE` reaction flag, set on both TaTP reactions. Flagged reactions send no temperatures or graphs, and the UI shows "Unknown" with a tooltip.

## The bug

Opening a TaTP reaction in the lookup UI showed its exact required temperature and, for the explosion, its overheat temperature, together with the rate-profile graph. That made the per-round randomization pointless. The issue asks for some way to obfuscate such information.

## Reproduction

Reproduced by reading the code only. The pre-fix UI output was not captured in game.

1. Open the reaction lookup UI (for example from a reagent container or the chem master) and select the TaTP reaction (`/datum/chemical_reaction/reagent_explosion/tatp`) or its explosion.
2. The temperatures shown are the round's real `required_temp` values.

After the fix, the data that the server builds for the UI was checked with the Lua editor: a beaker's `reagents.ui_reaction_id` was pointed at each reaction path and `ui_data()` was called as a player (see Verification).

## Cause

`code/modules/reagents/chemistry/recipes/pyrotechnics.dm:124-126` randomizes the TaTP temperature when the reaction is created:

```dm
/datum/chemical_reaction/reagent_explosion/tatp/New()
	. = ..()
	required_temp = 450 + rand(-49, 49)
```

The explosion does the same at lines 144-146 (`550 + rand(-49, 49)`). `code/modules/reagents/chemistry/holder/ui_data.dm`, in the `reagent_mode_recipe` block (lines 174 and 196), puts `"tempMin" = reaction.required_temp`, `"explodeTemp" = reaction.overheat_temp`, and `thermodynamics`/`explosive` profiles generated from the reaction into the data for `tgui/packages/tgui/interfaces/common/RecipeLookup.jsx`. Nothing excluded reactions whose temperature is meant to be secret. The graph also leaks the temperature, so hiding the numbers alone would not be enough.

## Fix

One commit, "Fix issue 80617: hide TaTP's randomized temperature in the reaction lookup UI":

- `code/__DEFINES/reagents.dm`: new reaction flag `REACTION_HIDE_TEMPERATURE` (`1<<6`).
- `pyrotechnics.dm`: both TaTP reactions get `reaction_flags = REACTION_HIDE_TEMPERATURE`.
- `holder/ui_data.dm`: for flagged reactions, `tempMin`, `explodeTemp`, `thermodynamics` and `explosive` are set to null and `hideTemperature` is set to TRUE.
- `RecipeLookup.jsx`: when `hideTemperature` is set, the rate-profile row shows an italic "Unknown" with the tooltip "The temperature of this reaction changes every round, and has to be found out by experimentation." Otherwise the original markup is used (only re-indented).
- `Reagents/types.ts`: the temperature and graph fields are nullable and `hideTemperature?` was added.

A generic flag was chosen over special-casing TaTP so that other secret-temperature reactions can opt in.

## Verification

The DM and tgui bundles were built (`tsc` was clean). In game, with the Lua editor, `ui_data()` for each reaction gave:

| Reaction | tempMin | explodeTemp | hideTemperature | thermodynamics | explosive |
|---|---|---|---|---|---|
| TaTP | nil | nil | 1 | nil | nil |
| TaTP explosion | nil | nil | 1 | nil | nil |
| nitroglycerin (control) | 0 | 900 | nil | list | list |

No new runtimes appeared.

Not checked: the "Unknown" display itself. The test client does not run tgui JavaScript, so the `RecipeLookup.jsx` change was only compiled and type-checked. The pre-fix data was not captured in game either.

## Notes

- The issue's comment also complains that the omega soap recipe (`omegasoapification`, `code/modules/reagents/chemistry/recipes/others.dm:106`) is listed in the lookup although it is meant to be found in maintenance. That is a design decision and was not changed. The new flag only covers temperatures, not hiding a whole recipe.
- Other randomized recipes (`recipes/special.dm`, `/randomized`) are already excluded from the lookup (`code/_globalvars/lists/reagents.dm:200`). The crafting menu does not list TaTP.
