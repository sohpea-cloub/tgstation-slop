# #28286: Discounted uplink gear costs full price when bought from its regular listing

| | |
|---|---|
| Issues | [#28286](https://github.com/tgstation/tgstation/issues/28286): verified (reproduced, fixed) <br> [#87890](https://github.com/tgstation/tgstation/issues/87890): not reproduced (related, no fix) |
| Status | #28286 verified with a fix; #87890 not reproduced |
| Fix branch | [fix/28286](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/28286) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Uplink sales are separate item datums that exist only in the uplink handler's `extra_purchasable` list. The regular listing buys by type path, and the server always resolves that path to the base item from `SStraitor.uplink_items_by_type`. So an item that is on sale is only charged the sale price when bought from the discount tab. The fix adds `get_best_offer()` to the uplink handler and uses it when buying by path, so the regular listing is charged the cheapest in-stock sale. It also changes the Uplink tgui to show that sale price on the regular entry. #87890 (a discount that raised a price) was not reproduced: no code path can produce a price above base, and 152 generated traitor sales were all at or below base.

## The bug

### #28286

A traitor sees an item at a sale price in the discount section (for example a Stechkin for 3 TC), but the same item in its normal category is listed and charged at full price (7 TC). The report is from 2017. Comments over the years disagree on whether it had been fixed: one said "almost positive this is fixed", others confirmed it still happened in 2021 and 2023 ("you won't get the discount unless you buy from the discounts menu or through item search"). It was still present on master `87b93338`.

The "item search" route the last commenter mentions was not exercised, because the test client does not run tgui JavaScript (see Verification).

### #87890

The report says that in one nuclear operative round the CNS Rebooter was offered for 10 TC when its normal price is 8, and asks whether discounts can be negative. The reporter gave no reproduction steps ("roll a lot of discounts until you get a ripoff"). A commenter looked at `uplink_items.dm` and found no way for the discount to be negative.

## Reproduction

### #28286

1. On the test server, start the round, observe, and open the Lua editor.
2. Create a human, call `mind_initialize()`, and give it the traitor antagonist datum (`mind:add_antag_datum(/datum/antagonist/traitor)`). This creates an uplink handler with its sales. Listing `uplink_handler.extra_purchasable` showed several sale entries, each with a discounted cost against the base cost, for example `Energy Sword (33% off!) cost=4 base=6`.
3. Buy the base item by type path, as the regular listing does. This was done by calling `purchase_item` on `SStraitor.uplink_items_by_type[/datum/uplink_item/dangerous/sword]` through Lua. This is the call `ui_act("buy")` makes for a path buy, but on master it was made directly, not through the Uplink UI.
4. Observed: telecrystals went from 16 to 10, a cost of 6 (the base cost), not 4.

One oddity: the return value of the first call reported telecrystals of 16 both before and after the purchase, while a later read of the same handler showed 10. The charge did happen; why the first read still showed 16 was not established.

### #87890

1. Using the Lua editor, create 30 humans with the traitor datum and compare each entry in `extra_purchasable` with the base cost of its type.
2. Result: 152 sales, none above base cost, lowest ratio 0.14 (sale cost / base cost).
3. The nuclear operative uplink (where the report happened) was not tested. Attempts to call `create_uplink_sales()` directly with a nuclear-operative-style item list failed on an unfiltered list (division by zero, see Notes) and then on Lua scripting errors, so the 152 sales are all from the traitor path.

## Cause

### #28286

- `code/modules/uplink/uplink_items.dm:3-54` (`create_uplink_sales`) does not change existing items. For each sale it makes `new taken_item.type()`, then sets its `cost`, name, `discounted = TRUE` and `stock_key`. Traitor sales go into the handler's `extra_purchasable` (`code/modules/antagonists/traitor/datum_traitor.dm:80`); nuclear operative team sales are added the same way (`code/modules/antagonists/nukeop/datums/operative.dm:70`).
- The Uplink tgui lists the regular entries from the shared item list, and the sale copies separately from `extra_purchasable`. Buying a sale entry sends its `ref`; buying a regular entry sends only its `path`.
- `code/datums/components/uplink.dm:238-250` handles the `buy` action. With a `ref`, it picks the sale datum out of `extra_purchasable`. With a `path`, it takes the base item:

  ```dm
  item = SStraitor.uplink_items_by_type[item_path]
  ...
  uplink_handler.purchase_item(ui.user, item, parent)
  ```

  `purchase_item` (`code/modules/antagonists/traitor/uplink_handler.dm:92`) charges `to_purchase.cost`, which for the base item is the full price.
- The tgui (`tgui/packages/tgui/interfaces/Uplink/index.tsx`) also showed regular entries at the base cost, so the player was not told about the sale either.

### #87890

The cost of a sale is `max(round(uplink_item.cost * (1 - discount)), 1)` (`code/modules/uplink/uplink_items.dm:47`), and the discount values come from `get_discount_value`, which returns 0.25, 0.5 or 0.75 (0.2, 0.35 and 0.5 for the double-bladed energy sword, `code/modules/uplink/uplink_items/dangerous.dm:80`). Halved again for items costing 20 or more (`uplink_items.dm:43-44`). With a positive base cost and a discount between 0 and 1, the result cannot exceed the base cost. It could only rise when the base cost is 0, and the item filters require a cost of at least 4 for traitors (`TRAITOR_DISCOUNT_MIN_PRICE`) and above 1 for nuclear operatives. A search of the source found no other code that writes an uplink item's cost. The reported CNS Rebooter case (8 to 10) could not be reconstructed. It may come from an older version or from something not found here.

## Fix

One commit, "Fix issue 28286: buying a discounted uplink item from its regular listing now uses the discount", touching three places:

- `code/modules/antagonists/traitor/uplink_handler.dm`: new proc `get_best_offer(to_purchase)`. If the item passed is already a sale (`discounted`) or already in `extra_purchasable`, it is returned unchanged. Otherwise it walks `extra_purchasable` for discounted items of the same type that are cheaper than the best found so far and not out of stock (`item_stock[offer.stock_key]` is null or above 0), and returns the cheapest, or the original item if there is none.
- `code/datums/components/uplink.dm`: in `ui_act("buy")`, the path branch now sets `item = uplink_handler.get_best_offer(item)` after the lookup (when the item exists), so a path buy gets the sale cost, stock limit and name.
- `tgui/packages/tgui/interfaces/Uplink/index.tsx`: when building the item list, a regular entry without a `ref` is replaced by a copy with the sale cost and the sale's `ref` if an in-stock sale of the same item exists. The listing therefore shows the sale price and buys by `ref`.

The fix is on the server so a path buy is always right, and the tgui changes so the displayed price matches what is charged. The alternative of only changing the tgui would leave the server charging base price for any path buy.

## Verification

After rebuilding (DM build 0 errors, 0 warnings; the tgui bundle also built):

1. A new traitor was created and possessed. Its uplink had the Makarov Pistol Case on sale (base 7 TC, sale 1 TC, listed "85% off").
2. The real Uplink UI was opened from the uplink's Activate button.
3. The `buy` action was sent with the base item's path `/datum/uplink_item/dangerous/pistol`, as the regular listing does.
4. Telecrystals went from 16 to 15 and the gun case appeared in the traitor's hand. Before the fix, the same kind of path buy cost the full price (Energy Sword, 16 to 10, base 6, sale 4).

Not checked:
- The tgui display change. The TSX compiled, but the test client does not run tgui JavaScript, so the regular entry showing the sale price (and buying through `ref`) was not seen. A type check was attempted and could not run (the tool was not installed).
- Nuclear operative uplink (team discounts, limited-stock discounts), where `extra_purchasable` is shared by team; and the behavior of limited sale stock when bought from the regular listing.
- Items restricted to certain roles or species.
- The item search route from the issue.
- Refunds of an item bought this way.

## Notes

- Buying from the regular listing now uses up the sale's stock, if the sale has a stock limit, and uses the sale's name and description for the purchase. This follows from reusing the sale datum; a maintainer may want to look at it for limited-stock discounts.
- The fix applies only to path buys. A `buy` with an explicit `ref` is unchanged.
- This change touches both the purchase path and a tgui file, so it should be reviewed by someone who knows the uplink.
- Related, not part of this fix: `create_uplink_sales()` called on a list that contains a cost-0 or cost-1 item can hit a division by zero at `uplink_items.dm:48` (the "% off" text divides by the initial cost). This was seen once when calling the proc directly from Lua with an unfiltered item list; the real callers filter out items costing 1 or less (traitors: below 4).
- A side observation on the percentages shown in sale names: a tester noted that `round()` with one argument looked like it was flooring on this build (7 TC with a 25% discount gave 1 TC under a label of "85% off", and 7 x 0.75 = 5.25 gave 5 with 28% shown). The notes disagree on the cause (one says it follows DM semantics and not the speed-patched BYOND, the other says it could be the patched BYOND and was untested with fixes disabled), and the examples given are also consistent with ordinary rounding. Treat this as unconfirmed and not part of this change.
