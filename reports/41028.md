# #41028: Dish drive power usage gets odd with upgrades

| | |
|---|---|
| Issues | [#41028](https://github.com/tgstation/tgstation/issues/41028): verified, fixed |
| Status | Fixed, checked in game with admin tools |
| Fix branch | [fix/41028](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/41028) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A dish drive's power use does not fall with better parts as its code intends. At part tier 3 and 4 the idle power was 1600 W and 3100 W (base 100 W) and the active power was 0, because `RefreshParts()` only overrides the usage when the summed part tier is below 9, and otherwise leaves idle at the inflated value computed by the generic machine code. The override also subtracts the tier sum, a few units, from values in the tens and hundreds of watts. The fix scales both idle and active usage down by 10% per tier above the base parts, from their initial values.

## The bug

The issue (2018, updated 2023) listed the usage values seen on upgrading the dish drive: `active_power_usage` 10, 7, 0, 0 and `idle_power_usage` 5, 2, 8, 8, and noted that idle power jumps up from 2 to 8 when it should go down. Those numbers come from an older version of the code and the power constants have since changed, but the pattern is the same on master: idle usage goes up at the higher tiers and active usage drops to 0. A 2023 comment calls the way the machine handles upgrades unstable and says tier 4 parts set idle usage to "wacky values".

## Reproduction

Admin tools: the Lua editor. The upgrade was simulated by swapping the machine's stock part datums and calling `RefreshParts()`, not by building and upgrading a drive by hand.

1. Start a round and open the Lua editor.
2. For each tier 1 to 4, spawn an `/obj/machinery/dish_drive`. In its `component_parts`, replace the servo and the two matter bins with the stock part datums of that tier (from `GLOB.stock_part_datums`, for example `/datum/stock_part/servo/tier3`), then call `RefreshParts()`.
3. Read `idle_power_usage` and `active_power_usage` of each drive.

Observed on master (idle / active, in watts):

| Tier | Idle | Active |
|---|---|---|
| 1 | 97 | 37 |
| 2 | 94 | 34 |
| 3 | 1600 | 0 |
| 4 | 3100 | 0 |

## Cause

Two pieces of code interact.

The generic `/obj/machinery/proc/RefreshParts()` (`code/game/machinery/_machinery.dm:829-846`) resets idle and active usage and then sets both to `initial(...) * (1 + parts_energy_rating)`, where each part's `energy_rating()` (`code/modules/research/stock_parts/stock_part_datum.dm`) is 1, 3, 5 and 10 for tiers 1 to 4. Better parts therefore make an ordinary machine use more power. The dish drive has three parts (one servo and two matter bins; see `/obj/item/circuitboard/machine/dish_drive` in `machine_circuitboards.dm`), so its parent value is `100 * (1 + 15) = 1600` W at tier 3 and `100 * (1 + 30) = 3100` W at tier 4.

The dish drive's own override (`code/game/machinery/dish_drive.dm:110-118`) is meant to lower power use for better parts:

```dm
if(total_rating >= 9)
	update_mode_power_usage(ACTIVE_POWER_USE, 0)
else
	update_mode_power_usage(IDLE_POWER_USE, max(0, initial(idle_power_usage) - total_rating))
	update_mode_power_usage(ACTIVE_POWER_USE, max(0, initial(active_power_usage) - total_rating))
```

Two things are wrong with it:

- It subtracts the summed tier (3 to 12) from usage values of 100 W idle (`BASE_MACHINE_IDLE_CONSUMPTION`) and 40 W active (`BASE_MACHINE_ACTIVE_CONSUMPTION * 0.04`), so the intended reduction is tiny (97 and 37 at tier 1, 94 and 34 at tier 2).
- At a total tier of 9 or more it only sets active usage to 0 and never touches idle, so idle keeps the parent's high value (1600 W and 3100 W above), while the active use drops to 0.

## Fix

One commit, "Fix issue 41028: dish drive power usage scales consistently with part tiers", changes `RefreshParts()` in `code/game/machinery/dish_drive.dm`. The two branches are replaced by one calculation:

```dm
var/usage_multiplier = max(0.1, 1 - 0.1 * (total_rating - 3))
update_mode_power_usage(IDLE_POWER_USE, initial(idle_power_usage) * usage_multiplier)
update_mode_power_usage(ACTIVE_POWER_USE, initial(active_power_usage) * usage_multiplier)
```

Usage is 10% lower for each tier above the base parts (the base build has a total of 3), with a floor of 10% of the initial value. Both idle and active use are computed from their initial values every time, so repeated calls give the same result and nothing is left over from the generic calculation. This keeps the original intent (better parts, less power) and keeps idle and active consistent with each other.

## Verification

After rebuilding, the same Lua test gave (idle / active, in watts):

| Tier | Idle | Active |
|---|---|---|
| 1 | 100 | 40 |
| 2 | 70 | 28 |
| 3 | 40 (39.999996 as read, a float rounding effect) | 16 |
| 4 | 10 | 4 |

Calling `RefreshParts()` a second time on the tier 4 drive gave 10 / 4 again. The base tier now matches the initial values.

Not checked: building a drive from a machine frame and upgrading it with real parts, mixed-tier part combinations (only the same tier for all three parts was tried), and the effect on the area's power draw while the drive operates.

## Notes

- The 10% per tier curve and the 10% floor are a design choice; the issue does not specify one. The fix assumes the original intent was lower power use with better parts. A maintainer may prefer another curve, or may prefer to drop the override and keep the generic rule that better parts use more power.
- Other machines use the generic scaling (better parts, higher consumption). The dish drive was the one examined here.
