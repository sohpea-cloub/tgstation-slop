# #90708: Hunger bar stays hidden while the "getting a bit hungry" moodlet is active

| | |
|---|---|
| Issues | [#90708](https://github.com/tgstation/tgstation/issues/90708): verified, fixed |
| Status | Fixed on the fix branch (one commit); partly a design question, see Notes |
| Fix branch | [fix/90708](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/90708) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The hunger HUD element and the nutrition moodlets used different thresholds. Between 200 and 250 nutrition the mood system applied "I'm getting a bit hungry." while the hunger bar stayed hidden, so a player felt the penalty with nothing on screen explaining it. The fix makes `update_hunger_state()` use the same inclusive thresholds as `update_nutrition_moodlets()`. This also removes small gaps between the old `1 + X to Y` ranges, which could leave a stale state when the rounded fullness landed between two ranges. The second half of the issue title ("stay hungry for a while after being full") was not changed; it follows from the bar counting food that is still being digested, and looked intended.

## The bug

The issue (title: "you get hungry before you can see you're hungry (you also stay hungry for a while after being full?)") says the hunger bar does not show when the character is hungry, and that the hungry moodlet is sometimes still there when the character is full. The linked media was not available to this investigation.

What was confirmed: with nutrition from 200 to 250 the mood showed "I'm getting a bit hungry." but the hunger bar was invisible. The bar only appeared from about 195 down, where the mood is already the stronger "I'm hungry!".

## Reproduction

On master, with admin tools on the test server:

1. Start the round and join as an Assistant.
2. In the Lua editor, set the character's nutrition to a value (for example 245, then 220) with `set_nutrition`, and call `update_nutrition_moodlets` on the mob's mood datum.
3. Read the hunger HUD element's `alpha` (`hud_used.screen_objects['mob_hunger']`) and the description of the nutrition mood event.

Observed on master:

- 245 and 220 gave `alpha` 0 (bar hidden) together with the mood "I'm getting a bit hungry."
- The bar only became visible from 195 downward, with the mood "I'm hungry!".

This was done by setting nutrition and calling the update procs from Lua, not by letting a character get hungry over time. The float-gap part of the cause (below) was found by reading the code; a gap value such as 250.05 was not tested in game.

## Cause

Two pieces of code disagree.

The mood side, `code/datums/mood.dm:137-139` (inside `update_nutrition_moodlets()`), uses closed ranges on raw `nutrition`. `NUTRITION_LEVEL_HUNGRY` is 250, `NUTRITION_LEVEL_VERY_HUNGRY` is 200 and `NUTRITION_LEVEL_STARVING` is 150 (`code/__DEFINES/mobs.dm:321-323`):

- 200 to 250 gives `/datum/mood_event/hungry` ("I'm getting a bit hungry.")
- 150 to 200 gives `/datum/mood_event/hungry_very` ("I'm hungry!")
- below 150 gives `/datum/mood_event/starving`

The HUD side, `/atom/movable/screen/hunger/proc/update_hunger_state()` in `code/_onclick/hud/screen_objects/screen_objects.dm:1202`, maps rounded fullness to a state:

```dm
fullness = round(hungry.get_fullness(only_consumable = TRUE), 0.05)
switch(fullness)
	...
	if(1 + NUTRITION_LEVEL_HUNGRY to NUTRITION_LEVEL_FULL)
		state = HUNGER_STATE_FINE
	if(1 + NUTRITION_LEVEL_VERY_HUNGRY to NUTRITION_LEVEL_HUNGRY)
		state = HUNGER_STATE_FINE
	if(1 + NUTRITION_LEVEL_STARVING to NUTRITION_LEVEL_VERY_HUNGRY)
		state = HUNGER_STATE_HUNGRY
```

So 200 to 250 was `HUNGER_STATE_FINE`, and `update_hunger_bar()` (line 1240) only fades the bar in for a non-fine state (or when digesting food makes fullness differ from nutrition by 1 or more). The bar therefore started one tier too late.

Second, `fullness` is a float rounded to 0.05, and the ranges are `1 + X to Y`. A value such as 250.05 falls in none of them, so `state` keeps its previous value. The mood side has no such gap.

## Fix

One commit, "Fix issue 90708: hunger bar now shows for the "getting a bit hungry" moodlet", changing `update_hunger_state()` only:

- It uses the mood's inclusive thresholds: 550 and above is `HUNGER_STATE_FULL`, 250 up to 550 is `HUNGER_STATE_FINE`, 150 up to 250 is `HUNGER_STATE_HUNGRY`, and everything else is `HUNGER_STATE_STARVING`.
- The final range is now an `else`, so no value can fall through the switch.
- A comment says the thresholds must stay in line with `update_nutrition_moodlets`.

The two former FINE/HUNGRY rows at 200-250 and 150-200 merged into one HUNGRY row; the HUD has a single hungry state, so nothing else needed splitting.

## Verification

After rebuilding and restarting the test server, with the same Lua method as in the reproduction:

- 220 and 200 gave `alpha` 255 and the hungry moodlet.
- 245 gave `alpha` 255 after a 3 second wait (the bar fades in over 1 second, so reading it immediately is too early).
- 250, 260 and 300 gave `alpha` 0 and no moodlet.
- 195 down to 150 gave `alpha` 255.
- 140 and 100 gave `alpha` 255 (starving).
- 550 showed the bar, with the "too wellfed" mood.

Not checked: float values between ranges (such as 250.05), characters with the fat, glutton, no-hunger or stomachless handling (those branches were not touched), and a full play-through of gradually losing nutrition.

## Notes

- **"Stay hungry after being full."** Not changed. The HUD uses `get_fullness(only_consumable = TRUE)` (`code/modules/mob/living/life.dm:102`), which adds the nutrition of food and reagents still being digested, while the mood uses raw `nutrition`. After eating, the bar can look full while the hungry moodlet persists until digestion actually raises nutrition. This looks deliberate, but a maintainer could decide the mood should also count digesting food.
- The alternative direction, making the mood follow the HUD, would remove the moodlet at 200-250. That changes gameplay values, so the fix instead aligned the display with the existing mood tiers.
