## Summary

The 2021 report says that a player turned into a gorilla by the genetics monkey mutation could not punch walls with combat mode on and could not eat with combat mode off. On current master the gorilla is a basic mob (`/mob/living/basic/gorilla`) that tears walls and eats food on a plain click in both combat-mode states, so neither symptom could be reproduced. The unarmed-attack handlers that do this have no `combat_mode` check, so the bug looks gone, but the old mob and its code were not looked at, so what exactly fixed it is not established.

## The bug

As reported (client 513.1542, round 156593): a geneticist used a monkey mutator on themselves, then, standing next to three uranium blocks, mutated into a gorilla. As a gorilla they could not punch walls with combat mode on and could not eat with combat mode off. An admin told them the bindings were broken.

## Reproduction

The attempt was on master and used the same path as the report (the genetics gorilla), with admin tools to set it up. It did not reproduce.

1. On the test server, in the Lua editor, spawn a human and call `gorillize(true)` on it (the genetics path in `code/modules/mob/transform_procs.dm:210`). The result was a `/mob/living/basic/gorilla/genetics` named "Lab Gorilla".
2. Set the gorilla's `ckey` so a player controls it.
3. Make a wall on the tile north of it (`ChangeTurf` to `/turf/closed/wall`) and spawn a banana (`/obj/item/food/grown/banana`) on the tile east.
4. Combat mode off (the state the gorilla started in; its value was not read back at this point): click the wall. Result: "Lab Gorilla (626) begins tearing through the wall!" with a progress bar. Click the banana. Result: "You gnaw the banana." and the banana was consumed.
5. Press the combat mode key (C). Reading `combat_mode` back through Lua gave `1`. A second wall and banana were set up (the first wall had been partly torn, and the first banana was gone). Clicking the wall again gave "begins tearing through the wall!" and clicking the banana gave "You bite the banana." (the banana was consumed).

So neither reported symptom occurred. Notes on the method:

- Between the two states the gorilla also picked up an iron sheet by clicking it, and dropped it with the drop key. This was incidental.
- Clicks were sent to the game as mouse clicks. The test did not exercise a key-binding or hotkey interface beyond the combat mode key, so it cannot rule out a problem in some other hotkey layer that the original report could have been about.

## Cause

There is no live defect to point to. The reports' explanation for why the bug is gone is that the gorilla changed type, and the code on master supports that the current gorilla is not gated by combat mode:

- `code/modules/mob/living/basic/farm_animals/gorilla/gorilla.dm:65` adds the `wall_tearer` element (`allow_reinforced = FALSE`) and line 68 adds `basic_eating` with the gorilla's food list.
- `code/datums/elements/wall_tearer.dm:31` registers its handler on `COMSIG_HOSTILE_PRE_ATTACKINGTARGET` and `COMSIG_LIVING_UNARMED_ATTACK`. The element has no `combat_mode` check.
- `code/datums/elements/basic_eating.dm:40` registers `on_unarm_attack` on `COMSIG_LIVING_UNARMED_ATTACK`. It also has no `combat_mode` check, so a click on food eats it in either state.
- The one combat-mode check in the eating element is in `try_feed()` (`basic_eating.dm:44`, `if(user.combat_mode || ...) return NONE`). That handler runs on `COMSIG_ATOM_ITEM_INTERACTION`, that is, when someone feeds the mob with a held item. It is for feeding, which is intended to need combat mode off, and it is not used when the gorilla clicks food itself.

What the 2021 gorilla was is not established from the code here. The investigation's working belief was that it was a different mob type with attack and eating code that depended on combat mode; this was not checked in the history, which is shallow in this checkout.

## Fix

None. No code was changed and nothing was committed.

## Verification

The not-reproduced result was confirmed in game as described under Reproduction: both clicks (wall, food) worked in both combat-mode states with a possessed genetics gorilla on current master. No runtime was looked for.

Not checked:

- The first combat-mode-off run did not read `combat_mode` back; the "off" state was assumed from the default.
- Keyboard or hotkey bindings beyond the combat mode key (the report said "bindings were broken").
- Other gorilla variants (the bar gorilla, the spell form `/datum/action/cooldown/spell/shapeshift/gorilla`, the cargo gorilla) were not tested.
- Reinforced walls (the element is set to not tear them, `allow_reinforced = FALSE`) and eating foods the gorilla's list does not include.
- A real genetics mutation sequence (monkey mutator, then radiation to the gorilla stage); the gorilla was made with `gorillize(true)`, which the test took to be the same transformation.

## Notes

- The investigation looked at upstream PR #69091 (a merged PR that mentions this issue, about removing the shapeshift holder). It concluded that this PR is not the relevant change; the rewrite of the gorilla as a basic mob is. The specific upstream PR for that rewrite was not identified.
- The issue carries the "Oversight" label and has had no comments since 2021. It could probably be closed as fixed by the basic-mob rewrite, if a maintainer is satisfied with the check above.
