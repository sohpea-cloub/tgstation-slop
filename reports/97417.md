# #97417: Scooped blood decals come out as blood type U

| | |
|---|---|
| Issues | [#97417](https://github.com/tgstation/tgstation/issues/97417): verified, fixed |
| Status | Reproduced and fixed; fix checked in game (decals built directly, not from a real wound) |
| Fix branch | [fix/97417](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97417) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Blood decals build their reagents lazily, and `lazy_init_reagents()` gave them only a DNA entry as reagent data, and only for `/datum/reagent/blood`. Scooping a decal into a beaker therefore produced blood with no blood type (shown as the universal fallback, U), and non-blood blood reagents such as liquid electricity got no data at all. The fix builds each reagent's data from its blood type's default blood data, with that type's own DNA sample.

## The bug

After hitting someone so that a blood decal appears, scooping it up with a beaker gave blood with the right DNA but blood type U. The report adds that for an Ethereal, the scooped liquid electricity had no DNA at all.

## Reproduction

On the test server, using the Lua editor (the decal was created directly instead of by wounding someone):

1. Spawned a human and a beaker.
2. Created an `/obj/effect/decal/cleanable/blood/splatter` with the human's blood DNA list (`get_blood_dna_list()`).
3. Called the decal's `item_interaction(human, beaker, {})`, the scoop path, and read the beaker's reagent data.

Result on master: `/datum/reagent/blood`, volume 5, `type=U`, with the DNA present.

## Cause

`lazy_init_reagents()` in `code/game/objects/effects/decals/cleanable/blood.dm:127` collected only the reagent types from the decal's blood DNA, then added them with:

```dm
data = ispath(reagent_type, /datum/reagent/blood) ? list(BLOOD_DATA_DNA = pick(blood_DNA)) : null)
```

(`blood.dm:139-142`.) Two defects follow:

- No `BLOOD_DATA_TYPE` is set. `/datum/reagent/blood/on_new()` treats missing type data as an artificially created blood and falls back to the universal type (`code/modules/reagents/chemistry/reagents/other_reagents.dm:25-30`), hence U.
- Reagents that are not `/datum/reagent/blood` (liquid electricity) get `null` data, so no DNA. Even for blood, `pick(blood_DNA)` gave every reagent one random DNA sample rather than its own.

## Fix

**Fix issue 97417: scooped blood decals keep their blood type.** For each entry in the decal's blood DNA, the code now takes the `/datum/blood_type`, calls `get_default_blood_data()`, sets `BLOOD_DATA_DNA` to that entry's own DNA sample, and adds the type's reagent with that data. This is the same data blood taken from a mob has, and it applies to every reagent type.

## Verification

On the test server after rebuilding, with decals built directly from the mob's blood DNA list (the same list the splatter code uses), scooped into a beaker:

- Human: `blood type=A-` with its own DNA.
- Ethereal: `liquidelectricity type=LE` with its own DNA.
- Decal with both human and ethereal blood: both reagents at 2.5u each, each with its own type and DNA.

Not checked: the real path of wounding or bleeding a mob to create the decal; gibs and other decal subtypes that now also receive blood type data through this proc (same data as mob blood, unverified in game).

## Notes

- The trail and gibs decal types override `lazy_init_reagents()` (`blood.dm:493`, `:550`) and were not touched or examined here.
