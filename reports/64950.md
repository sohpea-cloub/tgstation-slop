# #64950: Shuttles can dock over other shuttles that sit off-dock

| Status | Fixed on a branch for ordinary shuttles; emergency shuttle case left as is |

## Summary

`canDock()` decides whether a stationary dock is free only by looking for a mobile port on the dock's own tile. A different dock whose rectangle overlaps a parked shuttle therefore looks free, and the arriving shuttle crushes the parked one. The fix makes `canDock()` also refuse when the arriving shuttle's footprint overlaps any other mobile port, returning `SHUTTLE_SOMEONE_ELSE_DOCKED`. The emergency shuttle overrides `canDock()` to always succeed and is unchanged.

## The bug

The report shows two shuttles on Deltastation (the escape shuttle and the whiteship) ending up intersecting, with parts of them deleted. A commenter says the same happens with Syndicate shuttles and can hard-delete objects such as a console. The report has no steps; the Deltastation case was not loaded here.

## Reproduction

Done on MetaStation with a synthetic dock, because no two stationary ports on the default map overlap (apart from the disabled auxiliary base zone). Admin tools only.

1. Start a round, observe, open the Lua editor.
2. Create a `/obj/docking_port/stationary` at (155,108,1) with the ferry's size and orientation (width 5, height 13, dwidth 2, dheight 0, facing west). The cargo shuttle was parked at (152,108), occupying roughly x146..152, y103..114, so the new dock overlaps it.
3. Call `canDock(dock)` on the ferry (`/obj/docking_port/mobile`) and then `initiate_docking(dock)`.

Observed on master: `canDock` returned `can_dock`; the ferry landed on the overlapping dock and the cargo shuttle disappeared from `SSshuttle.mobile_docking_ports` (it was destroyed). No runtime was logged. (From Lua, `initiate_docking` returned nil because of its `CHECK_TICK` sleeps, but it completed asynchronously.)

This reproduces the cause by calling the docking procs directly. It does not exercise a real call of the escape shuttle or whiteship.

## Cause

`/obj/docking_port/mobile/proc/canDock` (`code/modules/shuttle/mobile_port/mobile_port.dm:239`) checks size fit and then occupancy at lines 260-269 using `stationary_dock.get_docked()`, which is only `locate(/obj/docking_port/mobile) in loc` (`code/modules/shuttle/stationary_port/stationary_port.dm:106`). A shuttle parked off that exact tile is not found, even if it lies inside the area the new shuttle would take.

The navigation computer's placement check refuses overlap with other *stationary* ports only, and only when a destination is placed. Mapped docks, docks added later and shuttles without a navigation computer are never checked against mobile ports.

## Fix

One commit, "Fix issue 64950: Shuttles can't dock over other shuttles that sit off-dock":

- A new proc, `overlaps_other_shuttle(stationary_dock)`, computes the footprint with `return_coords(dock.x, dock.y, dock.dir)` and compares it, as a bounding rectangle, with the current bounds of every other mobile port on the same z level (skipping itself and deleted ports).
- `canDock()` returns `SHUTTLE_SOMEONE_ELSE_DOCKED` when that is true, after the existing checks.

That return code is already handled by `SSshuttle.action_load` (the template replacement case), so replacing a shuttle with a new template should be unaffected; this was not exercised in game.

## Verification

On a rebuilt test server with a fresh round and the same synthetic overlapping dock:

- `canDock` returned "someone else docked"; `initiate_docking` returned 1 (blocked); the ferry stayed at its away position and the cargo shuttle was untouched.
- A clear dock about 40 tiles away: `canDock` returned `can_dock` and the ferry docked there.
- `SSshuttle.moveShuttle('mining', 'mining_away')` still worked.
- No new runtimes.

Not checked: Deltastation, the whiteship, Syndicate shuttles, shuttle template loading and replacement, and the emergency shuttle.

## Notes

- `/obj/docking_port/mobile/emergency/canDock` (`code/modules/shuttle/mobile_port/variants/emergency/emergency.dm:22`) always returns `SHUTTLE_CAN_DOCK` on purpose ("it will force itself to land even if it has to crush a few departments"). So if the Deltastation case was the escape shuttle landing on a whiteship at an overlapping port, it is not fixed. Adding the overlap check there would risk the emergency shuttle being unable to land; that trade-off is for maintainers.
- The overlap test uses bounding rectangles, so it is conservative for shuttles that are not rectangular.
- The change touches only `canDock` and the new proc in `mobile_port.dm`.
