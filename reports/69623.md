# #69623: Hypnotic trigger phrase is censored when heard during a trance (Enhanced Interrogation Chamber)

| | |
|---|---|

| Status | #69655 fixed and checked in game; #69623 closed as not reproducible with the caveats below |

## Summary

The enhanced interrogation chamber (hypnochair) does give its victim the Hypnotic Trigger trauma, and saying the trigger phrase near them does put them in a trance, so the "doesn't work" report in #69623 could not be reproduced. The behaviour described in #69655 is real, though: if the phrase is heard again while the victim is already in a trance, the trigger censors it to `*********` before the trance reads the message, so the victim is hypnotized with the censored text (and a second trance is queued). The fix makes the trigger ignore messages while a trance is active, and makes the delayed trigger do nothing if a trance is already running.

## The bug

### #69623

The reporter brainwashed someone with the chair, said the trigger phrase, and "nothing happens". A comment asked whether the phrase had been started with a capital letter.

### #69655

Throw someone in the chamber, say their trigger phrase, then say it again. The admin log then shows a hypnosis with a censored phrase (the report has a screenshot). The reporter's note: "This hypnotic message isn't applied, and the user will be hypnotized by the next message they hear."

## Reproduction

### #69623 (not reproduced)

1. On the test server, using the Lua editor, spawn a hypnochair and two humans, a victim and a speaker.
2. Close the victim in the chair, set the trigger phrase to `banana` (`set_phrase()`), and run `interrogate()` and then `finish_interrogation()`. A 10% roll gives `hypnotic_stupor` instead of the trigger trauma, so this was repeated until the victim had the Hypnotic Trigger trauma. The real 45-second timer path was also run once from `set_phrase` and `interrogate`, ending with the message "You feel odd, like you just forgot something important" and the trauma gained.
3. Have the speaker say "hello banana there".

Observed: the victim sees "Hello ********* there"; one second later "The words trigger something deep within you..." appears together with the Trance alert. This is the designed behaviour, so the basic trigger works.

A test-setup pitfall worth knowing: `mob/living/Hear()` returns early when the mob has no client (`code/modules/mob/living/living_say.dm:278`, `!GET_CLIENT(src)`), so an NPC victim with no client never reacts to anything. The first attempts showed "nothing happened" for exactly that reason. The victim has to be a player-controlled mob. (This only concerns testing; a connected player is not affected.)

Possible explanations for the original report that are not code bugs:

- The trigger phrase only gives a trance (`stun` is false, with greyscale colour and mute). The next message the victim hears is the hypnotic suggestion, so nothing visible happening at first is by design.
- A victim wearing eye protection (sunglasses and similar) is not affected by the chair at all (`code/game/machinery/hypnochair.dm:137`, `finish_interrogation()`).
- There is a 10% chance that the victim gets `hypnotic_stupor` instead of the trigger trauma (`hypnochair.dm:139`-`142`).
- The victim is deaf while being interrogated.
- The capital-letter question in the comments does not matter: the trigger regex is built with the `i` flag.

The 2022 report was made with several testmerged init-time PRs, and it may have been one of the above or an older, since-fixed bug. This cannot be determined from the inputs.

### #69655 (reproduced on master)

1. Set up the victim as above with a Hypnotic Trigger trauma and a player-controlled victim.
2. The speaker says "hello banana there"; the victim goes into a trance.
3. While the victim is in the trance, the speaker says "banana" again.

Observed on master: the victim's chat showed `Speaker says '*********'`, then "You snap out of your trance!". The victim was then hypnotized with `hypnotic_phrase` equal to the span `<span class='hypnophrase'>*********</span>`; the admin message read "was hypnotized with the phrase '<span ...>*********</span>'", and the attack log held the same text. The trigger also queued another trance ("The words trigger something deep within you" again). The speaker's real phrase was never applied.

## Cause

Both the Hypnotic Trigger trauma and the trance status effect listen for what the victim hears (`COMSIG_MOVABLE_HEAR`). The trauma's handler is registered first, so it runs first.

`/datum/brain_trauma/severe/hypnotic_trigger/handle_hearing()` (`code/datums/brain_damage/severe.dm:296`) replaces every match of the trigger phrase in `hearing_args[HEARING_RAW_MESSAGE]` with `span_hypnophrase("*********")` and queues `hypnotrigger()` one second later:

```dm
if(findtext(hearing_args[HEARING_RAW_MESSAGE], reg))
	addtimer(CALLBACK(src, PROC_REF(hypnotrigger)), 1 SECONDS) //to react AFTER the chat message
	hearing_args[HEARING_RAW_MESSAGE] = reg.Replace(hearing_args[HEARING_RAW_MESSAGE], span_hypnophrase("*********"))
```

When the victim is already in a trance, `/datum/status_effect/trance/hypnotize()` (`code/datums/status_effects/debuffs/debuffs.dm:728`) is the next handler. It treats the next message heard as the hypnotic suggestion and reads `HEARING_RAW_MESSAGE`, which by now is the censored text. It logs it and gives the `hypnosis` trauma with that text as the phrase. Also, `hypnotrigger()` (`severe.dm:306`) had no check that a trance was already running, so the queued call started another one.

## Fix

One commit, "Fix issue 69655: hypnotic trigger no longer censors the suggestion heard while in a trance", in `code/datums/brain_damage/severe.dm`:

- `handle_hearing()` returns early if the owner has `/datum/status_effect/trance`. The message is then left unchanged for the trance to read, so the next thing the victim hears (including the trigger phrase itself) becomes the hypnotic suggestion.
- `hypnotrigger()` returns early if the owner is `QDELETED` or already entranced, so a trigger that was queued before the trance began cannot stack a second trance.

An alternative would have been to make the trance handler read the original message. The chosen change is smaller and keeps the trigger's censoring (and the one-second delayed reaction) for normal use.

## Verification

After rebuilding and starting a new round, with a player-controlled victim holding the trigger trauma:

- "hello banana there" and "banana" within one second of each other: both messages were censored, and only a single trance resulted.
- After the trance began, the speaker said "banana" again. The message reached the victim uncensored ("Banana"), the victim gained the `hypnosis` trauma, and the game log read "was hypnotized with the phrase 'Banana'". The attack log read "hypnotised ... with the phrase 'Banana'".
- No runtimes.

Not checked: other trigger phrases or a trigger that is also a normal word; trigger and trance interplay with `hypnotic_stupor`; the effect of the fix on the original #69623 screenshot-less scenario (which did not reproduce).

## Notes

- With the fix, a trigger phrase said during a trance is not censored, so the victim reads it in clear text; it then becomes the hypnosis phrase. That follows the trance's design (the next message heard is the suggestion), but it does mean the phrase is visible to the victim at that point.
- #69623 may still be worth keeping open only if someone can describe a concrete case; none of the visible failure modes found were code bugs.
