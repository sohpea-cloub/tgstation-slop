## Summary

The crew monitor's tgui interface compares each entry's `life_status` against `STAT_DEAD = 4`, but the game's `DEAD` is `3`, so a dead player never matches. Wearers of binary sensors therefore show "Alive" after dying, and wearers of vitals sensors keep a heartbeat icon instead of a skull. The fix changes the constant to `3`. The server side was found to be correct. #93303 is a different bug (the medical HUD, not the crew monitor).

## The bug

Per #98024, with suit sensors set to "binary", dying leaves the crew monitor showing the wearer as "alive". A comment on the issue says the second sensor mode also does not work. That matches what was found: with vitals sensors the dead wearer is shown with the heartbeat icon rather than the skull.

## Reproduction

1. On master, on the test server, using the Lua editor, spawn three humans in grey jumpsuits.
2. Set their sensor modes to 1, 2 and 3 with `set_sensor_mode`.
3. Kill each with `death()`.
4. Refresh the crew monitor's data with `GLOB.crewmonitor:update_data(2)` and read the entries.

Observed: all three dead humans reported `life_status = 3` (DEAD). Mode 1 entries had no `oxydam` value; modes 2 and 3 had damage values. So the data sent to the interface was correct.

The tgui rendering could not be run, because the test client does not execute tgui JavaScript. The bug was therefore established by reading the interface code against these data values, not by seeing a wrong screen.

## Cause

`tgui/packages/tgui/interfaces/CrewConsole.tsx:20` declares:

```ts
const STAT_LIVING = 0;
const STAT_DEAD = 4;
```

but `code/__DEFINES/stat.dm:5` has `#define DEAD 3` (the stats are STABLE 0, SOFT_CRIT 1, HARD_CRIT 2, DEAD 3). The server sends `life_status` from the mob's `stat` (`code/game/machinery/computer/crew.dm:262`, and `:265` for the dead/alive-only case), so a dead mob arrives as `3`.

Because nothing ever equals 4:

- `CrewConsole.tsx:264` and `:281` (`life_status !== STAT_DEAD ? ... 'Alive' ...`) always take the "alive" branch. Binary sensors have no `oxydam`, so the status text is the only indicator, and it reads "Alive".
- `statToIcon` (`CrewConsole.tsx:94-100`) never returns `'skull'`, so it falls through to `'heartbeat'` for the vitals mode. This explains the comment about the second mode.

## Fix

One commit, "Fix issue 98024: crew monitor shows dead binary-sensor wearers as alive", changes `STAT_DEAD` from `4` to `3` in `tgui/packages/tgui/interfaces/CrewConsole.tsx`. No alternative was considered; the constant simply disagrees with the DM define.

## Verification

- The server data was checked as described above (`life_status` 3 for dead humans in all three sensor modes).
- After the change, tgui was rebuilt without error and the compiled bundle contained `case 3:return"skull"` for the icon switch.

Not checked: the interface as rendered in a client (no "Dead" text or skull icon was seen on screen), and the fix on a real round with a real crew monitor console.
