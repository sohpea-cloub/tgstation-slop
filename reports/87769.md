## Summary

The Networked Fibers blob strain has no resource-producing structure of its own. Its "faster resources" is a side effect: when a core or node automatically expands, the new blob is deleted and the overmind gets a point instead. When a core or node has nothing left to expand into (all four neighbouring tiles already hold blob, or are blocked), no expansion happens, so no point is paid, and the strain's income falls to the base rate. This is what happens if the blob grows around its core and nodes under another strain first and then swaps back to fibers. The fix adds a hook that is called when a pulse had the chance to expand and failed, and Networked Fibers pays the same point there.

## The bug

The reporter of #87769 describes nodes giving good income on Networked Fibers, income dropping after switching to another strain, and then, after switching back, income being only the base rate, "8+ nodes and seemingly base resource generation". Nothing in the strain stores state across a swap, so the explanation is not a leaked or stuck value. The strain's income depends on whether the core and nodes can still auto-expand, which the other strain's growth takes away.

#92295 describes resource gain freezing at 2 points with at least three resource blobs after a swap from Shifting Fragments to Cryogenic Poison and a second biohazard announcement. A commenter suggests time dilation instead.

## Reproduction

All runs were on the test server using the Lua editor, with a blob overmind created by hand (no real player client). Because of that, the measurement calls `pulse_area` on a node directly instead of waiting for the node to pulse by itself.

**#87769, isolated measurement on master**
1. Create a blob overmind with the Networked Fibers strain and one node, and reset the overmind's points to a known value (background income was about 3 points over the test).
2. Call `node:pulse_area(overmind, 0, 0, 0)` 200 times from Lua.
3. With the node's neighbouring tiles free: the overmind gained 144 points.
4. With all four neighbouring tiles holding blob: the overmind gained 3 points, i.e. no income beyond the background.

The income comes from `expand_reaction` being triggered by a successful expansion of the core or node, which is not possible once all four neighbours are taken.

**#92295**
1. Create a blob with Shifting Fragments and three resource blobs, then change the strain to Cryogenic Poison.
2. "+1 resource" floaters appeared before and after the swap and income did not change.
3. A second biohazard announcement was not triggered in this run.

This did not reproduce the report. It also is not related to the Networked Fibers cause, since neither strain is Networked Fibers. The commenter's explanation (lag stopping the processes that blob relies on) was not tested.

## Cause

`/datum/blobstrain/reagent/networked_fibers/expand_reaction()` (`code/modules/antagonists/blob/blobstrains/networked_fibers.dm:14`) is the only place where this strain generates anything:

```dm
if(!overmind && new_blob.overmind)
    new_blob.overmind.add_points(1)
    qdel(new_blob)
    return
```

So an automatic expansion (no controlling overmind) is turned into one point, and the new blob is deleted. This hook is called from `/obj/structure/blob/proc/expand()` (`code/modules/antagonists/blob/structures/_blob.dm:221-222`), but only when a blob is really made. `expand()` returns without doing anything if all four orthogonal tiles around the blob already contain a blob (`_blob.dm:174-184`), or if the target tile is blocked.

`pulse_area()` (`_blob.dm:432`) calls `expand()` on the core or node with a 70% chance (line 437). Other strains are not affected by a full area. They grow normally, so by the time the overmind switches back to Networked Fibers, the area around its core and nodes can be full. `expand()` then finds no free tile, `expand_reaction` is never called, and the income is the base rate. The strain change itself (`on_gain` / `on_lose` in `_blobstrain.dm`) does not leave anything behind that causes this.

## Fix

One commit, "Fix issue 87769: networked fibers still pay out when a node or the core has nothing left to expand into":

- `_blobstrain.dm`: new empty hook `expand_failed_reaction(obj/structure/blob/special/pulser)` on `/datum/blobstrain`.
- `_blob.dm`, `pulse_area()`: the 70% expansion roll is now split into "rolled and `expand()` succeeded" and "rolled and `expand()` failed" (`expand_failed`). At the end of the pulse, if the roll was made, `expand()` failed, and nothing else expanded during the loop over nearby blobs (`!expanded`), and the pulser has an overmind, it calls `overmind.blobstrain.expand_failed_reaction(src)`.
- `networked_fibers.dm`: overrides the hook to `overmind.add_points(1)`, the same as a successful automatic expansion.

The income per pulse is meant to match the open-area case, so a boxed-in core or node earns what a free one would. A different approach would be a fixed resource income for the strain, independent of expansion. That would change the strain's design, so the existing mechanism was kept and only the missing case added.

## Verification

After the fix, using the same isolated measurement (200 calls to `pulse_area` on a node):
- Neighbours free: about 138 points (master: 144).
- All four neighbours blob: about 147 points (master: 3).

The two are about equal, and the difference from master in the free case is within what the 70% rolls and background income give.

A natural run was done as well: Networked Fibers, then Blazing Oil for about 2.5 minutes, then Networked Fibers again. Income continued after the swap back. Separately, Shifting Fragments to Cryogenic Poison with resource blobs kept paying "+1 resource" before and after the swap (this is the #92295 check).

Not checked:
- A full round with a real blob player over a long period. The nodes were pulsed by hand for the measurement.
- Whether the case where the core or node is only partly boxed in, or other expansion paths within `expand_range`, give a different income than the plain open-area case.
- Any effect on blob balance. Boxed-in cores and nodes now earn the full amount, which means a large Networked Fibers blob earns at the full rate for all nodes.
- #92295's lag explanation.

## Notes

- `expand_failed_reaction` is called with the pulsing structure so another strain could use it. Only Networked Fibers overrides it.
- A latent issue was noticed but not changed: `on_lose()` (`_blobstrain.dm:104`) does not subtract `core_range_bonus` from `pulse_range` the way `on_gain()` adds it. No current strain uses the range bonuses, so it has no effect today.
- #92295 stays unresolved: it involves two strains that do not use the expansion mechanism, so the fix here does not apply. The reporter gave no round log, and the only lead is the commenter's lag theory.
