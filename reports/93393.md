## Summary
**#93393.** The GPS component adds hardcoded `emp` and `working` overlays even when the MOD GPS module created it with overlay state disabled. The module's icon file has no `working` state, and its `emp` state is the animated red ERROR text, so the module showed an ERROR sprite after an EMP. The fix makes the component remember its overlay state and touch overlays only when it has one.

**#97382.** A painted standard MOD rendered fully recoloured both inactive and active, so the report was not reproduced. The issue screenshots could not be viewed, so what "incomplete paint" refers to is unknown. Two untested candidates are listed under Notes.

## The bug
### #93393
The report has only a screenshot of a MOD GPS with an ERROR sprite, and says to check the round's logs. The in-game cause is below.

### #97382
The report says that after painting a MOD with a MOD paint kit and activating it, the paint looks incomplete.

## Reproduction
### #93393
Reproduced with a proc call, not an actual EMP source.
1. Using the Lua editor, spawn a human, a `/obj/item/mod/control/pre_equipped/standard` and a `/obj/item/mod/module/gps`, and install the module into the suit.
2. Call `emp_act(1)` on the GPS module.
3. Drop the module and render it. It showed the animated ERROR sprite (the `emp` state of `mod_modules.dmi`). The module's overlay count went from 1 to 3.

### #97382
1. Spawn a human with a standard MOD on the back.
2. Call `set_mod_color` with `#ff2020`, and separately with a 12-value colour matrix, then activate the suit (`quick_activation`) and wait about 20 seconds.
3. Render the mob. In both runs the whole suit, including the helmet visor, was uniformly recoloured (dark red and green respectively); no uncoloured parts. This calls `set_mod_color` directly rather than using the paint kit item.

The renderer output also noted "parts naming an icon_state their icon lacks x1" on the worn suit; the source was not identified.

## Cause
### #93393
`code/modules/mod/modules/modules_supply.dm:20` creates the GPS component with `overlay_state = FALSE`. In `code/datums/components/gps.dm`, `Initialize` honours that (`if(overlay_state)` before adding the overlay at line 60), but `on_emp_act` (line 116), `reboot` (line 128) and `toggletracking` (line 142) hardcode the overlays: `A.cut_overlay("working")` / `A.add_overlay("emp")` at lines 122-123, the reverse in `reboot` at 131-132, and `"working"` at 150 and 154. With no `working` state in `mod_modules.dmi`, and `emp` being the animated ERROR text, the module showed an ERROR sprite.

### #97382
No cause found.

## Fix
One commit, "Fix issue 93393: MOD GPS module no longer gets working/emp overlays", in `code/datums/components/gps.dm`. The component gets an `overlay_state` variable set in `Initialize`. `on_emp_act`, `reboot` and `toggletracking` cut and add overlays only `if(overlay_state)`, using that state instead of the hardcoded `"working"`. Regular GPS devices use the default `"working"` and so keep their overlays. No fix for #97382.

## Verification
- #93393: after rebuilding and restarting the test server, the same steps gave 1 overlay before and 1 after the EMP, and the dropped module rendered as the plain GPS module sprite with no ERROR text.
- Not checked: a real EMP source; the alt-click tracking toggle on the MOD module; a regular `/obj/item/gps` under EMP (unchanged by the code path, not retested).
- #97382: only the standard theme with `set_mod_color` was tested; no paint kit item, other themes or skins, or modules.

## Notes
- #97382 candidates, not tried: `set_mod_color` (`code/modules/mod/mod_control.dm`) recolours the suit's parts and control with a fixed-priority colour, but worn module overlays only use the suit colour when the module has `use_mod_colors` (`code/modules/mod/modules/_module.dm:418`, default FALSE), and the visor overlay from `get_visor_overlay` is built without the part colour. Either could stay unpainted once active. Other themes and skins, and emissive overlays (not visible to the renderer), were also untested. Someone with the screenshots should compare against these.
