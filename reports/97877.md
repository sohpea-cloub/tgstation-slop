## Summary

#97877 asks why Watchers, Magmawings and Frostwings fire before the player can see them. Their targeting uses the basic-mob default `vision_range` of 9 (a square), larger than the 7-tile-high screen. A watcher was never seen firing from 8-9 tiles, and the long acquisition range looks intended, so nothing was changed. #98050 is a real bug: the Magmawing's "Searing Glare" gaze (and the other watcher gazes) affected blindfolded or blind targets because `valid_target()` never checked sight. The fix makes `valid_target()` reject blind mobs.

## #97877: detection range beyond the view

### The report

Lavaland watchers and variants hit players with bolts and gazes before the player can see them. A comment says all lavaland mobs seem to target from further away since the behaviour tree rework (legion skulls charging from off-screen, tendrils without a visible goliath).

### What was found

- Watchers use the default basic-mob target acquisition. `vision_range = 9` is set at `code/datums/ai/basic_mobs/basic_ai_behaviors/targeting.dm:14`, and `basic_ranged_attack` has `max_range = 9` (`code/datums/ai/basic_mobs/basic_ai_behaviors/basic_attacking.dm:72`). The watcher's controller overrides only skirmish distances (3 and 5), not these ranges. The default 9-tile square reaches past the 7-row vertical view of the default screen, which is probably what players notice.
- On the test server, a bait human 4 tiles from a watcher was targeted within about a second, and the watcher fired from roughly 5 tiles. A retained target moved to 8 tiles away made the watcher walk closer, to about 5 tiles, before firing. Firing from 8-9 tiles was never observed.
- Fresh acquisition at 8-12 tiles was not validly tested: in the attempts the AI was off or the bait was in godmode. So whether a watcher can newly acquire a target at 8-9 tiles in practice is unconfirmed, though the code reads that way.
- No change was made, as the longer range matches the defaults the other basic mobs share and no clear intended value is documented.

### Side finding: `BB_AGGRO_RANGE` is dead code

The block in `code/datums/ai/basic_mobs/basic_ai_behaviors/targeting.dm` (from line ~51) that reads `controller.blackboard[aggro_range_key] || vision_range` is commented out ("TEMP DISABLED"). Mobs that set `BB_AGGRO_RANGE` (for example the polar bear, `BB_AGGRO_RANGE = 2`) therefore get no effect from it. If the range for lavaland mobs is to be tuned, this may be the first thing to look at. This was not tested in game.

## #98050: Magmawing gaze hits blind targets

### The bug

Blindfolded players and players with the blind trait, or no eyes, are still hit by the Magmawing's fire gaze (the version with the charge-up). Normal watchers' gaze is negated by blindness.

### Reproduction

1. On the test server, using the Lua editor, spawn a magmawing and two humans 3 and 4 tiles east of it, both facing west toward it. Give one human `/obj/item/clothing/glasses/blindfold` and leave the other bare-eyed.
2. Trigger the gaze with `gaze:trigger_effect()` on the magmawing's gaze action.
3. Observed before the fix (by the issue's steps and code reading): any conscious, facing mob qualified. A pre-fix control run in the final build was not done; in the earlier natural gaze the sighted human was ignited repeatedly.

### Cause

`valid_target()` in `code/modules/mob/living/basic/lavaland/watcher/watcher_gaze.dm:94` checked only that the viewer is a living mob, is not unconscious/critical, is not the owner, and faces the watcher. The fire gaze's `apply_effect()` override does not call `flash_act()` (the base one at `:102` does), so nothing else tested sight, and blindfolds had no effect.

### Fix

One commit, "Fix issue 98050: watcher gazes no longer affect blind targets", adds to `valid_target()`:

```dm
// Blindfolded, eyeless or otherwise blind mobs can't meet our gaze
if (viewer.is_blind())
	return FALSE
```

`is_blind()` covers blindfolds, missing eyes and the blind trait or status effect. Because the check is in `valid_target()`, it applies to all gazes.

### Verification

After the fix, `gaze:trigger_effect()` with both humans in range:

- Blindfolded human: fire stacks 0, not on fire, not paralyzed (unaffected).
- Sighted human: paralyzed (30), fire stacks 9.4, on fire.

Not checked: a before/after comparison on the same build; the blind trait or missing-eyes cases (only a blindfold was used); the ice gaze; unit tests. No new runtimes appeared from the change.

### Notes

- The ice gaze override (`watcher_gaze.dm:221`) reads `if(!HAS_TRAIT(viewer, TRAIT_RESISTCOLD)) return`, which looks inverted: it applies the effect only to cold-resistant targets and returns a falsy value for everyone else, skipping the flash overlay too. It is probably meant to be `if(HAS_TRAIT(...)) return FALSE`. This was only read, not tested or changed. `watcher_projectiles.dm:41` uses the same trait check in the opposite sense and looks correct.
