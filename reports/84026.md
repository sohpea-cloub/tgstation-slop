## Summary

When a soulstone asks ghosts to become its shade, the result of the poll is thrown away unless the user is still holding the stone next to the victim. Cult sacrifice runes and chaplain sparring shards put the stone on the floor, and a sacrifice rune also gibs the victim while the poll runs, so the ghost is announced as "selected" and nothing happens. The fix lets forced captures skip the hold, reach and incapacitation checks, and stops the shade code from touching the already-deleted victim. Separately, the poll never checked the ghost's cultist preference (#82925); it now does.

## The bug

### #84026

The poll runs, a winner is announced ("A Shade Poll: X was selected"), but the winner stays a ghost and the soulstone stays empty, so it can be used again. The reporter did not say how the poll was started and had the cultist role enabled, so #82925 was not the explanation for them.

### #82925

Ghosts with the Cultist role disabled in their preferences were still shown the shade poll and could be picked. The reporter saw the same symptom (selected, but still a ghost) and suspected a disabled-cultist ghost could keep being picked and hog the shade. A comment on the issue says the poll does not check `ROLE_CULTIST`.

## Reproduction

All steps used the Lua editor as an observing admin. The player actions (a real sacrifice rune, a real sparring match) were not performed; the relevant procs were called directly.

### #84026

1. Start a round on the test server, observe, and open the Lua editor.
2. Baseline, stone held. Spawn a human master holding an empty soulstone and a dead mindless human (the victim). Call `stone:capture_soul(victim, master)`. The ghost poll appeared; signing up and waiting 20 seconds made the observer a "Shade of ...". So the plain held-stone path already worked, and this is not the cause of the report.
3. Rune-style case. Spawn a dead human and a soulstone lying on the floor, call `stone:capture_soul(victim, master, true)` (forced, as the sacrifice rune does), then immediately `victim:gib()`. Sign up to the poll and wait 20 seconds.

Observed on master in step 3: the chat said "A Shade Poll: ... was selected", but the observer stayed a ghost and the soulstone stayed empty.

### #82925

1. Remove "Cultist" from the observer's `be_special` preference list in the Lua editor.
2. Spawn a human master holding a soulstone and a dead mindless human, and call `capture_soul(victim, master)`.

Before the fix this was not observed directly in a separate run; the cause is evident in the code (below). After the fix (see Verification) no poll was shown with the preference off.

## Cause

### #84026

`capture_soul()` (`code/modules/antagonists/wizard/equipment/soulstone.dm:313`) starts the poll with `SSpolling.poll_ghosts_for_target(...)` and then calls `on_poll_concluded(user, victim, chosen_one)` (`soulstone.dm:349`), which sleeps until the poll ends. On return it starts with:

```dm
if(isnull(victim) || master.incapacitated || !master.is_holding(src) || !victim.IsReachableBy(master, reach))
	return FALSE
```

(`soulstone.dm:468-469`.) That check only makes sense for a user using a held stone on an adjacent victim. Callers that pass `forced = TRUE` do not satisfy it:

- The sacrifice rune creates the stone on the floor, calls `stone.capture_soul(sacrificial, invokers[1], forced = TRUE)`, and then gibs the victim (`code/modules/antagonists/cult/runes.dm:394-399`). `capture_soul` waits in the poll, so the rune code resumes only after the poll and the gib has happened; `master.is_holding(src)` is false and the victim is gone.
- Sparring shards are created on the floor and called with `forced = TRUE` (`code/modules/religion/sparring/sparring_datum.dm:304-305`), so they fail `is_holding` the same way.

The function returns `FALSE` silently, after the ghost has already been told it was selected.

The shade code also assumes a live victim. `init_shade()` calls `soulstone_spirit.copy_languages(victim, LANGUAGE_MIND)` (`soulstone.dm:418`) and `victim.dust(drop_items = TRUE)` (`soulstone.dm:443`). With the first fix applied alone, `copy_languages` crashed with "get_language_holder() called on a QDELing atom" for a gibbed victim.

### #82925

The poll call at `soulstone.dm:339-340` passes `check_jobban = ROLE_CULTIST` but no `role`. `SSpolling.is_eligible()` checks the `be_special` preference only when `role` is set (`code/controllers/subsystem/polling.dm:292-294`), so only job bans were checked. The shade-from-construct poll at `soulstone.dm:549-551` passes `role` and does not have this problem.

## Fix

Two commits on `fix/84026`, both in `soulstone.dm`.

**"Fix issue 84026: shade poll winner not made a shade when the stone is not held or the victim is gone"**
- `capture_soul` now passes `forced` to `on_poll_concluded`.
- `on_poll_concluded` takes `forced = FALSE`. A null victim still returns early, but the null master, incapacitated, `is_holding` and reach checks apply only when not forced. A null master is also tolerated.
- The "Capture successful!" message goes to the master only if there is one.
- `init_shade` skips `victim.dust()` and the `LANGUAGE_MIND` language copy when the victim is `QDELETED`.

A shade made from a gibbed victim therefore gets the default shade languages plus the master's, and not the victim's.

**"Fix issue 82925: only poll ghosts with the cultist role enabled for a shade"**
- Adds `role = ROLE_CULTIST` to the poll in `capture_soul`, matching the construct poll.

## Verification

#84026, with the first commit: the same rune-style script (floor stone, forced capture, victim gibbed) was run on the rebuilt server. The observer signed up, was selected, and became "Shade of ..." inside the soulstone shard. The first attempt with only the hold/reach change crashed in `copy_languages`, which led to the `QDELETED` guard; after that, the runtime log showed no new runtimes from this change besides known noise from the test setup.

#82925, with the second commit: with "Cultist" removed from the observer's `be_special` list, `capture_soul` with a held stone showed no poll and the observer stayed a ghost. After adding "Cultist" back, the poll was shown ("Do you want to play as a shade?"). The signed-up-and-selected result with the preference on was not repeated after this commit; the baseline from before it covers that path.

Not checked: a real sacrifice rune, a real sparring match, the chaplain/cult items in actual play, and an observer who is selected while the stone's master is dead or has left. The reporter's own situation in #84026 is unknown, so it is not confirmed that the rune/sparring case is what they hit.

## Notes

- The #82925 reporter's symptom (selected, still a ghost) is probably the same unforced-check failure as #84026, since both involve the chaplain/cult stone, but that is inferred; the preference check on its own would only have let disabled-cultist ghosts be picked.
- A held-stone, non-forced capture where the victim is gibbed or the master drops the stone is still discarded by design; only forced captures bypass the check.
- A shade created from a gibbed victim copies no languages from the victim, since there is nothing left to copy from.
