# #90849: Gas filters round the filtered gas's temperature to 2.7 K

| | |
|---|---|
| Issues | [#90849](https://github.com/tgstation/tgstation/issues/90849): verified and fixed |
| Status | Fixed, one commit |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/90849 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The trinary gas filter builds its "filtered out" mixture from an empty `datum/gas_mixture`, whose temperature defaults to TCMB (2.7 K). `merge()` ignores temperature differences of 0.5 K or less, so gas within 0.5 K of TCMB was merged into that mixture without its temperature being applied and came out at exactly 2.7 K on the filtered side. The fix starts the filtered mixture at the temperature of the gas being filtered.

## The bug

Gas at about 2.72 K sent through a filter left the filtered (side) output at 2.7 K while the straight output stayed at 2.72 K. The issue also mentions other inconsistencies with filters keeping old temperatures, "possibly from the same issue". The reporter called the behaviour strangely inconsistent and offered more detail. Those other inconsistencies were not investigated.

## Reproduction

On the test server, using the Lua editor as an observer:

1. Spawn a `/obj/machinery/atmospherics/components/trinary/filter` and turn it on.
2. Set `filter_type` to CO2, using the gas id taken from a vent scrubber's `filter_types[1]`. Gas ids are typepaths. Lua string keys gave a heat capacity of 0 in this setup, so DM-sourced ids were needed.
3. Point `nodes[1..3]` at the filter itself. Set `airs[1]` to half of a turf's air plus 10 moles of CO2 at 2.72 K, and `airs[2]` and `airs[3]` to empty mixtures at 3.5 K.
4. Call `process_atmos()` and read the temperatures.

This drives the filter's `process_atmos` directly, not through a built pipe network.

Result on master: input 2.72 K, side (filtered) output **2.7 K**, main output 2.72 K. Moles were 10 on the side output and 52 on the main output.

## Cause

In `code/modules/atmospherics/machinery/components/trinary_devices/filter.dm:100`:

```dm
var/datum/gas_mixture/filtered_out = new
```

A new mixture starts at `temperature = TCMB` (`code/modules/atmospherics/gasmixtures/gas_mixture.dm:17`). The filter then merges each removed gas into it. `merge()` (`gas_mixture.dm:147`) only updates the temperature when `abs(temperature - giver.temperature) > MINIMUM_TEMPERATURE_DELTA_TO_CONSIDER` (0.5 K):

```dm
if(abs(temperature - giver.temperature) > MINIMUM_TEMPERATURE_DELTA_TO_CONSIDER)
	...
	temperature = (giver.temperature * giver_heat_capacity + temperature * self_heat_capacity) / combined_heat_capacity
```

For gas between 2.7 K and 3.2 K the difference is within the threshold, so `filtered_out` stays at 2.7 K while holding the moles. That mixture is then merged into the side output (`air2.merge(filtered_out)`), which is empty or nearly so, and so carries 2.7 K onward. The main output is built from `removed`, which keeps the true temperature. The vent scrubber already avoids this by setting `filtered_out.temperature = environment.temperature` after creating its mixture (`vent_scrubber.dm:236`).

## Fix

Commit "Fix issue 90849: gas filter rounds its filtered output to TCMB" adds one line after the mixture is created:

```dm
filtered_out.temperature = removed.temperature
```

with a comment explaining why. This matches the scrubber code. Changing `merge()` itself was not done, because the 0.5 K threshold is used throughout atmospherics.

## Verification

After rebuilding and repeating the steps above: input 2.72 K, side output 2.72 K, main output 2.72 K, with the same moles as before (10 and 52).

Not checked: a real built pipe network, the other filter inconsistencies the reporter mentioned, gas colder than 2.7 K, and the behaviour with several filtered gases at different temperatures.

## Notes

- `merge()` skipping deltas under 0.5 K could produce similar rounding wherever a mixture is created at the default temperature and gas near TCMB is merged into it. This was not searched for and nothing else was changed.
