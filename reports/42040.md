# #42040: Delivery chutes swallow ridden vehicles and leave the rider behind

| | |
|---|---|
| Issues | [#42040](https://github.com/tgstation/tgstation/issues/42040): verified |
| Status | Verified and fixed |
| Fix branch | [fix/42040](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/42040) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a ridden vehicle or chair bumps a delivery chute, the chute moves the vehicle inside and flushes it, but the buckled rider stays on the floor, still buckled to something that no longer exists there. `delivery_chute/Bumped()` calls `forceMove()` on the vehicle alone, and buckled mobs only follow an object in `Move()`, which cannot succeed here because the chute is dense. The fix makes the chute ignore anything that has riders, and any mob that is itself buckled, which matches what the disposal bin already does.

## The bug

The issue reports that vehicles "pretend to go into delivery chutes but will not actually do so": the rider is not unbuckled, and when the rider moves, the vehicle reappears under them, so the rider cannot enter the chute themselves. A comment on the issue adds a video in which the reporter could not move at all after the chair went in.

What happens in the code is that the vehicle really is moved into the chute and flushed. The rider is not carried with it. They remain on the floor tile they were on, with `buckled` still pointing at the vehicle, which is now inside the chute or already sent down the pipes.

## Reproduction

Reproduced on master with the Lua editor from an observer. This exercised the same code path a rider uses when driving into the chute (the vehicle's `Move()` hits the dense chute, which calls `Bumped()`), but the move was triggered by calling `Move()` on the chair from Lua rather than by a player driving it.

1. Using the Lua editor, spawn a `/obj/machinery/disposal/delivery_chute` on a floor tile and set its `dir` to NORTH.
2. On the tile directly north of the chute, spawn an `/obj/structure/chair/office` and a `/mob/living/carbon/human`, and buckle the human to the chair with `buckle_mob()`.
3. Call `chair:Move(<chute turf>, SOUTH)`, which moves the chair toward the chute from its input side, as a rider steering it would.
4. Read back the locations.

Observed before the fix:

- `chair.loc` was the delivery chute.
- The human's `loc` was the floor tile, and `h.buckled` was still the office chair.
- `Move()` returned 0, so `handle_buckled_mob_movement()` did not run for the chair.
- The chute played its flush animation and sent the chair away, leaving the rider buckled to nothing nearby. This matches the report.

## Cause

`code/modules/recycling/disposal/bin.dm:716`, `/obj/machinery/disposal/delivery_chute/Bumped(atom/movable/AM)`, checks only `QDELETED(AM)` and `AM.CanEnterDisposals()` and then the direction. For objects it does this (line 735):

```dm
if(isobj(AM))
	var/obj/O = AM
	O.forceMove(src)
```

A vehicle or chair is an object, so it is moved into the chute directly. Mobs buckled to it are only moved along by `atom/movable/Move()` through `handle_buckled_mob_movement()` (`code/game/atoms_movable.dm:883`, `code/game/atoms_movable.dm:1476`). That path is not taken: the original `Move()` into the chute's turf had already failed because the chute is dense, which is why `Bumped()` was called, and `forceMove()` does not move buckled mobs. The result is a vehicle inside the chute and a rider left outside.

`CanEnterDisposals()` (`bin.dm:746`) only excludes projectiles, effects and mechs, so nothing else rejects a ridden vehicle. The disposal bin has an equivalent guard in its mob-loading checks (`bin.dm:215`, `if(target.buckled || target.has_buckled_mobs()) return FALSE`), but the chute's `Bumped()` never got it.

## Fix

One commit, "Fix issue 42040: delivery chutes no longer swallow vehicles with riders". In `delivery_chute/Bumped()`, right after the existing `CanEnterDisposals()` check, it returns early when:

- `AM.has_buckled_mobs()`, i.e. the thing being bumped has someone riding it (vehicles, chairs), or
- `AM` is a mob and its `buckled` var is set, i.e. the mob is itself buckled to something.

This is the same rule the bin already applies to mobs (`bin.dm:215`). The alternative of carrying the riders into the chute along with the vehicle was not tried. The chute would then have to handle mobs buckled to arbitrary objects, and the issue only asks that vehicles stop misbehaving.

## Verification

After rebuilding and restarting the test server, using the Lua editor:

- Two delivery chutes were set up facing north, each with an office chair on the input side. One chair had a buckled human. Both chairs were moved toward their chutes.
- The ridden chair stayed on the floor outside the chute. The rider stayed buckled to it, on the floor.
- The unridden chair went into the other chute and the flush animation played, so normal behavior is unchanged.
- No new runtimes appeared in the runtime log for that round.

Not checked: only the office chair was tested. Other ridden vehicles (scooters, wheelchairs, ATVs) reach the same `Bumped()` code but were not individually tested. A buckled mob bumping the chute directly (the second half of the guard) was not tested. The test used scripted `Move()` calls, not a player driving a vehicle into the chute.

## Notes

- With the fix, a rider driving into a chute is simply blocked, as with any dense object. The rider can still unbuckle and enter the chute on their own, which was impossible before because the vehicle kept reappearing.
- `Bumped()` is only used by the chute. No other code was changed.
