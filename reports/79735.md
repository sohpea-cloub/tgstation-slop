## Summary

The admin message for a reagent container splashing on a turf always read "splashed (thrown)", even when nothing was thrown. The fix prints "(thrown)" only when the splash came from a throw. The issue's main complaint, that a thrown bowl was attributed to a different player than the thrower, could not be reproduced: on master the thrower comes from the live throw, not from a stored previous holder. That part was judged from the code and not tested with a second handler.

## The bug

The reporter threw a bowl holding many reagents. The admin chat message named a different player (a disconnected one, `[DC]`) as the splasher and said "(thrown)", while the game and the thrower's own player log named the actual thrower. The disconnected player's log also contained the splash, with a location matching that player's mob instead of where the bowl landed. The bowl's hiddenprints listed three different players, the last being the real thrower.

## Reproduction

On the test server, using the Lua editor:

1. Spawn humans and a bowl containing water.
2. Throw the bowl at a turf with `throw_at(turf, 5, 1, bowl)`.
3. Call `bowl:splash_reagents(turf, human, false, false)` on a bowl for a splash that is not a throw.
4. Read the admin messages in chat.

Observed on master: the non-thrown splash was logged as `ADMIN LOG: *no key*/(Tel-Nor2) splashed (thrown) Water on the floor in Fore Primary Hallway (107,148,2)`. The "(thrown)" is wrong because no throw happened. The thrown case also reads "(thrown)", as it should.

The wrong-player attribution from the report did not appear in these runs, which only used one handler per bowl. The "handled by another mob first" case was not tested.

## Cause

`splash_reagents` in `code/modules/reagents/reagent_containers.dm` logs the splash twice. The `log_combat` line (`:264`) already uses `was_thrown`:

```dm
log_combat(splasher, target, "splashed [english_list(reagents.reagent_list)]", src, "in [AREACOORD(target)] [was_thrown ? "(thrown)" : ""]")
message_admins("[ADMIN_LOOKUPFLW(splasher)] splashed (thrown) [english_list(reagents.reagent_list)] on [target] in [ADMIN_VERBOSEJMP(target)].")
```

The `message_admins` line (`:265`) had the text "(thrown)" written in and ignored `was_thrown`.

For the attribution: `throw_impact` (`:226`) passes `throwingdatum?.get_thrower()` as the splasher, and `get_thrower()` (`code/controllers/subsystem/throwing.dm:131`) resolves the thrower stored in the throw itself. No hiddenprints or fingerprints are consulted. A bowl that other mobs touched first should therefore still be attributed to the actual thrower on current master. The report was made with an older client version and a testmerge, so the stale-thrower behaviour may have come from code that is no longer present; this was not checked further.

## Fix

One commit, "Fix issue 79735: admin log only says (thrown) for thrown splashes". It changes the `message_admins` line to `splashed [was_thrown ? "(thrown) " : ""][english_list(...)]`, so it agrees with the `log_combat` line above it. No change to who is named.

## Verification

With the same two calls (thrown and non-thrown) after the fix, using a different spawned human as the handler:

- Non-thrown: `ADMIN LOG: ... (Tel-NorB) splashed Water on the floor in Central Primary Hallway (110,144,2)`
- Thrown: `ADMIN LOG: ... (Tel-NorB) splashed (thrown) Water on the floor ...`

Not checked: a bowl handled by several mobs before being thrown (the wrong-attribution scenario itself), and the reporter's disconnected-player log entries.

## Notes

- The reporter's observation that the splash was also written to a disconnected player's log, at that player's location, is not explained by anything found. It is consistent with the old stale-thrower attribution, but that was not confirmed.
- Side finding, not changed: a bowl thrown at a non-turf, non-mob object (an airlock was tried) logs nothing, because the logging is inside an `isturf(target)` check (`reagent_containers.dm:263`).
