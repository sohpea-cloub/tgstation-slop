## Summary

`/mob/proc/PossessByPlayer` assigned only `mob.ckey`. That leaves `mob.key` as the lowercase, hyphen-free ckey, and `key_name()` prints `mob.key`, so every mob a player was moved into logged as `testplayer/(...)` instead of `Test-Player/(...)`. The fix makes `PossessByPlayer` copy the real key from the connected client's entry in `GLOB.directory`. It also routes the remaining direct `mob.ckey =` assignments through that proc.

## The bug

The issue reporter saw their logs switch from `Decker-5` to `decker5` once their character died and they became a golem. Before that, logins and lobby-mob entries used the real key. After it, SAY lines, ownership lines and explosion "last fingerprints" lines used the ckey form. Any player with a hyphen, capital letter or other character that `ckey()` strips was affected. The same mismatch appeared again in a later round for the same player.

## Reproduction

The test server ran the default map, with a hyphenated key (`Test-Player`) as the only client. The trigger was a direct call to `PossessByPlayer`, not the golem-shell path from the issue.

1. Start the round with the Start Now admin verb, then observe.
2. Open the Lua editor, create a state and run:
   ```lua
   local SS13 = require('SS13')
   local me = SS13.get_runner_client().mob
   local h = SS13.new('/mob/living/carbon/human', me.loc)
   h:PossessByPlayer(me.ckey)
   ```
3. Read the round's `game.log`.

Observed on master:

- The lobby mob logged `Test-Player/(Test-Player)`.
- Observing already logged `Mob Login: testplayer/(ghost) was assigned to a /mob/dead/observer`.
- The new human logged `testplayer/(Autumn Isemann) ... has taken ownership`.

The first line matches the issue's `Decker-5` to `decker5` change.

## Cause

`PossessByPlayer` (`code/modules/mob/mob.dm:113-121`) ends with:

```dm
src.ckey = ckey(ckey)
```

Setting a mob's `ckey` in BYOND links the client but leaves the mob's `key` var as the ckey value. `key_name()` for a mob reads `M.key` (`code/__HELPERS/logging/_logging.dm:178`). That is how the log line becomes `testplayer`.

This is what AnturK described in the issue comments. The ckey is normalized, but the key is never set. Every `PossessByPlayer` caller goes through this path. That includes ghostize and body transfer, golem shells and mob spawners, `transfer_to`, and admin verbs.

Several places skip the proc and assign `mob.ckey =` directly, with the same effect:

- the two assignments in `code/datums/brain_damage/split_personality.dm`
- the admin Give Direct Control verb in `code/modules/admin/verbs/debug.dm`
- the two crossbreeding status effects in `code/modules/research/xenobiology/crossbreeding/_status_effects.dm`
- `code/modules/capture_the_flag/ctf_game.dm`
- the two assignments in `code/modules/antagonists/_common/antag_spawner.dm`
- `code/modules/shuttle/shuttle_events/player_controlled.dm`
- the send-to-lobby topic in `code/modules/admin/topic.dm`

## Fix

One commit: "Fix issue 72747: PossessByPlayer keeps the client's real key so logs show hyphens".

- `PossessByPlayer` normalizes the ckey, then looks up `GLOB.directory[ckey]`. If that client is connected, it sets `src.key = target_client.key` and returns. Otherwise it falls back to `src.ckey = ckey`.
- The ten direct `mob.ckey =` assignments listed above now call `PossessByPlayer`, so they get the same behavior. In total the commit touches 8 files (+19/-11).

No alternatives were recorded. Fixing the shared proc covers every caller that already uses it; the direct assignments needed converting separately.

## Verification

After rebuilding, the same Lua steps on the test server logged `Mob Login: Test-Player/(ghost)` and `Test-Player/(Kaitlyn Best) ... has taken ownership`. The runtime log had no new runtimes.

Not checked:

- The converted direct-assignment call sites (split personality, Give Direct Control, crossbreeding effects, CTF, antag spawners, shuttle event, send-to-lobby) were not exercised in game. Those edits are mechanical.
- The golem-shell path from the issue was not run.
- A target who is not connected (no client). That case still takes the ckey fallback and would still log the ckey form.

## Notes

- `PossessByPlayer` is core possession code, and the change touches 8 files, so it deserves a careful review.
- The fix changes behavior only when a client for that ckey exists in `GLOB.directory`. For disconnected targets, `key` stays the ckey, as before.
- The send-to-lobby topic previously assigned the new lobby mob's ckey directly. It now goes through the proc and so also sets the key.
