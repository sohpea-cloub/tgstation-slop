## Summary

The Radioactive Resonance virus symptom heals toxin damage, and the irradiated component deletes itself as soon as toxin damage reaches 0. A carrier was therefore de-irradiated within seconds, which stopped the symptom from working. The fix removes the toxin healing and leaves the brute and burn healing. #89671 (curing HARS leaves the character eyeless) could not be reproduced on master.

## The bug

### #72629

A player with the Radioactive Resonance symptom who got irradiated (radiation from HFR, the supermatter or tritium fires) stayed irradiated only briefly. The symptom only heals while the host is irradiated, but its own toxin healing brought toxin damage to 0 and ended the irradiation. A maintainer confirmed in the issue that this was not intended.

### #89671

The report says curing HARS (the "headless" mutation) leaves the character looking eyeless. The reporter said it happens consistently after adding and then removing HARS with View Variables, and that it also happened in a real round. Another contributor could not reproduce it.

## Reproduction

### #72629 (reproduced on master)

1. Using the Lua editor on the test server, create a human.
2. Create an advanced disease with only the Radioactive Resonance symptom (`/datum/symptom/heal/radiation`), refresh it, force the human to contract it, and set the disease stage to 5.
3. Irradiate the human (`SSradiation.irradiate`).
4. Wait about 15 seconds.

Observed: toxin damage was 0 and the irradiated component was gone.

The Lua steps stand in for the player route, where the host catches the disease and is irradiated by a radiation source. The disease and the irradiation were applied directly.

### #89671 (not reproduced)

On master, HARS was added and removed with the DNA `add_mutation` / `remove_mutation` calls from Lua, using the `activated` source. This is equivalent to a View Variables add and remove, but the View Variables dropdown itself was not used.

- NPC human: after the cure, the eyes organ was present, `get_eye_overlays()` returned 6 overlays, and the set eye colours were preserved.
- Human controlled by a client: before HARS the mob had the `eyes_l` and `eyes_r` overlays in its eye colour. During HARS they were gone, which is expected since HARS makes the character blind. After the cure the character's appearance listing showed the head, both eye overlays in the original colour, and the Blind alert was cleared. No runtimes were logged.

## Cause

### #72629

`/datum/symptom/heal/radiation/Heal()` in `code/datums/diseases/advance/symptoms/heal.dm:593-603` healed toxins as well as brute and burn:

```
needs_update += carbon_host.adjust_tox_loss(-2 * heal_amt, updating_health = FALSE)
```

`code/datums/components/irradiated.dm:88-89` ends irradiation when toxin damage reaches 0:

```
if (human_parent.get_tox_loss() == 0)
	qdel(src)
```

The symptom's `CanHeal()` (`heal.dm:589`) only runs while the host has `TRAIT_IRRADIATED`. The symptom therefore removed the condition it needs, usually within seconds.

### #89671

Not applicable (not reproduced). Code inspected: `/datum/mutation/headless` is at `code/datums/mutations/body.dm:531`. In `on_losing()` it regenerates the head and then the other organs with `replace_current = FALSE`, so existing organs are kept. The eye overlays come from `get_eye_overlays()` in `code/modules/surgery/bodyparts/head_hair_and_lips.dm`.

## Fix

One commit, "Fix issue 72629: Radioactive Resonance no longer cures its own irradiation", changing `heal.dm`. `Heal()` no longer calls `adjust_tox_loss()`. It still heals brute and burn through `heal_overall_damage()` and only calls `updatehealth()` if that healed something. A comment in the code explains why toxins are not healed.

An alternative was considered and rejected: healing toxins but never below 1, so the host would stay irradiated forever. That would make irradiation permanent for carriers.

## Verification

After rebuilding, the same Lua setup was run on the test server (host with brute damage, symptom at stage 5, irradiated). After 30 seconds, toxin damage was 12, brute damage had gone from 30 to 15, and the irradiated component was still present.

Not checked: behaviour with the Resistance 7 power level (`power = 2`), other host types, or a real radiation source rather than a direct irradiate call.

## Notes

- This is a balance change. The symptom no longer heals toxins at all, and maintainers should decide whether that is acceptable or whether another way of keeping the toxin healing is wanted.
- The issue mentions that older versions let rad resonance heal without ending irradiation; the inputs do not say when this changed, and that was not investigated.
- #89671 was filed in February 2025, and the reporter said in June 2025 that they did not know whether it still happened. It may have been fixed since, or it may depend on something not tried: other species, eye damage, glasses, the View Variables dropdown, or an actual Dream Seeker render of the sprite. The in-round case from the report was not recreated.
