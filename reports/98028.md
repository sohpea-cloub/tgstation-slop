# #98028: Lobby menu keeps showing admin-only ready counts after you deadmin

| Status | Fixed on the branch; checked at the level of the messages the server sends to the lobby menu, not on the rendered screen |

## Summary

The new lobby menu shows admins two extra lines on its TV: how many players are ready, and how many admins are ready out of the total. Non-admins get a shorter text. Whether to show the admin lines is decided from an `isAdmin` flag that the server sent only once, in the menu's initial message, so deadminning in the lobby (or readminning) never changed it. The server also sent the ready and admin counts to every player in every update. The fix sends `isAdmin` with each update and sends zeros for the counts to anyone who is not an admin.

## The bug

An admin who uses the Deadmin verb while in the lobby keeps seeing "N players ready" and "X / Y admins ready" on the lobby TV, which normal players do not see. #98030 notes that this used to go away on deadmin and no longer does. #98028 describes the same thing.

## Reproduction

On a test server running master, in the pre-game lobby, using the local (admin) client:

1. Connect to the lobby. The lobby menu's initial message has `isAdmin` set, and `adminCount` is 1.
2. Run the Deadmin verb. The game replies "You are now a normal player."
3. Read the messages the lobby menu window has received since.

Observed on master: the lobby menu only ever received its initial message, with `isAdmin` = 1 and `adminCount` = 1. No message afterwards changed `isAdmin`. The TV code in `tgui/packages/tgui-lobby/LobbyMenu.tsx:466` (`else if (ss.isAdmin)`) therefore keeps choosing the admin lines (`readyCount`, `adminReadyCount / adminCount`) from the state it received at init.

The tool used here could not run the menu's JavaScript or render it, so the on-screen text was not looked at; the conclusion rests on the messages sent and the TypeScript that consumes them.

## Cause

`/datum/lobby_menu` (`code/modules/lobby_menu/lobby_menu.dm`):

- `send_init()` (`:224`) sends `"isAdmin" = !isnull(client?.holder)` (`:243`) once, when the menu is created or asked to re-init.
- `process()` (`:120`) runs every second and calls `send_update()` with the countdown, player count, and the ready and admin counts, but not `isAdmin`. The client keeps `isAdmin` from the init payload for its whole life.
- The ready and admin counts (`readyCount`, `adminReadyCount`, `adminCount`) are sent unconditionally, in `process()` (`:124-126`) and in `send_init()` (`:238-240`), so a non-admin client receives them too; only the front end hides them.

## Fix

One commit, "Fix issue 98028: lobby menu keeps showing admin ready counts after deadmin", in `lobby_menu.dm`:

- `process()` computes `is_admin = !isnull(client?.holder)` each tick and sends it as `"isAdmin"` in the update. The menu's state reducer for `serverUpdate` takes a partial state and merges it (`LobbyMenu.tsx`, the `serverUpdate` case), so no front-end change was needed.
- `readyCount`, `adminReadyCount` and `adminCount` are sent as 0 unless `is_admin`, in both `process()` and `send_init()`. So non-admin clients no longer receive these numbers at all.

Making the client re-request `init` on deadmin was not done: sending one flag per tick is simpler and also covers readmin.

## Verification

After rebuilding and starting the server, the local client ran Deadmin in the lobby. The lobby menu's state messages then carried `isAdmin` = 0, `readyCount` = 0, `adminReadyCount` = 0 and `adminCount` = 0, which makes the TV fall back to the non-admin text (countdown and player count).

Not checked:

- The rendered lobby TV, in a real client.
- Readminning in the lobby. By the same code `isAdmin` should flip back to 1 on the next tick and the real counts should return, but this was not tested.
- Non-zero counts: no player was readied in the test, so the ready counts were 0 before and after. The zeroing for non-admins was therefore confirmed only through `adminCount`, which went from 1 to 0.
- Admin ranks with partial permissions, and clients that have no `holder` for other reasons.

## Notes

- Sending zeros to non-admins hides the numbers from their clients rather than just from the UI, which is the stricter reading of "leaks admin info". If a non-admin client is later expected to show these counts, that would need the front end and server to change together.
- The `isAdmin` flag is now refreshed once a second, with the other update fields. If a faster response to Deadmin and Readmin is wanted, the admin verbs could ask the lobby menu to resend, but that was not tried.
- #98030 was closed as a duplicate by the maintainer in its own comments; it adds a screenshot of the ready lines.
