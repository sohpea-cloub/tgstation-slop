# #57213: Announcement Intern replaces round-important antagonist announcements

| | |
|---|---|
| Issues | [#57213](https://github.com/tgstation/tgstation/issues/57213): verified, fixed |
| Status | Fixed (one commit on the fix branch) |
| Fix branch | [fix/57213](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/57213) |

## Summary

The "Announcement Intern" station trait replaces the text of every priority announcement with "Please stand by for an important message from our new intern" unless the caller passes `has_important_message = TRUE`. Several announcements that tell the crew about round-deciding events never passed it, so with the trait active the crew could not read them. The fix passes the flag for the revolution "heads win" announcement, both nuclear off-station detonation announcements, the two blob endgame announcements and the heretic ascension announcement. Only the revolution path was exercised in game.

## The bug

With the Announcement Intern trait, the announcer's custom alert message stands in for the real announcement text. That is intended for routine announcements, but the flag exists to protect messages that are "critical to the game". The issue reporter noted that a revolution ending is one of these: players who were not revolutionaries would not know whether revolutionaries were still around after the heads of staff died. Under the trait, the crew only saw the intern's stand-by line, and never the actual text.

## Reproduction

On the test server, on master:

1. Start a round (observing is enough) and open the Lua editor.
2. Switch the announcer to the intern and make the revolution handler declare that the heads of staff won:
   ```lua
   local SS13 = require('SS13')
   dm.global_vars.SSstation.announcer = SS13.new('/datum/centcom_announcer/intern')
   local h = SS13.new('/datum/revolution_handler')
   h:declare_heads_win()
   ```
3. Read the chat.

Observed on master: the announcement under the "Loyalty Monitoring Division" sender contained only "Please stand by for an important message from our new intern." The real text was not shown.

This reproduces the announcement by calling `declare_heads_win()` directly. It does not play out a revolution with real revolutionaries. The announcer was swapped through Lua rather than by rolling the station trait, but the trait only sets `SSstation.announcer` to the same datum type (`code/datums/station_traits/neutral_traits.dm:138-140`).

## Cause

`priority_announce()` in `code/__HELPERS/priority_announce.dm` takes a `has_important_message` argument (documented at line 35). At line 75 it picks the text:

```dm
if(SSstation.announcer.custom_alert_message && !has_important_message)
	announcement_strings += MAJOR_ANNOUNCEMENT_TEXT(SSstation.announcer.custom_alert_message)
else
	announcement_strings += MAJOR_ANNOUNCEMENT_TEXT(text)
```

The intern announcer sets `custom_alert_message` to the stand-by line (`code/datums/announcers/intern_announcer.dm:46`). Some callers already pass `has_important_message = TRUE` (for example the captain and Syndicate messages in `code/datums/communications.dm:51-53`), but these announcements did not:

- `code/modules/antagonists/revolution/revolution_handler.dm:111`, the "mutiny has been quelled" message sent by `declare_heads_win()`.
- `code/modules/antagonists/nukeop/equipment/nuclear_bomb/_nuclear_bomb.dm:707` and `:721`, the detonation results for a Syndicate base hit and for an off-station detonation.
- `code/modules/antagonists/blob/overmind.dm:201` (critical mass reached) and `:231` (emergency countermeasures activated).
- `code/modules/antagonists/heretic/heretic_knowledge.dm:835`, the ascension announcement.

## Fix

One commit, "Fix issue 57213: round-important antagonist announcements ignore the intern announcer's replacement text". It adds `has_important_message = TRUE` to the six `priority_announce()` calls listed above (the revolution heads-win, the two nuke results, the two blob messages, the heretic ascension). Each is a one-argument change, using the mechanism the proc already provides. No change to `priority_announce()` or to the trait itself.

## Verification

After rebuilding and restarting the test server, the same Lua snippet was run. The chat showed the real text ("It appears the mutiny has been quelled. Please return yourself and your incapacitated colleagues to work. We have remotely blacklisted the head revolutionaries in your medical records to prevent accidental revival.") under the Loyalty Monitoring Division header, and the intern's alert sound played. The build compiled without errors.

Not checked in game: the nuke, blob and heretic announcements. They use the same flag in the same way, but none of them was triggered after the change.

## Notes

- `declare_revs_win()` (`code/modules/antagonists/revolution/revolution_handler.dm:70`) makes no announcement at all, with or without the trait. A revolutionary victory therefore still has no crew-wide message. This was not changed: it is a gap in the revolution code, not in the intern trait.
- The fix is a list of specific callers. Other announcements that arguably mark round-ending events were left alone: the malfunctioning AI doomsday announcement (which uses its own announcer), wizard finale announcements and dynamic ruleset events. A maintainer may want a different policy for which of these count as "important".
- The issue text is short and mentions revolutions specifically, so the other callers were fixed on the same reasoning rather than on the issue's request.
