# #90718: Two-headed monkey (and apparently dwarfs)

| | |
|---|---|
| Issues | [#90718](https://github.com/tgstation/tgstation/issues/90718): not reproduced |
| Status | Not reproduced on master; a suspect code path is described below but was not shown to fail |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The issue reports that after a monkey, or a human with the dwarf mutation, is buckled to a guillotine and unbuckled, the character shows two heads, and that humanoids get broken underwear overlays. On master `87b93338` neither could be reproduced: after unbuckling, the overlay list matched a never-buckled control and held exactly one head. The guillotine code draws the head with raw overlays that are removed by value match later, which is fragile and could produce a duplicate head, but no variation tried made it do so. No fix was written.

## The bug

As reported (April 2025, client 516.1659, with two test merges active in that round): buckle someone to the guillotine and unbuckle them. Afterwards monkeys have two heads, humanoids have broken underwear overlays, and humans with the dwarf mutation also have two heads. The reporter's screenshots were not available to this investigation, so the exact look of the problem is unknown.

## Reproduction

Not reproduced. Using admin tools on the test server:

1. Spawned a guillotine, monkeys, and human dwarfs (`TRAIT_DWARF`, height 6). The humans wore boxers, a jumpsuit, a hard hat and a gas mask, and were tried both standing and lying.
2. Using the Lua editor, called `buckle_mob(M, TRUE, FALSE)` on the guillotine, then `unbuckle_all_mobs()`.
3. Compared each mob's overlays (via `inspect`) with a control mob of the same kind that had never been buckled.

Results:

- Plain buckle then unbuckle, for a monkey and a dwarf: overlays identical to the control, head present once.
- `update_body(TRUE)` called while buckled: same result.
- While buckled, removed the dwarf trait and ran `update_mob_height` (height 6 became 12, so the head's height filter and offset changed), then unbuckled: the overlay count was 32 before and after, and exactly one `human_head_m` overlay was present.
- While buckled, set the head's `lip_style` and `lip_color`, called `update_body(TRUE)`, and called `set_species` with the same species type, then unbuckled: same result, 32 overlays and one head.
- The only difference from a never-buckled mob was that the layer value was 3.9999997 instead of 4, from floating point drift in the guillotine's `layer` adjustment. This has no visible effect.
- In the overlay lists, `l_leg` and `r_leg` appeared twice in both the tested and control mobs, which is normal bodypart layering.

All of this was done by calling the buckle and unbuckle procs from Lua. The player click path (a real client using the unbuckle action) was not tried, and neither was a head changed by surgery or limb replacement while buckled, or other species and mutations on top of monkey or dwarf.

## Cause

No cause was demonstrated. The following is a code-reading hypothesis only.

`post_buckle_mob()` in `code/game/objects/structures/guillotine.dm:237` calls `render_only_head()` (`code/modules/mob/living/carbon/human/human_update_icons.dm:761`) on human victims. That proc does `cut_overlays()` and then `add_overlay(my_head.get_limb_icon())`. These are raw overlays added directly to the mob, outside the `overlays_standing` list that the normal icon update manages.

`post_unbuckle_mob()` (`guillotine.dm:262`) only calls `M.regenerate_icons()`. The head overlay is removed indirectly: the bodypart update path does `remove_overlay(BODYPARTS_LAYER)` and a `cut_overlay()` that must match the raw head overlay by value. If the head's appearance at unbuckle time differs from the one added at buckle time, that match fails and the old head stays next to the new one, which would look like two heads. In every variation tried the removal still worked, so the match held, and it is not known what extra condition the reporter's round had.

A related note: `cut_overlays()` in `render_only_head()` leaves stale entries in `overlays_standing` (for example underwear on `BODY_LAYER`). Calling `update_body` while buckled re-adds underwear to the head-only body. That is cosmetic and could be related to the "bugged unders" part of the report, but it was not observed to persist after unbuckling.

## Fix

None. No commits were made. A defensive change was considered but not written: keep the raw head overlays in a variable on the mob and `cut_overlay()` them explicitly in `post_unbuckle_mob()` before `regenerate_icons()`, or put the head into `overlays_standing[BODYPARTS_LAYER]` through `apply_overlay` and `remove_overlay` so that `regenerate_icons()` always removes it.

## Verification

Nothing to verify, since no change was made. The negative results above are the evidence.

Not checked: a real player unbuckling by clicking; the humanoid underwear case as the reporter saw it; the reporter's exact test merges (CatwalkStation and a storage rework), which could have changed icon handling in that round.

## Notes

- The report dates from April 2025 and was made with test merges applied. Later icon refactors on master may have fixed it, or the test merges may have caused it. This cannot be told apart from the evidence here.
- Suggested handling: keep the issue open only if someone can reproduce it on current master; otherwise the defensive change above is the cheapest hardening.
