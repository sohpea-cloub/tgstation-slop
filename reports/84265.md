# #84265: Removing your own mind magnification helmet leaves a held-item sprite on the monkey

| | |
|---|---|
| Issues | [#84265](https://github.com/tgstation/tgstation/issues/84265): verified, fixed |
| Status | Verified on the test server; fixed on the fix branch |
| Fix branch | [fix/84265](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/84265) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a mind-magnified monkey takes off its own helmet, the helmet deletes itself in `dropped()`, but the monkey keeps a held-item overlay (`monkeymind2up`) for it with nothing in its hands. `put_in_hand()` rebuilds the hand overlays before it notices that the item was deleted, then clears the hand slot without rebuilding them. The fix refreshes the held-item overlays in that deleted-item branch.

## The bug

A monkey that became sentient through the mind magnification helmet removes the helmet from its head slot. The helmet vanishes (the "flicker of sentience ripped away" message is shown), but other players looking at the monkey, or the monkey's own sprite, still show it holding a helmet. The inventory shows empty hands.

## Reproduction

The helmet was put on by an admin-style setup and the monkey was taken over through the normal ghost poll; the removal itself was done by clicking in the HUD, as a player would.

1. Start the round on the test server and become an observer.
2. In the Lua editor, spawn a monkey and a `/obj/item/clothing/head/helmet/monkey_sentience`, and equip the helmet on the monkey's head slot (slot 64). In the test this was done from a timer, since the helmet's equip code sleeps for the ghost poll.
3. Sign up to the ghost poll and take control of the monkey.
4. Open the HUD's inventory toggle and click the helmet in the head slot with an empty active hand, which takes it off into the hand.

Observed on master: the chat showed the "flicker of sentience ripped away" message and the helmet was gone, yet the monkey's overlays still contained `monkeymind2up`. Through the Lua editor, the monkey's `head` was nil and every entry of `held_items` was nil. Calling `update_held_items()` on the monkey by hand removed the overlay, which showed that the stale overlay was the one built by the held-item code.

## Cause

`put_in_hand()` in `code/modules/mob/inventory.dm` (master, lines 238-260) does, in this order:

```dm
	held_items[hand_index] = I
	...
	if(!has_equipped(I, ITEM_SLOT_HANDS, initial = visuals_only))
		return FALSE
	update_held_items()
	...
	if(QDELETED(I))
		held_items[hand_index] = null
		return FALSE
```

The helmet's `dropped()` (`code/modules/clothing/head/mind_monkey_helmet.dm:139`, with the `qdel(src)` at line 142) deletes it during the unequip. By the time `update_held_items()` runs, the item is already deleted, so the hand overlay is built for the deleted item. The `QDELETED(I)` check then sets `held_items[hand_index]` to null and returns without refreshing the overlay, so the old overlay stays until something else triggers a refresh.

## Fix

One commit, "Fix issue 84265: clear the stale held-item overlay when an item deletes itself as it is put in hand". It adds one line to the `QDELETED(I)` branch in `put_in_hand()`:

```dm
		held_items[hand_index] = null
		update_held_items() // the overlay built above still shows the deleted item
		return FALSE
```

The branch is the only place that knows the slot was cleared after the overlay was built, so the refresh goes there. Moving the `QDELETED` check before `update_held_items()` was not tried; it would change the order that `has_equipped()` and the overlay update run in for every item.

## Verification

The same steps were repeated after rebuilding and restarting the test server with the fix. After the helmet was removed through the HUD, the monkey's overlay list had no `monkeymind` entry. The monkey's inventory still worked normally in the same session.

Not checked: other items that delete themselves when put in a hand (the code comment names slappers and circle hands), human mobs, and an observer's view of the sprite from another client; the check was of the monkey's overlay list.

## Notes

- Any item whose `dropped()` or equip handling deletes it while being moved into a hand hits the same path. The fix covers them all, but only the mind magnification helmet was tested.
- The existing comment on the `QDELETED(I)` check describes the same family of self-deleting items, which suggests the missing refresh was a latent issue for those too.
