| | |
|---|---|
| Issues | [#95117](https://github.com/tgstation/tgstation/issues/95117): verified, fixed |
| Status | Fixed on the branch and checked in game (via a Lua-driven status effect, not the spell UI) |

## Summary

When a shapechanged mob returns to its true form, `restore_caster()` moves the shape into nullspace before moving the real body out of it. The real body, and anything it carries such as the nuclear authentication disk, is briefly inside a mob with no turf. The disk's stationloving component reads that as "out of bounds" and relocates the disk. The fix adds a short-lived trait that the stationloving component honours, set only around that swap. Real nullspacing still relocates the disk.

## The bug

A player carrying the nuke disk in a backpack or pocket (not in hand, since a held disk is dropped on polymorph) polymorphs and then returns to their original form. The disk is no longer on them: it has been teleported to a random station location, and an admin log line says it was moved out of bounds.

## Reproduction

Done on the test server with the Lua editor. The shapechange status effect was applied and restored directly from Lua, not through the spell and its tgui path. Both run the same `restore_caster()` code.

1. Start a round and, as an observer admin, spawn a human and a cockroach together (at 107,144 on z-level 2 in this test).
2. Move a real nuke disk into the human's contents (`disk.forceMove(human)`).
3. Apply the shapechange status effect to the cockroach, with the human as the caster (`roach:apply_status_effect(/datum/status_effect/shapechange_mob, human)`), then call `status:restore_caster()`.

Observed before the fix: the disk's location afterwards was the floor at a different place (79,193 on z-level 2 in one run; a different random turf in the first run), not the human. The admin log read: "The nuclear authentication disk attempted to be moved out of bounds from Central Primary Hallway (107,144,2) to nonexistent location. Moving it to Prison Mess Hall (79,193,2)". It reproduced twice.

## Cause

`restore_caster()` in `code/modules/spells/spell_types/shapeshift/_shape_status.dm:83` does:

```
owner.moveToNullspace()
caster_mob.forceMove(former_loc) // This is to avoid crushing our former cockroach body
```

(lines 98-99). The real body (`caster_mob`) is stored inside the shape (`owner.contents`), so for a moment the disk is inside a mob that has no turf. `on_parent_moved()` in `code/datums/components/stationloving.dm:86` fires, `atom_in_bounds()` fails because there is no turf below ("No turf below us = nullspace = not in bounds", line 159), and `relocate()` moves the disk. The component cannot tell this momentary swap from a real banishment to nullspace.

## Fix

One commit, **"Fix issue 95117: nuke disk teleports away when its holder exits a shapechange"**:

- A new trait `TRAIT_STATIONLOVING_NULLSPACE_SAFE` (declared in `code/__DEFINES/traits/declarations.dm`, registered in `code/_globalvars/traits/_traits.dm`).
- `restore_caster()` adds the trait to `caster_mob`, with the status effect as the source, immediately before `owner.moveToNullspace()`, and removes it right after `caster_mob.forceMove(former_loc)`.
- In `on_parent_moved()`, if the parent has no turf and any container in `get_nested_locs(parent)` has the trait, the proc returns without relocating.

Why a trait rather than reordering the moves: the existing order exists to avoid crushing the former body (the comment says "to avoid crushing our former cockroach body"), so it was kept. The trait is scoped to the swap, so anything else that really puts a disk in nullspace is still relocated. Because the check is in the component, other stationloving objects are covered too.

## Verification

After rebuilding:

- Same Lua steps: the disk's location stayed the human (`/mob/living/carbon/human`), and no relocation admin log appeared.
- Safety net: with the disk inside a human, `human:moveToNullspace()` still relocated the disk. The admin log recorded the move, and the disk ended up in Transit Tube (176,135 on z-level 2).

Not checked:

- The real spell and tgui path (the status effect was driven from Lua).
- Other stationloving items. They share the component code, but no other item was tested.

## Notes

- The nullspace order in `restore_caster()` was kept because of its code comment (avoiding crushing the former body); reordering the moves was not tried.
- Only `restore_caster()` sets the trait.
