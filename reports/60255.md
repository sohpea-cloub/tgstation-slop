## Summary

**#60255:** the abductor outfit is equipped with `equip_to_slot_or_del`, so every outfit item whose slot is already occupied is deleted instead of being equipped. A clothed player made an abductor keeps their old gear and loses the abductor gear. The fix drops everything the player is wearing before the outfit is equipped.

**#82439:** the abductor omnitool's welder mode fails the generic fuel checks that welding tools override, and the blood filtration surgery only accepts the blood filter item, not the blood filter tool behaviour. The fix makes the omnitool's welder mode pass those checks and makes the surgery key on `TOOL_BLOODFILTER`.

The two issues share a branch because both are in the abductor code; they are otherwise unrelated.

## The bug

### #60255

An admin who makes a player who is already wearing clothes into an abductor (the issue uses the traitor panel, solo abductor) finds that the player lacks equipment after the teleport to the abductor ship. The items missing are the ones that belong in slots the player already had filled. A comment on the issue says this is the same for all antagonists except wizard, even nuclear operatives; that was not tested.

### #82439

Some tool modes of the abductor omnitool do nothing: the issue names the blood filter and the welding tool ("but not limited to"). Only those two were investigated.

## Reproduction

### #60255

1. On the test server, using the Lua editor, spawn a human and give it a full security outfit with `equipOutfit(/datum/outfit/job/security)`.
2. Give the human a mind and add the antagonist datum `/datum/antagonist/abductor/scientist/onemanteam` with a new `/datum/team/abductor_team` as its team. The team argument is required; without it, `on_gain` runtimes on a null `team.objectives`. This mirrors what the traitor panel does for a solo abductor; the traitor panel itself was not clicked.
3. Inspect the human's equipment. Before the fix every slot still held the security gear: uniform, boots, backpack, headset, belt, helmet, vest, and a disabler in the suit storage slot where the abductor baton should have been.

### #82439

Only the code path was read and then exercised by calling procs with the Lua editor; no real click on a target was made (see Verification).

1. Spawn an abductor omnitool and switch it to the welder mode.
2. The generic tool checks (`tool_use_check` and `use`) return `!amount` in the base item (`code/game/objects/items.dm:1269` and `:1273`), so any non-zero fuel amount fails. The welding tool overrides these; the omnitool did not.
3. Switch it to the blood filter mode. The blood filtration operation (`code/modules/surgery/operations/operation_filter.dm`) only accepted the item type `/obj/item/blood_filter`, so the omnitool was not valid for it. Before the fix `check_availability` was 0 for the omnitool by reading the code; this was not run against the unfixed build.

## Cause

### #60255

`code/modules/antagonists/abductor/abductor.dm:90-98` (`finalize_abductor()`) calls `new_abductor.equipOutfit(outfit)` without clearing the existing equipment. The outfit equips each item with the macro at `code/datums/outfit.dm:163`:

```dm
user.equip_to_slot_or_del(SSwardrobe.provide_type(##item_path, user), ##slot_name, TRUE, indirect_action = TRUE); \
```

`equip_to_slot_or_del` deletes the new item if it cannot be put in the slot. For an occupied slot, it cannot. So the abductor item is deleted and the old item stays.

### #82439

Two defects:

1. In welder mode the omnitool only sets `tool_behaviour`. Welding actions call `tool_use_check()` and `use()`, which in the base item (`code/game/objects/items.dm:1269`, `:1273`) fail for any non-zero amount. Welding tools override them to handle fuel (`code/game/objects/items/tools/weldingtool.dm`), but `/obj/item/abductor/alien_omnitool` (`code/modules/antagonists/abductor/equipment/gear/abductor_items.dm:650`) did not, so welding wordlessly failed.
2. `/datum/surgery_operation/limb/filter_blood` set `implements = list(/obj/item/blood_filter = 1)` (`operation_filter.dm:5`), and both `on_success` (`:34-36`) and `has_filterable_chems` (`:60-70`) cast the tool to `/obj/item/blood_filter` and read its `whitelist`. The omnitool is not that type, so the operation never offered itself to it, and the casting code could not work with it anyway.

## Fix

Two commits.

**"Fix issue 60255: abductor outfit missing items on already-clothed players"** adds a loop to `finalize_abductor()` before `equipOutfit`: every item from `get_equipped_items(INCLUDE_POCKETS)` is dropped with `dropItemToGround(worn_item, force = TRUE)`. Dropping rather than deleting means the player's old gear is on the floor under them and nothing is destroyed. Stripping the player before the outfit is applied matches what abductors expect (the issue notes that admins were otherwise told to strip the player through the traitor panel first).

**"Fix issue 82439: abductor omnitool welding and blood filter modes do nothing"**:

- In `abductor_items.dm`, the omnitool gets `tool_use_check()` and `use()` overrides that return `TRUE` when `tool_behaviour == TOOL_WELDER` and otherwise call the parent. The welder mode therefore needs no fuel and no ignition.
- In `operation_filter.dm`, `implements` is now `list(TOOL_BLOODFILTER = 1)`. A new `get_whitelist(tool)` proc returns the tool's `whitelist` if it is an `/obj/item/blood_filter` and null otherwise. `on_success` and `has_filterable_chems` use it; `has_filterable_chems` now takes a plain `obj/item`. A tool without a whitelist filters every chemical.

The alternative of making the omnitool a subtype or giving it a blood filter datum was not pursued; the issue thread notes the two items have many special properties (fuel, UI data), and the approach here touches only the checks that fail.

## Verification

### #60255

On the test server, repeating the reproduction steps after the fix: the human wore the alien jumpsuit, combat boots, backpack, alien headset, agent belt, headgear and vest, and held the advanced baton. The old security gear was on the floor under the human. The species was Abductor.

Not checked: the traitor panel button itself; other antagonists; the teleport to the ship (the abductor ship teleport did not happen when driven from Lua, because no ship console existed on the test map).

### #82439

Everything was done with Lua editor proc calls:

- Welder mode: `tool_start_check` returned 1, and `use_tool(..., amount 1)` returned 1.
- Blood filter mode: `filter_blood.check_availability` with a lying patient, a chest with `SKIN_OPEN` and the omnitool returned 1 (it was 0 before, from reading the code). A real blood filter also returned 1, and a crowbar 0. Calling `on_success` removed morphine from 20 to 15.6.

Not checked: a real click on a welding target (airlock, window, frame, etc.), a full surgery do_after loop with the omnitool (it sleeps and was avoided from Lua), and any other omnitool mode.

No runtimes came from the changes. The only warning seen was the expected recall-implant "no machinery for team" message, since there was no abductor ship console.

## Notes

- Welder mode does not heat or ignite anything (`get_temperature` was unchanged) and is not eye-damaging. Anything relying on a lit welder for heat will still not work with the omnitool.
- Other tool modes of the omnitool were not tested, so "a few tools" in the issue title may include more than these two.
- The #60255 comment says other antagonists with outfits behave the same way. The fix is in the abductor antagonist only; other roles that use `equipOutfit` on clothed players were not changed.
- Dropped items land on the player's tile. If the player is then teleported to the ship, the old gear stays behind where they stood.
