## Summary

A dead blobbernaut shows the goop "dead" sprite, but if a blob strain is applied to its corpse afterwards, `blob_minion/on_strain_updated` resets `icon_state` to the living sprite. The corpse then looks alive. The fix skips that reset for dead mobs and makes the blobbernaut override set the dead sprite explicitly. This is the only code path found that puts a living icon on a blobbernaut corpse, so it is the likely cause of the report, but the reporter's round was not seen.

## The bug

The issue has a screenshot and the single step "kill blobbernaut". The screenshot could not be viewed, so the description rests on the title: "Sometimes blobbernauts dont turn into goop on death". Killing a blobbernaut always produced the goop sprite in testing. That fits the report saying "sometimes": the bug needs a strain change on the corpse.

## Reproduction

This reproduces the sprite revert by calling the strain-change proc directly on a corpse. No real blob overmind was used.

1. Start a round on the test server, observe, and open the Lua editor.
2. Spawn a `/mob/living/basic/blob_minion/blobbernaut/independent` and a `/mob/living/basic/blob_minion/blobbernaut/minion`.
3. Call `death()` on each. Each took its dead icon (`blobbernaut_independent_dead` and `blobbernaut_dead`), as expected.
4. Get each one's `/datum/component/blob_minion` and call `strain_properties_changed(nil, strain)` with any blobstrain datum. This is what an overmind picking or changing a strain, or a blob mutation, does to every registered minion, and dead minions stay registered.
5. Read `icon_state` again. The `minion` blobbernaut's icon flipped from `blobbernaut_dead` to `blobbernaut`. The player's view also showed this: a nearby mob changed from `blobbernaut_dead` to `blobbernaut`.

Only the minion variant's before and after values were recorded in the notes. The independent variant should go through the same code, but no result for it was recorded.

## Cause

`/mob/living/basic/blob_minion/proc/on_strain_updated` in `code/modules/mob/living/basic/blob_minions/blob_mob.dm:46-50` resets the sprite with no stat check:

```dm
//revert independent blob mobs to the pale sprite so they can be recoloured
if(new_strain)
	icon_state = base_icon_state
```

`/mob/living/basic/blob_minion/blobbernaut/on_strain_updated` (`blobbernaut.dm:~66-86`) calls this through `..()` and then recomputes `icon_dead`/`icon_living`, but also does not consider the dead state. A dead blobbernaut stays in the overmind's list of mobs and keeps its strain signals (`code/datums/components/blob_minion.dm:50`, `strain_properties_changed` at line 62), so a later strain change reaches the corpse.

## Fix

One commit, "Fix issue 93797: dead blobbernauts revert to a living sprite when their blob strain changes":

- `blob_mob.dm`: the reset becomes `if(new_strain && stat != DEAD)`, so corpses keep their dead sprite.
- `blobbernaut.dm`: after `icon_dead` is recomputed, `if(stat == DEAD) icon_state = icon_dead`. This matters for an independent corpse, whose dead sprite name changes with the strain handling (`"[base_icon_state]_dead"`), so it gets the recolourable pale dead sprite.

## Verification

Before the fix, the revert was reproduced (see above). After the fix, nothing was run in game: the server was stopped after the commit. The planned check, repeating the script on both variants and confirming `icon_state` stays `*_dead`, was not done and the build was not run.

Not checked: a real overmind choosing or rerolling a strain, a blob mutation, and the reporter's scenario.

## Notes

- Not confirmed: the report may have a different cause. No other path that restores a living icon on a corpse was found.
- Plain death was never seen to fail, which matches "sometimes".
