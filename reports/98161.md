# #98161: Admin invisibility traits leak onto living mobs (stealth mode / invisimin)

| | |
|---|---|
| Issues | [#98161](https://github.com/tgstation/tgstation/issues/98161): verified, fixed. [#98158](https://github.com/tgstation/tgstation/issues/98158): verified, fixed |
| Status | Both fixed on the branch and checked in game |
| Fix branch | [fix/98161](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/98161) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Both bugs are in `code/modules/admin/admin_verbs.dm`, where admin-only traits end up on a living body and stay there. Turning on Stealth Mode inside a living mob put `TRAIT_ORBITING_FORBIDDEN` on that body, and turning it off later only cleaned the admin's current mob, so the body became permanently unobservable (#98161). AGhost copied invisimin to the ghost but left it on the body as well, so whoever controlled the body next inherited invisibility and the other invisimin effects, admin or not (#98158). The fixes limit the stealth trait to observers and strip the invisimin traits from the body when AGhost moves them to the ghost.

## #98161: stealth mode makes a living mob unobservable

### The bug

An admin who enables Stealth Mode while controlling a living mob, then ghosts out and turns Stealth Mode off, leaves the original body permanently impossible to orbit or observe.

### Reproduction

1. On the test server, start a round and observe. Using the Lua editor, spawn a human ("VictimA") and set its `ckey` to the admin's to take control.
2. Use Stealth Mode (enter a display name at the prompt), then AGhost, then turn Stealth Mode off.
3. Using Lua or View Variables, read the body's state.

Observed on master: `VictimA inv=0 alpha=255 traits=orbiting_forbidden`. The body was visible but still carried `TRAIT_ORBITING_FORBIDDEN` after stealth was off.

### Cause

`/client/proc/enable_stealth_mode()` (`code/modules/admin/admin_verbs.dm:209`) applies the visual changes only inside `if(isobserver(mob))`, but the trait and the orbiter clear were outside that block:

```
	ADD_TRAIT(mob, TRAIT_ORBITING_FORBIDDEN, STEALTH_MODE_TRAIT)
	QDEL_NULL(mob.orbiters)
```

(`admin_verbs.dm:221-222`). In a living body, the trait went on the body. AGhost then added another copy to the ghost (`admin_verbs.dm:57`), and `disable_stealth_mode()` removes the trait with `REMOVE_TRAIT(mob, TRAIT_ORBITING_FORBIDDEN, STEALTH_MODE_TRAIT)` (`admin_verbs.dm:242`) from the admin's current mob only, which was the ghost. The body kept the trait for good.

### Fix

Commit "Fix issue 98161: Stealth mode only applies orbit-forbidden to observers" moves the `ADD_TRAIT` and `QDEL_NULL(mob.orbiters)` lines into the existing `isobserver(mob)` block. Stealth mode inside a living body then adds nothing to it. AGhost already adds the trait to the ghost when stealth mode is active, so a ghost still cannot be orbited.

### Verification

After the fix (rebuilt, server restarted, same steps): `VictimA` had no traits (the list was empty). No new runtimes were seen.

Not checked: the case of enabling Stealth Mode in a living body and staying in it; with the change the body no longer gets the trait, so it is also not protected from orbiting, which is a consequence of this approach (see Notes).

## #98158: possessing an invisimin'd mob inherits invisimin

### The bug

If an admin with invisimin on uses AGhost out of a living body, the next controller of that body (a possessing player, no admin rights needed) has the invisimin effects too.

### Reproduction

1. On the test server, spawn a second human ("VictimB") and take control of it as above.
2. Use Invisimin, then AGhost.
3. Read the body's state with Lua or View Variables.

Observed on master: `VictimB inv=61 alpha=255 traits=invisimin,orbiting_forbidden,move_phasing,pierce_immunity,invisible_to_camera`. That is invisibility level 61 plus the invisimin traits left on the body. The possession itself by a non-admin was not played through; the state left on the body is what makes the inheritance happen, since the traits and invisibility belong to the mob.

### Cause

AGhost (`admin_verbs.dm:19`, the "Carry over invisimin to their aghost" block at line 44) adds `TRAIT_INVISIMIN` and the invisibility to the new ghost, but never removes them from the body. The body keeps invisimin's traits (`TRAIT_INVISIMIN`, `TRAIT_ORBITING_FORBIDDEN`, `TRAIT_MOVE_PHASING`, `TRAIT_PIERCEIMMUNE`, `TRAIT_INVISIBLE_TO_CAMERA`) and its invisibility, as well as the removal from the data HUDs.

### Fix

Commit "Fix issue 98158: Admin ghosting out of an invisimin'd body no longer leaves it invisimin'd" adds, inside AGhost after the carry-over, a block that runs when the admin was invisimin'd. It removes those five traits (source `ADMIN_TRAIT`) from the body, puts the body back on all human data HUDs, and removes the invisimin invisibility source. This mirrors the invisimin verb's own toggle-off code, so the body is returned to the state a normal toggle-off leaves it in.

### Verification

After the fix, with the same steps: `VictimB inv=0 alpha=255 traits=` (empty), and the invisibility of the body was seen to go from 61 to 0 as the admin ghosted out. No new runtimes.

Not checked: that the ghost itself still carries invisimin afterwards (that code path was left unchanged), and an actual non-admin possessing the cleaned body.

## Notes

- Invisimin applied to a living body that is never AGhosted is not covered: the admin toggles it off themselves, which was left as designed.
- #98158 only handles the invisimin path of AGhost. The stealth-mode carry-over adds its own trait to the ghost only, which #98161's fix covers.
- Design point for a maintainer: after the #98161 fix, an admin in stealth mode inside a living body can be orbited, because the orbit-forbidden trait is now observer-only. The issue text itself says the trait should be inside the observer check, so this was taken as intended.
