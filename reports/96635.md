# #96635: Gas flow meters can be stacked without limit on one pipe

| | |
|---|---|
| Issues | [#96635](https://github.com/tgstation/tgstation/issues/96635): verified and fixed |
| Status | Fixed |
| Fix branch | [fix/96635](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/96635) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Fastening a meter item to a pipe (wrench) or to the floor (screwdriver) never checked whether a meter was already there, so any number of gas flow meters could be built on one tile and layer. The fix adds a check, `meter_exists_on_layer()`, to both actions and refuses with a warning when a meter is already fastened on that tile and piping layer.

## The bug

The report says infinite gas flow meters can be placed in one spot, producing a large amount of lag and server load (it happened on a downstream server). Each meter is a machine that reads the pipe's gas, so stacking many of them multiplies that work on one tile.

## Reproduction

The test used the Lua editor to create the items and call the tool action directly, rather than a player building by hand. The Resource-Pipe-Dispenser (RPD) path was read in the code but not played.

1. Start a round on the test server and, using admin tools, spawn a pipe on a tile and a wrench.
2. Spawn five `/obj/item/pipe_meter` on the same tile.
3. In the Lua editor, call `wrench_act` on each meter with the wrench.
4. Observed on master: "You fasten the meter to the pipe." five times, and five "gas flow meter" objects on that tile.

## Cause

In `code/game/machinery/pipe/construction.dm`, `/obj/item/pipe_meter/wrench_act` (line 469) looks for a pipe on the tile whose `piping_layer` matches, and then creates `new /obj/machinery/meter(loc, piping_layer)` and deletes the item. `screwdriver_act` (line 484) does the same with `/obj/machinery/meter/turf`. Neither looks for an existing meter, so nothing limits how many are created.

The RPD builds meters through the same code: `code/game/objects/items/rcd/RPD.dm:549-553` creates a `/obj/item/pipe_meter` and calls its `wrench_act`, so it was affected as well.

## Fix

One commit, "Fix issue 96635: block stacking gas flow meters on one pipe layer":

- New proc `/obj/item/pipe_meter/meter_exists_on_layer()` loops over the contents of `loc` for an `/obj/machinery/meter` whose `target_layer` equals the item's `piping_layer`.
- `wrench_act` (after the "need a pipe" check) and `screwdriver_act` (after the floor check) return early with the warning "There is already a meter on this pipe layer!" if it returns TRUE. Because the RPD calls `wrench_act`, it is covered too.

The check is per layer, so meters on different layers of the same tile are still allowed, since a pipe tile can legitimately have a pipe on several layers.

## Verification

On the test server with the fix built, the same script gave one "You fasten the meter to the pipe." and then "There is already a meter on this pipe layer!" five times (four more wrench attempts and one screwdriver attempt for a floor meter). Only one meter object remained on the tile.

Not checked:
- A meter on a different layer being allowed: the attempted test used a spawned pipe that turned out to be on layer 3, not layer 5, so the test was invalid. Only same-layer blocking was observed.
- Building with a real RPD. From the code, a refused meter leaves the `pipe_meter` item on the floor (nothing is lost or duplicated), but this was not run.
- Maps or saved rounds that already contain stacked meters are not changed by this fix.

## Notes

- The wrench check requires a matching pipe, but the meter check looks only for another meter on the layer; a screwdriver-fastened (turf) meter and a pipe meter on the same layer also block each other.
