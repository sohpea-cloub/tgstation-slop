# #73384: Replica pods clone a player as their original character after they took a ghost role (and after suicide)

| | |
|---|---|

| Status | Fixed (one commit on the fix branch), checked in game |
| Fix branch | [fix/73384](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/73384) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A replica pod seed remembers the mind and ckey of the person whose blood was put into it. When the pod is harvested, `harvest()` looks for a connected player with that ckey and revives them as a podperson using the stored mind, without checking that the player still owns that mind. A player who died, then took a ghost role (and died again) could therefore be pulled back into the round as their original character. The same lookup checks `TRAIT_SUICIDED` on the player's current mob (a ghost) rather than on the original body, so players who suicided could also be podcloned. The fix requires the player's current mob to still hold the sampled mind and the original body not to be a suicide.

## The bug

Draw a player's blood into a replica pod, let that player die and take a ghost role, let them die again, then harvest the pod. The player is pulled out of their ghost-role death and returned to the round with their original name and mind, as a podperson. The issue reporter says this is not how it should work. A commenter on the issue adds that the same path lets suicided mobs be brought back, and another says the code only looks for a ghost with the player's ckey.

## Reproduction

On master (`87b93338`), using admin tools on the test server (the Lua editor, which also called the relevant procs directly):

1. Take a human with a player in control (mind M1). Put a blood sample from them into a `/obj/item/seeds/replicapod` planted in a hydroponics tray. The test added the blood to the seed's reagents with the human's blood data rather than using a syringe. The seed then held `mind = M1` and the player's ckey.
2. Kill the human and ghostize the player.
3. Spawn the player into a hermit ghost-role spawner (`create_from_ghost`). The new body gets a new mind, so the player's current mob no longer holds M1.
4. Kill the hermit and ghostize again.
5. Call the seed's `harvest()` with the ghost as the user.

Observed before the fix: the ghost's mind ("Jayson Priebe") differed from the seed's mind ("Podtest Alpha"), and the ghost had `can_reenter_corpse` set. Harvesting returned the message "you are now mob 'Podtest Alpha'" and the pod's limbs were created, so the player was cloned as the original character after having played the hermit.

The harvest was made by calling the proc rather than by a player doing it at the tray. Procs called through the Lua editor after a ghostize or possess in the same script failed ("WrapAdminProcCall with no ckey"), so the test used a separate script for each mob change.

## Cause

`/obj/item/seeds/replicapod/harvest()` in `code/modules/hydroponics/grown/replicapod.dm`:

- The ckey branch (`:119`-`:132`) walks `GLOB.player_list` and takes the first mob whose ckey equals the seed's:

  ```dm
  if (corpse.ckey != ckey || HAS_TRAIT(corpse, TRAIT_SUICIDED))
      continue
  ```

  It never checks that `corpse.mind` is still the sampled mind. The player's current mob is a ghost with a different mind, which qualifies if `can_reenter_corpse` is set. Later `mind.transfer_to(podman)` (`:193`) moves the old mind into the new podperson.
- The suicide check on `:122` reads the trait from the player's current mob. `TRAIT_SUICIDED` stays on the original body and is not on the ghost, so the check passes for someone who suicided.
- The mind-key branch (`:134`-`:152`), used when the player had ghosted before the blood was drawn, matched on `ckey(corpse.mind.key)` only and had the same two gaps.

## Fix

One commit, "Fix issue 73384: podclone only revives the player if they still own the sampled mind", in `harvest()`:

- Ckey branch: after the existing checks, `break` (no podman) if `corpse.mind != mind` or the sampled mind's original body (`mind.current`) has `TRAIT_SUICIDED`.
- Mind-key branch: also requires `corpse.mind == mind`, and skips the player if `mind.current` has `TRAIT_SUICIDED`.

Both checks are guarded on `mind.current` so a gibbed or deleted original body does not runtime. Without a podman the existing "devoid of soul" prompt and seed harvest happen as before.

## Verification

After rebuilding and restarting the test server, using the same Lua-based setup:

- Ghost-role case: harvest showed the "Harvest Seeds?" alert (pod devoid of soul); the player stayed a ghost and no podperson was created.
- Suicide case: the suicided trait was placed on the dead original body, with the player a ghost holding the same mind. Harvest gave the same "devoid of soul" alert and no podperson.
- Normal case: with the trait removed and the same body, ghost and mind, harvest worked: the player became "Podtest Beta" and the pod limbs appeared. Podcloning still works for a legitimate case.

Not checked: a gibbed or null original body (`mind.current` null) was only read through the code, not run. The flows were exercised by calling `harvest()` from Lua, not by a player harvesting at the tray with a syringe-drawn sample.

## Notes

- The mind check also covers other cases where the player has moved on (for example being cloned elsewhere), not just ghost roles.
- The mind-key branch got the same checks for consistency; only the ckey branch was run in the ghost-role test.
