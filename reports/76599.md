# #76599: Randomised tails sometimes get the blank "None" sprite accessory

|---|---|

| Status | Fixed |

## Summary

Tail organs that get a random appearance when created (admin-spawned, or dropped by gibbed mobs) sometimes ended up with the blank "None" sprite accessory as their `sprite_datum`, so they had no overlay. The shared `/datum/sprite_accessory/blank` entry inherited `natural_spawn = TRUE`, so the random pick treated it like any real accessory. The fix sets `natural_spawn = FALSE` on it.

## The bug

The report spawned 100 each of several tail subtypes and read each tail's `bodypart_overlay.sprite_datum`. For cat tails about half had the "None" accessory, and implanting one gave a human no visible tail. The reporter's counts for the other subtypes (monkey 9%, lizard and fake lizard 24%) no longer reproduce on current master, as described below.

## Reproduction

On master, with admin tools:

1. As an observer, open the Lua editor and spawn 100 each of `/obj/item/organ/tail/cat`, `/obj/item/organ/tail/monkey`, `/obj/item/organ/tail/lizard` and `/obj/item/organ/tail/lizard/fake`. Note that the type path is `/obj/item/organ/tail`, not the `/obj/item/organ/external/tail` of the original report.
2. For each tail, count how many have `bodypart_overlay.sprite_datum.name == "None"`.

Observed:
- Cat: 46 of 100 had "None".
- Monkey, lizard and fake lizard: 0 of 100. Their own "None" subtypes already have `natural_spawn = FALSE` (`code/datums/sprite_accessories/tails.dm:55` and `:89`).

The count was made by creating the organs and reading the variable, which exercises the same code the spawn path uses; no mob was gibbed and nothing was implanted.

## Cause

`/datum/sprite_accessory/blank` (`code/datums/sprite_accessories/_sprite_accessory.dm:54`) is the "None" entry that `init_sprite_accessory_subtypes()` adds when called with `add_blank = TRUE` (`code/controllers/subsystem/sprite_accessories.dm:149`). It did not set `natural_spawn`, so it inherited TRUE.

When an organ is created, `setup_bodypart_overlay` calls `randomize_appearance`, which calls `get_random_appearance()` (`code/datums/bodypart_overlays/mutant_bodypart_overlay.dm:75`). That proc skips accessories whose `natural_spawn` is FALSE and picks uniformly from the rest. The cat tail list contains the real "Cat" accessory and the blank, so the blank was picked about half the time (46/100 observed). The blank also overwrites any same-keyed "None" entry in the list, which is why the tails with their own `natural_spawn = FALSE` "None" subtype were unaffected.

## Fix

One commit, "Fix issue 76599: randomised tails no longer pick the blank "None" sprite accessory": it adds `natural_spawn = FALSE` to `/datum/sprite_accessory/blank`, with a comment. Other readers of `natural_spawn` are the hair and facial hair code, which use their own "None" entries, so they are unaffected.

## Verification

After rebuilding and restarting the test server, the same script gave 0 of 100 "None" for all four tail types (cat was 46/100 before).

Not checked: gibbing mobs, spawning through the Game Panel, and implanting tails in a human. The check sampled random appearances directly.

## Notes

- The reported monkey (9%) and lizard (24%) rates were not seen on master; those lists no longer include the blank.
- #76353 was mentioned in the issue as related. It was not examined.
