# #69537: Planted C4 vanishes without exploding when the object it is stuck to is deleted

| | |
|---|---|
| Issues | [#69537](https://github.com/tgstation/tgstation/issues/69537): verified (reproduced, then fixed) |
| Status | Fixed on the fix branch, verified in game for one case (stool picked up) |
| Fix branch | [fix/69537](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/69537) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary
A C-4 charge planted on an object is moved into nullspace and only remembers its target. If the target is deleted before the fuse ends (a stool picked up, paper burned, a wall changed), the charge's `detonate()` finds a deleted target, has no location, and silently deletes itself without exploding. The fix listens for the target's deletion; the charge then drops onto the target's turf, says it "falls off", and keeps ticking and explodes at the end of its fuse. Whether the vanishing was intended as counterplay is a design question the issue thread left open.

## The bug
Players plant C-4 on an item such as a stool or a sheet of paper. If that item is deleted (the issue's GIF and a commenter describe picking up a stool; the author says changing an item's icon or burning paper also does it), the bomb disappears with no explosion and no message. The issue author found this while planning to let faxes carry sticky bombs. Comments are split: one maintainer called it a niche non-bug that removes counterplay, another said a bomb should not just vanish. Suggested fixes in the thread were a `Destroy()` override that moves the bomb to the object's tile.

## Reproduction
On master, with admin tools:

1. Using the Lua editor, spawn a human and give the admin's client control of it, spawn a stool one tile east, and spawn a C-4 charge (`/obj/item/grenade/c4`) on the floor.
2. Pick up the C-4 and click it on the stool. Planting takes 3 seconds; the fuse was 10 seconds.
3. Ctrl-drag the stool onto yourself to pick it up. Picking up the stool deleted the old stool object.

Observed on master: no explosion at all. The attack log only contained "planted C-4 charge on stool". The charge was in nullspace the whole time.

This was reproduced through the real player actions (plant, then pick up), not by calling procs directly. Targets other than an item (a turf, a mob) were not tried.

## Cause
`plant_c4()` in `code/game/objects/items/grenades/plastic.dm` stores `target = bomb_target`, then calls `moveToNullspace()` (line 140), so the charge has no location of its own. `detonate()` (line 66) works out where to explode like this:

```dm
if(target)
    if(!QDELETED(target))
        location = get_turf(target)
        ...
else
    location = get_turf(src)
if(location)
    explosion(...)
qdel(src)
```

When `target` is set but already deleted, `location` stays null. The explosion is skipped and the charge is deleted. Nothing watches the target, so any `qdel` of the host disarms the bomb without a trace.

## Fix
One commit, "Fix issue 69537: planted C4 falls off its target when the target is deleted instead of vanishing", in `code/game/objects/items/grenades/plastic.dm`:

- `plant_c4()` registers `COMSIG_PREQDELETED` on the target.
- New handler `on_target_deleting()` unregisters the signal, clears `target`, and (if the charge itself is not being deleted) removes the invisibility added to it, moves it to `get_turf(source)`, and shows "[charge] falls off [target]!".
- With `target` null, `detonate()` uses the charge's own turf, so it explodes there when the fuse ends.
- The signal is unregistered in `detonate()` (before the target is blown up) and in `Destroy()`.

The signal fires before the target's contents are deleted, so the charge can be moved out in time. Alternatives from the thread: a `Destroy()` override on the bomb (not workable on its own, since the bomb is not the object being destroyed), or detonating immediately when the host dies (not tried).

## Verification
After rebuilding with the fix, the same steps were repeated: planted on the stool, then picked the stool up. Chat showed "C-4 charge falls off the stool!", the charge appeared on the stool's tile, and at the end of the fuse it exploded ("You're set on fire!", ears ringing). No new runtimes appeared in the round's runtime log.

Not checked: other deletion causes (burnt paper, wall change, icon change), turf and mob targets, directional charges, and the interaction with any other change to `plant_c4`.

## Notes
- Design: the first comment argues disappearing is acceptable counterplay. This fix turns it into a fall-off with the bomb still live, so a maintainer should decide whether that or something else (e.g. detonating at once) is wanted. Falling off lets a player defuse by deleting the host only if they then handle the charge, which is arguably still counterplay.
- Related: the charge now stays live if its host is deleted, including when the host is an object being destroyed by the explosion of another source.
- An older, separate fix attempt for issue #52247 (C-4 handling in `plant_c4`, forceMove into the target plus invisibility) touches the same function. It does not address this bug: a deleted target would delete its contents, including the bomb. The two would conflict textually in `plant_c4`, and they were not tested together. This fix's handler restores visibility and uses `forceMove`, so it should combine with that change.
