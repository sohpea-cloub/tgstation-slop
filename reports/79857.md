# #79857: Tram remote is offered in uplinks and as a spy reward on maps without a tram

| | |
|---|---|
| Issues | [#79857](https://github.com/tgstation/tgstation/issues/79857) verified and fixed (with an open question about the uplink listing on tram maps, see Verification); [#84871](https://github.com/tgstation/tgstation/issues/84871) verified and fixed (same cause) |
| Status | Fixed on the branch; the non-tram case was checked in game, the tram-map uplink listing was not checked the way players see it |
| Fix branch | [fix/79857](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/79857) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The "Tram Remote Control" uplink item is only useful with a tram, but nothing ever checked whether the map has one: it was listed, buyable and, for spies, eligible as a bounty reward on every map. The fix adds an overridable `is_available_on_map()` to uplink items, makes `can_be_bought()` use it, overrides it for the tram remote to require a tram controller, and applies it when building the uplink item list and the spy reward pool. On MetaStation (no tram) the remote was then not buyable and was in none of the spy pools tested. One thing to check by a maintainer: the uplink item list is generated very early in initialization, probably before any tram exists, so the remote may be hidden from the uplink screen on tram maps too (details below).

## The bug

On a map with no tram (the issue says it was tested locally, no map named), a traitor uplink lists the tram remote for purchase. The second report, #84871, shows the same item offered to spies as a bounty reward on a station with no tram. A comment on #79857 notes the remote "was never restricted to stations with trams"; a comment on #84871 notes that the remote does not exist as a normal item on the station, only as an uplink purchase, so it should not be a bounty target either. The spy system's author commented on #84871 that it was "Technically intended insofar that I didn't add any code to prevent it but 100% not opposed to making it not happen".

## Reproduction

On the test server with the Lua editor, on MetaStation (no tram):

1. Look up the uplink item `/datum/uplink_item/device_tools/tram_remote` in `SStraitor.uplink_items_by_type`.
2. Call `can_be_bought(null)` on it and check `SStransport.transports_by_type`.

Observed on master: the item was named "Tram Remote Control", `can_be_bought()` returned TRUE, and `SStransport.transports_by_type` was empty (no tram controllers on the map).

This checks the purchase gate only. It does not show the item in a player-facing uplink screen, and the spy pool was not measured on master. That the spy pool includes it follows from `try_add_to_loot_pool()` (below) and from the post-fix comparison, where the same measurement on the fixed build gave no remotes on Meta and many on Tramstation.

## Cause

Three places never asked whether the map could use the item:

- `/datum/uplink_item/proc/can_be_bought()` (`code/modules/uplink/uplink_items.dm:220`) simply returned `TRUE`. Only the contractor items override it (`code/modules/uplink/uplink_items/contractor.dm:30`). `check_if_restricted()` in `code/modules/antagonists/traitor/uplink_handler.dm:51-52` is where purchases and the "random item" bundle go through it.
- The uplink's item list for the UI is generated by `/datum/asset/json/uplink/generate()` (`code/modules/asset_cache/assets/uplink.dm:19-41`). It listed every item that has an `item` type.
- The spy bounty reward pool is built in `/datum/spy_bounty_handler/proc/try_add_to_loot_pool()` (`code/modules/antagonists/spy/spy_bounty_handler.dm:139-151`), which accepts every item that is non-abstract and purchasable by spies:

```dm
if(isnull(item.item) || item.item == ABSTRACT_UPLINK_ITEM || !(item.purchasable_from & UPLINK_SPY))
	return FALSE
```

The remote itself is defined at `code/modules/uplink/uplink_items/device_tools.dm:62` (cost 2 TC).

## Fix

Commit "Fix issue 79857: Tram remote uplink item is only available on maps with a tram" changes:

- `uplink_items.dm`: adds `/datum/uplink_item/proc/is_available_on_map()` (default `TRUE`) and makes `can_be_bought()` return it.
- `device_tools.dm`: `/datum/uplink_item/device_tools/tram_remote/is_available_on_map()` returns `LAZYLEN(SStransport.transports_by_type?[TRANSPORT_TYPE_TRAM]) > 0`, i.e. true only if a tram controller exists.
- `assets/uplink.dm`: the JSON item list skips items for which `is_available_on_map()` is false. The items are still created and registered in `SStraitor.uplink_items`, so other code that loops over that list is unchanged.
- `spy_bounty_handler.dm`: `try_add_to_loot_pool()` also rejects such items.

Surplus and random-item paths already go through `can_be_bought()`, so they pick up the check without changes. Traitor discounts are not affected in practice, because discounts need `cost >= TRAITOR_DISCOUNT_MIN_PRICE` (4) and the remote costs 2.

The check is a generic hook rather than a tram special case, in line with the suggestion in the issue comments for "some convenient way to check if the current map has an eligible tram", and so other map-dependent items can use it.

## Verification

All on the test server with the Lua editor:

1. Fixed build on MetaStation: `can_be_bought(null)` = 0 and `is_available_on_map()` = 0. Forty fresh `/datum/spy_bounty_handler` instances were created and their `possible_uplink_items` pools counted (8,312 pool entries in total): the tram remote appeared in none of them.
2. The map was switched to Tramstation (Change Map, then a server restart). `can_be_bought(null)` = 1, `is_available_on_map()` = 1, `SStransport.transports_by_type` had 2 entries, and the remote appeared in 39 of 40 fresh spy handlers' pools. The one missing is probably a handler whose refresh had already consumed it as a bounty, which was not confirmed.
3. On Tramstation, calling the uplink asset's `generate()` again at runtime produced 331 items, containing "Tram Remote Control" once.

Not checked:

- **The uplink screen on a tram map as a player sees it.** Step 3 re-ran `generate()` after the round was loaded. The data players receive (`uplink.json`) comes from the cached asset, and `/datum/asset/json/uplink` is marked `early = TRUE`, so it is created by the Early Assets subsystem, which is declared to run before Mapping and Atoms (`code/controllers/subsystem/early_assets.dm`). Tram controllers are created when the map's atoms initialize and register in `SStransport` then. If that reading is right, `SStransport.transports_by_type` is empty when the cached asset is built, and the remote would be missing from the uplink screen on every map including Tramstation, even though purchase and spy rewards would be right. This was not tested. A maintainer should open an uplink on Tramstation with the fix to confirm.
- Opening a real uplink on MetaStation to see the item hidden (hidden by the same JSON filter; the purchase gate was checked by call).
- Actually buying through the UI or the random-item bundle, a full spy round, and maps other than Meta and Tramstation. Which maps have trams was not listed (a comment on #84871 says the remote "isn't limited to Tramstation/Birdshot").

## Notes

- If the early-asset concern above holds, the JSON filter is the part to rework. Options include leaving every item in the JSON and dropping unavailable ones when the UI data is built per handler, or making the filter run when the asset is generated after the map loads. The purchase gate and the spy pool filter do not depend on this and run at runtime.
- The test run called `generate()` a second time, which appended duplicate item instances to `SStraitor.uplink_items` on that test server. Real rounds do not call it twice.
- The check reads the controller list at the time it runs. Whether other tram lines (`SStransport.debug_tram_list` names heretic and Hilbert hotel ones) can appear later in a round on a map without a station tram, and then count, was not examined.
- A comment on #79857 suggests a general helper for "does this map have an eligible tram"; `is_available_on_map()` is the uplink-side hook, and other systems that care about a tram would still need their own check.
