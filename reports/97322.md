# #97322: Speed potion used on a table slathers the table instead of being placed

| | |
|---|---|

| Status | Fixed |

## Summary

Clicking a table (or any non-item object that has no drag slowdown) with a speed potion in hand uses the potion up on the object instead of placing it, even though there is nothing to speed up. `/obj/item/slimepotion/speed/interact_with_atom()` only refuses items that cannot be sped up; non-items always take the potion. The fix returns `NONE` for non-items whose `drag_slowdown` is 0 or unset, so the click falls through to normal item placement.

## The bug

A player who tries to put a speed potion down on a table gets "You slather the red gunk over the the table, making it faster.", the table is recoloured red, and the potion is consumed. The table's behavior is unchanged, because it never had drag slowdown.

## Reproduction

1. Using admin tools (Lua editor), spawn a human and possess it, spawn a table next to it, and give the human a speed potion (`/obj/item/slimepotion/speed`) in hand.
2. Click the table with the potion.

Observed on master: the chat message above, and the potion was gone from the hand. This was done with a real click as the player.

## Cause

`/obj/item/slimepotion/speed/interact_with_atom()` is at `code/modules/research/xenobiology/xenobiology.dm:960`. For items, a block at line 973 refuses anything with `slowdown <= 0` (and returns `NONE` for storage items so the potion can go in a bag). For non-item objects there is no such check. After the `COMSIG_SPEED_POTION_APPLIED` signal at line 980, which only ridable objects handle, the proc goes straight to the "slather" code at line 986: it recolours the object, sets `drag_slowdown = 0`, adds `TRAIT_SPEED_POTIONED` and calls `qdel(src)`. Since the proc returns `ITEM_INTERACT_SUCCESS`, the click is consumed and the potion is never placed on the table.

## Fix

One commit, "Fix issue 97322: speed potion no longer slathers itself on tables", adds to the non-item branch:

```dm
else if(interacting_with.drag_slowdown <= 0)
	return NONE // nothing to speed up (a table, say): let the potion be placed on it as usual
```

An unset (null) `drag_slowdown` counts as 0 here. Ridable objects are unaffected, since their signal handler runs earlier. Objects that do have drag slowdown (e.g. closets) still take the potion.

## Verification

After rebuilding and restarting, the same click on a table put the potion on the table's tile, with no message and no recolouring of the table. Two further checks were done by calling the interaction directly from Lua rather than by clicking: a closet (`drag_slowdown` 1.5) still consumed a potion and was sped up, and a crate (`drag_slowdown` 0) did not consume it.

Not checked: ridable objects (vehicles, etc.), other non-item objects with no drag slowdown, and the runtime log beyond the absence of errors in chat.

## Notes

- Any non-item object with `drag_slowdown` of 0 or null is now treated as "can't be improved" silently, with no "can't be made any faster" message, unlike items. A maintainer may prefer to give a message or to block rather than fall through; falling through was chosen so potions can be set down on tables and crates.
