# #89982: Loot panel (alt-click) can list tile contents the player cannot see

| Status | Duplicate-cause of a loot panel visibility bug (meson sight); fix cherry-picked and verified in game |

## Summary

The issue reports that after alt-clicking a tile, a player can walk out of view and use the panel's refresh button (new in BYOND 516) to see what is on the tile. The server side does close the loot panel within about a second when the tile leaves the player's line of sight, so a stale panel for a plain player was not reproduced. A related defect was reproduced: the visibility checks use `viewers()`, which BYOND treats as true for any turf a `SEE_TURFS` mob (meson goggles) can see, even behind a wall, so a meson wearer can open and keep a live panel listing objects on tiles they cannot see. The fix adds one helper that also requires real line of sight unless the mob has `SEE_OBJS` (x-ray), and uses it in both places.

## The bug

Players alt-click a tile to get a panel listing its contents. The issue reporter says that with BYOND 516 they can move away so the tile is no longer visible, wait for something to be added or removed, press refresh, and see the change. A commenter notes that on 515 the panel simply disappears once you are a tile or two away, so the refresh behaviour is specific to 516.

What actually happens on the server: the panel's visibility check is `viewers()`-based. That check is satisfied for a turf that is only "seen" through `SEE_TURFS` (meson goggles) with no line of sight, so such a player can open the panel on a tile behind a wall and it stays open and updated.

## Reproduction

On master `87b93338`, with admin tools (Lua editor was used to spawn things and change turfs):

1. Plain-sight case (does not reproduce the issue): as a human, spawn a crowbar and a wrench on a tile of the arrival shuttle and alt-click the tile. The panel opens listing the floor, crowbar and wrench.
2. Move the human away (teleported out of the shuttle to the Pharmacy), or build a wall between the human and the tile (`ChangeTurf` to a wall). Observed: the LootPanel window was closed by the game within about one second (tgui's status check returns `UI_CLOSE`). No stale panel was observed server-side.
3. Meson case: give a mob `sight = SEE_TURFS` (meson goggles), and place a wall between the mob and a tile that has objects (in the maintenance test: mob at 60,93, wall at 62,93, tile at 64,93). Alt-click the tile.
4. Observed: the panel opened, listed the tile's objects, and stayed open despite the wall.

Also observed: dark tiles within range are listed too, because `viewers()` ignores darkness. This was judged intended and left alone.

Not tested: the 516 client's refresh button itself. The test server could only show that after the server closes the window the tgui window is released (`close` calls `release_lock`), so a client-side "ready"/refresh would receive no data. What a 516 client does with a suspended window it keeps visible is client behaviour that could not be checked here.

## Cause

Two places use `viewers()` to decide whether the user can see the turf:

- `code/_onclick/click_alt.dm:122`, in `try_open_loot_panel_on`: `if(!(src in viewers(target)) || (is_blind() && ...))`
- `code/modules/lootpanel/_lootpanel.dm:79`, in `ui_status`: `if(!(user in viewers(source_turf)) || ...)`

BYOND's `viewers()` includes a mob with `SEE_TURFS` for turfs it can see without line of sight, so both checks pass for a mesons wearer behind a wall. The same checks also keep the panel alive on every tgui refresh.

## Fix

One commit, cherry-picked from the fix for #91092: "Fix issue 91092: loot panel (alt-click) no longer lists objects on tiles only shown by mesons".

- Adds `/mob/proc/can_see_loot_turf(turf/target)` in `code/modules/lootpanel/misc.dm`. It returns false for a null turf or if the mob is not in `viewers(target)`. It returns true if the mob has `SEE_OBJS` (x-ray). Otherwise it requires the mob to be in `view(max(view_x, view_y), target)`, which needs real line of sight.
- `try_open_loot_panel_on` and `ui_status` call this helper instead of `viewers()`.

The branch has no commit of its own for this issue.

## Verification

After rebuilding, with a mob set to `sight = SEE_TURFS` on the arrival shuttle, tile at 45,139:

- Clear line of sight: alt-click opened the panel.
- With five wall tiles placed at x=43 between them: the panel was closed by the game within 3 seconds, and alt-click through the wall opened nothing.
- With `sight = SEE_OBJS|SEE_TURFS` (x-ray) and the wall still in place: alt-click opened the panel, so x-ray still works.

No runtimes were noticed. Not checked: the 516 client's refresh button, and any other source of out-of-sight tile information.

## Notes

- Whether #89982 should be closed as a duplicate of #91092 is a judgement call: the reported refresh path is not reproduced server-side for normal sight, only the meson variant is.
- Dark tiles in range remain listed (`viewers()` ignores darkness); not changed.
- The 515/516 difference commented on the issue points at the client, which may need its own fix if a 516 client keeps showing a window the server has closed.
