## Summary

Of the three issues, only #55249 (a heretic rune moving when a shuttle rotates) was still a bug on master. Its cause is that `shuttleRotate()` rotates the big rune's fixed centering pixel offsets and its direction; the fix overrides `shuttleRotate()` on heretic runes so those are left alone. #72899 (items hard to pick up under a rune) no longer reproduces: the rune is drawn on the floor plane, below items. #84249 (AIs can see the rune) has a silicon-only alternate appearance in the code that should hide the rune, but this could not be confirmed from an AI's view in game.

## #72899: items under or created by a rune are hard to pick up

### The bug

The 2023 report said items dropped on a heretic rune, or created by it (blades), were on a layer below the rune and hard to pick up.

### Reproduction

Not reproduced. Using the Lua editor on master, a big heretic rune (`/obj/effect/heretic_rune/big`) and a pocket crowbar were placed on the same tile. Values read back: rune plane -6 (`FLOOR_PLANE`), layer 10017 (`RUNE_LAYER`), `mouse_opacity` 1; crowbar plane -4 (`GAME_PLANE`), layer 3. A click aimed at the crowbar on that tile reached the crowbar. Only plane ordering and one click were checked; no ritual was performed to see created items.

### Cause

The rune now sets `plane = FLOOR_PLANE` and `layer = RUNE_LAYER` (`code/modules/antagonists/heretic/transmutation_rune.dm:10-11`), so it draws and hit-tests below everything on `GAME_PLANE`. The agents' notes name upstream PR 75868 as the change that did this; that attribution was not checked against the PR itself.

### Fix

None needed.

## #55249: heretic runes move when a shuttle takes off

### The bug

A rune left on a shuttle moved down and to the right when the shuttle took off.

### Reproduction

Reproduced by calling the proc directly, not with a real shuttle move:

1. Using the Lua editor, spawn `/obj/effect/heretic_rune/big` on a floor tile.
2. Call `shuttleRotate(90)` on it.
3. Before the fix, `pixel_x`/`pixel_y`/`dir` changed from (-30, 18, south) to (18, 30, west); `pixel_z` stayed -48. The rune's drawn position was thus shifted off its tile.

### Cause

`/atom/proc/shuttleRotate()` (`code/modules/shuttle/mobile_port/shuttle_rotate_callbacks.dm:9`) rotates an atom's `dir` (`ROTATE_DIR`) and swaps and negates its pixel offsets (`ROTATE_OFFSET`) for each quarter turn. The big rune's `pixel_x = -30`, `pixel_y = 18`, `pixel_z = -48` (`transmutation_rune.dm:269-271`) are not a real displacement; they only center a 96x96 icon on a 32x32 tile. Rotating them moves the rune.

### Fix

Commit "Fix issue 55249: heretic runes no longer shift when a shuttle rotates" adds, in `transmutation_rune.dm` just above `/obj/effect/heretic_rune/big`:

```dm
/obj/effect/heretic_rune/shuttleRotate(rotation, params)
	params &= ~(ROTATE_OFFSET|ROTATE_DIR)
	return ..()
```

The rune is symmetrical, so keeping its direction and offsets is correct. This follows the pattern of the alien weeds override in `shuttle_rotate_callbacks.dm`, which also masks rotation parameters. The override sits on the base rune type so subtypes inherit it.

### Verification

After a rebuild and a new round, the same direct `shuttleRotate(90)` call left the big rune at pixel_x -30, pixel_y 18, pixel_z -48, dir south.

Not checked: a real shuttle move or transit; the short-lived `/obj/effect/temp_visual/drawing_heretic_rune` (30 seconds), which has the same offsets and is not covered by the fix.

## #84249: AIs can see heretic runes

### The bug

An AI saw a heretic rune on the mining base. Comments say AIs also see heretic influences while cyborgs do not, and that silicons should not see cult runes either. The report was filed against a testmerge of the "Cult Vs. Heretic" rework.

### Reproduction

Not reproduced in game. The agents tried to view the rune from an AI eye, but a Lua-spawned AI had no location and no eye object, so no AI view was obtained.

### Cause / current code

On master, `/obj/effect/heretic_rune/Initialize()` (`transmutation_rune.dm:15-19`) adds an alternate appearance on `/datum/atom_hud/alternate_appearance/basic/silicons` with an image whose `icon_state` is null and `override = TRUE`. For silicons (AIs and cyborgs) this replaces the rune's appearance with the blank image. The drawing animation does the same (line ~298). The icon file `eldritch.dmi` has no empty-named icon state (checked by listing its states), so the image should draw nothing. This is the same technique cult runes use (`code/modules/antagonists/cult/runes.dm:82-84`). This is a code reading; the effect was not confirmed on screen.

### Fix

None. The report may predate this code (it was filed against a testmerge), or it may still occur in a case the code review missed; heretic influences were not examined.
