# #62054: AI and cyborgs don't count as observers for the Creature's "Uncanny Movement"

| | |
|---|---|
| Issues | [#62054](https://github.com/tgstation/tgstation/issues/62054): verified, fixed |
| Status | Fixed on a branch; checked in game by calling the visibility check, not by a full player jaunt |
| Fix branch | [fix/62054](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/62054) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The sentient netherworld Creature's "Uncanny Movement" is meant to be blocked while something can see it. The check ignores any mob with `TRAIT_UNOBSERVANT`, and all silicons have that trait, so an AI or cyborg watching the Creature never blocked the jaunt. The fix adds an opt-in `silicons_observe` option to the `unobserved_actor` component, makes the Creature's jaunt use it, and also counts an AI watching through its camera eye. Statues, drones and bots keep ignoring silicons.

## The bug

A player Creature (made from a gold slime core with a sentience-style transfer) teleported next to a malfunctioning AI and killed it, although the jaunt is supposed to be unavailable while observed. A second commenter said the observation requirement did not seem to work at all, even for a human creator.

## Reproduction

1. On the test server, using the Lua editor, `AIize()` a human and give the AI a client.
2. Spawn a `/mob/living/basic/creature` about 2 tiles from the AI.
3. Call `can_be_seen(creature)` on the Creature's `unobserved_actor` component (the one its jaunt action adds).

Observed on master: with the AI having a client, not blind, 2 tiles away, `can_be_seen` returned 0 (not observed). This was done by calling the component's check directly, not by casting the jaunt as a player.

## Cause

`code/modules/mob/living/silicon/silicon.dm:76` gives every silicon `TRAIT_UNOBSERVANT`. `can_be_seen` in `code/datums/components/unobserved_actor.dm:94-109` skips any mob with that trait:

```dm
for(var/mob/living/mob_target in oview(my_turf, 7))
	if(mob_target.client && !mob_target.is_blind() && !HAS_TRAIT(mob_target, TRAIT_UNOBSERVANT))
		return TRUE
```

The mecha-occupant loop at lines 104-107 has the same condition. Only living mobs in view are checked, so an AI viewing through its camera eye (a separate eye mob) was never considered either. The Creature's jaunt adds the component at `code/modules/mob/living/basic/space_fauna/netherworld/creature.dm:85`.

## Fix

One commit, "Fix issue 62054: AI and cyborgs now count as observers for the Creature's Uncanny Movement":

- `unobserved_actor.dm`: new variable and `Initialize` argument `silicons_observe` (default FALSE). A new `is_observer(watcher)` proc requires a living mob with a client that is not blind; if it has `TRAIT_UNOBSERVANT` it only counts when `silicons_observe` is set and it is a silicon. Both existing loops now use it. When the option is set, AI camera eyes within 7 tiles also count, via the eye's AI.
- `creature.dm:85`: the jaunt passes `silicons_observe = TRUE`.

The option is opt-in so the other users of the trait (statues, drones, bots) behave as before.

## Verification

Checked in game by calling `can_be_seen` through the Lua editor with an AI that had a client:

- Creature 2 tiles from the AI: 0 before the fix, 1 after.
- Creature near the AI's camera eye with the AI body more than 7 tiles away: 1.
- Creature far from both: 0.
- A statue near the AI: still 0 (unchanged).
- No new runtimes were noted.

Not checked: casting the jaunt as a player; the second comment's claim that the check does not work at all; cyborgs and AI shells (covered by the code, not tested); jaunting directly onto the AI's own tile, which the `oview` check does not cover because mobs on the same turf are excluded.

## Notes

- Design choice: AIs and cyborgs now observe the Creature. This could be made the component's default, but that would change statues and bots, so it was left opt-in.
- `/mob/living/basic/creature/proc/can_be_seen` (`creature.dm:47-68`) is an older duplicate of the check with the same `TRAIT_UNOBSERVANT` condition. I did not check whether it is still called, and it was not changed.
- The mecha occupant loop in that duplicate omits the trait check, so the two copies already differ.
