# #73030: Phlogiston foam damages mobs in fully sealed modsuits

| | |
|---|---|
| Issues | [#73030](https://github.com/tgstation/tgstation/issues/73030): verified, fixed |
| Status | Fixed (one-line change), checked in game with pure phlogiston only |
| Fix branch | [fix/73030](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/73030) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Foam (and smoke) containing phlogiston still burns a mob that has full bio protection, such as a human in a sealed elite syndicate modsuit. `/datum/reagent/phlogiston/expose_mob` applies the touch protection to the fire-stack part of its damage, then floors the result at 0.3, so a fully protected mob takes 0.3 burn per exposure. `adjust_fire_loss` ignores armor, so this adds up over a large, long-lived foam. The fix applies the protection after the floor, so 100 bio armor gives 0 damage.

## The bug

The report shows a player in a sealed elite syndicate modsuit killed within seconds by pink foam (the reporter did not know the chemical mix). The suit is fully heat-proof and has full bio armor, so the player expected foam to do nothing. A commenter on the issue guessed the foam was phlogiston mixed with something that adds fire stacks. The issue text does not confirm the mix.

On master, phlogiston exposure through foam deals a flat minimum amount of burn damage that no suit can reduce.

## Reproduction

Pure phlogiston was tested. The reporter's actual mix is unknown. Foam was made by calling `do_foam` from the Lua editor, not by a player-made grenade or chemical reaction.

1. On a test server, spawn two humans on separate tiles a few tiles apart. Leave one naked. Equip the other with `/obj/item/mod/control/pre_equipped/elite` and activate it with `quick_activation()`, so the suit is active with its parts deployed and sealed (bio armor 100).
2. In the Lua editor, call `do_foam(2, null, turf, /datum/reagent/phlogiston, 40)` once on each human's turf.
3. Wait for the foam to expire, then read each human's fire loss, fire stacks and status.

Observed on master:

- Naked human: dead, fire loss above 270.
- Suited human: fire loss 11.7, fire stacks 19, body temperature 310. The suit's thermal protection stopped the human from burning from the fire status effect, so the 11.7 did not come from burning. It came from the direct damage in the reagent's `expose_mob`.

## Cause

Foam exposes each mob in it every tick: `foam_mob` calls `reagents.expose(foaming, VAPOR, fraction)` (`code/game/objects/effects/effect_system/fluid_spread/effects_foam.dm:141`). `/mob/living/expose_reagents` turns that into `touch_protection = getarmor(null, BIO) * 0.01` for VAPOR and TOUCH exposures (`code/modules/mob/living/living_defense.dm:795`), which is 1 for the elite suit. It passes that value to each reagent's `expose_mob`.

Phlogiston's `expose_mob` (`code/modules/reagents/chemistry/reagents/pyrotechnic_reagents.dm:275`) was:

```dm
var/burndmg = max(0.3 * exposed_mob.fire_stacks * (1 - touch_protection), 0.3)
if(burndmg)
    exposed_mob.adjust_fire_loss(burndmg, 0)
```

With `touch_protection` at 1, the product is 0, but `max(..., 0.3)` raises it back to 0.3. The 0.3 is therefore always dealt, whatever the protection. `adjust_fire_loss` does not check armor, so nothing else reduces it. Foam from many tiles that lasts several seconds exposes the mob many times.

## Fix

One commit, "Fix issue 73030: phlogiston burn damage ignored bio protection (foam went through sealed suits)", changes two lines:

```dm
var/burndmg = max(0.3 * exposed_mob.fire_stacks, 0.3) * (1 - touch_protection)
if(burndmg > 0)
```

The protection now scales the whole damage, floor included. The `> 0` check is needed because fully protected mobs now give exactly 0, and the old `if(burndmg)` only skipped a zero value anyway. Nothing else in the proc changed, so the mob still gets a fire stack and `ignite_mob()` is still called.

## Verification

The same two-human test was run on a rebuilt test server after the fix:

- Suited human: fire loss 0 (11.7 before).
- Naked human: still died, fire loss about 263 (above 270 before). Unprotected mobs are still hurt.
- No runtimes in the new round's runtime log.

Not checked:

- Any mix other than pure phlogiston, including the reporter's. Whether the reporter's foam was phlogiston at all is not known.
- Partial protection (armor between 0 and 100).
- Foam made by a grenade or a real chemical reaction. It was made by `do_foam` through Lua.
- Smoke, which uses the same `expose_mob` path.

## Notes

- After the fix, fire stacks still build up on the suited mob. They are harmless because the suit's thermal protection meets `FIRE_IMMUNITY_MAX_TEMP_PROTECT`.
- Other reagents may have the same pattern, a flat minimum applied after touch protection. They were not audited.
- Whether phlogiston should hurt armored mobs at all is a design choice. The issue thread argues a chemical should not ignore a suit's stats; the fix follows that for bio armor.
