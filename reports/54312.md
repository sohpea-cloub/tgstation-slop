# #54312: Paraplegic quirk makes the spawning mob pick up unrelated items from its tile

| | |
|---|---|
| Issues | [#54312](https://github.com/tgstation/tgstation/issues/54312): verified |
| Status | Verified; fix committed |
| Fix branch | [fix/54312](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/54312) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A character with the Paraplegic quirk who spawns on a tile holding items (the captain's bed with its bedsheet, or the rubber duck mentioned in a comment on the issue) starts with one of those items in their hands. `/datum/quirk/paraplegic/add_unique()` re-grabs "dropped" items from the tile by comparing `fingerprintslast` with the holder's `ckey`. At that point the mob has no ckey (null), and untouched items have a null `fingerprintslast`, so every item on the tile matches. The fix records what the mob was actually holding when the quirk is added and only restores those items.

## The bug

On maps where the captain can spawn on the bed, a Paraplegic captain starts holding the bedsheet. A commenter on the issue saw the same with a rubber duck lying on the spawn tile. The mob is not intentionally picking anything up: the quirk's code puts every item on the tile into the mob's hands.

## Reproduction

1. On the test server, with the Lua editor, spawn a human mob that has no ckey on the turf of the captain's bed (the bedsheet "captain's bedsheet" lies there).
2. Call `add_quirk(/datum/quirk/paraplegic)` on it.
3. Read the mob's `get_held_items()` (or View Variables).

Observed before the fix: the held items were `nil|captain's bedsheet`, and the mob's `ckey` was `nil`.

Caveat: this was reproduced by spawning a ckey-less human and adding the quirk directly, not through the real round-start path. Readying up as Captain with the quirk was possible, but on that map the spawn tile was not the bed, so the exact player scenario was not observed. The code path (`add_unique()` with a null ckey) is the same.

## Cause

`code/datums/quirks/negative_quirks/paraplegic.dm:16-22`:

```dm
/datum/quirk/paraplegic/add_unique(client/client_source)
	quirk_holder.put_in_wheelchair()
	// During the spawning process, they may have dropped what they were holding, due to the paralysis
	// So put the things back in their hands.
	for(var/obj/item/dropped_item in get_turf(quirk_holder))
		if(dropped_item.fingerprintslast == quirk_holder.ckey)
			quirk_holder.put_in_hands(dropped_item)
```

The intent is to give the holder back items they dropped when the paralysis trauma was applied. The test for "dropped by this mob" is `fingerprintslast == quirk_holder.ckey`. Quirks are assigned during spawning (`code/datums/quirks/_quirk.dm:91-105`, `add()` then `add_unique()`), before a player controls the mob, so `quirk_holder.ckey` is null. An item nobody has touched also has a null `fingerprintslast`, so `null == null` is true for every item on the tile and `put_in_hands()` is called on all of them.

## Fix

One commit, "Fix issue 54312: paraplegic quirk no longer picks up unrelated items from the spawn tile":

- Adds a `held_before_paralysis` list to the quirk.
- In `add()`, before the paralysis trauma is gained, stores `human_holder.get_held_items()`.
- In `add_unique()`, loops over that list instead of the whole tile, and puts an item back only if it is not `QDELETED` and its `loc` is the holder's turf (that is, it was dropped). The list is then cleared.

This keeps the original behaviour (restoring what the mob held) and removes the dependence on `ckey`/`fingerprintslast`. An alternative would be to require a non-null `fingerprintslast`, but that would still depend on forensics data that may not be set for the held items.

## Verification

After rebuilding, on the test server: a human holding a crowbar, standing on a tile that also had a bedsheet and a rubber ducky, was given the Paraplegic quirk. The hands were `pocket crowbar|nil`, the bedsheet and the duck were still on the floor, and the quirk was present.

Not checked:
- A real drop caused by the paralysis. The crowbar stayed in the hand in this test, so the restore path (items on the turf being put back) was not exercised in game.
- The full round-start flow as a Paraplegic captain on the bed.

## Notes

- The same null-ckey match would affect anything else that compares `fingerprintslast` to a ckey of a mob that has not been possessed yet; only this quirk was examined.
- The restore loop only matters if the paralysis trauma makes the holder drop items at spawn. This was not observed, so the loop may be effectively dead code; it was kept to preserve the original intent.
