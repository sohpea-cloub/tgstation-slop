## Summary

When a player scoops up a simple animal, the mob is wrapped in an `/obj/item/mob_holder` that defaults to being wearable on the head, with its worn sprite named after the animal's current `icon_state`. For most pets the head icon file (`icons/mob/clothing/head/pets_head.dmi`) has no such state, so the pet can be put on the head but nothing is drawn. This is the main complaint of #93547 (cat, and a stoat that also has no in-hand sprite). The fix makes the holder fall back to the held state for the worn sprite and, if no head sprite exists at all, makes the pet unwearable on the head instead of invisible. A separate bug found while looking at the group, `update_icon_state()` on the cat ignoring death, was also fixed (#94118). The actual head and in-hand art for the affected pets does not exist in the repo and was not drawn.

## The bug

### #93547 and #91489: worn pets are not shown

Players can wear a scooped cat (and other pets) on their head, but nothing shows on the head slot. The reporter of #93547 also notes the stoat has no in-hand sprite. #91489 reports the same for a mothroach (suspecting a colourful reagent was involved; an admin testing with a fresh human saw it fine).

### #93578: coloured cockroaches lose their colour

The report says rare / coloured cockroaches lose their colour after being put in a bag and taken out.

### #94118: dead simple mobs look alive

The report says a killed cat, once scooped and dropped, looks alive but is still dead (hud and examine text show dead).

## Reproduction

All steps used the Lua editor on the test server as an observer.

### #93547 / #91489 (worn state)

1. Spawn a human and a mob (cat, stoat, cockroach, corgi, mothroach, frog).
2. Call `mob:mob_pickup(human)`, then `human:equip_to_slot_if_possible(holder, 64)` (the head slot).
3. Read the holder's `icon_state`, `worn_icon`, `slot_flags`, and call `icon_exists(worn_icon, state)` (`dm.global_procs.icon_exists`).

Observed on master: for the cat, `state=cat2`, `icon_exists` was false, `slot_flags` was the head slot, and the equip succeeded (the pet was worn but invisible). Stoat, cockroach and corgi behaved the same. A normal mothroach had `state=mothroach`, the state existed, and it was drawn on the head layer. The head icon `pets_head.dmi` only contains states for the monkey, breaddog, frog variants, mothroach (and dead), axolotl, maint spider, lizard variants, barroach and snail. For the stoat and the cockroach the holder's `inhand_icon_state` was nil: neither mob sets `held_state`, and there is no sprite for them in the held-item icon files.

Not reproduced: an invisible mothroach (#91489). Normal, dead and coloured mothroaches all had their overlay on the head layer. The reagent connection was not shown to matter.

### #93578 (cockroach colour)

A cockroach coloured `#ff0000` was scooped, released, and also inserted into and removed from a backpack. Its colour was `#ff0000` before, on the holder, and after in every case. No "rare" cockroach type exists in this tree (there is a rare frog, which was not tested), so the reporter's rare cockroach could not be spawned.

### #94118 (dead cat)

1. Spawn a cat and kill it. `icon_state` is `cat2_dead`.
2. Scoop it, put it in a backpack, take it out: it was still `cat2_dead` afterwards in every case (this is what the issue describes and it did not reproduce).
3. Call `update_appearance(UPDATE_ICON_STATE)` on the dead cat: `icon_state` changed to `cat2`, the living sprite, while the cat remained dead.

So the visual revert needs some code path that updates the cat's icon state while dead; plain scooping or bagging was not such a path in these tests. Which game event triggers it in real play was not determined.

## Cause

### Worn pets are invisible

`/obj/item/mob_holder` defaults to `slot_flags = ITEM_SLOT_HEAD` (`code/modules/mob/living/inhand_holder.dm:14`) and in `Initialize` (line 16) only changes it when the mob sets `worn_slot_flags` (line 25). The holder copies the mob's appearance (`update_visuals`), so its `icon_state` is the mob's current icon state, such as `cat2`. When it is worn, `build_worn_icon` uses `worn_icon_state || icon_state` from the head icon file `pets_head.dmi` (`head_icon`, default in `code/modules/mob/living/living_defines.dm:216`). If no such state exists nothing is drawn. The holder's `inhand_icon_state` is set from the mob's `held_state` (line 20). It is not used for the worn sprite unless the fix below applies.

Only some mobs (frog, lizard, axolotl, mothroach, breaddog) set `worn_slot_flags = ITEM_SLOT_HEAD` deliberately and have art for it. Every other holder inherits the default and becomes wearable without art.

### Dead cat reverts to a living sprite

`/mob/living/basic/pet/cat/update_icon_state()` (`code/modules/mob/living/basic/pets/cat/cat.dm:130`) set `icon_state = "[icon_living]_rest"` or `"[icon_living]"` without checking `stat`, so any update of the icon state on a dead cat replaced `cat2_dead` with `cat2`. `update_resting()` guards against this for death (`if(stat == DEAD) return`), but a direct `update_appearance(UPDATE_ICON_STATE)` did not.

### Cockroach colour

No defect found in these tests.

## Fix

Two commits on the fix branch:

**"Fix issue 93547: pets with no head sprite can't be worn on the head (invisible), fall back to the held state for the worn sprite"** adds to `/obj/item/mob_holder/Initialize` (`inhand_holder.dm`), after the mob is inserted:

```dm
if(!icon_exists(worn_icon, worn_icon_state || icon_state))
	if(inhand_icon_state && icon_exists(worn_icon, inhand_icon_state))
		worn_icon_state = inhand_icon_state
	else if(!worn_slot_flags)
		slot_flags = NONE
```

If the default worn state is missing from the head icon, the holder uses the held state as the worn state when that exists in the head icon (this covers, for example, a mothroach whose current `icon_state` is `mothroach_rest`, which `pets_head.dmi` has no entry for). If neither exists, and the mob did not explicitly ask to be worn (`worn_slot_flags` unset), the holder is no longer wearable on the head. Mobs that explicitly set `worn_slot_flags` keep that slot regardless of whether art exists, so mobs that explicitly opted in are not overridden.

**"Fix issue 94118: dead cats no longer revert to their living sprite when their icon state updates"** adds a dead check in `cat.dm` `update_icon_state()` that sets `icon_state = icon_dead` and returns.

Alternatives: drawing the missing sprites (head sprites for cat, corgi, stoat, cockroach, mouse; in-hand sprites for stoat and cockroach) would be the complete answer to "display them", but needs new art in DMI files and was not done.

## Verification

On the rebuilt test server (Lua editor):

- Cat and stoat holders: `slot_flags` was 0 and they could not be equipped to the head.
- Mothroach, frog and a dead mothroach: still wearable on the head and drew the head overlay.
- A dead cat stayed `cat2_dead` after `update_appearance(UPDATE_ICON_STATE)`.
- No new runtimes in the runtime log.

Not checked: other pets and variants (corgi, mouse, fox, sloth, space cat and so on) after the change; the resting mothroach case that the fallback was written for; the in-hand view; behaviour for a player dropping a worn pet or other inventory flows; the unit tests; the cat's resting state after the change.

## Notes

- The result for #93547 as a user feature request is "pets are not wearable" rather than "pets are displayed". If maintainers want cats and stoats on heads, head icons need to be added to `pets_head.dmi`; if the art is added, the added states should be named after the held states or `icon_state` so the holder finds them.
- The stoat and cockroach have no `held_state`, so they have no in-hand sprite either (the second part of #93547). Not addressed.
- #91489 is a duplicate in the triage. Its exact invisible-mothroach case could not be reproduced; the fallback is a plausible but unproven explanation (mothroach resting sets `icon_state` to `mothroach_rest`, code at `mothroach.dm:56-63`, and the head icon has no such state).
- #94118 links to #90662 as the same problem; that issue was not examined. The issue's actual reproduction (scoop a dead cat, drop it) did not trigger the revert here, so the cause that was found is a necessary condition, not shown to be the reporter's trigger.
- #93578 may be specific to the reporter's round (test merges listed in the issue) or to a "rare" cockroach that is not in this tree.
