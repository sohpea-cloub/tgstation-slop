## Summary

#83426 reported that a magicarp with the bolt of animation (a "dancing" carp) cannot target items lying on the floor. On master a player-controlled magicarp with that spell clicked a toolbox three tiles away and the toolbox came to life as a mimic, so the report could not be reproduced. The cause was most likely that non-dense objects stopped being hit by projectiles unless they were the clicked target, which pull request #83419 ("fix shooting at objects on the floor") fixed; the code on master is consistent with that. No fix was made. #97975, which was grouped with it as a related magicarp spell issue, was not examined.

## #83426: Magicarps can't shoot items

### The bug

The reporter (May 2024) said that dancing carps cannot target items on the floor, which makes their power almost useless, and added that the animation bolt also no longer worked on machinery. The only comment (Jacquerel) said it would presumably be fixed by #83419.

### Reproduction (not reproduced)

Done on master with admin tools, as an observer, with the Lua editor. The magicarp was controlled by a player (the tester) rather than by its AI, so this checks the path the report describes (the player-aimed shot), not the AI's own target selection.

1. Start a round, observe, and open the Lua editor.
2. In an open stretch of the Central Primary Hallway with no dense objects between the two tiles (only cables and lighting objects), spawn a `/mob/living/basic/carp/magic` and set `carp.spell.projectile_type` to `/obj/projectile/magic/animate` (read back to confirm).
3. Spawn a `/obj/item/storage/toolbox/mechanical` named "testbox" three tiles east of the carp.
4. Give the carp the observer's key (`carp.key = me.key`), face it east, and click the toolbox.

Observed: the spell's cooldown started, a projectile sound played near the toolbox, and the toolbox turned into a mob (a dense mob that kept the toolbox's look and gained "googly_eyes" overlay). The attack log recorded "fired at testbox with the bolt of animation". The runtime log had no new runtimes.

### Why it works on master (from code reading)

- A player-controlled magicarp's `RangedAttack()` calls `spell.Trigger(target = atom_target)` (`code/modules/mob/living/basic/space_fauna/carp/magicarp.dm:115-116`).
- The projectile attack action sets `our_projectile.original = target` (`code/datums/actions/mobs/projectileattack.dm:54-55`), so the clicked item is the projectile's direct target.
- In `can_hit_target()`, an object that is not dense and is above `hit_threshhold` in layer is only hit when `direct_target` is set (`code/modules/projectiles/projectile.dm:652-658`). A clicked floor item satisfies that. #83419 is what restored this for clicked non-dense objects; the toolbox in the test was on layer 3.
- The bolt's `on_hit()` calls `animate_atom_living()` on the target unless its type is in `GLOB.animatable_blacklist` (`code/modules/projectiles/projectile/magic.dm:181-184`).

The machinery remark in the report is not a regression: `animate_atom_living()` is only overridden for items and structures (`obj/item`, `obj/structure`, a few special cases), so machinery has never been animatable by this bolt.

### Not checked

- The AI-controlled magicarp: how it picks targets for the bolt of animation (it uses the `MAGICARP_SPELL_OBJECTS` targeting set in `assign_spell_ai()`, `magicarp.dm:105-112`) was not tested, so if the reporter meant that wild dancing carps never animate items on their own, that remains unverified.
- Items other than the toolbox, items on other layers, and items with a dense object in the path.
- Whether the item would have been animated on master before #83419; this was not checked on an older commit. The link to #83419 is from the PR title and the code, not from a before/after test.

## #97975: Name change potion affects ability to cast magicarp spells

Not tested and not examined in the code. The report (September 2026, from a round with three test merges: lighting objects moved to turf, bodypart overlay flags, and recursive crafting menu tooltips) says that a player controlling a chaos magicarp could cast normally until a name change potion was applied, after which casting changed only the carp's colour and no spell was fired. The reporter thinks it may apply to all simple mobs. The suggested reproduction is to possess a chaos magicarp, apply a name change potion, and try casting; this was not tried, so there is no verdict on whether it reproduces on master `87b93338`.
