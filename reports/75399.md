| | |
|---|---|

| Status | Not reproduced on master; the nude-only ventcrawl check now covers a hat on the head |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The issue reports that a monkey who has a hat thrown onto its head can still ventcrawl, although equipping the same hat by hand would block it. On master, a hat in the head slot blocks ventcrawling for a monkey. A hat landing on the head after a throw is equipped through the normal inventory call, and the ventcrawl check looks at every equipped item. No bypass was found. Nothing was changed.

## The bug

As reported (2023-05-12): monkeys can only ventcrawl while carrying nothing. If a crewmember throws a hat onto a monkey's head, the monkey could still crawl into vents. With a hat that has storage space (a fedora, for example), small items could be carried through the vents in the hat. The issue's only comment points at the hat `throw_impact` code in `code/modules/clothing/head/_head.dm` and at `code/modules/mob/living/ventcrawling.dm`.

## Reproduction

The thrown-hat step was not reproduced as an actual throw. The test used the call that the throw ends in. Using the Lua editor as an observer on a test server:

1. Spawn a `/mob/living/carbon/human/species/monkey` next to a `/obj/machinery/atmospherics/components/unary/vent_pump`.
2. Call `can_enter_vent(vent, false)` on the monkey. It returned 1 (allowed).
3. Spawn a fedora and call `equip_to_slot_if_possible(fedora, ITEM_SLOT_HEAD)` on the monkey (slot value 64). It returned 1, and the monkey's head item was the fedora.
4. Call `can_enter_vent(vent, false)` again. It returned null (blocked).

The first Lua attempt failed with a syntax error and the second, corrected script produced the results above.

## Cause

There is no defect on master. The relevant code:

- `code/modules/clothing/head/_head.dm:16` (`/obj/item/clothing/head/throw_impact`) handles a hat thrown at someone's head. For a carbon target it knocks off an existing hat where allowed, then calls `H.equip_to_slot_if_possible(src, ITEM_SLOT_HEAD, 0, 1, 1)` (line 44). So a thrown hat ends up in the same head slot as a hat put on by hand, with no special state. The hat is also not thrown into place if it has contents (`LAZYLEN(contents)`), which stops a hat with items stuffed into it from being thrown on.
- `code/modules/mob/living/ventcrawling.dm:19` sets `required_nudity` for a mob that has `TRAIT_VENTCRAWLER_NUDE` but not `TRAIT_VENTCRAWLER_ALWAYS`. Monkeys get `TRAIT_VENTCRAWLER_NUDE` from their legs (`code/modules/surgery/bodyparts/species_parts/monkey_parts.dm:42`). Lines 47-48 then reject any carbon with `required_nudity` that has anything in `get_equipped_items(INCLUDE_POCKETS|INCLUDE_HELD)` (or a cuffed item). That includes the head slot.
- `handle_ventcrawl` (line 68) calls `can_enter_vent` first, and calls it again as an `extra_checks` callback of the `do_after` on the way in (line 95). A hat that is thrown onto the monkey while it is climbing in therefore also cancels the climb.

The hat-in-a-hat storage trick from the issue's last point is covered by the same check: the hat is an equipped item, so it blocks the crawl however it got there.

## Fix

None. No change was made.

## Verification

Checked in game: the sequence above (bare monkey allowed, monkey with a fedora in the head slot blocked).

Not checked:
- A real thrown hat (`throw_at` that hits the head) was not tested. It ends in the same `equip_to_slot_if_possible` call that was tested, but the throw path itself was not exercised.
- A hat thrown at a monkey in the middle of its entry `do_after` was not tested. That the climb is cancelled is read from the code, not observed.
- Actually moving through the vents was not tested; `can_enter_vent` was called directly.
- A mob already inside the pipes cannot be hit by thrown items; this was reasoned from the code and not tested.
- Other bodies with `TRAIT_VENTCRAWLER_NUDE` (for example the rat organ set from the DNA infuser) share the same check and were not tested.

## Notes

- The issue is from May 2023. The nudity check has since been reworked into `can_enter_vent`, which the investigation found to be the reason the report no longer applies. The history of that change was not looked up, and the local checkout is shallow.
- The issue can probably be closed as fixed or obsolete.
