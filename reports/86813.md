## Summary

On this master, augmenting a limb sends nothing to nullspace. Organs and implants of the replaced limb move into the new robotic limb, and the augment operation refuses a robotic limb that already contains anything, which closes the "stack implants and become EMP proof" exploit described in #86813. Of the three items in #71699, the HUD/tongue duplication no longer happens, and the other two describe the old multi-step surgery datums, which are gone. A residual gap exists for non-surgery code that attaches a pre-stuffed limb; it was identified in the code but not tried in game.

## #86813

### The bug (as reported)

Augmenting someone with a robotic limb leaves the limb's contents empty. The reporter also notes this can be used to give oneself implants while becoming EMP immune.

### Reproduction attempt

Everything was done from the Lua editor on an observer, calling the surgery operation procs directly. The full surgeon-and-tool interaction was not played out. Operation used: `replace_limb` (from the operations registry), `on_success`, with a human holding the robotic limb as surgeon.

1. Gave a patient a toolkit arm implant in the left arm and had the surgeon hold a robotic left arm. Ran `on_success` of `replace_limb` on the old arm. Result: the patient's left arm was the robot arm; the implant's `loc` and `bodypart_owner` were the robot arm; the implant's `owner` was the patient; the old arm had 0 contents; the patient's organ count was unchanged (10).
2. Repeated for the head, chest and right leg on a human with all organs. Organs were 9/9 after each; none had a null `loc`; none was outside its bodypart (the brain was in the robotic head, the stomach in the robotic chest).
3. Tried the exploit: a robot arm with the toolkit implant inserted into it with `bodypart_insert`, then `replace_limb`'s `pre_preop`. It returned FALSE, with the surgeon told that the limb "needs to be empty in order to be attached!".

### Why it works on master

- `code/modules/surgery/operations/operation_replace_limb.dm:53` (`pre_preop`) rejects a tool limb whose `contents` is non-empty. The comment says this prevents "quickly filling someone with high-tier organs by augmenting them with a pre-stuffed limb". `start_operation` calls it at `code/modules/surgery/operations/_operation.dm:1109`.
- Organs of the replaced limb are nullspaced only transiently. `remove_bodypart` with `special` (`code/modules/mob/living/carbon/carbon.dm:847`) calls `bodypart_remove` on each organ. The `special` loop in `try_attach_limb` (`code/modules/surgery/bodyparts/dismemberment.dm:276-282`) then calls `bodypart_insert` into the new limb for each of the owner's organs in that zone.

### Residual gap (not fixed, not tested in game)

`add_bodypart` (`carbon.dm:825`) calls `mob_insert` on every organ in the new limb and has no organ-slot conflict check. A non-surgery path that attaches a limb already holding organs would not be stopped by `pre_preop`. One example is `prosthetic_replacement`, which attaches the tool limb through `try_attach_limb` (`code/modules/surgery/operations/operation_add_limb.dm:97` region). Reaching it needs the patient to already hold an organ in the same slot as one in the limb, which seems hard to arrange normally. Upstream PR #92162 (closed) tried to fix this at the bodypart level.

## #71699

The issue lists three problems.

1. **Can't cancel augmentation halfway.** This belonged to the old multi-step surgery datums. Surgery is now a set of single operations (`surgery_operation`), and augmentation is one operation gated on `SURGERY_SKIN_OPEN`, so there is no halfway state to cancel. Code check only, not in game.
2. **HUDs (and tongues) duplicate after organ manipulation.** Checked in game by calling `organ_manipulation/internal`'s `on_success_insert_organ` on the head with a medical HUD implant and a lizard tongue. In both cases `organ.owner` was the patient, `organ.loc` was the head, and the patient's tongue slot held the new tongue. The only object that appeared on the floor was the patient's displaced old tongue, which is expected when an organ in the same slot is replaced. No duplicate HUD or tongue appeared. This matches upstream PR #71737, which was merged.
3. **Can't scan a patient mid-surgery.** The comments explain it as tied to aiming at the operated bodypart. The in-progress-surgery state it depended on is gone, and `health_analyzer.dm` has no reference to surgery. Code check only, not in game.

## Notes

- Neither issue yielded a commit.
- The residual `add_bodypart` gap above is the only open lead; a maintainer may want a conflict check there if non-surgery attachers of stuffed limbs are a concern.
