## Summary

The issue reports a nightmare's brain ("tumorous mass") being moved into a human by organ manipulation surgery, which turned the human into a nightmare but left a body that could not be defibrillated ("Patient's brain is missing"), with a brain mob nested inside a brain inside the head and a "cyclic contents" runtime when the brain was ejected from an MMI. On master, the code path in the reported stack trace no longer exists, and inserting a nightmare brain, passing it through an MMI and back, and re-inserting it all ran without any runtime and with a defibrillatable result. No fix was written. The tests were scripted and did not include a real surgery, defibrillator use, or a real MMI click, so the result is "not reproduced", not "disproved".

## The bug

As reported (on a round with test merge #89549, the pills/stomach refactor):

- Transferring a nightmare's brain into a human by organ manipulation completed the surgery and the human mutated into a nightmare.
- Defibrillating that body failed with "Patient's brain is missing. Further attempts futile."
- The reporter saw a brain mob inside a brain inside the head, with the `organs` lists in a bad state, and thought that broke the revive.
- Ejecting the nightmare brain from an MMI (the stack trace is from `mmi.eject_brain`) logged "Attempt to move Unknown's tumorous mass to Unknown's tumorous mass was rejected by BYOND, possibly due to cyclic contents": the brain mob was being moved into a brain that was apparently already (indirectly) inside it.
- Entering the ghost body repeatedly triggered a "too many actions in a minute" admin warning.

## Reproduction

Not reproduced. What was tried on the test server, all through the Lua editor:

1. Created a nightmare brain (`/obj/item/organ/brain/shadow/nightmare`) holding a brain mob and mind (via `transfer_identity` from a human with a mind), then called `Insert` on a human with no brain. Result: the human became the nightmare species, the brain slot held the `shadow/nightmare` "tumorous mass", the brain mob was gone (`nil`), the mind moved to the body, `can_defib()` returned 1 (defibrillation possible) and the brain's `loc` was the head. No runtime appeared in the round's runtime log.
2. Called `Remove` on a nightmare's brain (which creates a brain mob carrying the mind), then `insert_brain` and `remove_brain` on an MMI with it. Result: the brain came back out onto the floor with the brain mob inside it, and no runtime or cyclic-contents error.
3. Re-inserted that brain into another human. Result: fine.

Runtimes that did show up in the log came from the test setup (for example Lua calls from a script with no ckey, and an ambience runtime for a mob with no client) and were not related to the issue.

## Cause

No defect matching the report was found on master, so there is no cause to give for the reported behaviour. What was established by reading the code:

- The stack trace goes through `/obj/item/mmi` `eject_brain` -> `brainmob.forceMove(brain)`. `eject_brain` no longer exists on master. The MMI's brain handling now lives in `/obj/item/brain_processor/organic` (`code/modules/mob/living/brain/processor/organic.dm`): `insert_brain` (line 107) and `remove_brain` (line 136), which does `old_brainmob.forceMove(brain)` at line 146 after `set_brainmob(null)` and `brain.brainmob = old_brainmob`.
- `insert_brain` takes the brain mob out of the brain (`set_brainmob(brain.brainmob)`, then `brain.brainmob = null`) before moving it into the MMI, so the brain and its mob are not both claiming each other as `loc`. The old code that produced the trace was not examined.
- The nightmare brain (`code/modules/antagonists/nightmare/nightmare_organs.dm`, `on_mob_insert` at line 19) sets the species to nightmare if the owner is not one already, and grants the shadow jaunt (and the terrorize spell, only for a mind with the nightmare antagonist datum).
- The species change calls `regenerate_organs` (`code/modules/mob/living/carbon/human/_species.dm:288`), but `get_replaceability` (`code/modules/surgery/organs/_organ.dm`, around line 445) returns FALSE for an organ whose type already matches the new one, so the inserted nightmare brain is not replaced or deleted by the species change.
- "Patient's brain is missing" comes from `can_defib_brain` (`code/modules/mob/living/carbon/carbon.dm:760`), which returns `DEFIB_FAIL_NO_BRAIN` when the brain organ is missing or being deleted (`QDELETED`).
- Surgery inserts the organ with a plain `organ.Insert(limb.owner)` (`code/modules/surgery/operations/operation_organ_manip.dm:258`), the same call as in test 1.

The likeliest explanation is that the problem came from the MMI code before its refactor or from the reporter's test merge (#89549), not from current master. That is an inference from the missing code path, not something that was demonstrated.

## Fix

None. No code was changed and nothing was committed.

## Verification

Checked, with the results above: nightmare brain `Insert` into a brainless human (via script); MMI insert and remove round trip with a nightmare brain; re-insertion; `can_defib()` on the resulting body; the runtime log for the round.

Not checked:

- A real organ manipulation surgery, and a real defibrillator on the resulting body (only `can_defib()` was called).
- Ejecting through a real MMI click (`attack_self`) rather than calling `insert_brain` and `remove_brain` directly.
- Inserting the brain into a body of another species (for example a lizard or a shadow person).
- Inserting while the target still has a living mind or client (which would ghostize the player).
- The antagonist nightmare path (a mind with the nightmare antagonist datum, terrorize spell).
- Entering the ghost body repeatedly, and the "too many actions" admin warning.
- Behaviour with the pills/stomach refactor test merge the reporter was running.

The work was stopped at this point because the remaining variants were judged low-value, given that the code path in the stack trace is gone.

## Notes

- When reading the Lua test results: moving the runner's own mind or key with `Insert` or `transfer_identity` has to be the last call in a script, and `Remove` moves the mind into the removed brain's brain mob, so the original body no longer holds it.
- If this issue is ever picked up again, the first things to try are a real surgery followed by a real defibrillator, and the MMI click path.
