# #86479: Deconstructing an AI built from a positronic sphere returns a cube posibrain

| | |
|---|---|
| Issues | [#86479](https://github.com/tgstation/tgstation/issues/86479): verified, fixed |
| Status | Fixed on branch, verified in game |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/86479 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An AI created from a spherical posibrain (`/obj/item/brain_processor/positronic/sphere`) always gave back a plain cube posibrain when its core was deconstructed. `make_mmi()` creates a fresh brain container and hard-codes the cube type, and the AI only remembered a boolean (`posibrain_inside`), not which posibrain it came from. The fix adds a `posibrain_type` variable to the AI, fills it when the core is activated, and makes `make_mmi()` create that type.

## The bug

A player builds an AI core with a positronic sphere, brings the AI online and later deconstructs it. The brain container that comes out is a cube posibrain (icon `posibrain`), not the sphere that went in. The sphere is lost. The issue's links point at older code; the same logic now lives in `code/modules/mob/living/silicon/ai/ai.dm` and `code/game/machinery/ai_core/_core.dm`, where the container is called `brain_processor`.

## Reproduction

On master, as an observer with admin tools:

1. Using the Lua editor, spawn a `/obj/item/brain_processor/positronic/sphere`, then an `/obj/structure/ai_core` in state 5 (finished) holding it as its `core_mmi`.
2. Spawn a human, initialise their mind and transfer it into the sphere's `brainmob`.
3. Call `ai_structure_to_mob()` on the core. This brings the AI online.
4. Call `ai_mob_to_structure()` on the AI. This is the proc that deconstruction uses. (The Lua editor reported "destructed callback" errors after this call. They only mean the AI was deleted by the call, and were ignored.)
5. With an SDQL2 query, read the new core's `core_mmi`: `SELECT /obj/structure/ai_core MAP [x, core_mmi.type, core_mmi.icon_state]`.

Observed on master: `core_mmi.type` was `/obj/item/brain_processor/positronic` with `icon_state` `posibrain` (the cube). The sphere was gone.

This was reproduced by calling the construction and deconstruction procs directly. The physical steps (inserting the sphere with a player's hands, wrenching, welding and so on) were not carried out.

## Cause

- `code/game/machinery/ai_core/_core.dm:183`, in `ai_structure_to_mob()`, sets only `ai_mob.posibrain_inside = core_mmi.braintype == "Android"`. The same boolean is set from the card-to-core transfer path at line 229.
- `code/modules/mob/living/silicon/ai/ai_defines.dm:26` declares `posibrain_inside` as a plain boolean, so nothing records the exact type.
- `code/modules/mob/living/silicon/ai/ai.dm:413`, in `make_mmi()`, builds a new container whenever `posibrain_inside` is true:

  ```
  copied_mmi = new /obj/item/brain_processor/positronic(destination, FALSE)
  ```

  `ai_mob_to_structure()` (line 425) passes that new container to the new core. The original sphere is never referenced again.

## Fix

One commit, "Fix issue 86479: AI core deconstruction keeps the spherical posibrain type":

- `ai_defines.dm`: new var `posibrain_type`, defaulting to `/obj/item/brain_processor/positronic`.
- `_core.dm`: in `ai_structure_to_mob()`, and in the card-to-core `transfer_ai` path, when the AI has a posibrain and `core_mmi.type` is a subtype of `/obj/item/brain_processor/positronic`, `posibrain_type` is set to `core_mmi.type`.
- `ai.dm`: `make_mmi()` now does `new posibrain_type(destination, FALSE)`.

The approach keeps the existing recreate-on-deconstruct design and only remembers the type. Keeping a reference to the original item was not tried.

## Verification

After the fix the test server was rebuilt and restarted, and the same Lua sequence was run. The resulting core's `core_mmi.type` was `/obj/item/brain_processor/positronic/sphere`, with icon state `spheribrain`. The new round's runtime log contained no new runtimes.

Not checked:
- The card-to-core `transfer_ai` path was changed but not exercised.
- Deconstruction by a player's tools was not done.
- Other positronic subtypes (for example the display brain) were not tested.

## Notes

- An AI that never sat in a core (for example a human turned into an AI with `AIize()`) still returns the default cube, since there is no original type to remember.
- An organic MMI is still recreated from scratch (a fresh `/obj/item/organ/brain`), so brain identity and MMI type are not preserved. That is outside this issue.
- The issue discussion mentions #69941 (posibrains turning into MMIs). It was not investigated here.
