# #72705: Full auto guns fire the offhand gun on every shot, outside combat mode and at the full auto rate

## Summary

Three dual-wield problems share one code area. An automatic gun (`/datum/component/automatic_fire`) fired the gun in the other hand on every autofire tick, without checking combat mode or `TRAIT_NO_GUN_AKIMBO`, so the offhand gun fired at the automatic gun's rate (#72705). Akimbo shots from the offhand gun called `process_fire()` directly, which skipped the ballistic bolt-lock and empty-alarm handling that lives in `fire_gun()`, so offhand guns never locked back when empty (#80970). The autofire cooldown was stored per gun, so swapping hands between two automatic guns gave the other gun a fresh cooldown and raised the combined fire rate (#83428). The branch has one commit for each.

## The bug

### #72705

A player holding a full auto gun (for example a WT-550) in the active hand and any other gun in the other hand, who holds the mouse button down, also fires the other gun. It fires once per shot of the automatic gun, at the automatic gun's rate. The issue's example is a laser gun that fires at full auto speed. It also happened with combat mode off and for people wearing the MOD module that sets `TRAIT_NO_GUN_AKIMBO`, although manual akimbo firing is limited to combat mode and respects that trait. The reporter also remarks that burst-fire guns in the offhand would fire whole volleys at the autofire rate; this was not tested (see Notes).

### #80970

With two guns that rack or lock back when empty (the Makarov, the Ansem, the foam force pistol), only the gun in the main hand locks its bolt back after its last shot. The offhand gun stays in its "loaded" state. The empty-gun alarm also does not play for the offhand gun.

### #83428

Two automatic guns that cannot normally be fired akimbo (the disabler SMG, the Cybersun S-120; the laser carbine at the time of the report) fire faster than either gun alone when the player alternates between them: click to fire, swap hands, click, swap, and so on. The report says this works with or without combat mode and with no spread penalty. The cause is the cooldown (below). The accuracy part of the report is not a separate bug. These guns are created with `allow_akimbo = FALSE`, so they never took the akimbo spread.

## Reproduction

### #72705

1. On the test server, spawn a WT-550 autorifle and a Type 5 laser gun (a charged one) and put the WT-550 in the active hand and the laser gun in the other hand. Combat mode off.
2. Hold the left mouse button on a floor tile a few tiles away for about 3 seconds.
3. Read the chat log. The WT-550 line "You fire the WT-550 Autorifle!" and the laser line "You fire the Type 5 laser gun!" appeared in equal numbers. In one run both appeared 13 times. In a later 3 second run on the same setup both appeared 10 times. The laser gun has `fire_delay = 0`, so nothing limits it except the WT-550's cadence.
4. Hold for 1 second with combat mode off: the laser gun still fired with every WT-550 shot.

Using the Lua editor, the guns were created and given to the test mob directly and combat mode was toggled with `set_combat_mode`. The firing itself was done with real mouse presses.

### #80970

Reading the code showed the cause (below). Only the fixed build was tested in game; the unfixed behavior is from the code, not from an observation.

1. Spawn two Makarov pistols, one in each hand, and turn combat mode on.
2. Click at a nearby tile repeatedly until both are empty.
3. Check `bolt_locked` on each gun (Lua editor or View Variables). On the unfixed code it is expected to be 0 on the offhand gun (code reading).

### #83428

The real-time exploit could not be measured, because each tool call takes about 0.7 s, far more than the 0.15 s autofire delay. The mechanism was reproduced instead, with the fire rate slowed down:

1. Spawn two disabler SMGs (`/obj/item/gun/energy/disabler/smg`, autofire delay 0.15 s, `allow_akimbo = FALSE`), one in each hand.
2. With the Lua editor, set `autofire_shot_delay = 40` (4 seconds) on both guns' `automatic_fire` components and `next_shot_cd = 0`. This makes the cooldown easy to observe.
3. Click once with gun A (fires). Click again immediately (no shot, the cooldown is running). Press the swap-hands key. Click with gun B (fires). Click again (no shot).
4. Result on master: two shots within about 3 seconds, although each gun alone cannot fire more than once per 4 seconds.

## Cause

### #72705

`/obj/item/gun/proc/do_autofire_shot` (`code/datums/components/fullauto.dm:319`) runs for each autofire tick. It fetches the inactive-hand item and, if it is a gun, schedules it to fire 0.1 seconds later:

```dm
var/obj/item/gun/akimbo_gun = shooter.get_inactive_held_item()
var/bonus_spread = 0
if(istype(akimbo_gun) && weapon_weight < WEAPON_MEDIUM && allow_akimbo)
    if(akimbo_gun.weapon_weight < WEAPON_MEDIUM && akimbo_gun.can_trigger_gun(shooter))
        ...
        addtimer(CALLBACK(akimbo_gun, TYPE_PROC_REF(/obj/item/gun, process_fire), target, shooter, TRUE, params, null, bonus_spread), 0.1 SECONDS)
```

(lines 322-328). The manual akimbo path in `fire_gun()` (`code/modules/projectiles/gun.dm:433`) only does this when `user.combat_mode && !HAS_TRAIT(user, TRAIT_NO_GUN_AKIMBO)`, and it calls `can_trigger_gun(user, akimbo_usage = TRUE)` (`gun.dm:440`). The autofire path had neither check. The offhand gun is only limited by its own `fire_delay` inside `process_fire`, which is 0 for the laser gun, so it fires at the main gun's rate. `akimbo_usage` matters because some guns refuse akimbo use: the dueling pistols, the Russian roulette and reverse revolvers, and the tesla cannon override `can_trigger_gun` for it.

### #80970

`postfire_empty_checks()` (bolt lock-back, empty alarm) and `prefire_empty_checks()` (open-bolt drop) are called only in `/obj/item/gun/ballistic/fire_gun` (`code/modules/projectiles/guns/ballistic.dm:692-695`, helpers at 675-690). The akimbo shots for the other gun are queued directly on `process_fire` (`gun.dm:447-449` for manual combat-mode akimbo, `fullauto.dm:328` for autofire), so `fire_gun()` never runs for the offhand gun and the ballistic checks are skipped. The checks are the code that locks the bolt back, so an offhand gun that ran out of ammo never did.

### #83428

`next_shot_cd` is declared on each automatic fire component (`fullauto.dm:33`), and `process_shot()` checks and restarts it (`fullauto.dm:255` and `:273`). Each gun has its own component, so the cooldown belongs to the gun, not to the shooter. Swapping hands stops autofiring (`COMSIG_MOB_SWAP_HANDS` is registered at `fullauto.dm:185`), and the first shot after a mouse-down is processed immediately (`fullauto.dm:195`). So click-swap-click-swap with two guns gets a first shot from each gun without waiting for either one's cooldown.

## Fix

The branch has three commits, one per issue, on top of master `87b93338`.

- **Fix issue 72705: Autofire akimbo only fires the offhand gun in combat mode.** `do_autofire_shot` now applies the same conditions as `fire_gun()`: `shooter.combat_mode && !HAS_TRAIT(shooter, TRAIT_NO_GUN_AKIMBO)`, and it passes `akimbo_usage = TRUE` to `can_trigger_gun`. Outside combat mode, or with the trait, only the main gun fires. The change is small and reuses the existing akimbo rules.
- **Fix issue 80970: Offhand akimbo guns now run the ballistic empty checks.** A new proc `/obj/item/gun/proc/fire_akimbo(target, user, params, bonus_spread)` (`gun.dm`) just calls `process_fire`. `/obj/item/gun/ballistic/fire_akimbo` (`ballistic.dm`) wraps it with `prefire_empty_checks()` and `postfire_empty_checks()`, like `fire_gun()`. The akimbo timers in `gun.dm` and `fullauto.dm` call `fire_akimbo` instead of `process_fire`. Only the ballistic override adds the extra checks; other gun types behave as before. `fire_gun()` was not called for the offhand gun, since it also does the click-level handling (including the akimbo logic itself) that should not run again for the extra gun.
- **Fix issue 83428: Autofire guns share their fire rate cooldown across hands.** A new cooldown `next_autofire_shot_cd` on `/mob/living` (`living_defines.dm`). `process_shot` returns early (and keeps autofiring) if the shooter's cooldown is still running, and starts it with the same delay as the gun's own `next_shot_cd`. For a single gun nothing changes, because both cooldowns start together and have the same length. After a swap, the other gun has to wait out the remaining delay of the previous one.

## Verification

All checks were made on the test server with the fixed build, with real mouse presses and the Lua editor for setup and reading values.

- **#72705:** the WT-550 in the active hand and the laser gun in the other. With combat mode off and the mouse held for 2 seconds, only "You fire the WT-550 Autorifle!" lines appeared, no laser lines. With combat mode on, both guns fired, in equal numbers.
- **#80970:** two Makarovs with combat mode on, clicked until both were empty. Both guns had `bolt_locked = 1` at the end, the offhand gun included. The unfixed behavior was not observed in game.
- **#83428:** the slowed-down setup above. With the fix, the click A / click A / swap / click B / click B sequence produced exactly one shot in the attack log, against two shots on master. Normal hold-fire still works: with the delay set to 3 (0.3 s) and the mouse held for about 8 seconds, about 27 shots were fired, and the runtime log showed no runtimes.

Not checked:

- The real-speed exploit from the video (spamming clicks and swaps at human speed) was not reproduced or re-tested, only the cooldown mechanism with a 4 second delay.
- The laser carbine from the report is not an autofire gun on master (see Notes), so it was not tested; the disabler SMG was used as the example of a gun with this component.
- Burst-fire guns in the offhand, two automatic guns, and the Cybersun S-120 were not tested.
- Other autofire guns (such as the minigun and its windup behavior) were not re-tested with the shared cooldown beyond the disabler SMG hold-fire check.

## Notes

- With combat mode on, the offhand gun still fires on every autofire tick of the main gun. The fix does not change that. It treats it as the existing akimbo design, and the offhand gun is still limited by its own `fire_delay`. If the maintainers want the offhand to have an independent, slower rate, that needs a separate decision. The spread of the autofire offhand shot is still the flat `dual_wield_spread`, without the scaling used by manual akimbo (`AKIMBO_PENALTY_SCALING`).
- On master the laser carbine (`/obj/item/gun/energy/laser/carbine`, `laser.dm:82`) is a burst-fire gun (`burst_size = 2`) with `weapon_weight = WEAPON_MEDIUM`, not an autofire gun. The guns on master that have the autofire component with `allow_akimbo = FALSE` that the report describes are the disabler SMG (`stun.dm:54`) and the Cybersun S-120 (`laser.dm:105`).
- The shared cooldown means that swapping from a fast gun to a slower gun makes the slower gun wait for the fast gun's delay, not its own. This was judged acceptable.
- The #72705 reporter's comment that two automatic guns "might be increasing the fire rate exponentially" was not investigated separately. From the code, only the gun in the active hand has a running autofire component, and the other gun is fired through `process_fire` on a timer. The swap-hands cooldown reset (#83428) is one way two automatic guns could add up.
- PR #87415 (merged 2024-10-24, "fixed akimbo firing automatic guns runtiming on the offhand gun when it's empty") only changed the empty-gun handling in `fullauto.dm`. It did not fix #80970 (which concerns the manual combat-mode akimbo path as well) or #72705. An earlier upstream PR, #79359, which the investigation checked, did not cover the autofire path either.
