## Summary

When a deathmatch ends through `end_game()` (the last player standing wins, or the game times out), every remaining player's arena body is ghosted with `can_reenter_corpse = FALSE`. That clears the ghost's mind, so the `temporary_body` component, which is supposed to hand the player's original mind back when the arena body is deleted, cannot find any ghost, logs a stack trace and gives up. The player is left as a ghost with no mind, and "Re-enter Corpse" says "You have no body." The fix ghosts the arena body normally so the component can find the ghost and restore the old mind. A second change, for #93349, makes the ghost that comes back from a temporary body take the name and hair of the old body instead of keeping the arena character's.

## The bug

### #90620 and #87438: "You have no body" after deathmatch

A player who is dead (a ghost with a corpse) opens or joins a deathmatch lobby and plays. Afterwards they expect to be able to use "Re-enter Corpse" to go back to their original body (the lobby warns that this may not always work, per a comment on #87438, but it is meant to). Instead the verb says "You have no body." The ghost is no longer connected to the old body at all. #90620 reports this after winning a deathmatch; #87438 reports the same message after playing and being revived. Commenters on #87438 suggested being possessed in a wizard deathmatch with a possession bolt as the trigger; that path was not examined (see Notes).

### #93349: wrong ghost appearance

A player who died as something other than their preferences character (the issue uses a xenomorph), then plays a deathmatch and dies in it, comes back as a ghost that looks like their preferences character (the arena body), not like the xenomorph they died as.

## Reproduction

Everything below was done on the test server with admin tools. The deathmatch lobby was created and force-started by admin tools instead of through a normal lobby with a second player, and the game was ended by calling `end_game()` on the lobby with the Lua editor, which is the same function the game calls when the last opponent dies or the timer runs out. The winner path was therefore reproduced by calling the proc directly, not by actually fighting.

### #90620 (winner path)

1. As an admin, used the Lua editor to make a dead human with a mind (named "Corpse Guy"), and ghosted it normally (`can_reenter_corpse` TRUE), so the player is a ghost with a body to return to.
2. Created a deathmatch lobby for the ghost (`create_new_lobby`) and force-started it from the lobby window's admin "Force start" function.
3. In the arena, using the Lua editor, checked that the player had a new character with a new mind and a `/datum/component/temporary_body` whose `old_mind` was "Corpse Guy" and whose `old_body` was the corpse.
4. Called `end_game()` on the lobby with the Lua editor. The game announced "THE GAME HAS ENDED. THE WINNER IS: ...".
5. Observed:
   - The runtime log showed `/datum/component/temporary_body belonging to <the arena character> was completely unable to find a ghost to put back into a body!` (a stack trace from `code/datums/components/temporary_body.dm:84`).
   - The player's ghost had `mind = null`.
   - Using the "Re-enter Corpse" verb printed "You have no body." and nothing moved.

With the fix (below), the same steps ended with "Re-enter Corpse" moving the player back into the old body.

### #87438

The reported symptom (the "You have no body" message after deathmatch) is the one observed above. The possession bolt scenario was not tried.

### #93349

1. Spawned an alien hunter with a mind named "Corpse Guy", moved the client into it (`transfer_to`), killed it and ghosted it, so the ghost was named "Corpse Guy" with no hairstyle.
2. Created and force-started a deathmatch lobby for that ghost, as above, and let the arena character die (`death()`), which goes through the lobby's normal `player_died` path.
3. Observed on the lobby-only fix: the resulting ghost was named after the arena character and had the arena character's hairstyle ("Shorter Long Bedhead"), while its mind was correctly "Corpse Guy" again. The expected result was a ghost named "Corpse Guy" with no hairstyle, as before the deathmatch.

## Cause

### #90620

At master, `/datum/deathmatch_lobby/proc/end_game()` does this to every player still in the game (`code/modules/deathmatch/deathmatch_lobby.dm:187-193`):

```dm
loser.ghostize(can_reenter_corpse = FALSE)
qdel(loser)
```

(`deathmatch_lobby.dm:192`.) `ghostize()` with `can_reenter_corpse = FALSE` creates the ghost and then sets `ghost.mind = null` (`code/modules/mob/dead/observer/observer.dm:286-287`). The arena body got a `/datum/component/temporary_body` when the player joined (`deathmatch_lobby.dm:143-146`), and that component hands the old mind back from `return_mind()` when the arena body is deleted (`code/datums/components/temporary_body.dm:78-96`):

```dm
var/mob/new_body = parent
var/mob/dead/observer/ghost = new_body.get_ghost() || new_body.ghostize(forced = TRUE)
if(QDELETED(ghost))
	stack_trace("... completely unable to find a ghost to put back into a body!")
	qdel(src)
	return

ghost.mind = old_mind
```

`get_ghost()` looks for an observer whose `mind` is the arena body's mind (`code/datums/mind/_mind.dm:460-466`). After `ghostize(FALSE)` there is none, and the fallback `ghostize(forced = TRUE)` returns nothing because the arena body no longer has a key (the key moved to the ghost). So `return_mind()` takes the stack trace branch, never runs `ghost.mind = old_mind`, and the player's ghost keeps `mind = null`. "Re-enter Corpse" starts with `if(!mind || QDELETED(mind.current))` and prints "You have no body." (`observer.dm:367-369`).

Only this path is affected. When a player dies in the arena, `player_died()` (`deathmatch_lobby.dm:208-237`) ghosts them with plain `ghostize()`, so the ghost keeps the arena mind and `return_mind()` can find it. Winners and timeouts go through `end_game()`, which is the path the issue's "Win deathmatch" step hits.

### #93349

When the arena character dies, `player_died()` ghosts the body, so `/mob/dead/observer/Initialize()` builds the ghost from the arena body: name from the arena mind and hairstyle/colours from the arena human (`observer.dm:98-120`). `return_mind()` then reuses that same ghost and only swaps `ghost.mind` to the old mind (`temporary_body.dm:88`). The ghost's name and hair therefore stay those of the arena character, not those of the old body (a xenomorph in the report).

## Fix

Two commits on the branch.

**"Fix issue 90620: deathmatch winners can re-enter their old body again"** changes `end_game()` to ghost with the default `can_reenter_corpse` (`loser.ghostize()`), with a comment explaining why. The ghost then keeps the arena mind, `return_mind()` finds it when the arena body is deleted on the next line, and sets `ghost.mind = old_mind`, which also reconnects the ghost to the old body. This is a one-line change that makes `end_game()` behave like the existing death path. The alternative of teaching `return_mind()` to find the player's ghost by key or by the old mind was not tried; it would change shared code for a problem in one caller.

**"Fix issue 93349: returning from a temporary body gives the ghost the old body's looks"** changes `temporary_body.return_mind()` so that, after setting the old mind, it copies the old body's appearance onto the ghost:

- The code that sets a ghost's gender, name, and hair from a body was moved out of `/mob/dead/observer/Initialize()` into a new proc, `/mob/dead/observer/proc/copy_appearance_from_body(mob/body)`. It also sets `real_name` and resets the hair variables to their defaults before copying, so a body without hair does not leave the previous hair behind. `Initialize()` now calls it.
- `return_mind()` calls it with the old body when there is one. If the old body is gone, it renames the ghost from the old mind (`ghostname`, then `name`). It then calls `update_appearance()` on the ghost.

Factoring out the copy, rather than duplicating it in the component, keeps ghost creation and ghost return using the same rules.

## Verification

Checked on the test server after the fix:

- **#90620, winner path:** with the lobby change built, `end_game()` on a force-started lobby, followed by "Re-enter Corpse", moved the player back to the old body (the character with the "Corpse Guy" mind). No stack trace this time.
- **Baseline for comparison:** an unfixed run of the same steps (ghost with mind nil, the `temporary_body` runtime at line 84, "You have no body.") is described under Reproduction.
- **#93349, loser path, on the final build (both commits):** the alien hunter corpse's ghost was "Corpse Guy" with no hairstyle. After joining a deathmatch and dying in the arena, the ghost was again "Corpse Guy" with no hairstyle (before the second commit it carried the arena character's name and hairstyle).

Not checked:

- The winner path was **not re-run on the final build** with both commits. It was run with the lobby commit only. It uses the same `return_mind()` code as the loser path, which was re-run.
- A **living** old body (the `reenter_corpse()` call in `return_mind()` is unchanged by the fix, but was not exercised).
- The **timeout** ending, a deathmatch with more than one player, and the **possession bolt** scenario from #87438.
- Other users of `temporary_body`; see Notes.
- A normal player win from actual combat; `end_game()` was called directly.

## Notes

- `temporary_body` is used by more than deathmatch: capture the flag, bitrunning, mafia, basketball, the cult rune, changeling absorption, and dream projection also add it (`git grep temporary_body` at master). The #93349 change alters the ghost that comes back from any of them: it now takes the old body's name and hair. That is the intended behaviour, but it was not exercised outside deathmatch.
- The fix for #90620 depends on the ghost being left with the arena mind until the body is deleted. If `end_game()` is ever changed to remove the arena body's key or mind first, the same stack trace will come back.
- #87438's comments blame the temporary body component and suggest the wizard possession bolt. If a body is possessed away from its player the component may be unable to give the mind back for a different reason. That scenario was not tried, so this fix is only confirmed against the `end_game()` cause, which does match the message in #87438. Whether #87438 was caused by the same code at the time it was filed (2024) was not checked.
- #90620's reporter remembers an earlier fix that stopped deathmatch from disconnecting souls. No upstream pull request touching this was found by title search; the history of the `ghostize(can_reenter_corpse = FALSE)` line was not traced.
