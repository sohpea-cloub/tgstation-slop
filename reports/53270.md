## Summary

Using an iron sheet on a reagent tank turns it into a plumbed "stationary" tank. The new tank's name is set to "stationary [name]" once, and the plumbed tank types have a fixed name, description and icon. Wrenching the tank loose therefore leaves a movable tank that still calls itself stationary and still has the stationary icon. The fix makes plumbed tanks remember the name, description and icon of the tank they were made from, and show those while unanchored and the stationary versions while anchored.

## The bug

On a station, click a water tank (or fuel tank) with an iron sheet. It becomes a plumbed tank named "stationary water tank". Wrench it loose and it can be dragged around, but it keeps the "stationary" name, the stationary icon and the "A stationary, plumbed ..." description. The reporter asks for a way to lose the "stationary" name and overlay, for example by letting a wrench reset it. The only comment on the issue points at the code that does the conversion.

## Reproduction

The behavior was not run in game before the fix, because the cause was clear from the code. The after-fix check below used the same setup and is the only runtime evidence. To reproduce on master with admin tools:

1. Spawn a fuel tank (`/obj/structure/reagent_dispensers/fueltank`) and an iron sheet next to a human.
2. Use the iron sheet on the tank. On master the tank is replaced by a `/obj/structure/reagent_dispensers/plumbed/storage` named "stationary [original name]".
3. Wrench it down and wrench it loose again (or call `set_anchored` on it with TRUE and then FALSE using the Lua editor or ProcCall).
4. Read the tank's `name`, `desc`, `icon_state` and `anchored` variables with View Variables. Based on the code, `name` is still "stationary ..." and `icon_state` is still the stationary icon while `anchored` is 0.

## Cause

In `code/modules/reagents/reagent_dispenser.dm`, `item_interaction()` handles the iron sheet case (lines 114-124). It makes a new plumbed storage tank, copies the reagents over, and then does:

```dm
new_tank.name = "stationary [name]"
new_tank.update_appearance(UPDATE_OVERLAYS)
new_tank.set_anchored(anchored)
```

That sets the name once, and nothing ever changes it again. The plumbed types (`/obj/structure/reagent_dispensers/plumbed`, `.../storage`, `.../fuel`, lines 718-761) have a fixed `name`, `desc` and `icon_state` ("stationary water tank", "water_stationary", "fuel_stationary" and so on). The wrench handler for these tanks, `plumbed/wrench_act()` (lines 729-732), calls `default_unfasten_wrench()`, which toggles anchoring with `set_anchored(!anchored)` (`code/game/objects/objs.dm:288-310`). Nothing reacts to `set_anchored()` on a plumbed tank, so the appearance never follows the anchored state.

## Fix

One commit, "Fix issue 53270: unwrenched stationary tanks no longer claim to be stationary", in `code/modules/reagents/reagent_dispenser.dm`:

- `/obj/structure/reagent_dispensers/plumbed` gets three new variables, `mobile_name`, `mobile_desc` and `mobile_icon_state`, with defaults for a water tank ("water tank", "A water tank.", "water"). The storage and fuel subtypes override them (`storage`: "storage tank" and `tank_stationary`; `fuel`: "fuel tank", "A tank full of industrial welding fuel. Do not consume.", "fuel").
- `item_interaction()` no longer builds the name by hand. It copies the source tank's `name`, `desc` and `icon_state` into the new tank's `mobile_*` variables, calls `set_anchored(anchored)`, then `update_appearance()`.
- The plumbed type overrides `set_anchored()` to call `update_appearance(UPDATE_NAME | UPDATE_DESC | UPDATE_ICON_STATE)`, and overrides `update_name()`, `update_desc()` and `update_icon_state()`. While anchored the name is "stationary [mobile_name]", the description is "A stationary, plumbed, [mobile_name]." and the icon is the type's own stationary icon. While unanchored they are `mobile_name`, `mobile_desc` and `mobile_icon_state`.

The approach follows the anchored state instead of the wrench action, so every route that changes anchoring (wrench, admin tools, code) gives the right appearance. The alternative of resetting state from `wrench_act()` was not used for that reason. The mapped-in plumbed tanks (stationary water tank, fuel tank and storage tank) get defaults, so they also change when unwrenched.

## Verification

On the test server, after building the fix:

1. Spawned a fuel tank and an iron sheet using the Lua editor and called `item_interaction()` on the tank as a human. The new tank was a `plumbed/storage` and, since the source tank was unanchored, showed "fuel tank", "A tank full of industrial welding fuel. Do not consume.", icon `fuel`, `anchored` 0.
2. `set_anchored(true)`: name "stationary fuel tank", description "A stationary, plumbed, fuel tank.", icon `tank_stationary`.
3. `set_anchored(false)`: back to "fuel tank" with the `fuel` icon.

Not checked: the real wrench action with its delay (`set_anchored()` was called directly, which is what the wrench action calls at the end); the original unfixed behavior in game; water tanks and other source tank types (only a fuel tank was converted); mapped-in stationary tanks being unwrenched; the visible icon with a chemical color overlay on a client.

Known limitation: a storage tank with no origin (a mapped-in `plumbed/storage`) has no movable-tank art, so after unwrenching it keeps the `tank_stationary` icon and only its name changes ("storage tank").

## Notes

- The final icon choice for a converted tank is the source tank's own icon (`fuel`, `water`, ...). Source tanks with other icons (for example `water_high`, or the April Fools icon swap at line 60) were not checked individually, though the fix copies whatever `icon_state` the source tank had.
- Every converted tank becomes a `plumbed/storage` tank whatever the source type was (`item_interaction()` always creates that type), so while anchored it uses the storage tank icon (`tank_stationary`), as seen in the verification above, not the `fuel_stationary` or `water_stationary` art. Only its unanchored name, description and icon come from the source tank.
- The chemical color overlay in `plumbed/storage/update_overlays()` (lines 744-754) was not changed. The fix calls `update_appearance()` with all update flags once after conversion, which includes overlays, but the overlay was not checked on screen.
