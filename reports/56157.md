# #56157: Wall-like structures on the lower z level cannot be stood on from above open space

| | |
|---|---|
| Issues | [#56157](https://github.com/tgstation/tgstation/issues/56157): verified, fixed<br>[#92532](https://github.com/tgstation/tgstation/issues/92532): verified, fixed (same cause: false walls and the mime's invisible wall) |
| Status | Fixed on the fix branch; fix checked in game (on an artificially linked pair of z levels, see Verification) |
| Fix branch | [fix/56157](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/56157) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Open space only holds a mob up over a tile on the z level below if that tile is a closed turf or contains an object with the `BLOCK_Z_IN_DOWN` flag. Full-tile windows, closed doors, false walls, mineral doors, resin walls and the mime's invisible wall do not set that flag, so a mob walking over open space above them falls into them instead of standing on them as it does over a real wall. The fix sets `BLOCK_Z_IN_DOWN` on those objects (and clears it again while a door or false wall is open).

## The bug

On a station with multiple z levels, a mob that walks onto an open-space tile above a wall turf stays on the upper level. The same walk onto an open-space tile above a full-tile window, a closed airlock, a false wall, a resin wall or an invisible wall (#92532) makes the mob fall down a level, ending up on the tile that holds the structure. #56157 asks for these to behave like walls; #92532 reports the same for false walls and mime walls.

## Reproduction

Metastation has no multiple z levels, so the test linked two existing levels by hand with the Lua editor. This tests the movement rule, not an actual multi-z map such as Icebox.

1. With the Lua editor, set the multi-z links in `SSmapping.multiz_levels` so that z2 (the station level) has z1 (CentCom) as its level below, and z1 has z2 above: `multiz_levels[2][2] = 1` and `multiz_levels[1][1] = 1`.
2. For each case, on z1 at `(x, 144)`: make plating and put the structure on it (or, for the control, a wall turf instead).
3. On z2 at `(x, 144)`: change the turf to `/turf/open/openspace`.
4. Spawn a human on plating at `(x, 145, 2)`, move it onto the openspace tile, and read `human.z`. If `z` is 1 the human fell; if it is 2 it stood.

Results on master (`87b93338`):

| Object on the lower tile | z after moving onto the openspace |
|---|---|
| plating only (control) | 1 (falls, as expected) |
| wall turf | 2 (stands) |
| full-tile window | 1 (falls into it) |
| reinforced full-tile window | 1 |
| false wall (closed) | 1 |
| resin wall | 1 |
| closed airlock | 1 |
| mime wall (`/obj/effect/forcefield/mime`) | 1 |
| iron mineral door (closed) | 1 |
| table | 1 (expected: not wall-like) |

This was reproduced by moving a mob directly onto the tile with admin tools, not by a player's key presses.

## Cause

Moving down a z level goes through `can_z_move()` in `code/game/atoms_movable.dm`, which at line 467 requires `start.zPassOut(direction) && destination.zPassIn(direction)`. For a lower tile that is a closed turf, `/turf/proc/zPassIn()` (`code/game/turfs/turf.dm:333`) returns `FALSE`, so nothing can enter it from above and a mob on the openspace above is held up. For an open (floor) tile, `/turf/open/zPassIn()` (`code/game/turfs/open/_open.dm:149`) only refuses if one of the objects on it has `BLOCK_Z_IN_DOWN`:

```dm
/turf/open/zPassIn(direction)
	if(direction != DOWN)
		return FALSE
	for(var/obj/on_us in contents)
		if(on_us.obj_flags & BLOCK_Z_IN_DOWN)
			return FALSE
	return TRUE
```

`/turf/open/openspace/zPassIn()` (`code/game/turfs/open/openspace.dm:90`) has the same check. On master, the wall-like object that sets `BLOCK_Z_IN_DOWN` is the foamed metal wall (`effects_foam.dm:351`); the other places that set it are not wall-like (a search of `code/` for the flag found nothing for windows, doors, false walls, resin or forcefields). Windows, doors, false walls, resin and forcefields are structures or effects standing on an open turf and do not set the flag, so the check does not stop the fall.

## Fix

One commit, "Fix issue 56157: wall-like structures can be stood on from the z level above". It sets `BLOCK_Z_IN_DOWN` on:

- Full-tile windows: in `window.dm` `Initialize()`, inside the `fulltile` branch. Directional windows are untouched.
- Doors (`/obj/machinery/door`, `door.dm`): a new `update_z_block()` sets the flag while the door is dense and not an `ON_BORDER_1` object (so windoors are excluded). It is called from `Initialize()` and from `set_density()`, so it follows the door opening and closing.
- False walls (`false_walls.dm`): a new `update_z_block()` sets the flag while the false wall is dense, called from `Initialize()` and after `toggle_open` flips the density.
- Mineral doors (`mineral_doors.dm`): set in `Initialize()` (they start closed), cleared in `Open()` and set again in `Close()`.
- Alien resin (`aliens.dm`): in `/obj/structure/alien/resin/Initialize()` when `resintype` is set, which covers resin walls and membranes but not other resin structures such as flower buds.
- Forcefields (`forcefields.dm`): in `/obj/effect/forcefield/Initialize()`, which covers the wizard forcewall and the mime's invisible wall (#92532).

A per-type flag follows how metal foam already does it. A broader alternative (making every dense object block, or checking density in `zPassIn()`) was not tried and would affect tables, machines and other dense objects that should not be stood on.

## Verification

The same test was run on a build of the fix branch. Results:

- Stand (z = 2): wall turf, full-tile window, reinforced full-tile window, false wall, resin wall, resin membrane, closed airlock, mime wall, wizard forcefield, closed iron mineral door.
- Still fall (z = 1), as intended: the plating control, a table, an open airlock (it had density 0 and no `BLOCK_Z_IN_DOWN` in `obj_flags`), a windoor, a directional window, and a false wall after it was opened (`toggle_open`).
- No new runtimes were logged.

Not checked: a real multi-z map (Icebox); the airlock open-then-close transition in game (it goes through the `set_density()` hook, which was not exercised for that transition); shutters and firedoors (they share the door change, which was only read, not tested); playing out the fall or standing with real movement input; a fulltile window built or destroyed during play.

## Notes

- The forcefield change is on the base class, so every `/obj/effect/forcefield` subtype gets the flag, including types that are not dense. `/obj/effect/forcefield/cosmic_field` (the heretic's trail) is `density = FALSE` and inherits the flag; it was not tested whether that makes mobs hover over open space above it. A maintainer may prefer to limit the flag to dense forcefields or to set it only on the wizard and mime subtypes.
- The wizard forcewall (a different subtype) also holds mobs up now; the test confirmed that and it seems consistent with "solid like a wall".
- Which objects should be standable is a design decision: only the closed-door states, full-tile windows, resin and the walls listed above were included; the issue's title says "structures similar to walls", so other candidates (for example grilles or machines) were left out.
