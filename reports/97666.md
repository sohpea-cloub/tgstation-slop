## Summary

The examine text of a pressure tank with an open port says "The pipe port can be moved or closed with a wrench", but a wrench never moves a port. It toggles the port on the side the user stands on, so several ports can be open and a "move" is really closing one and opening another. The fix rewrites the examine hints to describe this. Behaviour was left unchanged, because tanks with several open ports are used for chambers.

## The bug

The reporter built an omni pressure tank, opened a port, tried to move it with the wrench as the description says, and could not. The issue title mentions the "third layer"; that is the tank's fixed pipe layer and is unrelated to the behaviour.

## Reproduction

Done with the Lua editor on the test server, by calling the procedure the wrench calls rather than using a real wrench (the Lua editor cannot wait out the tool's use delay).

1. Spawn `/obj/machinery/atmospherics/components/tank`. Initially `initialize_directions` is 0 and no port is open.
2. Call `toggle_side_port(NORTH)`: `initialize_directions` becomes 1 (north open).
3. Call `toggle_side_port(EAST)`: it becomes 5 (north and east both open).
4. Call it with NORTH again: 4 (east only). With EAST again: 0 (none open).
5. The same sequence with `dir = EAST` as the tank's direction behaved the same.

Each call toggles one side only; several ports can be open at once; no call moves a port.

## Cause

`wrench_act` (`code/modules/atmospherics/machinery/components/tank.dm:369`) takes `get_dir(src, user)` (ignoring diagonals), waits 3 seconds with the tool, then calls `toggle_side_port(new_dir)` (`tank.dm:214`, called at line 380), which enables or disables only that side. The examine hint (`tank.dm:129`) for a tank that already has a port said:

```dm
. += span_notice("The pipe port can be moved or closed with a [wrench_hint].")
```

which describes a single port that can be relocated, a behaviour the tank does not have.

## Fix

One commit, "Fix issue 97666: pressure tank examine text no longer claims the wrench moves the pipe port". The two examine hints now read:

- no port open: "A pipe port can be opened on the side you are standing on with a wrench."
- a port open: "A pipe port can be opened or closed on the side you are standing on with a wrench. Moving a port means closing it and opening another."

Alternative considered and not done: change `wrench_act` so that a wrench closes the existing ports first, making "move" literally true for single-port tanks. That would break tanks built with several ports, which chambers rely on.

## Verification

After rebuilding, examining a spawned tank in game showed the new hints (the no-port and the open-port wording). The toggle behaviour is as in Reproduction; no behaviour changed.

Not checked: a real wrench use on the tank (including the 3-second use delay and the standing-side logic in `wrench_act`); only the procedure it calls was exercised.

## Notes

- The real question for maintainers is whether the port should be movable. If so, a possible design is a single-port mode, or moving the one open port when the wrench is used from a different side; this needs a decision about multi-port chambers.
- The text change is the minimal correction; it does not add any new interaction.
