# #87753: Drinking glass keeps the previous drink's sprite under a fill overlay

| Status | Fixed on a branch; verified by reading `icon_state`, name and overlay values in game (not by looking at a render) |

## Summary

A drinking glass that holds a small amount of a drink with its own glass sprite (rum) and is then filled mainly with a drink that has no sprite of its own (pineapple juice) keeps the rum sprite. The generic fill overlay is then drawn over the rum glass. The cause is in `takes_reagent_appearance`: it reset the container's icon only when there was no glass style at all, not when the new style changed only the name and description. The fix resets the icon whenever the style has no icon and icon state.

## The bug

Drinking glasses change their sprite to match the drink inside. Some drinks, such as pineapple juice, have a glass style that only sets the name and description, so the glass should show the default glass sprite with the colored fill overlay, like a beaker. If the glass previously held a drink with its own sprite and that drink stops being the majority reagent, the old sprite stays and the fill overlay is drawn over it.

## Reproduction

1. On the test server, as an observer or admin, spawn `/obj/item/reagent_containers/cup/glass/drinkingglass`.
2. Using the Lua editor, add 10 units of rum. The glass's `icon_state` became `rumglass`, and `fill_icon_thresholds` was nil, so there is no fill overlay.
3. Add 30 units of pineapple juice (it is now the majority reagent).
4. Read the glass's variables. `name` was "glass of pineapple juice" and `fill_icon_thresholds` was a list again, so the fill overlay was re-enabled. `icon_state` was still `"rumglass"`, so the fill was drawn over the rum sprite. This matches the issue's screenshots.

The glass was filled by adding reagents directly with the Lua editor, not by pouring drinks as a player would.

## Cause

`/datum/component/takes_reagent_appearance/proc/update_icon()` (`code/datums/components/takes_reagent_appearance.dm:134`) handled two cases:

```dm
if(isnull(style))
	// no style (reset)
	item_parent.icon = icon_pre_change
	item_parent.icon_state = icon_state_pre_change
else if(style.icon && style.icon_state)
	// style
	style.set_appearance(item_parent)
	...
```

The icon was restored only for `style == null` (line 136). The pineapple juice style (`/datum/glass_style/has_foodtype/drinking_glass/pineapplejuice`, `code/modules/reagents/chemistry/reagents/drinks/glass_styles/juices.dm:42`) is not null, but it has a name and description and no icon or icon state. It matched neither branch, so the icon was neither set nor reset and the previous drink's `icon_state` stayed. The `on_icon_reset` callback that follows does run for this case and restores the fill thresholds, so the fill overlay was drawn on top of the stale sprite.

## Fix

One commit, "Fix issue 87753: drinking glass keeps previous drink sprite under a fill overlay", changes `update_icon()` in `code/datums/components/takes_reagent_appearance.dm`. The condition is now `style?.icon && style.icon_state`: only a style with both applies its appearance and returns early. Every other case, whether no style or a style without an icon, falls through to restoring `icon` and `icon_state` from `icon_state_pre_change` and `icon_pre_change`, and then invokes `on_icon_reset`. This replaces the separate null branch with a single reset path.

## Verification

On the test server with the fix, using the same glass and the Lua editor:

- 10 rum, then 30 pineapple juice: `icon_state` was `glass_empty`, the name was "glass of pineapple juice", the fill thresholds were a list, and the glass had 2 overlays.
- Adding 10 more rum while pineapple juice was still the majority: the glass stayed `glass_empty`.
- Clearing the glass: `glass_empty` and the name "drinking glass".
- 20 units of rum into the cleared glass: `rumglass` again.
- No runtimes appeared in the runtime log.

Not checked: the glass was never rendered or looked at, so the check rests on `icon_state`, name and overlay values only. Other containers that use this component were not tested, and the fix was not tested through player actions such as pouring from bottles.

## Notes

- A style with a name/description but no icon now resets the icon to the container's original one. Any existing style that relied on keeping the previous icon would change, but none was identified.
- The fix does not change which drink wins as majority reagent. A small amount of rum in a pineapple-juice glass keeps the default sprite with the fill, as intended.
