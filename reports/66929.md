# #66929: Attempting to catch something may fail due to blocking

| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The 2022 report said that with throw mode on and a blocking item (shield, energy sword, captain's sabre), a thrown item could be blocked and fall to the floor instead of being caught. On master, catching is attempted before blocking, so a character in throw mode with an empty active hand catches the item even when the block chance is 100%. No fix was needed.

## The bug

A player in throw mode, holding an item that can block, would sometimes see a thrown object bounce off a block rather than land in their hand. The reporter expected that throw mode should make the catch take priority.

## Reproduction

I could not reproduce the bug. The test used the Lua editor to set the scene and throw the item, so it exercised the same throw and hit code as a player throw but did not use a second player:

1. Spawned a human 3 tiles east of the thrower and gave it a riot shield in the off hand, with the shield's `block_chance` forced to 100. The active hand was empty.
2. Turned throw mode on for that human (`throw_mode_on`).
3. Threw a pocket crowbar at the human with `throw_at`.
4. The chat showed "Chad Barnes catches the pocket crowbar!". With a 100% block chance, the old behaviour would have blocked it.
5. Control: with throw mode turned off, the same throw gave "Chad Barnes blocks the pocket crowbar with the riot shield!". The block sound played and the crowbar bounced away.

So blocking works, and catching takes precedence when throw mode is on.

## Cause

There is no defect in current code. `/mob/living/carbon/hitby` calls `try_catch_item` first and returns TRUE on success (`code/modules/mob/living/carbon/carbon_defense.dm:77-80`). Only then does it call the parent `/mob/living/hitby` (`code/modules/mob/living/living_defense.dm:272`), where the block check happens. No `COMSIG_ATOM_PREHITBY` listener blocks mob catches earlier.

One remaining case looks like the bug but is intended. If the blocking item is in the active hand, `can_catch_item` returns FALSE because the hand is occupied (`living_defense.dm:352`; the carbon `try_catch_item` does not try the off hand). The throw is then blocked normally. I did not test this case in game.

## Fix

None.

## Verification

Only the check described under Reproduction was made, with one shield type and one thrown item. Other blocking items (energy sword, captain's sabre) share the same `hitby` path, but I did not test them. I also did not test a throw by a real second player or a full active hand.

## Notes

The fix is likely to have come from an earlier refactor of the hitby and block code. I did not look for the upstream PR.
