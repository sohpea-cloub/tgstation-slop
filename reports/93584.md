## Summary
A fireplace spawned from the admin Spawn Panel faces NORTH, and `fireplace.dmi` has no north frame, so nothing is drawn (the light and the tile still exist). The fix makes `/obj/structure/fireplace/setDir()` turn NORTH into SOUTH, the normal facing.

## The bug
Spawning `/obj/structure/fireplace` through the game panel gives an invisible object that still emits light. Spawning with build mode works, as the issue notes.

## Reproduction
1. Open Game Panel > Spawn Panel.
2. Select `/obj/structure/fireplace`; leave the direction at the panel's default (NORTH, value 1), amount 1, offset 0.
3. Create it. Inspecting the new object shows `dir: north`, and nothing is visible. The fireplace mapped in CentCom has dir south (2).

Analysis of the icon file showed the north frame (direction index 1) has 0 opaque pixels, while south has 1124 and east/west 757.

## Cause
The panel's tgui default is the first direction value (`tgui/packages/tgui/interfaces/SpawnPanel/CreateObjectSettings.tsx:48`), which is NORTH. `code/modules/admin/spawn_panel/spawn_handling.dm:31` and `:126` call `setDir()` with it, so every spawned atom is rotated to NORTH. The fireplace sprite has no north state, so it renders blank.

## Fix
One commit, "Fix issue 93584: admin-spawned fireplaces facing north are invisible", in `code/game/objects/structures/fireplace.dm`: `setDir()` replaces `NORTH` with `SOUTH` before calling the parent, with a comment explaining why. This is fireplace-local, so other atoms' behaviour is unchanged.

## Verification
After rebuilding, the same Spawn Panel steps produced a fireplace with `dir: south`, visible. Not checked: east/west facings, or the look of the lit state in game by eye beyond the dir value.

## Notes
The Spawn Panel forcing NORTH onto every atom, regardless of the type's own default, is arguably the wider problem. It was left unchanged because that change affects all spawned atoms.
