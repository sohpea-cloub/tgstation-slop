# #67600: The nuke going off after the round ends still mutes OOC

| | |
|---|---|
| Issues | [#67600](https://github.com/tgstation/tgstation/issues/67600) (verified, fixed) |
| Status | Fixed, one commit |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/67600 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Any global cinematic with `stop_ooc` set (the default) turns OOC off when it starts, with no check on the round state. When a nuclear bomb detonates after the round has already finished (for example, the shuttle docked and the round ended before the bomb went off), the ticker has already turned OOC on for the end-of-round chat, and the cinematic then turns it off again. The fix adds `SSticker.IsRoundInProgress()` to the condition, so cinematics only mute OOC while the round is in progress.

## The bug

The nuke mutes OOC while it detonates so players cannot leak information during the round. In the report, the Syndicate had the disk and survived but had not blown up the station before the shuttle docked (a minor victory). They then detonated the bomb after the round had ended, and OOC was disabled from then on, when players expect to talk freely about the round. A commenter on the issue said it still happened in October 2025. Another commenter suspected that OOC might also not be restored afterwards; the cause below shows the cinematic does restore it after its cleanup delay.

## Reproduction

The post-round detonation was reproduced with admin tools, not by playing it out through a real shuttle docking:

1. On the test server, start the round immediately and join as an observer.
2. In the Lua editor, spawn an `/obj/machinery/nuclearbomb/syndicate`.
3. Set `SSticker.force_ending = 1`. The ticker moves to `GAME_STATE_FINISHED` and turns OOC on (state 4, `GLOB.ooc_allowed` = 1).
4. Call `actually_explode()` on the bomb, through an SDQL2 `CALL` or a Lua timer.

Observed on master: right after the explosion, in the finished round, chat showed "The OOC channel has been globally disabled."

## Cause

`/datum/cinematic/proc/start_cinematic` (`code/datums/cinematics/_cinematic.dm:62`) contains:

```
// Pause OOC
var/ooc_toggled = FALSE
if(is_global && stop_ooc && GLOB.ooc_allowed)
    ooc_toggled = TRUE
    toggle_ooc(FALSE)
```

(`:70-74`; `stop_ooc` defaults to TRUE at `:46`). Nothing checks the round state. The ticker enables OOC when the round finishes (`code/controllers/subsystem/ticker.dm:177`, `toggle_ooc(TRUE)`), so a global cinematic started after that always sees `GLOB.ooc_allowed` true and mutes it. `clean_up_cinematic` (`:90`) turns OOC back on only after `cleanup_time` (30 seconds by default, `:44`), and the server may reboot before that.

A nuke that ends the round runs while the ticker is still in `GAME_STATE_PLAYING` (round end is paused until the detonation finishes), so muting for that one is still intended and is unaffected.

## Fix

Commit "Fix issue 67600: global cinematics no longer mute OOC after the round has ended" changes the condition to

```
if(is_global && stop_ooc && GLOB.ooc_allowed && SSticker.IsRoundInProgress())
```

and updates the comment. `IsRoundInProgress()` is `current_state == GAME_STATE_PLAYING` (`ticker.dm:606`). The check was put in the shared cinematic code rather than in the nuke so that every global cinematic follows the same rule. Because `ooc_toggled` stays FALSE in that case, the cleanup does not toggle OOC either, so there is nothing to restore.

## Verification

After rebuilding, the same steps (forced round end, then `actually_explode()`) were run. Lua timers recorded the ticker state as 4 and `GLOB.ooc_allowed` as 1 before the explosion, 5 seconds after it (the cinematic was playing and the "Station destroyed by Nuclear Device" reboot message appeared), and later. The "globally disabled" chat line did not appear.

Not checked: the real scenario of a nuke detonating after a shuttle-docking round end (only the forced end was used), a round-ending nuke during `GAME_STATE_PLAYING` after the change (still muting, by reading the code only), and other global cinematics.

## Notes

- The test setup was observer-only with a Lua-spawned bomb, and a runtime appeared in the `nuke_effects` path in the finished round. It was not investigated and it appeared unrelated to OOC. It may be an artifact of the observer-only setup.
- DOOC is not touched by the cinematic code and was not examined.
