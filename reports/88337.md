# #88337: Gibbing a Chipped quirk holder deletes the skillchip left in the surviving brain

| | |

| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a human with the Chipped quirk was deleted while their brain survived (a gib that drops the brain), the quirk's `remove()` ran `QDEL_NULL(installed_chip)` although the chip was still inside that brain. The chip was deleted and a dead reference stayed in the brain's `skillchips` list. The fix makes the quirk drop its reference when the holder is being deleted, leaving the chip in the brain, and, when the quirk is removed from a living mob, takes the chip out of the brain before deleting it. #67734 (a runtime when qdeleting brains that hold skillchips) could not be reproduced on master.

## The bug

### #88337

The reporter was gibbed with the Chipped quirk, was body-swapped, and no longer had the skillchip. The chip is hard deleted when the body is gibbed, so it cannot be regained from the brain, and the brain's `skillchips` list keeps a stale entry. The reporter's screenshots could not be viewed; the description above is from the issue text and the code.

### #67734

The issue reports a runtime from qdeleting a brain that has skillchips (text and a screenshot only, no steps).

## Reproduction

### #88337

1. Start a round on master and observe.
2. Using the Lua editor, spawn a human, create a `/datum/quirk/chipped`, set its `installed_chip` to `/obj/item/skillchip/acrobatics`, and call `add_to_holder(human, false, nil, true, false)` on it. The human then had one quirk and the chip was installed.
3. Using SDQL2, run `CALL gib(1) ON /mob/living/carbon/human` for that human. Argument 1 is `DROP_BRAIN`, so the brain survives the gib. (`gib()` without flags qdeletes the brain, and the chip dying then is legitimate.)
4. Run `SELECT /obj/item/organ/brain MAP [name, length(skillchips), skillchips]`.

Observed on master (in an earlier run of these steps): the dropped brain's `skillchips` list held "the old F058UR7 skillchip at nonexistent location", that is, a deleted chip left in the list.

The quirk was added through its own procs, not through character setup, and the gib was run through SDQL2 rather than a natural gib.

### #67734

Brains were qdeleted standalone and inside living humans, 73 brains in total, about 9 of them with active chips, through an SDQL2 `DELETE`. No runtime appeared in the runtime log.

## Cause

`/datum/quirk/chipped/remove()` (`code/datums/quirks/positive_quirks/chipped.dm:40`) deleted the chip unconditionally:

```dm
/datum/quirk/chipped/remove()
	QDEL_NULL(installed_chip)
	return ..()
```

When the quirk holder is deleted, `on_holder_qdeleting` (`code/datums/quirks/_quirk.dm:57`) leads to `remove_from_current_holder` (`code/datums/quirks/_quirk.dm:117`), which calls `remove()`. With a gib that drops the brain, the brain survives the mob and its `skillchips` list still contains the chip, now deleted. The brain's own cleanup (`destroy_all_skillchips`, `code/modules/mob/living/brain/skillchip.dm:79`) was never given the chance to handle the chip.

For #67734, `destroy_all_skillchips` checks `QDELETED(owner)` before calling `on_removal` on each chip and then `QDEL_LIST(skillchips)`, and no runtime occurred in testing.

## Fix

One commit, "Fix issue 88337: Chipped quirk no longer deletes a chip that is still in a surviving brain", changes `/datum/quirk/chipped/remove()`:

- If `installed_chip` is null, it only calls the parent.
- If the quirk holder is being deleted, it sets `installed_chip = null` and leaves the chip in the brain. The brain deals with its own skillchips when it is deleted.
- Otherwise (quirk removed from a living mob), it calls `holding_brain.remove_skillchip(installed_chip, silent = TRUE)` when the chip's brain is not deleted, and then deletes the chip.

## Verification

- Gib with `DROP_BRAIN` (two humans): the dropped brains contained the chip, still alive, in the brain (one was listed on the floor, "inside ... brain"), instead of a deleted chip.
- Removing the quirk from a living human with `remove_from_current_holder`: the brain's skillchip count went from 1 to 0 and `installed_chip` became null.
- Deleting all 73 brains afterwards produced no skillchip runtimes. Two runtimes in the runtime log came from a test setup mistake (a null turf) and are unrelated.

Not checked: a gib without `DROP_BRAIN`, which deletes the brain; the reported "body swapped, no chip" sequence; a natural gib or round-start Chipped holder (the quirk was added through Lua); whether the chip can then be recovered and re-implanted by a player.

## Notes

- #67734 is not reproduced on master; the guard in `destroy_all_skillchips` already covers the deleted-owner case. It may have been fixed since it was filed in 2022. No upstream PR was identified.
- With a gib that deletes the brain, the chip still dies with it, which is intended.
