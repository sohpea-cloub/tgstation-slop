## Summary

The mech gravitational catapult's repulse mode called `do_scatter()`, but nothing moved. `do_scatter()` called `move_away()` without `max_dist`, so the move loop's distance was 0 and its distance check was always false. The fix passes `max_dist = 5`. Sling (fling) mode, the subject of the older #70370, works on master. The same commit also fixes a log-message ordering bug in sling mode.

## The bug

### #77696 (repulse mode)

A mech with a gravity catapult in repulse mode runs `do_scatter()` on nearby objects, but they do not move.

### #70370 (fling/sling mode)

The 2022 report says clicking with the catapult does nothing in fling mode. A commenter suggested the mech refactor broke it, and another said it works for them like telekinesis. In #77696 the reporter confirms that fling works.

## Reproduction

### #77696

1. On the test server, using the Lua editor, spawn a Durand with a gravitational catapult in its left arm. Put a human in the mech.
2. Scatter three crowbars on the floor within 3 tiles of a target turf.
3. Switch the catapult to repulse mode (mode 2), with the mech facing east, and click a turf (116,144 in this run) with the crowbars nearby.
4. Result: no crowbar moved.

### #70370

Same setup, in the default sling mode, using real clicks:

1. Click a crowbar. The chat said "locked on the pocket crowbar."
2. Click a turf. The crowbar was thrown and hit a window, and the hit sound played.

The symptom in the report did not reproduce.

## Cause

`do_scatter()` (`code/modules/vehicles/mecha/equipment/tools/other_tools.dm:130-133`) called:

```
GLOB.move_manager.move_away(scatter, target, delay = delay, timeout = delay * dist, ...)
```

without `max_dist` (`code/controllers/subsystem/movement/movement_types.dm:638`). The loop's distance therefore defaulted to 0. The loop only steps while `check_dist()` is true, and for `move_away` that is `get_dist(moving, target) < distance` (`movement_types.dm:644-645`). That can never be true with a distance of 0, so the loop never moved anything.

In sling mode there was a smaller bug in `action()`: `movable_target` was set to `null` before it was used in the `log_message` call and in the "Lock on ... disengaged" message. Both messages named nothing.

## Fix

One commit, "Fix issue 77696: mech gravity catapult repulse mode never moved anything":

- `do_scatter()` now passes `max_dist = 5`. This matches the radius that `do_scatter()` already uses for its own timeout (`dist = 5 - get_dist(scatter, target)`).
- In sling mode, the `movable_target = null` lines were moved after the messages that use `movable_target`.

## Verification

After rebuilding, the same repulse setup was repeated. The crowbars moved: `117,144` to `120,144`, `118,144` to `121,144`, and `116,144` to `116,143`. No runtimes were logged.

Not checked: that the sling log and "Lock disengaged" messages now name the item (the change is a simple reorder and was not exercised); repulse on mobs; repulse with the target an object rather than a turf.

## Notes

- #70370 was not reproduced. The mech refactor since 2022 appears to have fixed it, or the original reporter's clicks were ignored. Clicks while the mech is not facing the target are silently dropped by the mech click handling (`code/modules/vehicles/mecha/_mecha.dm:692`), which may be what they saw. This is a guess, not tested.
- Comments in both issues suggest replacing the module with a mech version of the gravity module. That is outside this fix.
