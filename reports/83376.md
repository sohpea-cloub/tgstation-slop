## Summary

Grilling a pancake replaces the cooked result's reagents with the raw item's, so plain, blueberry and chocolate chip pancakes all ended up with the raw batter's 1 nutriment and 1 vitamin (#83376). The fix passes the extra nutrition through the grillable component's `added_reagents` and makes the component keep that list and `positive_result` when a topping re-adds it. Separately, slices of a custom bread were named with the custom prefix twice, because the slice already inherited the loaf's prefixed name and `ingredients_holder` added the prefix again (#94325). The holder now adds the prefix only when the name is still the default.

## The bug

### #83376

Eating a raw pancake, a cooked pancake, or a blueberry or chocolate chip pancake gave the same 1 nutriment and 1 vitamin. The cooked and topped pancakes define more reagents than the raw one (4/2 and 6/5 nutriment/vitamin), but those definitions were discarded when the raw pancake was grilled.

### #94325

A custom bread (bread with someone's meat added) sliced into pieces named like "small Zed Zorro slice of small Zed Zorro bread": the custom name appeared both before and inside "slice of".

## Reproduction

### #83376

On master, using the Lua editor, SDQL2 and View Variables:

1. Spawn a raw pancake (`/obj/item/food/pancakes/raw`). For the topped variants, add berries or a chocolate bar to it through its item interaction.
2. Call `finish_grilling` on the pancake's grillable component, which is what the grill does when cooking time is up. This was done by calling the proc directly, not by waiting on a grill.
3. Read the reagents of each result with SDQL2.

Observed: the plain pancake, the blueberry pancake and the chocolate chip pancake each had nutriment 1 and vitamin 1 (total 2).

### #94325

1. Spawn a plain bread (`/obj/item/food/bread/plain`) and a meat slab, and set the slab's `subjectname` to "Zed Zorro". `custom_materials` was cleared on the slab (see Notes).
2. Add the meat to the bread with the ingredients holder's `customizable_attack`, producing the custom loaf, "small Zed Zorro bread".
3. Slice the loaf by starting the processing on it with a knife (result bread slice, amount 2, time 1). This was also done by calling the procs from Lua, not by cutting with a knife in hand.

Observed: the slices were named "small Zed Zorro slice of small Zed Zorro bread".

## Cause

### #83376

`finish_grilling` (`code/datums/components/grillable.dm:144`) clears the result's reagents and moves the raw item's reagents into it (lines 161-164):

```dm
grilled_result.reagents?.clear_reagents()
original_object.reagents?.trans_to(grilled_result, original_object.reagents.total_volume)
if(added_reagents) // Add any new reagents that should be added
	grilled_result.reagents.add_reagent_list(added_reagents)
```

The raw pancake has `nutriment = 1, vitamin = 1` (`code/modules/food_and_drinks/food/pancakes.dm:21`), and neither `make_grillable()` (line 28) nor the topping code passed `added_reagents`, so every result got the raw amounts.

Two further problems affected the topped pancakes. When a topping is added, `item_interaction` (line 35) calls `AddComponent(/datum/component/grillable, cook_result = newresult)` (line 55) on an item that already has the component, which goes through `InheritComponent` (`grillable.dm:70`). That call did not pass `positive_result` or `use_large_steam_sprite`, so a topped pancake did not get the positive-result handling (the grilled-result message, the handmade/blackbox handling and the `TRAIT_GRILLABLE` removal) or the large steam sprite. `InheritComponent` also had no `added_reagents` parameter, so extra reagents could not be passed that way.

### #94325

`edible.dm:333` renames a processed item to "slice of [original_atom.name]". The original loaf's name already includes the custom prefix. Then the `ingredients_holder` component's `Initialize` (`code/datums/components/ingredients_holder.dm:60`) copies the custom name from the processed holder and sets `atom_parent.name = "[custom_adjective()] [custom_name] [atom_parent.name]"`, prefixing the already-prefixed name.

## Fix

Commit "Fix issue 83376: pancakes keep their cooked nutrition when grilled":
- `grillable.dm`: `InheritComponent` takes a `list/added_reagents` argument and stores it when given.
- `pancakes.dm`: the raw pancake's grillable component passes `added_reagents = {nutriment 3, vitamin 1}`, which tops the raw 1/1 up to the plain pancake's 4/2. Adding berries or chocolate computes `{nutriment 5, vitamin 4}`, topping 1/1 up to the 6/5 of the blueberry and chocolate chip pancakes. The topping's `AddComponent` call now also passes `positive_result = TRUE` and `use_large_steam_sprite = TRUE`, matching the plain pancake.

The added amounts are hardcoded differences from the raw batter. The alternative would be not to clear the result's reagents, but `finish_grilling` clears them deliberately so other grilled items can handle the transferred reagents themselves, so the existing `added_reagents` mechanism was used.

Commit "Fix issue 94325: custom bread slices no longer repeat the ingredient name": `ingredients_holder` now only sets the prefixed name when `atom_parent.name == initial(atom_parent.name)`. A slice that already inherited the loaf's name is left alone.

## Verification

After rebuilding and restarting the test server, repeating the steps above gave:

- #83376: plain pancake nutriment 4 / vitamin 2; blueberry pancake 6/5; chocolate chip pancake 6/5. The "turns into" message for topped pancakes is now the positive (notice) kind.
- #94325: slices were named "slice of small Zed Zorro bread".

Not checked: grilling on an actual grill over time, eating the pancakes in game, pancake stacks, other grillable foods, and slicing with a real knife. Both checks used direct proc calls.

## Notes

- #83376 also has a comment suggesting pancake stacks lose one pancake per bite; that is out of scope and was not touched.
- Side finding, not fixed: adding an ingredient with `custom_materials` (for example an unmodified meat slab) to `/obj/item/food/bread/plain` raised a `stack_trace` "materials with non-positive values ... meat = -400". It comes from the ingredients holder's `food_exited` handling calling `handle_materials` when the ingredient moves into the replacement loaf (`atom_materials.dm:46`). In the Lua editor the stack trace aborted the call; in game execution continues. This is why `custom_materials` was cleared on the slab in the #94325 reproduction. It may be a separate bug.
- The #94325 fix relies on the check `name == initial(name)`: any processed item that was renamed before the holder initializes will no longer get the prefix.
