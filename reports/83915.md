# #83915: Throwing objects while moving on a raptor hits the raptor instead

| | |
|---|---|
| Issues | [#83915](https://github.com/tgstation/tgstation/issues/83915): verified, fixed |
| Status | Verified on master; fix committed and checked in game |
| Fix branch | [fix/83915](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/83915) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An item thrown by a rider who is moving on a raptor can hit the raptor itself. The throw subsystem's per-tick obstacle check skips the thrower and the thrower's own passengers, but not the mount the thrower is buckled to. When the moving mount steps onto the item's tile, the dense mount counts as an obstacle and the item stops against it. The fix adds one condition so a mount the thrower is buckled to is not treated as an obstacle, unless it is the explicit target of the throw.

## The bug

A player riding a raptor throws an item in the direction the raptor is moving. The raptor moves ahead faster than the item, so the item lands on the same tile as the raptor and the player sees "The red raptor is hit by the pocket crowbar!" instead of the item flying on.

## Reproduction

The player action (riding and throwing while moving) was not performed by hand. The movement was reproduced by calling the relevant procs from the Lua editor, which gives the same ordering of events.

1. Start a round on the test server, observe, and open the Lua editor.
2. Using Lua, spawn a red raptor, a human and a crowbar on the same tile. Force-buckle the human to the raptor (`buckle_mob(human, TRUE)`).
3. Throw the crowbar from the human: `crowbar:throw_at(target, 4, 1, human)`, where `target` is the turf 4 tiles east (range 4, speed 1, thrower the human).
4. Immediately move the raptor one tile east (`raptor:Move(...)`), which mimics a rider moving in the throw direction.

Observed on master: the chat showed "The red raptor is hit by the pocket crowbar!" and the crowbar stopped on the raptor's tile (x=108).

A runtime also appeared in `riding_minigame.dm:58` (`Cannot read null.images`) in this setup. It is unrelated: the Lua-buckled human had no client, which the riding minigame expects. A first run of the script also stopped at a read-only-table error in the Lua script itself, after the throw had already happened. The hit message was produced before that error.

## Cause

`/datum/thrownthing/tick()` in `code/controllers/subsystem/throwing.dm` has a loop that "catches sneaky things moving on our tile while we slept" (`throwing.dm:149-160`). For each atom on the thrown item's turf it skips some cases and otherwise finalizes the throw against the obstacle:

```dm
if(obstacle == thrownthing || (obstacle == thrower && !ismob(thrownthing)))
	continue
...
if (obstacle == actual_target || (obstacle.density && !(obstacle.flags_1 & ON_BORDER_1) && !(obstacle in AM.buckled_mobs) && !(AM in obstacle.buckled_mobs)))
	finalize(TRUE, obstacle)
```

(`throwing.dm:151` and `throwing.dm:157`.) The thrower is skipped on line 151, and line 157 excludes mobs buckled to the thrown item and mobs the thrown item is buckled to. Nothing excludes the mount that the *thrower* is buckled to. When the raptor moves onto the item's tile, it is dense, is not the item's explicit target, and is not in any of the excluded relationships to the item, so `finalize(TRUE, obstacle)` hits it.

## Fix

One commit, "Fix issue 83915: a thrown item no longer hits the mount its thrower is buckled to", changes the density test at `throwing.dm:157`:

```dm
... && !(AM in obstacle.buckled_mobs) && !(thrower && (thrower in obstacle.buckled_mobs))))
```

A dense obstacle whose `buckled_mobs` contains the thrower is now ignored. The `obstacle == actual_target` branch is unchanged, so throwing something directly at your own mount still hits it. The change is local to the existing buckle exclusions in the same condition.

## Verification

After rebuilding, the same Lua script was run on the test server. The chat showed no hit message, the crowbar flew past the raptor and landed at x=111, the end of its range (4 tiles from the start).

Not checked: a real player riding a raptor and throwing while moving by hand (only the proc-level reproduction above was used); other mounts or ridden vehicles (the condition is generic over `buckled_mobs`, but only a raptor was tested); a throw explicitly targeted at the mount after the fix.

## Notes

- The condition is generic: any mob that carries the thrower as a buckled mob is now ignored by this check, not only raptors.
- The riding runtime in `riding_minigame.dm:58` is a test-setup artefact of buckling a clientless human, not part of this bug.
