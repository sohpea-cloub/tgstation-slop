# #94279: Tank transfer valve draws an ERROR sprite for some attached tanks

|---|---|

| Status | Fixed (partial match to the report) |

| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The tank transfer valve (TTV) draws each attached tank by using the tank's `icon_state` as a state in its own icon file, `icons/obj/devices/assemblies.dmi`. That file has no state for some tanks (the funny emergency tank, the pure anesthetic tank, and the "-on" states of jetpacks), so the valve showed an ERROR sprite. The fix draws the tank from its own icon when the valve's file lacks the state. The issue says the reporter's valve held two oxygen tanks and wires; that combination renders correctly on master, so the report does not exactly match what was found.

## The bug

A wired TTV with tanks attached showed the "ERROR" placeholder sprite in the reporter's screenshot. The issue gives no steps ("Idk probably wire TTV or something? TTV i found had wires and 2 oxytanks") and no tank names.

## Reproduction

1. On a started round, using the Lua editor, spawn an `/obj/item/transfer_valve`.
2. Spawn two tanks and `forceMove` them into the valve. Set `tank_one`, `tank_two` and `wired`, then call `update_appearance` on the valve and render it.

Results on master:
- Funny emergency (clown) tank and pure anesthetic tank: both tanks rendered as the missing-state placeholder sprite. The test tool draws a blue X for this; the game client draws ERROR.
- Two plain oxygen tanks with wires: rendered correctly. The reporter's stated case did not reproduce. Plain oxygen, yellow, red, emergency, engineering and double tanks all have states and render fine.

The jetpack case was not rendered (the test used a jetpack type that does not exist); it is covered by the same code path.

## Cause

`/obj/item/transfer_valve/update_overlays()` (`code/game/objects/items/devices/transfer_valve.dm:230-243`) adds the tank overlay as `"[tank_one.icon_state]"` (`:233`) and the tank_two underlay as `mutable_appearance(icon, icon_state = "[tank_two.icon_state]")` (`:238`). Both use the valve's `icon`, `assemblies.dmi`. That file lacks states for `anesthetic_warning` (pure anesthetic), `emergency_clown` (funny emergency tank), and jetpack "-on" states such as `jetpack-on` and `jetpack-sec-on`. The tank sprites are in `icons/obj/canisters.dmi`, which has all of them. A missing state draws an ERROR sprite.

## Fix

One commit on [fix/94279](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/94279), "Fix issue 94279: transfer valve showed an ERROR sprite for tanks missing from its icon file". It adds `/obj/item/transfer_valve/proc/tank_overlay(obj/item/tank/attached_tank)`: if `icon_exists(icon, attached_tank.icon_state)` it returns a `mutable_appearance` from the valve's icon, otherwise one from the tank's own `icon` and `icon_state`. The `tank_one` overlay and the `tank_two` underlay (with its existing translate) both use it. Tanks that already had a state render exactly as before; the alternative of adding the missing states to `assemblies.dmi` was not tried.

## Verification

After rebuilding the test server:
- The TTV with a funny emergency tank and a pure anesthetic tank, wired, drew both tanks (the clown tank and the rainbow pure anesthetic one) with wires.
- The two-oxygen wired TTV rendered as before.

Not checked: the jetpack "-on" states in a valve (by code only); the reporter's exact tanks, which are unknown; how the fallback tank sprite looks at the valve's scale and position beyond the render of the two cases above; the valve's floor, worn and inhand states (they exist in the file, and were not changed).

## Notes

- The reporter's tanks were probably not plain oxygen tanks, or a test-merged change altered a tank. This is a guess; the issue does not name the tanks.
- The fallback draws the tank's own sprite as it appears elsewhere, which may differ in style from the sprites in `assemblies.dmi`. This was not compared in game beyond the two cases rendered.
