# #58372: Ending maintenance drug withdrawal undoes the Deviant Tastes quirk

| | |
|---|---|
| Issues | [#58372](https://github.com/tgstation/tgstation/issues/58372): verified, fixed |
| Status | Fixed (one commit on the fix branch) |
| Fix branch | [fix/58372](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/58372) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

`/datum/addiction/maintenance_drugs/end_withdrawal()` restored the addict's tongue food preferences with `initial()`, which discards anything a quirk had changed. A character with Deviant Tastes therefore lost the swapped likes and dislikes as soon as that proc ran. It also runs on every addiction tick while the character has maintenance drugs in their system, so the quirk was undone without the character ever reaching withdrawal stage 2. The fix saves the tongue's food types when stage 2 changes them, restores exactly those values when withdrawal ends, and also clears the `too_bright` mood event that the issue's third comment pointed out.

## The bug

Deviant Tastes swaps the tongue's liked and disliked food types when it is added. A maintenance drug addict who was in withdrawal got "only likes gross food" tastes at stage 2. When withdrawal ended, the game set the tongue's tastes back to the tongue type's compile-time defaults rather than to what the tongue had before. For a Deviant Tastes character this means the swap was lost, so they went back to liking and disliking what a normal character does.

The issue was written against older code (`species.liked_food`, `eyes.refresh()`), which no longer exists on master, so the code in the issue text does not apply as written. The tastes now live on the tongue organ, and the `eyes.refresh()` call is gone, so the "eyeless" comment no longer applies either. The core complaint and the third comment (the `too_bright` mood event is not cleared) were still true on master.

## Reproduction

The effect was reproduced by calling the addiction's procs directly from the Lua editor. It was not reproduced by waiting through real addiction cycles with the drug.

1. On the test server, open the Lua editor and spawn a human, give it the `/datum/quirk/deviant_tastes` quirk with `add_quirk`, and give control of it to an admin (set its `ckey`).
2. Fetch the addiction datum with `GLOB.addictions[/datum/addiction/maintenance_drugs]` and read the tongue's `liked_foodtypes`, `disliked_foodtypes` and `toxic_foodtypes` (get the tongue with `get_organ_slot('tongue')`).
3. Call `withdrawal_enters_stage_2(human)` on the addiction, then `end_withdrawal(human)`, reading the three values after each step.

Observed on unfixed master (liked / disliked / toxic):

| Step | Values |
|---|---|
| Before (quirk applied) | 803844 / 136 / 2048 |
| After `withdrawal_enters_stage_2` | 1024 / 0 / 16776191 |
| After `end_withdrawal` | 136 / 803844 / 2048 |

The last row is the swap undone: liked and disliked have traded places back, so the quirk's effect is gone.

Because `end_withdrawal` is also called from `process_addiction` whenever the addicted mob has a qualifying amount of the drug in its system, the same loss happens without reaching stage 2. The in-game check of that case was only done on the fixed build (see Verification).

## Cause

- `code/modules/reagents/withdrawal/generic_addictions.dm:125-130`: `withdrawal_enters_stage_2` overwrites the tongue's tastes with `GROSS` / `NONE` / `~GROSS` and keeps no record of the old values.
- `code/modules/reagents/withdrawal/generic_addictions.dm:151-159`: `end_withdrawal` restores them with
  ```
  tongue.liked_foodtypes = initial(tongue.liked_foodtypes)
  tongue.disliked_foodtypes = initial(tongue.disliked_foodtypes)
  tongue.toxic_foodtypes = initial(tongue.toxic_foodtypes)
  ```
  `initial()` returns the tongue type's default, not the tongue's current state before withdrawal, so any change made by a quirk, or anything else that touched the tongue's tastes before withdrawal, is wiped. Other quirks write the same variables (Gamer sets `liked_foodtypes = JUNKFOOD`, Pineapple Hater adds `PINEAPPLE` to `disliked_foodtypes`), so they were exposed to the same problem.
- `code/modules/reagents/withdrawal/_addiction.dm:64-66` and `:72-74`: `process_addiction` calls `end_withdrawal` every tick for mobs with `TRAIT_NO_WITHDRAWALS`, and every tick while the addict has at least the relief threshold of the drug and has an addiction cycle. This is why `end_withdrawal` could not safely assume that withdrawal had changed anything.
- `code/modules/reagents/withdrawal/generic_addictions.dm:145` adds the `too_bright` mood event with that key, while `end_withdrawal` only cleared the generic `"[type]_addiction"` mood (in `_addiction.dm:133`), so a mood from stage 3 light sensitivity outlived the withdrawal. The stage 3 process proc only clears it while the mob is in the dark, and it no longer runs once withdrawal ends.

## Fix

One commit, "Fix issue 58372: maintenance drug withdrawal no longer resets food tastes set by quirks", changing `generic_addictions.dm`:

- The maintenance drug addiction gets a `saved_tastes` list, keyed by a weakref to the tongue, holding `list(liked, disliked, toxic)`.
- `withdrawal_enters_stage_2` stores the tongue's current three values the first time it changes them (it does not overwrite an existing entry), then applies the gross-food tastes as before.
- `end_withdrawal` looks the tongue up in `saved_tastes`. If there is an entry, it puts those values back and deletes the entry. If there is none (withdrawal never changed this tongue, for example when the proc is called every tick while on the drug), it leaves the tongue alone.
- `end_withdrawal` now also calls `clear_mood_event("too_bright")`.

The alternative of re-deriving the tastes by re-applying the character's quirks was not tried; saving and restoring the actual values keeps this addiction independent of which quirks or effects touched the tongue.

## Verification

Checked on the test server after rebuilding with the fix, with the same Lua editor method as above (procs called directly):

- Quirk present, initial tastes 803844 / 136 / 2048.
- `end_withdrawal` without stage 2 first: values unchanged.
- `withdrawal_enters_stage_2`: 1024 / 0 / 16776191, as before the fix.
- With a `too_bright` mood event added, `end_withdrawal` restored 803844 / 136 / 2048 and the mood event was gone.
- A second `end_withdrawal` immediately afterwards left the values unchanged.

Not checked: withdrawal reached by waiting through real addiction cycles with the actual drug; other quirks (Gamer, Pineapple Hater) combined with this addiction; a mob that is dead, gibbed or gets a new tongue mid-withdrawal.

## Notes

- `saved_tastes` is a list on the addiction datum, which is shared (`GLOB.addictions`). If a tongue is destroyed or replaced during withdrawal, its weakref key stays in the list until `end_withdrawal` runs for that tongue, which never happens, so the entry stays. It is small but is a leak. Pruning stale entries would need a decision about where to do it.
- If a tongue is replaced mid-withdrawal, the new tongue is never changed by the addiction and so is not restored either, which looks correct, but this was not tested.
- If another effect changes the tongue's tastes during withdrawal, `end_withdrawal` will overwrite that with the pre-withdrawal values. This is the same trade-off the old `initial()` code had, in a milder form.
- The issue's first two comments (eyes) refer to code that has since been rewritten, so no change was needed for them.
