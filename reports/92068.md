## Summary

The `flip` emote lists AIs in `mob_type_ignore_stat_typecache` so they can flip despite having no hands. That also skips the dead check in `can_run_emote()`, so a dead AI can still flip (and backflip). The fix overrides `can_run_emote()` in `/datum/emote/flip` to refuse any dead living mob. The other two issues in this unit, the AI's `track` verb and the missing late-join AI announcement, do not reproduce on this master.

## The bug

### #92068

An AI dies, and the player (or a ghost in its body) presses the flip hotkey: the dead AI core flips. The reporter's steps: be AI, die, press the flip hotkey while the ghost is in the body, and the dead body flips.

### #93069

The reporter's screenshots (not viewable during the investigation) were titled as the AI having a `track` verb again, which they regarded as a problem.

### #93956

The reporter said the "AI personality downloaded" chat announcement no longer appears when the AI joins late. A maintainer commented that it was probably their fault.

## Reproduction

### #92068

1. Late-joined as the AI from the lobby, then killed it.
2. Using the Lua editor, fetched the flip emote (`GLOB.emote_list['flip'][1]`) and called `can_run_emote(me, true, true)` on the dead AI (stat 3, DEAD).

Result: it returned 1 (allowed). This was reproduced by calling `can_run_emote()` directly, not by pressing the hotkey. The hotkey path (`code/datums/keybinding/emote.dm`) calls `mob.emote(key, intentional = TRUE)`, which goes through `can_run_emote()`, so the result should carry over, but the flip itself was not watched on screen. An SDQL2 `CALL emote(...)` attempt failed with a parsing error ("You need to specify what to call ON"), so Lua was used instead.

### #93069

Using the admin tools, listed the AI's verbs and filtered for "track". It showed as `track (hidden)`, and it was not in the AI's statpanel tabs, which show only entries such as "AI Commands". The source agrees: `GAME_VERB_HIDDEN(/mob/living/silicon/ai, ai_camera_track, "track")` at `code/modules/mob/living/silicon/ai/ai.dm:358`, with the comment that it exists so one can type "track <name>".

### #93956

Late-joined as the AI on the test server. Chat showed "X has been downloaded to an empty bluespace-networked AI core at AI Chamber (214,144,2)."

## Cause

### #92068

`/datum/emote/flip` (`code/modules/mob/emote.dm:76-81`) sets:

```
mob_type_ignore_stat_typecache = list(/mob/dead/observer, /mob/living/silicon/ai, /mob/eye/imaginary_friend)
```

In `/datum/emote/proc/can_run_emote()` (`code/datums/emotes.dm`, starting near line 381) the entire stat block, including the `DEAD` branch that returns FALSE unless `EMOTE_CANUSE_DEAD` is set, is wrapped in `if(status_check && !is_type_in_typecache(user, mob_type_ignore_stat_typecache))`. For an AI the block is skipped, so unconscious, hands-blocked and dead are never checked. The typecache entry was meant to let AIs flip without hands; skipping the dead check was a side effect. `backflip` inherits from flip, so it has the same problem. In the notes, `help` also ignores stat for AIs but was judged harmless, and `spin` does not list AIs.

### #93069 and #93956

No defect found; see Notes.

## Fix

One commit: "Fix issue 92068: dead AIs can no longer use the flip emote". It adds to `code/modules/mob/emote.dm`:

```
/datum/emote/flip/can_run_emote(mob/user, status_check = TRUE, intentional = FALSE, params)
	. = ..()
	// AIs ignore the stat checks (they have no hands to be blocked), but a dead AI shouldn't be flipping around
	if(. && status_check && isliving(user) && user.stat == DEAD)
		if(intentional)
			to_chat(user, span_warning("You cannot [key] while dead!"))
		return FALSE
```

This was chosen over removing the AI from the typecache, which would put back the unconscious and hands checks that the typecache entry exists to bypass. Observers (not living) and imaginary friends are unaffected. The same override applies to backflip through inheritance.

## Verification

After rebuilding, on the dead AI: `can_run_emote(me, true, true)` returned 0 and chat showed "You cannot flip while dead!". With the AI alive it returned 1.

Not checked: pressing the hotkey in game, backflip, any non-AI dead mob (for example a dead human, which was already blocked by the normal stat block), and a ghost in the AI's body beyond the AI's own stat being DEAD.

## Notes

- #93069: the current verb is hidden and the issue was probably fixed by the verb-system refactor after the September 2025 report. A hidden verb can still autocomplete in the command bar; this is by design ("type track Name"). The reporter's screenshots could not be viewed, so what they showed is uncertain.
- #93956: the announcement comes from `/datum/job/ai/announce_job` (`code/modules/jobs/job_types/ai.dm:85`), a `minor_announce()` called from job equipping and fired in game on late join. It is guarded by `SSticker.HasRoundStarted()`, so it does not fire for round-start AIs. The maintainer's comment suggests the breakage was fixed upstream after the report.
- `/mob/living/silicon/ai` was not otherwise audited for emotes that ignore stat.
