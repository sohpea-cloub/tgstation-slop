## Summary

**#59458:** CRISPR in the DNA console works on master when given a correct 32-character string. The reported "does nothing, uses no charge" matches the console silently abandoning the action for a wrong length or an invalid base, with no message. The fix makes the console say what is wrong, documents the string format in the prompt, and handles a stale mutation reference and a cancelled prompt.
**#66228:** Mulligan did re-roll moth wings and antennae on master, so the issue is already fixed there.
**#67643:** A dwarf (who gets the passtable trait) walking onto a glass table shattered it, because the shatter check ignored that trait. The fix skips the shatter check for dwarves.

## The bug

### #59458

In the DNA console, a player selects a mutation on the occupant, presses the CRISPR button, types a replacement string and confirms. When it failed, nothing visible happened: no message, no charge spent, no change. Reporters said they had double-checked the strings.

The string is not free text. It is 32 characters, built from the first base of each base pair: characters at odd positions come from the current gene's sequence, characters at even positions from the new gene's sequence. Anything else (not 32 characters, or a character that is not A, T, C or G) made the handler return without a word.

### #66228

The report says Mulligan does not re-randomize moth wings (and probably antennae, lizard horns, frills and snouts).

### #67643

A human with the dwarfism mutation can pass under tables (the sprite is drawn over them), but entering a glass table's tile still shattered it, with the dwarf hit by the shard. The issue also complains that the sprite draws over the table instead of under it.

## Reproduction

### #59458

1. On a test server running master, start a round. Using the Lua editor, spawn a DNA scanner and a DNA console next to each other (scanner east of the console), connect them, and put a human with a known mutation into the scanner. Set the console's `crispr_charges` to 3.
2. Possess a human (a ghost can only view) and open the console. Select the mutation on the occupant, press CRISPR, and confirm with `tgui_act` using source "occupant". The "console" and "disk" sources return early, so only the occupant works.
3. Submit a correct string. Example for replacing Glowy with Hulk: `GCGATGAAACCACAGCTCGCCCAGTGCAGAGG`. Result: charges went 3 to 2, and the mutation was replaced (the sequence, alias and name updated).
4. Submit a 31-character string, or a 32-character string containing a letter that is not A/T/C/G. Result on master: nothing happened, no message, no charge used. This reproduces the report.

### #66228

Not reproduced; see Cause.

### #67643

1. Give a human the dwarfism mutation (check the passtable trait is present).
2. Spawn a glass table and walk the dwarf onto it.
3. Observed on master: "The glass table breaks! You're hit by the shard!"

## Cause

### #59458

In `code/game/machinery/computer/dna_console.dm` (the CRISPR handler, roughly lines 695-745 on master), three conditions return without feedback:

- `length(new_sequence_input) != 32` just returns.
- In the unzip loop, a character that is not part of an `AT` or `CG` pair makes `new_pair` null, and the `else` branch returns ("drop out, no pair").
- `get_mut_by_ref()` can return null, and the code did not check.

Each of these happens before `crispr_charges--`, so no charge is used. The prompt text was just "Enter a replacement sequence", which does not say what the string should look like. Only the missing feedback was the defect; the mechanism worked.

### #66228

Mulligan randomizes features through `species.randomize_features` (`_species.dm`, around line 513), `initialize_dna` with randomized features (`code/datums/dna.dm:341-352`), and `updateappearance` calling `mutate_feature` on external organs. These paths cover the moth wings and antennae.

### #67643

`/obj/structure/table/glass/proc/check_break` (`code/game/objects/structures/tables_racks.dm:569`) shatters the table when the mob has gravity, `mob_size > MOB_SIZE_SMALL` and is not flying or floating. A dwarf's `mob_size` stays `MOB_SIZE_HUMAN`. Dwarfism grants `TRAIT_PASSTABLE` (`on_dwarf_trait` in `code/modules/mob/living/carbon/human/init_signals.dm`, around lines 19-28), but the check never looked at it. Monkeys are `MOB_SIZE_SMALL` and never broke the table.

## Fix

Two commits.

**"Fix issue 59458: DNA console CRISPR gives feedback on invalid input"** changes the CRISPR handler in `dna_console.dm`:
- returns early if the mutation reference resolves to nothing (a stale ref used to continue);
- returns quietly if the prompt was cancelled (null input);
- the console now says "ERROR: CRISPR sequence must be exactly 32 bases long." for a wrong length, and "ERROR: CRISPR sequence contains an invalid base at position N." for a bad character;
- the prompt text now explains the format: 32 letters (A, T, C, G), alternating the first base of each pair of the current gene with the first base of each pair of the new gene.

The CRISPR behaviour for valid input is unchanged.

**"Fix issue 67643: dwarves no longer shatter glass tables they walk under"** adds to `check_break`:

```dm
// Dwarves walk under tables rather than over them
if(HAS_TRAIT(M, TRAIT_DWARF))
	return FALSE
```

It checks `TRAIT_DWARF` (the cause of the passtable), so other sources of `TRAIT_PASSTABLE` are unaffected. Treating `TRAIT_PASSTABLE` in general was an option and was not tried. Nothing was committed for #66228.

## Verification

The fixes were built and tested on the test server.

- #59458 after the fix: a 31-character string produced the console message "ERROR: CRISPR sequence must be exactly 32 bases long."; a 32-character string with a `Z` produced "ERROR: CRISPR sequence contains an invalid base at position 32."; charges stayed at 3 in both cases. A valid string (odd characters from the current gene's first bases, even from the new gene's, taken from the full sequence list) took the charges from 3 to 2. The prompt text was updated.
- #67643 after the fix: a human with `TRAIT_DWARF` moved onto a glass table did not shatter it and the table stayed valid. A normal human moved onto another glass table shattered it (break sound and a shard).
- #66228: a moth was randomized with the randomize helper repeatedly and its wings and antennae changed each time (for example Dipped, Royal, Feathery, Lovers, Ragged). The real Mulligan reagent (5 units) changed Oak Worm wings and Ragged antennae to Rosy and Luna.
- The runtime log of the verification round showed only errors from the tester's own Lua misuse, none from the changed code.

Not checked: CRISPR through the player's full UI on a real round (the action was driven through UI actions on the test server), the "console" and "disk" sources, and other mutations than Glowy to Hulk. For #67643, the walk-onto move was done by moving the mob onto the tile rather than by key presses, and other passtable sources were not tested. Lizard parts were not tested for #66228.

## Notes

- Whether the CRISPR bug report is a bug is a judgment call: the feature worked, but the lack of any message made it look broken. The fix improves feedback only; a maintainer may also want the format explained in the console UI itself.
- Only occupant CRISPR works; "console" and "disk" sources return early. This was left unchanged.
- #67643: the part of the issue about the dwarf sprite drawing over the table instead of under it is a layering/visual matter and was not addressed. The comment about monkeys is moot for shattering because they are `MOB_SIZE_SMALL`.
- The issue #59458 refers to #58888 as possibly related; it was not examined.
