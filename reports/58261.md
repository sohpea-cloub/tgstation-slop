# #58261: Armless people can no longer buckle themselves to skateboards

| | |
|---|---|
| Issues | [#58261](https://github.com/tgstation/tgstation/issues/58261) - verified and fixed |
| Status | Fixed on a branch; checked in game |
| Fix branch | [fix/58261](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/58261) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

`is_user_buckle_possible()` refuses any carbon user with no usable hands, and that check applies to every buckle, including a mob buckling itself to something it merely hops onto, such as a skateboard. The fix adds a `buckle_requires_hands` var (default TRUE) and sets it to FALSE on skateboards, and the hand check is skipped only when the user is buckling themselves. Buckling someone else, and buckling to anything else, still needs a hand.

## The bug

A carbon with both arms missing cannot buckle themselves to a skateboard by dragging themselves onto it; nothing happens. The issue (April 2021) says this is a regression and "not radical, man". It came out of the discussion on an earlier PR (#58176), whose concerns about armless carbons were not addressed. A commenter guessed the cause was that buckling yourself to a skateboard calls `user_buckle_mob` when it should call `buckle_mob`.

## Reproduction

Reproduced on master by calling the drag-onto-skateboard code from the Lua editor; a real mouse drag was not performed.

1. Started a test round, joined as an observer, opened the Lua editor.
2. Spawned a human and an `/obj/vehicle/ridden/scooter/skateboard` on the same tile.
3. Called `is_user_buckle_possible(human, human, FALSE)` on the skateboard: result 1, with the human's `usable_hands` at 2.
4. Dismembered both of the human's arms (`usable_hands` became 0).
5. Called `is_user_buckle_possible(human, human, FALSE)` again: result 0. Called `user_buckle_mob(human, human, FALSE)`: result 0, and the human's `buckled` stayed null.

## Cause

`code/game/objects/buckling.dm:286-297`:

```
/atom/movable/proc/is_user_buckle_possible(mob/living/target, mob/user, check_loc = TRUE)
	// Standard adjacency and other checks.
	if(!Adjacent(user) || !Adjacent(target) || !isturf(user.loc) || user.incapacitated || target.anchored)
		return FALSE

	if(iscarbon(user))
		var/mob/living/carbon/carbon_user = user
		if(carbon_user.usable_hands <= 0)
			return FALSE
```

The hands requirement (lines 291-294) applies to any carbon user, whatever the target is and whether the user is buckling themselves or someone else. Dragging a mob onto a buckleable atom goes through `mouse_drop_receive()` (`buckling.dm:49`), `mouse_buckle_handling()` (line 59) and `user_buckle_mob()` (line 314), and `user_buckle_mob()` calls this check. Skateboards use that same path (`/obj/vehicle/ridden/user_buckle_mob` in `code/modules/vehicles/ridden.dm` just checks range and calls the parent), so an armless skater is refused.

The commenter's suggestion (`user_buckle_mob` versus `buckle_mob`) was not the cause: `user_buckle_mob` is the normal player-facing entry point, and the failure comes from the check inside it.

## Fix

One commit, "Fix issue 58261: armless people can buckle themselves to skateboards again":

- `code/game/objects/buckling.dm`: adds `var/buckle_requires_hands = TRUE` ("Whether a carbon user needs a usable hand to buckle themselves to us...") and changes the check to `if((buckle_requires_hands || user != target) && iscarbon(user))`.
- `code/modules/vehicles/scooter.dm`: sets `buckle_requires_hands = FALSE` on `/obj/vehicle/ridden/scooter/skateboard`, with the comment that you hop onto a skateboard and riding it does not need hands either. The subtypes of that path inherit it.

Why this approach: a global removal of the hand check would let armless players buckle themselves to chairs, beds and similar, and buckle other people, which the original check was meant to forbid. An override on the skateboard alone would be more code and would not cover the buckle-someone-else rule. The new var is off by default for everything but skateboards, and the `user != target` term keeps the hand requirement when someone else is being buckled even on a skateboard.

## Verification

After rebuilding the test server with the fix, on an armless human (both arms dismembered, `usable_hands` 0), calling `mouse_drop_receive()` directly from Lua:

| Case | Result |
|---|---|
| Armless human dragged onto a skateboard (self) | returned 1; `buckled` was the skateboard; chat: "buckles himself to the skateboard" |
| Armless human buckling another human onto the skateboard | returned 0; the other human stayed unbuckled |
| Armless human dragged onto a chair (self) | returned 0; unchanged from before the fix |

Not checked:

- A real mouse drag from a client (the drag handler was called directly).
- Skateboard subtypes (pro, hoverboard, improvised, wheelys/roller skates) and a board deployed from the held item; they inherit the new var but were not each tried.
- The result of riding or moving the skateboard once buckled without arms.
- Other buckleable objects beyond the chair.

## Notes

- The plain scooter (with handlebars) still requires hands to buckle, intentionally. Only skateboards were exempted.
- The var could be reused for other "just step onto it" objects if maintainers want them exempted too; no others were changed.
- The `user != target` term means the exemption only covers self-buckling. Whether armless people should be able to put someone else on a skateboard is a design choice; the fix keeps the old rule.
