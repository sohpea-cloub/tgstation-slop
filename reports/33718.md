# #33718: "Change Minds!" while a human is bloodcrawling leaves the swapped body inside the blood

| | |
|---|---|
| Issues | [#33718](https://github.com/tgstation/tgstation/issues/33718): verified (reproduced; the effect is milder than "stuck", see below) |
| Status | Reproduced, cause found, no fix committed |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The wizard event "Change Minds!" swaps the minds of random humans by calling `swap_minds()`, which never checks whether a body is jaunting. If one of the two humans is inside a blood-crawl holder (`/obj/effect/dummy/phased_mob/blood`), that body stays in the holder and is now occupied by the other mind, which wakes up inside the blood. The holder only throws its occupant out when the occupant's `stat` changes, and the knockout applied after the swap does not change `stat`. No fix was committed. A candidate patch was written and compiled but was not run in game, so it is not offered as a verified fix.

## The bug

The issue (opened 2017, with no reproduction steps beyond the title) says that a wizard "identity swap" event during blood crawling leaves the player stuck in the blood. In current code the only event that matches is "Change Minds!" (`code/modules/events/wizard/shuffle.dm:82`, the `shuffleminds` event). The other two events of that family, "Change Places!" and "Change Faces!", and "Mass Identity Spoof" (`identity_spoof.dm`) do not move the mind into another body while the body keeps its location, so they were not considered.

What happens: a human who is blood crawling is picked as one of a pair. Their body is left in the "ethereal form" holder, but it now holds the other person's mind. The other body, which now holds the crawler's old mind, is lying on the floor. Both are knocked out for the spell's unconscious duration (40 seconds, as recorded in the testing notes). The new occupant of the crawling body wakes up inside the blood in a body that is not theirs.

It is not a permanent trap in the tested situation: see Reproduction.

## Reproduction

Reproduced with the Lua editor on the test server, calling the swap proc directly rather than triggering the event (see the note at the end of this section).

1. Spawn two humans, A and B, each with a mind (`mind_initialize()`); give B's mind a key so it counts as player-controlled. Place a blood decal (`/obj/effect/decal/cleanable/blood`) under A.
2. Grant A the spell `/datum/action/cooldown/spell/jaunt/bloodcrawl` and force it into the blood with `try_enter_jaunt(blood, A, TRUE)`. A is now inside a `/obj/effect/dummy/phased_mob/blood` ("ethereal form"). In the observed run this left `stat` at 0 and the body's location reported as "the ethereal form".
3. Create a `/datum/action/cooldown/spell/pointed/mind_transfer` and call `swap_minds(B, A)`. This is the same call the event makes for each pair (`shuffle.dm:101`).
4. Read both bodies' location, `stat`, `key` and `mind.key`.

Observed after the swap:

- The body that had been jaunting: location "the ethereal form", `stat` 0, `mind.key` equal to B's key.
- The other body: location "the floor", `stat` 0, holding the key of the player who had been controlling A.

So the swapped-in mind is inside the blood holder and nothing ejected it.

To check whether the occupant can get out, the test player was put into the jaunting body (`PossessByPlayer`). They could move inside the holder (the holder moved with them), and clicking the Blood Crawl button with blood adjacent produced "The pool of blood starts to bubble..." and started the exit progress bar. The test recorded the bar at 35% and did not record the exit completing.

Not tested: waiting out the 40 seconds of unconsciousness, running the actual "Change Minds!" event through the admin event menu, and trying to leave when no blood is nearby.

## Cause

Three pieces of code combine:

- `swap_minds()` (`code/modules/spells/spell_types/pointed/mind_transfer.dm:96`) calls `caster_mind.transfer_to(to_swap)` and `to_swap_mind.transfer_to(caster)` (lines 126-127), then `Unconscious()` on both mobs (lines 136-137). It never looks at whether either mob is jaunting.
- The event's own filter (`shuffle.dm:86`) skips mobs that are unconscious or in crit, have no mind, are wizards, or have `TRAIT_NO_MINDSWAP`. A bloodcrawling human passes it.
- The holder only ejects its occupant from its stat-change handler (`code/game/objects/effects/phased_mob.dm:123-126`):

```dm
/obj/effect/dummy/phased_mob/proc/on_stat_change(mob/living/source, new_stat, old_stat)
	SIGNAL_HANDLER
	if(source == jaunter && IS_UNCONSCIOUS_OR_CRIT(source))
		eject_jaunter()
```

`Unconscious()` adds `TRAIT_KNOCKEDOUT` but leaves `stat` at CONSCIOUS (0 in the observed run), so `COMSIG_MOB_STATCHANGE` never fires and the handler never runs. `TRAIT_KNOCKEDOUT` is only added by `stat` changes to hard crit or dead (`code/modules/mob/living/living.dm`, `set_stat`), not the other way round.

## Fix

No commit exists for this unit. A candidate approach was written and compiled but not run in game, and it was reverted, so none of it is verified.

The idea: when a mob enters a jaunt, make the holder (in `phased_mob.dm`, `set_jaunter`) listen to the jaunter for `COMSIG_MOB_MIND_TRANSFERRED_OUT_OF` and `COMSIG_MOB_MIND_TRANSFERRED_INTO`, with a `SIGNAL_HANDLER` proc that calls `eject_jaunter()` when the source is the jaunter, and unregister them in `Exited()`. Ejecting through `eject_jaunter()` also runs the existing clean-up for the spell (`on_jaunt_exited`, via `COMSIG_MOB_EJECTED_FROM_JAUNT`).

Two details from the attempt:

- Listening for `..._OUT_OF` alone did not work. In `transfer_to()` the second transfer in `swap_minds` finds the body's `mind` already cleared by the first transfer, so no `OUT_OF` signal is sent to the jaunting mob. `..._INTO`, which is sent to the receiving mob, is needed as well.
- An alternative considered but not tried: eject both mobs directly inside `swap_minds()` if either is inside a `phased_mob`. This is simpler but covers only the mind-swap spell and event, not other mind transfers.

The patched tree built with no errors. It was not run, so whether the eject happens, and whether it causes runtimes or interferes with normal blood crawl or slaughter demon behaviour, is unknown.

## Verification

None for a fix, since none was committed. Only the bug was verified (see Reproduction).

## Notes

- "Stuck" in the issue title overstates what was seen. With blood within one tile (`blood_radius` is 1 in `code/modules/spells/spell_types/jaunt/bloodcrawl.dm`) the new occupant could start the normal exit. Someone who leaves the blood area, or whose blood decal dries or is cleaned, could not use the spell, but that scenario was not tried.
- The occupant of the crawling body also keeps the Blood Crawl spell and its hands, because the spell is granted to the body, not the mind.
- A mind-transfer signal handler on the holder would also cover other transfers into or out of a jaunting mob (for example admin-triggered ones), not only "Change Minds!". Slaughter demons are not an issue for the event, since they are not humans and the event only picks humans.
- Related behaviour not examined: `swap_minds()` is also used by the player-cast Mind Swap spell, so a player could produce the same result by targeting a bloodcrawling human.
