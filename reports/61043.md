# #61043: Condenser flamethrowers still ignite the gas they expel

| | |
|---|---|
| Issues | [#61043](https://github.com/tgstation/tgstation/issues/61043): verified, fixed |
| Status | Fixed on branch, verified through `ignite_turf` (not by firing) |
| Fix branch | [fix/61043](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/61043) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A flamethrower built with a condenser instead of an igniter still exposed every turf it sprayed to a hotspot, because `default_ignite()` hardcoded the exposure temperature from the tank and the condenser did not override `ignite_turf()`. The fix lets the igniter choose the temperature through a new proc, `get_flamethrower_exposed_temperature()`. Regular igniters keep the old formula, and the condenser returns null, which means no hotspot.

## The bug

The condenser is a subtype of the igniter and can be fitted to a flamethrower. It is meant to cool, but the flamethrower treats it like any igniter: each sprayed turf gets a hotspot at `(tank temperature * 2) + 380` K. The issue reports this, and a commenter confirmed it in 2024 with plasma at 3 K. At 3 K the exposure is 386 K, which is above the plasma burn temperature, so the gas lights anyway.

## Reproduction

`ignite_turf()` was called directly. A real fired flamethrower (`flame_turf()`) was not used.

1. On the test server, started the round and opened the Lua editor.
2. Spawned `/obj/item/flamethrower/full/tank`.
3. For each igniter type (regular igniter, condenser), replaced the flamethrower's `igniter`, set the tank's air temperature (3 K, and later 293 K), and called `igniter.ignite_turf(flamethrower, turf)` on a turf 3-6 tiles away.
4. Read `turf.active_hotspot`.

Result on master:

| Igniter | Tank temperature | Hotspot on turf |
|---|---|---|
| igniter | 3 K | yes |
| condenser | 3 K | yes (the bug) |

## Cause

`default_ignite()` in `code/game/objects/items/weaponry/ranged/flamethrower.dm:227-239` transfers 5% of the tank to the turf and then always calls

```
target.hotspot_expose((tank_mix.temperature*2) + 380,500)
```

(line 238). `/obj/item/assembly/igniter/proc/ignite_turf()` (line 284) just calls `F.default_ignite(location,release_amount)`, and the condenser (`code/modules/assembly/igniter.dm:56`) does not override it. The igniter therefore had no say in the exposure temperature. This is what the issue thread proposed to change.

## Fix

One commit, "Fix issue 61043: condenser flamethrowers no longer ignite the gas they expel":

- `default_ignite()` takes a new `exposed_temperature` argument and only calls `hotspot_expose(exposed_temperature, 500)` when it is not null.
- New `/obj/item/assembly/igniter/proc/get_flamethrower_exposed_temperature(tank_mix)` returns the old formula, `(tank_mix.temperature * 2) + 380`. `ignite_turf()` passes its result to `default_ignite()`.
- `/obj/item/assembly/igniter/condenser` overrides it to return null.
- `flame_turf()`'s no-igniter fallback passes the old formula explicitly, so that case behaves as before.
- The commented-out `location.hotspot_expose(...)` line was removed. The plasma x5 multiplier is unchanged.

This follows the suggestion in the thread that the igniter should decide the heat, without splitting the flamethrower into two types.

## Verification

After rebuilding and repeating the steps above:

| Igniter | Tank temperature | Hotspot on turf |
|---|---|---|
| igniter | 3 K | yes |
| condenser | 3 K | none |
| igniter | 293 K | yes |
| condenser | 293 K | none |

Not checked: firing a real flamethrower through `flame_turf()` (it sleeps, so `ignite_turf()` was called directly), the no-igniter fallback in `flame_turf()`, and the rupture path below.

## Notes

- A tank hit by a bullet ruptures through `ignite_turf()` too, so with a condenser fitted that path no longer ignites either. This was found from the code and was not tested.
- With a condenser, the gas is still released onto the turf, only the hotspot is gone. Whether the condenser should also cool the gas was not examined.
