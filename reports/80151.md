# #80151: Lightgeist heals are swallowed for 5 seconds after clicking an object

| | |
|---|---|
| Issues | [#80151](https://github.com/tgstation/tgstation/issues/80151): verified, fixed |
| Status | Verified on the test server; fix committed |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/80151 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A player-controlled lightgeist that clicks any object (a table, a machine) gets a 5-second click lockout, because the generic basic-mob melee code applies the lightgeist's `melee_attack_cooldown` whenever the "attack" on the object did something. Heal clicks during that window are silently dropped, which matches the "nothing happens until I click many times" report. The fix resets the lockout to the normal `CLICK_CD_MELEE` after a lightgeist attacks a non-living target.

## The bug

The reporter said a lightgeist player's clicks on a wounded person do nothing for a long time, and that it is unresponsive when healing. A commenter said clicking something that is not a floor (a table, a machine) made healing work immediately afterwards.

Healing itself is not what is slow. The delay is a click cooldown left over from an earlier click on something else.

## Reproduction

1. On the test server, join as an observer and open the Lua editor.
2. Spawn a `/mob/living/basic/lightgeist` and a human a few tiles away, give the human the `never_wounded` trait and about 60 to 80 brute damage, and set the lightgeist's `ckey` to the observer's so that it is player-controlled.
3. Click the injured human. Each click healed (clicks were about 0.8 seconds apart, the normal `CLICK_CD_MELEE`). Clicks sent faster than that were dropped. Early clicks while the server was still initialising also failed, which was lag and not this bug.
4. Click an object (a holopad was used), then click the human right away. No heal happened. Reading the lightgeist's `next_move` through the Lua editor gave 1123.5 against a `world.time` of 1089, about 3.5 seconds still to wait, consistent with a 5-second cooldown.
5. Clicking the floor sets no cooldown.

## Cause

- `code/modules/mob/living/basic/basic.dm:229-238`, `/mob/living/basic/proc/melee_attack`: after `target.attack_basic_mob(src, modifiers)` returns a truthy value, it calls `changeNext_move(melee_attack_cooldown)` unless `ignore_cooldown` is set.
- `code/modules/mob/living/basic/space_fauna/lightgeist.dm:22-24,43`: lightgeists have `melee_damage_lower/upper = 5`, `melee_attack_cooldown = 5 SECONDS` and `obj_damage = 0`.
- Clicking an object reaches `obj/attack_animal` (`code/game/objects/obj_defense.dm:72`), which goes to `attack_generic` with a damage roll of `rand(melee_damage)`. This returns truthy, so the 5-second cooldown is applied.
- Healing is done by the `healing_touch` component, which intercepts the attack and cancels the chain, so `melee_attack` returns FALSE and sets no cooldown. A heal click is therefore never what causes the lockout, but it is dropped while the lockout from an earlier object click is active.

The 5-second value is presumably meant to pace AI-controlled attacks; that was inferred and not checked.

## Fix

One commit, "Fix issue 80151: lightgeists no longer wait 5 seconds after clicking a non-living thing". In `code/modules/mob/living/basic/space_fauna/lightgeist.dm`, the `melee_attack` override now returns early if the parent returned falsy. For a living target it keeps the `add_ally` call. For anything else, when `ignore_cooldown` is not set, it calls `changeNext_move(CLICK_CD_MELEE)`, overriding the 5-second value set by the parent. It overrides only for lightgeists and leaves the shared basic-mob cooldown logic alone, as the comment on the issue suggested changing the default for all basic mobs; that wider change was not attempted.

## Verification

After rebuilding, on the test server: the lightgeist clicked a table, then clicked the injured human about one second later. The heal happened immediately ("begins mending ... wounds mend together"). No other behaviour was tested.

Not checked: AI-controlled lightgeists (the `ignore_cooldown` path), other basic mobs, or the runtime log.

## Notes

- `add_ally(target)` in the lightgeist's `melee_attack` never runs for heals, because the heal cancels the chain and `melee_attack` returns FALSE. So healed people do not become allies in practice. This was left alone.
- Lightgeists can still damage objects for 5 damage per hit: `obj_damage = 0` falls back to `melee_damage`. Left unchanged.
- Other basic mobs with long `melee_attack_cooldown` values could show the same symptom for player-controlled clicks on objects. This was not investigated.
