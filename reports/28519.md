## Summary

The 2017 report says that when a player inside a mech has their equipment stripped (the example was a Colossus "honk" crystal turning them into a clown), the items vanish instead of dropping. On master, items dropped by a mech occupant land on the mech's tile. `dropItemToGround()` uses `drop_location()`, which walks up the `loc` chain to the first container that allows drops, and `/obj/vehicle/sealed` does not, so the turf is used. No code change was needed or made. The exact Colossus crystal sequence was not run end to end.

## The bug

As reported in 2017: a player in a mech with some gear is hit by something that drops all their equipment (the reporter saw it happen on a live server with a Colossus crystal that turned someone into a clown). The expected result is that the gear drops to the ground, as it does for a person standing next to the mech. The reporter said it was lost instead. In the comments, one maintainer asked if the items had gone inside the mech's contents rather than nullspace, and another pointed out that mech contents are not reachable by the player, so such items would be effectively lost either way. The issue carries the "Tested/Reproduced" label.

## Reproduction

Attempted on master with admin tools:

1. On the test server, start the round and observe, then open the Lua editor.
2. Create a human, equip it with the security job outfit (`/datum/outfit/job/security`), create a mining Ripley (`/obj/vehicle/sealed/mecha/ripley/mining`) and put the human in it with `mob_enter(human, true)`. The human's `loc` was the Ripley and the worn items were the security uniform, jackboots and backpack, among others.
3. Call `unequip_everything()` on the human. This is the same drop call the Colossus honk crystal makes for each worn item (`dropItemToGround`, `code/modules/mining/lavaland/mining_loot/megafauna/colossus.dm:213-214`).
4. Observed: the uniform, boots, backpack, helmet, armor vest, disabler and ID card all appeared on the mech's tile. Nothing went to nullspace and nothing stayed inside the mech. (The Lua script had a further call after the drop that raised a runtime error in the Lua editor, so the per-item location list was not returned; the result above comes from the items appearing on the tile in the observer's view and from the recorded notes.)

Other equipment-changing paths were tried with the human in a mech, to look for a nullspace case:

- Robotize: the old items ended up on the floor.
- `monkeyize()`, `set_species(plasmaman)` and `death()`: the old items stayed on the mob (their `loc` was the mob), nothing was nullspaced.
- `equipOutfit(clown)` over the security gear: the old items stayed in the mob's contents. A control human outside a mech behaved the same, so this is general behavior of equipping an outfit over existing gear, not something specific to mechs, and not what the issue describes.

Not done: the Colossus honk crystal itself (it only affects dead mobs, which it revives), and any other crystal or transformation that the reporter might have meant.

## Cause

There is no defect here. This is how the drop works on master:

- `mob/proc/dropItemToGround` passes `drop_location()` to `transfer_item_to_turf` (`code/modules/mob/inventory.dm:418`).
- `atom/proc/drop_location` (`code/game/atom/_atom.dm:612`) starts at the atom's `loc` and uses it only if `loc.AllowDrop()` is true; otherwise it recurses to that container's `drop_location()`:

  ```dm
  var/atom/location = loc
  if(!location)
      return null
  return location.AllowDrop() ? location : location.drop_location()
  ```

- `AllowDrop()` returns FALSE by default (`_atom.dm:458`) and TRUE for turfs (`code/game/turfs/turf.dm:680`). Lockers, storage items and a few special holders override it. `/obj/vehicle/sealed/AllowDrop()` returns FALSE (`code/modules/vehicles/sealed.dm:161`), and mechs are sealed vehicles.

So for a mob inside a mech, the chain goes mob, then the mech (not allowed), then the mech's turf (allowed), and the item is moved to that turf. The 2017 comments suggested an old `loc`-based drop as the cause; that code is no longer present, but the history was not examined (the checkout is shallow).

## Fix

None. No commit was made.

## Verification

The drop behavior was checked in game as described under Reproduction: with a security-geared human inside a Ripley, `unequip_everything()` put every item on the mech's tile. No runtime errors from the game code were noted other than the Lua script's own error mentioned above.

Not checked:
- The Colossus honk crystal end to end (revive and `dress_up_as_job` for a dead mob in a mech). Only its drop step was exercised, with the same call.
- Mech types other than the mining Ripley (all mechs derive from the same sealed vehicle type, but that was read from the code, not tested).
- Behavior of other vehicles or containers.

## Notes

- The issue looks closable, since master already drops the items on the turf.
- A related behavior seen on the way: `equipOutfit()` over existing gear leaves the previous items in the mob's contents instead of dropping them. This is the same inside and outside a mech and was not investigated further.
