## Summary

The reported behaviour, a poster that turns into a different poster after being taken down and hung again, no longer occurs on master. A random poster now records which poster it picked (`cutdown_type`) and gives that type back when it is rolled up, so re-hanging it shows the same poster. The linked upstream PR #94377 ("Fixes a range of poster bugs", merged 2025-12-11) describes this change. The "poster falls to the floor" part of the report could not be tied to a code defect.

## The bug

The reporter hung a rolled-up contraband poster from maintenance. It fell to the floor without the usual delay; picking it up and hanging it again produced a different poster. Later they added that removing a poster from a wall (even with wirecutters) and hanging it again always gives a different poster, while the wall dropping the poster is occasional. One maintainer could not reproduce it and suspected a poster given as the unspecific base type rather than a set poster.

## Reproduction

All steps were done on the test server at master `87b93338`.

1. With the Lua editor, spawn a human in a hallway, possess it, and give it an `/obj/item/poster/random_contraband` and wirecutters.
2. Hang the poster on a wall by clicking the wall. It became "poster - Space Cola".
3. Use the wirecutters on it ("You carefully remove the poster from the wall"), which gave a rolled poster, then hang it again. It was still "poster - Space Cola". Three cycles gave the same result every time.
4. Cancel a placement by walking away during the delay. The poster went back into the hand; after walking back and hanging it again it was still Space Cola. So "falls to the floor" matches an interrupted placement, and that path also keeps the poster type.
5. With a Lua loop, run 45 cycles (15 each for `/obj/structure/sign/poster/contraband/random`, `/official/random` and `/obj/structure/sign/poster/random`): create the structure, call `roll_and_drop`, and compare `original_name` of the item's `poster_structure` with the original. There were 0 mismatches.

The bug was not seen, so there is no failing run. Steps 2 to 4 used real clicks; step 5 called procs.

## Cause

The old defect, which master no longer has: a random poster is rolled back into an item by creating a new `cutdown_type`, and for a random poster that was the random base type, so it was re-randomised on re-hanging.

On master, `randomise()` sets `cutdown_type = initial(selected.type)` after picking the poster (`code/game/objects/effects/posters/poster.dm:210`). `return_to_poster_item()` builds the item from it with `new poster_item_type(location, new cutdown_type)` (`poster.dm:278`). `Initialize()` sets `cutdown_type = type` first (`poster.dm:163`) for posters that are not random.

## Fix

None needed. The upstream PR #94377 contains the change. PR #95445 is reported to have fixed tearing a poster mid-placement, which may relate to the falling-to-the-floor part, but this was not tested.

## Verification

Checked as in Reproduction: the type was stable across cycles with wirecutters, with a cancelled placement, and across the three random poster types. Not checked: posters mapped in the round the reporter used, or the Birdshot and Metastation maps specifically.

## Notes

- The wall "autodropping" the poster was not explained by any code defect; the only cause found was the placement delay being cancelled (moving, swapping hands).
- Holiday posters keep `cutdown_type`, but they may lose the festive name and icon when re-hung. This was not tested, and it is not the reported bug.
