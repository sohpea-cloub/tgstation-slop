# #70476: A double esword can stay wielded after its holder becomes a hulk

| | |
|---|---|
| Issues | [#70476](https://github.com/tgstation/tgstation/issues/70476): verified (reproduced on master) |
| Status | Fixed on the fix branch, verified in game with the Lua editor |
| Fix branch | [fix/70476](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/70476) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The double-bladed energy sword refuses to be wielded by a hulk, but the check runs only at the moment of wielding. If the sword is wielded first and the holder then gains hulk (an activated hulk mutation from a DNA injector, or the genetics console), nothing reacts, and the holder keeps a wielded sword with 40 force and its block and reflect chances. The fix makes the sword listen for `TRAIT_HULK` being added to its wielder and unwield itself with the usual "You lack the grace to wield this!" message.

## The bug

A player activates (wields) a double esword and then becomes a hulk, for example by being injected with hulk DNA or by using the genetics console on themselves. They end up as a hulk holding a wielded double esword. The issue describes this as "free stun immunity + projectile immunity": the hulk's own traits plus the sword's block and reflect, which are meant to be unavailable to hulks.

Discussion in the issue notes that hitting something with the sword in this state makes the hulk drop it ("accidentally drop it"), so it is not a usable weapon. The remaining problem is the passive effects of a wielded sword (blocking and reflecting) combined with hulk. Those commenters also suggested moving the hulk check into the shared two-handed component; that was not done here (see Notes).

## Reproduction

On master, with admin tools only (no player action was involved beyond what the Lua editor calls directly):

1. Start a round and open the Lua editor.
2. Spawn a human and a double esword (`/obj/item/dualsaber`), and put the sword in the human's hands.
3. Wield it through its two-handed component (the same call a player's activation makes).
4. Add the hulk mutation to the human with a source, for example `h.dna:add_mutation(/datum/mutation/hulk, 'activated')`. (Calling `add_mutation` without a source only produced a runtime, "add_mutation() called without set source(s)", and no mutation was tested that way.)

Observed on master after step 4:

- The sword was still wielded (`wielded = 1`).
- Its force was 40 and its name was "double-bladed energy sword (Wielded)".
- The human was holding it and had the hulk mutation.

Hitting something would still make the hulk drop the sword (the check in `attack()`), but this was not exercised. The effect on block and reflect was read from the code rather than measured in game.

## Cause

`/obj/item/dualsaber/proc/on_wield` (`code/game/objects/items/weaponry/melee/dualsaber.dm:59`) contains the only hulk check on the wield path:

```dm
if(user && HAS_TRAIT(user, TRAIT_HULK))
	to_chat(user, span_warning("You lack the grace to wield this!"))
	return COMPONENT_TWOHANDED_BLOCK_WIELD
```

This runs when `/datum/component/two_handed/proc/wield` invokes the wield callback (`code/datums/components/twohanded.dm:253`). Nothing watches for the trait being gained afterwards. The hulk mutation grants `TRAIT_HULK` through `mutation_traits` (`code/datums/mutations/hulk.dm:19-21`), which does not touch the held item. The sword's `hit_reaction` (line 158) and `IsReflect` (line 186) only test `TRAIT_WIELDED`, so a wielded sword in a hulk's hands keeps blocking and reflecting. The only other hulk handling is in `attack()` (line 132), which drops the sword when a hulk attacks with it.

## Fix

One commit, "Fix issue 70476: unwield a double esword when its wielder becomes a hulk", changing only `dualsaber.dm`:

- `on_wield`: after the existing checks pass, registers `SIGNAL_ADDTRAIT(TRAIT_HULK)` on the wielder, with a new handler `on_wielder_hulk`.
- `on_wielder_hulk`: sends the same "You lack the grace to wield this!" warning and calls `unwield` on the sword's two-handed component.
- `on_unwield`: unregisters that signal from the user.

Hooking the trait signal, rather than the mutation, covers every source of `TRAIT_HULK` (injector, genetics console, other sources that add the trait). Going through the component's `unwield` means the normal unwield path runs, so force, name, icon, weight class, light and processing are all restored by the existing code.

An alternative raised in the issue was to add an optional "no hulks" flag with a signal to the two-handed component itself. That would help other two-handed items but is a larger change; the sword-local fix was chosen as the smaller one.

## Verification

On the test server, rebuilt with the fix, using the Lua editor:

1. Spawned a human with a double esword, wielded it (`wielded = 1`).
2. Added the hulk mutation (source `activated`). The sword became unwielded (`wielded = 0`), with force 3 and the plain name "double-bladed energy sword" (no "(Wielded)").
3. Tried to wield again as a hulk: refused (`wielded = 0`).
4. Removed the hulk mutation and wielded again: it worked (`wielded = 1`, force 40).

No runtimes related to the sword appeared in the runtime log.

Not checked: the chat warning message as seen by a player; gaining hulk through the real DNA injector or genetics console (only `add_mutation` was used); hulk gained through other `TRAIT_HULK` sources; the sword being swapped, dropped or deleted while the signal is registered; a hulk holding the sword in a non-wielded state and then losing hulk.

## Notes

- `attack()` still prints "You grip the blade too hard and accidentally drop it!" for hulks. After this fix a hulk can no longer hold a wielded sword, so the drop branch is effectively unreachable, but it was left alone.
- Other hulk-restricted two-handed items were not changed. The chainsaw variant has its own `pre_attack` check and was not looked at beyond that.
- The stun immunity mentioned in the issue comes from the hulk mutation itself and is not affected by the sword; it was not tested. The fix only removes the wielded sword's contribution (block and reflect, and the 40 force).
- The suggestion in the issue comments to move this check into `/datum/component/two_handed` (using `TRAIT_HULK` rather than the DNA) would be a more general design; this fix does not preclude it.
