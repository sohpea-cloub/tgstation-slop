## Summary

A status effect that shows its time left writes it into the `maptext` of its alert. Some alerts add overlays on top of their icon: the lobstrosity gland's "Lobster Rush" alert has a lobster overlay, and the golem and Rock Absorption alerts have a sheet overlay. Those overlays are separate appearances and cover the alert's own maptext, so the timer is hard or impossible to read. The fix draws the timer as its own overlay, one step above the alert's layer, added last, so no other overlay can sit over it.

## The bug

Both reports show a buff alert in the top right of the screen whose duration text is hidden by a large image:

- #98086: after using a lobstrosity gland, the "time left is overshadowed by the giant chasm lobstrosity" image.
- #97864: after eating titanium ore (or any ore whose sheet image covers the timer) with the Rock Absorption mutation, the sheet image is layered over the duration, so the player can only tell the time is running out from the alert blinking.

## Reproduction

Reproduced and checked on the test server with admin tools (the Lua editor and the hud inspection), by applying the status effects directly. This confirms which appearance holds the text; it does not show the on-screen draw order (see Verification).

1. Start a round and open the Lua editor as an admin.
2. Apply the status effects with `apply_status_effect` to the admin's mob: `/datum/status_effect/lobster_rush` (the lobstrosity gland's buff), a golem buff (the titanium one, the mineral-eating Rock Absorption kind), and a food haste effect for a comparison.
3. Inspect the alert objects.

On master the duration text is the alert's own `maptext`, set in `update_shown_duration()` (`code/datums/status_effects/_status_effect.dm:95`), while the lobster and mineral images are overlays of that same alert. The reports describe, and attach screenshots of, the overlays drawn over the text. The draw order was not observed in the test server's client (see Verification).

## Cause

`/datum/status_effect/proc/update_shown_duration` (`code/datums/status_effects/_status_effect.dm:95`) shows the time left with:

```dm
linked_alert.maptext = MAPTEXT_TINY_UNICODE("<span style='text-align:center'>[round(duration / 10, 1)]s</span>")
```

The alert's icon overlays are added in `/atom/movable/screen/alert/update_overlays` (`code/_onclick/hud/screen_objects/alert.dm:144`), which adds the master atom's icon and `mutable_appearance(overlay_icon, overlay_state)` when `overlay_state` is set. The lobster gland's alert uses it:

```dm
/atom/movable/screen/alert/status_effect/lobster_rush
	...
	overlay_state = "lobster"
```

(`code/modules/mining/equipment/monster_organs/rush_gland.dm:54-58`). The golem alert (`code/game/objects/items/stacks/golem_food/golem_status_effects.dm:66-68`) adds `mineral_overlay` in its own `update_overlays`. The maptext belongs to the alert object itself, and overlays are drawn as separate appearances on top of the object's own icon and maptext, so a large overlay is drawn over the timer. Both issues are this one mechanism. That the overlays are drawn above the object's maptext is the working assumption of the fix, consistent with what the two issues report; it was not confirmed in game (see Verification).

## Fix

One commit, "Fix issue 98086: draw status alert timers as a top overlay so alert overlays can't cover them". It also fixes #97864.

- `alert.dm`: the alert gets a `text_overlay` variable and a `set_overlay_text(new_text)` proc. The first call builds a `mutable_appearance` at `layer + 0.1`, on the alert's plane, with `RESET_COLOR | RESET_TRANSFORM`, and copies the alert's `maptext_width`, `maptext_height`, `maptext_x` and `maptext_y`. It sets the text and calls `update_appearance(UPDATE_OVERLAYS)`. Passing null clears it. `update_overlays()` adds the text overlay last.
- `_status_effect.dm`: `update_shown_duration()` calls `linked_alert.set_overlay_text(...)` instead of setting `maptext`.
- `drug_effects.dm`: the saline-glucose dilution effect also wrote its percentage to `linked_alert.maptext` (line 135), so it uses `set_overlay_text` too.
- `blood_worm/actions/inject_blood.dm`: the blood worm transfusion effect copied `linked_alert.maptext` to its own alert (line 111). It now copies `linked_alert.text_overlay?.maptext` through `set_overlay_text`, since the source no longer holds maptext.

This was chosen over changing each overlay (moving or shrinking the lobster and mineral images), because any future alert overlay would cover the timer the same way. Making the timer the topmost overlay fixes every alert that shows a duration through the common code.

## Verification

On the fixed build on the test server, using the Lua editor:

- `lobster_rush`, a golem (titanium) effect and a `food/haste` effect were applied. No new runtimes were logged.
- Inspecting the "Lobster Rush" alert showed its overlays as the lobster image plus a text overlay containing the markup for "24s", with the alert at layer 3 and the text overlay at layer 3.1.
- The hud change reports showed the timer text changing once a second as overlay text.
- The golem alert for #97864 uses the same shared code path and was checked on the titanium golem buff.

Not checked:

- Whether the timer is now actually visible above the lobster and sheet images on a real client. The test setup could report the layers and overlay contents but not the rendered image, so the draw order has not been seen. The 0.1 layer offset puts the text last among the alert's overlays, which should be enough, but a real client should confirm it.
- The drug effect (saline-glucose dilution) percentage and the blood worm transfusion alert, which were converted for consistency but not run in game.
- The golem alert's blinking early-expiry animation together with the new overlay.
- Using the real lobstrosity gland, or eating ore with the real Rock Absorption mutation. The status effects were applied directly.

## Notes

- Any other code that writes to `linked_alert.maptext` will still be drawn under overlays. Besides the two converted places, the other maptext writes found in the alert code at master (role, time left, candidate count and stack count text in `alert.dm`) are set on separate overlay objects (`role_overlay`, `time_left_overlay`, `candidates_num_overlay`, `stacks_overlay`), not on the alert itself.
