# #74741: Kudzu spreads out through an anchored directional window on its own tile

| | |
|---|---|
| Issues | [#74741](https://github.com/tgstation/tgstation/issues/74741): verified and fixed (reproduced through a single-tile test, not the holodeck glass box from the report) |
| Status | Fixed on a branch |

| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Kudzu's `spread()` checks only whether the destination turf can be entered. It never checks whether the vine can leave its own tile, so a directional (border) window on the vine's tile that faces the spread direction does not block it. The fix adds a `loc.Exit(src, direction)` check, so the vine is blocked the same way a mob would be.

## The bug

On the holodeck on Meta station, kudzu got out of a box made of directional windows and caused a large outbreak. The reporter guessed that the vine counted as standing on the glass rather than being enclosed by it. A commenter replied that border objects are cursed, and a later comment (2024-08) with a screenshot says it still happened.

## Reproduction

This reproduces the missing exit check on a single tile, not the full glass box.

1. On the test server, as an observer with the Lua editor, spawn an `/obj/structure/window` on a hallway turf (107,144,2) with `dir` NORTH (anchored, dense).
2. Create a `/datum/spacevine_controller` on that turf and take its first vine.
3. In one Lua run, with no sleeps so the controller's own processing cannot interleave, call that vine's `spread()` 80 times. Then count the controller's vines on each neighbouring turf.

Result on master: one vine on each of the north, south, east and west neighbours (N=1 S=1 E=1 W=1). A vine appeared north of the north-facing window, on the side the window should block.

## Cause

`obj/structure/spacevine/proc/spread()` (`code/modules/events/space_vines/vine_structure.dm:160`) picks a random cardinal direction and then tests the destination only:

```dm
if(is_space_or_openspace(stepturf) || !stepturf.Enter(src))
	return
```

(`vine_structure.dm:168`). Nothing asks the vine's own tile whether it may leave in that direction. A directional window blocks leaving through its facing side by handling the exit signal (`COMSIG_ATOM_EXIT`) on the turf it stands on. The new vine is created with `master.spawn_spacevine_piece(stepturf, src)`, which makes a new object on the destination rather than moving anything, so that exit handling never runs. The window only helps when it is on the destination tile facing the vine, which `Enter` already covers.

The report's glass box fits the same cause: vines inside the box stand on tiles where an outward-facing window sits on their own tile.

## Fix

One commit: "Fix issue 74741: kudzu can spread out of a tile through an anchored directional window". It adds, after the `Enter` check in `spread()`:

```dm
// Border objects (directional windows etc.) on our own tile can block us from leaving it
if(!loc.Exit(src, direction))
	return
```

This reuses the same check that movement uses, so any border object that blocks exits on that side also blocks kudzu, not only windows. No other approach was tried.

## Verification

After the fix the game was rebuilt and restarted, and the same script ran again. Result: north 0, south 1, east 1, west 1, with nothing elsewhere. So the north-facing window blocked spread to the north and the other directions still worked. The runtime log showed no runtimes in either the before or the after round.

Not checked: a real holodeck glass box or any full-scale spread over time. Other kinds of border objects (railings, windoors) were not tried. Kudzu controlled by its normal processing loop was not observed; the test called `spread()` directly.

## Notes

- Windows facing inward on the destination tile were already blocked by `Enter` and were not affected by this change.
- Upstream PR #85760 (about shoving into closets) was looked at and is unrelated, not a fix for this.
