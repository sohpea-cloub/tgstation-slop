## Summary

The 2021 report said a roundstart Clown Operative (and Wizard) spawned on the arrivals shuttle when a spawn-location station trait such as Late Arrivals was active, and was only moved to the antagonist base afterwards. On master the nuclear operative and wizard jobs override `get_roundstart_spawn_point()` and return their own spawn directly, so the trait-aware spawn code is never reached for them. No code change was made. A full roundstart clown-ops round was not run (see Verification).

## The bug

As reported: with a station trait that changes where players start, an off-station antagonist briefly appeared, unequipped, at the trait's spawn location (the arrivals shuttle) and then teleported to the nuclear operative base. Comments on the issue explained why: the trait's spawn location replaced job-based placement, and the antagonist teleport only happened later.

## Reproduction

Not reproduced as a player-visible bug. What was done on the test server:

1. Started a round and opened the Lua editor as an admin.
2. Added `STATION_TRAIT_LATE_ARRIVALS` to `SSstation` (`add_traits({'station_trait_late_arrivals'}, 'test')`).
3. For `/datum/job/nuclear_operative`, `/datum/job/nuclear_operative/clown_operative`, `/datum/job/space_wizard` and `/datum/job/assistant`, fetched the job datum with `SSjob.get_job_type()` and called `get_roundstart_spawn_point()` directly.

Observed: for the nuclear operative and wizard jobs the call ran their own overrides and failed with `pick() from empty list` at `code/modules/jobs/job_types/antagonists/nuclear_operative.dm:5` and `space_wizard.dm:7`. Those lists (`GLOB.nukeop_elevator_start`, `GLOB.wizardstart`) are empty because the nuclear operative elevator and wizard den are only loaded by their rulesets. The error shows which code ran: the antagonist override, not the generic trait-aware version. The same call on the assistant job was part of the script, but I could not confirm from the available notes that it returned a usable result, so I draw nothing from it.

This was a direct proc call, not a real roundstart. The notes also leave it unclear whether the trait was actually present when the calls were made: the first script that added it errored later in the same run (a bad `get_turf` call), and later scripts did not re-add it. This does not change the conclusion, since the override ignores the trait either way.

## Cause

Generic roundstart placement is `/datum/job/proc/get_roundstart_spawn_point()` in `code/modules/jobs/job_types/_job.dm` (around lines 474-489). If the job allows random spawns it checks `STATION_TRAIT_LATE_ARRIVALS`, `STATION_TRAIT_RANDOM_ARRIVALS` and `STATION_TRAIT_HANGOVER` before using job spawn overrides or the default landmark. That ordering is the 2021 problem.

On master the antagonist jobs bypass it:

```dm
/datum/job/nuclear_operative/get_roundstart_spawn_point()
	return pick(GLOB.nukeop_elevator_start)
```

(`nuclear_operative.dm:4-5`; `/datum/job/nuclear_operative/clown_operative` inherits it.) `space_wizard.dm:6-7` does the same with `GLOB.wizardstart`. The roundstart rulesets force these jobs through `SSjob.forced_occupations` (`code/controllers/subsystem/dynamic/dynamic_ruleset_roundstart.dm:165`, `:259`, `:384`), and `create_characters` in `code/controllers/subsystem/ticker.dm` (around line 463) places each player at `assigned_role.get_roundstart_spawn_point()`. So these roles go straight to their own spawn point and the station traits are never consulted. I did not trace which commit introduced the overrides.

## Fix

None. No change is needed for the behaviour described in the issue.

## Verification

Checked: the code path above, and the live calls to the job procs with the trait active, which ran the antagonist overrides.

Not checked: a complete roundstart nuclear operative or clown operative round with a spawn-location trait. The ruleset requires a minimum population of 30 (`min_pop = 30`), which was not available. The wizard roundstart was not run either. The empty-list errors came from calling the procs before the base/den existed; in a real round the ruleset loads them first.

## Notes

- The issue can probably be closed as already fixed, but a maintainer may want to confirm with a real roundstart under Late Arrivals first.
- The generic hangover/random/late-arrivals handling still applies to every job that does not override `get_roundstart_spawn_point()`.
