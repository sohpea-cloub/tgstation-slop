## Summary

The 2019 report shows a runtime while the matches of a matchbox were being added to its storage: `forceMove(null)` called from the old `/datum/component/storage/concrete` "signal fill type" callback. That code no longer exists. On current master the storage is a `/datum/storage` and a matchbox creates its 10 matches synchronously in `PopulateContents()`, so putting a matchbox into a backpack by the same call the family heirloom quirk uses produced a full box and no runtime. There is no fix because there is nothing left to fix on master.

## The bug

The issue (opened 2019-02-17) suspected that matchboxes created inside backpacks by the family heirloom quirk (the Atmospheric Technician's job heirloom can be a matchbox) caused this runtime:

```
Runtime in atoms_movable.dm, line 408: No valid destination passed into forceMove
proc name: forceMove (/atom/movable/proc/forceMove)
src: the match (/obj/item/match)
src.loc: the matchbox (/obj/item/storage/box/matches)
call stack:
the match: forceMove(null)
/datum/component/storage/concrete: insert physical item(the match, 0)
/datum/component/storage/concrete: handle item insertion(the match, 1, null, null)
/datum/component/storage/concrete: signal fill type(the matchbox, /obj/item/match, 10, 0)
/datum/callback: InvokeAsync(the matchbox, /obj/item/match)
```

The trace shows the matchbox being filled asynchronously through a callback, and one of the matches already having been moved into the box (`src.loc` is the matchbox) when the storage component tried to move it again to a null destination. The only comment on the issue says nothing useful about the cause.

## Reproduction

Not reproduced on master. What was tried, with admin tools on the test server:

1. Joined as an observer and opened the Lua editor.
2. Spawned a human and put a backpack on their back.
3. Three times: created a new `/obj/item/storage/box/matches` and called `equip_in_one_of_slots(matchbox, {"in your backpack"}, false, true)` on the human. This is the same call the heirloom quirk makes through `give_item_to_holder()` (`code/datums/quirks/_quirk.dm:232`, with `qdel_on_fail = FALSE` and `indirect_action = TRUE`).
4. Read back the result of each call.

Evidence: each call returned `in your backpack`, the matchbox held 10 matches, and the matchbox's `loc` was the backpack. The `runtime.log` of the round contained no "Runtime in" lines.

Caveats:

- The first attempt used a `get_turf` call through the Lua global-proc wrapper, which failed ("bad proc" in `WrapAdminProcCall`), so the matchboxes were created with a null location and then equipped. That worked as well, but it is not the path the quirk takes (the quirk creates the item on the holder's turf first).
- The real quirk was not run on an Atmospheric Technician. The heirloom choice is random (see `code/datums/quirks/negative_quirks/family_heirloom.dm:19-31`), and only the equip call was exercised, not the whole quirk assignment at round start.
- Only the backpack slot was tried; the quirk can also use the pockets and hands first.

## Cause

There is no defect on master. The code path in the old trace was removed when storage was rewritten:

- Items are no longer stored by `/datum/component/storage`; they use `/datum/storage` (`storage_type = /datum/storage/box/match` on the matchbox, `code/game/objects/items/storage/boxes/service_boxes.dm:86`).
- `/obj/item/storage/Initialize()` creates the storage and then calls `PopulateContents()` directly (`code/game/objects/items/storage/storage.dm:15-19`).
- The matchbox fills itself in that proc, creating each match inside the box, with no callback or deferred insertion:

```dm
/obj/item/storage/box/matches/PopulateContents()
	for(var/i in 1 to 10)
		new /obj/item/match(src)
```
(`service_boxes.dm:91-93`)

The matchbox is still the Atmospheric Technician heirloom (`code/modules/jobs/job_types/atmospheric_technician.dm:27`), so the situation from the report can still occur; it just no longer goes through an async fill that can race with the item being moved.

## Fix

None. No commits.

## Verification

Checked: the heirloom equip call into a backpack, three times, gave a full matchbox (10 matches) in the backpack with no runtime in the round's log.

Not checked: the full quirk path for an Atmospheric Technician, the pocket and hand slots, and the failure mode where the holder has no backpack. No before/after comparison was possible, because there is no fix.

## Notes

- Suggest closing #42823 as obsolete: the runtime comes from code that was removed in the storage rewrite. The upstream PR that did this was not identified from the available inputs.
- The issue is flagged "Runtime" and "Bug"; the only comment (April 2019) suggests people were reproducing it maliciously and adds no information.
