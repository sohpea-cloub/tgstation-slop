# #57813: Labor Camp shuttle counts as fleeing the station (on IceBox)

## Summary

The 2021 report said a midround head revolutionary given to a player in the IceBox labor camp was counted as having fled the station when the labor shuttle took them back. On current master that scenario cannot happen on IceBox: the map has no labor shuttle, the camp is on station z-levels, and `can_be_headrev` refuses candidates who are off the station level. On the other maps the labor shuttle goes to lavaland, which counts as leaving the station, and the issue's own comments describe that as intended. No fix was written.

## The bug

As reported, a player was a prisoner in the labor camp when they were made a midround head revolutionary. After earning enough points and riding the labor shuttle back, they were counted as having fled the station. The reporter guessed this was related to IceBox's multi-level layout. A commenter pointed out that the shuttle spends its trip in the shuttle transit z-level, which is not a station level. Non-station levels are all treated as "away", so no per-level flag is needed to make them count as fleeing.

## Reproduction

Not reproduced. What was checked, on a test server running IceBox:

1. Loaded IceBox, started the round, and used the Lua editor to inspect the map.
2. `SSshuttle:getShuttle("laborcamp")` returned `nil`, and no stationary docking port with a labor-camp name existed.
3. `SSmapping:levels_by_trait("Station")` returned levels 2, 3 and 4, which are all of IceBox's levels. The area `/area/mine/laborcamp` exists inside `IceBoxStation.dmm`, so the camp is on those station levels.
4. A search of `_maps/map_files/IceBoxStation/IceBoxStation.dmm` found no `laborcamp_home` or `laborcamp_away` docks. Those docks exist only in Meta, Kilo, Delta, Nebula, Catwalk, Tram and the runtime station map. On IceBox the camp is reached on foot through the prison gate.

A head revolutionary was not actually spawned in the camp, and no objective result was observed. The conclusion rests on the map data and the code below.

## Cause

On IceBox there is no shuttle ride into the transit z-level, so the original trigger does not exist. Two code paths matter:

- `datum/objective/mutiny/check_completion` (`code/game/gamemodes/objective.dm:255-275`) completes when the target's turf is missing or `!is_station_level(T.z)`. Any target that is off the station levels, including on the transit z-level or lavaland, counts as having left.
- `can_be_headrev` (`code/modules/antagonists/revolution/revolution_handler.dm:159`) now has `if(!is_station_level(head_turf.z)) return FALSE`, so someone standing in an off-station place cannot be picked as a head revolutionary. The reporter's trigger, getting the role while off the station, is blocked. The IceBox camp is on a station level anyway.

On maps that do have a labor shuttle, it docks at lavaland, which is not a station level. The issue comments call this counting as leaving intended, and nothing in the code contradicts that.

`printplayer` in `code/__HELPERS/roundend.dm:701-716` has a `fleecheck` argument that prints "fleeing the station". No caller found in the tested source passes it.

## Fix

None. No commit was made.

## Verification

Nothing was changed, so there was nothing to verify. Only the checks listed under Reproduction were done. Not checked: any non-IceBox map in game, and the actual round-end or objective result of a prisoner head revolutionary riding the shuttle on a map that has one.

## Notes

- The issue looks closable for IceBox. Whether the behavior on other maps should be changed is a design call; the thread favoured leaving it.
- Side finding, not part of this issue and not fixed: `considered_exiled` in `code/__HELPERS/game.dm:61-68` has a misplaced parenthesis:

  ```dm
  if(istype(implant_check, /obj/item/implant/exile && player_mind.current.onAwayMission()))
  ```

  The `&&` ends up inside the `istype` type argument, so exile implants are likely never matched and the proc returns false. This affects `mutiny/check_completion` and the wizard check in `dynamic_ruleset_roundstart.dm:172`. It may be relevant to issue #58924, which was not examined here.
