# #71771: A shuttle landing on a disposal pipe deletes a cyborg's MMI

| | |
|---|---|

| Status | Fixed (depends on the fix for #41650, see Notes) |
| Fix branch | [fix/71771](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/71771) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a shuttle docks on a turf holding an anchored disposal pipe, the pipe is `qdel`ed together with whatever is travelling through it. A cyborg inside the pipe is not gibbed first. The fix makes the pipe expel its contents before it is deleted, and stops a brain inside an MMI from being shuttle-gibbed on its own, which would also delete the MMI. The MMI survives the landing, but the fix branch also carries the #41650 change (shuttles crushing mobs inside containers), which this one builds on.

## The bug

The report describes a shuttle landing on a pipe that contained a cyborg and the MMI ending up "in nullspace". The screenshots were not available to us. In the reproduction below the MMI was not in nullspace as such: it had been deleted (it showed as "at nonexistent location"), which is how a deleted object looks from the outside. A comment on the issue guessed this: the shuttle deletes the pipe, the cyborg goes with it, and the MMI has no location left.

## Reproduction

Using admin tools on the test server (Lua editor and SDQL2) with the stock map:

1. While the cargo shuttle is away from its home dock, create a `/obj/structure/disposalpipe/segment` on the home dock turf (63,151,2).
2. Create a `/obj/structure/disposalholder` inside it, and a `/mob/living/silicon/robot` inside the holder.
3. Bring the shuttle in with `SSshuttle.moveShuttle('cargo', 'cargo_home', TRUE)` and wait for it to dock. This is a real landing, not a call to the move procs.
4. Run the SDQL2 query `SELECT /obj/item/brain_processor`. The borg's MMI was listed as "at nonexistent location". In the Lua editor its `gc_destroyed` was set and its brainmob was nil.
5. The borg was not gibbed, and no shuttle log line was written for it.

The borg was placed by script and has no player mind, so this is not exactly a player riding the pipe in a borg shell.

## Cause

`/turf/proc/toShuttleMove()` (`code/modules/shuttle/mobile_port/shuttle_move_callbacks.dm:19-47`) loops over the contents of each landing turf. Living mobs on the turf are gibbed. For anything else, an unanchored object is pushed (`step`) and an anchored one is deleted:

```dm
else if(!ismob(thing))
	if(!thing.anchored)
		step(thing, shuttle_dir)
	else
		qdel(thing)
```

An anchored disposal pipe takes this last branch. A cyborg travelling through the pipe sits in a `/obj/structure/disposalholder` inside the pipe, not on the turf, so the mob check never sees it. Deleting the pipe deletes the holder and its contents, including the borg's MMI.

The branch also showed two further problems once the first was addressed:

- With only the #41650 change in place (which gibs mobs found inside containers, using `get_all_contents_type(/mob/living)`), the borg was gibbed but the MMI was still deleted. The MMI's brainmob is itself a `/mob/living` inside the contents, and `/mob/living/brain/gib()` (`code/modules/mob/living/brain/death.dm:14-16`) does `qdel(container)`, which is the MMI. The borg then showed up twice in the shuttle log.
- Skipping the brainmob was still not enough. A gibbed cyborg drops its MMI at `drop_location()`, and that location is the disposal holder, because `/obj/structure/disposalholder/AllowDrop()` returns TRUE (`code/modules/recycling/disposal/holder.dm:208-209`). The anchored pipe is then deleted, and `/atom/movable/Destroy` deletes the holder and the MMI with it.

## Fix

Two commits on the branch:

1. "Fix issue 41650: shuttles now crush mobs inside lockers and other containers" is the #41650 change cherry-picked. It moves the gib logic into `/mob/living/proc/get_crushed_by_shuttle()` and applies it to mobs found inside things on the landing turf. It is another issue's change; see Notes.
2. "Fix issue 71771: a shuttle landing on a disposal pipe no longer deletes a cyborg's MMI" changes `toShuttleMove()` in two ways:
   - In the loop over mobs found inside a thing, it skips any `isbrain()` mob and any mob whose `loc` is another mob, so the brainmob in an MMI is not gibbed on its own and a cyborg that is gibbed still drops its MMI normally.
   - Before deleting an anchored `/obj/structure/disposalpipe`, it calls `spew_forth()`, which expels the pipe's contents (a cyborg's MMI, gibs, packages) onto the surroundings.

Expelling the pipe's contents seemed better than special-casing MMIs: whatever is in the pipe survives the landing, not only MMIs.

## Verification

Checked on the test server, repeating the real shuttle landing from the reproduction:

- Unfixed master: MMI deleted, no gib.
- #41650 change alone: borg gibbed, MMI still deleted (both causes above).
- With both commits: one shuttle log line ("Default Cyborg-971 was shuttle gibbed by the supply shuttle"). The MMI was alive at 56,168 on z 2 (space), thrown out by the pipe's expel. The runtime log stayed clean.

Not checked:

- A cyborg with a real player mind (the mind transfer in `dump_into_mmi`).
- Pipe types other than the straight segment, and unanchored pipes.
- Other things carried by a pipe besides the cyborg.

## Notes

- The change shares `toShuttleMove()` with the #41650 fix, so the two will conflict or must land in order. The branch contains the cherry-picked commit for that reason.
- The `isbrain(trapped) || ismob(trapped.loc)` skip is not specific to disposals. It is also needed in #41650's loop, since a cyborg or MMI brain in any container would otherwise have its MMI deleted by gib. It should be folded into that change.
- This touches shuttle landing, which is core code and worth a careful review.
