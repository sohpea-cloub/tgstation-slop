The two issues are unrelated bugs that both involve the supermatter. They were worked in one unit and each has its own commit.

## Summary

**#34731.** `/obj/item/hemostat/supermatter/proc/Consume()` calls `dust()` on a mob and ignores the result. Living megafauna (and living `/mob/living/basic/boss` mobs) refuse to be dusted, but the tongs still print the "both flash into dust" message, write the "has consumed" admin log line, dust the user and destroy the sliver. The fix makes `dust()` return whether it dusted anything. The tongs now stop with an "unaffected!" balloon alert when it did not, and the user and sliver are left alone.

**#84223.** The supermatter's `attackby_hit` returns early for every item with the `ABSTRACT` flag. The nightmare's light eater is an abstract hand replacement, so hitting the supermatter with it did nothing to the user, although the item's own effect still put out the crystal's light. The fix lets non-droppable hand replacements fall through to the existing "item is stuck to the person, dust the person" branch.

## The bug

### #34731

A player hits a living megafauna with supermatter extraction tongs holding a sliver. Chat reports that the user and the megafauna "flash into dust", and admins see `The supermatter extraction tongs has consumed *no key*/(colossus)`. The megafauna is untouched, because megafauna refuse to be dusted while alive. The user does die and the sliver is gone, so the messages and the log claim a consumption that did not happen.

### #84223

A nightmare, or anyone who has gained a light eater, hits the supermatter with it. The crystal's light goes out and the user sees "You hit the supermatter crystal with the light eater, without leaving a mark!". The user is not dusted. Every other item or body part that touches the crystal is consumed, and the user is dusted if the item cannot be dropped.

## Reproduction

Both were reproduced on the test server as an observer, using the Lua editor to spawn objects and call procs. They were triggered by calling procs directly, not by a player clicking. For #34731 the call was `interact_with_atom` on the tongs, which is what a click on a mob runs. For #84223 the call was `ClickOn`.

### #34731

1. Using the Lua editor, spawn a human, a `/mob/living/simple_animal/hostile/megafauna/colossus` and a `/obj/item/hemostat/supermatter` on the same turf. Create a `/obj/item/nuke_core/supermatter_sliver` inside the tongs, assign it to the tongs' `sliver` variable and call `update_appearance()`.
2. Call `tongs.interact_with_atom(colossus, human, {})`, with the human as the user.
3. Observed on master:
   - Chat: "As <user> touches the colossus with the supermatter extraction tongs, both flash into dust and silence fills the room...".
   - Admin log: `ADMIN LOG: The supermatter extraction tongs has consumed *no key*/(colossus) (JMP).`
   - State afterwards: the colossus had health 2500 and `stat` 0 (alive and unharmed). The user's `stat` was 3 (dead). The tongs' `sliver` was nil.

### #84223

1. Using the Lua editor, spawn a `/obj/machinery/power/supermatter_crystal/shard`. Spawn a human and put a `/obj/item/light_eater` in the human's active hand (`put_in_active_hand(item, TRUE)`).
2. Record the crystal's `light_on` (it was 1), then call `human.ClickOn(crystal)`.
3. Observed on master: the human's `stat` was 0 (alive), the crystal's `light_on` had gone from 1 to 0, and the light eater was still in the human's hands.

## Cause

### #34731

`Consume()` in `code/game/objects/items/tools/theft_tools.dm:327` handles a living target like this:

```dm
victim.investigate_log("has been dusted by [src].", INVESTIGATE_DEATHS)
victim.dust()
message_admins("[src] has consumed [key_name_admin(victim)] [ADMIN_JMP(src)].")
investigate_log("has consumed [key_name(victim)].", INVESTIGATE_ENGINE)
```

(lines 333-338; the `dust()` call is line 335). It then goes on to the chat message, `user.dust()` (line 349) and `QDEL_NULL(sliver)` whatever `dust()` did.

`dust()` can refuse. `/mob/living/simple_animal/hostile/megafauna/dust()` (`code/modules/mob/living/simple_animal/hostile/megafauna/_megafauna.dm:116`) and `/mob/living/basic/boss/dust()` (`code/modules/mob/living/basic/boss/boss.dm:56`) both start with `if(!force && health > 0) return`. `dust()` itself (`code/modules/mob/living/death.dm:101` and the `/mob/living` override below it) returned nothing, so a caller had no way to tell success from refusal. This matches the diagnosis in the issue comments.

### #84223

`attackby_hit` in `code/datums/components/supermatter_crystal.dm:157` starts with:

```dm
if(!istype(item) || (item.item_flags & ABSTRACT) || !istype(user))
	return
```

(line 160). `ABSTRACT` is meant to exclude things that are not physical items. The light eater is also `ABSTRACT`, but it is a hand replacement given `TRAIT_NODROP` from `HAND_REPLACEMENT_TRAIT`, so it is physically the user's hand. Because of the early return, the code never reached the branch at line 200 (`if(atom_source.Adjacent(user)) //if the item is stuck to the person, kill the person too ...`). That branch is what dusts a user whose item cannot be dropped (`user.dropItemToGround(item)` at line 189 fails for a no-drop item). The light eater's own effect on the crystal's light is separate and was not affected.

## Fix

**Fix issue 34731: supermatter tongs no longer claim to consume a megafauna that can't be dusted.**
- `/atom/movable/dust()` and `/mob/living/dust()` in `death.dm` now return `TRUE`, and the doc comment says so.
- The guardian and revenant overrides, which end in `death()` without calling the parent, also return `TRUE`.
- The megafauna and boss overrides return `FALSE` where they refuse.
- In `Consume()`, a mob target is now dusted with `if(!victim.dust())`. On failure the tongs show a balloon alert "unaffected!" to the user and return before the log lines, the user's dusting and the sliver's destruction. The "has been dusted by" investigate log call moved to after the check, so it is also no longer written falsely.

I chose to make `dust()` report its result rather than test for megafauna in the tongs, because the refusal logic already lives in the `dust()` overrides and the tongs should not duplicate it. Other callers of `dust()` ignore the return value, so they behave as before.

**Fix issue 84223: hitting a supermatter with a light eater now dusts the user.**
- The early return in `attackby_hit` now ignores the item only if it is `ABSTRACT` and does not have `TRAIT_NODROP` from `HAND_REPLACEMENT_TRAIT`. Such hand replacements are no longer skipped.
- They then follow the existing path: the drop fails, and the user is dusted by the "stuck to the person" branch.

## Verification

After rebuilding on the test server, with the same Lua editor calls as above:

- **#34731:** `interact_with_atom` on the colossus returned 1 (the interaction counted as handled) and the colossus still had 2500 health. The user's `stat` was 0 (alive) and the sliver was still in the tongs. No "consumed" admin log line was produced for the colossus.
- **Control:** the same tongs used on another human still dusted the user (`stat` 3), and the admin log still recorded `The supermatter extraction tongs has consumed ...` for the victim.
- **#84223:** after `ClickOn(crystal)` with a light eater in hand, the user's `stat` was 3 (dead), the admin log recorded the supermatter shard consuming the user, and `light_on` was still 0.
- The runtime log for the round showed no runtimes related to dusting, the tongs, the supermatter component or megafauna. It did contain 84 other runtime entries from round start, which were not examined individually.

Not checked:
- Neither bug was tried through real mouse clicks by a player character; both were called through the Lua editor.
- Only the colossus was tried as a megafauna, and no `/mob/living/basic/boss` mob was tried. The boss change follows the same pattern but was not run.
- No dead megafauna was tried, which should still be dusted.
- The guardian and revenant `dust()` return values were not exercised.
- Hand replacements other than the light eater were not tried (see Notes).

## Notes

- **Failed touch on a megafauna.** The fix makes the touch do nothing: no dusting of the user and the sliver is kept. Maintainers may prefer a different outcome (for example, still dusting the user), since the sliver is touching something. The issue comments only ask that the messages and logs be correct.
- **The #84223 fix is not specific to the light eater.** It applies to every `ABSTRACT` item with `TRAIT_NODROP` from `HAND_REPLACEMENT_TRAIT`. In the code searched, that trait is added in `code/datums/components/mutant_hands.dm` (line 152) and `code/datums/components/prosthetic_item.dm`, so mutant hands and prosthetic items are affected as well. Bare hands already dust the user, so this seems consistent. This was not tested for those cases.
- **What #84223 should do.** The issue comments suggest the light eater should still eat the light and dust the user. The fix does that. Making the light eater harmless to the user on purpose would instead need an explicit exception.
- The interaction between #84223 and the light eater's own effect is untouched: the crystal's light still goes out, as in the issue.
