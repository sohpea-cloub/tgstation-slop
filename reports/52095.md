# #52095: Changeling transforming back from a gigantism identity stays gigantic

| | |
|---|---|
| Issues | [#52095](https://github.com/tgstation/tgstation/issues/52095): verified and fixed (the "phantom PDA" part is intended behaviour) |
| Status | Fixed |
| Fix branch | [fix/52095](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/52095) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A changeling that transforms into someone who has the Gigantism mutation keeps Gigantism (size 1.25) after transforming back to its own identity. `transform()` copies the target profile's gene sequence and then calls `domutcheck()`, which only revisits genes that are in the new sequence, so an activated mutation that is not in the sequence being copied in is never removed. The fix removes activated mutations that are no longer in the sequence right after the sequence is copied and before `domutcheck()` runs. The "phantom PDA" in the same report is the changeling's fake clothing and works as designed.

## The bug

The reporter turned into a person with Gigantism, then tried to turn into someone else (or back) and stayed gigantic. They also saw a "phantom PDA" that did not open doors.

- Gigantism: after the changeling transforms into a giant identity and then back to its original one, it keeps the Gigantism mutation and its 1.25x size.
- Phantom PDA: the issue's comments explain that it is a piece of the changeling's fleshy pseudo-clothing, made to look like what the transform target wore. It has the appearance but not the function of the item, melds into the body when its slot would otherwise be filled, and can be removed by clicking it (or alt-clicking it). This is intended and was not changed.

A 2024 comment on the issue says the bug could not be replicated because `copy_dna()` fails with a null holder when copying mutations through changeling powers. That did not apply to current master (see Notes).

## Reproduction

Reproduced with the Lua editor from an observer, by calling the changeling's `transform()` directly rather than using the ability button.

1. As an admin, open the Lua editor and spawn two humans, A and B. Give A a changeling antagonist datum.
2. Give B the Gigantism mutation with source `activated`, and make sure Gigantism is in B's gene index with its gene active. A plain `add_mutation` on B is not enough: Gigantism was only carried into the changeling profile when it was in B's gene sequence. This was done by calling `generate_dna_blocks()` on B until Gigantism appeared in its index, then adding the mutation as activated and setting the gene block. Ling profiles are created with the default copy flags and do not copy mutations that are not gene-based.
3. Call `add_new_profile(B)` on A's changeling datum, then `transform(A, profile of B)`, then `transform(A, A's first profile)`.

Observed on master:

- `A as giant: size=1.25 gmut=Gigantism`
- `A back: Ling Alpha size=1.25 gmut=Gigantism`

So after transforming back, A had its own name but still had the Gigantism mutation and size 1.25. (In an earlier attempt where Gigantism was not in B's gene index, the profile did not carry it, and A stayed at size 1 throughout.)

## Cause

In `code/modules/antagonists/changeling/changeling.dm`, `transform()` (`:756`) copies the chosen profile's DNA with `chosen_dna.copy_dna(user.dna, COPY_DNA_SE|COPY_DNA_SPECIES)` (`:785`) and then calls `user.domutcheck()` (`:791`).

`copy_dna()` with `COPY_DNA_SE` replaces the target's `mutation_index` with the profile's (`code/datums/dna/dna.dm:90`). `/mob/living/carbon/domutcheck()` (`dna.dm:507`) then does:

```
for(var/mutation in dna.mutation_index)
	dna.check_block(mutation)
```

`check_block()` (`:516`) adds or removes the activated mutation for a gene, but only for genes that are in the (now new) `mutation_index`. The changeling's own sequence has no Gigantism gene. After transforming into the giant, Gigantism is in the sequence and gets activated. When transforming back, the sequence no longer lists Gigantism, so it is never checked and its `MUTATION_SOURCE_ACTIVATED` source is never removed.

## Fix

One commit, "Fix issue 52095: changeling transform leaves the old identity's activated mutations". In `transform()`, between `copy_dna()` and the `domutcheck()` call, it loops over a copy of `user.dna.mutations` and, for each mutation that has the `MUTATION_SOURCE_ACTIVATED` source and is not in the new sequence (`mutation_in_sequence()`), calls `remove_mutation(old_mutation, MUTATION_SOURCE_ACTIVATED)`. Mutations from other sources (for example ones that are not gene-based) are left alone, and mutations that are in the new sequence are still handled by `domutcheck()` as before.

## Verification

With the same Lua steps on the fixed build, two full round trips (transform into the giant, transform back, then again) gave `size=1 gmut=nil` on each return and `size=1.25 gmut=Gigantism` each time as the giant. No new runtimes were logged.

Not checked: the transform ability itself (the in-game button and sting), only calls to `transform()` made from the Lua editor; mutations other than Gigantism; a changeling who gained Gigantism through a different source (for example a mutator or injector) before transforming; and the phantom PDA behaviour, which was taken from the issue comments.

## Notes

- The 2024 comment's stack trace (`add_mutation` called from `copy_dna()` from `create_profile()` with a null holder) was not reproduced on master. Profiles are created with default copy flags and do not copy non-gene mutations. The comment appears to describe a different path, which is not established here.
- Not changed: `copy_dna()` assigns the `mutation_index` list by reference, so DNA datums that were copied from one another share the same list (`dna.dm:90`), and `is_same_as()` relies on that reference equality. A transformed changeling therefore shares its index list with the profile it copied. This was left as it is.
- The fix only removes activated mutations. Whether other mutation sources (for example ones the changeling gained by other means) should also be dropped on transform is a design question that was not examined.
