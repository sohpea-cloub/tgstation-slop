## Summary

Two windoors in Catwalk Station's virology, the isolation room door and the monkey cell door, had no `req_access`, so anyone, including a monkey, could open them. The other maps give the equivalent windoors `req_access = list("virology")`. The fix adds that to both windoors in `CatwalkStation_2023.dmm`. The issue's second point (the upstairs virology layout) is a design opinion and was not changed.

## The bug

The issue reports that the isolation windoor and the monkey cell windoor on Catwalk have no access assigned. A monkey in the cell can therefore walk out of it, and anyone can enter isolation. The issue also remarks that the upstairs virology room is awkwardly laid out, with the tables on the opposite side of the room from the fridge and the PANDEMIC.

## Reproduction

1. Set the next map to Catwalk Station, start the test server, start the round and join.
2. Open the Lua editor and list the windoors in the "Virology" area (via the machine subsystem's list of machines by type).
3. Read each one's `req_access`.

Observed on master: the isolation windoor (a `brigdoor`) and the monkey cell windoor, which the listing showed as `secure door` and `interior door`, both had no `req_access`. The two other virology windoors had medical access.

## Cause

In `_maps/map_files/CatwalkStation/CatwalkStation_2023.dmm`, tile `bZo` (around line 7716) holds `/obj/machinery/door/window/right/directional/west`, the monkey cell, and tile `lWZ` (around line 45027) holds `/obj/machinery/door/window/brigdoor/left`, the isolation door. Neither sets `req_access`, so `allowed()` passes for everyone. Meta, Delta and Kilo set `req_access = list("virology")` on the corresponding doors.

## Fix

One commit, "Fix issue 97282: Catwalk virology isolation and monkey cell windoors require virology access", adds `req_access = list("virology")` to both windoors in the map file. This copies what the other maps do. The layout complaint was left alone because it needs a subjective remap.

## Verification

After restarting the server with the fix, the same listing showed both windoors with `req_access = virology`. A spawned monkey and a bare human (no ID) each got `windoor:allowed() = 0` on the fixed windoors.

Not checked: a positive case, that a human with a virology ID can open them. The access string is the standard `"virology"`, so it is expected to work. The map was not otherwise inspected for other windoors lacking access.
