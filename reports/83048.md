# #83048: Player-controlled cleanbots can't climb ladders

| | |
|---|---|
| Issues | [#83048](https://github.com/tgstation/tgstation/issues/83048): verified, fixed. [#88500](https://github.com/tgstation/tgstation/issues/88500): verified, fixed (separate bug in the same click handling) |
| Status | Fixed, verified on the test server |
| Fix branch | [fix/83048](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/83048) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary
A cleanbot carries a `/datum/component/cleaner` that answers every unarmed click by scrubbing the target and cancelling the attack chain, so a player-controlled cleanbot never reaches a ladder's own interaction. The fix gives the component a `pre_clean` callback that skips ladders. Separately (#88500), clicking a roach or mouse sent the attack through the bot's always-dry mop, giving "mop is dry!" and no attack, and ignored the bot's pest-control setting. The fix checks the setting and hits the pest with the mop directly.

## The bug
### #83048
A sentient cleanbot that clicks a ladder (left or right click) starts cleaning it instead of climbing. Other bots can use ladders when possessed.

### #88500
A sentient cleanbot that clicks a cockroach with pest killing off gets "mop is dry!", which has nothing to do with the cause. The report says left and right click, with harm intent on and off, all gave this message. With pest killing on the pest was not hit either.

## Reproduction
### #83048
1. On the test server, open the Lua editor. Spawn a `/obj/structure/ladder` and a second one on the level above, created with the first as its `up` argument (the map had no ladders, so `GLOB.ladders` was empty).
2. Spawn a `/mob/living/basic/bot/cleanbot` next to the ladder and possess it with `PossessByPlayer(ckey)`.
3. Click the ladder with left and with right click. A bubbles overlay and a progress bar appeared (cleaning); the bot did not climb.

### #88500
1. Same cleanbot as above. Spawn a cockroach next to it.
2. Click the roach with pest control off, then with it on (`janitor_mode_flags` set to 5).
3. Both times a "mop is dry!" balloon alert appeared and the roach was unharmed.

Both were reproduced by possessing the bot and clicking, not by calling procs.

## Cause
### #83048
`code/modules/mob/living/basic/bots/cleanbot/cleanbot.dm:140` adds `/datum/component/cleaner` to the cleanbot mob itself. The component registers `COMSIG_LIVING_UNARMED_ATTACK` (`code/datums/components/cleaner.dm:39`), and `on_unarmed_attack` (line 53) returns `COMPONENT_CANCEL_ATTACK_CHAIN` (line 56) whenever the clean attempt succeeds. The only gate is `pre_clean_callback` (line 70), which the cleanbot used just to set its mode (`update_bot_mode(BOT_CLEANING)`, `cleanbot.dm:142`) and never to refuse. So every click by a sentient cleanbot became a scrub and never reached the ladder's `attack_animal`.

### #88500
`pre_attack` (`cleanbot.dm:319`) handled pests with
`INVOKE_ASYNC(our_mop, TYPE_PROC_REF(/obj/item, melee_attack_chain), src, target)` (line 326). The mop has its own cleaner component whose callback `should_clean` (`code/game/objects/items/mop.dm:50`) shows "mop is dry!" (line 54) and blocks the interaction. The bot's mop is always dry, so the attack never happened. `pre_attack` also never checked the bot's `CLEANBOT_CLEAN_PESTS` flag; only the AI checks it when choosing targets.

## Fix
- **"Fix issue 83048: sentient cleanbots can use ladders"**: adds a static `uncleanable_targets` typecache (currently only `/obj/structure/ladder`) and a `pre_clean` proc used as the cleaner's `pre_clean_callback`. For those targets it returns `CLEAN_BLOCKED|CLEAN_DONT_BLOCK_INTERACTION`, so the cleaner is skipped and the click goes on to the ladder. For anything else it calls `update_bot_mode(BOT_CLEANING)` as before.
- **"Fix issue 88500: sentient cleanbots no longer say 'mop is dry' at pests"**: for targets in `huntable_pests`, `pre_attack` now first checks `CLEANBOT_CLEAN_PESTS`; if off it shows "pest control disabled!" and cancels the attack chain. If on, it calls the mop's `attack(target, src)` directly rather than `melee_attack_chain`, so the mop's cleaner is not involved.

## Verification
After rebuilding, with the same steps:
- Left click on the ladder: "climbing up..." appeared and the bot arrived on the upper level (a goliath then killed it; unrelated).
- Roach with pest control off: "pest control disabled!", roach unharmed.
- Roach with pest control on: "You attack the cockroach in the chest with the mop!" and the roach died.

Not checked: right click on the ladder (going down) after the fix. It should use the same path (cleaner skipped, then `attack_animal_secondary`) but was not tested separately. Mice were not tested, though they share `huntable_pests` with roaches. Pest control off with harm intent versus other intents was not varied.

## Notes
- Only ladders are excluded. Any other structure with its own `attack_animal` interaction is still scrubbed instead of used by a sentient cleanbot. Widening `uncleanable_targets` is a one-line change if maintainers want more types.
- The mop is hit with `attack()`, which skips the item interaction steps `melee_attack_chain` would run; this is what avoids the mop's cleaner.
