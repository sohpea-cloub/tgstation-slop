# #56100: Dynamic admin panel timers shown with the wrong unit

## Summary

The issue (2021) reported that the Dynamic admin panel stored its timers in deciseconds but displayed them as seconds. This does not happen on current master: the server sends raw deciseconds and the panel's `formatTime()` divides by 10 before splitting into hours, minutes and seconds, for every timer shown. The panel in the issue's video has since been replaced, so there is nothing to fix.

## The bug

As reported, the timers in the Dynamic panel (such as the time until the next midround or latejoin ruleset) were ten times too large, because values in deciseconds were presented as if they were seconds. The issue has no text, only a video of the old panel.

## Reproduction

Not reproduced.

1. Started a round on the test server and, as an admin, ran the `Dynamic Panel` verb while still in the lobby.
2. Read the data the panel received.

Observed:

- `next_dynamic_tick` was `1000`. The lobby countdown had about 100 seconds left, so the value is in deciseconds.
- `time_until_lights` and `time_until_heavies` were `0` (no cooldown running).

With the conversion in the panel's code, 1000 deciseconds is shown as `0h 1m 40s`, which matches the roughly 100 seconds left. The rendered panel was not inspected visually, only the data it was given and the code that formats it. Timers other than `next_dynamic_tick` were `0` at that point, so their formatting was checked in the code only.

## Cause

There is no defect on master. The relevant code:

- The server side sends raw deciseconds. `code/controllers/subsystem/dynamic/dynamic_admin.dm:66-68` sets `time_until_lights`, `time_until_heavies` and `time_until_latejoins` with `COOLDOWN_TIMELEFT(...)`. Lines 70-71 do the same for `time_until_next_midround` and `time_until_next_latejoin`. Line 84 sets `next_dynamic_tick` to `SSdynamic.next_fire - world.time` (or `SSticker.GetTimeLeft()` before the subsystem has fired). All of these are deciseconds.
- The UI converts them. `tgui/packages/tgui/interfaces/DynamicAdmin.tsx:73-81` defines:

```ts
function formatTime(seconds: number): string {
  seconds /= 10;
  if (seconds < 0) {
    return 'never';
  }
  ...
  return `${hours}h ${minutes}m ${secs}s`;
}
```

Every timer in the panel goes through this function (`DynamicAdmin.tsx` lines 203, 219-220, 261, 277-278, 319, 335). The other Dynamic interface, `DynamicTester.tsx`, shows no timers.

## Fix

None committed; nothing to fix.

## Verification

Checked in game: the panel's `next_dynamic_tick` value was in deciseconds as described above. Not checked: how the panel renders, and the other timers while they are counting down (midround, latejoin and ruleset cooldowns), which would need a running round with those cooldowns active.

## Notes

- Cosmetic only: the parameter of `formatTime()` is named `seconds` but it receives deciseconds, which is probably the confusion the issue title describes. Renaming it (for example to `deciseconds`) would make the code match its behavior; this is not a bug.
- The issue carries the "Tested/Reproduced" label from 2021. Since then the panel has been rewritten, and the current one converts correctly, so the issue can likely be closed as fixed.
