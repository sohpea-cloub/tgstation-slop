## Summary

`SSjob.overflow_role` is the job with unlimited slots, and an admin or the config can change it (the issue's example is Clown). Most of the code paths the 2019 issue lists now use it. Two spots still assumed Assistant: `IsJobUnavailable()` in the new-player code, which gave only Assistant the "newbies can always join" and "full unless other slots are open" rules, and the imaginary friend's fallback appearance job. Both now use `SSjob.overflow_role`.

## The bug

If the overflow role is changed (for example to Clown), the lobby's slot rules for it do not follow:

- A job that is full is normally unavailable. The exception is the overflow role: a player whose account age is 14 or less may always take it, and anyone else may take it when no other job has an open slot. `IsJobUnavailable()` applied that exception to Assistant only. With Clown as overflow role, a full Clown was refused to a brand-new player, and a full Assistant was still treated as the overflow job.
- An imaginary friend whose owner's preferences have no job at High priority used Assistant for its look, whatever the overflow role was.

## Reproduction

On master, in the lobby (no round needed), using the Lua editor and a lobby `/mob/dead/new_player` as the caller:

1. Call `SSjob:set_overflow_role(/datum/job/clown)`.
2. Fill the Assistant job (set `current_positions` equal to `total_positions`, 5 in the test) and set `client.player_age = 0`.
3. Call `IsJobUnavailable('Assistant')`. Then do the same with `player_age = 30`.
4. Set Clown to 2 total and 2 current positions. Call `IsJobUnavailable('Clown')` with `player_age = 0`, then with `player_age = 30`.

Return values are `JOB_AVAILABLE` = 0 and `JOB_UNAVAILABLE_SLOTFULL` = 5 (`code/__DEFINES/jobs.dm`). Results on master:

| Job (full) | Player age | Result |
|---|---|---|
| Assistant | 0 | 0 (available: the newbie rule was applied to a job that is no longer the overflow role) |
| Assistant | 30 | 5 |
| Clown | 0 | 5 (the actual overflow job got no newbie rule) |

The imaginary friend fallback was found by reading the code and was not exercised in game.

## Cause

`code/modules/mob/dead/new_player/new_player.dm:140` checked `is_assistant_job(job)` (`code/__DEFINES/is_helpers.dm:352`, `istype(job_type, /datum/job/assistant)`):

```dm
if((job.current_positions >= job.total_positions) && job.total_positions != -1)
	if(is_assistant_job(job))
		if(isnum(client.player_age) && client.player_age <= 14) //Newbies can always be assistants
			return JOB_AVAILABLE
		for(var/datum/job/other_job as anything in SSjob.joinable_occupations)
			if(other_job.current_positions < other_job.total_positions && other_job != job)
				return JOB_UNAVAILABLE_SLOTFULL
	else
		return JOB_UNAVAILABLE_SLOTFULL
```

`code/datums/brain_damage/imaginary_friend.dm:180` fell back to `SSjob.get_job(JOB_ASSISTANT)` when no job preference was set to High.

The other locations the issue names were already correct on master:

- Lobby join and role assignment use `SSjob.overflow_role` (`code/controllers/subsystem/job.dm:303, 540, 564, 930`).
- The admin verb that creates a character uses `SSjob.get_job_type(SSjob.overflow_role)` (`code/modules/admin/verbs/admingame.dm:304`).
- Preferences use the overflow role (`code/modules/client/preferences.dm:196, 413`).
- The devil event no longer exists.
- The preferences dummy in `preferences_setup.dm` no longer sets a job (it is now handled in `species.dm`, as an outfit only).

## Fix

One commit, **Fix issue 43186: use the overflow role instead of hardcoded Assistant**:

- In `IsJobUnavailable()`, `is_assistant_job(job)` became `job.type == SSjob.overflow_role`, and the comment now says "overflow role". `SSjob.overflow_role` holds the job typepath, so the comparison is on `job.type`.
- In `setup_friend_from_prefs()`, the fallback became `SSjob.get_job_type(SSjob.overflow_role)`.

## Verification

After rebuilding, the same Lua test with Clown as overflow role gave:

| Job (full) | Player age | Result |
|---|---|---|
| Assistant | 0 | 5 (slot full) |
| Assistant | 30 | 5 |
| Clown | 0 | 0 (available) |
| Clown | 30, other jobs have open slots | 5 |

This matches the intended rule: with Clown as overflow role, a newbie can always take Clown, and Assistant no longer has the special treatment.

Not checked:

- The imaginary friend change was not exercised in game. Its change is a one-line substitution.
- The default configuration (Assistant as overflow role) was not re-tested after the change. The new condition is true for Assistant there, so behaviour should be the same.
- A real join through the lobby UI with a non-default overflow role was not performed. Only `IsJobUnavailable()` was called directly.

## Notes

- A few other places still name Assistant on purpose and were left alone: the Captaincy wizard finale (demotes to Assistant), the default mulligan kit, the dynamic ruleset `blacklisted_roles`, uplink `restricted_roles`, and an ID trim. These are not overflow-role logic.
- The change touches `IsJobUnavailable()`. Other open work on the same function (for example a branch for a different issue) may conflict textually.
- The issue's own examples are mostly stale: the line numbers in it no longer match, and the devil event was removed upstream. Closing it after this fix is reasonable, since the remaining items are gone or deliberate.
