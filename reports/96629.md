# #96629: Mass-spawned mice near space turfs runtime in `Life()` (`null.return_air()`)

| | |
|---|---|
| Issues | [#96629](https://github.com/tgstation/tgstation/issues/96629): not reproduced on master; already fixed (a null-`loc` guard exists in `Life()`). The issue is still open on GitHub. |
| Status | Not reproduced. The runtime only appears if the existing guard is removed. No new fix needed. |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The reported runtime (`Cannot execute null.return_air()` in `/mob/living/proc/Life`) happens when a mouse suffocates during `handle_breathing()`, dies, and deletes itself, so that `loc` is null by the time `Life()` reads `loc.return_air()`. Master already contains a guard that returns early in that case (`code/modules/mob/living/life.dm:52`). With roughly 730 mice spread around space turfs on unmodified master there was no such runtime. After the guard was temporarily removed from a scratch copy of the tree, the exact runtime from the issue came back. The issue appears to be fixed already.

## The bug

From the issue: after creating space tiles in an aired area (build mode) and mass-spawning mice around them, the runtime log filled with null-dereference runtimes at `life.dm` line 54, `loc.return_air()`. The reporter also noted that this caused sporadic failures in the monkey business unit test (the issue links an auto-generated flaky-test issue, #96437). Players see nothing: the mice just die; the only visible effect is the runtime spam and flaky CI.

## Reproduction

Not reproduced on unmodified master. Setup used, with the Lua editor on the test server after starting the round and observing:

1. Over a 21x21 area around the Central Primary Hallway, converted every third open turf to `/turf/open/space` (`ChangeTurf`) and spawned three `/mob/living/basic/mouse` on each of the other open turfs. That was about 730 mice. (Doing this in one Lua chunk hit the execution limit, so it was done in chunks of about seven columns.)
2. Waited and watched the area depressurise.
3. Queried the mice with SDQL2 and read the round's `runtime.log`.

Run 1, unmodified master: 729 mice were found by the SDQL2 query, and only 64 were still alive. About 665 had suffocated. The runtime log contained no `life.dm` runtime. The only entries were an unrelated `null.reset_cooldowns()` runtime in an atmos process cell and an error from the admin's own Lua script.

Run 2, with the guard removed (the two lines `if(isnull(loc)) // Mice can die and become items from breathing` / `return` after `handle_breathing()` in `life.dm`), rebuilt, same spawn: 19 runtimes within about 3 seconds:

```
runtime error: Cannot execute null.return air().
proc name: Life (/mob/living/proc/Life)
source file: code/modules/mob/living/life.dm,54
src: the mouse, src.loc: null
```

This is the same runtime as in the issue. The scratch change was reverted afterwards.

## Cause

The sequence matches the explanation in the issue's comment:

1. `Life()` calls `handle_breathing()` for a living, non-stasis mob (`code/modules/mob/living/life.dm:51`), which sends `COMSIG_LIVING_HANDLE_BREATHING`.
2. The `atmos_requirements` element handles that signal in `on_non_stasis_life` (`code/datums/elements/atmos_requirements.dm:37-43`). If the mouse is not in a breathable atmosphere (for example a depressurised or space turf) it calls `target.adjust_brute_loss(unsuitable_atmos_damage * seconds_per_tick)`.
3. If that damage kills the mouse, `/mob/living/basic/mouse/death` (`code/modules/mob/living/basic/vermin/mouse.dm:133`) runs. For a mouse without a mind it spawns a dead-mouse item and ends with `qdel(src)` (`mouse.dm:171`), which moves the mouse to nullspace.
4. Back in `Life()`, the code goes on to `var/datum/gas_mixture/environment = loc.return_air()` (`life.dm:56`). `loc` is now null, so this runtimes. The `isnull(loc)` check at the top of `Life()` (`life.dm:41`) ran before breathing and so did not help; that was the check the reporter pointed to in the issue.

Mass-spawning around space makes it frequent because many mice suffocate within the same few ticks. It is also why the monkey business unit test failed sporadically.

## Fix

No change was made. Master already has the guard right after breathing:

```dm
handle_breathing(seconds_per_tick)
if(isnull(loc)) // Mice can die and become items from breathing
	return
```

(`code/modules/mob/living/life.dm:51-53`). The comment names the mouse case directly. Which PR added it could not be determined: the checkout used was shallow, and the issue (opened 2026-06-22) predates the tested commit.

## Verification

- On unmodified master, about 730 mice around space turfs produced no `life.dm` runtime while about 665 of them died of suffocation.
- With the guard removed, the identical spawn produced the issue's exact runtime 19 times in about 3 seconds. This confirms both that the test setup triggers the bug and that the existing guard is what prevents it.

Not checked:
- The monkey business unit test itself was not run.
- Other living mobs that delete themselves on death during `handle_breathing()` were not tested; the guard is generic (`isnull(loc)`) so it should cover them, but that is reasoning from the code.
- The patched BYOND build (dmfast) was not implicated, but the behaviour was not compared against stock BYOND.

## Notes

- Issue #96629 is still open on GitHub, but the fix appears to be in place on master. It looks safe to close, ideally after confirming that the monkey business test no longer flakes (#96437).
- The guard only protects `Life()`. Anything else that runs after the breathing signal on a mob that can delete itself on death would need its own check; none was found in this investigation, but it was not searched for.
