## Summary

The issue reports that `/datum/traitor_objective/locate_weakpoint` kept references to a weakpoint locator (`locator`) and an ES8 explosive (`shatter_charge`) that were never cleaned up when the objective was deleted or ungenerated, causing hard deletes. On master the traitor objective system, including this objective and both variables, no longer exists, so the bug cannot occur. No fix was written.

## The bug

As reported: the objective declared

```dm
/// Reference to the weakpoint locator(if we sent one)
var/obj/item/weakpoint_locator/locator
/// Reference to the ES8 explosive (if we sent one)
var/obj/item/grenade/c4/es8/shatter_charge
```

and never cleared either reference when the objective was deleted or ungenerated. Anything the objective had spawned would then be held by it and hard delete when destroyed.

## Reproduction

Not reproducible; this was a code-only check and no server was started. Searching the `code/` tree at master:

1. `traitor_objective`, `locate_weakpoint`, `weakpoint_locator` and `es8` were searched for. There is no `/datum/traitor_objective*` type, no `locate_weakpoint` file, no `shatter_charge` variable and no ES8 grenade type.
2. `code/modules/antagonists/traitor/` now contains only `components/`, `contractor/`, `datum_traitor.dm` and `uplink_handler.dm`. The `objectives/` directory (the progression and objective system the issue concerns) is gone.

## Cause

The variables `locator` and `shatter_charge` lived on the deleted objective datum, so there is nothing left to hold the references. The commit that removed the objective system could not be identified because the checked-out repository is shallow.

## Fix

None. No commit was made.

Nothing to verify beyond the code search above. Not checked: a running server, and any historical version of the code where the objective existed.
