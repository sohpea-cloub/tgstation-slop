# #96761: Camera Range Display verb counts per camera instead of per tile

| | |
|---|---|
| Issues | [#96761](https://github.com/tgstation/tgstation/issues/96761): verified, fixed. [#94441](https://github.com/tgstation/tgstation/issues/94441): not reproduced as a code bug |
| Status | #96761 fixed; #94441 no code change (map data) |

## Summary

The admin verb "Camera Range Display" is meant to label each tile with the number of cameras that can see it. A one-word typo (`seen[cam]++` instead of `seen[cam_turf]++`) made it count per camera, so the labels did not show per-tile coverage. The fix changes the key to the turf. #94441 (camera `c_tag` names not matching area names) is not a code bug: the tags are hand-written in the map files, and no change was made.

## The bug

### #96761
Running Camera Range Display put numbers on tiles, but the issue reporter observed that it only showed the total number of tiles seen under the camera itself, not how many cameras see each tile. The loop incremented a counter keyed by the camera, then the labelling loop read that list keyed by turf, so the numbers were wrong.

### #94441
Camera names shown in AI/borg tracking and in station alert lists come from each camera's `c_tag`, which often does not match the name of the area the camera is in, while APCs, air alarms and the crew monitor use the real area name.

## Reproduction

### #96761
1. Start a round on the test server as an admin and enable the mapping verbs ("Enable Mapping Verbs").
2. Run "Camera Range Display".
3. Read the `maptext` of the turfs under cameras, for example through the Lua editor.

After the fix, the turfs under cameras showed different counts (for example `1 1 1 2 3 1` for six cameras read in order), which is the expected per-tile result. The numbers from before the fix were not captured. The bug was identified from reading the code, and the broken behaviour was not observed in game. The verb itself was run through the admin menu (not by calling procs directly) only after the fix.

### #94441
Using the Lua editor, `SScameras.cameras` was walked on MetaStation (340 cameras) and each camera's `c_tag` compared with the name of the area it sits in. 259 of the 340 tags did not contain the area name. Examples: "Mining Dock" in "Mining Office", "Medbay Virology Wing" in "Medbay Central", "Prison Forestry" in "Prison Garden", "Arrivals - Station Entrance" in "Arrival Shuttle Hallway". (A plain substring test, so some of these are deliberate naming rather than errors.)

## Cause

### #96761
`code/modules/admin/verbs/mapping.dm:11-15`:

```dm
for(var/obj/machinery/camera/cam as anything in SScameras.cameras)
	for(var/turf/cam_turf as anything in cam.can_see())
		seen[cam]++
for(var/turf/seen_turf as anything in seen)
	seen_turf.maptext = MAPTEXT(seen[seen_turf])
```

The counter at line 13 is keyed by `cam`, although the loop variable is `cam_turf`. The list then contains camera atoms, and the labelling loop at line 14 casts each key to `/turf`. It therefore never gets a per-tile count of overlapping cameras.

### #94441
`c_tag` is a plain variable (`code/game/machinery/camera/camera.dm:65`) set by the map. Only `/obj/machinery/camera/autoname` (`code/game/machinery/camera/presets.dm:85`) builds it from the area name (`"[format_text(camera_area.name)] #[number]"`). The alert and tracking UIs (for example `code/datums/station_alert.dm`) just display `c_tag`.

## Fix

One commit, "Fix issue 96761: Camera Range Display counted tiles per camera instead of cameras per tile", changes line 13 to `seen[cam_turf]++`, so each turf's counter goes up once for every camera that can see it. Nothing else was changed.

For #94441 no change was made. Possible fixes are mass-editing the map files or converting cameras to `autoname`; either is a mapping/design decision.

## Verification

After building with the fix, the test server was started and the verb was run. The turfs under cameras showed differing numbers (`1 1 1 2 3 1`), where the count is no longer a single per-camera total.

Not checked: the pre-fix output, an exact per-tile comparison against an independent count of cameras covering each tile, and the toggle-off behaviour (running the verb a second time to clear labels).

## Notes

- The verdict "verified" for #96761 rests on the code defect and the post-fix output; the broken output was not captured.
- #94441 is a duplicate-adjacent report: a commenter links #93036 as related. It was not examined.
- The `c_tag` mismatch counts were taken on MetaStation only.
