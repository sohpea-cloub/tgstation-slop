## Summary

A menacing ore vent (`/obj/structure/ore_vent/boss`) summons a megafauna when it is scanned, and it is meant to be tapped when that boss dies. It never was: the vent waited for a signal that only the spawner component sends, and bosses have no spawner, so nothing ever told the vent the fight was over. The fix listens for the boss's death instead. It also starts the vent's wave cooldown when the boss is summoned, which the boss override had skipped; without it the vent could be scanned again, and a second boss summoned, while the first was alive. #97869 (style meter multiplier) works on master for normal vents; boss vents only appeared to be affected because they were never tapped.

## The bug

Players who killed the boss of a menacing vent (Bubblegum and the Ash Drake in #97901, the demonic frost miner twice in #97656) found the vent still untapped afterwards, with the option to summon another boss. The vent gave no ore and no tap reward. #97901 suggests this may depend on how far the player ended up from the vent when the boss died. It does not: the boss's death never reaches the vent at any distance.

## Reproduction

All steps were done with admin tools on a test server running master.

1. As an observer, open the Lua editor.
2. Spawn a boss vent: `SS13.new('/obj/structure/ore_vent/boss', loc)`. Set `discovered = true` and call `start_wave_defense()` on it. A megafauna appeared (Bubblegum in this run), as it does when a player scans the vent.
3. Kill the boss by setting its health to 0 and calling `death()` on it. The game printed the megafauna's usual death message.
4. Read the vent's state.

Observed on master: `tapped` was 0 and `node` was nil. No node drone appeared and the vent stayed untapped.

This reproduces the problem by calling the vent's own procs directly (`start_wave_defense()`), not by scanning the vent with a mining scanner as a player would. The boss was killed next to the vent, not far from it.

A second observation, on master, from reading the code and the cooldown behaviour: `start_wave_defense()` on a boss vent never started `wave_cooldown`, so `scan_and_confirm()` (which refuses only when the cooldown is running or a node exists) would accept another scan while the first boss was alive.

## Cause

`/obj/structure/ore_vent/boss/start_wave_defense()` (`code/game/objects/structures/lavaland/vent_mining/boss_vent.dm:54-60`) replaces the normal wave defense with a single boss spawn:

```dm
var/mob/living/simple_animal/hostile/megafauna/boss = new summoned_boss(loc)
RegisterSignal(boss, COMSIG_VENT_WAVE_CONCLUDED, PROC_REF(handle_wave_conclusion))
```

`COMSIG_VENT_WAVE_CONCLUDED` is only ever sent by `/datum/component/spawner` (`code/datums/components/spawner.dm:107`, in `stop_spawning()`), and the boss has no such component. The signal is never sent from the boss, so `handle_wave_conclusion()` never ran for a boss vent. That handler (`boss_vent.dm:63-67`) is the one that creates the node drone and, through the parent proc (`ore_vent.dm:317-332`), calls `initiate_wave_win()`, which calls `become_tapped()`.

The normal vent's `start_wave_defense()` starts the cooldown (`ore_vent.dm:305`, `COOLDOWN_START(src, wave_cooldown, INFINITY)`) and registers the same signal on itself (`ore_vent.dm:306`), where the spawner component does send it. The boss override copied the registration but moved it to the boss, and left out the cooldown. `handle_wave_conclusion()` on the boss vent already does `COOLDOWN_RESET`, so it was written to run after a cooldown that was never started.

## Fix

One commit, "Fix issue 97901: tap menacing ore vents when their boss dies", in `boss_vent.dm`:

- The boss registration now uses `COMSIG_LIVING_DEATH` instead of `COMSIG_VENT_WAVE_CONCLUDED`. `handle_wave_conclusion()` is a signal handler that ignores its arguments, so it can be registered on the death signal unchanged.
- `start_wave_defense()` now calls `COOLDOWN_START(src, wave_cooldown, INFINITY)`, as the normal vent does, so the vent cannot be scanned again during the fight. The existing `COOLDOWN_RESET` in `handle_wave_conclusion()` clears it when the boss dies.

Listening for the boss's death on the boss itself was chosen over making the vent poll the boss or over giving bosses a spawner component, because it is the smallest change and the signal already exists.

## Verification

After the fix, the server was rebuilt and the same Lua steps were run on a new boss vent (colossus this time). When the boss died:

- the vent showed "vent tapped!";
- a node drone appeared and flew away ("The drone flies away to safety as the vent is secured");
- the vent icon changed to the active state and `tapped` was 1.

Calling `start_wave_defense()` twice on a fresh boss vent produced one boss, with `wave_cooldown` set to the infinite value.

Not checked:

- The Icebox vent and its bosses, including the demonic frost miner from #97656. It uses the same code (`/obj/structure/ore_vent/boss/icebox` only changes the boss list), but it was not run.
- A real scan by a player with a mining scanner, and a boss killed far from the vent.
- Rewards when the player is near the vent at the time of the tap (mining points and skill experience in `initiate_wave_win()`), beyond the vent becoming tapped.
- A boss that is deleted without dying, see Notes.

## Notes

- Open edge case: if the boss is deleted without dying (for example by an admin), `COMSIG_LIVING_DEATH` never fires, so the vent stays on an infinite cooldown and can never be scanned or tapped. Before the fix there was no cooldown, so the vent could be scanned again. Normal play ends the fight by death, but a `COMSIG_QDELETING` handler could be added if a maintainer wants to cover this. Also, if the boss somehow leaves the vent without dying, nothing resets the vent.
- #97869 (style meter): on master, tapping a vent does raise the style meter's permanent multiplier. A test with a human wearing a style meter and meson glasses: tapping a small vent through `initiate_wave_win()` raised `stored_permanent_multiplier` from 0 to 0.05; then a medium and another size-10 vent through `handle_wave_conclusion()` with a live node brought the total to 0.25 (0.05, 0.1, 0.1). The signal (`COMSIG_LIVING_ON_VENT_WIN`) is sent from `initiate_wave_win()` (`ore_vent.dm:347-368`) to living mobs within 7 tiles of the vent only, so a miner who is farther away gets nothing, by design. The reporter's scenario of tapping and defending a vent did not reproduce; the boss-vent case was broken only because boss vents were never tapped. Lua reads right after a win sometimes still showed the old multiplier and showed the increment a few seconds later. The issue's claim about vents tapped far from the wearer was not tested beyond that rule from the code.
- #97656 also says the vent offered to summon another boss after the fight. That matches the missing cooldown, now fixed, though that game round was not replayed.
