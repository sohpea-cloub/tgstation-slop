# #98282: Grinder dupes reagents

| | |
|---|---|
| Issues | [#98282](https://github.com/tgstation/tgstation/issues/98282): verified, fixed |
| Status | Reproduced, fixed and checked on the test server |
| Fix branch | [fix/98282](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/98282) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Grinding a stack of N material sheets yields N² times the per-sheet reagents instead of N times, because the stack's grind results are already computed for the whole stack and `grind_atom()` then multiplies them by the number of sheets again. Separately, grinding wings yields 10 units of flight potion instead of 5, because the wings' flight potion is both an edible reagent (transferred on grinding) and a `grind_results()` entry (added on top). The fix makes the stack's grind results per-unit, bases the "how many sheets fit" calculation on the per-unit volume, and removes the redundant wings `grind_results()` override.

## The bug

- A stack of 1 iron or gold sheet gives 20 units of reagent when ground. 2 sheets give 80 instead of 40, and 3 sheets give 180 instead of 60 (20·n·n instead of 20·n).
- Grinding an angel wings organ gives 10 units of flight potion. The wings code says 5, and the organ's own edible reagents are also 5.

The issue reporter also says the wings can be used to get unlimited flight potion from one organ. That was not tested; the doubling itself was confirmed.

## Reproduction

All steps are on master. The grind was triggered by calling the item's `grind()` proc from the Lua editor with the arguments the reagent grinder passes (`grind(beaker.reagents, user)`). The player action (loading the sheets into a grinder and running it) was not performed.

1. Start a round and open the Lua editor as an admin (observer is fine).
2. Create a bluespace beaker and a stack of iron sheets of size n (1, 2, 3) with no location (`SS13.new('/obj/item/stack/sheet/iron', nil, n)`). Spawning on a turf where the new stacks can merge with each other gives misleading results.
3. Call `stack:grind(beaker.reagents, nil, nil)` and read `beaker.reagents.total_volume`. Repeat with `/obj/item/stack/sheet/mineral/gold`.
4. Create a bluespace beaker and an `/obj/item/organ/wings/angel`, call `wings:grind(beaker.reagents, nil, nil)` and read the volume.

Observed on master:

| Item | Total volume ground |
|---|---|
| iron ×1 / ×2 / ×3 | 20 / 80 / 180 |
| gold ×1 / ×2 / ×3 | 20 / 80 / 180 |
| angel wings | 10 |

## Cause

`/obj/item/proc/grind_results()` (`code/game/objects/items.dm:1014`) derives reagents from `custom_materials`. For a stack, `custom_materials` is the material content of the whole stack, so for N sheets the result is already N times the per-sheet amount.

`/obj/item/stack/grind_atom()` (`code/game/objects/items/stacks/stack.dm:178`) was written assuming `grind_results()` is per unit (as the overrides for medical stacks, glass, light tubes and similar are). It scales the results by the number of sheets ground:

```dm
var/available_amount = ceil(current_amount * min(1, available_volume / total_volume))
...
for(var/reagent in grind_reagents)
	grind_reagents[reagent] *= available_amount
```

For the material-derived results this multiplies by N a second time, giving N². The same code also computed `total_volume` from these results and used it to work out how many sheets fit in the container; with a whole-stack total, that ratio is not a per-sheet figure either.

For the wings, `/obj/item/organ/wings/Initialize()` sets `food_reagents = list(/datum/reagent/flightpotion = 5)` for flight-capable wings (`code/modules/surgery/organs/external/wings/wings.dm:48`), so the organ holds 5 units of flight potion in its own reagents. The base `grind_atom()` (`items.dm:1061`) adds `grind_results()` to the target and also transfers the item's own reagents (`reagents.trans_to(...)`). `/obj/item/organ/wings/grind_results()` (`wings.dm:88`) returned `flightpotion = 5` too, so both applied: 5 + 5 = 10.

## Fix

One commit, "Fix issue 98282: grinder doubled stack and wing reagents":

- `stack.dm`: a new `/obj/item/stack/grind_results()` override calls the parent and divides each reagent amount by the stack's `amount` (if there is more than one unit), so stack results are per unit like the existing subtype overrides. `grind_atom()`'s scaling by sheets ground is then correct for both kinds.
- `stack.dm`: `grind_atom()` now computes `unit_volume` (volume of one sheet's results) and `available_amount = min(current_amount, ceil(available_volume / unit_volume))`, or `current_amount` when `unit_volume` is 0. The old expression divided by a total that could be 0 and was only meaningful for per-unit results.
- `wings.dm`: removed the `grind_results()` override. Flight-capable wings still yield flight potion through their edible reagents. Flightless wings have no flight potion in `food_reagents`, so they still yield nothing, which matches the intent of the removed override's comment ("you only get the juice if your wings are worth a damn").

An alternative for the stacks would have been to stop `grind_atom()` multiplying, but that would break the per-unit overrides of other stack types. Dividing in the base stack override keeps them unchanged.

## Verification

After rebuilding, using the same Lua calls as in the reproduction:

- iron ×1 / ×2 / ×3 and gold ×1 / ×2 / ×3 gave 20 / 40 / 60.
- Angel wings gave 5.
- A stack of 3 bruise packs (which has its own per-unit `grind_results()`) still gave 30, unchanged by the fix.
- 10 iron sheets ground into a 100-unit-capacity beaker: the beaker filled to exactly 100 and 5 sheets were left. With the first version of the fix, which did not yet include the `unit_volume` change, the stack ground all 10 sheets regardless of the space; that was the reason for the second part of the stack change.

Not checked: grinding through an actual reagent grinder machine (the all-in-one grinder UI and its `blended()` handling of partly ground stacks), flightless wings, or other stack types with material-derived results beyond iron and gold. No full test suite was run.

## Notes

- Only iron and gold were measured; other stacks whose results come from `custom_materials` go through the same code path.
- Other `grind_results()` overrides that coexist with `food_reagents` of the same reagent could have the same double-counting as the wings did. That was not searched for.
