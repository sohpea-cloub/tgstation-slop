# #82335: Atmos devices can render under pipes on the same tile

| | |
|---|---|
| Issues | [#82335](https://github.com/tgstation/tgstation/issues/82335): verified (layer overlap confirmed by layer values; fix is a disputed design call) |
| Status | Fixed on the fix branch; needs a maintainer decision on the intended draw order |
| Fix branch | [fix/82335](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/82335) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Atmos devices (vents, scrubbers, filters, mixers, connectors, pumps) and pipes are drawn on the same layer scale, and the two ranges overlap. Depending on piping layer and pipe color, a visible pipe can draw over a device on the same tile. The fix moves the three device base layers above the whole pipe range and gives devices a much smaller piping-layer and color offset, so any device always draws above any ordinary pipe. Whether devices should always be above pipes is disputed in the issue thread, so that is a design choice for maintainers.

## The bug

The reporter says connectors, mixers, filters and similar devices should show above every pipe on their tile, at least when wrenched down, but are sometimes hidden by pipes. A commenter replied that pipes appear under devices, and that only bridge pipes draw above devices, which they said is intended. The reporter and a later commenter said the problem still occurs, especially for structures spawned in during the round.

The inputs show that both statements are partly right. Bridge pipes are above devices on purpose. But apart from bridge pipes, the draw orders of ordinary pipes and devices do overlap.

## Reproduction

This was checked by reading layer values with admin tools. It was not checked by looking at a render on master. The values were read from objects spawned on a single tile.

1. Start a round and open the Lua editor.
2. Spawn a visible pipe (`/obj/machinery/atmospherics/pipe/smart/manifold4w/general/visible`) and the devices below on one tile: a portables connector, a gas filter, a gas mixer, a vent scrubber, a vent pump, a binary pump and a valve.
3. Read `.layer` and `.plane` on each object.

Observed on master:

| Object | layer |
|---|---|
| visible pipe, piping layer 3 | 2.47 |
| vent scrubber, vent pump | 2.46 |
| filter, mixer, connector | 2.48 |
| pump, valve | 2.49 |

All objects were on plane -4 (`GAME_PLANE`). Pipes also shift by (piping_layer − 3) × 0.005 plus pipe color × 0.0001, so visible pipes on piping layers 4 and 5 sit at 2.475 and 2.48. That ties with or beats a layer-3 filter, mixer or connector (2.48), and a visible pipe at 2.47 is above any vent or scrubber at 2.46. Devices also shifted by (piping_layer − 3) × 0.005 plus color × 0.001, up to roughly ±0.016, so off-layer or colored devices could drop below pipes as well.

The hidden pipe spawned in the same test was at 2.35, as expected for a pipe covered by a floor.

## Cause

`code/__DEFINES/layers.dm:216-219` defines the device base layers and the visible pipe layer:

```
#define GAS_SCRUBBER_LAYER 2.46
#define GAS_PIPE_VISIBLE_LAYER 2.47
#define GAS_FILTER_LAYER 2.48
#define GAS_PUMP_LAYER 2.49
```

The scrubber layer is below the visible pipe layer, and the filter layer equals the top of the pipe range.

Pipes add their offset in `code/modules/atmospherics/machinery/pipes/pipes.dm:150-151` (`(piping_layer - PIPING_LAYER_DEFAULT) * PIPING_LAYER_LCHANGE` plus the color term). `/obj/machinery/atmospherics/components/update_layer()` in `code/modules/atmospherics/machinery/components/components_base.dm:381-391` adds `get_pipe_layer_offset()` to the device layer. That offset uses the same `PIPING_LAYER_LCHANGE` step (0.005, defined in `code/__DEFINES/atmospherics/atmos_piping.dm`), so a device's draw position moves across the same range pipes move across.

Bridge pipes use `HIGH_PIPE_LAYER` (2.54, `code/modules/atmospherics/machinery/pipes/bridge_pipe.dm:8`) and stay above devices. That matches the commenter's explanation, but it does not explain the rest of the overlap.

## Fix

One commit, "Fix issue 82335: atmos devices render above pipes on the same tile":

- `GAS_SCRUBBER_LAYER`, `GAS_FILTER_LAYER` and `GAS_PUMP_LAYER` were changed to 2.484, 2.488 and 2.492. All are above the pipe range (top 2.47 + 0.0105 = 2.4805) and below `PLUMBING_PIPE_VISIBILE_LAYER` (2.495).
- A new proc `get_device_layer_offset()` returns `(piping_layer - 3) * 0.001 + color * 0.0001`. `update_layer()` for components now uses it. The offset is at most 0.0026 either way, so devices stay ordered among themselves by piping layer and color but never reach the pipe range. `get_pipe_layer_offset()` is kept, since the underlays still use it.
- Bridge pipes and layer manifolds were not touched, so bridge pipes still draw above devices.

The alternative of moving the pipes down was not tried. It would touch more code, and the pipe offsets are also used by other things.

## Verification

After the fix and a rebuild, the test server was started and a sweep was run in the Lua editor: six device types (portables connector, filter, mixer, vent scrubber, vent pump, pump) × piping layers 1–5 × three pipe colors, calling `set_piping_layer`, `set_pipe_color` and `update_layer`. The lowest device layer was 2.482 (a vent scrubber on piping layer 1) and the highest pipe layer was 2.48 (piping layer 5). The lowest device is therefore above the highest pipe. The runtime log of the new round had no runtimes.

Not checked: no render or screenshot after the fix; hidden pipes, bridge pipes and plumbing ducts were not re-measured; thermomachines, the crystallizer and the HFR parts override `update_layer()` and were not touched or tested.

## Notes

- The issue is disputed. Whether devices should always draw above all ordinary pipes is a behavior choice. The fix makes it so; maintainers may prefer a narrower change.
- A hidden pipe spawned at runtime on a covered tile stayed at 2.35 on `GAME_PLANE`. This was seen but not investigated.
- A first Lua query failed because `underfloor_state` exists only on components, not pipes. This did not affect the results.
