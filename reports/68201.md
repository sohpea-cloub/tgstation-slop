# #68201: Xenos in a body in a locker spawn outside of locker

| | |
|---|---|

| Status | Fixed on the fix branch; checked in game for a closet host |

## Summary

When an alien embryo bursts from a host who is inside a closet, the larva appeared on the floor outside while the host's gibbed remains stayed inside the closet. The burst spawned the larva at the host's turf instead of the host's container. The fix spawns it at `owner.drop_location()`, falling back to the turf, so the larva appears in the same place as the remains.

## The bug

The reporter put an infected body (living or dead) in a locker. When the xeno burst, the larva appeared outside the locker, while the gibs and items of the host stayed in the locker. A comment asks about mechs and similar containers; another notes that mechs drop the victim out before the gibbing, and that morgue trays might be affected.

## Reproduction

On master, with admin tools (the burst was triggered by calling the proc directly, not by waiting out the embryo's growth and a ghost poll):

1. Start a round and observe, then open the Lua editor.
2. Spawn a closet and a human on the same turf. Spawn an `/obj/item/organ/body_egg/alien_embryo` and insert it into the human. Move the human into the closet (`forceMove`).
3. Using SDQL2, call the burst with a ghost as the poll winner: `CALL on_poll_concluded(1, [<ghost mob>]) ON /obj/item/organ/body_egg/alien_embryo`. The proc sleeps, so it was run from SDQL2 and not from the Lua editor.
4. Run `SELECT /mob/living/carbon/alien/larva MAP [loc, loc.type]`.

Observed on master: the larva's `loc` was the floor turf (`/turf/open/floor/iron`) at the closet's coordinates, not the closet.

## Cause

In `on_poll_concluded` in `code/modules/mob/living/carbon/alien/special/alien_embryo.dm`, the larva was created at the host's turf:

```dm
var/atom/xeno_loc = get_turf(owner)
var/mob/living/carbon/alien/larva/new_xeno = new(xeno_loc)
```

(`alien_embryo.dm:120`). The host is then gibbed with `owner.gib(DROP_ORGANS|DROP_BODYPARTS)`, and the remains are dropped where the host is, which is inside the container. So the larva and the remains end up in different places when the host is in a closet.

## Fix

One commit, "Fix issue 68201: alien larva bursts into the host's container, not onto the floor". It changes the line to:

```dm
var/atom/xeno_loc = owner.drop_location() || get_turf(owner)
```

with a short comment. `atom/proc/drop_location()` (`code/game/atom/_atom.dm:612`) returns the host's `loc` if that container's `AllowDrop()` is true, and otherwise walks up to the next container. Closets and body bags accept drops, so the larva bursts inside them. Containers that don't (mechs, morgue trays and disposals, going by code reading) fall through to the turf as before, matching the previous behavior for those cases. `|| get_turf(owner)` covers a null result.

An alternative suggested in the issue, forcing the container open when the larva is born, was not implemented.

## Verification

After rebuilding and repeating the same steps on the fixed code, the larva's `loc` was "the closet" (`/obj/structure/closet`).

Not checked in game: hosts in a mech, morgue tray, body bag, or disposal unit (code reading only); the normal path through the embryo's growth stages and the ghost poll (the proc was called directly); a welded or locked closet (a larva inside can presumably get out like any other occupant, but this was not tested).

## Notes

- Behavior change to weigh: the larva now starts inside the closet instead of on the floor. A player larva in a closed closet can get out through the usual movement-out-of-container mechanic; a welded closet may trap it. The trade-off versus the old behavior (larva outside, remains inside) was not evaluated further.
- The non-gib path (`gib_on_success` false, "wriggles out of") uses the same `xeno_loc`, so it also changes.
