# #97403: Cyborgs created off the station's z level never link to a law rack and stay lawless

| | |
|---|---|
| Issues | [#97403](https://github.com/tgstation/tgstation/issues/97403) verified (latejoin cyborg), fixed; [#93369](https://github.com/tgstation/tgstation/issues/93369) not reproduced |
| Status | Fix committed on the branch below and checked in game for the latejoin case; merged law racks and cyborgs built off-station were not tried |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97403 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A cyborg tries to link itself to a law rack exactly once, in `/mob/living/silicon/robot/Initialize()`. The rack refuses to link a silicon on a different z level, so a cyborg that is created somewhere else, such as a latejoin cyborg that spawns on the arrivals shuttle while it is in transit, gets no laws and nothing ever tries again. The fix registers a retry on `COMSIG_MOVABLE_Z_CHANGED` when the first attempt fails, so the cyborg links as soon as it arrives on a z level with a rack. In the test the latejoin cyborg was lawless on the transit z and received its three laws when the shuttle docked.

## The bug

#97403 reports that when law racks are merged and the cyborg overflow role rolls, new cyborgs spawn with no laws and are not synced to any law rack, which the reporter calls being "purged". The steps given are: merge the racks, set cyborg overflow, latejoin as a cyborg "so you spawn on shuttle". A comment wonders whether the same would happen to a cyborg constructed on a z level that has no law rack.

#93369 is an older report of AI-less cyborgs spawning lawless on Tramstation while the law rack test merge was active.

## Reproduction

Done as an admin on the test server, with the default test map, which has one core law rack (named "alpha") on the station z level.

### #97403: latejoin cyborg

1. Start the round. In the Lua editor, raise the Cyborg job's `total_positions` and `spawn_positions` to 4 (the job had no open slots).
2. Use the latejoin menu to join as a Cyborg. The cyborg appears buckled on the arrivals shuttle, which is in transit.
3. Immediately read the cyborg's state from Lua.
4. Observed on this build: z level 12 (the transit z level, not the station), 0 inherent laws, 0 supplied laws, `get_law_rack()` returned nil, `lawupdate` 0 and `no_law_rack_link` 0. The cyborg was lawless and unlinked. (The chat shows the usual "Obey these laws" / "Remember, you are not bound to any AI" greeting regardless; the law list under it was empty.)

Note that this state was seen when the cyborg had just spawned, and the fix does not change it, since the retry only acts after a z change. That the cyborg would stay unlinked indefinitely on unmodified master follows from the code (below); it was not watched for a long time on an unmodified build.

The report's other ingredients, merged law racks and the overflow role itself, were not used: the job slots were opened by hand in Lua and only a single rack existed.

### #93369: roundstart cyborg on Tramstation

1. Change the map to Tramstation, restart, set Cyborg as the High job preference, ready up and start the round.
2. A roundstart AI-less cyborg spawned and, within about 20 seconds, had its three laws ("Remember, you are not bound to any AI" among the greeting).

This did not reproduce. The test was done on the build with the fix applied, so it shows that a roundstart cyborg on Tramstation gets laws with the fix in place. Since the roundstart link succeeds on the first attempt (so the new retry is not registered), it also indicates the roundstart path was working, but I did not run it separately on unmodified master. No check was made with merged racks.

## Cause

`code/modules/mob/living/silicon/robot/robot.dm:45-58`: when a new cyborg cannot connect to an AI and there is no human AI, it falls back to a law rack:

```dm
		else
			lawupdate = FALSE
			link_to_first_rack()
```

`link_to_first_rack()` (`code/modules/mob/living/silicon/laws.dm:50`) loops over the core law racks and calls `link_silicon()` on the first one for which `can_link_to()` is true. `can_link_to()` (`code/game/machinery/ai_core/law.dm:864`) begins with:

```dm
if(!is_valid_z_level(get_turf(src), get_turf(new_bot)))
	return FALSE // Can't link to bots on different z-levels
```

and `is_valid_z_level()` (`code/__HELPERS/levels.dm:13`) is true only when both turfs are on station levels or share a z level. A cyborg created in shuttle transit is on neither, so the check fails, the cyborg gets no laws, and the call in `Initialize()` is never repeated. Nothing else links it later: the rack's own z-level handling (`on_changed_z_level()` at `law.dm:~881`) only unlinks silicons that are already linked, and the comment there says so.

This also fits the commenter's guess about cyborgs built on a z level with no rack, which goes through the same `Initialize()` path (not tested).

## Fix

One commit on `fix/97403`: **"Fix issue 97403: cyborgs created on a z-level without a law rack (e.g. latejoin on the arrivals shuttle in transit) now link to a rack once they reach one"**.

- `robot.dm`: if `link_to_first_rack()` returns nothing in `Initialize()`, the cyborg registers `COMSIG_MOVABLE_Z_CHANGED` with a new handler, `retry_rack_link()`. The handler unregisters itself if the cyborg already has a connected AI, has `no_law_rack_link` set or already has a law rack. Otherwise it calls `link_to_first_rack(announce = TRUE)` and unregisters on success.
- `silicon/laws.dm`: `link_to_first_rack()` gained an `announce` argument (default `FALSE`, so existing callers are unchanged), passed on to `link_silicon()`. The retry passes `TRUE` so the cyborg sees its new laws.

Using the z-change signal avoids polling and fires exactly when the condition that blocked the link (being on another z level) can change. The handler stops as soon as the cyborg is linked to something, including a rack linked some other way.

## Verification

On a rebuilt test server with the fix, the latejoin steps above were repeated. The cyborg started on the transit z level, lawless. About 40 seconds later the arrivals shuttle docked and the cyborg moved to the station. The chat showed "Your laws have been changed", and Lua showed z level 2, 3 inherent laws (Asimov), the rack "core module rack 'alpha'" from `get_law_rack()`, and `no_law_rack_link` 1 (which `link_silicon()` sets on a successful link). The runtime log contained only noise from the Lua editor and a malformed test script, and nothing from the new code.

Not checked:

- Merged law racks and the overflow role, which the report mentions (the mechanism does not look specific to either, but that is from code only).
- A cyborg constructed (rather than latejoined) on a z level without a rack.
- A rack on a different z level from the cyborg's final destination, a cyborg that changes z several times before finding a rack, or multiple core racks.
- The behavior on unmodified master over a long period (see Reproduction).
- Roundstart cyborgs on other maps.

## Notes

- The report titles #93369 as "same cause" and it was grouped with #97403, but a roundstart AI-less cyborg on Tramstation received laws in the test, so the evidence supports only the latejoin/off-station cause. #93369 was filed against a test merge of the law rack system a year earlier, and it may have been a bug in that version.
- The rack-side code deliberately does not unlink silicons that leave the rack's z level ("to prevent random unlinking from visiting lavaland"). The new retry applies only to cyborgs that never got linked, so it does not change that policy.
- `link_to_first_rack()` is also used for other silicons; the new `announce` parameter defaults to the old behavior.
