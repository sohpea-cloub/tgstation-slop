## Summary

Right-clicking an accessory to switch it between "wearing above suits" and "wearing below suits" only flips a variable. If the accessory is already attached to a uniform that someone is wearing, nothing redraws the wearer, so the old suit-layer overlay stays on screen until some unrelated update happens. The fix adds a small proc that redraws the wearer's uniform, suit and neck slots right after the toggle. The exact flow in the report (toggle in hand, then attach) already worked on master, so the report may describe something slightly different; see Notes.

## The bug

The report says: take a pride pin or mime pin, set it in hand to be worn below the suit, put it on, and it still shows its sprite. A comment adds that once an accessory has been applied once, its icon state seems stuck to the jumpsuit.

What was found: the toggle changes `above_suit`, but the worn sprite is not refreshed. An accessory drawn over a suit stays drawn over it after being switched to "below", until something else forces a redraw.

## Reproduction

On master, using admin tools:

1. Spawn a human with a grey jumpsuit and an armor vest.
2. Attach a gold medal to the jumpsuit (it defaults to above the suit). The medal rendered over the vest.
3. With the Lua editor, call `attack_self_secondary` on the medal. This is the same proc the in-hand right-click runs. In game, right-clicking the item in hand does work and shows the "wearing below suits" balloon alert.
4. Observed: `above_suit` became 0, but rendering the human still showed the medal on top of the vest. The suit-layer overlay was stale.

This was reproduced by calling the proc on an accessory inside a worn uniform, not by a real player action. A worn accessory is inside the uniform, so a player cannot normally reach it to right-click.

The report's own flow was also tried and behaved correctly on master:

- A pride pin was toggled to "below" in hand with a real right-click, then attached to a worn uniform under a vest: it was not drawn.
- "Below" set before the suit was equipped: hidden.
- Suit equipped before the uniform: hidden.
- Detaching the accessory with the suit on: the overlay was removed.

So below/above works whenever a redraw happens.

## Cause

`attack_self_secondary` in `code/modules/clothing/under/accessories/_accessories.dm:203` flips `above_suit` and returns without redrawing anyone:

```dm
above_suit = !above_suit
balloon_alert(user, "wearing [above_suit ? "above" : "below"] suits")
return TRUE
```

The suit draws above-suit accessories itself, in the loop at `code/modules/clothing/suits/_suits.dm:39` (`if (accessory.above_suit)`), as part of the suit's worn overlays. Those overlays are only rebuilt on a suit update, which the toggle never triggers.

## Fix

One commit, "Fix issue 78452: toggling an accessory's above/below suit setting on a worn uniform now redraws it". It adds `/obj/item/clothing/accessory/proc/update_worn_layer()`, called after the toggle. The proc:

- returns unless the accessory's `loc` is an `/obj/item/clothing/under`;
- returns unless that uniform's `loc` is a human who has it in the uniform slot;
- otherwise calls `update_clothing(ITEM_SLOT_ICLOTHING | ITEM_SLOT_OCLOTHING | ITEM_SLOT_NECK)` on the wearer, covering the uniform, the suit (which draws above-suit accessories) and the neck slot (ties).

No other approach is recorded.

## Verification

After rebuilding, on the same setup (grey jumpsuit, armor vest, gold medal above the suit), the proc was called again. `above_suit` flipped and the medal disappeared from the rendered human at once.

Not checked: toggling back to "above" after the fix, ties in the neck slot, non-human wearers, and any automated tests.

## Notes

- The reproduction needs an admin-style call. The in-hand toggle already worked before the fix, so this fix covers the remaining case (toggling while worn) but may not be what the reporter saw.
- Possible real cause of the report: with no suit worn, a below-suit accessory is still drawn. `/obj/item/clothing/under/worn_overlays` (`code/modules/clothing/under/_under.dm:116`) adds `get_accessory_overlays()` for every accessory regardless of `above_suit`, so a below-suit accessory shows on the bare uniform, and an above-suit one is drawn twice (uniform layer and suit layer). This is probably intended, since a below-suit accessory should be visible without a suit, but it matches "still shows the sprite". It was not changed.
- Ties (`code/modules/clothing/neck/_neck.dm:157`) add all accessory overlays and ignore `above_suit`. Also not changed.
