# #93869: Plasma-rigged power cells in light fixtures never explode

| | |
|---|---|
| Issues | [#93869](https://github.com/tgstation/tgstation/issues/93869): verified for rigged cells (fixed); the plasma-tube claim was not reproduced |
| Status | Fixed on the branch below, with a design question for maintainers (see Notes) |
| Fix branch | [fix/93869](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/93869) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A power cell holding plasma is meant to explode when power is drawn from it. In a light fixture, any cell larger than the emergency light cell makes the fixture short-circuit and burn out before any power is drawn, so the rigged cell never goes off. The fix draws the power before burning the light out, so the explosion check runs. The report that plasma-injected light tubes do not explode was not reproduced; that path works.

## The bug

The reporter says rigged cells do not explode in lights, even with the smallest cell, and that plasma injected into a light tube does nothing. A commenter suggested the behaviour broke when power cells were added to lights.

With a plasma-rigged cell in a fixture, the player sees "The light fixture short-circuits from too powerful of a power cell!" and the light burns out. Nothing explodes.

## Reproduction

All steps used the Lua editor on the test server, with an observer.

Rigged cell (reproduces the bug):
1. Create a light fixture holding a `/obj/item/stock_parts/power_store/cell/crap` (5000 max charge) with 5 units of plasma in its reagents, and assign it as the fixture's cell. The area's light power was set off and the fixture's `on` was set to false, so the next `update()` put the light into emergency mode.
2. Call `update()` on the fixture.
3. Result on master: the chat message above, the light burned out, and no explosion.

Plasma tube (does not reproduce the bug):
1. Add plasma to a `/obj/item/light/tube` and have a human insert it into an empty `/obj/machinery/light` via `item_interaction`.
2. Result: "The solution violently explodes!", with an admin log entry "A rigged lightbulb ... has exploded."
3. Injecting a tube with a syringe also worked (the tube has the `INJECTABLE` flag and 5 units went in). An already installed fixture has no reagent holder, so a syringe on the fixture itself does nothing. That is by design, since the reagents come from the tube at insertion.

The tiny emergency cell (max charge 1200) does explode when rigged, through `process()` charging the cell, which reaches `give`, `change` and `try_explode`. Any normal cell is above the limit below (the smallest, 5000, exceeds 2.5 x 1200 = 3000), so none of them can.

## Cause

`use_emergency_power` in `code/modules/power/lighting/light.dm:526-538`:

```dm
if(real_cell.charge > 2.5 * /obj/item/stock_parts/power_store/cell/emergency_light::maxcharge) //it's meant to handle 120 W, ya doofus
	visible_message(span_warning("[src] short-circuits from too powerful of a power cell!"))
	burn_out()
	return FALSE
real_cell.use(power_usage_amount)
```

When the cell's charge is over the limit the proc burns the light out and returns before `real_cell.use()`. The rigged-cell explosion is triggered from `try_explode`, reached through the power store's `change()`, which only runs on use, so it never runs. The caller is at `light.dm:339`.

## Fix

One commit, "Fix issue 93869: rigged power cells in lights explode when the light overloads", adds `real_cell.use(power_usage_amount)` before `burn_out()` in the overload branch. The comment in the diff says that current still flows through the cell. The rest of the branch is unchanged: the light still burns out and the message still shows.

## Verification

Same script as the reproduction, after a rebuild: the short-circuit message appeared, then "The solution violently explodes!", with an admin log "has triggered a rigged power cell explosion at ...".

Not checked: a full power outage on the station, a player using a light switch, or cells other than the one used. Nothing was run for the unrigged case after the fix beyond the unchanged branch.

## Notes

- The explosion only happens in emergency mode (a power outage, with the fixture drawing from its cell). Switching a light on with normal station power does not draw from the cell, so it still does nothing. The issue text suggests a stronger expectation; this was not changed.
- The overload branch may be an intentional nerf to stop large cells in lights. The fix keeps the burn-out and only draws the power first, but maintainers should confirm that exploding there is wanted.
- The claim that plasma-injected light tubes never explode was not reproduced (see above).
