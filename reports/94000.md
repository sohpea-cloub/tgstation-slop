## Summary

The latejoin menu builds its sections from `SSjob.joinable_departments`, which is filled from each job's `departments_list` only. Assistant and Prisoner have no `departments_list` but do set `department_for_prefs`, so the menu put them under "No Department" while the preferences menu shows them under "Assistant" and "Security". The fix groups jobs in the menu with the same rule the preferences menu uses. A second commit stops the menu from writing a job-debug log line for every ineligible job on every UI update (#81754). #46956 (a 2019 runtime when head jobs are removed) no longer exists: the code it cites is gone.

## The bug

### #94000
Opening the latejoin menu showed Prisoner and Assistant in a "No Department" section. The preferences menu uses `department_for_prefs` to override the department list, so there the same jobs appear as Security (Prisoner) and Assistant.

### #81754
Every time the menu's data was built, `IsJobUnavailable` ran for each job. Each failed eligibility check (age, playtime, ban, account age) wrote a line to the job-debug log, so having the menu open while ineligible for some jobs filled that log with repeated lines.

### #46956
Reported in 2019: if a map removes the head jobs, the late join menu pulled Captain out of `name_occupations`, got null and runtimed, which blocked late joining.

## Reproduction

### #94000
Not reproduced on an unmodified build. The fix was built before the first reproduction attempt, so the old behaviour was derived from the code, not observed. To check on master:

1. Start a round and join as a latejoiner (or open the latejoin menu from the lobby once the round is running).
2. Inspect the menu's UI data (the JobSelection tgui window). Prisoner and Assistant should appear in a "No Department" section, going by the code below.

### #81754
Pre-fix spam is established by reading the code (one line per ineligible job per UI-data update). The fix's no-log behaviour was tested as follows (job-debug logging was enabled in the server config, which needs a restart because log categories are read at boot):

1. Set Station Engineer's `required_character_age` to 99 so it is ineligible for the test character.
2. Open the latejoin menu and leave it open for about 25 seconds.
3. Search the round's debug log for "Mob IsJobUnavailable".

### #46956
1. Using the Lua editor, set `SSmapping.current_map.job_changes` to give Captain, Head of Personnel, Head of Security, Chief Engineer, Chief Medical Officer, Research Director and Quartermaster 0 total and spawn positions, then call `SSjob:setup_occupations()`.
2. `get_job("Captain")` returned null, as expected.
3. Open the latejoin menu.

Result: the menu rendered normally (an empty Command section, all other sections as usual) and `runtime.log` had no new runtimes.

## Cause

### #94000
`setup_occupations()` in `code/controllers/subsystem/job.dm` builds `joinable_departments` (`:153-191`). Jobs with no `departments_list` go to `/datum/job_department/undefined` (`:179-185`); all others go to each department in their list. `department_for_prefs` is never consulted.

Assistant (`code/modules/jobs/job_types/assistant/assistant.dm:23`) and Prisoner (`code/modules/jobs/job_types/prisoner.dm:16`) set `department_for_prefs` but have no `departments_list`, so both land in the undefined department, displayed as "No Department". `ui_data` and `ui_static_data` in `code/modules/mob/dead/new_player/latejoin_menu.dm` (`:60`, `:102`) iterate `SSjob.joinable_departments` directly. The preferences menu instead uses `job.department_for_prefs || job.departments_list?[1]` (`code/modules/client/preferences/middleware/jobs.dm:50`).

### #81754
`ui_data`, `ui_static_data` and the random-job helper in `latejoin_menu.dm` (`:73`, `:114`, `:195`) call `owner.IsJobUnavailable(...)`, which calls `SSjob.check_job_eligibility` (`job.dm:953`, `new_player.dm:135`). That proc calls `job_debug()` on every failure, with no way to suppress it.

### #46956
The code quoted in the issue (`new_player.dm` looking up a head job in `name_occupations`) no longer exists. The current latejoin menu only uses `joinable_departments` and `joinable_occupations`.

## Fix

Two commits on [fix/94000](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/94000).

**"Fix issue 94000: latejoin menu lists jobs under their department_for_prefs".** Adds `/datum/latejoin_menu/proc/get_department_layout()`. It starts from `SSjob.joinable_departments`, then places each job from `SSjob.joinable_occupations`:
- Command jobs go under every department in their `departments_list` (as before).
- Other jobs go under `department_for_prefs`, else the first entry of `departments_list`, else the undefined department.
- Empty departments are dropped.

A department that is not in `joinable_departments` (Assistant, which no job lists in `departments_list`) gets a section built from `initial()` of its type's name and color. `ui_data` and `ui_static_data` now use this layout, replacing the old per-job "first department or command" filter. `SSjob.joinable_departments` itself was left unchanged because other code uses it (the report names the manifest and bans).

**"Fix issue 81754: latejoin menu no longer spams the job debug log".** Adds a `silent` argument (default FALSE) to `check_job_eligibility` and `IsJobUnavailable`; when set, nothing is written to the job-debug log. The menu's three calls in `ui_data`, `ui_static_data` and the random-job picker pass `silent = TRUE`. Joining a job (`AttemptLateSpawn`) still logs.

## Verification

#94000, after the fix, with the round started and the menu open (JobSelection UI data):
- Security contained Head of Security, Warden, Detective, Security Officer and Prisoner (Prisoner's `unavailable_reason` was "already filled to capacity").
- A new "Assistant" section held Assistant.
- No "No Department" section existed.
- Coroner was under Medical; Captain, Head of Security, Chief Engineer, Chief Medical Officer, Research Director, Quartermaster and Head of Personnel were still in Command and in their own departments.
- No runtimes.

#81754, after the fix: with the menu open and ticking for about 25 seconds and Station Engineer ineligible by age, the round's debug log had 0 "Mob IsJobUnavailable" lines. A non-silent call through the Lua editor (`me:IsJobUnavailable('Station Engineer', true)`) wrote one line, `DEBUG-JOB: Mob IsJobUnavailable Error: Your character is not old enough for ., Player: ...`; the `silent` call wrote none.

Not checked: the pre-fix menu in game (neither issue); the visual layout of the menu in a real client; maps or configs with other unusual department setups.

## Notes

- Design choice: command jobs keep appearing in every department they belong to, matching the old behaviour. Non-command jobs now use `department_for_prefs` first, which could differ from the old "first of `departments_list`" rule only for jobs that set both.
- Side finding, not fixed: the age error line reads "not old enough for ." because `check_job_eligibility` calls `get_job_unavailable_error_message(JOB_UNAVAILABLE_AGE)` without the job title.
- #46956 is closed by the code having changed, not by this fix. Its related PR #48988 (AI disabled) was already merged.
