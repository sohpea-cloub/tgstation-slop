# #64330: Dexterous holoparasites can't use the keybinds to store/take out items

| | |

| Status | Fixed on the branch; verified in game for a dextrous guardian |
| Fix branch | [fix/64330](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/64330) |

## Summary
Dextrous guardians (holoparasites) could store and take out items only by clicking, because the quick-equip (E) and smart-equip (Shift+E and related) keybindings were limited to humans. `can_use` required `ishuman`, and `smart_equip_targeted` was a human-only proc. The fix lets any living mob use these keybindings and moves `smart_equip_targeted` to `/mob/living`.

## The bug
A player controlling a dextrous guardian who holds an item and presses E does nothing. The guardian's internal storage slot works by clicking, and the equivalent hotkeys never fire. The issue's comment notes that the inventory hotkeys are not given to non-human mobs.

## Reproduction
1. On the test server, start the round and join as an observer (or any mob) with admin tools.
2. In the Lua editor, spawn a `/mob/living/basic/guardian/dextrous`, put a crowbar in its active hand and possess it by setting its `ckey`. Answer the name and colour prompts.
3. Press E with the crowbar in hand. Observed on master: nothing happened and the inventory was unchanged.
4. Call the `quick-equip` verb on the guardian directly. Observed: the crowbar moved into the guardian's "internal storage". The verb itself works, so only the keybinding was missing.

## Cause
`/datum/keybinding/human/can_use` in `code/datums/keybinding/human.dm:5-6` returned `ishuman(user.mob)`, so every keybinding in that category was refused for a non-human mob. Their `down()` procs also cast `user.mob` to `/mob/living/carbon/human`. In addition, `smart_equip_targeted`, used by the belt, bag, suit-storage and pocket keybindings, was defined as `/mob/living/carbon/human/proc/smart_equip_targeted` (`code/modules/mob/living/carbon/human/inventory.dm:349`), so non-humans could not call it. The dextrous guardian's internal storage is its suit-storage slot (the report says Shift+Q reaches it), which these procs handle generically.

## Fix
One commit, "Fix issue 64330: Dexterous holoparasites can use the storage keybinds":

- `code/datums/keybinding/human.dm`: `can_use` now returns `isliving(user.mob)`. The quick-equip and smart-equip `down()` procs use a `/mob/living` variable instead of casting to human.
- `smart_equip_targeted` was moved unchanged from `/mob/living/carbon/human` (`code/modules/mob/living/carbon/human/inventory.dm`) to `/mob/living` in `code/modules/mob/inventory.dm`, next to `quick_equip`.
- The doc comment for `COMSIG_HUMAN_NON_STORAGE_HOTKEY` (`code/__DEFINES/dcs/signals/signals_mob/signals_mob_carbon.dm`) was updated to the new proc and argument type.

Widening the check to living mobs, rather than adding a guardian-specific keybinding, fixes the same gap for any other living mob that has storage slots.

## Verification
After rebuilding, with a possessed dextrous guardian holding a crowbar:

- E: the crowbar moved into internal storage.
- Shift+Q (the suit-storage slot, the guardian's internal storage): the crowbar came back into the guardian's left hand.
- The runtime log showed only the known empty Lua runtime lines.

Not tested: humans (same code path, since a human is a `/mob/living`), and the other keybindings (belt, bag, pockets) for guardians or other mobs.

## Notes
- Side effect to weigh: other living mobs, such as cyborgs and simple mobs, can now trigger these hotkeys. With no belt, for example, Shift+E prints "You have no belt to take something out of!". The report calls this uncertain and it was not tested in game.
- The keybinding datums and signal names still use "human" naming, kept to keep the change small.
