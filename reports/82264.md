## Summary

Every container holding gunpowder reacts on its own when an explosion hits it, and each one starts its own `dyn_explosion()`. If several gunpowder pills sit on one tile, a single blast therefore produces one pill explosion per pill, which bypasses the usual limit of one explosion per tile. The fix keeps a short per-tile record: the first gunpowder holder hit on a tile in a given blast explodes, and any further holder on that tile within one second only loses its reagents.

## The bug

The reporter found that, unlike other explosives, gunpowder in pills can be stacked on a tile, and a blast then gives two or more booms from that tile. In their round, a large pile of pills near chemistry exploded mostly on the same few tiles and produced 3640 `/obj/effect/particle_effect/expl_particles` objects, which they had to delete. In normal chain-reaction bombs, a tile detonates at most once.

What actually happens is that nothing counts the detonations. Each pill is its own reagent holder, the explosion calls `ex_act` on every item on the tile, and each gunpowder reagent answers that call with a fresh explosion of its own. The comment on the issue asks whether pills can be heated at all; this report does not depend on heating, since an explosion is enough to set them off (see Notes for the heat and spark path, which was not tested).

## Reproduction

Done on master with admin tools, as an observer, using the Lua editor. This was reproduced through the same code path the player action uses (an explosion reaching the pills); the starting explosion was triggered by calling the `explosion()` proc, not by a chemical or heat reaction.

1. Start a round and open the Lua editor.
2. On one tile, spawn six `/obj/item/reagent_containers/applicator/pill` and add 10 units of `/datum/reagent/gunpowder` to each pill's reagents (`p.reagents:add_reagent(<gunpowder path>, 10)`). The test tile was in the Central Primary Hallway.
3. Trigger a small explosion on that tile: `explosion(tile, 0, 0, 1)` (devastation 0, heavy 0, light 1).
4. Read the admin log and listen to the explosion sounds.

Observed on master:

- The admin log showed one explosion "Possible cause: the floor" (the test explosion itself) and then six further explosions, each with "Possible cause: the pill".
- Seven explosion sounds played.
- The pills were thrown by the blast but not destroyed.

## Cause

`/datum/reagent/gunpowder` registers its holder's atom for `COMSIG_ATOM_EX_ACT` when it is created (`code/modules/reagents/chemistry/reagents/pyrotechnic_reagents.dm:127`). The handler is `/datum/reagent/gunpowder/on_ex_act()` (`pyrotechnic_reagents.dm:134`):

```dm
/datum/reagent/gunpowder/proc/on_ex_act(atom/source, severity, target)
	SIGNAL_HANDLER
	if(source.flags_1 & PREVENT_CONTENTS_EXPLOSION_1)
		return
	var/location = get_turf(holder.my_atom)
	var/datum/effect_system/reagents_explosion/expl = new(location, 1 + round(volume / 6, 1), message = FALSE)
	expl.start(holder.my_atom)
	holder.clear_reagents()
```

The signal is sent to each object as the explosion processes the tile (`code/__DEFINES/explosions.dm:27`). The handler only skips holders that are flagged `PREVENT_CONTENTS_EXPLOSION_1`; pills are not. The explosion is created through `reagents_explosion.start()` (`code/game/objects/effects/effect_system/effects_reagents_explosion.dm`), which calls `dyn_explosion()` with the pill as the cause. There is no per-tile check, and the pill is not removed before the other pills on the tile are processed, so every pill on the tile makes its own explosion from the same blast.

## Fix

One commit, "Fix issue 82264: only one gunpowder detonation per tile per explosion", changes `on_ex_act()` in `pyrotechnic_reagents.dm`:

- A static list on the gunpowder reagent, `blast_times`, maps a tile's coordinates (`"x,y,z"`) to the `world.time` until which that tile's detonation is considered spent.
- When a gunpowder holder is hit, the handler builds the key from the holder's turf. If the current time is still before the stored time, the handler only calls `holder.clear_reagents()` and returns, so the pill burns up without exploding. Otherwise it stores `world.time + 1 SECONDS` and explodes as before.
- The key is made from coordinates rather than the turf reference because the explosion may replace the turf.

The one-second window was chosen because the sibling pills are all hit by the same blast within the same tick, and a time window needs no cleanup hook at the end of the blast. The cost is described in Notes.

## Verification

After rebuilding, the same setup was repeated on the test server: six pills with 10 units of gunpowder each on one tile, then `explosion(tile, 0, 0, 1)`. The admin log showed one explosion caused by the floor and one caused by the pill, instead of six pill explosions.

Not checked:

- Chemical or heat ignition (`on_spark_act`) of stacked pills; the code was not changed there.
- Gunpowder in containers other than pills (beakers, grenades, bottles), and mixed piles.
- Two separate blasts on one tile within a second (see Notes).
- Whether the single remaining explosion's power is appropriate for a pile, for example whether it should scale with the total gunpowder on the tile. It uses the first holder's volume only.
- A full-size pile like the one in the reporter's screenshots.

## Notes

- Side effect of the time window: an independent second explosion on the same tile less than one second after the first will not set off gunpowder there, because the tile is still marked as spent.
- The remaining pills in a stack lose their reagents without exploding, so the total yield of a pile is that of one pill (the first one hit), not the sum. A maintainer may prefer to sum the volumes into one explosion instead; the fix does not do that.
- The heat and spark path (`on_spark_act`, `pyrotechnic_reagents.dm:144`) schedules or triggers `reagent_explode()` separately. It does not go through `on_ex_act`, and the fix leaves it alone. That path was not tested for the same stacking behaviour.
- The reproduction used a test explosion, not a chain of real bombs, so how much of the reporter's 3640 particle effects came from this path alone was not measured.
