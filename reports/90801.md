## Summary

- **#90801:** `/turf/open/floor/holofloor` blocks every item interaction. That handler runs before the fishing rod's own `interact_with_atom`, so a rod used on holodeck beach water from an adjacent tile did nothing. From two tiles away the rod fires a projectile and works. The water turf now lets fishing rods through.
- **#90756:** the grill-mark overlay was built from a 32x32 mask, so the right half of 64px-wide fish (the armored pike) stayed white. The mask is now tiled over the whole icon.
- **#96594:** the Amphibious trait only lifts the "needs water" check. Fish whose temperature range excludes room air still suffocate, which probably explains the report. No change was made, since ignoring the range would be a balance decision.

## #90801: can't fish from directly beside holodeck water

### The bug

On the holodeck beach, using a fishing rod on a water tile from the tile directly next to it produces no message and no cast. Stepping back one tile makes it work.

### Reproduction

1. On the test server, observe, then use the Lua editor to spawn a human and give control of it to the observer. Place it next to the holodeck console.
2. Load the beach program from the holodeck console (`load_program` with id `holodeck_beach`).
3. Spawn `/obj/item/fishing_rod/telescopic/master`, put it in the human's hand and call `attack_self` to extend it (it is collapsed otherwise).
4. The beach has water on the row y=172, coastline y=173 and sand y=174 (Recreational Holodeck, z2). Stand at 154,173 and click the water at 154,172.
5. Result on master: nothing happens. There is no chat line, `rod.fishing_line` stays null and no runtime is logged.
6. Step back to 154,174 (two tiles from the water) and click the same tile: "You start fishing..." appears.

Extra values read from Lua at 154,173: the rod had a hook, `casting` was 0, `combat_mode` was 0, `water:Adjacent(user)` was 1 and `get_cast_range` was 8, so nothing in the rod's state explained the failure.

### Cause

`cast_line` in `code/modules/fishing/fishing_rod.dm:418` skips the projectile when the target is adjacent: `if(target.Adjacent(user, null, null, 0)) hook_hit(target, user); return`. For a distance-2 target a projectile is fired and the cast reaches the fishing spot through `COMSIG_FISHING_ROD_CAST` without going through the turf's item interaction.

For an adjacent click, the click first goes through the turf's `item_interaction`, and only then to `tool.interact_with_atom` (`code/game/atom/atom_tool_acts.dm:40-48`). The holodeck floor defines:

```dm
/turf/open/floor/holofloor/item_interaction(mob/living/user, obj/item/tool, list/modifiers)
	return ITEM_INTERACT_BLOCKING
```

(`code/modules/holodeck/turfs.dm:10`). Since the beach water, `/turf/open/floor/holofloor/beach/water` (line 91, which adds the holographic fishing spot at line 98), inherits it, the rod's `interact_with_atom` is never called for it.

### Fix

Commit "Fix issue 90801: let fishing rods cast at adjacent holodeck water" adds an override on the beach water turf only:

```dm
/turf/open/floor/holofloor/beach/water/item_interaction(mob/living/user, obj/item/tool, list/modifiers)
	if(istype(tool, /obj/item/fishing_rod))
		return NONE
	return ..()
```

Other holofloor items stay blocked. The alternative of changing the base holofloor handler was not taken, because it would let every item interact with every holodeck floor.

### Verification

After rebuilding and repeating the steps above, standing at 154,173 and clicking the water at 154,172 printed "You start fishing...". Not checked: a non-holodeck fishing spot next to the user (the cause is specific to the holofloor by code), and other holodeck turfs with fishing spots, if any.

## #90756: half of a grilled armored pike is white

### The bug

A grilled armored pike (and probably any wide fish) shows white over the right half of its sprite.

### Reproduction

Not reproduced through the grill. The agents spawned an armored pike and a goldfish and added the `/datum/component/sizzle` component directly, then rendered them. The report records the cause from code and the result after the fix only. A render before the fix is not recorded in the reports, so the visual symptom on master was not confirmed in game.

### Cause

`code/datums/components/sizzle.dm:14-16` builds the overlay by copying the item's icon state, filling it with white, and multiplying it with the 32x32 `grillmarks` icon state at (1,1):

```dm
var/icon/grill_marks = icon(food.icon, food.icon_state)
grill_marks.Blend("#fff", ICON_ADD)
grill_marks.Blend(icon('icons/obj/machines/kitchen.dmi', "grillmarks"), ICON_MULTIPLY)
```

The pike icons are in `icons/obj/aquarium/wide.dmi` and are 64x32. The marks cover only the left 32 pixels, and multiplying with nothing leaves the right half as the plain white fill.

### Fix

Commit "Fix issue 90756: tile grill marks over icons wider than 32px" loops over the icon's width and height in steps of the mark icon's size and blends the marks at each offset, so the whole sprite gets marks.

### Verification

A small render of an armored pike with the sizzle component showed it brown with marks along its whole length and no white half. The real grill path was not used, and no other fish or taller icons were rendered.

## #96594: Amphibious trait works inconsistently

### Reproduction

In the Central Primary Hallway (293.15 K, 101 kPa) the test applied the amphibious trait to several fish in Lua (`apply_to_fish` with `initial` false) and called `proper_environment()` afterwards:

| Fish | Result |
|---|---|
| goldfish, pike, catfish, bumpy | 1 (survives) |
| clownfish | 0 (minimum 295.15 K) |
| cardinal | 0 (minimum 295.15 K) |
| sockeye salmon | 0 (maximum 292.15 K) |
| lavaloop | 0 |

### Cause

The trait only sets the fluid requirement to air (`aquarium.dm:413` and the fish trait file). `proper_environment` (`code/modules/fishing/fish/_fish.dm:1220`) still checks `safe_air_limits`, the temperature range (line 1238) and pressure in air. A fish whose range excludes the room's temperature keeps losing health, probably the reporter's case. This was not confirmed against the reporter's actual fish.

### Fix

None. A possible change is to skip the temperature range for fish with `TRAIT_FISH_AMPHIBIOUS` in the air branch of `proper_environment`. It was left out as a balance decision, and the issue stays open.
