## Summary

Rechargers inside a holodeck (the Firing Range weapon recharger in #83754, the "holographic recharger" in #96452) blink as if charging but never put any energy into a gun. The energy procs in `code/modules/power/power.dm` read the machine's area's `apc` directly, and a holodeck area has no APC (it only borrows its computer's area for `powered()`), so every energy draw fails. The fix adds an overridable `/area/proc/get_power_apc()`, makes the holodeck area return the APC of the area its computer sits in, and uses it in the four energy procs.

## The bug

On the Firing Range holodeck program, a weapon recharger is part of the scene. Putting a discharged energy gun in it makes the recharger light blink yellow as normal, but the gun never gains charge. #96452 (2026) reports the same for holographic rechargers with "guns, holographic or not". A comment on #83754 said the items "aren't real"; the reporter answered that real guns would not charge either and that this looked like a regression from the energy rewrite (#83529). A comment on #96452 traces the same chain: rechargers call `charge_cell` on the gun's cell, the cell goes through `use_energy`, and that returns `FALSE` when the area has no APC.

## Reproduction

1. Start a round on the test server (MetaStation was used) and open the Lua editor as an admin. Note: a local setting needed changing, see Notes.
2. With the Lua editor, load the Firing Range program on the holodeck console with `load_program('holodeck_firingrange', true, false)`.
3. Find the weapon recharger in the holodeck area, spawn an `/obj/item/gun/energy/e_gun`, set its cell to empty (`get_cell().charge = 0`) and `forceMove` the gun into the recharger (which starts charging via `Entered()`).
4. Wait about 15 seconds and read the cell's `used_charge()`.

Observed on unmodified master:
- The recharger was powered (`machine_stat` 0, `using_power` 1), and the holodeck area's `apc` var was null.
- `used_charge()` stayed at 10000 after about 18 seconds: no charge at all.

This was reproduced by moving a gun into the recharger with admin tools, which is what a player would do with the item, not by calling the charging procs directly. A real (non-holographic) gun was used, so the case in #96452 about "holographic or not" is the same code path: any gun's cell goes through `charge_cell`.

## Cause

`code/modules/power/power.dm` has four machine procs that find the APC by reading the machine's area directly:

- `available_energy()`: `var/obj/machinery/power/apc/local_apc = home.apc` (line 143)
- `use_energy()`: `home.apc` (line 169)
- `directly_use_energy()`: `my_area.apc` (line 204)
- `use_power_from_net()`: `home.apc` (line 230)

Each one returns `FALSE` when the APC is null. The holodeck area (`code/game/area/areas/holodeck.dm`) has no APC of its own. It overrides `powered()`, `addStaticPower` and `use_energy` on the area to use its linked computer's area, but the machine-level procs never go through those overrides and read `.apc` directly. So `charge_cell()` (`power.dm:253`) always gave the cell 0 in a holodeck. Apparently this was introduced by the energy rewrite (#83529), as the issue suggests.

## Fix

Commit **"Fix issue 83754: holodeck machines draw power from the linked area's APC"**:

- `code/game/area/areas.dm`: new `/area/proc/get_power_apc()`, which returns `apc`.
- `code/game/area/areas/holodeck.dm`: `/area/station/holodeck/get_power_apc()` returns the `apc` of `get_area(linked)`, or null if the holodeck is not linked to a computer (with the same `ASSERT` against a holodeck-in-holodeck loop that the neighbouring overrides use).
- `code/modules/power/power.dm`: the four procs above call `get_power_apc()` instead of reading `.apc`.

This keeps the existing model (the holodeck borrows its computer's grid) and fixes it at the one place the machine procs look up the APC, so every holodeck machine that draws power benefits, not only the recharger. Other places in `power.dm` read `source_area.apc` (lines 446 and 517) and were not changed.

## Verification

Checked in game with the same steps as in Reproduction, on the fixed build: `used_charge()` of the gun went from 10000 to 3000 after about 15 seconds, so the recharger charged the gun. No new runtimes appeared in the server log.

Not checked:
- Other holodeck machines that draw power (only the recharger path was exercised).
- Other holodeck programs than the Firing Range, and other maps' holodecks.
- A holodeck whose computer is in an area without an APC, or an unlinked holodeck (the code returns null there; it was not run).
- The fix was not tested with holographic guns specifically; they share the same code path.

## Notes

- Side finding, not fixed. `/obj/machinery/computer/holodeck/Destroy()` (`code/modules/holodeck/computer.dm:467-471`) does `linked.energy_usage = list(AREA_USAGE_LEN)`, which makes a 1-element list rather than `new /list(AREA_USAGE_LEN)` (the same expression is used at line 119), and it clears `linked.linked` without checking that `linked.linked == src`. Deleting a second console that has linked to the real holodeck area therefore unlinks it: `powered()` becomes `FALSE` and all machines read as unpowered, and `removeStaticPower` raised a `list index out of bounds` runtime at `areas.dm:561`. This was met on the test server only because the dev default `GENERATE_ASSETS_IN_INIT` (`config/config.txt:653`, documented as to be disabled in live environments) makes the map-preview subsystem spawn and delete a holodeck console at 1,1,1. The setting had to be commented out locally for testing, and the fix does not depend on it. Players on a live server are unlikely to hit this exact path.
- Reading `cell.charge` from the Lua editor returns the proc, not the value (use `used_charge()`); and `lua # on a list of nulls` and indexing `energy_usage` once crashed the test server (illegal operation in `lua_state.dm:97`), which was not investigated.
- #96452 is closed as a duplicate by this fix; no behavior specific to it was found.
