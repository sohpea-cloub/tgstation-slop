## Summary

The report shows "I AM ERROR" tiles (`/obj/effect/mapping_error`) appearing around the emergency shuttle dock during the Nar'sie ending on NebulaStation. The only code that ever created that object at runtime was an `Initialize` on the shuttle ceiling plating, which was removed by PR #90660 (merged 2025-04-21). On current master, the same scenario (Nebula, Nar'sie at the dock, emergency shuttle docking) produced no error objects, so the issue could not be reproduced. Nar'sie herself is not the cause.

## The bug

As reported, when the emergency shuttle docked while Nar'sie was nearby in the cult ending, a patch of tiles around the dock turned into red "I AM ERROR / FIX ME" markers, visible from the level above. The reporter's own wording is that the shuttle "tried to land on Nar'sie" and that the error tiles seemed to spread out from where the shuttle landed. The screenshot shows NebulaStation at security level delta with the Nar'sie ending running.

The markers are not related to Nar'sie's consume behaviour. `/obj/effect/mapping_error` is a debug marker ("should NEVER actually appear in production", `code/modules/mapping/mapping_helpers.dm:110-115`). Before PR #90660, the shuttle ceiling plating created one whenever a ceiling was placed over a space area that was not `/area/space/nearstation`. Any shuttle docking under open space in plain `/area/space` could therefore produce them, which is why a closed duplicate (#84597, a pirate ship drawn wrongly from the level above) describes the same thing.

## Reproduction

This is an attempt to reproduce on master; it did not show the bug.

1. Changed the map to NebulaStation with the Change Map admin verb, restarted the test server, used Start Now and joined as an observer. On this map the station is on z-levels 2 and 3, and the emergency shuttle's home dock is at 46,129,2 (footprint 22,120 to 46,148).
2. Using the Lua editor, checked z3 above the dock footprint: 481 tiles there were `/turf/open/space/openspace` in plain `/area/space`. This is exactly the situation that used to spawn error markers when a ceiling was placed.
3. Using the Lua editor, spawned an `/obj/narsie` at 34,134,2 (inside the dock footprint), called `start_ending_the_round()` on it, called the emergency shuttle and shortened its timer so it would dock quickly. Nar'sie's rising announcement and the delta alert appeared as expected.
4. Waited for the shuttle to dock at `emergency_home`. Nar'sie had moved away (she was at 78,164,2 when the shuttle docked), so the shuttle did not literally land on her. This differs from the issue's wording.
5. Checked the result:
   - A Lua scan of z2-3 around the dock found 0 `/obj/effect/mapping_error` objects, both while the shuttle was on approach and after it docked.
   - Of the shuttle ceiling plating tiles found on z3 (`/turf/open/floor/engine/hull/ceiling`), all 299 were in `/area/space/nearstation`.
   - An SDQL2 `SELECT /obj/effect/mapping_error` over the whole world, run after docking, was submitted (the result list was not read back directly, but the Lua scan found none).
   - The round's runtime log contained no runtime errors.

## Cause

Not present on master. `code/game/turfs/open/floor/hull.dm` now defines `/turf/open/floor/engine/hull/ceiling` with only a name; it has no `Initialize`. The only remaining references to `mapping_error` are its definition (`code/modules/mapping/mapping_helpers.dm:111`) and the nearstation unit test (`code/modules/unit_tests/mapping_nearstation_test.dm:15`), which looks for it.

The change that removed the old behaviour is PR #90660, "Implements an automatic nearstation area tiler". Space turfs now assign `/area/space/nearstation` to themselves whenever they are replaced (`code/game/turfs/open/space/space.dm:209-210`), so shuttle ceilings placed through `code/modules/shuttle/mobile_port/shuttle_move.dm:194-202` or `code/__HELPERS/shuttle.dm:424-429` end up in the nearstation area. The old ceiling-time marker was only a tracking aid for that problem and was dropped along with it. The ceiling placement paths themselves are unchanged.

## Fix

None committed. No change was needed on master.

## Verification

Checked in game on the scenario above (Nebula, Nar'sie ending, emergency shuttle docked over 481 open-space tiles in plain space area): 0 error objects, 299 ceiling tiles all in the nearstation area, no runtimes.

Not checked:
- The literal case of Nar'sie standing on the docking zone at the moment of landing. She had wandered off before the shuttle docked.
- Whether Nar'sie consuming parts of the shuttle or its dock causes any other visual or turf problems; the reported symptom was only the error markers.
- Other maps. The test used only NebulaStation, the map in the report's screenshot.
- Behaviour before PR #90660 was not re-run; the link to that PR rests on reading the code and the PR description, not on a before/after test.

## Notes

- The issue's screenshot and the closed duplicate #84597 point at the same cause. #88972 looks safe to close as fixed by PR #90660.
- The reporter's remark that the error tiles seemed to "spread out from where the shuttle landed" fits the old behaviour: markers appeared on each ceiling tile placed over non-nearstation space, i.e. across the shuttle's footprint.
