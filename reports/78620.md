# #78620: Meteor shuttle event causes heavy time dilation

| | |
|---|---|

| Status | Not reproduced, no fix |
| Fix branch | none |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The report says the meteor shuttle event dropped the server to 1-5% time dilation for a whole shuttle ride. On master the event, even stacked well past its normal size, produced at most about 0.7% dilation and no runtimes. The runtime quoted in the issue (a bluespace meteor teleporting into a cordon turf and calling `get_teleport_turfs(null, 6)`) no longer exists in the code, because `do_teleport` was refactored. The lag in the report was probably caused by the testmerged PRs or by the atmospherics runtime spam (about 1728 occurrences) listed in the same issue, not by the event.

## The bug

Per the reporter, on the shuttle home meteors flew past without hitting it and time dilation sat at about 1-5% for the whole ride, so they could not play music. A commenter linked the lag to runtimes when a bluespace meteor tries to teleport through a cordon turf, and also posted many repeated atmos runtimes from heat-exchanger pipes with null air.

## Reproduction

Not reproduced. What was tried on master:

1. Started the round, then called the evacuation shuttle with admin tools and, using the Lua editor, shortened the timer to dock and launch it. The shuttle rolled the "Various Meteors! (Safe)" event by itself, which includes `/obj/effect/meteor/bluespace`.
2. To stress it, added 9 more `/datum/shuttle_event/simple_spawner/meteor/safe` events (10 in total, 60 spawns per tick), then spawned 150 extra bluespace meteors through the event's `spawn_movable`.
3. Read `SStime_track.time_dilation_current` and its fast average, and `GLOB.meteor_list`, from the Lua editor.

Evidence:

| Meteors | Dilation (current / fast average) |
|---|---|
| 12 | 0 / 1.9 |
| 57 (10 events) | 0 / 0.93 |
| 47 | 0.21 / 0.46 |
| 649 in transit | 0.71 / 0.73 |

- A reading of 8.5% right after round start occurred with 0 meteors and was treated as start-of-round noise.
- 194 meteor bluespace teleports were logged in `game.log` during the stress test.
- The round's `runtime.log` held only one line from the tester's own faulty Lua call ("Global var world does not exist"). There was no `get_teleport_turfs` or cordon runtime.

## Cause

None found on master; the quoted runtime is gone.

- In the issue, `/obj/effect/meteor/bluespace/Bump` (`code/modules/meteors/meteor_types.dm:345`) called `do_teleport` when bumping a `/turf/cordon`, and `get_teleport_turfs` read `.x` of a null turf.
- `do_teleport` now picks its destination with `get_valid_teleport_turf` (`code/datums/helper_datums/teleport.dm:225`), which returns null when no turf qualifies, and `do_teleport` returns FALSE on `!destturf` (`teleport.dm:70`) instead of dereferencing null.
- Shuttle-event meteors also carry `TRAIT_FREE_HYPERSPACE_SOFTCORDON_MOVEMENT` and `TRAIT_DEL_ON_SPACE_DUMP` (`code/modules/shuttle/shuttle_events/_shuttle_events.dm:147-148`), so `/turf/cordon/Bumped` (`code/modules/awaymissions/cordon.dm:50`) deletes them via `dump_in_space` (`code/game/turfs/open/space/transit.dm:63`) rather than letting them keep bumping.

## Fix

None. There is no defect on master to fix, and no branch exists.

## Verification

Only the stress test above. Not checked: a full-length shuttle ride with real players, the heat-exchanger pipe runtimes from the issue (not examined), or the testmerged PRs named in the issue (not part of master).

## Notes

- The atmos runtimes in the issue (`process_atmos` and `return_air` on heat-exchanging pipes with null air, in space or on reinforced floor) are not meteor-related. They occurred 1728 times in the report, and are a more likely source of the lag, but were not investigated.
- The issue was filed on a build with two testmerged PRs, so the original dilation may have come from them.
- The issue is likely stale and could be closed as already fixed or not reproducible.
