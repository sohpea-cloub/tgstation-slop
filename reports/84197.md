## Summary

The report said that the station trait buttons beside the lobby (skub, bridge assistant, ...) stayed on screen when the lobby menu was collapsed. At master the lobby is a tgui window, and the trait buttons are collapsed together with the rest of the menu. The old screen-object buttons the report was about have no users left. This was established by reading the code only, not by seeing the lobby.

## The bug

As reported (against commit 7579e0e1), collapsing the lobby menu moved the menu away but left the station trait buttons floating on the side. The reporter expected them to animate into the shutter or at least disappear. The skub button never goes away during a shift, so the leftover was permanent.

## Reproduction

Not reproduced. The report's steps (force a station trait, collapse the menu, look at the buttons) need a client that runs the tgui lobby, and the test setup could not render tgui JavaScript, so the collapse animation could not be watched. The issue is purely visual, so there was no game state to read instead.

What was checked in the code at master:

- The old per-trait screen-object buttons used `HUD_NEW_PLAYER_LOBBY_BUTTON(type)` (`code/__DEFINES/hud.dm:79`). The define is the only match in `code/`: nothing uses it.
- Station trait buttons are now sent to the tgui lobby as `stationTraits` (`get_station_traits()` in `code/modules/lobby_menu/lobby_menu.dm:209`) and drawn by `tgui/packages/tgui-lobby/LobbyMenu.tsx`.

## Cause

None at master. In `LobbyMenu.tsx` (lines ~600-610) each trait is a `LobbyElement` that receives the same `collapsed` state as the other menu buttons:

```tsx
{ss.stationTraits.map((trait, i) => (
  <LobbyElement
    key={trait.ref}
    top={40 + (i % MAX_TRAITS_PER_COLUMN) * 27}
    left={-85 - Math.floor(i / MAX_TRAITS_PER_COLUMN) * 27}
    zIndex={3}
    collapsed={collapsed}
  >
```

When `collapsed` is set, `LobbyElement` adds the class `lobby__el--collapse-up`, which in `tgui/packages/tgui-lobby/styles/main.scss:68-71` is `transform: translateY(s(-146px))`, animated by the element's CSS transition. By the arithmetic of the layout, trait buttons are 24px tall with tops of 40, 67 and 94 (`40 + (i % 3) * 27`), so after the move their bottoms are at or above -28px, which is above the top of the window. The lobby page hides overflow, so they slide up out of view with the menu. Further traits go into extra columns at the same tops, with the same result.

## Fix

None. No commit was made.

## Verification

Verified by reading the code only; the collapse animation was not observed. Confirming it would need a real Dream Seeker client with the tgui lobby open, a forced station trait (to get at least one button) and a click on the collapse control. The heights, tops and overflow handling above are from the source, not from measurement.

## Notes

- The lobby was rewritten as a tgui window after this report was filed, which is what made the old screen-object buttons obsolete.
- Side finding: the localhost-only "start now" button is also a `LobbyElement` but is placed at `top={146}`, so after the 146px collapse its top is at y=0 and it stays visible. It is not a station trait and may be intentional.
