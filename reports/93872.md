## Summary

Virtual domain ghost-role spawners (`temp_body = TRUE`) moved the ghost's real mind into the virtual body. Dead antagonists therefore kept their antag datums, spells and memories inside the simulation. The same transfer renamed the real mind to the ghost role's name and gave it the Glitch job, which broke objectives that targeted it. It also confused the temporary-body component, so the player could not get back to their real body. The fix gives temporary-body ghost roles a fresh mind, the way bitrunner avatars and deathmatch already work. Two smaller fixes cover a null-mind runtime in the same spawner (#91549) and held domain items surviving the emagged-server equipment reset (#94050).

## The bug

Seven reports describe the same area from different sides.

- **#93872, #84765, #85153, #89806.** An antagonist dies, becomes a ghost and takes a virtual domain spawner (pirate, islander, beach bum, cyber police and so on). The new body keeps whatever the old character had. Reported examples are a heretic using Mansus Grasp and runes, a changeling using its abilities, a space dragon placing a portal inside the sim, and a blood brother keeping the Brother datum and memories. The reports say this only happens for spawners that let you return to your previous body.
- **#93346.** A traitor's assassination target died and took a pirate spawner, then returned to the old body. The traitor's objective text had changed to the ghost role's name ("Ionbeard, the Ghost Role") while the target was alive under their old name.
- **#91549.** Taking a virtual domain ghost role sometimes runtimed with `Cannot execute null.add antag datum()` in `special()`. The reporter said it was not consistent.
- **#94050.** Cyber police can leave a domain through an emagged quantum server and keep their domain weapons, and antag spells carry into the domain. The report also lists stamina-crit immunity, full station access, a P90 and wound immunity for cyber police.

## Reproduction

All steps were on master `87b93338`. The spawner was created next to the ghost with the Lua editor rather than reached through a loaded domain, and the "click the spawner" step was the normal spawner interaction.

**Mind transfer (#93872, #84765, #85153, #89806, #93346)**

1. Latejoin as an Assistant.
2. In the Lua editor, add the heretic and changeling antag datums to the character, call `death()`, then use the Ghost verb.
3. In the Lua editor, create a `/obj/effect/mob_spawn/ghost_role/human/virtual_domain/pirate` next to the ghost, click it and answer Yes to the prompt.
4. The pirate's HUD showed Mansus Grasp. Reading the pirate through the Lua editor gave:
   - the pirate's mind was the same mind object as the dead Assistant's
   - antag datums: Heretic, Changeling, Virtual Domain Actor
   - actions included Mansus Grasp, Absorb DNA, Regenerate and Transform
   - mind name `Spacebilge` (the pirate's name) and assigned role Glitch
   - the old body's `mind` was nil
   - the pirate's `temporary_body` component pointed at the pirate itself as the "old body"
5. Killing the pirate left the player as a ghost whose `mind.current` was the dead pirate, not the real body. The old body still had no mind, so the player could not return to it.
6. An assassinate objective targeting the original mind read "Assassinate Spacebilge, the Glitch." The target had been renamed and re-jobbed by the spawn.
7. The runtime log showed `parent_qdeleting overridden` runtimes (existing proc `return_mind`, new proc `on_body_destroy`), caused by the component re-registering its signals after the mind transfer (see Cause).

For #85153 (blood brother) the Brother datum was only checked after the fix. The code path is the same as for the other antag types, so it was counted as a duplicate rather than reproduced separately before the fix.

**#91549 (runtime)**

1. In the Lua editor, create an observer with no mind and a `key` set to a ckey that has no connected client.
2. Create an islander virtual domain spawner and call `create()` on it with that observer (done both from Lua and from SDQL2 `CALL create(...)`).
3. The spawned mob received the ckey but never ran `Login`, so it had no mind (`spawned_mind = nil`). A runtime was logged. The Lua-wrapped call produced an empty "uncaught runtime error" line; the report's own stack points at `special()` calling `add_antag_datum` on a null mind.

This reproduces the null-mind condition by constructing it; it was not reproduced by actually dropping a client during login.

**#94050 (held items)**

1. Create a human in the cyber police outfit holding a Makarov pistol.
2. Call `reset_equipment()` on the quantum server with that human (Lua editor).
3. After the call the human was still holding the Makarov pistol; the gun had not been deleted.

This was done by calling the proc directly. A full run with an emagged server and a spawned glitch leaving the domain was not performed.

## Cause

**Mind transfer.** In `/obj/effect/mob_spawn/ghost_role/special()` (`code/modules/mob_spawn/mob_spawn.dm:296-299`), whenever the possessor has a mind it is moved into the new body:

```dm
if(mob_possessor.mind)
	mob_possessor.mind.transfer_to(spawned_mob, force_key_move = TRUE)
else
	spawned_mob.PossessByPlayer(mob_possessor.key)
```

`create_from_ghost()` clears the ghost's mind first for normal ghost roles (`if(!temp_body) user.mind = null`, `mob_spawn.dm:262`), so normal roles reach the `else` branch with a blank slate. For `temp_body` spawners it does not, because the player is supposed to be able to return. The only users of `temp_body` are the virtual domain spawners (`code/modules/bitrunning/spawners.dm:7`). So for those, the ghost's real mind, with its antag datums, spells, memories, objectives and name, moved into the virtual body.

The rest of `special()` then ran on that real mind: `spawned_mind.name = spawned_mob.real_name` and `set_assigned_role_with_greeting(...)` (`mob_spawn.dm:301-304`) renamed it and gave it the ghost-role job. That is the #93346 symptom: objectives pointing at the mind showed the new name and the Glitch job.

**Return to the real body.** `virtual_domain/special()` attaches a `temporary_body` component that remembers the ghost's mind and its current body (`spawners.dm:13-15`). That component listens for `COMSIG_MIND_TRANSFERRED` on the old mind (`code/datums/components/temporary_body.dm:35`) and, in `on_mind_transfer()` (`temporary_body.dm:64-70`), resets `old_body = old_mind.current`. Because the old mind itself had just been moved into the virtual body, `old_mind.current` was now the virtual body, so the component's "body to return to" became the virtual body. The real body was left with no mind. This also explains the `return_mind` / `on_body_destroy` signal-override runtimes. Once the virtual body died there was nowhere valid to return.

**#91549.** `spawners.dm:20` does `spawned_mob.mind.add_antag_datum(...)` and assumes a mind exists. A mind is normally created by `/mob/Login`, which returns early (before `sync_mind()`) when the client is gone. That can happen when the client drops under lag, or when a polled ghost disconnected. In that case `PossessByPlayer()` sets the ckey but no mind is made, and `special()` runtimes on `null.add_antag_datum`. Before the transfer fix, this was masked whenever the ghost had its own mind (it was transferred instead); the runtime appears when the possessor has no mind.

**#94050 (held items).** `reset_equipment()` in `code/modules/bitrunning/server/util.dm:114-116` deletes only `get_equipped_items(INCLUDE_POCKETS | INCLUDE_ACCESSORIES)`, which does not include `INCLUDE_HELD`. Glitches leaving through an emagged server therefore keep anything in their hands. The spells part of #94050 comes from the same mind transfer as #93872.

## Fix

Three commits on the fix branch.

1. **Fix issue 93872: temporary-body ghost roles get a fresh mind instead of the ghost's.** In `ghost_role/special()` the condition became `if(mob_possessor.mind && !temp_body)`, so temporary-body roles go to `PossessByPlayer(key)` and receive a new mind. The old mind stays with the old body, and `temporary_body` returns the player to it afterwards. This is how bitrunner avatars (`avatar_connection`), deathmatch and capture the flag already behave, and how cyber police spawned by the server threat code (`threats.dm`, `new_mob.PossessByPlayer(ghost.key)`) already work. It fixes #84765, #85153, #89806, #93346 and the spell part of #94050. A comment on `temp_body` documents the behaviour.
2. **Fix issue 91549: virtual domain spawners no longer runtime when the spawned mob has no mind.** Before adding the antag datum, `special()` calls `spawned_mob.mind_initialize()` if the mind is null. With commit 1, every virtual domain spawn now goes through `PossessByPlayer`, so this guard matters more than before.
3. **Fix issue 94050: glitches leaving an emagged domain lose their held domain gear too.** Adds `INCLUDE_HELD` to the item sweep in `reset_equipment()`.

## Verification

The first two commits were tested together in game; the held-item change was tested by direct call.

- **Mind transfer.** Same steps as the reproduction, with a Blood Brother datum added as well. The pirate had its own mind: not the old mind, antag datums only `Virtual Domain Actor`, actions only "Open Virtual Domain Actor Information" and "Flip", job Glitch on the new mind only. The old mind kept Heretic, Changeling and Brother, its name (a normal character name) and job Assistant. `oldbody.mind` pointed at the old mind and the component's old body was the real body.
- **Objective (#93346).** The assassinate objective stayed "Assassinate Jeannine Stainforth, the Assistant", the original character's name and job.
- **Manual return.** Using Re-enter Corpse into the real body restored all antag datums and actions (Mansus Grasp, changeling powers, Brother).
- **Automatic return.** After reviving the real body, an islander was killed through ordinary damage in `Life()` (oxyloss until crit and death). The player went straight back into the live real body.
- **#91549.** A clientless ckey possessing a spawned islander now ended up with a mind carrying the Virtual Domain Actor datum, with no runtime from `special()`.
- **#94050.** After `reset_equipment()` the human's hands were empty and the pistol had been deleted.
- **Runtime log** after the fix: only three empty Lua "uncaught runtime error" lines. The signal-override runtimes were gone.

Not checked:

- #85153 (blood brother) was only observed after the fix, not before.
- No full emagged-quantum-server run was done: a glitch leaving the domain and the held-item check were done by calling `reset_equipment()` directly.
- Spawners reached through a real loaded domain and a real bitrunning round were not used; spawners were created with the Lua editor on the station map.
- Threat-spawned cyber police were not exercised (they need a live domain), though code reading shows they already use `PossessByPlayer`.

## Notes

- **Remaining bug, not fixed.** The automatic return can fail silently in one case. `temporary_body.return_mind()` calls `ghost.reenter_corpse()` (`temporary_body.dm:94`), which is a game verb. Verbs run asynchronously with `usr` as the invoker, and when `usr` is a mob without a client (here, the virtual body that had just died from a Lua-driven `death()`, and likely from succumb or suicide too) it returns without doing anything. The player stays a ghost, but Re-enter Corpse works by hand. It was seen when the death came from a Lua call; a death in `Life()` returned correctly. `grab_ghost` in `code/datums/mind/_mind.dm` uses the same pattern. This is older than, and independent of, this fix.
- **Why only return-to-body spawners were affected.** The reporters noticed the bug only for spawners that allow returning to your body. That matches the code: `temp_body` is what skips clearing `user.mind`, and the only `temp_body` spawners are the virtual domain ones. Regular ghost roles clear the mind first.
- **#94050's other points** (stamina-crit immunity, station access, weapons and wound immunity of cyber police, getting out of the domain again after taking another role) were not changed. Some are balance decisions. After this fix a domain actor's fresh mind has no `bitrunning_glitch` antag datum, so it cannot use the emagged-server exit that way. A commenter on #94050 asked whether keeping spells was intended; the fix treats it as unintended.
- **Memories and objectives.** With a fresh mind, the player in the simulation has no memories or objectives from their real life, only the domain actor role's own.
- No upstream PR addressing any of these seven issue numbers was found.
