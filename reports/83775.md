# #83775: Posibrain AIs become organic after an intellicard upload into a terminal with a swapped brain

| | |
|---|---|
| Issues | [#83775](https://github.com/tgstation/tgstation/issues/83775): verified, fixed (the fix follows one reading of an unresolved design question; see Notes) |
| Status | Fixed on the branch |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/83775 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a carded AI is uploaded to an AI terminal, `transfer_ai` sets the AI's `posibrain_inside` from whatever brain is in that terminal. Carding an AI leaves a terminal holding a posibrain, and players can swap that for an organic brain, so the AI comes out of the upload with `posibrain_inside` false and, when it is deconstructed, drops an organic brain holding its mind. The fix deletes that one line, so the AI keeps the brain type it was created with. Maintainers disagreed in the issue on whether this interaction is a bug at all, so the fix is a design choice that can be dropped if the interaction is wanted.

## The bug

Following the issue's steps, a player with a posibrain AI can: card the AI, replace the brain in the left-behind terminal with a soulless organic brain (the issue used a monkey brain), and put the card back in. The AI is then recorded as having an organic brain; when it is taken out of the core, its mind ends up in an organic brain that can be put in a body, which the issue calls a humanized posibrain.

The issue's discussion is split. The author of AI core deconstruction (13spacemen) said they allowed mindless brains in MMIs deliberately and regarded this as a harmless "neat interaction". Other commenters called it intended or emergent. The issue was reopened later as an exploit, and one commenter pointed to the possibility of replacing a living crew member's brain with a posibrain AI's.

## Reproduction

On master, using the Lua editor and SDQL2:

1. Spawn a human and call `AIize()` on it. The resulting AI has the default `posibrain_inside = TRUE`. Give the AI a mind with `mind_initialize`.
2. Call `capture_ai` on an AI card with that AI. `transfer_ai` creates a finished terminal (`/obj/structure/ai_core`) with a posibrain made by `make_mmi()`.
3. Build a finished AI core with an organic brain processor holding a mindless `/obj/item/organ/brain`, standing in for the swap described in the issue. This core was constructed directly rather than by taking the brain out of the card's terminal by hand.
4. Call `upload_ai` on the card with that core.
5. Read the AI's `posibrain_inside` and call its `make_mmi()`, which is what deconstruction and death use to drop its brain.

Observed on master: `posibrain_inside` went from 1 to 0, and `make_mmi()` returned an `/obj/item/brain_processor/organic` ("Cyborg"), so the mind ends up in an organic brain.

The last step of the issue, putting that brain into a humanized body, was not performed.

## Cause

`/obj/structure/ai_core/transfer_ai` in `code/game/machinery/ai_core/_core.dm`, in the `AI_TRANS_FROM_CARD` branch at line 229:

```dm
AI.posibrain_inside = isnull(core_mmi) || core_mmi.braintype == "Android"
```

This recomputed the AI's brain type from `core_mmi`, the brain sitting in the destination terminal. Carding creates that terminal with a posibrain, but the terminal's brain can be removed and replaced before the card is uploaded back. The AI's own flag was already set when the AI was created (`ai_structure_to_mob`, line 183), so this line only matters when the terminal holds a different brain than the one the AI had.

## Fix

Commit "Fix issue 83775: carding and re-uploading an AI no longer changes its brain type" removes the line at `_core.dm:229`. The AI keeps its own `posibrain_inside`, which is still set when it is first created from a core.

## Verification

After the change, with the same steps: `posibrain_inside` stayed 1, and `make_mmi()` returned `/obj/item/brain_processor/positronic` ("Android").

Not checked: the full player path (deconstructing the AI, the surgery and defibrillation steps); a posibrain AI uploaded to a terminal with no brain; the card and upload flow performed by hand rather than by procs.

## Notes

- This is a design call. If the maintainers regard the interaction as intended, the commit should be dropped. The fix takes the reopened-as-exploit reading.
- A side effect of the fix: the reverse direction also changes. An AI that is organic (made from an MMI or organic brain) and uploaded to a terminal holding a posibrain now stays organic, where before it would have become a posibrain AI. This direction was not tested.
- The fix does not stop the other parts of the original concern, such as swapping a living person's brain, which is a different mechanism.
