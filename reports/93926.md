# #93926: Shiny cytology mobs lose their colouration when held in hand and hovered over

| | |
|---|---|
| Issues | [#93926](https://github.com/tgstation/tgstation/issues/93926): verified, fixed |
| Status | Fixed (checked on the filter data, not on a rendered image) |
| Fix branch | [fix/93926](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/93926) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A held mob is wrapped in an `/obj/item/mob_holder` that copies the mob's appearance. The copy carries the mob's filters (the cytology "shiny mutation" colour shift is one) but not the `filter_data` and `filter_cache` lists that `add_filter()` rebuilds `filters` from. The first `add_filter()` on the holder, which is the item hover outline, replaced `filters` with a list that held only the outline, so the colour shift vanished. `update_visuals()` now copies the held mob's filter data into the holder.

## The bug

A mouse (or any other holdable mob) made "shiny" through cytology, whether painted or mutated, appears coloured when picked up. Hovering the mouse cursor over the held mob turns it back to its normal colour. The reporter could not show off their blue mutant-king rats because the rats "look brown when I point at them". The reporter also suspected this was a consistency issue rather than a real bug.

## Reproduction

1. On the test server, spawn a human and a mouse. With admin tools (the Lua editor), add a filter to the mouse the way the cytology code does: name `"shiny mutation"`, priority 15, a colour matrix filter in HSL space (`code/modules/research/xenobiology/vatgrowing/samples/_micro_organism.dm:154`). The mouse's colour was changed by the filter, as the cytology code intends.
2. Have the human pick up the mouse (`mob_pickup`), then take control of the human.
3. Hover the mouse cursor over the held mouse in the hand slot, so the item gets its hover outline.
4. Read `filter_data` and the number of `filters` on the held mob holder (View Variables).

Observed on master: `filter_data` contained only `hover_outline`, and there was 1 filter in `filters`. The "shiny mutation" filter was gone.

The held item was not rendered or compared as an image. The check is on the filter data, not on how the sprite looks.

## Cause

`update_visuals()` in `code/modules/mob/living/inhand_holder.dm:57-58` is:

```dm
/obj/item/mob_holder/proc/update_visuals(mob/living/held_guy)
	appearance = held_guy.appearance
```

Assigning `appearance` brings over the mob's visual `filters`, so the held mouse looks coloured at first. It does not set `filter_data` or `filter_cache` on the holder. These are the lists that `/datum/proc/add_filter()` keeps (`code/datums/datum.dm:63`, `:329-357`). `add_filter()` inserts the new filter into `filter_cache` and then assigns `atom.filters = filter_cache` (`datum.dm:353-357`). For the holder, `filter_cache` started empty, so after that assignment `filters` held only the new filter.

The item hover outline is applied with `add_filter(HOVER_OUTLINE_FILTER, 1, ...)` (`code/game/objects/items.dm:1213`). Mousing over a held item therefore overwrote the copied filters. This affects any filter on any held mob, not only cytology's. The shiny colour is the visible case.

## Fix

Commit "Fix issue 93926: mob holders keep the held mob's filters". `update_visuals()` now, after copying the appearance:

1. clears `filters`, `filter_data` and `filter_cache` on the holder,
2. calls `add_filter(name, priority, filter_info, update = FALSE)` for each entry in the held mob's `filter_data`,
3. assigns `filters = filter_cache` once, if any were added.

The holder then tracks the same filters the mob has, so later `add_filter()` and `remove_filter()` calls (the hover outline) work on the full set. This fixes the cause rather than special-casing the hover outline.

## Verification

On a build with the fix, the same steps were repeated (spawned human and mouse, "shiny mutation" filter on the mouse, pickup, hover):

- The holder's `filter_data` listed `hover_outline` and `shiny mutation`.
- After the cursor left the item and `hover_outline` was removed, `shiny mutation` was still on the holder (1 filter).

Not checked: the actual rendered colour of the held item (no screenshot or image comparison was taken), a mob that gets a real cytology mutation (a filter was added directly instead), other filters on held mobs, and holders other than a mouse picked up by a human.

## Notes

- The fix copies the filters once, when the holder is created or its visuals are updated. Filters added to the mob while it is held are not mirrored to the holder, as before the change.
- The holder's existing behaviour of copying `appearance` is unchanged.
