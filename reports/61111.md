# #61111: Husked bodies with robotic limbs can't be unhusked with synthflesh once burned

| | |
|---|---|
| Issues | [#61111](https://github.com/tgstation/tgstation/issues/61111): verified, fixed |
| Status | Fixed (verified on the test server) |
| Fix branch | [fix/61111](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/61111) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Synthflesh and rezadone refuse to unhusk a burn-husked carbon whose total burn damage is above `UNHUSK_DAMAGE_THRESHOLD` (50). That total includes burn damage on robotic limbs, but synthflesh only heals organic limbs, so on a body with robotic limbs the burn damage can never fall below the threshold and the husk stays. The fix counts only organic limbs' burn damage in the unhusk checks (synthflesh, rezadone) and in the two "burns need to be repaired first" warnings (synthflesh patch and medigel).

## The bug

The reporter augmented a husked crewmember and then could not unhusk them with synthflesh. Patching the body only printed "The liquid fails to properly stick on ... burns need to be repaired first!", and the only way out was to reattach an organic limb. The bug is not in augmenting itself: a robotic body that has no burn damage is unhusked normally. The block applies only when the body has burn damage over the threshold, which is common for a burn husk, and that damage sits on limbs synthflesh cannot touch.

## Reproduction

On master, as an observer with admin tools:

1. Using the Lua editor, spawn a human and replace all six limbs with `/obj/item/bodypart/{arm/left,arm/right,leg/left,leg/right,chest,head}/robot`.
2. Call `become_husk("burn")` on it and `adjust_fire_loss(300)`. (300 is well over the threshold of 50; the amount was not varied.)
3. Apply three synthflesh patches by calling the patch's `on_consumption` proc on the body. This calls the patch code directly, not a player's click.
4. Observed on master: each patch printed "The liquid fails to properly stick on R2. R2's burns need to be repaired first!" (six patches were tried) and the husk trait was never removed.
5. Control 1: the same setup with organic limbs and 300 burn. Patches printed "partially coats ...'s burns" and healed. The report records this as a working control; it does not say whether the organic body was fully unhusked, only that it healed.
6. Control 2: a robotic husk with no burn damage was unhusked by synthflesh via patch, TOUCH and VAPOR exposure (100u). So the block comes from the burn threshold alone.

## Cause

`code/modules/reagents/chemistry/reagents/cat2_medicine_reagents.dm:538` (synthflesh `expose_mob`):

```dm
//don't try to unhusk mobs above burn damage threshold
if(carbies.get_fire_loss() > UNHUSK_DAMAGE_THRESHOLD)
```

`get_fire_loss()` sums `burn_dam` over all bodyparts. Just above, synthflesh heals burn with `required_bodytype = affected_bodytype`, and `affected_bodytype` is `BODYTYPE_ORGANIC` by default (`code/modules/reagents/chemistry/reagents.dm:74`). Robotic limbs' burn damage is therefore never reduced, and the check can never pass while it exceeds 50.

The same pattern appears in three more places:

- Rezadone, `code/modules/reagents/chemistry/reagents/medicine_reagents.dm:260`: `patient.get_fire_loss() < UNHUSK_DAMAGE_THRESHOLD`.
- Synthflesh patch warning, `code/modules/reagents/reagent_containers/patch.dm:211`.
- Synthflesh medigel warning, `code/modules/reagents/reagent_containers/medigel.dm:131`.

The report notes that husking itself (`code/modules/mob/living/carbon/carbon.dm:439`) counts all limbs' burn damage.

## Fix

One commit, "Fix issue 61111: robotic limbs' burn damage no longer blocks unhusking with synthflesh or rezadone". It replaces `get_fire_loss()` with `get_fire_loss_for_type(...)` (an existing carbon proc that sums only bodyparts matching a bodytype) in all four places. Synthflesh and rezadone pass `affected_bodytype`; the patch and medigel warnings pass `BODYTYPE_ORGANIC`.

The reasoning is that a husk is flesh damage, and the threshold is meant to be a requirement the chemical can meet by healing. Damage it cannot heal should not count against it.

## Verification

On the test server with the fix, using the same Lua editor setup and calling the patch proc directly:

- Robotic husk with 300 burn and 3 synthflesh patches: the patches "partially mend" twice, then "coat R2's burns. R2 looks a lot healthier", and the husk trait was gone.
- Organic husk with 300 burn and 3 patches: still husked, as before the fix (no regression).

Not checked: rezadone, the patch and medigel warning messages, spraying or foam, a mixed body (some organic, some robotic limbs), and applying patches through real clicks rather than the proc call.

## Notes

- The reporter's other idea, that full augmentation should itself cure husking, is a balance decision and was not implemented.
- Comments on the issue say synthflesh sprays do not work and foam does. This work did not find a separate cause: TOUCH and VAPOR exposure of 100u unhusked a robotic body that had no burn damage. Sprays and foam were not tested directly.
- A body with mixed limbs now needs only its organic burn damage under 50. Robotic burn damage stays, and no longer affects whether the husk can be cured.
