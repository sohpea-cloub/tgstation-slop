## Summary

#92739: tackle gloves and Spider's Bite both added the same `/datum/component/tackler` to a mob. The component was `COMPONENT_DUPE_UNIQUE`, so they shared one instance, and taking the gloves off deleted it. The fix makes the component `COMPONENT_DUPE_SOURCES`, so the gloves and the martial art each hold their own source and the component goes away only when the last source does.

#97792: the strong arm implant's slam is handled on the early unarmed attack signal and cancels the attack chain, so martial arts never saw it. The fix adds an `H` to the current martial art's streak after a landed slam.

## #92739: tackle gloves remove Spider's Bite tackling

### The bug

A mob that has learned Spider's Bite can tackle. If they also wear tackle gloves and then take them off, they can no longer tackle, although they still know the art.

### Reproduction

1. In a running round, open the Lua editor as an observer.
2. Spawn a human, teach them `/datum/martial_art/spiders_bite`, and check for a `/datum/component/tackler` on them: present.
3. Equip a `/obj/item/clothing/gloves/tackler`: the component is present.
4. Make the human drop the gloves to the ground (`dropItemToGround`) and check again: the component was gone.

This was done by calling procs from Lua on a spawned human, not by a player wearing and removing gloves, but the proc path is the one the real equip and drop take.

### Cause

`code/datums/components/tackle.dm:15` set `dupe_mode = COMPONENT_DUPE_UNIQUE`. Both callers used `AddComponent`, so the second call returned the existing component:

- `code/datums/martial/spiders_bite.dm:17` (`activate_style`) stored the result in `tackle_comp`.
- `code/modules/clothing/gloves/tacklers.dm:43` (`equipped`) stored it in the gloves' `tackler` var.

In `dropped()` (`tacklers.dm:51`) the gloves called `QDEL_NULL(tackler)`, deleting the component the art was also relying on. The issue's comment notes that `COMPONENT_DUPE_UNIQUE` looked safe, which is why this was easy to miss.

### Fix

Commit "Fix issue 92739: tackle gloves no longer remove Spider's Bite tackling":

- `tackle.dm`: `dupe_mode` is now `COMPONENT_DUPE_SOURCES`.
- `tacklers.dm`: the gloves use `AddComponentFrom(REF(src), ...)` on equip and `RemoveComponentSource(REF(src), ...)` on drop. The `tackler` var and the `Destroy()` that cleared it were removed.
- `spiders_bite.dm`: the art uses `AddComponentFrom(REF(src), ...)` and `RemoveComponentSource(REF(src), ...)`. The `tackle_comp` var was removed.
- `tackle.dm`: an `on_source_add` override on the tackler that takes the same named arguments as the component's `Initialize` and calls the parent. Without it, the first test build logged `runtime error: bad arg name 'stamina_cost'` in `on_source_add`, because named arguments passed through `AddComponentFrom` must exist on that proc.

The sources approach was chosen over keeping a unique component with manual reference counting because the codebase already has the source mechanism (`AddComponentFrom` is used elsewhere, for example in `usb_port.dm` and `golem_food.dm`).

### Verification

After the final build, using Lua on spawned humans:

- Art first, then gloves on and off: the component stayed after the drop and was removed when the art was unlearned.
- Gloves first, then the art: unlearning the art kept the component; dropping the gloves removed it.
- Gloves only: equip added it, drop removed it.

The round's `runtime.log` had no runtime errors after the final build.

Not checked: a player actually tackling after these sequences, and the other glove variants (dolphin, combat, rocket), which inherit from the same type.

## #97792: strong arm slam does not count toward martial art combos

### The bug

With a strong arm implant and a martial art, the implant's slam does not count as the first hit of a combo.

### Reproduction

1. In the Lua editor, spawn two humans (both given the `never_wounded` trait for the test). Teach the first `/datum/martial_art/plasma_fist`, insert a `/obj/item/organ/cyberimp/arm/strongarm`, and set combat mode on.
2. Swap the first human's active hand to the implant arm and call `UnarmedAttack` on the other human.
3. The chat said the target was "bashed" and the art's `streak` stayed `""`. A first attempt, with the implant arm not active, gave a normal punch and the streak became `H`, which is the expected behaviour for a punch.

### Cause

In `code/modules/surgery/organs/internal/cyberimp/augments_arms.dm`, the implant registers `on_attack_hand` (line 458) on `COMSIG_LIVING_EARLY_UNARMED_ATTACK` (line 426) and returns `COMPONENT_CANCEL_ATTACK_CHAIN` (line 563) after a slam. Martial arts react to `COMSIG_LIVING_UNARMED_ATTACK`, which comes later in the chain and so never fired.

### Fix

Commit "Fix issue 97792: strong arm slam counts toward the martial art combo streak": after the slam lands and is logged, take the first entry in `source.martial_arts` and, if it `can_use` the user, the target does not have `TRAIT_MARTIAL_ARTS_IMMUNE`, and the user is not a pacifist (unless the style has `pacifist_style`), call `add_to_streak("H", target)`.

It deliberately does not call `check_streak`, so a combo that would complete on the slam itself does not fire; the slam only adds to the streak and the next normal punch can complete it. This is limited by the slam's 5 second cooldown on human targets.

### Verification

With the implant arm active:

- plasma fist: slam gave streak `H`, the next punch `HH`.
- CQC: the slam gave `H`, and the following punch triggered a combo (the "kicks ... back" message) and reset the streak.

Not checked: other martial arts, the pacifist and martial-arts-immune branches, and slams on non-human targets. The commit was first tested on a build that did not yet have the `on_source_add` override from the other fix; the final build contained both and the sequence for #92739 was re-run on it, but #97792 was not re-run on that final build.

## Notes

- A slam that would complete a combo does not fire it. If maintainers want the slam to be able to finish a combo, the fix would also need `check_streak`.
- The two fixes are independent; they were worked together because both concern martial arts.
