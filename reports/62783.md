## Summary

The two issues were looked at together because both involve the crafting component. In #62783, the "You can't craft X without a pipe fitting!" spam no longer exists in the code, and the notes say it was removed upstream by PR #62796. Pipe-fitting recipes could still fail with "missing component" when any other pipe fitting lay within reach, because they only inspected the first nearby pipe. In #87240, crafting counted any item with a `tool_behaviour`, so a welding tool or lighter with no fuel satisfied `TOOL_WELDER` recipes. The branch has one commit for each issue.

## The bug

### #62783

The report (written in 2021) describes chat spam of "You can't craft ... fitting without a pipe fitting!" lines after crafting and using several pipes, and the H/E pipe fitting recipe either greyed out or failing with "Construction failed, missing component."

On current master the spam string does not exist. Pipe fittings are made by `/datum/crafting_recipe/spec_pipe` recipes, which need a smart pipe. The failure that remains is that these recipes fail with `, missing component.` when a non-smart pipe fitting lies near the crafter, even with a smart pipe, an iron sheet, a wrench and a fueled welder also present. This fits the report's "after creating and using a bit more pipes they begin to be broken" and the H/E "missing component" error. The cause of the original spam was not examined further.

### #87240

An empty welding tool is accepted as the welder for recipes that need `TOOL_WELDER` (the report's example is the chainsaw). The crafting menu offers the recipe and crafting it works.

## Reproduction

Both were reproduced through the crafting component's procs called from the Lua editor, not by using the crafting menu in the UI.

### #62783

1. Using the Lua editor, spawn a human, a smart pipe fitting, a non-smart `/obj/item/pipe` (for example a layer adapter fitting), an iron sheet, a wrench and a fueled welding tool within one tile of the human. Spawn the non-smart pipe before the smart one.
2. Call `perform_all_checks` on the H/E pipe fitting recipe for that human.

Observed on master:

- With the non-smart pipe lying nearby, the check returned `, missing component.`
- With only the smart pipe present, the check passed.

### #87240

1. Using the Lua editor, spawn a human and a welding tool beside them, and clear its reagents so it is empty.
2. Call `get_surroundings` on the crafting component for that human and read the `tool_behaviour` entry for the welder.

Observed on master: the welder entry was 1 for the empty tool. With fuel it was also 1. An empty welding tool therefore satisfied welder requirements.

## Cause

### #62783

`/datum/crafting_recipe/spec_pipe/check_requirements` (`code/datums/components/crafting/atmospheric.dm:49`) only tested the first collected pipe:

```dm
var/obj/item/pipe/required_pipe = collected_requirements[/obj/item/pipe][1]
if(ispath(required_pipe.pipe_type, /obj/machinery/atmospherics/pipe/smart))
	return TRUE
return FALSE
```

If the first pipe was not a smart pipe, the recipe failed, even when a smart pipe was also in reach. Consumption had the same problem. `get_used_reqs` (`code/datums/components/crafting/_crafting.dm:476`) took `locate(path_key) in surroundings`, the first item of that path, so the item consumed was not necessarily the smart pipe that passed the check.

### #87240

`get_surroundings` (`code/datums/components/crafting/_crafting.dm:174`) records a tool whenever `item.tool_behaviour` is set. This is done in two loops (lines 185 and 214). `weldingtool.dm:29` and `lighter.dm:19` set `tool_behaviour = TOOL_WELDER` regardless of fuel, so an empty one counts as a welder.

## Fix

Two commits on `fix/62783`:

**"Fix issue 87240: empty welding tools and lighters no longer count as welders for crafting"**

- Adds `/obj/item/proc/can_be_crafting_tool()` in `items.dm`, returning TRUE by default.
- `weldingtool.dm` and `lighter.dm` override it to return `get_fuel() > 0`.
- Both loops in `get_surroundings` now require `can_be_crafting_tool()`, so an item must pass it as well as have a `tool_behaviour`.
- This keeps the question "does this item count as a tool right now" with the item. The welder does not have to be turned on, which is unchanged.

**"Fix issue 62783: pipe fitting recipes pick the smart pipe among nearby pipes"**

- `spec_pipe/check_requirements` now loops over every collected pipe and passes if any is a smart pipe.
- A new `/datum/crafting_recipe/proc/is_valid_requirement(candidate, requirement_path)` in `_recipes.dm` defaults to TRUE. `spec_pipe` overrides it so that, for `/obj/item/pipe`, only a smart pipe is valid.
- `get_used_reqs` now walks the surroundings and takes the first item that matches the path and is valid, instead of the first item of that path. The recipe consumes the smart pipe that passed the check and leaves other fittings alone.
- The hook is generic, so other recipes that care about a variable on the item can use it too.

## Verification

Verified on a rebuilt test server, through Lua calls to the crafting procs.

- #62783: with a layer adapter fitting and a smart pipe nearby (the adapter spawned first), `construct_item` for the H/E pipe fitting recipe returned "4-way pipe manifold fitting". The smart pipe was consumed and the adapter fitting was left. The `do_after` was skipped for this test by setting the component's `ignored_flags` to 512.
- #87240: for the chainsaw recipe with an empty welding tool, the check returned `, missing tool.` After adding 20 units of fuel, `construct_item` returned "the chainsaw" and an `/obj/item/chainsaw` existed. On master the empty welder passed.

Not checked:

- The crafting menu UI for either issue, including the greyed-out entry mentioned in the report.
- Lighters. The override is the same as for the welding tool, but only the welding tool was tested.
- Other recipes that use `TOOL_WELDER`, or other users of `get_surroundings`.
- The original spam message. It was confirmed absent from the source, not observed in game.

## Notes

- PR #62796 was named in the notes as the upstream change that removed the spam message. It was not examined further. The notes also say the pipe recipes were later reworked into the `spec_pipe` recipes.
- `is_valid_requirement` only filters which instance is consumed. Required amounts are still counted by path, so a recipe could pass the count with items its filter would reject. For the pipe recipes this is covered by `check_requirements`.
- Adding a proc to `/obj/item` for the tool check is a design choice. An alternative would be to check the welder's fuel inside crafting code, but that would put item-specific logic in the crafting component.
