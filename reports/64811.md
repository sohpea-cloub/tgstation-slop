# #64811: Reagents that force movement can steer you in zero G with nothing to push off

| | |
|---|---|
| Issues | [#64811](https://github.com/tgstation/tgstation/issues/64811): verified |
| Status | Verified, fixed |
| Fix branch | [fix/64811](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/64811) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Several reagents (space drugs, meth and bath salts overdoses, bath salts, mercury, lithium) and the spasms status effect move the victim by calling `step()` directly. `step()` never checks `Process_Spacemove`, so a mob in a no-gravity area with nothing to push off still walks around. The fix adds `/mob/living/proc/involuntary_step()`, which checks `Process_Spacemove` first, and uses it at all eight call sites.

## The bug

A player who took one of these reagents while gravity was off (the issue's example: a suspicious pill from maintenance, then the gravity generator going out) kept changing direction and moving as if they were walking on a floor, although they were floating with nothing adjacent to push off. Normal voluntary movement is correctly blocked in that situation.

## Reproduction

Done on the test server with the Lua editor, in a hallway of the station.

1. Added the `NO_GRAVITY` flag (16384) to the area's `area_flags` so the area had no gravity.
2. Confirmed with the Lua editor that `Process_Spacemove` returned 0 for directions 2, 4 and 8 for a human there (`has_gravity` was 0).
3. Gave a human lithium (a later run used lithium plus bath salts) and let it metabolize.
4. Observed: on master the lithium human moved from (107,144) to (113,145) in about 30 seconds with gravity off and nothing to push off.

This was reproduced through the reagent effect itself, not by calling procs directly. The bug was not reproduced with the exact trigger from the issue (a pill found in maintenance), but the cause is the same code path.

## Cause

The reagents call `step()` directly:

```dm
step(affected_mob, pick(GLOB.cardinals))
```

Locations at master:

- `code/modules/reagents/chemistry/reagents/drug_reagents.dm`: lines 26 (space drugs), 218, 270, 271 and 278 (meth and bath salts, including the overdose loops)
- `code/modules/reagents/chemistry/reagents/other_reagents.dm`: line 1065 (mercury) and 1177 (lithium)
- `code/datums/status_effects/debuffs/debuffs.dm`: line 758 (spasms)

`step()` goes to `Move()`, which does not call `Process_Spacemove`. Only the client movement path does (`code/modules/mob/mob_movement.dm:94`, `if(!mob.Process_Spacemove(direct))`). So these effects ignore the "no gravity and nothing to push off" rule that applies to players walking.

## Fix

The commit "Fix issue 64811: involuntary reagent steps no longer move you in zero G":

- adds `/mob/living/proc/involuntary_step(direction)` in `code/modules/mob/living/living_movement.dm`. It returns FALSE if `Process_Spacemove(direction)` fails, otherwise returns `step(src, direction)`;
- changes the eight call sites listed above to `involuntary_step(pick(GLOB.cardinals))`.

A shared helper was used rather than a check at each site so the rule is defined once, and so new involuntary movement can use it. If there is gravity, or a wall, lattice or other object to push off, `Process_Spacemove` passes and the step still happens, as before.

## Verification

After rebuilding and restarting the test server, the same setup was used: no-gravity area, a human with lithium and bath salts both metabolizing (lithium 30 to 22.8 units, bath salts 30 to 26.4). The human stayed at (107,144) for about 35 seconds, and emotes from the reagents still fired. As a control, the no-gravity flag was removed from the area and the same mob moved from (107,144) to (125,141) in about 12 seconds, showing the steps still work with gravity.

Not checked: mercury, plain space drugs, the meth overdose and the spasms effect were not run individually in game (they use the same helper, but were verified only by code reading). Having something adjacent to push off was not tested in game.

## Notes

- Other random-step sources were not changed: the electropack, voice of god and `flesh.dm`. Whether they should also respect zero G is a separate decision.
- In the mercury effect, the condition reads `HAS_TRAIT(src, TRAIT_IMMOBILIZED)` where `src` is the reagent, not the mob (`other_reagents.dm:1064`). This looks like an existing bug and was not changed here.
- In the diff, the new proc's doc comment sits between the existing `/// Living Mob use event based gravity` comment and `gravity_setup()`, so that comment is now detached from the proc it describes. A maintainer may want to move it.
