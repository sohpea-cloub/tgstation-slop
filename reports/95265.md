# #95265: Blood worms can drink their own host's blood to grow infinitely

| | |
|---|---|
| Issues | [#95265](https://github.com/tgstation/tgstation/issues/95265): verified, fixed (tested by calling procs, not through the real leech action) |
| Status | fixed, fix committed |
| Fix branch | [fix/95265](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/95265) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A blood worm inside a host has real, extractable blood. The worm could draw that blood with a syringe or IV drip into a container and leech the container, and all of it counted toward growth, so it could mature without limit. The fix tags blood taken from a blood worm host with an `unusable_content` ratio (1 for the host itself), carries and averages that ratio wherever the existing synthetic-blood ratio is carried, and makes `consume_blood()` add no growth for the unusable part. Unusable blood still heals the worm.

## The bug

As described in the issue: a blood worm in a host can extract its own host's blood into a container with a syringe or IV drip and drink it with its leech action. The blood counts toward growth, so repeating this matures the worm and lets it reproduce without feeding on anyone else. The reporter noted that simply making the host's blood synthetic would not be enough, since synthetic blood still grows the worm up to a cap that is above what a juvenile needs.

## Reproduction

Reproduced through the Lua editor, as an observer. The extraction and consumption procs were called directly. The real leech action was not used (it needs a client-controlled worm and a `do_after`).

1. Started a round and spawned a human and a hatchling blood worm.
2. Put the worm in the host with `worm:enter_host(host, true, false)`.
3. Spawned a beaker and called `host:transfer_blood_to(beaker, 50)`, which is what syringes and IV drips call.
4. The extracted 50u had no unusable flag in its blood data (the synthetic content was `null`).
5. Called `worm:consume_blood(50, synth)` with the data from that blood, as the leech action does for a container. The worm's consumed blood (growth) went from 0 to 50: the loop is possible.

## Cause

- Hosts' blood is normal blood. `/mob/living/proc/transfer_blood_to()` (`code/modules/mob/living/blood.dm:370`) and `get_blood_data()` (`blood.dm:433`) treat it like any other mob's blood. The worm's health is merged into the host's blood volume (`code/modules/antagonists/blood_worm/blood_worm_host_handling.dm`).
- `consume_blood()` (`code/modules/antagonists/blood_worm/blood_worm_blood_consumption.dm:4`) credits all consumed blood to growth, except for the synthetic share, which is reduced by `synth_blood_efficiency` and capped by `maximum_synth_blood`.
- The only marker that existed was `BLOOD_DATA_SYNTH_CONTENT`. It does not stop the loop: the cap (as the notes state, 1000 times 0.7) is more than the 500 that a juvenile needs.

## Fix

One commit, **Fix issue 95265: blood worms can no longer grow off of their own host's blood**.

- New `BLOOD_DATA_UNUSABLE_CONTENT` define (`code/__DEFINES/blood.dm`), a 0-1 ratio in blood data like the synthetic one.
- New `/mob/living/proc/get_blood_unusable_content(ignore_worm_host)` (`blood.dm`). It returns 1 for a mob with `TRAIT_BLOOD_WORM_HOST`, and otherwise the value held by the `synth_blood` component. `get_blood_data()` now stores a non-zero value in the blood data.
- The `synth_blood` component (`code/datums/components/synth_blood.dm`) now also holds `unusable_content` and decays it with the synthetic content (over ten minutes). It is removed only when both are 0. `InheritComponent` now returns after qdeleting itself.
- Mixing: `blood_reagent` `on_merge` (`code/datums/elements/blood_reagent.dm`) takes a volume-weighted average, as it does for the synthetic ratio.
- Transfusion and injection (`transfer_blood_to` in `blood.dm`, and the injection code in `code/modules/mob/living/carbon/life.dm`): the unusable ratio of the incoming blood is averaged into the receiver's component. Neither path does this for a receiver that is itself a blood worm host.
- `consume_blood()` takes an `unusable_content` argument and scales growth by `1 - unusable_content`. The worm is still healed.
- The leech action (`code/modules/antagonists/blood_worm/actions/leech_blood.dm`, for living targets and containers) passes the ratio through and shows a balloon alert ("unusable for growth", or "N% unusable for growth"). The growth preview text in `blood_worm_text_feedback.dm` accounts for the ratio.
- `enter_host` passes `get_blood_unusable_content(ignore_worm_host = TRUE)` so that the host trait set on entry does not zero out the blood the worm eats as it enters.

The approach follows the reporter's suggestion of a second ratio next to the synthetic one, reusing the existing synthetic-blood plumbing.

## Verification

After a rebuild and restart, with the same scripts:

- The 50u extracted from the host had `unusable_content` = 1 in its data. `consume_blood` with it changed growth from 0 to 0.
- Control: 50u of an ordinary human's blood changed growth from 0 to 50.
- Laundering check: `host:transfer_blood_to(depleted human with 300u, 100u)` left that human at `get_blood_unusable_content()` = 0.25 (100 of 400), so injecting the extracted blood into someone else and leeching them does not bypass the rule; the unusable portion is weighted.
- No runtimes came from the changed code (one runtime came from a mistaken line in the test script).

Not checked: the real leech action with a client-controlled worm (living target and container); the real syringe and IV drip interactions; the balloon alert text and growth preview text; the decay over time; blood types with their own handling.

## Notes

- **Design change.** The fix adds a new field to blood data and spreads it through several blood transfer paths (extraction, mixing, transfusion, injection, the component). Maintainers should weigh whether this is the approach they want, as the reporter asked that antagonist behaviour not change unintentionally.
- **Unusable blood still heals the worm.** The result is a neutral loop: extracting costs the host/worm health and drinking restores it, with no growth. If that should not heal, the `should_heal` path needs a change.
- The `mix_virus` duplication code (in `others.dm`) was left unchanged; it keeps the unusable fraction proportionally.
- A worm entering a host still gains growth from the host's starting blood, except for any unusable portion that blood already had.
