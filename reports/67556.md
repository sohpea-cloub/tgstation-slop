# #67556: Shot glasses and drinking glasses splash the target even when caught

| | |
|---|---|
| Issues | [#67556](https://github.com/tgstation/tgstation/issues/67556): verified, fixed |
| Status | Fixed |
| Fix branch | [fix/67556](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/67556) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A thrown reagent container splashes its contents on the person it was thrown at even when that person catches it in throw mode. `/obj/item/reagent_containers/throw_impact()` stores whether the throw was caught (the return of `..()`) but then splashes unconditionally. The fix skips the splash when the throw was caught.

## The bug

Throwing a shot glass of pepper spray (or acid, or similar) at someone who is in throw mode: they catch the glass, and are splashed with the contents anyway. The reporter notes this makes such glasses uncatchable, and effectively a free knockdown weapon. The second comment on the issue correctly notes that the glass itself does not smash when caught, so only the splash was wrong.

## Reproduction

Done with the Lua editor by spawning the mobs and throwing the item directly.

1. Spawn two humans. Turn throw mode on for the target (`throw_mode_on`).
2. Spawn a shot glass containing 10 units of condensed capsaicin and throw it at the target.
3. Read the chat log.

Before the fix: "X catches the filled shot glass!" was followed by "X is splashed with something!".

## Cause

`/obj/item/reagent_containers/throw_impact()` (`code/modules/reagents/reagent_containers.dm:223`):

```dm
/obj/item/reagent_containers/throw_impact(atom/hit_atom, datum/thrownthing/throwingdatum, do_splash = TRUE)
	. = ..()
	if(do_splash)
		splash_reagents(hit_atom, throwingdatum?.get_thrower(), was_thrown = TRUE, allow_closed_splash = FALSE)
```

`..()` returns true when the hit atom caught the item. The glass subtype handles this already: `/obj/item/reagent_containers/cup/glass/throw_impact()` (`code/modules/reagents/reagent_containers/cups/drinks.dm:15`) only calls `smash()` when `!.`. The base container ignores `.` and splashes every time, so all reagent containers behave the same way, not just shot glasses.

## Fix

One commit, "Fix issue 67556: caught reagent containers no longer splash their catcher", changes the condition in `reagent_containers.dm` to `if(do_splash && !.)`, with the comment "caught items don't splash their catcher". This mirrors the glass handling.

## Verification

After rebuilding, the same throw printed only "catches the filled shot glass!" with no splash. Uncaught throws (throw mode off) of a shot glass and of a beaker still hit and splashed ("is splashed with something!" for each).

Not checked: bottles and other `cup/glass` subtypes, emptiness/closed-container cases, and non-human catchers.

## Notes

- Behavior change beyond catching: any `hitby()` override that returns true now also suppresses the splash (for example a shield block or a disposal bin). The agents who looked at these thought this was intended. A maintainer may want to confirm.
- One could argue that a catch should still splash some of the contents (the second comment calls the old behavior sensible: "whatever was in the container can and will splash over"). The fix takes the view in the report, that a catch should be safe. That is a design choice.
- The first comment suggests the behavior might come from #65698; this was not checked.
