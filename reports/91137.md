## Summary

A scanner gate creates its scanline overlay object lazily and never gives it the gate's direction, so a gate that has a non-south direction when the scanline is first created shows a south-facing scanline. Later direction changes were already propagated. The fix adds one line, `scanline.setDir(dir)`, to the creation branch of `set_scanline`.

## The bug

The issue contains only a screenshot (not reproduced here) of a scanner gate whose scanline does not match the gate's orientation. A gate mapped or spawned facing a direction other than south draws its scanline facing south until something rotates the gate.

## Reproduction

The mapped gates on the test map (Meta) were both facing south (dir 2), so a naturally mapped non-south gate was not available. The condition was simulated:

1. On the test server, using the Lua editor, take a mapped scanner gate.
2. Set its `dir` to 4 directly (not through `setDir`, so the existing propagation does not run), and set its `scanline` variable to null.
3. Call `set_scanline("passive")`, which is exactly what `Initialize` does.

Observed on master: the gate's dir was 4 and the newly created scanline's dir was 2.

This is a simulation by calling the proc, not a gate spawned or mapped with a non-south direction.

## Cause

`set_scanline` in `code/game/machinery/scanner_gate.dm` (around lines 124-132) creates the overlay with `scanline = new(src)`, which gives it the default south direction, then sets only `icon`, `mouse_opacity` and `layer`. The gate's `setDir` override (line 103-105) forwards later direction changes with `scanline?.setDir(newdir)`, but at the time a mapped gate's `Initialize` calls `set_scanline("passive")` (line 86) the scanline does not exist yet, so the initial direction is never applied.

## Fix

Commit "Fix issue 91137: scanner gate scanline overlay now takes the gate's direction when created" adds `scanline.setDir(dir)` after `scanline.layer = layer` in the creation branch of `set_scanline`.

## Verification

After rebuilding and repeating the simulation, the gate's dir was 4 and the new scanline's dir was 4.

Not checked: any rendered or visual output, a gate actually mapped or spawned facing a non-south direction, and the scanning and alarm scanline states in game.
