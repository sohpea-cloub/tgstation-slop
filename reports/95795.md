# #95795: Forced kisses (circuit speech) bypass the kiss emote cooldown

| | |
|---|---|
| Issues | [#95795](https://github.com/tgstation/tgstation/issues/95795): fixed (for the kiss emote only) |
| Status | Fixed for kisses; verified through the same call the circuit makes, not with a built BCI |
| Fix branch | [fix/95795](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/95795) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Emotes that are forced skip the emote cooldown check entirely, and circuit speech components say their text as "forced". A BCI with a speech component that says `*kiss` therefore ignores the kiss emote's 3 second cooldown and is limited only by the component's own 1 second cooldown. With Syndicate lipstick each kiss is a ranged projectile, so this lets a wearer fire one every second. The fix makes the kiss emote always enforce its cooldown, forced or not. Other forced emotes still bypass cooldowns.

## The bug

The issue reports that with the force-say BCI circuit, emotes (including the Syndicate lipstick kiss) have "0 cooldown" and can be spammed infinitely fast. Commenters corrected this: the rate is not literally unlimited, because the speech component has a 1 second cooldown of its own. The kiss is the only emote that creates a ranged projectile, so it is the one where this matters, and several people spamming kisses is also a source of server lag. A comment notes that every emote is cooldown-free when forced. Another comment (on the Northstar gloves) is unrelated to this unit.

## Reproduction

The BCI and circuit were not built. The same call the speech component makes was issued directly from the Lua editor.

1. On the test server, spawn a human and give it the `syndie_kiss` trait (the trait Syndicate lipstick applies) and `never_wounded`.
2. In the Lua editor, call `say('*kiss', ...)` on that human four times in a row, with the `forced` argument set to `"circuit speech | test"` (the string format the speech component uses).
3. Look at the human's hands.

Result on master: both hands held "the syndie kiss". The second kiss was created even though the emote has a 3 second cooldown.

Control: the same four calls without `forced` (a normal `*kiss`) produced only one kiss.

## Cause

- `check_emote()` (`code/modules/mob/mob_say.dm:165`) turns a `*emote` message into `emote(..., intentional = !forced)`. A forced say is therefore a non-intentional emote.
- The speech component (`code/modules/wiremod/components/action/speech.dm:37`) says its message with `forced = "circuit speech | [creator]"`. Its own limit is `speech_cooldown`, 1 second (line 18).
- `/datum/emote/proc/check_cooldown()` (`code/datums/emotes.dm:251`) returns TRUE immediately when `intentional` is false (lines 256-257), before it looks at or records `emotes_used`:

  ```dm
  if(!intentional)
  	return TRUE
  ```

- The kiss emote sets `cooldown = 3 SECONDS` (`code/modules/mob/living/emote.dm:269`), but that value is only enforced for intentional use. Each non-blocked kiss emote creates a new `hand_item/kisser`; with the Syndicate kiss trait that is the `/obj/projectile/kiss/syndie` version.

So the effective limit for a circuit-driven kiss is the circuit's 1 second, not the emote's 3 seconds.

## Fix

One commit, "Fix issue 95795: forced kisses (circuit speech) respect the kiss emote cooldown". In `code/modules/mob/living/emote.dm` it adds an override on the kiss emote:

```dm
/datum/emote/living/kiss/check_cooldown(mob/user, intentional)
	return ..(user, TRUE)
```

Passing `TRUE` makes the parent proc apply and record the cooldown even for forced kisses. The parent's `COMSIG_MOB_EMOTE_COOLDOWN_CHECK` bypass (used for example for acrobatics) still applies, because the parent handles it.

A narrow fix was chosen because forcing emotes to skip cooldowns appears to be deliberate in general (hypnosis and similar effects force emotes). A comment on the issue proposes distinguishing "forced forced" from "technically forced" (circuit) sources, but that needs a new marker on the forced argument and was not attempted.

## Verification

On the test server after the fix, the same four forced `*kiss` calls left the active hand holding "the syndie kiss" and the other hand empty. After the kiss was deleted and about 7 seconds passed, a forced kiss worked again. The build had no compile errors or warnings.

Not checked: a real BCI with a speech component, a real tube of Syndicate lipstick, other kiss variants (garlic breath, chef's kiss) and other forced emotes. The runtime log was not reviewed beyond the build.

## Notes

- A forced kiss that is on cooldown now prints "You must wait another N" to the user, the same message a manual kiss prints.
- Other forced emotes still bypass their cooldowns when used from circuit speech. Only the kiss makes a ranged projectile, but other emotes could be spammed at 1 per second as well. A general fix would need the forced-versus-circuit distinction mentioned above.
- The 1 second figure from the comments is right: the problem is a 1 second rate instead of the emote's 3 seconds, not zero cooldown. The comment that stacking speech components in circuit modules once allowed faster firing was not investigated.
- Whether Syndicate lipstick should also have a resource cost or limit on how many people it can be applied to (suggested in the comments) is a design question and was not addressed.
