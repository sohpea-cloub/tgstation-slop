# #97604: The singularity does not eat asteroid sand

## Summary

The singularity never removed asteroid sand turfs. Sand's `baseturfs` is itself, and `ScrapeAway()` deliberately does nothing for a turf whose baseturf is its own type, so the singularity's consume step left it untouched. The fix adds a `singularity_act()` override on `/turf/open/misc/asteroid` that, on station levels, replaces such sand with space; sand on non-station levels (for example Lavaland) is left alone.

## The bug

The reporter saw the singularity pass over asteroid sand and leave it intact while eating the rest of the station, noticed on KiloStation only. The sand stayed as a floor in the middle of the destroyed area.

## Reproduction

The test was done with admin tools on a private server on a default station map, not on KiloStation.

1. Using the Lua editor, created a `/turf/open/misc/asteroid/airless` turf and set its `baseturfs` to its own type, as mapped sand has.
2. Called `singularity_act()` on it.
3. Result on master: the turf stayed `/turf/open/misc/asteroid/airless` and the call returned 2 (the singularity gained energy, but nothing was eaten).

A real singularity's `consume()` was used for the after-fix test only; before the fix the reproduction was by the direct `singularity_act()` call.

## Cause

`/turf/singularity_act()` (`code/game/turfs/turf.dm:554`) removes a turf by calling `ScrapeAway(flags = CHANGETURF_INHERIT_AIR)` and returns 2. `ScrapeAway()` ends with:

```dm
if(baseturfs == type)
	return src

return ChangeTurf(baseturfs, baseturfs, flags) // The bottom baseturf will never go away
```

(`code/game/turfs/baseturfs.dm:18`). Asteroid sand is declared with `baseturfs = /turf/open/misc/asteroid` (`code/game/turfs/open/asteroid.dm:8`), i.e. its own type, so it is treated as a "bottom" turf and `ScrapeAway()` returns it unchanged. Nothing lies beneath it, so nothing is revealed.

## Fix

One commit, "Fix issue 97604: the singularity now eats asteroid sand on station levels", adds this to `code/game/turfs/open/asteroid.dm`:

```dm
/turf/open/misc/asteroid/singularity_act()
	. = ..()
	if(baseturfs == type && !QDELETED(src) && is_station_level(z))
		ChangeTurf(/turf/open/space/basic, flags = CHANGETURF_INHERIT_AIR)
```

After the normal behaviour (which keeps the return value and handles anything on the turf), a sand turf that is its own baseturf and is on a station level becomes `/turf/open/space/basic`, inheriting air.

Choices: the change is on the asteroid type, not in `ScrapeAway()` or the base turf code, because the "bottom baseturf never goes away" rule is relied on elsewhere. Restricting it to station levels keeps Lavaland and other off-station sand from being turned into space, where space would be wrong (and, on Lavaland, atmosphere-breaking).

## Verification

After rebuilding and starting a new round, a real `/obj/singularity` `consume()` was called on hand-placed sand:

- on a station level: the sand became `/turf/open/space`;
- on a non-station level: it stayed `/turf/open/misc/asteroid/airless`.

Not checked: KiloStation itself, or a singularity actually moving across sand (the check used `consume()` on a placed turf); whether KiloStation's sand is mapped with the same self-referencing baseturf (assumed, not confirmed); sand subtypes beyond the `airless` one used; and what happens to adjacent atmosphere when the sand turns to space.

## Notes

- The override applies to every `/turf/open/misc/asteroid` subtype that is its own baseturf, so any station-level sand in other maps will now also be eaten, which is the intended behaviour.
- Sand with a different baseturf (for example a dug turf over something else) is unchanged: it goes through the normal `ScrapeAway()` path.
- A mined or dug sand turf on a station was not tested.
