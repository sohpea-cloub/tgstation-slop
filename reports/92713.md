# #92713: Mass VV of a new list does not work

| | |
|---|---|
| Issues | [#92713](https://github.com/tgstation/tgstation/issues/92713): verified, fixed |
| Status | Fixed on the branch; the "Many" option was verified in game, the "One" option was not re-run after the fix |
| Fix branch | https://github.com/sohpea-cloub/tgstation-slop/tree/fix/92713 |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When mass-editing a variable with "New List", the code handled the list as if it were a new datum type (`/list`). Choosing "Many" gave every target an empty list, and choosing "One" assigned the list to the first target only, leaving the rest null. The fix makes "Many" give each target its own copy of the populated list and "One" assign the same list to every target.

## The bug

The reporter wrote that mass VV of a new list with items "either sets the variable to null or sets it to an empty list, depending on whether you select one list or many". In the issue thread a maintainer asked what "one list or many" meant. It refers to the One / Many question the mass edit asks after the list has been built.

## Reproduction

1. On the test server, open the Lua editor and spawn crowbars, then open View Variables on one.
2. Use the "M" (mass edit) link beside `actions` (a variable that is null by default). Answer "Yes" to the warning, pick "Strictly this type", and choose the variable type "New List".
3. Populate the list ("Yes"), add one text entry "hello", and finish the list.
4. Choose One or Many when asked.
5. Check the result with SDQL2: `SELECT /obj/item/crowbar WHERE actions != null`.

Observed on master:

- **One:** SDQL2 reported "148 selected by path, 1 executed on" while 76 crowbars had been edited. Only the first thing got the list, and the others stayed null.
- **Many:** every thing received an empty list (read from the code; see Cause). The Many case was not separately run in game before the fix.

## Cause

In `code/modules/admin/view_variables/mass_edit_variables.dm`, the mass edit sets `class = VV_NEW_TYPE` whenever the chosen value has a `type` (line 90). The "New List" option in `vv_get_value` sets `type` to `/list` (`code/modules/admin/view_variables/get_variables.dm:297`), so a list is handled by the new-datum branch (line 143 onward). That branch assumes the value is a datum that was created while asking:

```dm
if(many && !new_value)
    new_value = new type()
...
if (D.vv_edit_var(variable, new_value) != FALSE)
...
new_value = null
```

- **Many:** `new_value` is nulled after every iteration, so for each thing `new type()` is run, which for `/list` is an empty list. The populated list is thrown away.
- **One:** the prepared value is used for the first thing and then `new_value = null` is set, so every later thing gets null.

## Fix

Commit "Fix issue 92713: mass VV of a new list gave nothing", in `mass_edit_variables.dm`. Each iteration now computes its own `item_value`:

- **Many, value is a list:** each thing gets `new_value:Copy()`, so the things do not share one list.
- **Many, value is a datum:** the first thing gets the datum made while asking, the others a fresh `new type()`, as before.
- **One:** every thing gets the same `new_value`. The nulling after each iteration was removed.

Copying is done only for lists, since a shared list would let an edit to one target change them all.

## Verification

After rebuilding and restarting, the same steps were run with "Many". `SDQL2` with `WHERE actions != null` mapped to `actions` showed that all 78 crowbars of the strict type had `["hello"]`. No other results were recorded.

Not checked: "One" after the fix. The change for it is that `item_value` is `new_value` for every thing. Mass edits of other new datum types (the `new type()` path) and mass edits with "This type and subtypes" were also not re-run.

## Notes

- The "One" case shares a single list between all targets, which follows from "One" in the prompt ("create only one ... and assign each"). If an edit to one target should not affect the others, "Many" is the right choice.
- The prompt text still says "Create only one /list", which is accurate but unusual wording for a list.
