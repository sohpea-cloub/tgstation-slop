# #88787: Unzipped duffel bags worn in suit storage or a pocket give no slowdown

| | |
|---|---|

## Summary

The movement-speed calculation collects the items a mob wears with `get_equipped_speed_mod_items()`, but it never asked for pocket and suit-storage items, so the human override of `get_equipped_items()` removed them from the list. A duffel bag that is unzipped (and so should add its `zip_slowdown`) therefore added nothing when it sat in suit storage or a pocket. The fix passes `INCLUDE_POCKETS` in that one call. #49980 (medal box sprite after relocking while open) could not be reproduced on master; the icon logic already handles it.

## The bug

### #88787

A duffel bag is meant to slow its holder while unzipped. Its slot flags only allow the back slot, but other items such as the santa suit (which can hold anything in suit storage) let a player put one elsewhere. A duffel bag in suit storage can be opened and used as storage, yet the wearer is not slowed. The same happens in the pocket slots, and for any other item with a slowdown value.

The cause is not specific to duffel bags or to the santa suit: any worn item with `slowdown` in a pocket or suit storage was ignored.

### #49980

The report (2020) says that if the captain's medal box is unlocked with an ID, opened (alt+click), and then relocked with the ID without closing it, it shows a wrong sprite (a screenshot is attached to the issue).

## Reproduction

### #88787

1. On the test server, using the Lua editor, create a human and equip a santa suit (`/obj/item/clothing/suit/space/santa`) in the outer-clothing slot.
2. Create a `/obj/item/storage/backpack/duffelbag` and equip it into the suit-storage slot.
3. Call `set_zipper(FALSE)` on the duffel bag (the unzipped state), then read the human's `cached_multiplicative_slowdown` after `update_equipment_speed_mods()`.

Observed on unpatched master: the human's slowdown was 1.5, which is the suit alone, although the bag's own `slowdown` variable was 1 (the unzipped value, so the bag should have added up to 2.5).

This was reproduced by equipping the items and calling procs through the Lua editor, not by a player opening a bag in game with the santa suit from the ruin.

## Cause

`code/modules/mob/inventory.dm:536-542`:

```dm
/mob/proc/get_equipped_speed_mod_items()
	. = get_equipped_items(INCLUDE_ABSTRACT|INCLUDE_PROSTHETICS)
	for(var/obj/item/thing in held_items)
		if(thing.item_flags & SLOWS_WHILE_IN_HAND)
			. += thing
```

The humans' override of `get_equipped_items()` (`code/modules/mob/living/carbon/human/inventory.dm:10-12`) does:

```dm
	var/list/items = ..()
	if(!(include_flags & INCLUDE_POCKETS))
		items -= list(l_store, r_store, s_store)
```

Since `INCLUDE_POCKETS` was not passed, the left pocket, right pocket and suit storage were removed, and `update_equipment_speed_mods()` never saw items in those slots. The duffel bag itself works as intended: it adds `zip_slowdown` to its `slowdown` when unzipped (`code/game/objects/items/storage/dufflebags.dm`, `Initialize` and `set_zipper`); the slowdown simply was not summed for these slots.

## Fix

One commit, "Fix issue 88787: duffel bags in suit storage or pockets now slow you down when unzipped". It adds `INCLUDE_POCKETS` to the `get_equipped_items()` call in `get_equipped_speed_mod_items()` (one line in `code/modules/mob/inventory.dm`). This is the existing flag the human override already honours, so no new mechanism was needed.

The alternative of restricting bags to the back slot or changing the santa suit (as the one comment on the issue suggests: "The santa suit should not be behaving like that") was not tried; that would leave pocket and suit-storage slowdown broken for all other items.

## Verification

After rebuilding, on a fresh round, in the Lua editor with the same setup (human in a santa suit, duffel bag in suit storage), `cached_multiplicative_slowdown` was read at each step:

| State | Slowdown |
|---|---|
| Santa suit only | 1.5 |
| Duffel bag zipped, in suit storage | 1.5 |
| Duffel bag unzipped | 2.5 |
| Duffel bag zipped again | 1.5 |

Not checked: a player actually walking with a bag in a pocket, the pocket slots themselves (only suit storage was exercised), movement speed as experienced in game, or other items with `slowdown` in pockets.

## Notes

- Side effect to weigh: any item with a slowdown value in a pocket or suit storage now slows the wearer, not just duffel bags. This looks like the intent of "equipped" speed modifiers, but it is a behaviour change for existing items and a maintainer may want to review which items that affects.
- The issue comment argues the real problem is the santa suit allowing arbitrary items in suit storage. This fix does not change that; it makes the slowdown correct wherever the bag ends up.

## #49980: not reproduced

On master, using the Lua editor, a medal box and a captain's spare ID were created and these were called in order: `toggle_locked` (unlock), `click_alt` (open), then `toggle_locked` again (relock). The icon state after opening was `medalboxopen`; after relocking it was `medalbox+l` (the locked sprite), with `open` still 1 and storage `locked` at 2.

This matches the code: `/obj/item/storage/lockbox/update_icon_state` (`code/game/objects/items/storage/lockbox.dm:60-69`) checks `broken`, then `locked`, and only then `open`, so a locked box cannot show the open sprite. The medal box's overlays, per the agents' notes, return early when locked, so stale medal overlays are not drawn either. Only the icon state and overlay logic were checked; the rendered sprite was not looked at, and the original screenshot was not compared. The bug was most likely fixed by later changes to the lockbox icon code.
