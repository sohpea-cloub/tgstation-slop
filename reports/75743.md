## Summary
The issue said that applying the xenomorph, lusty maid, Ian, slaughter demon or laughter demon appearance to a cardboard cutout with a crayon made the cutout invisible. On master all five cutouts point at icon states that exist, and each applied cutout rendered correctly. The bug appears to have been fixed earlier; the commit that did it is not in the shallow history available. A unit test that guards against it already exists.

## The bug
As reported (2023): using a crayon or spray can on a cutout and choosing one of those five appearances made it invisible but still interactable (alt-click, pull). The reporter suspected broken typepaths; a commenter saw the icon in the menu, invisible in hand, and visible once placed, and could not drag it while invisible.

## Reproduction
1. Started a round on the test server and used the Lua editor.
2. For each of xenomorph, xenomorph_maid, ian, slaughter_demon and laughter_demon, spawned an `/obj/item/cardboard_cutout` and applied the cutout datum with `get_cardboard_cutout_instance(type):apply(cutout)`. This is the call the crayon's `change_appearance()` path ends in.
3. Checked `icon_exists(direct_icon, direct_icon_state)` for each: it returned 1 for all five (`alienh` and `maid` in `icons/mob/nonhuman-player/alien.dmi`, `corgi` in `icons/mob/simple/pets.dmi`, `slaughter_demon` and `bow_demon` in `icons/mob/simple/demon.dmi`). Decoding the DMI metadata outside the game confirmed the same states exist.
4. Each applied cutout had the right name and alpha 255. Inspecting the Ian cutout showed an overlay "corgi from icons/mob/simple/pets.dmi (generated)", and a render of the xenomorph cutout showed the xenomorph sprite.

Not run: the crayon's radial menu click path itself; only `apply()` was called directly.

## Cause
The historical cause matches the reporter's guess in spirit: these cutouts use `direct_icon` and `direct_icon_state` (`code/game/objects/items/cardboard_cutouts.dm`, roughly lines 175-360), and the states they named did not exist then, so the overlay drew nothing. On master the states are correct. The commit that fixed this could not be identified; `git log` on that file shows only a changelog commit in the shallow clone.

## Fix
None needed; no commit was made.

## Verification
As in Reproduction: all five cutouts apply and draw. Not verified: the crayon UI path, and the "in hand" rendering the commenter described.

## Notes
- A unit test already checks that `icon_exists` holds for every cutout with a `direct_icon` (`code/modules/unit_tests/cardboard_cutouts.dm`), which would catch this regression.
- The issue can likely be closed as fixed.
