# #97712: point blank shot message names the shooter to blind or unconscious victims

## Summary

When a gun is fired point blank at a mob, the victim is sent "<shooter> fires <gun> point blank at you!" through an unconditional `to_chat`, so the message arrives even if the victim is blind or unconscious. The fix sends it with `show_message` as a visual message, with "You hear a gunshot!" as the audible fallback, so blind victims no longer get the shooter's name and unconscious victims get only the muffled "You can almost hear something" line.

## The bug

A player in critical condition was shot point blank with a captain's antique laser gun and their chat log named the shooter, although at that damage they only saw other people as "scratchy TV" figures. A commenter (MrMelbert) pointed out that this is not about the scratchy overlay: the message should not be sent to a blind target at all. Another commenter narrowed the issue to the point-blank shot message.

## Reproduction

Using the Lua editor on the test server, not a player shooting:

1. Spawn a human victim (and have a client possess it so it receives messages) and a shooter human holding a Makarov pistol.
2. Put the victim in hard crit (190 brute damage).
3. Call `shoot_live_shot(shooter, true, victim)` on the gun, which is the point-blank path of firing.
4. On master the victim's chat received "<shooter name> fires the Makarov pistol point blank at you!", with the shooter's real name.

The shot was triggered by calling the proc rather than by clicking, so the player-side targeting and the weapon used in the report (the captain's antique) were not exercised.

## Cause

In `code/modules/projectiles/gun.dm`, the point-blank branch of the firing message code (`gun.dm:272-290`) shows the shooter's `visible_message` to everyone except the victim (`ignored_mobs = pbtarget`) and then tells the victim separately:

```dm
to_chat(pbtarget, span_userdanger("[user] fires [src] point blank at you!"))
```

`to_chat` has no vision or consciousness checks. The victim is excluded from the `visible_message`, which would otherwise have applied the blindness handling, so nothing ever checked whether they could see the shooter.

## Fix

One commit, "Fix issue 97712: point blank shot message no longer names the shooter to blind or unconscious targets". When the target is a mob, the message now goes through `show_message(msg, MSG_VISUAL, span_hear("You hear a gunshot!"), MSG_AUDIBLE)`. `show_message` (`code/modules/mob/mob.dm:227`) already substitutes the alternative message for blind mobs, and for unconscious mobs it replaces audible messages with "... You can almost hear something ..." and sends nothing else. Using the existing function avoids duplicating those checks. Non-mob point-blank targets, which cannot read chat, no longer get a message.

## Verification

On the rebuilt test server, with the same Lua setup:

- Sighted victim: "<shooter> fires the Makarov pistol point blank at you!" with the name, as before.
- Victim with the blindness status effect: "You hear a gunshot!" and no name.
- Victim in hard crit (190 brute): "... You can almost hear something ..." and no name.

Not checked: deaf victims, the captain's antique itself, and a shot fired by a real click.

## Notes

- Only blindness and unconsciousness are honoured, as the commenter asked. A conscious, non-blind victim in soft crit still sees the name, because the "scratchy TV" overlay is not blindness; whether that overlay should hide names is a separate question the issue itself raises.
- Other fire messages in the same function already go through `visible_message` and were not touched.
