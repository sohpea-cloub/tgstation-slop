## Summary

The issue says the mining deathrattle kit contains an implanter that is already loaded with the deathrattle implant and no empty case, so the implant cannot be programmed before use. On master `87b93338` the kit is built differently: it holds an empty implanter, five pre-loaded expeditionary deathrattle cases and an implant pad. Programming the group and implanting someone both worked on the test server. No fix was made. The reporter most likely used an earlier version of the kit.

## The bug

As reported, a miner buys the deathrattle kit, finds the implanter already holding a deathrattle implant, and has nothing to put into the implant pad to set the group. Implanting the pre-loaded implant fails because the deathrattle must be configured first, so the implant is wasted.

## Reproduction

I could not reproduce it. On master:

1. On the test server, an admin opened the Lua editor and spawned `/obj/item/storage/box/minerdeathrattle` (the "boxed expeditionary deathrattle implant kit"). It spawned without error.
2. The kit's contents were inspected. The implanter's `imp` was `nil`, so it was empty. The kit also held pre-loaded deathrattle cases and an implant pad.
3. Spawning the parts separately (an implanter, an implant pad, two lavaland deathrattle cases, two humans) and calling the procs directly, the following was observed:
   - Case 1 was put in the pad and `init_deathrattle_group` was called. It returned 1 and created the group "MIN-504 Quebec".
   - Case 2 was put in the pad and `set_deathrattle_group` was called. It returned 1, the case's implant joined the same group, and the case was renamed with the group name.
   - `case:item_interaction(user, implanter)` drew the implant out of a case. The case's `imp` became `nil` and the implanter was loaded.
   - `implanter:attack(human, human)` implanted it. In a second clean run the human had 1 implant and the group's implant list had 1 entry.

These steps called the procs directly from Lua. They were not performed through a player's clicks. The pad's tgui actions (`ui_act` in `code/game/objects/items/implants/implantpad.dm`, around lines 81-92) were read and call the same procs, but the tgui buttons were not clicked.

## Cause

There is no defect on master. `/obj/item/storage/box/minerdeathrattle` is defined at `code/game/objects/items/storage/boxes/implant_boxes.dm:37-43`. Its `PopulateContents` creates five `/obj/item/implantcase/deathrattle/lavaland`, one plain `/obj/item/implanter` (no `imp_type`, so it starts empty) and one `/obj/item/implantpad`. The kit is sold for 900 credits through the mining order console (`code/game/machinery/computer/orders/order_items/mining/order_consumables.dm:51-53`).

The issue was opened on 2026-01-15. The kit was introduced by the merged PR "Offsite Deathrattle Implants and Repathed Kheiral Cuffs" (#94209, merged 2026-01-04). The test checkout is shallow, so no later commit that changed the kit could be diffed. The reporter's description (a pre-loaded implanter and no cases) does not match what the kit builds now, so the layout changed at some point, or the reporter was on an older build.

## Fix

None.

## Verification

Not applicable, since nothing was changed. What was not checked: whether the death alert is delivered on Lavaland, which is outside the issue; and real tgui clicks on the pad, as described above.

## Notes

- The issue can probably be closed as already fixed or obsolete, unless the reporter can show the kit contents on a current build.
- One minor point in the current design: all five cases come pre-loaded, and the pad's "init" on one case is what creates the group. This worked as intended, and nothing is missing from the kit. The code comment next to the case count says "3 miners 1 QM/paramed/etc, 1 for saving config, presumably".
