# #38418: Individual logs of a disconnected player cannot be reached once their body is gone

| | |
|---|---|
| Issues | [#38418](https://github.com/tgstation/tgstation/issues/38418): fixed (the cause is slightly different from the title; see below) |
| Status | Fixed on the branch below by adding an admin verb. Not tested with a real disconnect (see Verification). |
| Fix branch | [fix/38418](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/38418) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

The issue says a player's individual logs disappear when they disconnect and have no body. The logs are not deleted: they are stored per ckey in the player's persistent client, which outlives both the connection and the mob. They become unreachable, because the only ways to open the individual log panel start from a mob, and a mob's `Destroy()` unbinds it from the persistent client. The fix adds a "Show Ckey Logs" admin verb that picks any ckey that connected this round, and lets the individual log panel work from a ckey when there is no mob.

## The bug

An admin investigating a player who has disconnected, for example after the player's body was gibbed, deleted or went into cryo, cannot open that player's individual logs (attack, say, emote, comms, OOC, game). The Player Panel lists mobs, and its "LOGS" link opens the panel for a mob. With no mob there is nothing to click, so the logs look gone, as the reporter says ("If there's no body there's no individual logs").

## Reproduction

The loss of the logs themselves does not happen on master; what happens is that they cannot be opened. The reproduction therefore simulates the body being gone instead of playing out a real disconnect.

1. On a test round, observing as a ghost, opened the Lua editor.
2. Spawned a human, possessed it with the admin's ckey, and added two entries to its log: `log_message('Testy punched Bob (TEST ATTACK LOG)', LOG_ATTACK)` and `log_message('Testy says hi (TEST SAY LOG)', LOG_SAY)`. These go to both the mob's log and the ckey's persistent client log.
3. Made the persistent client lose its mob with `persistent_client:set_mob(nil)`, which is the same state `/mob/Destroy()` leaves behind (`code/modules/mob/mob.dm:32`).
4. Result on master, by code reading (this was not run before the fix): the panel's entry points require a mob (see Cause), and `GLOB.mob_list` no longer has one for that player, so there is no way to open the panel.


## Cause

- Logs are written by `/mob/proc/log_message` (`code/__HELPERS/logging/mob.dm:23-54`). When the mob has a connected player, each entry is appended both to the mob's own `logging` list and to `persistent_client.logging`. The persistent client is held in `GLOB.persistent_clients_by_ckey`, so the ckey-level log survives disconnects and mob deletion.
- Every way to view the logs needs a mob:
  - `show_individual_logging_panel(mob/M, ...)` returned immediately with `if(!M || !ismob(M)) return` (`code/modules/admin/verbs/individual_logging.dm:2`), and read the log from `M.persistent_client`.
  - The Player Panel "LOGS" link (`code/modules/admin/player_panel.dm:97`) sends `individuallog=<mob ref>`, and the handler does `locate(href_list["individuallog"]) in GLOB.mob_list` (`code/modules/admin/topic.dm:910-919`).
- `/mob/Destroy()` calls `persistent_client?.set_mob(null)` (`code/modules/mob/mob.dm:32`), so once the body is deleted nothing points an admin from the player to the persistent client any more.

## Fix

One commit, "Fix issue 38418: view a ckey's individual logs when the player has no mob left", touching `code/modules/admin/verbs/individual_logging.dm` and `code/modules/admin/topic.dm`.

- New admin verb `Show Ckey Logs` (Game category, `R_ADMIN`). It lists the ckeys in `GLOB.persistent_clients_by_ckey` in a sorted list input, logs the lookup with `log_admin`, and opens the panel for the chosen ckey. If the persistent client still has a mob, that mob is passed along too.
- `show_individual_logging_panel` and `individual_logging_panel_link` take a new `target_ckey` argument. With no mob, the panel is opened for the ckey's persistent client, always with the ckey log source; the "Mob" section then shows "The mob no longer exists" instead of links. The log source is read from `M?.logging` or `persistent_client.logging`.
- A new href, `individuallogckey=<ckey>`, handled in `topic.dm` with the same `R_ADMIN` check, so the panel's own links (Game, Attack, Say, ...) keep working when there is no mob.
- The existing mob-based path (`individuallog=<mob ref>`) is unchanged for callers that have a mob.

The storage was not changed, because the ckey-level log already survives; only access was missing.

## Verification

On a rebuilt test server (build with 0 errors and 0 warnings) in a round with the ckey's logs filled as in Reproduction:

- With the persistent client's mob set to null, `Show Ckey Logs` listed the test ckey. Choosing it opened the panel with "The mob no longer exists" in the Mob section. Its Attack Log showed `Testy punched Bob (TEST ATTACK LOG)`, and following the panel's Say Log link (`individuallogckey=...`) showed `Testy says hi (TEST SAY LOG)`.
- With a live mob, the old `individuallog=<mob ref>` link still worked, and with "Show All" it showed the ckey's entries from several mobs.
- No new runtimes appeared in the round's runtime log.

Not checked:
- A real disconnect, or a real cryo, gib or deletion of the body. The test used `set_mob(nil)` to produce the same state. Only one test client was available.
- The panel before the fix, in game (concluded by reading the code).
- Any verb argument handling other than choosing from the list.

## Notes

- This is a new admin feature rather than a repair of a deletion bug; the issue's title is not literally true on current master. Maintainers may prefer a different entry point, for example a link in the Player Panel, a verb that takes a ckey as free text, or listing disconnected players in the Player Panel.
- The verb only lists ckeys that have a persistent client this round (`GLOB.persistent_clients_by_ckey`). Logs from earlier rounds are not included.
- Events that a mob logs while its player is disconnected go only to the mob's own `logging`, because the ckey log is written only when `HAS_CONNECTED_PLAYER(src)` is true. That was left unchanged; it is arguably correct. Such entries are only visible through the mob, so they are lost once it is deleted.
- An earlier Lua test call that used `log_message` on a mob the admin did not yet own produced a runtime in `callproc.dm`. It was unrelated to this change.
