## Summary

`set_chameleon_gun()` in the chameleon gun code has no branch for guns outside the ballistic, magic, energy and syringe families (reagent gun, blast cannon, medbeam, underbarrel grenade launcher). For those it duplicated a bare `/obj/item/ammo_casing` that has no projectile, so `set_chameleon_projectile()` hit a `stack_trace` and returned early, and the chameleon gun kept the projectile look of the previous disguise (#79878, #79278). The fix copies the gun's own chambered casing when it has one, gives the blast cannon a blast wave look, and otherwise falls back to a practice laser. Three related problems were fixed in separate commits: an unfired locker bolt dropped its locker when deleted (#67618), the chameleon gun always kept the Type 5 laser's examine lore (#95206), and mimicking the underbarrel grenade launcher deleted the chameleon gun's firing pin (found while testing, no issue).

## The bug

Players see:

- Switching a chameleon gun to the reagent gun or the blast cannon produces a runtime, and the gun then fires whatever projectile the previous disguise had (for example, an HE rocket projectile while looking like a reagent gun).
- Switching to the staff of the locker creates two magic lockers at the user's feet per switch.
- Examining a chameleon gun, whatever it is disguised as, shows "You can look closer to learn a little more about the Type 5 laser gun."

What is happening: the chameleon gun is a subtype of `/obj/item/gun/energy/laser`. On each disguise change it builds a throwaway copy of the target gun, duplicates one of that gun's casings to read its projectile, then deletes both. That process fails or has side effects for several kinds of gun, described below.

## Reproduction

All on master `87b93338`, using admin tools on a test server, as an Assistant. A chameleon gun (`/obj/item/gun/energy/laser/chameleon`) was spawned into the hand with the Lua editor, and the disguise was changed with its "Change Gun Appearance" action button (the list input window).

### #79878 (reagent gun)

1. Spawn the chameleon gun. Switch it to "Rocket Launcher", then to "reagent gun (chemgun)".
2. Fire it. The game said "You fire the reagent gun!" and an "HE rocket" projectile appeared. Reading the chameleon casing's `projectile_vars["name"]` with Lua after the switch to the reagent gun gave "HE rocket", i.e. the previous disguise's projectile.
3. The runtime `is not a valid projectile.` (empty name, as in the issue) was reported at `chameleon_gun.dm:105`. When the switch was made through Lua instead of the button, it showed up as a runtime line in the log.

### #79278 (blast cannon)

1. Spawn the chameleon gun, switch to "blast cannon (blastcannon empty)", fire.
2. Same result: "You fire the blast cannon!" with an "HE rocket" projectile. `runtime.log` contained `runtime error:  is not a valid projectile.` at `code/modules/clothing/chameleon/chameleon_gun.dm:105`, called from `set_chameleon_projectile(null)` < `set_chameleon_ammo(the bullet casing (/obj/item/ammo_casing))` < `set_chameleon_gun(the blast cannon)` < `update_look` < `select_look` < the action button `Trigger`.

### #67618 (staff of the locker)

1. Spawn the chameleon gun and switch it to "staff of the locker (locker)". Two `/obj/structure/closet/decay` appeared per switch.
2. Without any chameleon gun: spawn `/obj/item/gun/magic/staff/locker` on a turf with Lua and delete it. One decay closet was left on the turf (counts across three trials: 0, 0, 1; the inputs do not say what the first two trials were, so the intermittent result is unexplained). So the problem is not specific to the chameleon gun.

### #95206 (lore)

1. Spawn the chameleon gun, disguise it as the staff of the locker, and examine it. It still said "You can look closer to learn a little more about the Type 5 laser gun."

### Extra: underbarrel grenade launcher

1. Disguise the chameleon gun as the underbarrel grenade launcher. Looking at its contents with Lua afterwards, the firing pin was gone and the gun's `pin` var was null.

## Cause

### #79878, #79278

In `code/modules/clothing/chameleon/chameleon_gun.dm`, `set_chameleon_gun()` picks a casing to copy by gun family. The final fallback (lines 81-82 at master) is:

```dm
else
	casing_to_dupe = new /obj/item/ammo_casing(src)
```

A bare `/obj/item/ammo_casing` has `projectile_type = null`, so it has no `loaded_projectile`. `set_chameleon_ammo()` passes that null to `set_chameleon_projectile()`, which hits `stack_trace("[template_projectile] is not a valid projectile.")` at line 105 and returns before it sets `cartridge.projectile_vars` (line 139). `reset_chameleon_vars()` does not clear those vars, and `ready_proj()` applies them on every shot, so the previous disguise's projectile stays. This fallback is reached by `/obj/item/gun/chem` (#79878), `/obj/item/gun/blastcannon` (#79278), `/obj/item/gun/medbeam` and `/obj/item/gun/grenadelauncher`.

The base `/obj/item/gun/magic` is in the disguise list too and has a null `ammo_type`, so the magic branch (`new magic_gun.ammo_type(src)`, line 69) runtimed on `new null`.

### #67618

`/obj/projectile/magic/locker/Initialize` (`code/modules/projectiles/projectile/magic.dm:215`) creates a decay locker inside the bolt. `/obj/projectile/magic/locker/Destroy` (line 249) moves every content, the locker included, onto the turf. A bolt deleted before it is fired therefore leaves its locker behind. `set_chameleon_disguise()` creates a throwaway staff (whose chambered casing makes one bolt) and a duplicated casing (a second bolt) and deletes both, giving two lockers per switch. Deleting a real staff of the locker drops one.

### #95206

`/obj/item/gun/Initialize` calls `add_deep_lore()` (`code/modules/projectiles/gun.dm:127`). The laser's override (`code/modules/projectiles/guns/energy/laser.dm:310`) adds the Type 5 `examine_lore` element, and the chameleon gun inherits it. Nothing changes it when the disguise changes.

### Underbarrel grenade launcher

`/obj/item/gun/ballistic/revolver/grenadelauncher/underbarrel/Initialize` (`code/modules/projectiles/guns/ballistic/launchers.dm:34`) sets `pin = gun.pin` from the gun it is inside. The throwaway template created inside the chameleon gun therefore takes the chameleon gun's firing pin, and `/obj/item/gun/Destroy` then deletes it (`QDEL_NULL(pin)`) when the template is qdeleted.

## Fix

Four commits on the fix branch.

**Fix issue 79878: chameleon gun copies the projectile of guns it has no branch for** (`chameleon_gun.dm`; also fixes #79278)
- A new branch duplicates `gun_to_set.chambered.type` when the gun's own chambered casing has a projectile. This covers the reagent gun (its dart).
- The blast cannon gets a `/obj/projectile/blastwave` template, with `range` reset to the initial value (the blast cannon makes the wave itself when it fires, so there was no casing to copy).
- With nothing to copy (medbeam, grenade launcher), it uses a `/obj/projectile/beam/practice` template instead of keeping the stale projectile vars.
- The magic branch is guarded against a null `ammo_type`, and `reset_chameleon_vars()` against a null `chambered`.

**Fix issue 67618: an unfired locker bolt takes its locker with it when deleted** (`magic.dm`)
- `locker/Destroy` now qdels the locker when `!fired`. It was fixed at the projectile and not in the chameleon code, so that deleting a staff no longer leaves a locker either, and the chameleon gun needs no special case.

**Fix issue 95206: chameleon gun copies the deep lore of the gun it mimics** (`chameleon_gun.dm`)
- The chameleon gun overrides `add_deep_lore()` to do nothing. A new `set_chameleon_lore()`, called from `set_chameleon_gun()`, removes the previously copied element, then finds the template gun's `examine_lore` element among `_listen_lookup[COMSIG_ATOM_EXAMINE_MORE]` and re-adds it with the same hint and lore text. A gun with no lore leaves the chameleon gun with none.

**Chameleon gun: don't offer the underbarrel grenade launcher as a disguise** (`chameleon_action_subtypes.dm`)
- Adds `/obj/item/gun/ballistic/revolver/grenadelauncher/underbarrel` to `chameleon_blacklist`. It is an attachment, already `spawn_blacklisted`, and has no issue number.

## Verification

After the first three fixes, using the action button:
- Rocket Launcher -> reagent gun -> fire: no runtime; the casing's projectile vars named "dart" with icon state "cbbolt". Then blast cannon -> fire: no runtime.
- Staff of the locker: no closets appeared, and the examine text no longer showed the lore hint.
- M1911 disguise: examine said "You can look closer to learn a little more about the M1911."
- `examine_more` read through Lua gave exactly one lore entry each time: M1911 lore, then the Type 5 laser lore, then Sakhno lore, then none for the staff.
- A real staff of the locker fired at a spawned monkey: the monkey ended up in a welded `/obj/structure/closet/decay`, so the hit still works. Spawning and deleting a staff now leaves 0 lockers.

On the final build (all four commits), a Lua sweep called `update_look` for every entry in the chameleon gun list (241 after the blacklist), putting a sentinel in `projectile_vars` before each switch:
- 0 new runtimes (`GLOB.total_runtimes` delta 0) and 0 decay lockers.
- No stale or empty projectile vars; the gun's contents (pin, cell, casing) never changed and the pin was still present at the end.
- 33 disguises carry lore.
- Sampled results: base magic gun = practice laser, staff of the locker = locker bolt, blast cannon = blast wave, reagent gun = dart, grenade launcher = practice laser.

The same sweep on the earlier build had flagged one runtime (the base `/obj/item/gun/magic`, now guarded) and the pin loss to the underbarrel launcher.

Not checked: firing every disguise (the sweep checked the stored variables, not actual shots); the `real_hits` mode; a multiplayer round.

## Notes

- `set_chameleon_lore()` reads `_listen_lookup` on the template gun because elements keep no record of what they are attached to. That is an introspection hack a reviewer may dislike. Alternatives would be an explicit lore field on guns, or having `add_deep_lore()` return the data instead of attaching it; neither was tried.
- The blast wave and dart copies are visual only (no phasing, no reagents), like every other mimicked projectile.
- Other tells remain: the chameleon gun still has the laser's seclite mount ("It has a mounting point for a seclite") and the laser's weight and material lines. Not addressed.
- `real_hits` (the badmin mode) was not touched. It does `qdel(chambered.loaded_projectile)` without nulling it, and `reset_chameleon_vars()` never restores `projectile_type`, so it looks buggy as well, but this was not tested.
- Upstream: a search of upstream pull requests for these four issue numbers found none. A search for "chameleon gun" found #85520 (pacifists, merged), #87600 and #77140 (refactors), none of which fix these.
- Nothing in the results points at the build tooling; these are plain DM logic bugs.
