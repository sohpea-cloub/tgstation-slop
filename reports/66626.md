## Summary

The issue reports that mass purrbation deletes lizard tails and that undoing it does not bring them back. On master the tail is restored correctly. What is still lost is the lizard's spines: `purrbation_apply` removes them, but `purrbation_remove` only gives them back inside the branch that replaces a cat tail, so a lizard that never received a cat tail stays without spines. The fix moves the spine restoration out of that branch so it runs whenever the spines are missing.

## The bug

An admin uses the "Mass Purrbation" secret on a round with lizards, then undoes it. The issue says the lizards' tails are gone for good. A commenter adds that other species data (implants, job traits) also gets lost because changing species is destructive.

On master, the tail comes back. The remaining defect: a lizard who goes through apply then remove can end up with no spines, and nothing in the game indicates it.

## Reproduction

The mass verbs only loop over `GLOB.human_list` and call `purrbation_apply` / `purrbation_remove` on each human (`code/modules/mob/living/carbon/human/species_types/felinid.dm:39-47`). The test called `mass_purrbation()` and `mass_remove_purrbation()` once and the per-human procs directly after that, from the Lua editor, rather than pressing the admin secret button.

1. Start a round on the test server and observe.
2. Open the Lua editor and create a state.
3. Spawn a human, make it a lizard (`set_species` with `/datum/species/lizard`), and record its tail, ears and spines organs.
4. Call `mass_purrbation()`, record again, call `mass_remove_purrbation()`, record again. (Calling `purrbation_apply` then `purrbation_remove` on the one human gave the same result.)

Results on master with the default lizard (`tail_cat` feature `None`):

| Stage | Tail | Ears | Spines |
|---|---|---|---|
| start | lizard | normal | present |
| after purrbation | lizard | cat | none |
| after un-purrbation | lizard | normal | **none** |

The tail is intact at every stage. The spines are gone after undoing.

Repeating with `dna.features["tail_cat"]` set to `Cat` before applying: start lizard tail and spines, purrbation gave a cat tail and no spines, and un-purrbation restored the lizard tail and the spines. So the spines only come back in the cat-tail case.

A runtime was also logged by the test spawns in `code/datums/bodypart_overlays/mutant_bodypart_overlay.dm:33` ("adding a /obj/item/organ/ears/cat to a ... when it shouldn't be!"). It came from purrbating a monkey that was in the mass loop and, in the later run, a plain human; it is unrelated to the spine loss and was not investigated.

## Cause

`purrbation_apply` removes a non-basic species' spines unconditionally (`felinid.dm:67-71`). `purrbation_remove` restores them only inside `if(istype(old_tail, /obj/item/organ/tail/cat))` (`felinid.dm:98`), in the loop over `target_species.mutant_organs`:

```dm
// Don't forget the spines we removed earlier
else if(ispath(external_organ, /obj/item/organ/spines))
```
(`felinid.dm:108`)

Whether the lizard got a cat tail depends on `should_visual_organ_apply_to(/obj/item/organ/tail/cat, ...)` in `purrbation_apply`, which is false with the default `None` cat-tail feature. Then no cat tail exists, the block never runs, and the spines are never put back.

## Fix

One commit, "Fix issue 66626: restore lizard spines when removing purrbation without a cat tail". The `else if` spine branch is removed from the tail loop, and a separate block after the tail handling re-inserts spines if the human has none: it loops over `target_species.mutant_organs`, skips anything that is not a spines path or fails `should_visual_organ_apply_to`, and inserts a new spines organ with `DELETE_IF_REPLACED`. The guard on the missing spines slot avoids replacing spines the human still has.

## Verification

After rebuilding and restarting the test server, the same Lua script ran for both `tail_cat` variants. With `None`, the lizard ended with spines and a lizard tail; with `Cat`, the lizard tail and spines were restored. The first post-fix run's `None` start row showed no spines on the freshly spawned lizard (the spines feature was not set), so a second run set `dna.features["spines"]` to `Short` before the species change; the end state of that run is recorded only as "spines restored" in the test notes, and the exact organ listing could not be confirmed.

Not checked: the admin secret button itself, any lizard other than freshly spawned ones, implants or traits (the commenter's concern), and other non-basic species that have spines.

## Notes

- The headline claim (permanent tail loss) is already fixed on master; the testing attributes this to earlier upstream work, but the exact upstream PR was not established (the only hint is "PR #88328 era code").
- Spine restoration depends on `dna.features["spines"]`; if it is `None`, `should_visual_organ_apply_to` may skip the organ, which is intended.
- The commenter's wider point (species change being lossy for implants and traits) is not addressed by this change.
