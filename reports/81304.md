# #81304: Living basic mobs (xenomorphs, lavaland fauna) hide under the corpses of their own kind

| | |
|---|---|
| Issues | [#81304](https://github.com/tgstation/tgstation/issues/81304): verified, fixed. [#97902](https://github.com/tgstation/tgstation/issues/97902): fixed (same cause as #81304) |
| Status | Fixed; layer values checked in game, rendering not checked |
| Fix branch | [fix/81304](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/81304) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A dead `/mob/living/basic` keeps the layer it had when alive (4), so a living mob that moves onto a pile of corpses is drawn at the same layer as them and can end up hidden underneath, and is harder to click. Mobs that lie down are moved to `LYING_MOB_LAYER` (3.8) by `on_lying_down()`, but dying basic mobs never lie down (`body_position` stays 0), and `look_dead()` never changes the layer. The fix makes `look_dead()` lower a default-layer mob to `LYING_MOB_LAYER` and `look_alive()` restore it.

## The bug

#81304: when a couple of xenomorphs have been killed and a living xenomorph is brought to the same tile, the living one "disappears under a pile of corpses". The reporter suspected the corpses and the living mob have the same layer. (The report names `/mob/living/simple_animal/hostile/alien`; the xenomorphs are now `/mob/living/basic/alien` types.)

#97902 is the same thing with lavaland fauna: a living goliath or lobstrosity standing on the corpse of another can hide under it, so the player has a harder time clicking it in melee and cannot easily see its tentacle attacks.

## Reproduction

The reproduction compared layer values with admin tools; it did not look at the rendering.

1. On a test server on master, as an observer, open the Lua editor.
2. On one tile, spawn two `/mob/living/basic/alien/drone` and one `/mob/living/basic/mining/goliath`.
3. Print the `layer` of all three. All were 4.
4. Call `death()` on one drone and on the goliath.
5. Print the layers again, together with `body_position` and `density`.

Observed on master: the dead drone, the living drone and the dead goliath all had `layer` 4 (and `body_position` 0 for the dead drone). A corpse is therefore drawn at the same layer as a living mob on the same tile, instead of behind it.

## Cause

`/mob/living/basic/death()` calls `look_dead()` (`code/modules/mob/living/basic/basic.dm:181`). `look_dead()` (`basic.dm:200`) only changes the icon state, flips the transform when `FLIP_ON_DEATH` is set, makes the mob undense, and sends `COMSIG_BASICMOB_LOOK_DEAD`. It never changes `layer`.

For other living mobs, the corpse goes behind living mobs by lying down: `on_lying_down()` (`code/modules/mob/living/living.dm:742-744`) does

```dm
if(layer == initial(layer)) //to avoid things like hiding larvas.
	layer = LYING_MOB_LAYER //so mob lying always appear behind standing mobs
```

and `on_standing_up()` (`living.dm:752-753`) restores the layer. A dead basic mob does not go through this path (its `body_position` stayed 0 in the reproduction), so it stays at the standing layer. `look_dead()` is also what the `play_dead` AI behavior calls (`code/datums/ai/basic_mobs/basic_ai_behaviors/play_dead.dm:11`, with `look_alive()` on line 25).

## Fix

One commit on `fix/81304`, "Fix issue 81304: dead basic mobs drop to the lying mob layer so living ones don't hide under corpses", changing `code/modules/mob/living/basic/basic.dm`:

- `look_dead()`: if the mob's layer is still its initial layer and that layer is above `LYING_MOB_LAYER`, set `layer = LYING_MOB_LAYER`.
- `look_alive()`: if the layer is `LYING_MOB_LAYER`, restore `layer = initial(layer)`.

This copies the condition used by `on_lying_down()` and `on_standing_up()`. It leaves mobs with custom or already lower layers alone, so for example a mob that was deliberately set below the standing layer does not get moved up. The change is in the basic-mob death appearance rather than in the generic living death code, because carbon mobs (including player xenomorphs) already lie down on death.

## Verification

The server was rebuilt with the fix and the same script was run (two drones and a goliath on one tile, one drone and the goliath killed):

- Dead drone: layer 3.8. Living drone: layer 4. Dead goliath: layer 3.8.
- After calling `revive(1)` on the dead drone, its layer was 4 again.

So corpses now sit behind a living mob on the same tile. Not checked:

- The visual result in a real client (the cases in the issues' screenshots were not recreated; only the `layer` values were read).
- Clicking on a stack of corpses with a living mob among them, for #97902's "harder to hit" symptom.
- Mobs that play dead use `look_dead()` and `look_alive()`, so they now also drop to the lower layer while pretending to be dead, and come back when they stop. This follows from the code and was not run.
- Basic mobs with a non-default layer (for example ones that set their own `layer`), `FLIP_ON_DEATH` mobs, and the effect on other layered objects (items dropped on a corpse) were not tested.

## Notes

- #97902's report is from a newer client build but the same tgstation behavior, and its goliath is a `/mob/living/basic`, so it falls under the same code path.
- A dead mob that is dense (`REMAIN_DENSE_WHILE_DEAD`) still blocks movement. The fix only affects drawing order.
- Player-controlled carbon xenomorphs were not tested; by code reading they go through `on_lying_down()` when they die.
