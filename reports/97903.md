# #97903: Cleaving saw's open-phase cleave does not hit other enemies when the target is a legion skull

| | |
|---|---|
| Issues | [#97903](https://github.com/tgstation/tgstation/issues/97903): verified, fixed |
| Status | Fixed (one-line change), verified in game with a test setup |
| Fix branch | [fix/97903](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97903) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

With the cleaving saw open, attacking a legion skull hits only that skull, even when other skulls stand beside it or on its tile. The saw's `attack()` only does its three-tile sweep when the primary target is dense (`target.density`), and legion skulls (`/mob/living/basic/mining/legion_brood`) are never dense. The fix replaces the density check with a check that the target is not lying down, which is what the sweep loop already filters on.

## The bug

Players who open the saw and click a legion skull see a single normal hit and a single dead skull. Other skulls adjacent to the user, in front or to either side of the target, are untouched. The reporter noted that the sweep works when the primary target is something dense (a goliath, for example).

The issue comment proposes that the sweep does not run because legion skulls are deleted on death, so the code after the first hit never executes. That is not what happens; see Cause.

## Reproduction

On master, using admin tools:

1. Using the Lua editor, spawn a human with `never_wounded` and a `/obj/item/melee/cleaving_saw`, put the saw in their hands and call `attack_self` to open it. Set `combat_mode = TRUE`.
2. Spawn four `/mob/living/basic/mining/legion_brood` around them: one directly in front of the human (the primary target), one in front-left, one in front-right, and one stacked on the primary target's tile.
3. Call `saw:melee_attack_chain(human, skull1)` on the first skull. This drives the attack from Lua rather than by clicking, so the player's click path itself was not exercised.
4. With SDQL2, run `SELECT /mob/living/basic/mining/legion_brood MAP [x, y, stat]`.

Observed before the fix: only the targeted skull was dead (`stat` 3). The other three skulls had `stat` 0, still alive, and `density` was 0 on the skulls.

## Cause

`code/modules/mining/lavaland/mining_loot/megafauna/blood_drunk.dm:68`, in `/obj/item/melee/cleaving_saw/attack`:

```dm
if(!is_open || swiping || !target.density || get_turf(target) == get_turf(user))
```

When this condition is true the proc takes the single-target path (nemesis effects, then `. = ..()`, then `return`). `!target.density` makes any non-dense primary target take that path. `legion_brood.dm:31` sets `density = FALSE` for skulls, so an open saw never sweeps when a skull is clicked. The sweep itself (lines 80-87) loops over the three turfs and skips targets with `body_position == LYING_DOWN` (line 86), so the density check appears to have been a proxy for "prone target" that also excludes non-dense living mobs.

The deletion-on-death explanation in the issue comment does not apply: the decision to skip the sweep is made before the target is attacked.

## Fix

One commit, "Fix issue 97903: cleaving saw cleave works on non-dense targets like legion skulls". It changes the condition on line 68 to:

```dm
if(!is_open || swiping || target.body_position == LYING_DOWN || get_turf(target) == get_turf(user))
```

The single-target path is now taken only for a lying-down primary target (the apparent intent of the density check) instead of any non-dense one. No alternative was recorded.

## Verification

Same setup as the reproduction, on the fixed build. The chat showed one "cleaves the legion" line and two "slashes the legion" lines, and SDQL2 showed all four skulls dead, including the one stacked on the primary's tile. No runtimes were seen.

Not checked: a lying-down primary target (it should behave as before, with a single attack; this was not tested), and a real player click rather than `melee_attack_chain` called from Lua. The chat showed three attack messages for four dead skulls; the stacked skull's attack message was not separately accounted for.

## Notes

- The change affects every non-dense living mob, not only legion skulls: with the saw open, they are now swept like dense ones. Other non-dense living targets were not tested.
- Mobs that are dense but lying down, and the user's own tile, keep the old single-attack path.
