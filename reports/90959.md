## Summary

The smart organ storage UI identifies an item's picture by its icon file and icon state. Bodyparts have an empty icon state (they are drawn from overlays), so the UI had nothing to look up and showed its question-mark fallback. The fix also sends a flattened image for such items, and the UI uses it. Separately, surgery step messages addressed to the surgeon were dropped for a blind surgeon, because `display_results()` did not ask for the self message to always be shown. The fix adds that flag.

## #90959: Limbs appear as question marks in organ storage UI

### The bug

In the organ storage UI, internal organs show their sprite but a detached limb shows a question mark.

### Reproduction

Reproduced at the data level, not by viewing the UI.

1. On the test server, with the Lua editor, spawn an `/obj/machinery/smartfridge/organ` and put a right arm and a liver in it.
2. Call `fridge:ui_data(me)` and inspect the entries for each item.

Observed on master: the arm's entry had `icon_state` `""` and no other image data; the liver's entry had `icon_state` `liver`. tgui's ImageButton only uses the icon-and-state lookup when both are non-empty, and otherwise shows the question-mark fallback, which accounts for the report. The fallback itself was not seen on screen.

### Cause

`/obj/machinery/smartfridge/ui_data()` sends only `atom.icon` and `atom.icon_state` for each stored item (`code/modules/food_and_drinks/machinery/smartfridge.dm:386-388`). Bodyparts use `icon = 'icons/mob/human/bodyparts.dmi'` and `icon_state = ""` (comment: "Leave this blank! Bodyparts are built using overlays", `code/modules/surgery/bodyparts/_bodyparts.dm:9`). The UI's `ImageButton` calls (`tgui/packages/tgui/interfaces/SmartVend.tsx:112` and `:167`) pass only `dmIcon` and `dmIconState`.

### Fix

Commit "Fix issue 90959: Limbs show as question marks in the smart organ storage UI":

- `smartfridge.dm`: each item entry gets `"icon_base64" = atom.icon_state ? null : icon2base64(getFlatIcon(atom, no_anim = TRUE))`. Items with an icon state are unchanged; only items without one pay for flattening.
- `SmartVend.tsx`: the `Item` type gets `icon_base64: string | null` and both `ImageButton`s get `base64={item.icon_base64}`. According to the agents, tgui-core's `ImageButton` prefers `base64` over `dmIcon` when it is set; that was not independently checked here.

### Verification

On the fixed build, `ui_data` for the same fridge gave the arm entry an `icon_base64` of length 352 (the flattened icon had 33 opaque pixels), while the liver still had `icon_state` `liver` and no `icon_base64`. The tgui bundle built without errors, and no new runtimes appeared in the runtime log.

Not checked: the UI actually showing the arm (the test tool does not run tgui's JavaScript), a typecheck or tests of the TSX change, other bodyparts (legs, heads), other smart fridges, and the cost of flattening icons for large stocks.

## #51219: Surgery feedback messages missing while blind

### The bug

A surgeon who is blind did not get messages such as "you fix some of the wounds" while performing surgery steps. A commenter noted that visible messages are supposed to carry a non-visual alternative for the actor.

### Reproduction

1. As a human on the test server, apply blindness with the Lua editor: `surgeon:apply_status_effect(dm.global_procs._text2path('/datum/status_effect/grouped/blindness'), 'test')` (string paths did not work).
2. Create a `/datum/surgery_operation/limb/incise_skin` and call `display_results(surgeon, patient, 'SELFMSG-BLIND-TEST', ...)`.

On master, a first attempt showed no chat line for the surgeon, but the blindness was not confirmed at the time (`has_status_effect` was not read), so that result is inconclusive. This was a direct proc call, not a played surgery step.

### Cause

`display_results()` (`code/modules/surgery/operations/_operation.dm:973`) sends the surgeon's message through `surgeon.visible_message(..., self_message = self_message, ...)` (line 981) with no flags. `visible_message` delivers the self message as a visual message, which a blind mob does not receive, and no blind message is given. Lines 147 and 163 of the same file already pass `visible_message_flags = ALWAYS_SHOW_SELF_MESSAGE` in other messages.

### Fix

Commit "Fix issue 51219: Show surgery step messages to blind surgeons" adds `visible_message_flags = ALWAYS_SHOW_SELF_MESSAGE` to that call.

### Verification

On the fixed build, with blindness applied (the Blind alert appeared), calling `display_results` showed "SELFMSG-BLIND-TEST" in the surgeon's chat. Not checked: a real surgery performed blind, and the reporter's other complaint (no defibrillation success feedback while blind), which was not examined.
