# #94267: Mech weapons still fire while the mech is inside Convoke Void's talisman

| | |
|---|---|
| Issues | [#94267](https://github.com/tgstation/tgstation/issues/94267): verified / fixed |
| Status | Fixed |
| Fix branch | [fix/94267](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/94267) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a pilot casts the Convoke Void genetic ability inside a mech, the spell's target is the mech, so the mech (not the pilot) is placed in an immortality talisman and becomes invulnerable. The pilot's own state is unchanged, so the click handler that blocks actions for mobs stuck out of reality never fires, and the mech's weapons keep working. The fix adds the same check to the mech's own click handler, so clicks are cancelled while the mech carries `TRAIT_NO_TRANSFORM`.

## The bug

A player with the Convoke Void mutation, sitting in a mech, activates it. The message "The <mech> is dragged into the void, leaving a hole in its place!" appears, and the mech is invulnerable for the duration of the talisman (10 seconds in the test). The pilot can still click to fire the mech's weapons at others while invulnerable. The reporter used a Clarke; the other mech tested was a Durand (see Verification).

## Reproduction

1. Using the Lua editor, spawn a human, spawn a Durand, attach a scattershot to it and put the human in as pilot. Give the human the mutation `/datum/mutation/void` (`add_mutation` needs a source argument) and take control of them.
2. Click the Convoke Void action button, then click a target tile (a window several tiles south, with the mech facing south) within the 10 seconds the talisman lasts. Clicks in a direction other than the mech's facing are ignored, and two early attempts failed only because the 10 seconds had elapsed between the test's calls.

Result on master: the message "The Durand is dragged into the void, leaving a hole in its place!", then the click one second later fired the scattershot (gunshot sound twice, "full tile reinforced window is hit by a bullet" four times, the window and shards broke), while the void hole object still existed.

## Cause

`get_caster_from_target` (`code/modules/spells/spell.dm:240`) returns the mech as the spell's `cast_on` target, because mechs have `TRAIT_CASTABLE_LOC`. `/datum/action/cooldown/spell/void/cast` (`code/datums/mutations/void_magnet.dm:39`) then runs `new /obj/effect/immortality_talisman/void(get_turf(cast_on), cast_on)`, so the mech is the thing put into the talisman. The talisman's `vanish` (`code/modules/mining/lavaland/mining_loot/equipment.dm:205`) adds `TRAIT_GODMODE` and `TRAIT_NO_TRANSFORM` to the mech.

`mob/ClickOn` (`code/_onclick/click.dm:76`) ignores clicks only when the clicking mob has `TRAIT_NO_TRANSFORM`. The pilot does not have it. The mech's own `COMSIG_MOB_CLICKON` handler, `/obj/vehicle/sealed/mecha/proc/on_mouseclick` (`code/modules/vehicles/mecha/_mecha.dm:675`), never looked at the mech's trait.

## Fix

One commit on [fix/94267](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/94267), "Fix issue 94267: mechs can't use equipment while stuck in the void/immortality talisman". In `on_mouseclick`, after the middle-click safety toggle, it adds:

```dm
if(HAS_TRAIT(src, TRAIT_NO_TRANSFORM)) // Mirrors mob/ClickOn: ...
	return COMSIG_MOB_CANCEL_CLICKON
```

This mirrors what `mob/ClickOn` does for a mob in the same state, and applies to anything that gives a mech `TRAIT_NO_TRANSFORM`. The alternative of making Convoke Void target the pilot instead of the mech was not tried; that would change how the spell works for mechs, and the report does not evaluate it.

## Verification

On a fresh test server with the fix, using the same steps (Durand with a scattershot, possessed pilot): the void cast, then a click one second later produced no shot and no sound and no chat message. After "The Durand pops back into reality!", the same click fired normally.

Not checked: a Clarke (the mech in the report), which goes through the same `on_mouseclick` path; AI pilots; other mech equipment such as non-click abilities.

## Notes

- The mech's action buttons (shield toggle, eject) still work while the mech is in the void. This was observed in the test, was not part of the issue, and was not changed.
- The middle-click safety toggle is placed before the new check, so it still works while the mech is in the talisman. That is how the change is ordered; whether it matters was not considered further.
- The bug affects any mech put in an immortality talisman, not only through Convoke Void.
