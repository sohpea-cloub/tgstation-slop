## Summary

The issue reports that the cult's Nar'sie ending shows a screen about the station's self-destruct even when the nuke core has been removed from the nuclear bomb. That is how the code is written: the cult ending never checks the nuke bomb or its core. It plays its own cinematic, which is a Central Command "nuclear package" and not the station's self-destruct. Master already uses a cult-specific summary screen for this. No change was made, and this was checked by reading the code only (no in-game run).

## The bug

As reported: a traitor takes the nuke core, the blood cult then summons Nar'sie, and the round ends with a nuke cinematic. The summary screen at the end says "self destruct sequence activated". The reporter expected the station's nuke to be unable to go off without its core, and suggested forcing the "second ending" in that case.

What happens in the code is different from what the report assumes. The cult ending is not the station's nuke detonating. Per the in-code comment, it is Central Command deploying a nuclear package after the cult won, and the code does not look at the bomb or its core.

## Reproduction

Not reproduced in game. The test server was started and stopped without a round being played, because the code path is unconditional: nothing in it depends on the nuke core, so there was nothing to vary. The conclusion rests on reading the code and on extracting the summary frames from the icon file.

To check by hand with admin tools: remove the core from the nuclear bomb, then trigger the cult ending (for example by letting Nar'sie be summoned or by calling `cult_ending_helper()` with ProcCall). The cult cinematic plays whether or not the core is present.

## Cause

- `cult_ending_helper()` (`code/modules/power/singularity/narsie.dm:313-326`) picks the cinematic from its `ending_type` argument only. The default, `CULT_VICTORY_NUKE`, plays `/datum/cinematic/nuke/cult`. Its comment reads "The cult won, but centcom deployed a nuke. Default". There is no reference to the nuclear bomb or its core.
- `/datum/cinematic/nuke/cult` (`code/datums/cinematics/nuke_cinematics.dm:58-65`) is documented as "A blood cult summoned Nar'sie, but central command deployed a nuclear package to stop them." It sets `after_nuke_summary_state = "summary_cult"`. The station's self-destruct uses a different state, `summary_selfdes` (line 37).
- The two summary frames in `icons/effects/station_explosion.dmi` were extracted and compared. `summary_selfdes` has the full self-destruct text, with authorization and device details. `summary_cult` reads "Self destruct sequence activated aboard outpost NTSS13" followed by "ERROR / CONNECTION LOST", with Nar'sie's silhouette. Only the header art ("SBJ: SELF DESTRUCT ACTIVATION ALERT") is shared between them. That header is probably what the reporter's screenshot shows.
- The cult ending does not set `GLOB.station_was_nuked`. Only the nuclear bomb code does (`_nuclear_bomb.dm:678`; not re-checked here). The round-end news report for a cult win is `CULT_SUMMON` (`code/controllers/subsystem/dynamic/dynamic_ruleset_roundstart.dm:225`, handled at `code/controllers/subsystem/ticker.dm:691`), not `STATION_NUKED` (`ticker.dm:720`), so the round-end report does not claim a station self-destruct either.

## Fix

None. The suggestion to force the second ending when the core is removed would be a design change. Nobody in the thread asked for it, and nemvar's comment ("I don't think removing the nuke core matters for any ending") points the other way.

## Verification

Not applicable: no code was changed. Not checked: an actual in-game cult ending with the core removed, and the exact text shown on the live screen (only the icon file's frames were inspected).
