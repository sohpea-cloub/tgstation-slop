## Summary

The issue says that a tank bomb assembled with a timer and igniter only opens the tank's release-valve menu when activated in hand, leaving no way to set or start the timer. On master `87b93338` this does not happen: activating the assembled tank in hand opens the timer UI and the timer can be started. The valve menu is now opened by right-click (`attack_self_secondary`) instead. The behaviour was presumably fixed after the issue was filed (the last comment is from 2024-06-16); no specific upstream PR was identified.

## The bug (as reported)

After the single-tank bomb rework, the reporter found that a tank with an attached timer + igniter assembly, once welded in place, brought up only the valve menu on use in hand, so a timer or igniter bomb could not be armed. A June 2024 comment says it was still the case then.

## Reproduction

On master, using admin tools:

1. Start the round, observe, open the Lua editor, spawn a human and take control of it.
2. Make a timer and an igniter and toggle their secured state on both (the "screwdriver" step), join them into an assembly holder, then attach the holder to a plasma tank with the tank's item interaction (the chat reported "bomb assembled").
3. With the tank in hand, press Z (activate held item).
4. Observed: the Timer tgui window opened (not the tank valve UI). Sending the timer's `time` action with 100 changed `timing` from 0 to 1, i.e. the timer started. With the parts unsecured the chat said "The timer is unsecured!", which also shows that the use in hand reached the timer.

The welding step ("weld to arm") was not performed, so the `bomb_status` path was not tested; the in-hand code below does not consult it.

## Cause

Nothing is broken at master:

- `/obj/item/tank/attack_self` (`code/game/objects/items/tanks/tanks.dm:425`) calls `tank_assembly.attack_self(user)` and returns TRUE when an assembly is attached.
- `/obj/item/assembly_holder/attack_self` (`code/modules/assembly/holder.dm:168`) forwards to each assembly in it (and says "part missing!" if there is only one).
- The tank's own UI is opened from `attack_self_secondary` (`tanks.dm:431`), i.e. right-click.

## Fix

None; no commit.

## Verification

Reproduction steps above, run on the test server; the result was the Timer window and a started timer. Not checked: the welded state, a signaller-based bomb, other assembly types, and a bomb used from a player's hand through the actual UI beyond the Z key.

## Notes

- It is not known which upstream PR changed this. The behaviour may have been changed by one of the reworks of tank/assembly interaction after the issue was opened; the issue could probably be closed or confirmed by the reporter.
- Right-click opening the valve menu may be unobvious to players; that is a design question, not a bug here.
