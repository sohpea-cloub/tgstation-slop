## Summary
Clicking (Reply) on a PDA message made the Direct Messenger the active program without telling the already open tablet window, so the window kept the chat client's interface while receiving the messenger's data, and the chat appeared blank. The fix updates the open tablet UI when the reply switches the program. It was checked on the test server by inspecting the window's interface name; the rendered window was not seen.

## The bug
With the chat client (NtosNetChat) open on a PDA, clicking (Reply) in a chat log line to send a PDA message left the chat window empty until the app was closed and reopened. The issue's comment also mentions a second bug: after losing NTNet connection, the minimize and close buttons turned into the power button. That one was not investigated.

## Reproduction
1. Latejoin as an Assistant. Using the Lua editor, install the chat client on the PDA, open it, create a channel "testroom" and send a line to it.
2. Create a second PDA (registered as a messenger, "Bob (Clown)") and send a PDA message from it to the first PDA, so the chat log contains a line with a (Reply) link.
3. With the chat client window open, fire the Reply link's topic (`choice=message`), which is what the client sends when the link is clicked. This was done through admin tools rather than by clicking, so the click itself was not exercised.

Observed before the fix: the open window stayed on `NtosNetChat` ("Chat Client"), and its data updates became the messenger's (`saved_chats`, `messengers`, `owner`, ...) with no chat data. Lua showed the PDA's `active_program.filedesc` as "Direct Messenger". A real client would render the chat interface with messenger data, i.e. a blank chat.

## Cause
In `Topic()` of the messenger program (`code/modules/modular_computers/file_system/programs/messenger/messenger_program.dm:735`), the line

```dm
if(!(computer.active_program == src || computer.open_program(usr, src, open_ui = FALSE)))
	return
```
(`messenger_program.dm:746`) switches the active program with `open_ui = FALSE` and never calls `update_tablet_open_uis`, so a window that is already open keeps its previous interface.

## Fix
One commit, "Fix issue 75287: switch the open PDA window to the messenger when replying from chat". If the active program is not the messenger, it opens it as before, and then, if the user has the tablet's UI open (`SStgui.get_open_ui(usr, computer)`), calls `computer.update_tablet_open_uis(usr)`. The condition keeps the original intent of `open_ui = FALSE`: no window is opened if the user had none.

## Verification
After the fix, with the same steps, the Reply topic opened the window as `NtosMessenger` ("Direct Messenger") together with the text input prompt. No new runtimes appeared (the only error in the log came from the test setup, an unregistered second PDA).

Not checked: the Reply link with no PDA UI open (covered by the same condition but not run); a visual check of the window, since the test client does not run tgui's JavaScript; the second bug from the comment.
