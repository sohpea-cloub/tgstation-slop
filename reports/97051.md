# #97051: Removed moth wings (and other mob-sprite organs) are invisible

| | |
|---|---|

| Status | Fixed (one commit) |
| Fix branch | [fix/97051](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97051) |

## Summary

`/obj/item/organ/update_overlays()` returned early whenever the organ had no `bodypart_owner`, which is always the case for a loose organ. When it did not return early, it added the associative list from `get_all_overlays()` (overlay = flags) into the overlays list, which produced garbage appearances. As a result, wings and other organs that draw their item sprite from their mob sprite rendered nothing. The fix removes the `bodypart_owner` guard and adds only the overlay entries.

## The bug

Moth wings taken off a moth, and held or dropped as an item, are invisible.

## Reproduction

1. Observe on the test server and open the Lua editor.
2. Spawn a human and set its species to moth.
3. Remove its wings organ with `Remove()` and move the organ to a turf. A freshly spawned `/obj/item/organ/wings/moth` was also checked.
4. Inspect the item and render it with the admin render tools.

Evidence on master: the item's `icon_state` was nil, `overlays` held one or two garbage entries (named like "icon organs.dmi (#000000)"), and the render was a blank white tile. The inspection also reported "parts naming an icon_state their icon lacks". The organ was produced with admin tools, not with an organ harvester or by hand, which the issue says makes no difference.

## Cause

All line numbers are at master. `/obj/item/organ/update_overlays()` is in `code/modules/surgery/organs/external/_visual_organs.dm:93`:

```dm
if(!use_mob_sprite_as_obj_sprite || isnull(bodypart_owner) || isnull(bodypart_overlay))
	return

. += bodypart_overlay.get_all_overlays(bodypart_owner)
```

There are two defects:

1. `bodypart_remove()` sets `bodypart_owner` to null before `update_appearance()` runs, so for a loose organ the proc always returned early and added nothing.
2. `get_all_overlays()` (`code/modules/surgery/bodyparts/_bodyparts.dm:1451` per the test notes) returns an associative list of overlay = flags. Adding that list directly to `.` puts the keys' values (flags) into the overlays, not the overlay objects. This is what produced the garbage entries on organs that did get past the guard, such as a freshly spawned one.

## Fix

One commit, "Fix issue 97051: removed moth wings (and other mob-sprite organs) are invisible", in `_visual_organs.dm`:

- The `isnull(bodypart_owner)` condition was dropped from the early return. A comment notes that the limb can be null for a loose item and that the overlays handle that.
- The result of `get_all_overlays()` is now iterated with `for(var/actual_overlay, actual_overlay_flags in ...)`, adding only `actual_overlay` to `.`.

## Verification

After rebuilding, the same steps rendered the moth wings sprite. The removed wings had 4 overlays and the freshly spawned wings had 3.

Not checked: other organs that use `use_mob_sprite_as_obj_sprite` (other wings, pod hair, mushroom cap) were not rendered; they share the code path. Dropped versus held rendering, worn-state sprites and the organ in a body were not checked either.

## Notes

- The notes say the change affects every organ with `use_mob_sprite_as_obj_sprite`: all wings, pod hair and the mushroom cap.
- The issue lists several test merges (storage diagnostics, Heretic changes, AI laws). The bug was reproduced on plain master, so none of them is needed.
- Whether `get_all_overlays()` was changed to return an associative list recently was not checked in the git history (the repository is shallow).
