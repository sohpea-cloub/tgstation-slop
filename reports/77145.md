# #77145: `equalize()` divides by zero when both gas mixtures are empty

| | |
|---|---|
| Issues | [#77145](https://github.com/tgstation/tgstation/issues/77145): verified, fixed |
| Status | Fixed; checked on the test server by calling the proc directly (not through a nested container) |
| Fix branch | [fix/77145](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/77145) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

`/datum/gas_mixture/proc/equalize()` averages the two mixtures' temperatures weighted by heat capacity. For a non-turf mixture with no gas the heat capacity is 0, so two empty non-turf mixtures at different temperatures make the divisor 0 and the proc runtimes with "Division by zero". The fix computes the combined heat capacity first and only averages the temperatures (and reports that something changed) when it is greater than 0.

## The bug

The issue reports one round whose runtime log held the same `equalize()` "Division by zero" runtime 8021 times. Players would not see anything directly; the damage is runtime spam, and the rest of `equalize()` does not run when it hits the error. The report's screenshot could not be read, so the exact trigger in that 2023 round is not known.

## Reproduction

This was reproduced by calling the proc directly, not by a player action.

1. On master, start a round and open the Lua editor (as an observer admin), then create a Lua state.
2. Run code that creates two fresh `/datum/gas_mixture`s (both empty, not turf air), sets `a.temperature = 293.15`, leaves `b` at its default temperature (2.7 K, TCMB), and calls `a:equalize(b)`.
3. Observed: the Lua call returned `nil`; the temperatures stayed 293.15 and 2.7; the server runtime log had `Runtime in code/modules/atmospherics/gasmixtures/gas_mixture.dm,282: Division by zero`, proc `equalize`.

A real in-game version (for example a sealed closet opened inside another sealed closet) was not played; see Notes.

## Cause

`code/modules/atmospherics/gasmixtures/gas_mixture.dm:282` (master):

```dm
var/new_temp = (temperature * self_heat_cap + other.temperature * other_heat_cap) / (self_heat_cap + other_heat_cap)
```

This is inside the branch taken when the two temperatures differ by more than `MINIMUM_TEMPERATURE_DELTA_TO_SUSPEND`. `heat_capacity()` of a non-turf mixture is the sum over its gases, so it is 0 when the mixture is empty. Turf mixtures return `HEAT_CAPACITY_VACUUM` instead, so only pairs where neither side is a turf's air can hit the zero. Callers that pass such pairs include `code/game/objects/structures/crates_lockers/closets.dm:234`, `code/game/objects/structures/morgue.dm:291`, `code/modules/atmospherics/machinery/components/unary_devices/passive_vent.dm:36` and `code/game/objects/structures/transit_tubes/station.dm:169`. A sealed closet or freezer opened inside another sealed one (the outer one's `return_air()` is its own internal mixture) is the example found by reading the code.

## Fix

One commit, "Fix issue 77145: gas_mixture equalize divided by zero for two empty mixtures", changes `equalize()` in `gas_mixture.dm`. It computes `combined_heat_cap = self_heat_cap + other_heat_cap` and only does the temperature averaging if that is above 0. The `. = TRUE` ("something changed") return was moved inside that check, since with no heat to average nothing changes. The pressure/gas-sharing part of the proc is untouched. Skipping the averaging was chosen over substituting a minimum heat capacity, because there is no energy to redistribute between two empty mixtures; no alternative was tested.

## Verification

After rebuilding and restarting the test server, using the Lua editor:

- Two empty mixtures at different temperatures (293.15 K and 2.7 K): no runtime, `equalize()` returned 0 (false), temperatures unchanged. The log contained no "Division by zero".
- A mixture with 10 mol of oxygen at 400 K against an empty one: returned 1 (true), both ended at 400 K, moles split 5 / 5. So the normal path still works.

Not checked: a real nested-container scenario in play, any other caller of `equalize()`, or whether this accounts for the 8021 runtimes in the reported round.

## Notes

- Whether this is the reporter's actual trigger is unconfirmed. It is the only zero divisor reachable in `equalize()` with temperatures at or above TCMB, but the code has changed since the 2023 round.
- Returning false for a pair of empty mixtures at different temperatures means callers such as the closet's process loop will see "no change"; the temperatures of those two empty mixtures are simply left as they are.
