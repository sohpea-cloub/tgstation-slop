## Summary

Warm Ready-Donks inherit the cold donk's "bake/microwave into the next stage" setup, but their next stage is a burned mess, so they tell the player that baking or microwaving them makes a "burned mess" as if that were a proper recipe (and a bake in progress reads as good progress). The fix gives the warm donk its own bakeable/microwavable setup flagged as a bad recipe. Separately, the soup pot's "you smell something good" message was sent to everyone, including mobs with anosmia; a new smell flag on `audible_message` now skips them. #77811 (curry sauce vs cornmeal porridge) no longer conflicts on master.

## #77376: Ready-Donk "thinks it's a rebake"

### The bug

The reporter's screenshot shows a freshly baked, warm Ready-Donk whose description says it can be baked further, and noted that boiled pasta and things made from it say they can be microwaved again into boiled pasta.

### Reproduction

1. With the Lua editor, spawn `/obj/item/food/ready_donk/warm` and call `examine()` on it as the admin's mob.
2. Observed on master: "The warm Ready-Donk: Bachelor Chow can be baked into a burned mess." and "... microwaved into a burned mess." (The cold donk correctly says it becomes a warm Ready-Donk.)
3. A warm donk left in an oven reports "probably needs to be baked a bit longer". This line comes from reading the code (`bakeable.dm:144-148`), not from the recorded in-game run.

The pasta half was not rechecked in game. By reading the code, boiled spaghetti now uses the plain microwavable with `bad_recipe = TRUE` (`spaghetti.dm:14-20`, `_food.dm:207-208`), so it no longer shows a "can be microwaved into" line; this was not examined on the server.

### Cause

`/obj/item/food/ready_donk/make_bakeable()` and `make_microwaveable()` (`code/modules/food_and_drinks/food/packaged.dm:235-239`) add a bakeable component with `positive_result = TRUE` and a microwavable element without `bad_recipe`, using `warm_type`. `/obj/item/food/ready_donk/warm` (`packaged.dm:260`) only overrides `warm_type = /obj/item/food/badrecipe` to stop people burning warm donks, so it inherits the "good result" setup, which makes the examine text list the burned mess as a normal recipe. Microwaving it would also add omnizine again (`added_reagents`).

### Fix

Commit "Fix issue 77376: Warm Ready-Donks no longer claim a burned mess is a good bake" adds overrides on `/obj/item/food/ready_donk/warm`: `make_bakeable()` adds the bakeable component with a 25-40 second time and `positive_result = FALSE`, and `make_microwaveable()` adds the microwavable element with `bad_recipe = TRUE` and no added reagents. The Donk-a-Roni (mac and cheese) warm variant inherits the override.

### Verification

On the test server after the fix, `examine()` on a cold donk still listed "baked into a warm Ready-Donk" and "microwaved into a warm Ready-Donk"; the warm donk and the warm mac and cheese listed no baked or microwaved line. Not checked: actually baking or microwaving a warm donk (that it still burns or what the player sees), and the pasta half.

## #82687: Anosmia does not stop soup smelling

### Reproduction

1. Give the admin's mob the `anosmia` trait (Lua editor), put the curry ingredients into a soup pot, set its temperature to 480 and call `handle_reactions()`.
2. Observed on master: "You smell something good coming from the steaming pot of soup." appeared in chat.

### Cause

The soup recipes' `mix_message` (`soup_mixtures.dm:36`) describes a smell but is delivered as an ordinary `audible_message` to all nearby mobs (`code/modules/reagents/chemistry/holder/reactions.dm:142` and `:202`, `equilibrium.dm:384`). Nothing marks it as a smell, so anosmia cannot filter it.

### Fix

Commit "Fix issue 82687: Anosmia prevents soup smell messages":
- New `SMELL_MESSAGE` flag in `code/__DEFINES/say.dm`; `atom/audible_message` (`code/modules/mob/mob.dm`) skips mobs with `TRAIT_ANOSMIA` when it is set.
- New reaction var `mix_message_is_smell` (`recipes.dm`), TRUE on `/datum/chemical_reaction/food/soup`.
- `reactions.dm` (`handle_reactions` and `force_stop_reacting`) collects smell messages separately and sends them with the flag; `equilibrium.dm` passes the flag for the random in-reaction message.

### Verification

With the trait the smell message did not appear; with the trait removed it did, from the same setup. The first run's script ended in a Lua error from a nonexistent method call in the test script itself (the only runtime logged); the message check relies on the chat output of the two runs. Not checked: other reaction messages.

## Notes

- Only soups are flagged. Other `mix_message`s that mention smells (some toxins and drinks) are unchanged, and the issue thread notes that many `mix_message` values mix smell and sight. A third caller, `reactions.dm:248` (`selected_reaction.mix_message`), was not changed.
- Flagging per reaction means a message that is partly a sight and partly a smell cannot be split; the author's fix treats the whole soup message as a smell.
- Upstream PR #77570 (burning food handling) is referenced in the issue's triage hints; it did not touch the warm-donk setup, per the code check.
