## Summary

Examining a soup pot with a duct spider (or any carried mob) in it listed the ingredient as "1 bugged mob". The pot's examine text groups ingredients by type and prints the type's compile-time default name, and a mob holder's default name is "bugged mob"; the real name is only set at runtime. The fix groups and prints ingredients by their actual names.

## The bug

A player puts a duct spider into a soup pot. Examining the pot shows "Inside, you can see: • 1 bugged mob", which looks like an error. The same code also ignores any other renaming: a renamed item is shown under its original name.

## Reproduction

On master, with admin tools:

1. In the Lua editor, spawn a human, a soup pot, and a duct spider (`/mob/living/basic/spider/maintenance`).
2. Have the human pick up the spider (`spider:mob_pickup(human)`), which creates the mob holder item in their hands, and put the holder in the pot (`pot:item_interaction(human, holder, {})`).
3. Add a tomato that has been renamed, then examine the pot.

Observed on master: "Inside, you can see: • 1 bugged mob • 1 tomato". The renamed tomato was also listed as "tomato". This matches the screenshot in the issue ("1 bugged mob"). The ingredients were put in using procs from Lua, not through normal player interaction with the pot.

## Cause

`reagent_special_examine` in `code/modules/food_and_drinks/machinery/stove.dm` (lines 76-87) counted ingredients by `ingredient.type` and printed `initial(ingredient_type.name)`. `initial()` returns the name a type is declared with. `/obj/item/mob_holder` is declared with the name "bugged mob" (`code/modules/mob/living/inhand_holder.dm:5`) and `insert_mob` sets the real name when a mob is put into the holder, so the declared name is never the visible one. Renamed or fried items have the same problem.

## Fix

One commit, "Fix issue 82246: soup pot examine shows "bugged mob" for mob holders". In `stove.dm` the amounts are keyed by `ingredient.name` rather than `ingredient.type`, and that name is printed. This is a single-file change in the examine text only.

The trade-off is that two different item types with the same name now share a line, which is arguably how the list reads best to a player.

## Verification

Same steps on a rebuilt, restarted test server. The pot now listed "• 1 duct spider (942) • 2 renamed tomatos • 1 tomato". The number in the spider's name is its own random name suffix. "tomatos" comes from the existing `\s` plural macro, not from the change. No other checks were done, such as examining a pot with several mob holders or with fried items.

## Notes

- The comments on the issue read it as a joke (bug in the soup gives bug soup), and the maintainer's remark "cooking mob holder items strikes again" points to a wider class of problems. This fix only changes the text.
- Separate behaviour seen during testing and not changed: cooking a soup with the holder in the pot turns the holder into a fried item ("fried duct spider"), and dumping the pot then moves it to the floor, which releases the spider alive (it "uncurls"). Whether mob holders should be accepted as ingredients at all is a design question for maintainers.
