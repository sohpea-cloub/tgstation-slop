## Summary

The four issues share a symptom (wrong antagonist listings in the Check Antagonists panel and the round-end report) but come from three separate defects. `admin_remove()`, the proc behind the traitor panel's "remove antag" link, only calls `on_removal()` and never deletes the antag datum, so the datum stays in `GLOB.antagonists` with its owner and keeps being listed (#98210). The imposter wizard event adds an antag datum to the wizard team's member list, which must contain minds, so the wizard team renders empty in Check Antagonists and the same bad member causes the runtime in #75210 and #86779. The fugitive team's round-end panel opens a `<div>` and never closes it, so the pirate panel is nested inside it (#81728). Each has a one-commit fix.

## The bug

- #98210: an admin removes an antagonist (the report used a changeling) with the traitor panel. The mob's status is cleared, but the person is still listed in Check Antagonists and in the "The changelings were: ..." line of the end-of-round screen.
- #75210 and #86779: after the imposter wizard event fires, the wizard team's section in Check Antagonists is empty ("failed to list any wizards"), and the report suggests the end-of-round panel listed none either. #86779 is a round-end runtime on an imposter apprentice datum (`undefined variable .../imposter/var/antag_datums`).
- #81728: in the round-end report the space pirate section appears inside the fugitive section instead of after it.

## Reproduction

All with admin tools (Lua editor) on the test server after the round had started.

### #98210

1. Create a mind and give it a changeling antag datum from Lua.
2. Call `admin_remove(admin)` on that datum. This is the same call the traitor panel link makes (`code/datums/mind/_mind.dm:250`), so the panel click itself was not driven through the UI.
3. Observed on master: `GLOB.antagonists` still held the changeling (not deleted, `owner` still set). `build_antag_listing()` (the Check Antagonists panel text) still contained it and `SSticker.antag_report()` still printed "The changelings were: ... " with the test key.

### #75210 / #86779

1. Build a wizard with an apprentice and an imposter the way the event does: `wiz_team.add_member(imposter)` where `imposter` is the `/datum/antagonist/wizard/apprentice/imposter` datum, then `add_antag_datum(imposter)`.
2. Observed on master: `wiz_team.members` was `/datum/mind, /datum/antagonist/wizard/apprentice/imposter, /datum/mind`, and `build_antag_listing()` rendered the team as an empty table ("Wizzy team <table></table>") while the other sections (changelings) were fine.
3. The exact runtime text from #86779 (it refers to `roundend.dm` line 621) was not reproduced as such: current `antag_report` no longer reads `antag_datums` there. The same bad member instead breaks `get_team_antags()`, described below.

### #81728

Not reproduced in game. The cause was found by reading `fugitive.dm`; the fix was checked by calling the team's `roundend_report()` and confirming the returned string now ends in `</div>`.

## Cause

### #98210

`/datum/antagonist/proc/admin_remove` (`code/modules/antagonists/_common/antag_datum.dm:449-454`) logs the removal and calls `on_removal()` and nothing else. `on_removal` (line 321) strips effects, removes the datum from `owner.antag_datums` and from its team, but leaves `owner` set and the datum alive. The datum leaves `GLOB.antagonists` only in `Destroy()` (lines 76-82). Both `build_antag_listing` (`code/modules/admin/check_antagonists.dm:58`) and `antag_report` (`code/__HELPERS/roundend.dm:622`) iterate `GLOB.antagonists` and skip only datums without an owner. The other removal path, `/datum/mind/proc/remove_antag_datum` (`code/datums/mind/antag.dm:30-40`), calls `on_removal()` and then `qdel(antag)`; `admin_remove` lacked the second step.

### #75210 / #86779

`code/modules/events/wizard/imposter.dm:25` (master) does `master.wiz_team.add_member(imposter)` with an antag datum. `/datum/team/proc/add_member` (`code/modules/antagonists/_common/antag_team.dm:38`) expects a `/datum/mind`, and `add_antag_datum` already registers the mind with the team through `get_team()`. `get_team_antags` (`antag_team.dm:85-99`) loops `for(var/datum/mind/team_mind as anything in members)` and reads `team_mind.antag_datums`, which is not a variable of an antag datum, so it runtimes on the imposter entry and the team section comes out empty. #86779's log comes from older roundend code (its line 621 read `antag_datums`); at master the reader that fails on the same bad entry is `get_team_antags`.

### #81728

`/datum/team/fugitive/roundend_report` (`code/modules/antagonists/fugitive/fugitive.dm:106-122`) starts with `result += "<div class='panel redborder'>..."` and returns `result.Join("<br>")` without a closing `</div>`. The pirate report (`pirate.dm`, ends with `</div>` wrapping) is emitted after it in `antag_report`, so it is rendered inside the unclosed fugitive panel.

## Fix

Three commits, each touching one file:

1. "Fix issue 98210: delete antag datums removed via the traitor panel": `admin_remove` now calls `qdel(src)` after `on_removal()`, matching `remove_antag_datum`. The cultist override (`cultist.dm:117`) only sets `silent` and calls the parent, so it gets the same behaviour.
2. "Fix issue 75210: stop adding the imposter datum to the wizard team's member list": removes the `master.wiz_team.add_member(imposter)` line from `imposter.dm`. The mind is added to the team when `add_antag_datum(imposter)` runs. This also removes the #86779 runtime.
3. "Fix issue 81728: close the fugitive roundend panel div": appends `result += "</div>"` before the return.

## Verification

On the test server after rebuilding:

- #98210: after the fix, with three entries in `GLOB.antagonists`, `admin_remove` brought it to two; the removed changeling's name no longer appeared in `build_antag_listing()` or `antag_report()`, and the wizard entries were still listed.
- #75210 / #86779: the real event proc (`round_event/wizard/imposter:start()`) was run and a ghost signed up through the poll. `wiz_team.members` held only the three minds. Check Antagonists and the round-end report listed both the wizard ("Wizzy") and the imposter.
- #81728: returned-string check only (see Reproduction).

Not checked:

- Clicking the traitor panel link itself; `admin_remove` was called directly.
- A complete round end with fugitives, hunters and pirates, to look at the rendered report.
- Whether the end-of-round panel lost wizards in #75210 before the fix (only the Check Antagonists listing was seen empty on master).
- Other `admin_remove` overrides beyond reading the cultist one, and whether any caller keeps using the datum after `admin_remove` returns.
- Note on method: calling `SSticker.antag_report()` from Lua can yield at `CHECK_TICK` and a later line in the same run raced the report ("Cannot read null.current" in `changeling.dm`); this was a test artifact and the report was called in a separate run.

## Notes

- #86779 was triaged as a duplicate of #98210. It is not: its cause is the imposter datum in the team member list, the same as #75210. Its quoted stack trace comes from older code.
- #75210 also wonders whether the event should spawn an imposter for both the wizard and the apprentice; that design question was not looked at.
- #81728 is labelled Good First Issue upstream. The returned HTML is now balanced, but the visual result was not seen.
- `admin_remove` now frees the datum. Anything that holds a reference to it after the traitor panel removes it (admin tools, listeners on `COMSIG_ANTAGONIST_REMOVED`) would see a deleted datum; no such user was checked for.
