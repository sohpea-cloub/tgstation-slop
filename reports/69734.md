## Summary
The 2022 report showed a runtime in `/datum/mind/proc/add_memory` when xenomorphs were gibbed, in the report by an arrivals shuttle landing on them. On current master, gibbing xenomorphs with minded humans and a minded xenomorph nearby produced no runtime. The old call that passed a string memory type from the gib path no longer exists: only humans create death memories now, and the memory helpers validate their type.

## The bug
The reporter spawned xenomorph drones next to the arrivals shuttle's dock, respawned as a random character, and let the shuttle land on the drones. The shuttle gibbed them, and `add_memory` runtimed. The stack trace showed `gib()` calling `add memory in range(..., 7, "gibbed", list, 4, 32)`, which called `add_memory` on a mind with the arguments `"gibbed", list, 4, 32`: the old string-keyed memory interface.

## Reproduction
Attempted on master; no runtime resulted.

1. On the test server, started the round and observed. Using the Lua editor, spawned a human with a mind, and a minded xenomorph drone (`/mob/living/carbon/alien/adult/drone`).
2. Next to them, gibbed a minded drone and a minded human (`gib()`), and separately gibbed a plain (mindless) drone next to a minded human.
3. Read the runtime log.

Results: the log had no runtime from `add_memory` or `gib`. The only runtime was caused by the tester's own mistyped spawn path ("Cannot create objects of type null"). The minded human witness received a memory (`witness_gib`) from the human's gib; the xenomorph gibs created none.

The shuttle landing itself was not tested; the gibs were called directly. The shuttle path calls the same `gib(DROP_ALL_REMAINS)` (`code/modules/shuttle/mobile_port/shuttle_move_callbacks.dm:41`), so this should exercise the same code.

## Cause
Nothing is broken now. Why the report no longer applies:

- `gib()` calls `send_death_moodlets(gibbed = TRUE)` (`code/modules/mob/living/death.dm:20`). Only `/mob/living/carbon/human/send_death_moodlets` (`death.dm:210`) creates a memory, using a typepath: `add_memory_in_range(src, 7, (gibbed ? /datum/memory/witness_gib : /datum/memory/witnessed_death), protagonist = src)` (`death.dm:216`). Xenomorphs use the base `/mob/living/proc/send_death_moodlets` (`death.dm:185`), which does not add a memory.
- `_add_memory` (`code/__HELPERS/memory_helpers.dm:59`) rejects invalid memory types with an explicit `CRASH` (line 63), and `_add_memory_in_range` (line 19) takes a `memory_args` list rather than the old positional string/number arguments.

I did not trace which upstream change removed the original call.
