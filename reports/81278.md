## Summary

The camera eye created by an advanced camera console never consults the console's `z_lock` when it moves between z-levels, so page up / page down (the "move up / move down a floor" action) can step the eye through every linked level. The Lavaland syndicate base's two comms consoles are plain `camera_advanced` consoles with no lock, so they are affected. The fix makes the eye refuse z moves to levels outside the console's `z_lock`, and gives the two Lavaland consoles the station lock.

## The bug

Reported: using the advanced camera console in the Lavaland syndicate base, page up and page down flip the view through every z-level instead of staying on the station's, so the user can lose track of which level holds the station. The reporter notes that there are few cameras on other levels, so it is a minor problem.

## Reproduction

Done on the "MultiZ Debug" map so that several linked levels exist (station levels 2 and 3, a mining-camera console on level 5):

1. Latejoin as an Assistant.
2. Using the Lua editor, spawn a plain `/obj/machinery/computer/camera_advanced` next to the character and use it. A plain console has an empty `z_lock`, which is the same situation as the Lavaland comms console.
3. Move the eye to z2 (Lua, `setLoc` on the eye) and press "Move up a floor": the message "You move upwards." appeared and the eye was at 133,120,3. "Move down a floor" returned it to z2.

Not done: the Lavaland syndicate base ruin was not loaded, so the mapped console was not used directly. The plain console is the same type.

Keyboard Page Up arrives as the "Northeast" key, which calls `mob/eye/up()`, which calls the same `zMove()` and `can_z_move()` path as the button, so it is covered by the same check.

## Cause

- The eye (`/mob/eye/camera/remote`, `code/modules/mob/eye/camera/remote.dm`) inherits `up()`/`down()` and `can_z_move()` from `/mob/eye` and does not look at the console. The console's `z_lock` is only used when the eye is first placed and for the camera Jump list (`code/game/machinery/computer/camera_advanced.dm:178-195`).
- `allow_z_transition()` (`remote.dm:162`) only governs z-level transitions across space-level links, not these explicit moves.
- The two Lavaland consoles (`_maps/RandomRuins/LavaRuins/lavaland_surface_syndicate_base1/commswilding_1.dmm:31` and `commswilding_2.dmm:160`) are bare `/obj/machinery/computer/camera_advanced` with no `lock_override`.

## Fix

One commit, "Fix issue 81278: lock advanced camera console z-moves to its z_lock; lock lava comms consoles to the station":

- `remote.dm`: a `can_z_move()` override on `/mob/eye/camera/remote`. After the parent allows the move, if the origin console has a non-empty `z_lock` and the destination z is not in it, the move is refused with a warning ("The console can't reach that level!") when feedback is requested.
- `commswilding_1.dmm` and `commswilding_2.dmm`: the console gets `lock_override = 1` (`CAMERA_LOCK_STATION`).

Consoles with an empty `z_lock` are not affected.

## Verification

On the test server, with a console whose `z_lock` was set via Lua to z2 and z5, the eye at z2, "Move up a floor" printed "You can't move upwards!" and the eye stayed on z2 (z3 is not in the lock). The warning text from the new override was not separately recorded in the notes.

Not checked: the Lavaland ruin loaded in game with the edited consoles (the map edits are plain var syntax and the code compiled with no errors); moving between station levels with the station lock (expected to still work, since both are in the lock); any other console type.

## Notes

- The new check applies to every console with a `z_lock`, not only the Lavaland ones: for example the shuttle navigation consoles and other camera-based consoles that set one can no longer z-move out of their locked levels. The author flagged this for review.
- The station lock still allows moving between station z-levels, which seems the intended behaviour.
- The icemoon underground comms agent consoles (`_maps/RandomRuins/IceRuins/icemoon_underground_comms_agent`, syndie type) are also unlocked; they were not changed, since the issue is about Lavaland.
