## Summary

Two unrelated language bugs were fixed on one branch, one commit each.

- **#90789:** the sentence splitter in `scramble_paragraph` ended a sentence after a single punctuation character. `HEY!!` was therefore scrambled as two sentences, `HEY!` and `!`, and came out as `WORD! WORD`-style text with an extra word. The regex now consumes a whole run of terminators.
- **#92773:** split personalities (including the blackout-drunk one) had their own default language holder, so they understood only Common whatever their body knew. They now use the body's language holder.

## #90789: double punctuation

### The bug

When a listener only partly understands a language, the speech is run through `scramble_paragraph`, which splits it into sentences and scrambles each one. A run of terminators such as `!!` was split in the middle, so the second `!` became a sentence of its own and was scrambled into an extra word followed by its own punctuation.

### Reproduction

1. Join as an observer on the test server and open the Lua editor.
2. Fetch the Xenocommon language instance from `GLOB.language_datum_instances`.
3. Call `scramble_paragraph('HEY!! Get over here you slimy thing!!', nil)` and `scramble_paragraph('Run!!! Now', nil)` on it.

This was done by calling the proc directly from Lua. No player was made to speak to a listener.

Output on master (identical in six repeated calls):

```
SSS! SSS SSS sSssss sSssSs sSs ssssss sSsSSS! SSS! // SSS! SSS!! SSS
```

- `HEY!!` produced `SSS! SSS`: the first `!` ended one sentence and the second `!` became a separate sentence.
- `thing!!` produced `sSsSSS! SSS!`, with an extra scrambled word.
- `Run!!! Now` produced `SSS! SSS!! SSS`.

### Cause

`code/modules/language/_language.dm:239`:

```dm
var/static/regex/first_sentence = regex(@"(.+?(?:[\.!\?]|$))", "g")
```

The lazy match `.+?` followed by exactly one of `. ! ?` ends the sentence at the first terminator. For `HEY!!` the first match is `HEY!`, and the next iteration matches the remaining `!` as a sentence. The loop at line 241 passes each match to `scramble_sentence`, so the lone `!` was scrambled as its own sentence.

### Fix

Commit "Fix issue 90789: keep repeated punctuation in one sentence when scrambling languages" changes the terminator class to `[\.!\?]+`, so a run of terminators stays attached to its sentence. It is a one-character change in the regex.

### Verification

On the rebuilt test server, the same Lua calls gave (identical in four repeated calls):

```
SSS!! SSS sSsSSS ssssSs SSS ssssss sssSSS!! // SSs!!! SSs
```

`HEY!!` stays together as `SSS!!`, `thing!!` as `sssSSS!!`, and `Run!!!` as `SSs!!!`. Not checked: a real player speaking to a partly-understanding listener, and other punctuation runs such as `?!` or `...`.

## #92773: blackout drunk understands only Common

### The bug

The report is of a xeno queen who got blackout drunk and could no longer understand Xenocommon, only Common.

### Reproduction

The real path (the blackout trauma) needs a ghost poll for the personality, and it was not run. The cause was found by reading the code. The check on master below was not run in game.

1. Create a human and grant it Xenocommon.
2. Construct a `/mob/living/split_personality` inside that human.
3. Call `has_language` for Xenocommon on both. The human returns true. The personality, according to the code, has only the default holder (Common).

### Cause

`/mob/living/split_personality` (`code/datums/brain_damage/split_personality.dm:147`) stores its `body` (line 150) but never ties its language holder to it. `get_language_holder()` (`code/game/atoms_movable.dm:1591`) therefore creates the default holder from the mob's initial type, which gives only Common. The blackout personality (line 338) and the brainwashing "traitor" personality (line 250) both inherit this.

### Fix

Commit "Fix issue 92773: split personalities share their body's languages" adds an override:

```dm
/mob/living/split_personality/get_language_holder()
	if(!QDELETED(body))
		return body.get_language_holder()
	return ..()
```

The personality reuses its body's holder, so it understands whatever the body understands. All the `has_language`, `copy_languages` and similar procs go through `get_language_holder()`, so they follow.

### Verification

On the rebuilt test server, with a human that had Xenocommon granted and a directly constructed split personality inside it: `has_language(Xenocommon)` returned 1 for both the human and the personality, and `personality.body == human`. Not checked: the real blackout-drunk flow, the brainwashing flow, and the behaviour before the fix in game.

## Notes

- The override also applies to the brainwashing (traitor) personalities. This seems intended, but it was not discussed or tested.
- Because the holder is now shared, language swaps made when a mind moves between mobs (`code/datums/mind/_mind.dm:196-197` takes the old and new mobs' holders) now touch the body's holder when a personality takes over or leaves. This was reasoned about from code and not tested.
- The test mob had no trauma attached, so `/mob/living/split_personality/Life` logged `Cannot read null.initialized` every two seconds (`trauma.initialized`). That is an artifact of the test setup (compare the check at `split_personality.dm:170`), not of the fix.
- Apart from those, no new runtimes appeared in the test round.
