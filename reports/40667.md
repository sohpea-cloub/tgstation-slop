# #40667: Objective text uses the borg name and "Cyborg" role once the target is borged

| | |
|---|---|
| Issues | [#40667](https://github.com/tgstation/tgstation/issues/40667): verified, fixed |
| Status | Fixed, checked in game with admin tools |
| Fix branch | [fix/40667](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/40667) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

When a kill target is turned into a cyborg and takes a cyborg name, the "Assassinate X, the Y." objective of whoever hunts them is rewritten to the borg's name and the job "Cyborg" (for example "Assassinate Beepy-9, the Cyborg."). The rewrite happens because `fully_replace_character_name()` refreshes the text of every objective that targets the renamed mob, and the text is built from the target's live name and assigned role. The fix skips that refresh when the renamed mob is a silicon, so the objective keeps the wording it was given.

## The bug

The issue (2018, a screenshot only, label "Consistency Issue") says that if your target gets borged, the objective shows the target's borg name and role "Cyborg". The one comment asks whether this only shows on the round end screen. The screenshot was not viewable here, so the issue is understood from its title.

Objective text is shown to the owner during the round and printed on the round end screen (`printobjectives()`, `code/__HELPERS/roundend.dm:737`, prints `explanation_text`), so the changed text is visible in both places. Only the round end report was not looked at; the objective text itself was read directly in game.

## Reproduction

Admin tools: the Lua editor. It was reproduced with calls to the same procs the game uses, not through a player who actually gets borged at a robotics console or with a cyborg name preference.

1. Start a round and spawn a traitor (Alice) and a victim (Carl) with the job Scientist.
2. Add an `/datum/objective/assassinate` targeting Carl's mind to Alice's traitor datum, and call `update_explanation_text()`. The text read "Assassinate Carl Victim, the Scientist."
3. Give Carl a client by setting a ckey on him, then call `Robotize()` on him.
4. Call `fully_replace_character_name(real_name, "Beepy-9")` on the new borg. This is what `apply_pref_name()` does for a player whose cyborg name preference is not the default.
5. Read the objective text from Alice's traitor datum.

Observed before the fix: "Assassinate Beepy-9, the Cyborg." with the target's mind role being Cyborg.

Findings from the attempts:

- `Robotize()` alone, with the default borg name, left the text unchanged ("Assassinate Bob Victim, the Scientist." in an earlier try on a victim without a client). The text only changed once the borg was renamed, so in practice the bug appears when a borg is renamed, such as when the target's cyborg name preference is applied.
- Without a client attached, the target's mind kept the role Scientist after `Robotize()`, so the "Cyborg" part of the text depends on the mind being re-initialised as a borg.

## Cause

`/mob/proc/fully_replace_character_name()` in `code/modules/mob/mob.dm` ends its rename work with (lines 1220-1225 at master):

```dm
for(var/datum/mind/T in SSticker.minds)
	for(var/datum/objective/obj in T.get_all_objectives())
		// Only update if this player is a target
		if(obj.target && obj.target.current && obj.target.current.real_name == name)
			obj.update_explanation_text()
```

For an assassination objective, `update_explanation_text()` (`code/game/gamemodes/objective.dm:230`) rebuilds the text as "Assassinate [target.name], the [target.assigned_role.title]." from live values. By the time the borg is renamed, the mind's role is Cyborg (`/mob/living/silicon/robot/mind_initialize()`, `code/datums/mind/initialization.dm:30-32`), and the name is the new borg name, so the objective is rewritten with both.

## Fix

One commit, "Fix issue 40667: objective text no longer takes a borged target's silicon name and Cyborg role", changes `code/modules/mob/mob.dm`. The objective refresh loop in `fully_replace_character_name()` is now wrapped in `if(!issilicon(src))`, with a comment saying that a silicon name and the Cyborg or AI "job" are not what the objective's owner knows the target by. Renames of non-silicon mobs still refresh objectives as before. This covers AI targets too, since `issilicon()` includes AIs (this was not tested).

## Verification

After rebuilding and restarting the test server, the same steps were repeated (traitor, Scientist victim, objective, `Robotize()`, rename to "Beepy-9"). The text stayed "Assassinate Carl Victim, the Scientist.", while the mind role was Cyborg and the mob was named Beepy-9, so the objective was no longer rewritten.

Not checked: the round end screen itself, the objective as seen through a player UI, AI targets, and a real client with a non-default cyborg name preference (the rename was done by calling `fully_replace_character_name()` directly).

## Notes

- Other callers of `update_explanation_text()` are not covered. Changeling identity theft and revolution objectives re-run it explicitly, and if that happens after the target is borged they could still show the Cyborg role. These were not tested.
- Design choice for maintainers: the fix keeps the original name and job in the objective after borging. If the intent is for the text to follow a rename in general (the refresh exists for that reason), the exclusion for silicons is the narrow way to avoid this specific case.
