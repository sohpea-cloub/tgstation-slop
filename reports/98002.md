# #98002: Lipstick is displaced on spacer sprites

| | |
|---|---|
| Issues | [#98002](https://github.com/tgstation/tgstation/issues/98002): verified, fixed |
| Status | Verified; fix committed |
| Fix branch | [fix/98002](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/98002) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

Lip overlays are added to a head's icon after the bodypart code has applied the mob's height offset, so they never receive it. On humans taller than normal (spacers), lipstick is drawn too low, near the chin or neck, while eyes and hair are offset correctly. The fix applies the same `UPPER_BODY` height offset to the lip overlay, as eyes and hair already get.

## The bug

The issue reports that lipstick does not account for the height of spacers and appears far below the mouth on the sprite. In game, the red lip pixels on a tall human sat down by the chin/neck, well below the eyes.

## Reproduction

1. On master, using the Lua editor on the test server, spawn three humans and set their heights to 12, 16 and 18 with `set_mob_height`.
2. On each human's head bodypart, set `lip_style = "lipstick"` and `lip_color` to red, then call `update_body()`.
3. Render the three humans.

Observed: on the height-16 and height-18 humans the red lip pixels were far below the eyes, by the chin/neck. On the height-12 human they sat at the mouth. This was a visual check of the rendered images only; no `pixel_z` values were read. The reproduction used the Lua editor to set heights and lips directly, not the spacer quirk and a real lipstick item.

## Cause

`get_limb_icon()` in `code/modules/surgery/bodyparts/head.dm:193` appends the lip overlays (`. += get_lips_overlays(dropped)`) after the base bodypart proc has already applied height to the overlays generated so far (`code/modules/surgery/bodyparts/_bodyparts.dm:1437-1443`, which calls `owner.apply_height(generated_overlay, ENTIRE_BODY)`). The lips are therefore never offset.

`get_lips_overlays()` (`code/modules/surgery/bodyparts/head_hair_and_lips.dm:35-44`) only applied `worn_face_offset`, which is the species face offset, not the height offset. Eyes and hair, by contrast, call `apply_height(..., UPPER_BODY)` in `update_eyes` and `update_hair` in `code/modules/mob/living/carbon/human/human_update_icons.dm`. For heights above medium (spacers), the `UPPER_BODY` offset moves the face up, so lips drawn at the unmodified position end up displaced relative to the eyes.

## Fix

One commit, "Fix issue 98002: Lipstick is displaced on spacer sprites", changes `get_lips_overlays()` in `code/modules/surgery/bodyparts/head_hair_and_lips.dm`:

```dm
worn_face_offset?.apply_offset(lip_overlay)
// Lips are part of the head's icon but get added after the bodypart's height handling, so apply height like we do for eyes and hair
if(!dropped)
	owner?.apply_height(lip_overlay, UPPER_BODY)
. += lip_overlay
```

The offset is skipped for dropped heads, which have no owner and are drawn facing south. The head's limb icon cache key already includes `mob_height`, so no cache change was needed (per the agent's reading of the code; not separately tested).

## Verification

After rebuilding, the same Lua setup was rendered again. On the height-18 human the lips sat just under the eyes, like on the height-12 human.

Not checked: dropped heads (the code path is unchanged by the `!dropped` guard), the spacer quirk and a real lipstick item (heights were set directly), and the issue's "apply the lipstick to your neck" step, which was taken to be the displaced look itself. Pixel offsets were not read, only the rendered images.

## Notes

- The fix uses `UPPER_BODY` rather than `ENTIRE_BODY` (what the bodypart code uses for the generated overlays) to match eyes and hair, which sit on the upper body. The bodypart code's own comment says it uses `ENTIRE_BODY` for heads for consistency with things like `getflaticon`; whether lips should match that is a maintainer's call.
