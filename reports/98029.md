## Summary

The issue reports that a wielded fire axe still looks one-handed. On master `87b93338` this does not happen: wielding the axe switches its in-hand state from `fireaxe0` to `fireaxe1`. The regression had been introduced by PR #97811 and was fixed by PR #98091, merged 2026-10-14, which is already in the tested tree. No change was made.

## The bug

As reported (opened 2026-10-03): pick up a fire axe, wield it, and the character still appears to hold it with one hand, because the in-hand sprite does not change on wielding.

## Reproduction

Not reproduced. What was done on master:

1. Using the Lua editor on the test server, spawned a human and a `/obj/item/fireaxe` and put the axe in the human's hands.
2. Called `attack_self` on the axe with the human as user, which wields it.

Observed:

- Before wielding: `inhand_icon_state = "fireaxe0"`.
- After wielding: `inhand_icon_state = "fireaxe1"`, `icon_state = "fireaxe1"`, name "fire axe (Wielded)".
- The human's `overlays_standing[HANDS_LAYER]` contained `fireaxe1|icons/mob/inhands/weapons/axes_lefthand.dmi` and `offhand|.../items_righthand.dmi`.
- Both in-hand icon files contain `fireaxe0` and `fireaxe1` states.

The wield was triggered by calling `attack_self` directly rather than by a player clicking, and the sprite was checked through the overlay list, not by looking at a rendered image.

## Cause

Historic cause, from the agents' reading of the code and the PR references in the issue's context (the PR texts themselves were not read): PR #97811 gave two-handed items explicit `inhand_icon_state` values such as `"fireaxe0"`. The `two_handed` component's icon update changed only `icon_state`, so the in-hand state stayed at the unwielded value.

Current code: `on_update_icon` in `code/datums/components/twohanded.dm:372-378` sets both states:

```dm
if(update_icon_state)
	source.icon_state = source.inhand_icon_state = "[BASE_OR_INITIAL_ICON_STATE(source)][wielded]"
	return COMSIG_ATOM_NO_UPDATE_ICON_STATE
```

The fire axe adds the component with `update_icon_state=TRUE` (`code/game/objects/items/weaponry/melee/fireaxe.dm:50`) and has `base_icon_state = "fireaxe"`, so it gets `fireaxe1` when wielded. That is the PR #98091 change.

## Fix

None needed; no commits.
