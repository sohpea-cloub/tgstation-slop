## Summary

The wild mutation botany experiment only accepts atoms of type `/obj/item/food/grown`, so a wild-mutated inedible product such as a steel cap's logs (`/obj/item/grown`) is never counted. The fix adds an overridable type-match hook to scanning experiments and overrides it in the wild experiment so `/obj/item/grown` also satisfies the requirement. #98035 (the destructive scanner leaves fish alive) is the intended behavior of the fish experiments: they are not destructive and fish are items, not mobs. No change was made for it.

## #67372: the bug

A player who wild-mutated a tower cap into a steel cap could not submit the logs for the Wild Mutation experiment, while a wild-mutated golden apple from an apple was accepted. The linked comment correctly identifies the cause as two separate type trees for grown plants: `/obj/item/grown` (steel cap logs) and `/obj/item/food/grown` (apples).

### Reproduction

Done with the Lua editor in a running round, calling the experiment procs directly rather than by operating a scanner.

1. Create a wild mutation plant experiment datum (`/datum/experiment/scanning/random/plants/wild`).
2. Spawn a steel cap log (`/obj/item/grown/log/steel`) and an apple, and give both `TRAIT_PLANT_WILDMUTATE`.
3. Call `experiment_requirements()` for each.

Before the fix: the log returned null (rejected), the apple returned `/obj/item/food/grown` (accepted). This matches the issue.

### Cause

`/datum/experiment/scanning/proc/experiment_requirements` (`code/modules/experisci/experiment/types/scanning.dm:108`) tests each required atom with `istype(target, req_atom)` (line 111). The plant experiments set `possible_types = list(/obj/item/food/grown)` (`code/modules/experisci/experiment/types/scanning_plants.dm:6`), so that is the only required type. Wild-mutated products get `TRAIT_PLANT_WILDMUTATE` regardless of their type (`code/modules/hydroponics/seeds.dm:236`), but `/obj/item/grown` is not under `/obj/item/food/grown`, so the `istype` check fails for steel cap logs.

### Fix

One commit, "Fix issue 67372: wild mutation experiment accepts inedible grown items":

- `scanning.dm`: a new proc `target_matches_requirement(target, req_atom)`, defaulting to `istype(target, req_atom)`, now used by `experiment_requirements()`. Its doc comment says experiments whose requirement spans several unrelated type trees can override it.
- `scanning_plants.dm`: the wild plant experiment overrides it to also accept `/obj/item/grown` when the requirement is `/obj/item/food/grown`.

This was chosen over the two options in the issue's comment. Repathing all grown items is a large change, and letting experiments list several types would change how required atoms are counted and displayed. The hook leaves other experiments unchanged.

### Verification

In game via the same Lua calls after rebuilding:
- steel cap log without the trait: rejected (null)
- apple without the trait: rejected (null)
- steel cap log with the trait: accepted (returned `/obj/item/food/grown`, the requirement it counts toward)
- `perform_experiment_actions` on the log returned 1, the experiment reported complete, and the log was deleted.

Not checked: using a real scanner or destructive scanner on a log, a log from an actual wild-mutation harvest, or the end-to-end research point reward.

### Notes

- Only the wild experiment was changed. The "traits" plant experiment (`/datum/experiment/scanning/random/plants/traits`) still takes only `/obj/item/food/grown`. This was left as out of scope.
- Because the hook is general, other experiments can use it later.

## #98035: destructive scanner does not destroy fish

The report says an experimental destructive scanner leaves fish alive and unharmed. This was answered from the code only; it was not tried in game.

- The fish experiments set `traits = EXPERIMENT_TRAIT_TYPECACHE` (`code/modules/experisci/experiment/types/scanning_fish.dm:14`), not `EXPERIMENT_TRAIT_DESTRUCTIVE`. They only record which species were scanned.
- `scanning.dm:92` deletes scanned targets only for destructive experiments, and never living ones.
- `destructive_scanner.dm:76-90` (`open()`) gibs only `isliving()` atoms. Fish are `/obj/item/fish` items, so they are moved out of the scanner unharmed.

So the fish coming out of the scanner, even looking healthier, is the current design: the scan consumes nothing. Making the fish experiments destructive would consume fish players may want to keep, so that is a design decision for the maintainers. No change was made.
