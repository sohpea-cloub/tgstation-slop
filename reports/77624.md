# #77624: AI ctrl-click and alt-click on atmos pumps did nothing

| | |
|---|---|
| Issues | [#77624](https://github.com/tgstation/tgstation/issues/77624): verified, fixed |
| Status | Fixed on a branch and checked in game as an AI, for pumps only |
| Fix branch | [fix/77624](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/77624) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

An AI ctrl-clicking a pump got no effect, and alt-clicking one opened the loot panel instead of setting the pressure. The AI click handlers (`AICtrlClick`, `ai_click_alt`) are empty by default and never call the `click_ctrl` / `click_alt` procs that pumps implement. Atmospherics components also lacked `ALLOW_SILICON_REACH`, so the AI's range check failed. The fix makes the default AI handlers fall back to `click_ctrl` / `click_alt` and gives atmos components `ALLOW_SILICON_REACH`. This is a broad change, because it applies to every atom whose `click_ctrl` / `click_alt` accepts silicons.

## The bug

The issue reports that ctrl-clicking a pump as an AI does not toggle it. The reporter also says alt-click still worked, but a 2024 comment says alt-click is now broken as well. On master, both were broken. The pump's screentip still advertised "Ctrl-LMB Turn on".

## Reproduction

1. On the test server, start the round and observe.
2. Using the Lua editor, turn a human into an AI (`AIize()`), give the AI a client, and spawn `/obj/machinery/atmospherics/components/binary/pump` on the tile under the AI eye.
3. As the AI, ctrl-click the pump. Result: the pump stayed `pump_off-1` and no message appeared.
4. Alt-click the pump. Result: no pressure change. The click fell through to the loot panel, as the 2024 comment describes.

## Cause

`code/_onclick/ai.dm:131-132`: `/mob/living/silicon/ai/CtrlClickOn` only calls `target.AICtrlClick(src)`. The default `/atom/proc/AICtrlClick` is empty (`ai.dm:160`), so the generic `click_ctrl` (`code/_onclick/click_ctrl.dm:68`), where the pump's toggle lives (`pump.dm:37`), is never reached. Overrides such as airlocks, APCs and turret controls are unaffected.

Alt-click is the same. `ai_base_click_alt` (`ai.dm:136-151`) checks range, sends `COMSIG_CLICK_ALT`, and then calls `target.ai_click_alt(src)`. The default `ai_click_alt` (`ai.dm:163`) returned nothing and does not call `click_alt` (`code/_onclick/click_alt.dm:63`), where the pump's set-to-max-pressure lives (`pump.dm:45`). When nothing returned `CLICK_ACTION_ANY`, the code opened the loot panel.

Separately, `/obj/machinery/atmospherics/components` had `interaction_flags_click` at its default, without `ALLOW_SILICON_REACH`. The AI's `can_perform_action` range check therefore failed for these machines.

## Fix

One commit, "Fix issue 77624: let AIs ctrl/alt-click atmos components":

- `code/_onclick/ai.dm`: the default `AICtrlClick` now sends `COMSIG_MOB_CTRL_CLICKED` and `COMSIG_CLICK_CTRL`, as the normal ctrl-click path does. Then, if `user.can_perform_action(src, interaction_flags_click | SILENT_ADJACENCY)` passes, it calls `click_ctrl(user)`.
- `code/_onclick/ai.dm`: the default `ai_click_alt` now returns `click_alt(user)`.
- `code/modules/atmospherics/machinery/components/components_base.dm`: `interaction_flags_click = ALLOW_SILICON_REACH`.

Existing overrides (airlock, APC, turret controller, holopad) are untouched. A narrower alternative would be to override only on atmos components. The fallback was put in the atom defaults so that other machines using `click_ctrl` / `click_alt` also work for AIs.

## Verification

With the build rebuilt, the same setup was used as an AI:

- Ctrl-click on the pump showed a "turned on" balloon alert, and the icon changed from `pump_off-1` to `pump_on-1`.
- Alt-click showed "pressure output set to 4500 kPa".

Not checked: other component types (cryo, thermomachines) clicked by an AI, and any regression in airlock bolting or other overrides. Those overrides were not modified, so only the default path should have changed.

## Notes

- The default-handler change is broad: any atom whose `click_ctrl` / `click_alt` is reachable with its `interaction_flags_click` now responds to AI clicks, including some that did nothing before. A maintainer should review whether that is wanted, or whether it should be restricted to chosen types.
- The fallback depends on each type's `interaction_flags_click` allowing silicons, which is why the components needed `ALLOW_SILICON_REACH`.
