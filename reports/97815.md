# #97815: Wheelchairs can no longer move on raised surfaces

| | |
|---|---|
| Issues | [#97815](https://github.com/tgstation/tgstation/issues/97815): verified, fixed |
| Status | Cause reproduced; fix committed and checked in game; unit tests not run |
| Fix branch | [fix/97815](https://github.com/sohpea-cloub/tgstation-slop/tree/fix/97815) |
| Tested on | tgstation master `87b93338`, 2026-10-23 |

## Summary

A player buckled into a wheelchair who climbed onto a table (or similar climbable surface) could not roll to the next tile of that surface; only moving off it worked. The `climb_walkable` element lets a mover pass other climbable objects only if the mover itself carries `TRAIT_ON_CLIMBABLE`, and it only hands that trait to dense atoms. A wheelchair is non-dense, so it never gets the trait and the next table blocks it. The fix lets a mover through when any of its buckled mobs has the trait.

## The bug

The report: after climbing onto a raised surface such as a stage, platform or table, a wheelchair user is stuck in place and can only move off the surface. If they unbuckle, they move normally. The rider can step from table to table, but the chair carrying them cannot follow, and the rider is moved with the chair, so they are stuck.

## Reproduction

1. On the test server, spawn a human, a wheelchair, and two climbable tables in a row (for example at x, x+1), with floor beyond them.
2. Buckle the human into the wheelchair, next to the first table.
3. Have the human climb the first table (drag themselves onto it).
4. Try to move onto the second table.

The pre-fix reproduction was done with the Lua editor calling `Move()` directly on the atoms, not with real keypresses. With the rider on the first table, `wheelchair:Move(second table)` returned 0 while the rider's own `Move(second table)` returned 1, and the wheelchair never had `TRAIT_ON_CLIMBABLE`. This matches the report.

## Cause

`code/datums/elements/climb_walkable.dm` implements walking over climbable objects:

```dm
/obj/structure/proc/on_climb_enter(datum/source, atom/movable/arrived)
	...
	if(arrived.density)
		ADD_TRAIT(arrived, TRAIT_ON_CLIMBABLE, ELEMENT_TRAIT(/datum/element/climb_walkable))   // :40
...
/datum/element/climb_walkable/proc/can_allow_through(datum/source, atom/movable/mover, border_dir)
	SIGNAL_HANDLER
	if(HAS_TRAIT(mover, TRAIT_ON_CLIMBABLE))                                                    // :25
		return COMSIG_COMPONENT_PERMIT_PASSAGE
```

Only dense arrivals get the trait (`:39-40`), and passage is decided only by the mover's own trait (`:25`). `/obj/vehicle/ridden/wheelchair` sets `density = FALSE` (`code/modules/vehicles/wheelchair.dm:9`). So when the rider climbs a table the chair is carried along, but it is not given the trait, and for the next move the chair is checked against the dense table (via `COMSIG_ATOM_TRIED_PASS` from `CanPass`, `code/game/atom/_atom.dm:231`) and refused. The rider alone is fine because they are dense and have the trait.

## Fix

One commit, "Fix issue 97815: let wheelchairs follow their rider across climbable tables", extends `can_allow_through`: after the existing trait check, it loops over `mover.buckled_mobs` and permits passage if any rider has `TRAIT_ON_CLIMBABLE`. The alternative of giving the trait to non-dense atoms in `on_climb_enter` would also let empty non-dense items and vehicles through, so the check was tied to the rider instead.

## Verification

On the test server with the fix built, using real keypresses on a human buckled to a wheelchair, with tables on two adjacent tiles and floor after them:

- Dragging onto the first table: "You climb onto the table"; the human moved onto it.
- East from table to table: the wheelchair moved with the rider and the roll sound played.
- East again, off the table onto the floor: the wheelchair moved with its rider.
- West from the floor, twice: no movement; a chair on the floor still cannot roll back onto a table.
- Through the Lua editor: with the rider buckled on the floor, `wheelchair:Move(table)` returned 0; after unbuckling, the empty wheelchair's `Move(table)` returned 0, and an unclimbed human's `Move(table)` returned 0. So only chairs whose rider is already on a climbable get through.

No runtimes were seen. Not checked: unit tests; surfaces other than tables (stages, platforms) and other vehicles; chairs carrying more than one buckled mob.

## Notes

- Any other non-dense mover with a buckled rider on a climbable now also passes; that matches the intent but was not tested on other vehicles.
- A wheelchair rolling off a table onto the floor keeps working since the rider's trait is removed by the existing exit handler.
